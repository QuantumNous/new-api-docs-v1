- Admin と Root のみアクセスできます。サイドバーの「管理者」→「モデル」から開きます。
- このサイトのモデル情報、名前のマッチング、モデル広場での表示、プロバイダー、事前入力グループを管理し、価格設定へのアクセス、モデル情報と価格の同期、io.net のモデルデプロイを行えます。
- このページで管理するのはモデル情報です。チャネルで実際に使用するモデル、グループ、ルーティングは<a href="/ja/docs/guide/feature-guide/admin/channel" target="_blank" rel="noopener noreferrer">チャネル管理</a>で管理します。

<Callout type="info" title="ヒント">

- 「モデル」「プロバイダー」「デプロイ」の 3 つのタブがあり、ページタイトルはそれぞれ「モデル管理」「プロバイダー管理」「デプロイ」です。
- モデル情報、プロバイダー、事前入力グループ、モデルデプロイは、Admin と Root の両方が管理できます。
- モデルの価格設定を変更できるのは Root のみです。[Admin と Root の違い](#admin-と-root-の違い)を参照してください。
- 価格ルールについては、<a href="/ja/docs/guide/feature-guide/system-settings/settings-billing" target="_blank" rel="noopener noreferrer">課金と支払いの設定</a>および<a href="/ja/docs/guide/feature-guide/admin/billing-expression" target="_blank" rel="noopener noreferrer">課金式</a>を参照してください。
- モデル情報を作成またはインポートしても、モデルを呼び出せるチャネルは作成されません。
- デプロイを作成しても、チャネルは新規作成も関連付けもされません。
</Callout>

## 主な操作

この節では、モデルの追加と編集、価格の設定、削除、不足しているモデル情報の追加、モデル情報と価格の同期、事前入力グループ、プロバイダー、デプロイの管理を、利用する順に説明します。

### モデルの追加と編集

- モデル管理 - モデルの作成

![モデル管理 - モデルの作成画面](/assets/guide/feature-guide/model-management-add-model-model-information.png)

**操作手順**

1. 「モデル」タブの右上にある「モデルを追加」をクリックして、「モデルの作成」ドロワーを開きます。編集する場合は、モデル名、「編集」、または「情報を追加」をクリックすると、モデル名をタイトルとするドロワーが開きます。
2. 「モデル情報」タブで各フィールドに入力します。
3. 「情報を保存」をクリックします。

<Callout type="info" title="ヒント">

- ドロワーのタイトルの下に「モデル情報、価格設定、チャネルとの関連付けを管理します。各セクションは個別に保存します。」と表示されます。
- ドロワーには「モデル情報」「価格設定」「チャネルとグループ」の 3 つのタブがあります。新規作成時は、まず「モデル情報」のみ入力できます。保存後に「価格設定」と「チャネルとグループ」が利用可能になります。
- 「情報を追加」または「不足しているモデル → 設定」から開いた場合は、モデル名が入力済みで、3 つのタブすべてを利用できます。
- 保存に失敗すると、理由がドロワーの下部に表示されます。
- 価格設定に未保存の変更がある間は、モデル名を変更できません。先に価格設定の変更を保存するか、破棄してください。
- ドロワーを閉じる際にモデル情報または価格設定に未保存の変更があると、「未保存の変更を破棄しますか？」と表示されます。
</Callout>

**モデル情報**

- モデル管理 - モデルの編集 - モデル情報

![モデル管理 - モデルの編集 - モデル情報画面](/assets/guide/feature-guide/model-management-edit-model-model-information.png)

**設定項目の説明**

「モデル情報」は「基本情報」「マッチングルール」「エンドポイント」「状態と同期」の 4 つのセクションに分かれています。以下の表は、タブ内の表示順に並んでいます。

| 設定項目 | セクション | 定義 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- | --- |
| モデル名 | 基本情報 | モデルの一意の識別子。 | 必須。最大 128 文字で、既存のレコードと同じ名前は使用できません。<br/>名前を変更しても、チャネル内のモデル名は変更されず、価格設定も移行されません。既存の価格は元の名前に紐付きます。 | 空欄（情報を追加する場合は入力済み） |
| 説明 | 基本情報 | モデルの説明。 | — | 空欄 |
| アイコン | 基本情報 | モデルのアイコン。 | 最大 128 文字。「プロバイダーのアイコンを継承」または「モデルのアイコンをカスタマイズ」を選択できます。「適用されるアイコン」には、実際に使用されるアイコンが表示されます。 | プロバイダーのアイコンを継承 |
| プロバイダー | 基本情報 | モデルが属するプロバイダー。 | 登録済みのプロバイダーを指定する必要があります。 | 未選択 |
| タグ | 基本情報 | モデルのタグ。 | 合計で最大 255 文字。Enter キーまたはカンマで追加します。 | 空欄 |
| 名前のルール | マッチングルール | このモデル情報を適用するモデル名の条件。 | 4 種類から 1 つを選択します。[名前のマッチングルール](#名前のマッチングルール)を参照してください。一覧の「表示」と同期ウィザードでは「マッチングタイプ」と表記されます。 | 完全一致 |
| エンドポイント設定 | エンドポイント | ユーザーに表示するエンドポイントの種類とカスタムパス。 | 保存時にバックエンドが形式を検証します。[エンドポイント設定](#エンドポイントの設定)を参照してください。 | 空欄 |
| 広場での表示 | 状態と同期 | モデル広場での表示を許可するかどうか。 | 利用可能なチャネルがあり、ユーザーのグループのアクセス条件を満たしている必要もあります。API のアクセス権限には影響しません。 | オン |
| 情報の同期を許可 | 状態と同期 | 「モデル情報の同期」で、プレビューの確認後に選択したフィールドを上書きすることを許可します。 | オフにすると、同期ウィザードに「情報の同期は禁止されています」と表示され、このモデルは変更されません。オンの場合も「モデル情報の同期」を手動で実行する必要があります。 | オン |

**チャネルとグループ**

- モデル管理 - モデルの編集 - チャネルとグループ

![モデル管理 - モデルの編集 - チャネルとグループ画面](/assets/guide/feature-guide/model-management-edit-model-channels-and-groups.png)

このタブは読み取り専用です。有効なチャネルに基づいて、広場での表示状態、「関連付けられたチャネル」（チャネルとその種類）、「有効なグループ」、「対応エンドポイント」が表示されます。完全一致以外のルールでは、「一致するモデル」も表示されます。

<Callout type="info" title="ヒント">
モデルを呼び出せるようにするには、<a href="/ja/docs/guide/feature-guide/admin/channel" target="_blank" rel="noopener noreferrer">チャネル管理</a>でチャネルにモデルを追加してください。
</Callout>

### 価格設定

- モデル管理 - モデルの編集 - 価格設定

![モデル管理 - モデルの編集 - 価格設定画面](/assets/guide/feature-guide/model-management-edit-model-pricing.png)

**価格を設定する手順**

1. モデル行の「価格設定」をクリックするか、編集ドロワーで「価格設定」タブをクリックします。
2. 名前のルールが完全一致以外の場合は、先に「モデルを選択」で一致するモデルを 1 つ選択します。
3. 下部のエディターで価格を設定します。フィールドと課金方式については、<a href="/ja/docs/guide/feature-guide/admin/billing-expression" target="_blank" rel="noopener noreferrer">課金式</a>を参照してください。
4. 「モデル価格を保存」をクリックします。

<Callout type="info" title="ヒント">

- 編集できるのは Root のみです。Admin がこのタブを開くと、「モデルの価格設定はスーパー管理者が管理します。」とだけ表示されます。
- 上部には、現在適用されている課金設定の概要が表示されます。
- <a href="/ja/docs/guide/feature-guide/system-settings/settings-billing#モデル価格" target="_blank" rel="noopener noreferrer">課金と支払いの設定 → モデル価格</a>と同じエディターで、同じ設定を変更します。
- ドロワーを開いた後に別の場所でこのモデルの価格が変更されると、保存に失敗します。「価格設定を再読み込み」をクリックしてから変更してください。
</Callout>

**デフォルトの価格設定に戻す手順**

1. 「デフォルトの価格設定に戻す」をクリックし、確認ダイアログで「デフォルトに戻す」をクリックします。

<Callout type="warn" title="注意">
「デフォルトの価格設定に戻す」を実行すると、このモデルのカスタム価格が削除され、組み込みのデフォルト価格が適用されます。デフォルト価格がないモデルは、価格未設定になります。
</Callout>

### モデルの削除

**操作手順**

1. 行末の ⋯ メニューで「削除」をクリックするか、複数のモデルを選択して「選択したモデルを削除」をクリックします（一度に 1～1000 件）。
2. 「モデルを削除しますか？」の確認ダイアログで、2 つのオプションを必要に応じて選択します。デフォルトではどちらも選択されていません。
3. 「削除」をクリックします。

<Callout type="info" title="ヒント">

- 「メタデータなし」の行にはモデル情報がないため、削除できません。
- どちらのオプションも選択しない場合は、モデル情報のみが削除されます。チャネル内のモデル名、チャネルの機能情報、価格は保持されます。
- 有効なチャネルが引き続きその名前を参照している場合は、一覧の「メタデータなし」の行と「不足しているモデル」に再び表示されます。
- 削除後に、同じ名前でモデル情報を作成し直せます。
</Callout>

**オプションの説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| オプション | 説明 |
| --- | --- |
| すべてのチャネルからも削除 | 各チャネルのモデル一覧から該当する名前を削除し、チャネルの機能情報も更新します。選択したモデルに完全一致以外のルールが含まれる場合、このオプションは利用できません（「完全一致の場合のみ利用可能」と表示されます）。 |
| 価格設定も削除 | 該当するモデル名のカスタム価格を削除します。選択すると「組み込みの価格設定が再び適用される場合があります。」と表示されます。Root のみ選択できます。 |

</div>

<Callout type="warn" title="注意">
「すべてのチャネルからも削除」を選択すると、チャネルのモデル一覧が直接変更されます。削除後は、該当するチャネルからモデルを呼び出せなくなります。復元するには、各チャネルにモデル名を再度追加してください。
</Callout>

### 不足しているモデル情報の追加

- モデル管理 - 不足しているモデル

![モデル管理 - 不足しているモデル画面](/assets/guide/feature-guide/model-management-missing-models.png)

「不足しているモデル」には、有効なチャネルで使用されており、**名前が完全に一致する**モデル情報がないモデル名が一覧表示されます。前方一致、部分一致、後方一致のルールが適用される名前も表示されます。

**操作手順**

1. 「モデル」タブの右上にある ⋯ →「不足しているモデル」をクリックします。
2. 名前で検索し、情報を追加するモデルを探します。
3. 行の「設定」をクリックし、モデル名が入力済みの作成ドロワーで情報を入力して保存します。下部の「不足している情報を同期」をクリックすると、[モデル情報の同期](#モデル情報の同期)ウィザードを開けます。

<Callout type="info" title="ヒント">

- 一覧は 1 ページあたり 20 件です。
- 「不足しているモデル」は、有効なチャネルのみを対象とします。
- モデル一覧の「メタデータなし」の行には、無効なチャネルのモデル名も含まれるため、両者の件数が異なる場合があります。
</Callout>

### モデル情報の同期

「モデル情報の同期」をクリックすると、「モデル情報の同期」ウィザードが開きます。公式メタデータカタログからモデル情報をインポートし、必要に応じてプロバイダーを新規作成します。ウィザードは 4 ステップで構成され、同期するたびにプレビューと確認が必要です。

<Callout type="info" title="ヒント">

- 同期で変更されるのはモデル情報のみです。同期によるチャネルの追加、モデルへのアクセスの許可、価格の設定、モデル名や「情報の同期を許可」スイッチの変更は行われません。
- デフォルトのデータソースは `https://basellm.github.io/llm-metadata` です。デプロイ時に環境変数 `SYNC_UPSTREAM_BASE` で変更できます。ページ上に対応する設定項目はありません。
- サーバーからデータソースにアクセスできる必要があります。ウィザードのステップ 1 には、実際に使用されるモデルとプロバイダーの取得元が表示されます。
- 同期の実行中はウィザードを閉じられません。
</Callout>

**モデルの選択**

- モデル管理 - モデル情報の同期 - モデルの選択

![モデル管理 - モデル情報の同期 - モデルの選択画面](/assets/guide/feature-guide/model-management-sync-information-select-model.png)

**モデルを選択する手順**

1. 「情報の言語」（中国語、英語、日本語）を選択し、「情報のプレビューを読み込む」をクリックします。言語を切り替えると、読み込んだプレビューと選択内容がクリアされます。
2. 「同期範囲」で「このサイトで使用しているモデル」（デフォルト。情報が登録済みのモデルと不足しているモデルが対象）または「上流のモデル一覧」（公式カタログの全モデルが対象）を選択します。
3. 必要に応じて検索するか、「同期可能な項目のみ表示」を選択します。対象のモデルにチェックを入れるか、「同期可能な項目をすべて選択」をクリックして全ページから選択し、「選択した変更をプレビュー」をクリックします。

各モデルの「予定されている操作」については、[同期で予定されている操作](#同期時に予定される操作)を参照してください。

**フィールドのプレビュー**

- モデル管理 - モデル情報の同期 - フィールドのプレビュー

![モデル管理 - モデル情報の同期 - フィールドのプレビュー画面](/assets/guide/feature-guide/model-management-sync-information-preview-fields.png)

選択したモデルごとに「適用」「フィールド」「現在の値」「変更後の値」が表示されます。

- 情報の新規追加では、全 7 フィールドをインポートします。チェックを入れる必要はありません。各フィールドへの影響については、[モデル情報の同期時の上書きルール](#情報同期時の上書きルール)を参照してください。
- 情報の変更では、公式カタログの値と異なるフィールドのみが表示され、デフォルトではどのフィールドも選択されていません。チェックを入れたフィールドは「変更後の値」に置き換えられ、選択しなかったフィールドは現在の値を保持します。「変更フィールドをすべて選択」と「選択をすべて解除」は、選択済みの「情報の変更」対象モデルすべてに適用されます。
- 新規追加するモデルがなく、フィールドも 1 つも選択されていない場合は、「内容を確認」が利用できません。

## ルールと仕組み

このセクションでは、Admin と Root の権限の違い、名前のマッチングルール、エンドポイントの設定形式、情報同期時のフィールドごとの上書きルールについて説明します。

### Admin と Root の違い

モデル情報、プロバイダー、事前入力グループ、モデルデプロイは、Admin と Root の両方が管理できます。モデルの価格設定を変更できるのは Root のみです。

**権限の違い**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 場所 | Root | Admin |
| --- | --- | --- |
| 「価格を同期」ボタン | 表示される | 表示されない |
| 一覧の「価格設定」列 | 現在の価格の概要が表示され、クリックすると「価格設定」タブが開く | 「スーパー管理者」と表示される |
| 行内の「価格設定」ボタン | 表示される | 表示されない |
| 編集ドロワーの「価格設定」タブ | 編集して保存できる | 「モデルの価格設定はスーパー管理者が管理しています。」のみ表示される |
| 削除時の「価格設定も削除」 | チェックできる | チェックできず、その下に「モデルの価格設定はスーパー管理者が管理しています。」と表示される |

</div>

### 名前のマッチングルール

名前のマッチングルールによって、このモデル情報を適用するモデル名が決まります。

**ルールの説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| ルール | マッチング方法 |
| --- | --- |
| 完全一致 | モデル名が完全に一致する場合にのみマッチします。 |
| 前方一致 | その名前で始まるモデル名にマッチします。 |
| 部分一致 | その文字列を含むモデル名にマッチします。 |
| 後方一致 | その名前で終わるモデル名にマッチします。 |

</div>

**マッチングの適用ルール**

- 同じモデル名が複数のモデル情報にマッチする場合は、完全一致、前方一致、後方一致、部分一致の順で、最初に該当するモデル情報が適用されます。
- マッチングルールはモデル情報（説明、アイコン、タグ、プロバイダー、エンドポイント、広場での表示）にのみ適用されます。価格は常に個々のモデル名に対して設定され、ルールでマッチしたモデルには引き継がれません。
- 完全一致以外のルールを使用する場合、チャネル内の個々のモデル名はモデル情報に書き込まれません。そのため、「未登録のモデル」にそれらの名前が表示されることがあります。また、削除時に「すべてのチャネルからも削除」は選択できません。

### エンドポイントの設定

エンドポイントの設定では、ユーザーに表示するモデルのエンドポイントタイプとカスタムパスを指定します。

**入力方法**

- 行ごとに「エンドポイントタイプ」と「設定」を入力します。
- 「JSON モード」に切り替えると、JSON を直接入力できます。
- 「テンプレートを読み込む...」を選ぶと、現在の内容がすべて選択したテンプレート（`openai`、`openai-response`、`anthropic`、`gemini`、`jina-rerank`、`image-generation`、`embeddings`）に**置き換わります**。

**検証ルール**

- 空欄のままにすると未設定になります。入力する場合は、JSON オブジェクトまたはエンドポイントタイプを表す文字列の配列で指定します。
- オブジェクトのキーには、空でないエンドポイントタイプを指定します。値には、`/` で始まるパス、または `path`（`/` で始まるパス）と任意の `method`（`GET`、`POST`、`PUT`、`PATCH`、`DELETE`、`HEAD`、`OPTIONS`）を含むオブジェクトを指定します。

<Callout type="info" title="ヒント">
エンドポイントの設定は、ユーザー向けの表示に使用します。チャネルの Base URL の設定や、上流チャネルの作成は行いません。「チャネルとグループ」タブの「対応エンドポイント」は、有効なチャネルに基づいて判定されます。ここで設定するカスタムエンドポイントとは別に扱われます。
</Callout>

### 情報同期時の上書きルール

情報の同期では、チェックしたフィールドのみが更新されます。

**フィールドごとの変更内容**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| フィールド | 変更内容 |
| --- | --- |
| 説明、アイコン、タグ | 公式の内容に置き換えます。 |
| プロバイダー | このサイトに同名のプロバイダーがない場合は、公式のプロバイダー一覧をもとに新規作成します。 |
| カスタムエンドポイント | ユーザーに表示するエンドポイントタイプとカスタムパスを変更します。 |
| マッチングタイプ | この情報を引き継ぐモデル名の範囲を変更します。価格は引き継がれません。 |
| 広場での表示 | モデル広場での表示を変更します。チャネルの有効状態と既存の呼び出し権限には影響しません。 |

</div>

**同期の対象範囲**

- 「情報の同期を許可」がオフのモデルは処理対象外です。
- 変更候補には、公式の情報と異なるフィールドのみが表示されます。チェックしなかったフィールドは変更されません。

## 保存と反映

このページでは、各操作の確定時に変更が即座に保存されます。ページ全体に適用する保存ボタンはありません。リクエストを処理したノードには即座に反映されます。他のノードへの同期方法は対象によって異なります。

**モデル情報とプロバイダー**

モデル情報、プロバイダー、事前入力グループはデータベースに保存され、管理ページの一覧は保存直後に更新されます。モデル情報の編集、表示・非表示の切り替え、情報の同期、プロバイダーの変更を行うと、リクエストを処理したノードのモデル広場は即座に更新されます。他のノードは通常約 3 秒以内、遅くとも約 1 分で更新されます。ユーザーがすでにモデル広場を開いている場合は、ページを再読み込みすると新しい内容が表示されます。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方法 | 反映タイミング |
| --- | --- | --- |
| モデル情報を編集 | 編集ドロワーの「モデル情報」タブで「情報を保存」をクリックします。 | 上記のタイミングで、新しい情報がモデル広場に表示されます。 |
| 非表示・表示（一括操作を含む） | 行の ⋯ メニューで「モデル広場で非表示にする」または「モデル広場に表示する」をクリックすると、即座に保存されます。 | モデル広場での表示のみに反映され、API の呼び出しには影響しません。 |
| 情報を同期 | プレビューを確認し、「N 件のモデルの変更を適用」をクリックします。 | 選択したモデルの情報をまとめて書き込みます。1 件でも失敗すると、すべての書き込みが取り消されます。「情報の同期を許可」がオフのモデルは処理対象外です。 |
| プロバイダーとその関連付け | プロバイダーの追加や編集では「情報を保存」をクリックします。関連付けの設定や解除、プロバイダーの統合や削除では、プレビューを確認して「変更を適用」をクリックします。 | モデル広場のプロバイダーフィルターとアイコンが更新されます。プレビュー後にデータが変わると適用に失敗するため、再度プレビューを確認する必要があります。 |
| モデルを削除 | 確認ダイアログで「削除」をクリックします。 | モデル情報は即座に削除されます。チャネル内のモデル名、対応機能、価格は保持されます。[モデルの削除](#モデルの削除)を参照してください。 |

</div>

**モデルの価格**

モデルの価格はシステム設定として保存されます。リクエストを処理したノードには即座に反映されます。他のノードには、システム設定の同期に伴い通常約 3 秒以内、遅くとも 1 同期周期以内（デフォルトは 60 秒）に反映されます。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方法 | 反映タイミング |
| --- | --- | --- |
| モデルの価格を変更 | 「価格設定」タブで「モデルの価格を保存」をクリックするか、価格の同期で「変更を確定」をクリックします（Root のみ）。 | 次のリクエストから新しい価格で課金されます。<a href="/ja/docs/guide/feature-guide/admin/billing-expression#保存と反映" target="_blank" rel="noopener noreferrer">課金式</a>を参照してください。 |
| 削除時に「価格設定も削除」にチェックを入れる（Root のみ） | 削除と同時に実行されます。 | 組み込みの価格設定が再び適用される場合があります。 |

</div>

**チャネル、事前入力グループ、デプロイ**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方法 | 反映タイミング |
| --- | --- | --- |
| 削除時に「すべてのチャネルからも削除」にチェックを入れる | 削除と同時に実行されます。 | 同じ操作でチャネルのモデル一覧と対応機能が変更されます。各ノードが新しい設定でルーティングを開始するタイミングは、<a href="/ja/docs/guide/feature-guide/admin/channel#保存と反映" target="_blank" rel="noopener noreferrer">チャネル管理</a>を参照してください。 |
| 事前入力グループ | 新規作成時は「新規作成」、編集時は「変更を保存」をクリックします。 | 次にチャネルの編集ドロワーを開いたときに、新しい内容が読み込まれます。保存済みのチャネルには影響しません。 |
| io.net デプロイ | 作成、設定更新、延長、名前の変更、削除はすべて io.net に直接送信され、New API には保存されません。 | 結果は io.net からの応答で確定します。チャネルの新規作成や変更は行われません。 |

</div>

## 注意事項

- **「すべてのチャネルからも削除」はチャネルを直接変更します。** 削除後に元に戻すには、チャネルにモデル名を追加し直す必要があります。[モデルの削除](#モデルの削除)を参照してください。
- **デプロイは外部リソースです。** デプロイの削除は元に戻せません。終了または変更する前に、そのデプロイを参照しているチャネルから、別の利用可能なチャネルに切り替えてください。[デプロイの確認と管理](#デプロイの確認と管理)を参照してください。
- **モデル名は一意の識別子です。** モデル名を変更しても、チャネル内のモデル名は変更されず、価格も引き継がれません。価格は常に個々のモデル名に対して設定されます。[モデルの追加と編集](#モデルの追加と編集)を参照してください。
- **情報を同期すると、チェックしたフィールドが上書きされます。** 上書きしたくないモデルでは、「情報の同期を許可」をオフにしてください。[情報の同期](#モデル情報の同期)を参照してください。
- **「広場での表示」は呼び出し権限に影響しません。** モデルを呼び出せるかどうかは、チャネル、グループ、API キーの制限によって決まります。[広場での表示状態](#広場での表示状態)を参照してください。

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="モデルがモデル広場に表示されない">
**説明**

まず、一覧で対象モデルの「広場での表示」の状態を確認してください。詳しくは[広場での表示状態](#広場での表示状態)を参照してください。

**考えられる原因**

- 状態が「非表示」の場合、モデル情報の「広場での表示」がオフになっています。
- 状態が「表示不可」の場合、そのモデルを提供するチャネルが無効になっているか、チャネルのモデル一覧にその名前が含まれていません。
- 状態が「表示中」の場合、ユーザーの所属グループにそのモデルへのアクセス権限がありません。

**対処方法**

1. 状態に応じて「広場での表示」をオンにするか、チャネルとユーザーの所属グループを確認してください。
</Accordion>

<Accordion title="一覧に「メタデータ不足」の行が表示される">
**表示メッセージ**

これらの行を選択すると、「モデル名一覧をコピー」以外の一括操作ボタンが無効になります。ボタンにカーソルを合わせると、「先に、選択したすべてのモデルにメタデータを追加してください。」（英語 Add metadata to all selected models first.）と表示されます。

**考えられる原因**

チャネルで使用しているモデル名と完全に一致するモデル情報がありません。完全一致以外のルールでは、これらの行は解消されません。

**対処方法**

1. 「モデル情報を追加」をクリックするか、「モデル情報を同期」でインポートしてください。
2. 一括操作を行う場合は、「メタデータ不足」の行の選択を解除してください。
</Accordion>

<Accordion title="削除したモデルが再び一覧に表示される">
**考えられる原因**

有効なチャネルが引き続きそのモデル名を参照しています。

**対処方法**

1. モデルを完全に削除するには、削除時に「すべてのチャネルからも削除」にチェックを入れてください。このオプションは完全一致ルールの場合のみ使用できます。
</Accordion>

<Accordion title="同期時にモデルを選択できない">
**考えられる原因**

- 「実行予定の操作」が「モデル情報の同期は無効」の場合、そのモデルの「モデル情報の同期を許可」がオフになっています。
- 「実行予定の操作」が「同期元に見つかりません」の場合、公式カタログにそのモデル名がありません。

**対処方法**

1. 同期が必要な場合は、モデル情報で「モデル情報の同期を許可」をオンにしてください。
</Accordion>

<Accordion title="「モデル情報のプレビューを読み込む」をクリックすると失敗する">
**表示メッセージ**

「メタデータのプレビューに失敗しました」（英語 Failed to preview metadata）と表示されます。サーバーが失敗の理由を返した場合は、その英語メッセージがそのまま表示されます。

**考えられる原因**

サーバーがデータソースにアクセスできないか、デプロイ担当者が `SYNC_UPSTREAM_BASE` でデータソースのアドレスを変更しています。

**対処方法**

1. サーバーからデータソースにアクセスできるか確認してください。
</Accordion>

<Accordion title="同期を適用すると再プレビューを求められる">
**表示メッセージ**

`Upstream metadata changed; preview again` または `metadata changed; preview again before applying`（英語のみ）

**考えられる原因**

プレビュー後に、公式カタログまたはこのサイトのモデル情報が変更されました。

**対処方法**

1. 「再プレビュー」をクリックして手順 1 に戻り、選択し直してください。
</Accordion>

<Accordion title="「価格を同期」ボタンや「価格設定」タブが表示されない">
**表示メッセージ**

Admin が「価格設定」タブを開くと、「モデルの価格設定はスーパー管理者が管理しています。」（英語 Model pricing is managed by a super administrator.）と表示されます。

**考えられる原因**

現在のアカウントに Root 権限がありません。モデルの価格設定を変更できるのは Root のみです。

**対処方法**

1. Root に操作を依頼してください。
</Accordion>

<Accordion title="モデル名を変更すると価格が表示されなくなる">
**考えられる原因**

価格はモデル名ごとに保存されます。モデル名を変更しても、価格は新しい名前に引き継がれません。

**対処方法**

1. 新しいモデル名の価格設定を Root に依頼するか、元の名前に戻してください。
</Accordion>

<Accordion title="価格設定列に「一致するモデルごとに設定」と表示される">
**考えられる原因**

モデル名の照合ルールが完全一致に設定されていません。

**対処方法**

1. 「価格設定」タブで対象のモデルを選択してから、価格を設定してください。
</Accordion>

<Accordion title="プロバイダーを削除できない">
**表示メッセージ**

「プロバイダーに関連付けられているモデルレコードが … 件あります。先に関連付けを変更または解除してください。」（英語 Vendors still have … linked model records. Transfer or clear their assignments first.）

**考えられる原因**

このプロバイダーに関連付けられているモデルが残っています。

**対処方法**

1. 「関連モデル」で、対象モデルのプロバイダーを変更するか、関連付けを解除してください。
2. または、「プロバイダーを統合」を使用してください。
</Accordion>

<Accordion title="「デプロイ」タブに無効または接続失敗のメッセージが表示される">
**表示メッセージ**

「モデルデプロイサービスが無効です」（英語 Model deployment service is disabled）または「接続に失敗しました」（英語 Connection failed）

**対処方法**

1. Root に「システム設定」→「モデル」→「モデルデプロイ」で、有効化の設定と API Key を確認してもらってください。
2. 「再試行」をクリックしてください。
</Accordion>

<Accordion title="デプロイが終了した、またはコンテナに異常がある">
**対処方法**

1. デプロイの詳細、コンテナの状態、ログを確認してください。
2. そのデプロイのアドレスを参照しているチャネルが残っていないか確認してください。残っている場合は、先に別の利用可能なチャネルに切り替えてください。
</Accordion>

</Accordions>
