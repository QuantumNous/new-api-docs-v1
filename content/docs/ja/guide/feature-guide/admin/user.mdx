</Callout>

## よく使う操作

ユーザーの追加と編集、クォータの調整、管理者権限の設定、有効化・無効化と昇格・降格、連携とサブスクリプションの管理、Passkey と 2FA のリセット、ユーザーの削除を、利用する順に説明します。

### ユーザーの追加

- ユーザー管理 - ユーザーの新規作成

![ユーザー管理 - ユーザーの新規作成ページ](/assets/guide/feature-guide/user-management-add-user.png)

**操作手順**

1. 右上の「ユーザーを追加」をクリックします。
2. ユーザー名とパスワードを入力します。作成時はパスワードの入力が必須です。
3. 必要に応じて表示名を入力します。空欄の場合はユーザー名が使われます。
4. ロールとして「一般ユーザー」（既定）または「管理者」を選択し、「変更を保存」をクリックします。管理者を作成する場合は、先に[セキュリティ確認](#セキュリティ確認)を完了します。

<Callout type="info" title="ヒント">

- 管理者ユーザーを追加できるのは Root のみです。
- Root が管理者ユーザーを追加または編集する際は、ドロワー下部の「管理者権限」セクションで権限を設定できます。詳細は[管理者権限](#管理者権限)を参照してください。
</Callout>

**設定項目の説明**

「ユーザーの新規作成」ドロワーには「基本情報」と「管理者権限」の 2 つのセクションがあります。「管理者権限」は、Root が「管理者」ロールを選択した場合にのみ表示されます。以下の表は、ドロワーでの表示順に並んでいます。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 設定項目 | 定義 | 入力要件と制限 | 既定値 |
| --- | --- | --- | --- |
| ユーザー名 | ログインに使用するユーザー名。 | 必須。最大 20 文字で、一意である必要があります。追加後は変更できません。 | 空欄 |
| ロール | アカウントのロール。 | 「一般ユーザー」または「管理者」を選択できます。下部に「ユーザーのロールを設定します（Root は指定できません）」と表示されます。Admin は一般ユーザーのみ、Root は一般ユーザーと Admin を作成できます。 | 一般ユーザー |
| 表示名 | 一覧およびユーザー画面に表示される名前。 | 最大 20 文字です。空欄の場合はユーザー名が使われます。ログイン用のユーザー名には影響しません。 | 空欄 |
| パスワード | 初期パスワード。 | 必須。8～128 文字です。入力欄の下にパスワードの強度と推奨事項が表示されます。強度にかかわらず保存できます。 | 空欄 |

</div>

<Callout type="warn" title="注意">
初期パスワードをスクリーンショット、チケット、共有ドキュメントに記載しないでください。
</Callout>

### ユーザー情報の編集

- ユーザー管理 - ユーザーの更新

![ユーザー管理 - ユーザーの更新ページ](/assets/guide/feature-guide/user-management-edit-user-information.png)

**操作手順**

1. 対象ユーザーの行にある鉛筆アイコンをクリックします。
2. 編集可能なフィールドを変更します。
3. 「変更を保存」をクリックします。パスワードまたは管理者権限を変更した場合は、先に[セキュリティ確認](#セキュリティ確認)を完了します。

<Callout type="info" title="ヒント">

- 残りのクォータの変更には「クォータを調整」を使用してください。詳細は[ユーザークォータの調整](#ユーザークォータの調整)を参照してください。
- ロールの変更には、⋯ メニューの「昇格」「降格」を使用してください。詳細は[ロールとステータス](#ロールとステータス)を参照してください。
</Callout>

**設定項目の説明**

「ユーザーの更新」ドロワーには、上から「基本情報」「グループとクォータ」「管理者権限」「連携情報」の 4 つのセクションがあります。「管理者権限」は Root が Admin を編集する場合にのみ表示されます。以下の表は、ドロワーでの表示順に並んでいます。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 設定項目 | セクション | 定義 | 入力要件と制限 | 既定値 |
| --- | --- | --- | --- | --- |
| ユーザー名 | 基本情報 | ログインに使用するユーザー名。 | 読み取り専用です。 | 現在の値 |
| 表示名 | 基本情報 | 一覧およびユーザー側の画面に表示される名前。 | 最大 20 文字です。 | 現在の値 |
| パスワード | 基本情報 | 新しいパスワード。 | 空欄の場合は現在のパスワードが維持されます。新しいパスワードは 8～128 文字で入力します。入力すると、下部にパスワードの強度と推奨事項が表示されます。パスワードを変更すると既存のブラウザーセッションが無効になり、ユーザーは再ログインする必要があります。 | 空欄 |
| グループ | グループとクォータ | ユーザーが現在所属するグループ。 | 現在利用可能なグループから選択します。グループを変更すると、そのユーザーの既存のセッションが無効になります。 | 現在の値 |

| メモ | グループとクォータ | 管理者用の内部メモ。 | 管理者のみ閲覧でき、最大 255 文字です。キー、トークン、不要な機微情報は記載しないでください。 | 現在の値 |
| 連携情報 | 連携情報 | 連携済みのログイン方法。 | GitHub ID、Discord ID、OIDC ID、WeChat ID、メールアドレス、Telegram ID が読み取り専用で表示されます。LinuxDO とカスタム OAuth を含む連携の一覧を確認したり、連携を解除したりする場合は、メニューの「連携を管理」を開きます。詳細は[ユーザーの連携管理](#ユーザーの連携管理)を参照してください。 | — |

</div>

### ユーザークォータの調整

**操作手順**

1. 対象ユーザーの行にある鉛筆アイコンをクリックし、編集ドロワーを開きます。
2. 「残りのクォータ」の横にある「クォータを調整」をクリックします。
3. 「モード」で「追加」「減少」「上書き」のいずれかを選択します。
4. 金額を入力し、「確認」をクリックします。

<Callout type="info" title="ヒント">

- ダイアログの上部に「現在のクォータ：… +… = …」のように、調整結果のプレビューが表示されます。
- 「追加」と「減少」には 0 より大きい金額を入力します。「上書き」には 0 または負の値も入力できます。
- クォータの調整は「変更を保存」とは別に適用され、セキュリティ確認は不要です。
- 調整に成功すると、対象ユーザーの使用ログに「チャージ」タイプの記録が 1 件追加されます。
</Callout>

### 管理者権限

管理者権限は、Admin の権限マトリクスです。Root が「管理者」ロールのユーザーを新規作成または編集すると、ドロワーの下部に「管理者権限」セクションが表示され、そのアカウントの既定の Admin 権限を上書きできます。リソースごとに 1 行が表示され、権限ボタンをクリックすると権限を付与または取り消せます。リソース名の横にある ⓘ で各項目の説明を確認できます。権限を変更するには[セキュリティ確認](#セキュリティ確認)が必要です。保存した権限がいつ反映されるかは、[保存と反映](#保存と反映)を参照してください。

**権限の説明**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| リソース | 権限名 | Admin の既定値 | 説明 |
| --- | --- | --- | --- |
| 監査ログ | 他のアカウントの監査ログを表示 | いいえ | 「user および admin ロールの監査ログを表示します。root レベルのログは常に除外されます。」 |
| チャネル管理 | チャネルの読み取り | はい | 「キーを含まないチャネル一覧と詳細を表示します。」 |
| チャネル管理 | チャネルの運用 | はい | 「チャネルのテストと残高の更新を行い、個別、一括、またはラベル単位でチャネルを有効化・無効化します。」 |
| チャネル管理 | チャネルルーティングの編集 | はい | 「モデル、グループ、ルーティングルールなど、機密性のない設定を編集します。」 |
| チャネル管理 | 機密性の高いチャネル設定の編集 | いいえ | 「チャネルを作成するか、キー、ベース URL、上書きルールを編集します。」 |
| チャネル管理 | チャネルキーの表示 | いいえ | 「セキュリティ確認後にチャネルキーの全体を表示するための予約権限です。」 |
| タスクプラグイン | タスクプラグインの関連付け | いいえ | 「登録済みのタスクプラグインを一覧表示し、タスクプラグイン用チャネルの作成時や編集時に関連付けます。」 |

</div>

### ロールとステータス

- ユーザー管理 - 操作メニュー

![ユーザー管理 - 操作メニューページ](/assets/guide/feature-guide/user-management-operations.png)

**操作手順**

1. 対象ユーザーの行にある ⋯ をクリックし、「有効化」「無効化」「昇格」「降格」のいずれかを選択します。
2. [セキュリティ確認](#セキュリティ確認)を完了します。

**操作の説明**

| 操作 | 対象 | 動作と制限 |
| --- | --- | --- |
| 有効化 | 無効なユーザー | ステータスを有効に変更します。対象のロール階層に応じた権限が必要です。 |
| 無効化 | 有効なユーザー | ステータスを無効に変更します。Root は無効化できません。無効化すると、アカウントの記録を保持したまま、ログインと API 呼び出しを一時的に停止できます。 |
| 昇格 | 一般ユーザー | 一般ユーザーを Admin に昇格できるのは Root のみです。 |
| 降格 | Admin | Admin を一般ユーザーに変更します。Root は降格できません。降格時には、そのアカウントに対する権限の個別上書き設定が消去され、既存のセッションが無効になります。 |

<Callout type="info" title="ヒント">
ロールまたはステータスに認証上重要な変更があった場合、システムは認証状態を更新し、関連キャッシュを消去して、ユーザーのセッションを無効にします。
</Callout>

### ユーザーの連携管理

- ユーザー管理 - アカウント連携管理

![ユーザー管理 - アカウント連携管理ページ](/assets/guide/feature-guide/user-management-user-binding.png)

アカウント連携管理ダイアログには、メールアドレス、GitHub、Discord、OIDC、WeChat、Telegram、LinuxDO、設定済みのカスタム OAuth プロバイダーが表示されます。無効になったプロバイダーも、過去の連携情報に基づいて一覧に表示される場合があります。

**操作手順**

1. 対象ユーザーの ⋯ をクリックして操作メニューを開き、「連携を管理」を選択します。
2. ダイアログには既定で連携済みの方法が表示されます。「すべて表示」をクリックすると、未連携のプロバイダーと無効なプロバイダーも表示され、ボタンが「連携済みのみ」に切り替わります。
3. 連携を解除する場合は、連携済みプロバイダーのカード右上にある連携解除アイコンをクリックします。「連携解除の確認」で確定し、[セキュリティ確認](#セキュリティ確認)を完了します。

<Callout type="warn" title="注意">

- アカウント連携管理ダイアログで行えるのは連携の解除のみです。メールアドレス、OAuth、Passkey などのログイン方法をユーザーに代わって新たに設定することはできません。
- 連携を解除する前に、ユーザーにパスワードまたは別の利用可能な復旧手段があることを確認してください。解除後は、そのアカウント連携を使ってログインできなくなります。
</Callout>

### ユーザーのサブスクリプション管理

- ユーザー管理 - ユーザーのサブスクリプション管理

![ユーザー管理 - ユーザーのサブスクリプション管理ページ](/assets/guide/feature-guide/user-management-user-subscription.png)

**操作手順**

1. 対象ユーザーの ⋯ をクリックし、「サブスクリプションを管理」を選択して、「ユーザーのサブスクリプション管理」ドロワーを開きます。
2. 一覧で、そのユーザーのサブスクリプション記録を確認したり、以下の操作を行ったりできます。

**サブスクリプション一覧の説明**

| フィールド | 説明 |
| --- | --- |
| ID | サブスクリプション記録の一意の識別子。 |
| プラン | プラン名とサブスクリプションの登録元。管理者が代理で追加した場合、登録元は通常 `admin` です。 |
| ステータス | 有効、無効化済み、期限切れ。 |
| 有効期間 | 開始日時と終了日時。サブスクリプション作成時点のプランの有効期間に基づいて計算されます。 |
| 総クォータ | 使用済みクォータと総クォータを「使用済み／合計」の形式で表示します。総クォータが 0 の場合は「無制限」と表示されます。単位はインスタンスの課金設定に従います。 |
| 操作 | 行のメニューから「クォータをリセット」「無効化」「削除」を選択できます。サブスクリプションの追加には、上部の「サブスクリプションを追加」を使用します。 |

**サブスクリプションを追加する手順**

1. 上部のプラン選択欄で、管理画面から追加できるプランを選択します。
2. 「サブスクリプションを追加」をクリックします。

<Callout type="info" title="ヒント">

- 管理者が代理でサブスクリプションを追加する場合、決済注文は作成されません。API を利用するには、インスタンスで決済コンプライアンスの確認が完了している必要があります。API はプラン ID とユーザーごとの購入上限も再確認します。
- 購入上限には、有効、期限切れ、無効化済みを含め、そのユーザーが同じプランで登録した既存のサブスクリプション記録がすべて集計されます。購入枠が空くのは、古い記録を削除した場合のみです。
</Callout>

**クォータをリセットする手順**

1. 対象プランの有効なサブスクリプション行で操作メニューを開き、「クォータをリセット」を選択します。
2. 必要に応じて「次回のリセット日時を更新」をオンのままにするか、オフにします。このスイッチは既定でオンです。
3. 確認ダイアログで「クォータをリセット」をクリックします。

<Callout type="info" title="ヒント">

- リセットは、そのユーザーが対象プランで利用している、有効かつ期限内のサブスクリプションすべてに適用されます。
- リセットすると、対象のサブスクリプションの使用済みクォータが 0 になります。
- スイッチをオンにすると、現在のプランのリセットルールに基づいて次回のリセット日時を再計算します。オフにすると、使用済みクォータのみを 0 にし、既存のリセット日時を維持します。
- 完了メッセージには、実際にリセットされた有効なサブスクリプションの件数が表示されます。
</Callout>

**無効化と削除の比較**

「クォータをリセット」と「無効化」は、「有効」ステータスのサブスクリプションにのみ使用できます。「削除」はどのステータスでも使用できます。有効なサブスクリプションを削除する前に、無効化で要件を満たせるか確認してください。

| 影響範囲 | サブスクリプションの無効化 | サブスクリプションの削除 |
| --- | --- | --- |
| 処理方法 | 記録を保持し、ステータスを「無効化済み」、終了日時を現在の日時に変更します。 | サブスクリプション記録全体を完全に削除します。 |
| サブスクリプション記録 | サブスクリプション履歴、プラン情報、総クォータ、使用済みクォータ、登録元、グループのスナップショットを保持します。 | 記録と、記録内の利用権、クォータ、ステータス、日時、グループのスナップショットがすべて消去されます。 |
| 以降の新規リクエスト | 有効なサブスクリプションとして認識されなくなり、新規リクエストのクォータ供給元として使用できなくなります。 | 有効なサブスクリプションとして認識されなくなります。 |
| ユーザーグループ | 元のグループに戻る場合があります。 | 同様に元のグループに戻る場合があります。その後、スナップショットを削除します。 |
| ウォレット残高 | ウォレット残高は増えません。 | ウォレット残高は増えません。 |
| 支払額 | 返金も決済注文の変更も行いません。 | 返金も決済注文の変更も行いません。 |
| 未使用クォータ | 未使用クォータは返還されず、使用済みクォータもリセットされません。 | サブスクリプション記録とともに消去されます。ウォレットや別のアカウントへの移行は行われません。 |
| 使用ログ／タスクログ | 削除されません。 | 削除されません。ログ内のサブスクリプション ID は、削除済みの記録を指す場合があります。 |
| 購入回数の上限 | 記録が残るため、引き続きプランの購入回数に含まれます。 | 削除後は、既存の記録件数に含まれません。 |
| 復旧方法 | 無効化を取り消す機能はありません。サブスクリプションを作成し直す必要があります。 | 復旧機能はなく、通常は復元できません。 |
| 処理中のリクエスト／タスク | 記録が残るため、通常はサブスクリプション ID を使って後続の精算や返金を完了できます。 | サブスクリプション ID での後続の照会に失敗し、精算や返金を完了できない場合があります。 |

<Callout type="warn" title="注意">

- サブスクリプションの効力を停止し、履歴をすべて残す場合は「無効化」を使用してください。
- 「削除」は、記録に誤りがある場合、テストデータの場合、または履歴を保持する必要がないと確認できた場合にのみ使用してください。
- 返金が必要な場合は、別途返金手続きを行ってください。無効化や削除では返金されません。
- 削除する前に、処理中のリクエスト、非同期タスク、未完了の返金がないことを確認してください。
</Callout>

### Passkey のリセット

- ユーザー管理 - Passkey のリセット

![ユーザー管理 - Passkey のリセットページ](/assets/guide/feature-guide/user-management-reset-passkey.png)

<Callout type="warn" title="注意">
リセットする前に、対象ユーザーが利用できるログイン手段を確認してください。設定済みのパスワード、連携済みで利用可能な外部アカウント、またはリセットメールを受信できる連携済みメールアドレスのいずれかが必要です。利用できる手段がない場合、リセット後にログインできず、Passkey も再登録できません。
</Callout>

**操作手順**

1. ユーザー行のメニューで「Passkey をリセット」を選択します。
2. 確認ダイアログで確定し、[セキュリティ確認](#セキュリティ確認)を完了します。

<Callout type="info" title="ヒント">

- システムは対象ユーザーの既存の Passkey 認証情報を削除し、すべてのログインセッションを無効にします。成功すると「パスキーが正常にリセットされました」と表示されます。
- パスワードなしのログインを再開するには、ユーザーが Passkey を再登録する必要があります。
</Callout>

### 2FA のリセット

- ユーザー管理 - 2FA のリセット

![ユーザー管理 - 2FA のリセットページ](/assets/guide/feature-guide/user-management-reset-2fa.png)

**操作手順**

1. ユーザー行のメニューで「2FA をリセット」を選択します。
2. 確認ダイアログで確定し、[セキュリティ確認](#セキュリティ確認)を完了します。

<Callout type="info" title="ヒント">

- システムは対象ユーザーの既存の 2FA 認証要素とバックアップコードを削除し、認証バージョンを更新して、すべてのログインセッションを無効にします。成功すると「二要素認証がリセットされました」と表示されます。
- ユーザーは「セキュリティとアクセス」ページで 2FA を再設定する必要があります。
</Callout>

### ユーザーの削除

<Callout type="warn" title="注意">

- 対象ユーザーより上位のロールを持つ操作者のみ実行できます。この手順で Root アカウントを削除することはできません。
- このページには復旧機能がないため、組織で保持が必要な監査情報は削除前にエクスポートするか、保存してください。
- 「削除」は取り消せない完全削除です。ログインや API 呼び出しを一時的に停止する場合は「無効化」を使用してください。「削除」は、対象データの範囲、保持要件、削除後の復旧方針を確認したうえで実行してください。
- ここで削除したユーザーは一覧から消えます。ユーザーが「セキュリティとアクセス」ページで自ら退会した場合は、「退会済み」としてアカウントが一覧に残り、操作はできません。
</Callout>

**操作手順**

1. 対象行の ⋯ メニューを開き、「削除」を選択します。
2. 「よろしいですか？」という確認ダイアログで「削除」をクリックします。ダイアログには「この操作は取り消せません」と表示されます。
3. [セキュリティ確認](#セキュリティ確認)を完了します。

<Callout type="info" title="ヒント">
完全削除では、ユーザーのメインレコードと、システム上で明示的に関連付けられている次の認証データが消去されます。

- API トークンおよびその他のユーザー認証トークン
- ブラウザーセッションおよび認証フローの記録
- Passkey 認証情報
- 2FA の設定とバックアップコード
- 組み込みの外部認証で使用される ID の割り当て記録
- カスタム OAuth の連携情報
</Callout>

## ルールと仕組み

ロールの階層と、セキュリティ確認が必要な操作について説明します。

### ロールの階層

| ロール | 管理範囲 |
| --- | --- |
| ユーザー | 一般ユーザー。ユーザー管理ページにはアクセスできません。 |
| Admin | 一般ユーザーを管理できます。同じ階層の Admin や Root のアカウント情報、セキュリティ設定は管理できません。 |
| Root | 一般ユーザーと Admin を管理できます。Root アカウントについては、アカウント情報の編集、連携管理、サブスクリプション管理が可能です。無効化、降格、削除、Passkey のリセット、2FA のリセットは画面から実行できません。 |

### セキュリティ確認

以下の操作を確定する前に、「認証後にユーザーを削除」などのタイトルが付いた認証ダイアログが表示されます。操作者が本人確認を再度行い、認証に成功すると操作が実行されます。

- ユーザーの有効化、無効化、昇格、降格
- ユーザーの削除
- Passkey のリセット、2FA のリセット
- 「連携を管理」での連携解除
- ユーザー編集時のパスワードまたは管理者権限の変更
- 「管理者」ロールのユーザーの作成

認証方法は、個人アカウントでセキュリティ上重要な操作を行う場合と同じです。2FA を有効にしている場合や Passkey を登録している場合は、利用可能な 2FA または Passkey を使用します。それ以外の場合はアカウントのパスワードを使用します。パスワードがないアカウントでは、連携済みの外部ログインを使用します。詳細は<a href="/ja/docs/guide/feature-guide/system-settings/settings-auth#ログイン時の検証とセキュリティ" target="_blank" rel="noopener noreferrer">認証設定</a>を参照してください。

<Callout type="info" title="ヒント">

- 一般ユーザーの作成、表示名・グループ・メモのみの変更、「クォータを調整」、サブスクリプション管理には、セキュリティ確認は不要です。
- パスワードログインまたは Passkey 機能を無効にすると、その方法は認証に使用できません。操作者にほかの利用可能な方法がない場合は、上記の操作を完了できないため、先に<a href="/ja/docs/guide/feature-guide/user/security#2-段階認証を有効にする" target="_blank" rel="noopener noreferrer">セキュリティとアクセス</a>ページで 2FA を有効にしてください。
</Callout>

| --- | --- | --- |
| 有効化、無効化、昇格、降格 | ⋯ メニュー → セキュリティ確認 | すぐに反映されます。ステータスまたはロールが実際に変わると、セッションが無効化されます。ユーザーを無効化すると、次のリクエストからそのユーザーの API キーを使ったリクエストが拒否されます。降格すると、そのアカウントの管理者権限の上書き設定もクリアされます。 |
| 管理者権限 | 編集ドロワーで「変更を保存」をクリックして確定します。セキュリティ確認が必要です。 | リクエストを処理したノードではすぐに反映されます。他のノードでは約 3 秒以内に再読み込みされます（遅くとも 1 同期周期以内。既定値は 60 秒）。セッションは無効化されません。同期周期は環境変数 `SYNC_FREQUENCY` で秒単位で設定します。変更後は再起動が必要です。このページに該当する設定項目はありません。 |
| パスワードの変更 | 編集ドロワーに新しいパスワードを入力し、「変更を保存」をクリックします。セキュリティ確認が必要です。 | すぐに反映され、セッションが無効化されます。 |
| アカウント連携の解除 | 「アカウント連携の管理」で連携解除アイコンをクリックし、「連携解除を確定」を選択してセキュリティ確認を完了すると、「… の連携を解除しました」と表示されます。 | すぐに反映され、以降は連携を解除したアカウントではログインできなくなります。ログイン済みのセッションは無効化されません。 |
| パスキーのリセット、2FA のリセット | ⋯ メニュー → 確認 → セキュリティ確認の順に進むと、「パスキーをリセットしました」または「二要素認証をリセットしました」と表示されます。 | 該当する認証情報がすぐに削除され、セッションが無効化されます。 |
| ユーザーの削除 | ⋯ メニュー →「よろしいですか？」→ セキュリティ確認の順に進むと、「ユーザーを削除しました」と表示されます。 | すぐに削除され、復元できません。詳細は[ユーザーの削除](#ユーザーの削除)を参照してください。 |

</div>

## 注意事項

- **ユーザーの削除は取り消せません。** ログインと API 呼び出しを一時的に停止する場合は、「無効化」を使用してください。詳細は[ユーザーの削除](#ユーザーの削除)を参照してください。
- **ロール階層による制限があります。** Admin が管理できるのは一般ユーザーのみです。ユーザーの昇格と管理者の作成は Root のみ実行できます。詳細は[ロール階層](#ロールの階層)を参照してください。
- **セキュリティ確認を完了できない場合があります。** パスワードログインまたはパスキー機能を無効にすると、該当する方式をセキュリティ確認に使用できなくなります。操作者にほかの利用可能な方式がない場合、セキュリティ確認が必要な操作は実行できません。詳細は[セキュリティ確認](#セキュリティ確認)を参照してください。
- **連携を解除する前に、ユーザーが引き続きログインできることを確認してください。** 連携を解除したりパスキーをリセットしたりする前に、ユーザーがパスワードなど、ほかのログイン方法を利用できることを確認してください。詳細は[ユーザーのアカウント連携管理](#ユーザーの連携管理)と[パスキーのリセット](#passkey-のリセット)を参照してください。
- **サブスクリプションを無効化または削除しても、返金は行われません。** どちらの操作でも未使用のクォータは返還されません。返金が必要な場合は別途処理してください。詳細は[ユーザーのサブスクリプション管理](#ユーザーのサブスクリプション管理)を参照してください。

<Accordion title="ユーザーの管理操作時に、同等以上の権限レベルのユーザー情報を更新する権限がないと表示される">

**説明**　Admin と Root では管理できる範囲が異なり、その範囲を超える操作はサーバー側で拒否されます。よく表示されるメッセージは以下のとおりです。

| 表示メッセージ | 考えられる原因 | 対処方法 |
| --- | --- | --- |
| 「同等以上の権限レベルのユーザー情報を更新する権限がありません」（英語：No permission to update users of same or higher permission level） | Admin が同じ権限レベルの Admin または Root のアカウントを操作しようとした。 | Root に操作を依頼してください。 |
| 「一般の管理者は、他のユーザーを管理者に昇格させることができません」（英語：Regular administrators cannot promote other users to administrator） | ユーザーを昇格できるのは Root のみです。 | Root に昇格を依頼してください。 |
| 「自分と同等以上の権限レベルを持つユーザーは作成できません」（英語：Cannot create users with permission level equal to or higher than yourself） | Admin が作成できるのは一般ユーザーのみです。 | Root に管理者の作成を依頼してください。 |

</Accordion>

<Accordion title="確認ダイアログに「この操作に使用できる確認方法がありません。」と表示される">

**表示メッセージ**　「この操作に使用できる確認方法がありません。」（英語：No verification method is available for this action.）

**考えられる原因**　操作者に利用可能な確認方法がありません。パスワードログインまたはパスキー機能を無効にすると、該当する方式をセキュリティ確認に使用できなくなります。ダイアログには、各方式を利用できない理由が表示されます。

**対処方法**

1. <a href="/ja/docs/guide/feature-guide/user/security#2-段階認証を有効にする" target="_blank" rel="noopener noreferrer">セキュリティとアクセス</a>ページで 2FA を有効にします。
2. 操作を再実行します。

</Accordion>

<Accordion title="ユーザーのパスワードまたはグループを変更すると、そのユーザーに再ログインが求められる">

**説明**　パスワードまたはグループが実際に変更されると、対象ユーザーの既存のブラウザーセッションが無効化されます。これは仕様どおりの動作です。有効化、無効化、昇格、降格によってステータスまたはロールが実際に変わった場合や、パスキーまたは 2FA をリセットした場合も、セッションは無効化されます。

**対処方法**

1. ユーザーに再ログインするよう伝えてください。利用を中断させたくない場合は、利用中のパスワードやグループの変更を避けてください。

</Accordion>

<Accordion title="ユーザーのサブスクリプションクォータをリセットすると「このユーザーには、このプランの有効なサブスクリプションがありません」と表示される">

**表示メッセージ**　「このユーザーには、このプランの有効なサブスクリプションがありません」（英語：This user has no active subscription to this plan）

**考えられる原因**　選択したプランに、ステータスが有効で終了日時に達していないサブスクリプションがありません。サブスクリプションの期限が切れている、すでに無効化されている、一度も追加されていないなどの可能性があります。

**対処方法**

1. サブスクリプション一覧でステータスを確認します。
2. 必要に応じて、先にサブスクリプションを追加します。

</Accordion>

</Accordions>
