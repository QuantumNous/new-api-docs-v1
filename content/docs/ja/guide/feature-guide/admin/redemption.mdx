- Admin と Root のみアクセスできます。サイドバーの「管理者」→「引き換えコード」から開きます。
- クォータ引き換えコードを一括作成して配布できます。名前、クォータ、有効期限、有効化の状態を管理し、無効になった引き換えコードを削除できます。
- 引き換えコードを作成するには、事前に Root が決済コンプライアンス規約を確認する必要があります。[権限とコンプライアンスの前提条件](#権限とコンプライアンスの前提条件)を参照してください。

<Callout type="info" title="ヒント">

- 引き換えコードは一度だけ使えるクォータの引き換え用コードです。ユーザーがウォレットページで引き換えると、クォータがユーザーの残高に加算されます。
- クォータと有効期限は作成時に入力します。クォータの表示単位は、サイトの課金設定によって決まります。
- このページでは Admin と Root の操作権限は同じです。「管理者権限」には引き換えコードに関する権限項目はありません。
- 「システム設定」→「サイトとブランド」→「サイドバーモジュール」→「管理者エリア」の設定は、メニュー項目の表示のみを制御します。管理者権限は取り消されません。
- 特定の Admin に引き換えコード機能を使わせないようにするには、そのアカウントのロールを変更する（一般ユーザーに<a href="/ja/docs/guide/feature-guide/admin/user#ロールとステータス" target="_blank" rel="noopener noreferrer">降格</a>するなど）か、デプロイ環境側でアクセスを制御する必要があります。
</Callout>

## よく使う操作

引き換えコードの作成、コピーと配布、編集、有効化と無効化、削除、および無効な引き換えコードの一括削除を、利用する順に説明します。

### 引き換えコードの作成

- 引き換えコード管理 - 引き換えコードの作成

![引き換えコード管理 - 引き換えコードの作成画面](/assets/guide/feature-guide/redemption-create.png)

- 引き換えコード管理 - 引き換えコードの作成完了

![引き換えコード管理 - 引き換えコードの作成完了画面](/assets/guide/feature-guide/redemption-save.png)

**前提条件**

- Root が最新版の決済コンプライアンス規約を確認済みであること。[権限とコンプライアンスの前提条件](#権限とコンプライアンスの前提条件)を参照してください。

**操作手順**

1. ページ右上の「コードを作成」をクリックします。
2. 「引き換えコードを作成」ドロワーで、名前、クォータ、有効期限、個数を入力します。
3. 「変更を保存」をクリックします。
4. 「引き換えコードの作成完了」ウィンドウが開きます。配布用リストを保存する場合は「ファイルとして保存」にチェックを入れ、ファイル形式と含める項目を選択します。
5. 「完了」をクリックします。

<Callout type="warn" title="引き換えコードの取り扱いに注意">
  コードの全文は、譲渡可能なクォータの引き換え用コードとして利用できます。公開するスクリーンショット、グループチャット、サポートチケット、ログ、コードリポジトリには掲載しないでください。一括作成後は配布先とバッチを記録し、未使用コードの平文コピーへのアクセスも制限してください。
</Callout>

### 引き換えコードのコピーと配布

**1 件ずつコピーする手順**

1. 対象行の「引き換えコード」列にあるコピーアイコンをクリックします。カーソルを合わせると「コードをコピー」と表示されます。

**一括コピーの手順**

1. 現在のページでコピーする引き換えコードにチェックを入れます。
2. ページ下部の一括操作バーにあるコピーアイコンをクリックします。カーソルを合わせると「選択したコードをコピー」と表示されます。

**コピー形式**

一括コピーでは、1 行につき 1 個の引き換えコードが次の形式でコピーされます。

```text
名称<Tab>完整兑换码
```

<Callout type="info" title="ヒント">

- マスクされた引き換えコードをクリックすると、「コードの全文」が開き、コード全体を確認できます。
- このページには引き換えコードのインポート機能はありません。一覧からファイルをエクスポートすることもできません。
- ファイルは「引き換えコードの作成完了」ウィンドウで一度だけ保存できます。
- コピーした内容や保存したファイルは、アクセスを管理できる環境で取り扱ってください。コードの全文を通常のスプレッドシートや共有ドキュメントに長期間保管することは避けてください。
</Callout>

### 引き換えコードの有効化と無効化

**操作手順**

1. 対象行の ⋯ メニューをクリックします。
2. 「無効にする」または「有効にする」を選択します。

<Callout type="info" title="ヒント">

- 「未使用」の引き換えコードのメニューには「無効にする」、「無効」の引き換えコードのメニューには「有効にする」が表示されます。
- 「使用済み」と「期限切れ」の引き換えコードのメニューには「削除」のみが表示されます。
- 選択すると確認ダイアログを表示せず、すぐに処理を実行します。
- 有効期限を過ぎた「無効」の引き換えコードを有効にすると、「期限切れ」と表示され、引き続き引き換えには使えません。
</Callout>

### 引き換えコードの削除

**1 件ずつ削除する手順**

1. 対象行の ⋯ メニューをクリックし、「削除」を選択します。
2. 「よろしいですか？」の確認ダイアログで「削除」をクリックします。

**一括削除の手順**

1. 現在のページで削除する引き換えコードにチェックを入れます。
2. ページ下部の一括操作バーにある赤い削除アイコンをクリックします。カーソルを合わせると「選択した引き換えコードを削除」と表示されます。
3. 「引き換えコードを … 個削除しますか？」の確認ダイアログで「削除」をクリックします。

<Callout type="warn" title="注意">

- ステータスに関係なく削除されます。「未使用」の引き換えコードも削除の対象です。
- 削除したコードを復元する機能はありません。配布を一時停止する場合は「無効にする」を使用してください。
</Callout>

### 無効な引き換えコードの削除

- 引き換えコード管理 - 無効な引き換えコードの削除

![引き換えコード管理 - 無効な引き換えコードの削除画面](/assets/guide/feature-guide/redemption-delete-invalid.png)

「無効なコードを削除」は、サイト全体を対象にした一括削除操作です。現在の検索条件、フィルター、チェックボックスの選択状態には左右されません。

**削除対象**

- 「使用済み」の引き換えコード
- 「無効」の引き換えコード
- 無効化されていないものの、有効期限を過ぎた引き換えコード（サーバー時刻で判定）

**操作手順**

1. ページ右上の「無効なコードを削除」をクリックします。
2. 「無効な引き換えコードを削除しますか？」の確認ダイアログで「無効なコードを削除」をクリックします。

<Callout type="warn" title="注意">

- 削除したコードを復元する機能はありません。
- 「無効」の引き換えコードも削除されます。後で有効にする予定のコードがある場合は、そのコードを有効にするまで「無効なコードを削除」を実行しないでください。
</Callout>

## ルールと仕組み

引き換えコードの作成とユーザーによる引き換えの前提条件、および引き換え時の検証と結果を説明します。

### 権限とコンプライアンスの前提条件

**コンプライアンスルール**

- Root が「システム設定」→「課金と決済」→「決済ゲートウェイ」で最新版の決済コンプライアンス規約を確認すると、管理者が引き換えコードを作成できるようになり、ユーザーのウォレットページに引き換え欄が表示されます。詳細は<a href="/ja/docs/guide/feature-guide/system-settings/settings-billing#支付合规确认" target="_blank" rel="noopener noreferrer">決済コンプライアンスの確認</a>を参照してください。
- コンプライアンスの状態が「確認済み」であり、確認済みの規約バージョンが最新版と一致している必要があります。
- 規約の確認は、Root のコンソールセッションからのみ行えます。アクセストークンでこのセッションを代用することはできません。
- 規約が未確認の場合やバージョンが一致しない場合でも、既存の引き換えコードの表示、編集、有効化、無効化、削除は可能です。コードの作成とユーザーによる引き換えは拒否されます。

### 引き換えルール

ユーザーはウォレットページの「引き換えコードをお持ちですか？」欄にコードを入力して引き換えます。操作手順は<a href="/ja/docs/guide/feature-guide/user/wallet#引き換えコード" target="_blank" rel="noopener noreferrer">ウォレット</a>を参照してください。

**検証と結果**

- 引き換えできるのは「未使用」のコードのみです。無効化されておらず、有効期限内である必要があります。期限切れかどうかはサーバー時刻で判定します。
- 同じ引き換えコードに対してリクエストを繰り返したり、同時に送信したりしても、成功するのは最大 1 回です。
- 引き換えに成功すると、コードのステータスは「使用済み」になり、引き換えたユーザーと引き換え日時が記録されます。
- クォータはユーザーの残高に加算されます。そのユーザーの使用ログには「チャージ」タイプのレコードが 1 件追加され、引き換えコードに関する情報としては ID のみが記録されます。
- 引き換えに失敗した場合は、理由にかかわらず、ユーザー側に「引き換えに失敗しました。しばらくしてから再試行してください」と表示されます。[よくある質問](#よくある質問)を参照してください。

| 検索欄 | 一覧上部のツールバー | プレースホルダーは「名前または ID で絞り込み...」です。入力すると自動で検索されます。検索キーワードはページの URL に保持されます。 |
| ステータス | 一覧上部のツールバー | 「未使用」「無効」「使用済み」「期限切れ」から 1 つ選択します。ポップアップの上部で選択肢を検索できます。選択済みの場合、下部に「フィルターをクリア」が表示されます。選択した値はページの URL に保持されます。 |
| リセット | 「表示」の左側 | キーワードまたはステータスで絞り込んでいる場合に表示され、両方の条件をクリアします。 |
| 表示 | 一覧上部のツールバーの右側 | 「列の切り替え」で、ID、名前、ステータス、引き換えコード、クォータ、作成日時、有効期限、引き換えユーザーの各列の表示と非表示を切り替えます。設定は保存されず、ページを再読み込みすると元に戻ります。 |
| ページネーション | 一覧の下部 | 「合計：…」が表示されます。「ページあたりの行数」は 10、20、30、40、50、100 から選択できます。既定はデスクトップで 20 件、モバイルで 10 件です。ページ番号とページあたりの行数はページの URL に保持されます。 |

</div>

<Callout type="info" title="ヒント">

- キーワードが数字の場合、ID が完全に一致するか、名前の先頭がその数字で始まるコードがヒットします。それ以外のキーワードでは、名前の先頭が一致するコードのみがヒットします。
- 「ステータス」フィルターは、サーバー時刻で期限切れを判定します。
- 列ヘッダーで並べ替えることはできません。
</Callout>

## 保存と反映

引き換えコードの保存先はデータベースのみで、キャッシュは使用しません。以下の操作は、各ノードで次回の引き換えから反映されます。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方法 | 反映されるタイミング |
| --- | --- | --- |
| 引き換えコードの作成 | 「引き換えコードを作成」ドロワーで「変更を保存」をクリックすると、「引き換えコードの作成完了」が開きます。<br/>1 個作成した場合は「引き換えコードを作成しました」と表示されます。<br/>複数作成した場合は「引き換えコードを … 個作成しました」と表示されます。 | すぐに引き換えできます。 |
| 編集 | 「引き換えコードを更新」ドロワーで「変更を保存」をクリックすると、「引き換えコードを更新しました」と表示されます。 | すぐに反映され、以降の引き換えにのみ適用されます。引き換え済みの分は変わりません。 |

| 期限切れ | 操作は不要です。 | サーバー時刻が有効期限に達すると引き換えできなくなります。一覧の「期限切れ」は、ブラウザーの現在時刻に基づいて表示されます。 |

</div>

## 注意事項

- **コードの全文はクォータの引き換えに使用できます。** 配布と保管の方法は、[引き換えコードの作成](#引き換えコードの作成)の注意事項を参照してください。
- **削除したコードは復元できません。** 配布を一時停止する場合は「無効にする」を使用してください。「無効なコードを削除」を実行すると、サイト内の「無効」の引き換えコードがすべて削除されます。[無効な引き換えコードの削除](#無効な引き換えコードの削除)を参照してください。
- **監査記録**。引き換えコードの作成、編集、有効化、無効化、削除（1 件削除、一括削除、無効なコードの削除を含む）は監査記録に残ります。記録は<a href="/ja/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">監査ログ</a>ページで確認でき、「使用ログ」には記録されません。
- **サーバーのエラーログには入力された引き換えコードがそのまま記録されます。** 使用ログの引き換え記録には、引き換えコードの ID のみが含まれます。ユーザーによる引き換えが失敗した場合は、送信された引き換えコードがサーバーのエラーログにそのまま記録されます。運用者はログへのアクセスを制限し、自組織のコンプライアンス要件に従って保護やマスキングを行ってください。
- **ユーザーによる引き換えには、重要なエンドポイントに対するレート制限が適用されます。** 同一 IP アドレスからの引き換えリクエストは、ログイン、登録、パスワードの再設定、チャージ注文の作成などの操作と同じカウンターを使用します。既定では 1200 秒間に最大 20 回で、上限を超えたリクエストは拒否されます。Redis が有効な場合は全ノードでカウンターを共有し、無効な場合は各ノードが個別にカウントします。
- **レート制限は環境変数で調整できます。** `CRITICAL_RATE_LIMIT` は回数の上限（既定値は 20）、`CRITICAL_RATE_LIMIT_DURATION` は計測期間（単位は秒、既定値は 1200）です。`CRITICAL_RATE_LIMIT_ENABLE` の既定値は `true` で、`false` に設定するとレート制限が無効になります。3 つの環境変数は起動時にのみ読み込まれるため、変更後は再起動が必要です。このページに対応する設定項目はありません。詳細は<a href="/ja/docs/guide/feature-guide/system-settings/settings-security#レート制限" target="_blank" rel="noopener noreferrer">セキュリティと制限の設定</a>を参照してください。

<Accordion title="引き換えコードの作成時に、決済、引き換えコード、サブスクリプションプラン、招待報酬の機能が無効と表示される">
**表示メッセージ**　「決済、引き換えコード、サブスクリプションプラン、招待報酬の機能は無効です。有効にするには、管理者が先にコンプライアンス声明を確認する必要があります。」（英語：Payment, redemption, subscription, and invitation reward features are disabled. The administrator must confirm compliance terms before enabling them.）

**考えられる原因**　Root が決済コンプライアンス条項をまだ確認していないか、確認済みの条項が現行バージョンではありません。

**対処方法**

1. Root に「システム設定」→「請求と決済」→「決済ゲートウェイ」でコンプライアンス条項を確認してもらいます。詳しくは<a href="/ja/docs/guide/feature-guide/system-settings/settings-billing#支付合规确认" target="_blank" rel="noopener noreferrer">決済コンプライアンスの確認</a>を参照してください。
2. 引き換えコードを再度作成します。
</Accordion>

<Accordion title="引き換えコードの作成・編集時に、パラメーターが無効と表示される">
**説明**　名前、クォータ、数量はドロワー内で事前に検証され、該当する入力欄の下にメッセージが表示されます。クォータが 0 の場合や有効期限が現在時刻より前の場合は、サーバー側の検証により、保存時にメッセージがポップアップ表示されます。

| 表示メッセージ | 考えられる原因 | 対処方法 |
| --- | --- | --- |
| 「名前は 1～20 文字で入力してください」 | 名前が 20 文字を超えているか、編集時に名前が空欄になっています。 | 名前を修正してください。 |
| 「クォータは正の数である必要があります」 | クォータが負の数です。 | 0 より大きいクォータを入力してください。 |
| 「数量は 1～100 の範囲で指定してください」 | 「数量」が 100 を超えているか、負の数です。 | 複数回に分けて作成してください。 |
| 「引き換えコードのクォータは 0 より大きい必要があります」（英語：Redemption quota must be positive） | クォータが 0 です。 | 0 より大きいクォータを入力してください。 |
| 「有効期限を現在時刻より前に設定することはできません」（英語：Expiration time cannot be earlier than current time） | 有効期限が現在時刻より前です。 | 有効期限を選び直すか、「無期限」を選択してください。 |
</Accordion>

<Accordion title="引き換え時に「引き換えに失敗しました。しばらくしてから再試行してください」と表示されるとユーザーから報告があった">
**表示メッセージ**　「引き換えに失敗しました。しばらくしてから再試行してください」（英語：Redemption failed, please try again later）

**説明**　ユーザー画面には、失敗の原因にかかわらず同じメッセージが表示されます。

**考えられる原因**

- 引き換えコードが存在しないか、すでに削除されています。
- 引き換えコードが使用済み、無効、または期限切れです。
- データベースで一時的なエラーが発生しました。

**対処方法**

1. 一覧で名前または ID を使って該当の引き換えコードを探し、ステータスと有効期限を確認します。
2. 「無効」の引き換えコードは、引き換え前に有効にします。「使用済み」または「期限切れ」の引き換えコードは再利用できないため、別途作成します。
3. ユーザー側での対処方法は<a href="/ja/docs/guide/feature-guide/user/wallet#よくある質問" target="_blank" rel="noopener noreferrer">ウォレット</a>を参照してください。
</Accordion>

<Accordion title="引き換えコードの作成時に「引き換えコードの作成に失敗しました。しばらくしてから再試行してください」と表示される">
**表示メッセージ**　「引き換えコードの作成に失敗しました。しばらくしてから再試行してください」（英語：Failed to create redemption code, please try again later）

**説明**　一括作成では引き換えコードを 1 件ずつ生成し、途中でエラーが発生すると処理を停止します。エラー発生前に生成された引き換えコードは一覧に残りますが、「引き換えコードの作成完了」ウィンドウは表示されません。

**考えられる原因**　データベースの一時的なエラーなどにより、データベースへの書き込みに失敗しました。

**対処方法**

1. 一覧で名前を使って今回作成した引き換えコードを検索し、生成済みの件数を確認します。
2. 必要に応じて、生成済みの引き換えコードをコピーまたは削除します。
3. 必要な数の引き換えコードを再度作成します。
</Accordion>
