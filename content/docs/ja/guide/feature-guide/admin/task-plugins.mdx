- Root のみアクセスできます。サイドバーの「管理者」→「プラグイン」から開きます。
- プラグインをアップロードするか、プラグインマーケットプレイスからインストールし、有効化状態とバージョンを管理します。
- プラグインをアップロードまたはマーケットプレイスからインストールしても、チャネルやリクエスト処理インスタンスは自動作成されません。

<Callout type="info" title="ヒント">

- プラグインは JavaScript スクリプトで、New API に組み込まれたサンドボックス内で実行されます。
- プラグインには3種類の機能を含めることができます。タスク機能は、画像・動画・音声などを扱う非同期タスクプラットフォームを共通のタスクインターフェースに接続します。チャネル機能は、高度なカスタムチャネルと同様に通常の API リクエストを転送します。リクエスト処理機能は、上流サービスへの送信前にリクエストを検査または変更します。1つのプラグインに複数の機能を含めることができます。
- タスク機能とチャネル機能を使用するには、プラグインを「タスクプラグイン」タイプのチャネルに関連付けます。[プラグインチャネルの作成](#プラグインチャネルの作成)を参照してください。プラグインは拡張機能として New API チャネルに関連付けることもできます。
- リクエスト処理機能を使用するには、サイドバーの<a href="/ja/docs/guide/feature-guide/admin/request-processing" target="_blank" rel="noopener noreferrer">リクエスト処理</a>ページでインスタンスを追加します。インスタンスは特定のチャネルにも追加できます。
- ページ右上の「プラグインを有効にする」は全体に適用されるスイッチです。オフにすると、プラグインによるタスクとプラグインチャネルはサービスを停止します。リクエスト処理は通常どおり動作します。[プラグインの有効化と無効化](#プラグインを有効化または無効化する)を参照してください。

</Callout>

## 主な操作

プラグイン管理ページでのアップロード、インストール、チャネルの作成、詳細の確認、有効化と無効化、削除、マーケットプレイスの配布元の管理について、操作別に説明します。

### プラグインのアップロード

- プラグイン管理 - プラグインのアップロード

![プラグイン管理のプラグインアップロード画面](/assets/guide/feature-guide/plugins-upload-plugin.png)

- プラグイン管理 - 新しいバージョンのアップロード

![プラグイン管理の新しいバージョンのアップロード画面](/assets/guide/feature-guide/plugins-upload-new-version.png)

**プラグインをアップロードする手順**

1. 「インストール済み」タブで、ページ右上の「プラグインをアップロード」をクリックします。
2. ソースコードを指定します。`.js` ファイルをドラッグ＆ドロップするか、「ファイルを選択」をクリックして選びます。「URL からインポート」にアドレスを入力して「取得」をクリックするか、「プラグインのソースコード」に直接貼り付けることもできます。
3. 「プラグインのソースコード」の下にプレビューされる対象チャネル、上流サービスの認証方式、デフォルトの API アドレス、追加のアクセス先ドメイン、サポートされるモデルを確認します。
4. 必要に応じて「プラグインアイコン」を選択し、「備考」を入力します。
5. 「アップロード」をクリックします。

**新しいバージョンをアップロードする手順**

1. プラグインの行末にある ⋯（カード表示ではカード右上）をクリックし、「新しいバージョンをアップロード」を選択します。
2. プラグインをアップロードする手順の 2～4 に従って入力し、ソースコード内の `key` が対象プラグインの Key と一致することを確認します。
3. 「アップロード」をクリックします。

<Callout type="warn" title="注意">

- ダイアログ上部の「サードパーティ製プラグインのリスク」には、「プラグインはチャネルの API キーを読み取り、上流サービスに送信する内容を変更できます。アクティブ化する前に、コードと変更内容を確認してください。」と表示されます。アップロード前にソースコードを確認してください。
- サーバーはソースコードをコンパイルしてメタデータを検証し、既存のプラグインとモデル、チャネルタイプ、ルートが競合しないかを確認します。すべてのチェックに合格した場合のみ保存します。チェックに失敗すると、ダイアログに「ゲートウェイがこのプラグインを拒否しました」と具体的な理由が表示されます。競合がある場合は、競合するプラグインも明示されます。[プラグインのメタデータ](#プラグインのメタデータ)と[バージョン、有効化・無効化、競合に関するルール](#バージョン有効化と無効化競合のルール)を参照してください。

</Callout>

**操作手順**

1. 「プラグインマーケットプレイス」タブをクリックします。
2. 「公式プラグイン」または「コミュニティプラグイン」を選択し、タイプから「タスク」「チャネル」「リクエスト処理」のいずれかを選択します。
3. プラグインのカードで「インストール」をクリックします。プラグインコードがわかっている場合は、右側の「プラグインコード」に8桁の数字を入力して「検索」をクリックし、検索結果のカードで「インストール」をクリックします。
4. バージョン選択欄で、インストールするバージョンを選びます。
5. 「プラグイン詳細」「バージョン間の差分」「ソースコード全文」「変更履歴」の各タブでプラグインの内容を確認します。
6. 「インストールして有効化」をクリックします。

<Callout type="warn" title="注意">

- インストール時もアップロード時と同様に、コンパイル、メタデータの検証、競合チェックが行われます。どの方法でもこれらのチェックは省略できません。
- インストールに失敗すると、ダイアログに「プラグインのインストールに失敗しました」、具体的な理由、および「先に『インストール済み』ページで競合を解消してから、再度インストールしてください。」と表示されます。競合が原因の場合は、「インストール済み」で競合するプラグインを削除または無効化してから、再度インストールしてください。
- インストールするプラグインの配布元が、配布元一覧に登録されている必要があります。登録されていない場合は「このプラグインの配布元は、マーケットプレイスの配布元一覧にありません」と表示されます。
- 「整合性チェック失敗」の場合はインストールできません。「整合性ハッシュなし」の場合はインストールできますが、ソースコードが配布元で公開されたものと一致するかは確認できません。
- インデックスとハッシュ値はどちらもブラウザーがダウンロードします。サーバーは受け取ったソースコードのハッシュ値を再計算するだけで、マーケットプレイスのインデックスは検証しません。ブラウザーが改ざんされていると、ソースコードとハッシュ値の両方が置き換えられる可能性があります。整合性チェックではこの種の改ざんを防げません。

</Callout>

### プラグインチャネルの作成

- プラグイン管理 - タスクプラグインチャネルの作成

![プラグイン管理のタスクプラグインチャネル作成画面](/assets/guide/feature-guide/plugins-create-plugin-channel.png)

**前提条件**

- 対象のプラグインが有効で、「実行状態」が「登録済み」であることを確認してください。組み込みプラグインはアップロード不要です。その他のプラグインは、事前にアップロードするか、プラグインマーケットプレイスからインストールしてください。無効なプラグインは選択肢に表示されません。リクエスト処理機能のみのプラグインは「プラグイン」カテゴリに表示されないため、<a href="/ja/docs/guide/feature-guide/admin/request-processing" target="_blank" rel="noopener noreferrer">リクエスト処理</a>ページでインスタンスを追加してください。
- Root はデフォルトでプラグインチャネルを作成できます。Admin の場合は、Root が管理者権限の設定でチャネルの操作権限と「タスクプラグインの関連付け」権限を付与する必要があります。これらの権限がない場合、「プラグイン」カテゴリは表示されません。
- 上流サービスのアドレスと認証情報を用意してください。

**操作手順**

1. サイドバーから「チャネル」ページを開き、「チャネルを作成」をクリックします。
2. 選択ダイアログで「プラグイン」カテゴリに切り替えます。
3. 対象のプラグインのカードをクリックします。
4. 「モデル」に自動入力されたプラグインのモデルを確認し、必要に応じて追加または削除します。
5. 「API アドレス」と「API キー」を入力します。
6. プラグインが設定項目を宣言している場合は、「プラグイン設定」欄にプラグインの要件に従って入力します。
7. 必要に応じてグループ、優先度、重みを調整します。
8. 「チャネルを作成」をクリックします。上流サービスのアカウントへのログインが必要なプラグインでは、ボタンは「保存してログイン」と表示されます。保存後、「認証情報」欄でログインを完了します。

<Callout type="warn" title="注意">

- タスク機能のみのプラグインチャネルは「接続テスト」に対応しておらず、このタイプではテストできない旨のメッセージが表示されます。チャネル機能を含むプラグインチャネルではテストが可能です。詳細テストにはプラグインがサポートするエンドポイントのみが表示されます。
- プラグインを削除または無効化する前に、関連付けられているチャネルを別のプラグインに切り替えてください。無効化する場合は、関連付けられたチャネルも連動して無効化できます。いずれの対応も行わないと、プラグインが使用できなくなるため、これらのチャネルへのリクエストは失敗します。

</Callout>

**比較手順**

1. 「比較するバージョンを選択」で、過去のバージョンを選択します。

**プラグインサンドボックス**

- プラグイン管理 → プラグイン詳細 → プラグインサンドボックス

![プラグイン管理のプラグイン詳細にあるプラグインサンドボックス画面](/assets/guide/feature-guide/plugins-plugin-details-plugin-sandbox.png)

現在有効なバージョンのフックを 1 つ実行します。アップストリームへのリクエストは送信されません。

**ドライランの手順**

1. ドロップダウンからフックを選択します。デフォルトは `buildSubmitRequest` です。ほかに `parseSubmitResponse`、`extractUsage`、`buildQueryRequest`、`parseTaskResult`、`buildBatchQueryRequest`、`parseBatchResult`、`buildContentRequest`、`renderers.openai_video` などを選択できます。
2. 「パラメーター JSON」に JSON 配列を入力します。デフォルトは `[{}]` です。
3. 「ドライランを実行」をクリックします。
4. 「ドライラン結果」で返された JSON を確認します。

<Callout type="info" title="ヒント">

- パラメーターが JSON 配列でない場合は「パラメーターは JSON 配列である必要があります」と表示されます。フックでエラーが発生した場合は、「ドライラン結果」にエラーメッセージが表示されます。
- ドライランはプラグインの一時コピーを使用するため、現在有効なレジストリには影響しません。フックの処理ロジック、フィールドの値、使用量の抽出処理を確認する際に利用できます。

</Callout>

### プラグインを有効化または無効化する

**個別のプラグインを有効化または無効化する手順**

1. プラグインが表示されている行の「有効」列にあるスイッチ（カード表示ではカードの下部）をクリックします。
2. 確認ダイアログで「有効化」または「無効化」をクリックします。
3. 無効化する際に「プラグインがまだ使用されています」と表示された場合は、「関連チャネルも無効化」または「強制実行」をクリックします。

**グローバルスイッチをオフにする手順**

1. ページ右上の「プラグインを有効化」スイッチをオフにします。
2. 「プラグインのタスクとチャネルを停止しますか？」ダイアログで一覧に表示されたプラグインを確認し、「無効化」をクリックします。

<Callout type="warn" title="注意">

- 組み込みプラグイン、または同名の組み込みプラグインがあるカスタムバージョンを無効化すると、その Key の組み込みプラグインも停止します。動作ステータスは「無効」と表示され、組み込みバージョンへのフォールバックは行われません。再度有効化すると、両方が復旧します。組み込みプラグインに切り替えるには、その Key のカスタムバージョンをすべて削除してください。手順は[現在のカスタムバージョンを削除する](#現在のカスタムバージョンを削除する)を参照してください。
- プラグインを無効化した場合も、グローバルスイッチをオフにした場合も、進行中のタスクはキャンセルされません。進行中のタスクはタイムアウト時のクリーンアップで処理されます。詳細は[タスクのタイムアウトとクリーンアップ](#タスクのタイムアウトとクリーンアップ)を参照してください。
- 有効なチャネルがプラグインを使用している場合は、プラグインを無効化する際に関連チャネルの処理も必要です。それらのチャネルを引き続き使用する場合は、先に別のプラグインに切り替えてください。

</Callout>

## ルールと仕組み

### プラグインの構成と提供元

プラグインは、対応モデル、紐付け可能なチャネルタイプ、課金パラメーター、各機能のエンドポイントを宣言します。プラグインをアップロードまたはインストールすると、これらの機能が登録されます。チャネルは自動作成されません。プラグインは下表の 3 種類に分類されます。一覧での表示は[提供元バッジ](#ソースラベル)を参照してください。

### プラグインのメタデータ

**コンパイルと検証**

- `apiVersion` は `1` である必要があります。
- `name` と `author.name` は必須です。
- `key` に使用できるのは英小文字、数字、`-`、`_` のみで、最大 30 文字です。また、ゲートウェイの既存のパスセグメント（`api` など）と同じ名前は使用できません。既存のパスセグメントと重複すると、`plugin meta key … is a reserved path segment` と表示されます（英語のみ）。
- `version` はセマンティックバージョニングに準拠する必要があります。
- `models` は空にできず、大文字と小文字を区別せずに比較したときに各要素が一意である必要があります。
- `channelTypes` の要素は重複のない正の整数である必要があります。`60`（New API）と `61`（タスクプラグイン）は指定できません。
- `allowedHosts` にはホスト名を指定します。ポート番号は指定できますが、スキーム、パス、認証情報は含められません。
- `fetchMode` には `per_task` または `batch` のみ指定できます。
- `channelType`、`submitPaths`、`actions` などの旧フィールドはサポートを終了しました。これらのフィールドが含まれるとアップロードが拒否されるため、`channelTypes` と `routes` に移行してください。

**フィールドの説明**

プラグインのソースコードでは、以下のフィールドを `meta` に宣言します。各機能の宣言ルールの詳細は<a href="/ja/docs/plugins" target="_blank" rel="noopener noreferrer">プラグインドキュメント</a>を参照してください。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_td_code]:wrap-anywhere [&_th]:whitespace-nowrap">

| フィールド | 型・ルール | 説明 |
| --- | --- | --- |
| `apiVersion` | 整数。現在は `1` が必須 | プラグイン API のバージョン。 |
| `key` | 30 文字以下の文字列。`^[a-z0-9][a-z0-9_-]*$` | プラグインの一意な識別子。チャネルとの紐付けやマーケットでの識別に使用します。 |
| `name` | 文字列またはローカライズ済みテキスト。必須 | プラグインの表示名。ローカライズ済みテキストには `en` が必須で、画面の表示言語に応じて名前が表示されます。 |
| `icon` | 任意 | アイコン。 |
| `description` | ローカライズ済みテキスト | 多言語の説明。 |
| `version` | セマンティックバージョニングに準拠した文字列 | プラグインのバージョン番号。 |
| `author` | `{ name, url }`。`name` は必須 | 作成者の情報。 |
| `channelTypes` | 正の整数の配列 | 紐付け可能なチャネルタイプの番号。`60` と `61` は指定できません。 |
| `models` | 空でなく、各要素が一意な文字列の配列 | プラグインがサポートするモデルの識別子。 |
| `fetchMode` | `per_task` / `batch` | 取得モード。タスク単位の取得には `buildQueryRequest` が、一括取得には `buildBatchQueryRequest + parseBatchResult` が必要です。 |
| `routes` | 配列 | プラグインが宣言するネイティブルート。ルーティングの生成に使用されます。 |
| `protocols` | 配列 | `openai_responses`、`openai_video`、`openai_image` など、ホスト側のプロトコルの宣言。`openai_responses` では `supports` でストリーミング、同期、バックグラウンドの各モードを指定します。 |
| `allowedHosts` | ホスト名の配列 | プラグインがリクエストを送信できるアップストリームのホスト名。ポート番号も指定できます。 |
| `auth` | オブジェクト | プラグイン接続時に使用する認証方式（OAuth2 JWT など）。 |
| `usageSchema` | オブジェクト | 課金パラメーターの宣言。タスクモデルの課金式が参照します。 |
| `baseUrl` | 文字列。任意 | デフォルトのアップストリームアドレス。タスクプラグインのチャネルを作成すると、「API アドレス」に自動入力されます。 |
| `relay` | 配列。任意 | チャネル機能の転送ルート。空でない場合、プラグインは高度なカスタムチャネルと同様に通常の API リクエストを転送できます。 |
| `channelConfig` | オブジェクト。任意 | チャネル単位の設定の宣言。このプラグインに紐付けられたチャネルのフォームに「プラグイン設定」が表示されます。 |
| `configSchema` | オブジェクト。任意 | リクエスト処理インスタンスの設定の宣言。詳細は<a href="/ja/docs/guide/feature-guide/admin/request-processing#インスタンスの追加と編集" target="_blank" rel="noopener noreferrer">リクエスト処理</a>を参照してください。 |

</div>

<Callout type="info" title="ヒント">

- `routes` と `protocols` は、プラグインがリクエストを受け付ける方法を決めます。`usageSchema` は、タスクの結果に対する課金方法を決めます。詳細は、プラグイン詳細の「課金パラメーター」タブを参照してください。
- モデルとチャネルタイプがプラグインの宣言に一致するリクエストのみ、そのプラグインにルーティングされます。

</Callout>

### 公式プラグインとコミュニティプラグイン

「プラグインマーケットプレイス」は「公式プラグイン」と「コミュニティプラグイン」の 2 グループに分かれます。各ソースの所属グループは、ソースのアドレスだけで決まります。

**一覧とグループ分けの違い**

| --- | --- | --- | --- |
| アドレス | デフォルトの Official と GitHub の 2 つのアドレス | デフォルトの Community アドレス | 管理者が追加したその他のアドレス |
| 所属グループ | 「公式プラグイン」 | 「コミュニティプラグイン」 | 「コミュニティプラグイン」 |

**コミュニティプラグインの公開**

- プラグイン管理-newapi.ai コミュニティアカウント

![プラグイン管理-newapi.ai コミュニティアカウント画面](/assets/guide/feature-guide/newapi-publish-plugin.png)

プラグインの作者は、New API 公式サイトの「プラグイン」ページで「プラグインを公開」をクリックし、GitHub を連携すると「コミュニティアカウント」ページに移動します。そこで、自分の公開 GitHub リポジトリのリリースタグからプラグインを公開できます。「プラグインを送信」で「リポジトリパス」を入力し、「送信」をクリックします。

**公開ルール**

1. plugin.js がリポジトリのルートディレクトリにある場合は `owner/repo`、サブディレクトリにある場合は `owner/repo/path` を入力します。
2. バージョンごとに `v1.2.0` または `1.2.0` の形式でタグを付けます（サブディレクトリのプラグインでは `path/v1.2.0` または `path/1.2.0`）。プラグインの meta に記載するバージョン番号は、タグのバージョンと一致している必要があります。
3. プラグインの `meta.key` は、小文字の GitHub ユーザー名、アンダースコア、プラグイン名の順で構成する必要があります（例 `raymondxox_myplugin`）。
4. 各バージョンのタグには、plugin.js と同じディレクトリに README.md と CHANGELOG.md が必要です。README.md には、チャネルの設定方法、対応するモデルとインターフェース、課金方法、リクエスト例を記載します。CHANGELOG.md には、そのバージョンでの変更点を所定の形式で記載します。両ファイルの書き方は、そのページにあるリンクを参照してください。
5. いずれかのファイルがないタグや、ファイルの形式が正しくないタグは公開されません。プラグインページに修正箇所が表示されます。

<Callout type="info" title="ヒント">

- ページの「AI エージェントに開発を任せる」には、エージェント（Claude Code、Codex、Cursor など）に渡せる説明文があります。「エージェントにコピー」で説明文をコピーし、末尾に作りたいプラグインの内容を追記します。エージェントは newapi-plugin-dev スキルを使い、上記のルールに沿って plugin.js、README.md、CHANGELOG.md を作成します。公開前に内容を確認してください。送信済みのプラグインは「マイプラグイン」に表示されます。
- 公開後は、ゲートウェイ管理者が「コミュニティプラグイン」で閲覧したり、プラグインコードで検索してインストールしたりできます。インストール時のプラグイン識別子のルールは、第 3 項と同じです。[公式プラグインとコミュニティプラグイン](#公式プラグインとコミュニティプラグイン)を参照してください。プラグインの開発方法は、<a href="/ja/docs/plugins" target="_blank" rel="noopener noreferrer">プラグインドキュメント</a>を参照してください。
</Callout>

### バージョン、有効化と無効化、競合のルール

同じ Key に複数のバージョンを保存できますが、同時に適用されるのは 1 バージョンのみです。有効化と無効化には、グローバルスイッチとプラグインごとのスイッチの 2 段階があります。

**バージョンのルール**

- その Key の最初のバージョンは、アップロードまたはインストール後に自動的にアクティブになります。すでにアクティブなバージョンがある場合、新しいバージョンは保存のみ行われます。
- 同じ Key とバージョンがすでに存在し、ソースコードが異なる場合は、アップロードが拒否され、`plugin key and version already exist with different source`（英語のみ）と表示されます。既存のバージョンの内容は変更できません。ソースコードを変更するには `version` を上げる必要があります。
- ソースコードは 8 MiB 以下です。プラグインアイコンは別に計算され、512 KiB 以下です。

**有効化、無効化、削除のルール**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 組み込みプラグインとそのカスタムバージョン | サードパーティプラグイン |
| --- | --- | --- |
| 無効化 | その Key の組み込みプラグインも停止し、動作ステータスは「無効」になります。組み込みバージョンへの切り替えは行われません。 | そのプラットフォームが利用できなくなり、動作ステータスは「無効（プラットフォーム利用不可）」になります。 |
| 再有効化 | カスタムバージョンと組み込みプラグインの動作が再開します。 | 動作が再開します。 |
| 現在のカスタムバージョンを削除 | アップロード済みの別バージョンがある場合は、そのうち最後にアップロードされたバージョンがアクティブになり、そのバージョン自身の有効・無効設定が維持されます。別バージョンがない場合は組み込みプラグインに戻ります（その Key が無効化されている場合を除きます）。 | 別バージョンがある場合は左欄と同じです。ない場合はそのプラットフォームが利用できなくなります。 |
| グローバルスイッチをオフにする | プラグインのタスクとチャネルはすべて停止します。リクエスト処理は通常どおり動作します。 | 左欄と同じです。 |

</div>

**競合チェック**

- アップロード、インストール、有効化、バージョンのアクティブ化、および現在のバージョンの削除（別のバージョンのアクティブ化、または組み込みバージョンへの切り替えを伴う）では、既存プラグインのモデル、チャネルタイプ、ルートとの競合を確認します。競合がある場合は操作が拒否されます。このチェックはどの方法でも省略できません。

<Callout type="info" title="ヒント">

- API 経由でバージョンをアップロードする場合は、`enabled`（デフォルトで有効）、`remark`（備考）、`sourceSha256` パラメーターを指定できます。`sourceSha256` を指定する場合は、ソースコードの SHA-256 と一致する必要があります（大文字と小文字は区別しません）。一致しない場合、アップロードは拒否されます。画面からのアップロードとマーケットプレイスからのインストールは常に有効として扱われ、マーケットプレイスからのインストールでは `sourceSha256` が自動的に指定されます。
- カスタムバージョンが有効化されておらず、同名の組み込みプラグインが稼働している場合、動作ステータスは「無効（組み込みバージョンを使用中）」になります。画面上で無効化した場合は、このステータスにはなりません。
</Callout>

### タスクのタイムアウトとクリーンアップ

プラグインを無効化したり、グローバルスイッチをオフにしたりしても、処理中のタスクはキャンセルされません。タイムアウトしたタスクは、グローバルポーリングでクリーンアップされます。

**クリーンアップのルール**

- 処理中のタスクとは、`platform` がプラグインの Key で、ステータスが成功でも失敗でもないタスクを指します。
- グローバルポーリングでタイムアウトしたタスクを検出し、送信時点から `TASK_TIMEOUT_MINUTES`（デフォルトは 4320 分、つまり 72 時間）が経過すると失敗としてマークします。`0` に設定すると、経過時間によるタイムアウトは無効になります。旧バージョンのタスクを除き、クォータが返還されます。
- このクリーンアップは、`UPDATE_TASK` が有効な場合にのみ実行されます。無効にすると、タイムアウトしたタスクは失敗としてマークされず、クォータも返還されません。
- ポーリングの連続失敗回数の上限は `TASK_POLL_MAX_FAILURES`（デフォルトは 20）で設定します。

<Callout type="info" title="ヒント">
タイムアウトによるクリーンアップは、すべてのプラグインを対象とするグローバルポーリングで行われます。プラグインを無効化した後も、残っているタスクには同じタイムアウトと再試行のポリシーが適用され、直ちに失敗扱いにはなりません。
</Callout>

## 保存と反映

このページの各操作は、送信後すぐにサーバー側で実行されます。ページ全体の変更をまとめて保存するボタンはありません。リクエストを処理したノードには即時反映されます。ほかのノードへの同期方法は対象によって異なり、以下の 2 グループに分かれます。複数インスタンスの構成では、各ノードの読み込み状況がページ右上に表示されます。[ノード同期ステータス](#ノード同期ステータス)を参照してください。

**プラグインバージョン**

リクエストを処理したノードは、プラグインレジストリを直ちに更新します。ほかのノードでは約 3 秒以内、遅くとも 30 秒以内に読み込まれます。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方法 | 反映のタイミング |
| --- | --- | --- |
| アップロード、マーケットプレイスの「インストールして有効化」 | サーバーでコンパイル、メタデータの検証、事前の競合チェックを行い、すべてを通過した場合に保存します。 | その Key の最初のバージョンは、保存後すぐにアクティブになります。すでにアクティブなバージョンがある場合は「プラグインを保存しました。アクティブ化待ちです。」と表示され、現在のバージョンが引き続き使用されます。「今すぐアクティブ化」をクリックするか、バージョン履歴からアクティブ化すると反映されます。 |
| バージョンのアクティブ化、ロールバック | 「バージョン履歴」で操作します。成功すると「プラグインバージョンをアクティブ化しました。」と表示されます。 | アクティブ化の前にコンパイルします。コンパイルに失敗した場合は、バージョンを切り替えません。 |
| カスタムプラグインの有効化、無効化 | スイッチを切り替え、確認ダイアログで確定します。プラグインが引き続き使用されている場合は、「プラグインは使用中です」の案内に従います。 | 無効化すると、その Key はルーティングの対象外になります。再有効化するとルーティングに戻ります。進行中のタスクはキャンセルされません。 |
| 現在のカスタムバージョンの削除 | 確認ダイアログで確定します。成功すると「プラグインバージョンを削除しました。」と表示されます。 | その Key に別バージョンがある場合は、そのうち最後にアップロードされたバージョンをアクティブにします。別バージョンがない場合は組み込みプラグインに戻ります。組み込みプラグインがなければ、そのプラットフォームは利用できなくなります。組み込みプラグインに戻る前に競合を確認し、競合がある場合は削除を拒否します。 |
| アップロード、インストール、アクティブ化、有効化、現在のバージョンの削除後の価格チェック | 操作結果とともに返されます。 | 課金できないタスクモデルがある場合は「次のモデルの価格設定に対応が必要です。」と表示されます。「課金と支払い」の設定で対応してください。[プラグインをアップロードする](#プラグインのアップロード)を参照してください。 |

</div>

**グローバルスイッチ、組み込みプラグイン、マーケットソース**

これらはシステム設定として保存されます。リクエストを処理したノードには即時反映され、ほかのノードにはシステム設定の同期に合わせて約 3 秒以内、遅くとも 1 同期周期以内（デフォルトは 60 秒）に反映されます。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方法 | 反映のタイミング |
| --- | --- | --- |
| グローバル設定の「プラグインを有効化」 | スイッチを切り替えます。オフにする前に「プラグインのタスクとチャネルを停止しますか？」と表示されます。成功すると「プラグイン設定を更新しました。」と表示されます。 | オフにすると、新しいプラグインタスクとプラグインチャネルへのリクエストは拒否されます。リクエスト処理は通常どおり動作し、進行中のタスクはキャンセルされません。 |
| 組み込みプラグインの有効化、無効化 | スイッチを切り替え、確認ダイアログで確定します。 | 無効化すると、その Key の組み込みプラグインは停止し、代替バージョンへの切り替えは行われません。再有効化すると動作が再開します。 |
| マーケットソース | 「マーケットソース」ダイアログで一覧全体をまとめて保存します。成功すると「マーケットソースを更新しました。」と表示されます。 | 「プラグインマーケットプレイス」で閲覧できるソースだけが変わります。インストール済みのプラグインには影響しません。 |

</div>

**補足**

- **同名の組み込みプラグインとカスタムプラグインの同時有効化・無効化**。それぞれのグループの方法で同期されます。ほかのノードには両方とも約 3 秒以内に反映され、デフォルト設定では遅くとも約 60 秒以内に反映されます。
- **コンパイル失敗**。あるノードで新しいバージョンの読み込み時にコンパイルが失敗すると、そのノードは読み込み済みの旧バージョンを使い続け、動作ステータスは「コンパイル失敗」と表示されます。
- **プラグインサンドボックスの「ドライランを実行」**。一時コピーを使って実行されます。変更は保存されず、現在のレジストリには影響しません。
- **プラグインチャネル**の保存と反映については、<a href="/ja/docs/guide/feature-guide/admin/channel#保存と反映" target="_blank" rel="noopener noreferrer">チャネル管理</a>を参照してください。

## 注意事項

**インストールと提供元**

- **アップロードとインストールには管理者による信頼性の判断が必要です**。プラグインはチャネルの認証情報を読み取り、アップストリームへのリクエストを組み立てることができます。コミュニティやサードパーティのプラグインは外部の開発者が公開しているため、インストール前にソースコードを確認してください。詳しくは[プラグインのアップロード](#プラグインのアップロード)と[公式プラグインとコミュニティプラグイン](#公式プラグインとコミュニティプラグイン)を参照してください。
- **コミュニティからのインストール時は統計情報が送信されます**。Community からインストールすると、サーバーはプラグインの識別子、バージョン番号、このゲートウェイにランダムに割り当てられた番号を newapi.ai に送信します。詳しくは[公式プラグインとコミュニティプラグイン](#公式プラグインとコミュニティプラグイン)を参照してください。

**有効化・無効化と削除**

- **無効化すると同名の組み込みプラグインも停止します**。組み込みプラグイン自体を無効にした場合も、同名の組み込みプラグインがあるカスタムバージョンを無効にした場合も、そのキーの組み込みプラグインは提供を停止します。組み込みプラグインへのフォールバックは行われません。詳しくは[バージョン、有効化・無効化、競合のルール](#バージョン有効化と無効化競合のルール)を参照してください。
- **処理中のタスクはキャンセルされません**。グローバルスイッチをオフにするかプラグインを無効にすると、処理中のタスクはタイムアウト時にクリーンアップされます。クリーンアップは `UPDATE_TASK` が有効な場合にのみ実行されます。詳しくは[タスクのタイムアウトとクリーンアップ](#タスクのタイムアウトとクリーンアップ)を参照してください。
- **削除や無効化の前に、紐づけられたチャネルに対処してください**。対処せずに削除や無効化を行うと、プラグインが利用できなくなり、それらのチャネルへのリクエストが失敗します。詳しくは[プラグインの有効化と無効化](#プラグインを有効化または無効化する)を参照してください。
- **削除後は別のバージョンが引き継ぎます**。現在のカスタムバージョンを削除したときに、同じキーの別バージョンが残っていれば、最後にアップロードされたバージョンがアクティブになります。詳しくは[現在のカスタムバージョンの削除](#現在のカスタムバージョンを削除する)を参照してください。

**バージョンと競合**

- **ソースコードを変更したらバージョンを上げてください**。キーとバージョンが同じでソースコードが異なる場合は拒否されます。詳しくは[バージョン、有効化・無効化、競合のルール](#バージョン有効化と無効化競合のルール)を参照してください。
- **競合チェックはスキップできません**。アップロード、インストール、有効化、アクティブ化、現在のバージョンの削除では、いずれも競合チェックが行われます。どの操作でもチェックを省略することはできません。詳しくは[バージョン、有効化・無効化、競合のルール](#バージョン有効化と無効化競合のルール)を参照してください。

<Accordion title="チャネルの作成時に「プラグイン」カテゴリが表示されない">

**表示メッセージ**

タスクプラグインチャネルをコピーまたは送信すると、`task plugin channels require the task_plugin.bind permission`（英語のみ）と表示されることがあります。

**考えられる原因**

現在のアカウントに「タスクプラグインを紐づける」権限がありません。この権限がない場合、選択ダイアログに「プラグイン」カテゴリは表示されません。

**対処方法**

1. Root に、<a href="/ja/docs/guide/feature-guide/admin/user#管理者権限" target="_blank" rel="noopener noreferrer">ユーザー管理</a>の「管理者権限」で「タスクプラグインを紐づける」権限を付与してもらってください。

</Accordion>

<Accordion title="タスクプラグインチャネルを保存できない">

**表示メッセージ**

`task plugin "…" is not registered`、`task plugin key must not exceed 30 characters`、`base URL is required for task plugin channels`、`channel cannot be empty`（いずれも英語のみ）や、「このチャネルタイプでは Base URL が必須です」（英語では Base URL is required for this channel type）などが表示されます。

**考えられる原因**

- 紐づけられたプラグインが登録されていない。
- チャネルに紐づけられたプラグインのキーが 30 文字を超えている。
- 「API アドレス」または「API キー」が入力されていない。

**対処方法**

1. 表示されたメッセージに従って、該当箇所を修正してください。
2. プラグインの動作ステータスが「登録済み」であることを確認してください。

</Accordion>

<Accordion title="リクエストが想定したプラグインにルーティングされない">

**表示メッセージ**

`selected channel does not match the pinned task plugin` が表示されます。プラグインシステムまたは該当プラグインが無効な場合、クライアントには HTTP 400 とともに `the task plugin system is disabled on this gateway` または `task plugin "…" is disabled on this gateway` が返されます（いずれも英語のみ）。

**考えられる原因**

- チャネルに紐づけられたプラグインのキーが、リクエストで固定されたキーと一致していない。
- 他のチャネルタイプの番号が、プラグインの `channelTypes` に含まれていない。
- チャネルタイプが「タスクプラグイン」ではない、チャネルに紐づけられたキーが誤っている、グループが一致していない、またはモデルがプラグインの `models` に含まれていない。
- グローバル設定の「プラグインを有効にする」または該当プラグインが無効になっている。

**対処方法**

1. 上記の原因に沿って、チャネルとプラグインの設定を順に確認してください。
2. プラグインが無効になっている場合は、再度有効にしてください。

</Accordion>

<Accordion title="プラグインのアップロードに失敗する">

**表示メッセージ**

「プラグインのソースコードが上限の 8 MiB を超えています。」（英語では Plugin source exceeds the 8 MiB limit.）、`plugin source sha256 mismatch`、`plugin key and version already exist with different source`（後者 2 件は英語のみ）などが表示されます。

**考えられる原因**

- ソースコードが 8 MiB を超えている。
- `apiVersion`、`key`、`version`、`name`、`models` のいずれかが検証要件を満たしていない。
- モデル、チャネルタイプ、またはルートが既存のプラグインと競合している。
- 同じキーとバージョンのプラグインがすでに存在し、ソースコードが異なる。

**対処方法**

1. 競合がある場合は、先に「インストール済み」で競合するプラグインを削除または無効化し、再度アップロードしてください。
2. ソースコードを変更した場合は、`version` を上げてからアップロードしてください。

</Accordion>

<Accordion title="プラグインに「コンパイル失敗」と表示される">

**表示メッセージ**

動作ステータスにカーソルを合わせると、`plugin … is missing required export "buildSubmitRequest"`（英語のみ）などのエラーを確認できます。

**考えられる原因**

ソースコードに誤りがある、メタデータが不足している、または `buildSubmitRequest`、`parseSubmitResponse`、`parseTaskResult` などの必須エクスポートがありません。`batch` モードでは、バッチ処理用のエクスポートも必要です。

**対処方法**

1. 詳細画面でソースコードとエラーを確認し、修正してください。

</Accordion>

<Accordion title="プラグインに「未登録」と表示される">

**説明**

このバージョンは有効になっていますが、リクエストを処理したノードのプラグインレジストリにはまだ読み込まれていません。他のノードは約 3 秒以内に新しいバージョンを読み込みます。また、各ノードは 30 秒ごとにデータベースと同期します。

**対処方法**

1. 少し待ってから一覧を更新してください。
2. 「未登録」のままの場合は、サーバーログでタスクプラグインの同期エラーを確認してください。

</Accordion>

<Accordion title="プラグインの無効化時に「プラグインは使用中です」と表示される">

**説明**

有効なチャネルまたは処理中のタスクが、引き続きプラグインを使用しています。

**対処方法**

1. 確認ダイアログで「関連チャネルも無効化」をクリックしてください。処理中のタスクが残っている場合は「強制実行」をクリックしてください。詳しくは[プラグインの有効化と無効化](#プラグインを有効化または無効化する)を参照してください。
2. これらのチャネルを引き続き使用する場合は、先に別のプラグインに切り替えてください。

</Accordion>

<Accordion title="カスタムバージョンを無効にすると、同名の組み込みプラグインも停止する">

**説明**

同名の組み込みプラグインがあるカスタムバージョンを無効にすると、組み込みプラグインも無効になります。

**対処方法**

1. そのまま再度有効にすると、現在のカスタムバージョンが復旧します。
2. 組み込みプラグインに切り替える場合は、「現在のカスタムバージョンを削除」でそのキーのカスタムバージョンをすべて削除してください。「提供元」に「組み込み」と表示されたら、該当行の「有効」スイッチをオンにしてください。

</Accordion>

<Accordion title="タスクに課金が適用されない">

**考えられる原因**

- プラグインが `usageSchema` を宣言していない。
- リクエストが該当プラグインにルーティングされていない。
- <a href="/ja/docs/guide/feature-guide/admin/billing-expression#タスクモデル" target="_blank" rel="noopener noreferrer">課金式</a>で、該当するタスクモデルのタスク式が設定されていない。

</Accordion>

<Accordion title="マーケットプレイスからのインストールに失敗する">

**表示メッセージ**

「整合性チェックに失敗しました」（英語では Integrity check failed）や、「『インストール済み』タブで競合を解消してから、再度インストールしてください。」（英語では Resolve the conflict on the Installed tab, then install again.）などが表示されます。

**考えられる原因**

- インデックスにアクセスできない。
- ソースコードのハッシュがインデックスと一致していない。
- ルートが競合している。
- コミュニティまたはサードパーティからインストールするプラグインの識別子が組み込みプラグインと同じか、作者の GitHub ユーザー名にアンダースコアを続けた形式で始まっていない。
- プラグインの提供元が、提供元の一覧に登録されていない。

**対処方法**

1. 表示されたメッセージに従って対処し、再度インストールしてください。競合がある場合は、先に「インストール済み」で競合するプラグインに対処してください。
2. 識別子が要件を満たしていない場合は、プラグインの作者に連絡してください。

</Accordion>

<Accordion title="マーケットプレイスの提供元を読み込めない">

**表示メッセージ**

「この提供元を読み込めませんでした」（英語では Could not load this source）または「プラグインのコードをダウンロードできませんでした。しばらくしてから再試行してください。」（英語では Could not download the plugin code. Try again later.）と表示されます。

**考えられる原因**

- インデックスの `indexVersion` が 1 より大きい。この場合、その提供元のプラグインは一覧に表示されません。
- ブラウザーがホストにアクセスできないか、ホストがクロスオリジンリクエストを許可していない。

**対処方法**

1. 「提供元 URL」を修正してください。
2. ホストがクロスオリジンリクエストを許可していないか、ブラウザーからホストにアクセスできない場合は、ソースコードをダウンロードして「プラグインのアップロード」に貼り付けてください。

</Accordion>

<Accordion title="タスクプラグインチャネルの「接続テスト」が機能しない">

**表示メッセージ**

`Task Plugin channel test is not supported`（英語のみ）

**説明**

タスク部分のみを実装しているプラグインのチャネルでは、接続テストはサポートされません。チャネル部分も実装しているプラグインのチャネルでは、接続テストを実行できます。

**対処方法**

1. 実際のモデルでタスクを実行し、タスクログで結果を確認してください。

</Accordion>

<Accordion title="コミュニティプラグインのインストール時に、識別子が要件を満たしていないと表示される">

**表示メッセージ**

「コミュニティプラグインは組み込みプラグイン … の識別子を使用できません」または「コミュニティプラグインの識別子は、`alice_foo` のように、作者の GitHub ユーザー名にアンダースコアを続けた形式で始める必要があります」と表示されます。

**説明**

コミュニティやその他のサードパーティからインストールするプラグインには、組み込みプラグインとは異なる識別子を使用し、作者を示すプレフィックスを付ける必要があります。

**対処方法**

1. プラグインの作者に連絡し、ルールに従って識別子を修正した新しいバージョンを公開してもらってください。
2. 作者が公開時に従う識別子のルールについては、[公式プラグインとコミュニティプラグイン](#公式プラグインとコミュニティプラグイン)の「コミュニティプラグインの公開」を参照してください。

</Accordion>

</Accordions>
