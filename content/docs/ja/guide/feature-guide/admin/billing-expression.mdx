- Root のみアクセスできます。「システム設定」→「課金と支払い」→「モデル価格設定」、または「モデル」ページの「価格設定」から価格エディターを開きます。
- 課金式でモデルの価格を設定し、保存前に料金を見積もったり、リクエストをシミュレーションしたりできます。
- このページでは、エディターの使い方と式の書き方を説明します。モデル価格一覧、入力の事前控除倍率、グループ倍率については、<a href="/ja/docs/guide/feature-guide/system-settings/settings-billing" target="_blank" rel="noopener noreferrer">課金と支払いの設定</a>を参照してください。

<Callout type="info" title="ヒント">

- 1 つの課金式で、1 モデルの料金体系全体を定義します。トークン単価、段階条件、キャッシュ・画像・音声の個別料金、リクエスト単価、リクエストルールの倍率をすべて同じ式に記述します。
- 課金式には、従来のモデル倍率や補完倍率などの設定は重複適用されません。
- グループ倍率は通常どおり適用されます。
- 旧モードの「トークン単位（非推奨）」「リクエスト単位（非推奨）」は引き続き利用できます。変換方法は[旧モードからの変換](#旧モードからの変換)を参照してください。
- `gpt-image-2`、`gpt-6-astra`、`deepseek-v4-pro` などのモデルには、課金式が組み込まれています。
</Callout>

## 主な操作

このセクションでは、価格エディターの開き方、2 種類のエディターでの価格設定、リクエストルールの設定、料金の見積もり、旧モードからの変換、タスクモデルの価格設定、保存の手順を説明します。

### 価格エディターを開く

**操作手順**

1. 次のいずれかの場所から価格エディターを開きます。
   - 「システム設定」→「課金と支払い」→「モデル価格設定」→「モデル価格」で、「モデルを追加」またはモデル行の編集アイコンをクリックします。
   - 「モデル」一覧で、モデル行の「価格設定」ボタンをクリックします。
   - モデル編集ドロワーの「価格設定」タブを選択します。
2. 課金モードのタブで「課金式」を選択します。
3. 「エディターモード」で「ビジュアルエディター」または「式エディター」を選択します。

<Callout type="info" title="ヒント">

- モデル価格を閲覧・変更できるのは Root のみです。Admin がモデルページで「価格設定」を開くと、「モデル価格はスーパー管理者が管理しています。」と表示されます。
- 3 つの入口で編集するモデル価格設定は共通です。保存方法は[モデル価格を保存する](#モデル価格を保存する)を参照してください。
- モデルページでの開き方は、<a href="/ja/docs/guide/feature-guide/admin/model#価格設定" target="_blank" rel="noopener noreferrer">モデル管理</a>を参照してください。
</Callout>

### ビジュアルエディターで価格を設定する

**操作手順**

1. 「エディターモード」で「ビジュアルエディター」を選択するか、「プリセットテンプレート」でいずれかのプリセットをクリックして編集を開始します。
2. ティアカードの「ティア名」に `base` や `standard` などの名前を入力します。
3. 条件に応じてティアを分ける場合は、「課金分岐を追加」をクリックし、新しいカードの「段階条件」で条件を設定します。
4. 「分岐の課金方式」で「トークン単位」または「呼び出し単位」を選択します。
5. 「トークン単位」を選択した場合は、個別に課金する価格項目にチェックを入れ、単価を入力します。
6. 「呼び出し単位」を選択した場合は、「リクエスト単価」を入力します。
7. 画像や音声の価格を設定する場合は、「メディア価格設定」を展開して入力します。

<Callout type="info" title="ヒント">

- ティアは、式内の 1 つの `tier()` に対応します。画面上の「段階」はティアと同義です。適用されたティア名は消費ログに記録されます。
- 「課金分岐を追加」をクリックすると、現在のティアの前に条件付きの分岐が挿入されます。
- ルールは先頭から順に照合され、最初に一致したルールで適用ティアが決まります。
- 最後のティアはフォールバックティアです。カードには「フォールバックティア」と「前のルールにいずれも一致しない場合」と表示されます。ティアが 1 つだけの場合は「常に一致（デフォルトティア）。」と表示され、「フォールバックティア」のラベルは付きません。
- 「メディア価格設定」はデフォルトで折りたたまれており、メディア価格が設定済みの場合は自動で展開されます。「メディア価格設定」をクリックして手動で展開・折りたたみすることもできます。
</Callout>

**設定項目の説明**

次の表は、ティアカードの設定項目を表示順に示しています。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 設定項目 | 定義 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| ティア名 | 適用された価格ティアを識別する名前です。 | `base`、`standard` など、識別しやすい名前を使用してください。 | `base` |
| 段階条件 | このティアが適用される条件です。 | 「入力全体の長さ」「課金対象の入力トークン」「課金対象の出力トークン」「時」「分」「曜日」「月」「日付（日）」を選択できます。時間に関する項目ではタイムゾーンを選択します。<br/>「条件を追加」「条件グループを追加」を使用できます。グループ内では「すべてを満たす」または「いずれかを満たす」を選択でき、「反転」もできます。<br/>長さでティアを分ける場合は「入力全体の長さ」（`len`）を使用してください。「課金対象の入力トークン」（`p`）はキャッシュヒットで値が小さくなるため、意図しないティアが適用される可能性があります。 | なし<br/>条件を追加したときは「時」`>=`、タイムゾーンは `Asia/Shanghai` |
| 分岐の課金方式 | このティアをトークン単位とリクエスト単位のどちらで課金するかを指定します。 | 「トークン単位」の場合は、下の価格項目を入力します。単位は選択した価格設定通貨 / 100 万トークンです。<br/>「呼び出し単位」の場合は、「リクエスト単価」を入力します。単位は選択した価格設定通貨 / リクエストです。<br/>式で `image_count` を使用する画像モデルでは、「呼び出し単位」と「リクエスト単価」はどちらも「画像 1 枚あたりの価格」と表示されます。 | 「トークン単位」 |

</div>

**価格項目の説明**

各価格項目の先頭にはチェックボックスがあり、チェックを入れた項目のみ個別に課金されます。チェックを入れていないキャッシュ、画像、音声の使用量は、引き続き入力または出力に含まれ、それぞれの基本価格で課金されます。

ビジュアルエディターでの価格単位は選択した価格設定通貨 / 100 万トークンです。式内の係数は常に米ドル / 100 万トークンです。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| パラメーター名 | 式の変数 | 定義 |
| --- | --- | --- |
| 入力価格 | `p` | 入力トークンの基本単価です。 |
| 出力価格 | `c` | モデルが出力するトークンの基本単価です。 |
| キャッシュ読み取り価格 | `cr` | 既存のプロンプトキャッシュを再利用する際に、キャッシュにヒットした入力トークンの単価です。 |
| キャッシュ書き込み価格 | `cc` | デフォルトのラベルは「キャッシュ書き込み価格」です。「1 時間キャッシュ書き込み価格」にチェックを入れると、「キャッシュ作成 (5m)」と表示されます。12 時間の項目にも同時にチェックを入れた場合も同じです。「12 時間キャッシュ書き込み価格」のみにチェックを入れると、「キャッシュ作成 (30m)」と表示されます。Claude では 5 分、OpenAI では 30 分のキャッシュ書き込みに対応します。他の上流プロバイダーでは通常のキャッシュ書き込みに適用されます。 |
| 1 時間キャッシュ書き込み価格 | `cc1h` | 有効期間が **1 時間**のプロンプトキャッシュを作成する際に、キャッシュに書き込むトークンの単価です。Claude 専用です。チェックを入れていない場合は、キャッシュ書き込み価格の 1.6 倍（6 ÷ 3.75）で課金されます。 |
| 12 時間キャッシュ書き込み価格 | `cc12h` | OpenAI で有効期間が **12 時間**のプロンプトキャッシュを作成する際に、キャッシュに書き込むトークンの単価です。チェックを入れていない場合は、キャッシュ書き込み価格の 2 倍で課金されます。 |
| 画像入力価格 | `img` | 入力画像に対応する画像トークンの単価です。 |
| キャッシュ済み画像入力価格 | `img_cr` | キャッシュにヒットした画像入力トークンの単価です。上流プロバイダーが画像キャッシュの有効な使用量内訳を返す必要があります。 |
| 画像出力価格 | `img_o` | モデルが生成した画像に対応する画像出力トークンの単価です。 |
| 音声入力価格 | `ai` | 入力音声に対応する音声トークンの単価です。 |
| 音声出力価格 | `ao` | モデルが生成した音声に対応する音声トークンの単価です。 |

</div>

<Callout type="info" title="ヒント">
キャッシュ書き込み価格にもチェックを入れていない場合、長時間キャッシュへの書き込みには、入力価格に上記の倍率を掛けた価格が適用されます。
</Callout>

### リクエストルールを設定する

- 課金式の段階条件、フォールバックティア、リクエストルール

![モデル価格設定の追加：リクエストルールの例](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-model-prices-add-model-pricing.png)

「リクエストルールによる課金」はビジュアルエディターにのみ表示されます。リクエストパラメーター、リクエストヘッダー、または時刻に応じて、最終価格に倍率を掛けます。

**操作手順**

1. 編集領域の下部にある「リクエストルールによる課金」で、「ルールグループを追加」をクリックします。
2. ルールグループで「パラメーター／ヘッダーを追加」または「時間条件を追加」をクリックし、条件を追加します。
3. 「倍率」に、ルールが適用された場合の倍率を入力します。

<Callout type="info" title="ヒント">

- 「リクエストルールによる課金」の下には、「条件を満たすと最終価格に X を掛けます。複数のルールに一致した場合は、倍率を掛け合わせます。1 未満の値は割引になります。」と表示されます。
- 同じグループ内のすべての条件を満たすと、そのグループのルールが適用されます。複数のグループが適用される場合は、各グループの倍率を掛け合わせます。
- ルールが複雑すぎる場合は、「この式はビジュアルエディターで扱うには複雑すぎます。式エディターに切り替えて編集してください。」と表示されます。
</Callout>

**保存後の式**

- ルールは基本式の後ろに通常の乗算として追加されます。形式は `(基本式) * (条件 ? 倍率 : 1)` で、式エディターに切り替えると確認できます。
- リクエストルールとして消費ログに記録されるのは、条件が `param`、`header`、または時間関数を参照し、一致時の値が数値、不一致時の値が `1` である乗数のみです。

**設定項目の説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| フィールドまたは操作 | 入力要件 | 説明 |
| --- | --- | --- |
| リクエストボディのパラメーター | パラメーターのパス、比較方法、値 | リクエスト JSON 内のパスを読み取ります。たとえば `service_tier` でサービスレベルを区別できます。比較方法は「等しい」「含む」「存在する」「より大きい」「以上」「未満」「以下」です。クライアントから送られた元の JSON リクエストボディを読み取ります。 |
| リクエストヘッダー | ヘッダー名、比較方法、値 | 実際に送信されたリクエストヘッダーを照合します。比較方法は「等しい」「含む」「存在する」です。 |
| 時間 | 時間項目、タイムゾーン、比較値または範囲 | `Asia/Shanghai` など、タイムゾーンを明示します。時間項目は「時」「分」「曜日」「月」「日付（日）」です。比較方法は「等しい」「以上」「未満」「時間範囲」です。時間範囲には開始値を含み、終了値は含みません。21 時から 6 時までのように、開始値が終了値より大きい場合は午前 0 時をまたぐ範囲になります。 |
| 倍率 | 用途に応じた倍率 | 同じグループ内のすべての条件を満たす場合に適用されます。複数のグループが適用される場合は倍率を掛け合わせます。`1` 未満の値は割引を表します。 |

</div>

<Callout type="warn" title="注意">

- `service_tier` などのリクエストパラメーターに基づいて割増料金を設定する前に、チャネルがそのパラメーターを上流に転送することを確認してください。
- チャネルはデフォルトで `service_tier` を取り除きます。チャネル設定で「service_tier のパススルーを許可」を有効にしてください。無効のままでは、ユーザーに割増料金が適用されても、上流では標準サービス料金が適用される場合があります。
</Callout>

## Expression Language

Expressions are based on standard arithmetic with ternary operators.

### Token Variables

Input side:
- p — input token count (for pricing). Automatically excludes sub-categories priced separately (e.g., if cr is used, cache tokens are deducted from p)
- len — total input context length (for condition checks). Not affected by auto-exclusion; always reflects the full input length. Use in tier conditions
- cr — cache-hit (read) token count
- cc — cache-create token count (Claude 5-min TTL, OpenAI 30-min TTL)
- cc1h — cache-create token count (1-hour TTL, Claude-specific)
- cc12h — cache-create token count (12-hour TTL, OpenAI-specific)
- img — image input token count
- ai — audio input token count

Output side:
- c — output token count. Also auto-excludes sub-categories priced separately
- img_o — image output token count
- img_cr — image cache input tokens; deducted from img and cr only when the upstream reports a valid image cache breakdown
- ao — audio output token count

### p/c Auto-exclusion

p and c are fallback variables representing all tokens not separately priced in the expression. If the expression uses a sub-category variable (e.g., cr), those tokens are deducted from p to avoid double-billing. Unused sub-category tokens remain in p/c at base price.

Important: len is NOT affected by auto-exclusion. Tier conditions should use len instead of p to prevent cache hits from lowering p and misidentifying the tier.

### Built-in Functions

- tier(name, value) — labels the billing tier; must wrap the cost expression
- fixed(amount) — a finite non-negative USD price per request, used only as tier("name", fixed(0.01)); replaces token charges in that leaf. Other leaves may still use token prices. Group/request multipliers and existing tool surcharges still apply. Unsupported for task usage expressions and Realtime.
- max(a, b), min(a, b) — maximum/minimum
- ceil(x), floor(x), abs(x) — ceiling, floor, absolute value
- header(name) — reads a request header
- param(path) — reads a request body JSON path (gjson syntax)
- has(source, substr) — substring check
- hour(tz), minute(tz), weekday(tz), month(tz), day(tz) — time functions, tz is a timezone like "Asia/Shanghai"

### Price Coefficients

Numbers in the expression are $/1M tokens prices. For example, p * 2.5 means input $2.50/1M tokens.

## Expression Examples

Simple pricing:
tier("base", p * 2.5 + c * 15)

With cache:
tier("base", p * 2.5 + c * 15 + cr * 0.25)

Multi-tier (use len for conditions):
len <= 200000
  ? tier("standard", p * 3 + c * 15 + cr * 0.3 + cc * 3.75 + cc1h * 6)
  : tier("long_context", p * 6 + c * 22.5 + cr * 0.6 + cc * 7.5 + cc1h * 12)

Image model:
tier("base", p * 2 + c * 8 + img * 2.5)

Multimodal with audio:
tier("base", p * 0.43 + c * 3.06 + img * 0.78 + ai * 3.81 + ao * 15.11)

Three-tier example:
len <= 128000
  ? tier("standard", p * 1.1 + c * 4.4)
  : (len <= 1000000
    ? tier("medium", p * 2.2 + c * 8.8)
    : tier("long", p * 4.4 + c * 17.6))

## Rules

1. Every leaf branch must be wrapped in tier("name", cost_expr)
2. Use English tier names, e.g. "base", "standard", "long_context"
3. Use len for tier conditions (not p), supports <, <=, >, >=
4. Multi-tier uses nested ternary: cond1 ? tier(...) : (cond2 ? tier(...) : tier(...))
5. Price coefficients are the provider's official $/1M tokens prices
6. If cache/image/audio don't need separate pricing, omit those variables; their tokens are included in p/c automatically

Please generate a billing expression based on the model information and pricing requirements provided.

### 旧モードからの変換

**操作手順**

1. 課金モードのタブで「トークン単位（非推奨）」または「リクエスト単位（非推奨）」を選択します。
2. 案内の下にある「課金式に変換」をクリックします。
3. 「価格設定の移行プレビュー」で左右の内容を比較し、確認後に「下書きに適用」をクリックします。
4. 「モデル価格を保存」をクリックします。[モデル価格を保存する](#モデル価格を保存する)を参照してください。

<Callout type="info" title="ヒント">

- 旧モードのタブには「旧価格設定モードは非推奨です。現在の価格を課金式の下書きに変換できます。変更は保存後に適用されます。」と表示されます。
- 課金式の下書きがすでにある場合、ボタンは無効になり、「課金式の下書きがすでにあります。編集を続けるには『課金式』タブを開いてください。」と表示されます。
- 変換できない場合は画面に理由が表示されます。該当するケースは下の「**変換ルール**」を参照してください。
</Callout>

**変換ルール**

- トークン単位モードでは、`tier("base", p * … + c * … …)` が生成されます。基本入力単価はモデル倍率 × 2（米ドル / 100 万トークン、1 米ドルあたりのデフォルトクォータで換算）となり、設定済みの補完倍率、キャッシュ倍率、画像倍率に対応する項目も生成されます。
- リクエスト単位モードでは、`tier("request", fixed(価格))` が生成されます。
- 画像のリクエスト単価は `tier("image", fixed(価格)) * image_count` に変換され、従来のサイズ倍率と品質倍率も付加されます。
- 次の場合は自動変換できません。タスクプラグインのモデル、動画、Realtime、上流の料金からキャッシュ書き込み料金を逆算する OpenRouter の Claude 価格設定、Gemini と OpenAI のインターフェースで同一モデルの音声価格が異なる場合、入力価格が未設定の場合、モデルのルーティングを検証できない場合、すでに課金式を使用している場合。
- 変換後も旧価格のフィールドは保持されるため、旧モードに戻すことができます。
- 変換後の事前控除と丸め処理には、課金式のルールが適用されます。適用単価は同じですが、リクエストごとの丸め後の料金には若干の差が生じる場合があります。

## ルールと仕組み

このセクションでは、式の単位とクォータへの換算、使用量変数、関数と構文、事前控除・精算・ログ、タスクモデルの課金ルール、保存時の検証を説明します。

### 単位とクォータへの換算

式内の価格係数は米ドル建てです。計算結果は次のルールに従ってクォータに換算されます。

**換算ルール**

- **単位**　トークンの係数は米ドル / 100 万トークンです。`p * 2.5` は入力 100 万トークンあたり 2.5 米ドル、`fixed(0.01)` は 1 リクエストあたり 0.01 米ドルを表します。
- **換算**　クォータ = 式の結果 ÷ 1,000,000 × 1 米ドルあたりのクォータ（デフォルトは 500,000）× グループ倍率。計算結果は四捨五入します。
- **バージョンプレフィックス**　式の先頭に `v1:` を付けることができます。省略時は v1 として扱われます。

**換算例**

- `tier("base", p * 2 + c * 8)` で、入力 1,000 トークン、出力 500 トークン、グループ倍率 1 の場合、結果は 6,000、つまり 0.006 米ドルです。1 米ドルあたりのデフォルトクォータで換算すると、3,000 クォータが差し引かれます。
- `fixed()` の金額も内部で 1,000,000 倍して結果に反映されます。そのため、同じ換算条件では `fixed(0.01)` により 1 リクエストあたり 5,000 クォータが差し引かれます。

**変数の説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_td:nth-child(2)]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 変数 | 名前 | 定義 |
| --- | --- | --- |
| `len` | 入力コンテキストの全長 | 長さに応じてティアを選択するために使います。下記の自動除外の影響は受けません。Claude 以外の形式では上流から返される入力トークンの総数です。Claude 形式ではテキスト入力、キャッシュ読み取り、キャッシュ作成の合計です。 |
| `p` | 基本入力トークン | 入力の基本価格が適用される使用量です。式で個別に課金するキャッシュ、画像、音声の入力は `p` から自動的に除外されます。個別に課金されない分は `p` に残ります。 |
| `c` | 基本出力トークン | 出力の基本価格が適用される使用量です。式で個別に課金する `img_o` と `ao` は `c` から自動的に除外されます。 |
| `cr` | キャッシュ読み取りトークン | プロンプトキャッシュにヒットし、キャッシュを再利用した入力の使用量です。 |
| `cc` | キャッシュ作成トークン | Claude では 5 分、OpenAI では 30 分のキャッシュ書き込み使用量です。他の上流プロバイダーでは通常のキャッシュ書き込み使用量です。 |
| `cc1h` | 1 時間キャッシュ作成トークン | Claude の 1 時間キャッシュの作成使用量です。`1h` はキャッシュの有効期間です。 |
| `cc12h` | 12 時間キャッシュ作成トークン | OpenAI の 12 時間キャッシュへの書き込み使用量です。 |
| `img` | 画像入力トークン | 入力画像に対応するトークン使用量です。 |
| `img_cr` | 画像キャッシュ読み取りトークン | キャッシュにヒットした画像入力の使用量です。式がこの変数を参照し、上流プロバイダーが画像キャッシュの有効な内訳を返した場合にのみ個別に計上されます。それ以外の場合は 0 です。 |
| `img_o` | 画像出力トークン | モデルが生成した画像に対応する出力トークンの使用量です。 |
| `ai` | 音声入力トークン | 入力音声に対応するトークン使用量です。 |
| `ao` | 音声出力トークン | モデルが生成した音声に対応する出力トークンの使用量です。 |
| `image_count` | 課金対象の画像枚数 | 1 枚単位で課金する画像の枚数です。1～128 の整数で、未指定の場合は 1 です。`fixed()` を使うティアに掛けることができます。リクエストで指定された枚数に基づいて事前控除し、実際に返された枚数に基づいて精算します。 |

</div>

**自動除外ルール**

- 例として、上流から入力 1,000 トークン（キャッシュ読み取り 200、画像 100 を含む）が返されたとします。`p * 3 + c * 15` の場合は `p = 1000`、`p * 3 + c * 15 + cr * 0.3` の場合は `p = 800`、さらに `img * 2` を加えた場合は `p = 700` です。
- 上記の自動除外は、OpenAI などの Claude 以外の形式に適用されます。Claude 形式が返す入力トークンにはキャッシュが含まれていないため、個別に課金されないキャッシュ読み取りとキャッシュ書き込みの使用量は入力に加算されます。控除後に `p` や `c` が 0 未満になった場合は 0 として扱います。
- 長時間キャッシュへの書き込みを個別に課金しない場合は、`cc1h` に `cc` の価格の 1.6 倍、`cc12h` に 2 倍を適用します。`cc` にも価格を設定していない場合は、`p` の価格に同じ倍率を掛けて計算します。

### 関数

**課金関数と数値関数**

| 関数 | 引数の定義 | 動作／戻り値 | 例 |
| --- | --- | --- | --- |
| `tier(name, value)` | `name` はティア名の文字列、`value` は課金式です。 | 課金の計算結果を返し、適用ティアの名前を記録します。 | `tier("base", p * 2 + c * 8)` |
| `fixed(amount)` | `amount` は有限かつ非負の数値リテラルです。単位は米ドル / リクエストです。 | リクエスト単位の基本価格を設定します。`tier()` の第 2 引数に直接記述する必要があります。ティアに `image_count` やリクエストルールの倍率を掛けることができます。トークン料金との加算や、複数の `tier()` の加算はできません。実際には適用されない分岐でも、これらのルールを満たす必要があります。Realtime リクエストとタスクの使用量に基づく式では使用できません。グループ倍率、リクエストルールの倍率、ツール呼び出しの追加料金は通常どおり適用されます。 | `tier("request", fixed(0.01))`、`tier("image", fixed(0.04)) * image_count` |
| `max(a, b)` | 2 つの数値です。 | 大きい方の値を返します。計算値の下限を設定できます。 | `max(p * 2 + c * 8, 1000)` の場合、トークン課金の料金は最低 0.001 米ドルになります。 |
| `min(a, b)` | 2 つの数値です。 | 小さい方の値を返します。計算値の上限を設定できます。 | `min(p, 100000)` は最大 100,000 の入力使用量を返します。 |
| `ceil(x)` | 1 つの数値です。 | 整数に切り上げます。 | `ceil(1.2)` は `2` を返します。 |
| `floor(x)` | 1 つの数値です。 | 整数に切り下げます。 | `floor(1.8)` は `1` を返します。 |
| `abs(x)` | 1 つの数値です。 | 絶対値を返します。 | `abs(-2)` は `2` を返します。 |

| 関数 | 戻り値 | 例の意味 |
| --- | --- | --- |
| `hour(tz)` | 時（`0–23`）。 | `hour("Asia/Shanghai") >= 21` は現地時刻の 21 時以降を表します。 |

<Callout type="info" title="ヒント">

- 引数には `Asia/Shanghai` や `UTC` などの IANA タイムゾーン名を指定します。ビジュアルエディターの段階条件では、無効なタイムゾーンが通知されます。式エディターで誤った名前を指定したり空欄にしたりしてもエラーにはならず、サーバー側でもブラウザーのシミュレーションでも UTC で計算されます。
- 事前控除と精算は、それぞれの処理時点の時刻で式を評価します。リクエストが時間帯の境界をまたいだ場合は、精算時（リクエスト終了時）の時間帯に基づいて課金されます。
</Callout>

### よく使う構文

**構文の説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 構文 | 意味 | 例 |
| --- | --- | --- |
| `+`、`-`、`*`、`/` | 加算、減算、乗算、除算です。 | `p * 2 + c * 8` |
| `>`、`>=`、`<`、`<=` | 大小を比較し、真偽値を返します。 | `len <= 200000` |
| `==`、`!=` | 等しい、等しくないことを判定します。 | `param("priority") == true` |
| `&&` | 論理積です。両方の条件を満たす場合に真になります。 | `len < 32000 && c < 200` |
| `\|\|` | 論理和です。少なくとも一方の条件を満たす場合に真になります。 | `hour("UTC") >= 21 \|\| hour("UTC") < 6` |
| `!` | 論理否定です。 | `!(param("priority") == true)` |
| `条件 ? A : B` | 条件が真の場合は A を、偽の場合は B を評価します。 | `len <= 200000 ? tier("short", p * 2) : tier("long", p * 4)` |
| `(...)` | 式をグループ化し、計算順序を明示します。 | `(基本式) * (条件 ? 2 : 1)` は構造を示す例です。日本語の仮置き部分を実際の式に置き換えてください。 |
| `"テキスト"`、`true`、`false`、`nil` | 文字列、ブール値、空値です。 | `true` と `"true"` は型が異なります。 |

</div>

### 事前控除、精算、ログ

リクエスト送信前に推定使用量に基づいて事前控除し、上流から応答が返った後に実際の使用量で精算します。課金の明細は消費ログに記録されます。

**処理ルール**

- **事前控除**　リクエスト送信前に、ローカルで推定した入力トークン数を `p` と `len` の両方に使用します。`c` とその他の使用量はすべて 0 として評価します。
- **事前控除倍率**　トークン単位のティアの結果には「入力の事前控除倍率」を掛けます。リクエスト単位のティアには、この倍率を適用しません。最後にグループ倍率を掛けます。<a href="/ja/docs/guide/feature-guide/system-settings/settings-billing#クォータ設定" target="_blank" rel="noopener noreferrer">クォータ設定</a>を参照してください。
- **事前控除時の条件**　`c` を条件に使う分岐は、事前控除時には常に `c = 0` として判定されます。
- **事前控除額が負の場合**　事前控除の結果が 0 未満の場合、リクエストは拒否されます。
- **精算**　上流から応答が返った後、実際の使用量で式を再評価し、事前控除額との差分を返還または追加で差し引きます。精算時に式の評価に失敗した場合は、事前控除額で精算します。
- **ログ**　消費ログには、適用ティア `matched_tier`、課金単位 `billing_unit`、リクエスト単価 `fixed_price`、画像枚数 `image_count`、リクエストルール `request_rules`（各ルールの一致状況を含む）、base64 でエンコードされた式の全文 `expr_b64` が記録されます。ユーザーも自分のログ詳細でこれらのフィールドを確認できるため、ユーザーに公開したくない内容は式に記述しないでください。

### タスクモデル

タスクプラグインが提供するモデルは、プラグインが報告した使用量に基づいて課金されます。編集パネルでの操作は、[タスクモデルの価格を設定する](#タスクモデルの価格を設定する)を参照してください。

**課金ルール**

- タスク用の式では、`u("フィールド")` でプラグインが報告した使用量（秒数や枚数など）を読み取ります。結果はそのまま米ドル建ての金額となり、1,000,000 で割る必要はありません。
- タスク用の式では `fixed()` を使用できません。
- タスク用の式では、トークン数や `image_count` など、チャットリクエストの使用量を読み取れません。保存時に `task usage expressions cannot read chat request quantities …` と表示されます（英語のみ）。
- プラグインが同じモデルの通常リクエストも転送する場合は、通常リクエストにモデル単位の価格が適用されます。
- この場合、モデル単位の価格が旧モード「リクエスト単位（非推奨）」の価格、または `u()` を含む式であるときに限り、タスクにも引き継がれます。それ以外の場合は、該当するプラグインのタブで個別に価格を設定してください。
- 個別に設定していない場合、タスクの送信時に「モデル … にはプラグイン … のタスク価格がありません。モデル価格設定で、このプラグインの価格を個別に設定してください」と表示されます。
- プラグインの使用量フィールド、プラグイン単位での価格の上書き、保存時の検証については、<a href="/ja/docs/plugins/billing" target="_blank" rel="noopener noreferrer">使用量と課金</a>を参照してください。

**価格設定に対応が必要な場合**

- タスクモデルに課金できない場合は、モデル価格一覧でモデル名の横に「価格設定に対応が必要」と表示されます。理由は「価格がまだ設定されていません」「価格設定が、プラグインが提供を終了した使用量フィールドを参照しています」「プラグインはこのモデルの提供を終了しました」のいずれかです。
- 対処方法は、<a href="/ja/docs/guide/feature-guide/system-settings/settings-billing#価格の対応が必要" target="_blank" rel="noopener noreferrer">課金と支払いの設定</a>を参照してください。

### 保存時の検証

保存時にサーバーがモデルごとに式を検証します。検証に失敗したモデルがある場合は、一括保存の対象全体が保存されません。

**検証ルール**

- 式をコンパイルできる必要があります。通常モデルでは `u()` を使用できません。
- 続いて、すべてが 0 のケースや非常に大きな `len` を含む 7 通りの固定使用量について、それぞれ 2 種類のリクエストコンテキストで試算します。一方は空のリクエスト、もう一方は `anthropic-beta: fast-mode-2026-02-01` リクエストヘッダーと `service_tier: fast` リクエストボディを含むリクエストです。
- すべての試算結果が有限かつ 0 以上の数値である必要があります。
- 他のリクエストパラメーター、リクエストヘッダー、時間条件によって適用される分岐は、この試算の対象外です。
- エラーメッセージについては、[よくある質問](#よくある質問)を参照してください。

## 保存と反映

エディターでの変更は下書きにのみ反映され、「モデル価格を保存」をクリックすると送信されます。操作手順は[モデル価格を保存する](#モデル価格を保存する)、保存方式は<a href="/ja/docs/guide/feature-guide/system-settings/system-setting#保存方法" target="_blank" rel="noopener noreferrer">システム設定の概要</a>を参照してください。モデル価格はシステム設定として保存され、次のタイミングで反映されます。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 対象 | 反映されるタイミング |
| --- | --- |
| 保存リクエストを処理したノード | 次のリクエストから、新しい価格で事前控除と精算を行います。 |
| その他のノード | 通常は約 3 秒以内、遅くとも 1 同期周期（デフォルトは 60 秒）以内にシステム設定が同期され、新しい価格が適用されます。<br/>同期が完了するまでは旧価格で課金されます。<a href="/ja/docs/guide/feature-guide/system-settings/system-setting#反映範囲と複数インスタンス間の同期" target="_blank" rel="noopener noreferrer">適用範囲と複数インスタンス間の同期</a>を参照してください。 |
| 事前控除済みのリクエスト | 精算時にも、事前控除時の式を使用します。今回の保存による影響はありません。 |
| 送信済みの非同期タスク | タスクモデルに送信済みのタスクには、送信時の式が適用されます。今回の保存による影響はありません。 |
| モデル広場 | 保存リクエストを処理したノードでは価格がただちに更新されます。その他のノードでは、約 3 秒以内にシステム設定が同期されてから更新されます。すでにモデル広場を開いているユーザーには、ページを再読み込みすると新しい価格が表示されます。 |

</div>

**補足**

- **無効な下書き**　ビジュアルエディターに無効なフィールドがあると保存できません。「無効なフィールドを修正してから保存するか、モードを切り替えてください。最後に有効だった式は保持されています。」と表示されます。
- **一括保存**　複数のモデルを一度に送信した場合、いずれかのモデルの検証に失敗すると、どのモデルも保存されず、既存の価格が維持されます。検証ルールは[保存時の検証](#保存時の検証)を参照してください。
- **バージョンの競合**　ページを開いた後に別のユーザーが価格を変更した場合は、保存が拒否されます。「価格設定を再読み込み」をクリックしてから、変更をやり直してください。

## 注意事項

- **試算の対象となる分岐には限りがあります**　他のリクエストパラメーター、リクエストヘッダー、時間条件によって適用される分岐は、個別には検証されません。すべての分岐の結果が 0 以上になることを確認してください。[保存時の検証](#保存時の検証)を参照してください。
- **「デフォルト価格に戻す」を実行するとカスタム価格が削除されます**　モデルの「価格設定」タブで実行すると、そのモデルのカスタム価格（課金式を含む）が削除され、組み込みのデフォルト値に戻ります。デフォルト価格がないモデルは価格未設定になります。<a href="/ja/docs/guide/feature-guide/admin/model#価格設定" target="_blank" rel="noopener noreferrer">モデル管理</a>を参照してください。
- **課金フィールドはユーザーにも表示されます**　式の全文などの課金フィールドは、ユーザー自身のログ詳細に表示されます。[事前控除、精算、ログ](#事前控除精算ログ)を参照してください。
- **リクエストパラメーターに基づく割増料金を設定するには、チャネルでそのパラメーターを転送する必要があります**　チャネルはデフォルトで `service_tier` を取り除きます。[リクエストルールを設定する](#リクエストルールを設定する)を参照してください。

## よくある質問

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="見積もり結果と実際の請求額が一致しない">

**説明**　トークン見積もりにはリクエストルールとグループ倍率が適用されません。リクエストシミュレーションにもグループ倍率は適用されません。実際の請求額は、精算時の使用量と時刻で再計算したうえでグループ倍率を掛け、ツール呼び出しの追加料金を別途加算します。
</Accordion>

<Accordion title="ティアが想定どおりに切り替わらない">

**考えられる原因**

- 条件に `len` ではなく `p` を使っています。キャッシュにヒットすると `p` の値が小さくなります。
- `c` を条件に使う分岐は、事前控除時には `c = 0` として判定されます。実際の出力に基づいて切り替わるのは精算時です。
</Accordion>

<Accordion title="時間帯別の価格がずれて適用される">

**考えられる原因**　時間関数のタイムゾーン名が誤っているか、空欄になっています。この場合はエラーが表示されず、UTC で計算されます。
</Accordion>

<Accordion title="リクエストルールが適用されない">

**説明**　`param()` は JSON 形式のリクエストボディのみを読み取ります。

**対処方法**

1. リクエストシミュレーションで、条件が「一致」になっているか確認します。
2. 消費ログに記録されたリクエストルールを確認します。
</Accordion>

<Accordion title="保存時に expr compile error と表示される">

**エラーメッセージ**　`expr compile error: …` が含まれます（英語のみ）。

**考えられる原因**

- 構文エラーがあるか、存在しない変数または関数を使っています。
- 予約名を使用しています。この場合は `identifier "_trace" is reserved for internal use` も表示されます。

**対処方法**

1. スペル、括弧、引用符、カンマを確認します。
2. 予約名を使用している場合は、別の名前に変更します。
</Accordion>

<Accordion title="保存時に fixed price に関するエラーが表示される">

**エラーメッセージ**　`fixed price must be a finite, non-negative numeric literal…` または `fixed pricing requires tier(name, fixed(amount)) leaves…` が含まれます（英語のみ）。

**考えられる原因**

- `fixed()` の金額が非負の数値リテラルになっていません。
- `fixed()` を使うティアをトークン料金と加算しているか、式の構造が要件を満たしていません。

**対処方法**

1. `fixed(0.01)` のように、金額を数値リテラルに変更します。
2. リクエスト単位の各ティアを `tier(名前, fixed(金額))` の形で記述します。
</Accordion>

<Accordion title="保存時に result must be finite and non-negative と表示される">

**エラーメッセージ**　`vector {p=…, c=…}: result must be finite and non-negative, got …` が含まれます（英語のみ）。

**考えられる原因**　いずれかの試算結果が負数または無限大になっています。試算の対象範囲は[保存時の検証](#保存時の検証)を参照してください。

**対処方法**

1. 減算、除算、各分岐の計算を確認します。
</Accordion>

<Accordion title="通常モデルの保存時に expression references usage keys と表示される">

**エラーメッセージ**　`expression references usage keys […] but the model has no task plugin usage schema` が含まれます（英語のみ）。

**考えられる原因**　通常モデルで `u()` を使用しています。

**対処方法**

1. `u()` を削除します。モデルがタスクプラグインから提供されている場合は、[タスクモデル](#タスクモデル)を参照してください。
</Accordion>

<Accordion title="保存時に model pricing changed と表示される">

**エラーメッセージ**　`model pricing changed; reload before saving` が含まれます（英語のみ）。

**考えられる原因**　ページを開いた後に、別のユーザーが対象モデルの価格を変更しています。

**対処方法**

1. 「価格設定を再読み込み」をクリックします。
2. 変更をやり直して保存します。
</Accordion>

<Accordion title="タスク送信時にプラグインのタスク価格がないと表示される">

**エラーメッセージ**　「モデル … にはプラグイン … のタスク価格がありません。モデル価格設定で、このプラグインの価格を個別に設定してください」（英語では Model … has no task price for plugin …; set a separate price for this plugin in model pricing）

**考えられる原因**　プラグインが同じモデルの通常リクエストも転送しています。モデル単位の価格が旧モード「リクエスト単位（非推奨）」の価格でも `u()` を含む式でもなく、該当するプラグインにも個別の価格が設定されていません。`fixed()` を使う式はタスクに引き継げません。

**対処方法**

1. 対象モデルの価格エディターを開き、該当するプラグインのタブをクリックします。
2. 「このプロバイダーに個別の価格を設定」を有効にし、価格を設定して保存します。[タスクモデルの価格を設定する](#タスクモデルの価格を設定する)を参照してください。
</Accordion>

</Accordions>
