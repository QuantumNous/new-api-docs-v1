- サイドバーの「一般」→「タスクログ」から開きます。
- 動画、音楽、画像生成などの非同期タスクのステータス、進捗、生成結果、失敗理由を確認できます。
- ページには「画像生成ログ」と「タスクログ」の 2 つのタブがあります。サイドバーから開くと「タスクログ」タブが表示されます。

<Callout type="info" title="ヒント">

- 非同期タスクとは、送信してから結果が生成されるまでに時間がかかるタスクです。動画や音楽の生成、Midjourney による画像生成などが該当します。送信に成功するとタスク ID が返され、システムがバックグラウンドでタスクのステータスを定期的に照会して更新します。
- 一般ユーザーは、自分のアカウントのタスクのみ確認できます。管理者は、ページ右上の「すべて」と「自分のみ」を切り替えられます。この切り替えは管理者にのみ表示されます。「自分のみ」を選択すると、一般ユーザーと同じ内容が表示されます。
- タスクの請求と返金の記録は<a href="/ja/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">利用ログ</a>で確認できます。
- 左サイドバーに「タスクログ」ページが表示されない場合や、ページに「画像生成ログ」「タスクログ」タブが表示されない場合は、以下の設定を確認してください。<br/>「プロフィール」ページの「左サイドバーの個人設定」で「コンソール領域」「画像生成ログ」「タスクログ」を有効にし、保存します。
</Callout>

## タスクログの概要

- タスクログ - タスク一覧

![タスクログのタスク一覧ページ](/assets/guide/feature-guide/general-task-logs.png)

「タスクログ」タブでは、期間やタスク ID で動画や音楽などの非同期タスクを検索し、ステータス、進捗、生成結果を確認できます。

- [タスクを絞り込む](#タスクを絞り込む)
- [タスクの詳細と成果物を確認する](#タスクの詳細と成果物を確認する)
- [画像生成ログを確認する](#画像生成ログを確認する)
- [プロンプト、画像、失敗理由を確認する](#プロンプト画像失敗理由を確認する)
- [失敗したタスクの返金を確認する](#失敗したタスクの返金を確認する)

<Callout type="info" title="ヒント">
タスクが長時間完了しない場合や失敗した場合は、[よくある質問](#よくある質問)を参照してください。
</Callout>

## タスクを絞り込む

**操作手順**

1. ページタイトルの下にある「タスクログ」または「画像生成ログ」タブをクリックします。
2. 「期間」をクリックし、プリセットから選択します。期間を手動で指定する場合は、「開始日時」と「終了日時」を入力して「確定」をクリックします。
3. 必要に応じてタスク ID を入力します。「タスクログ」タブでは「タスク ID で絞り込む」、「画像生成ログ」タブでは「MjProxy タスク ID で絞り込む」に入力します。
4. 「検索」をクリックするか、入力欄で Enter キーを押します。
5. 絞り込み条件をクリアするには、「リセット」をクリックします。

<Callout type="info" title="ヒント">

- デフォルトでは、当日の 00:00:00 から現在時刻の 1 時間後までに送信されたタスクのみが表示されます。それ以前のタスクを探す場合は、先に期間を変更してください。
- 絞り込み条件を変更したら、「検索」をクリックして適用します。ページは自動更新されないため、タスクの最新のステータスを確認するには「検索」をクリックしてください。
</Callout>

**絞り込み項目の説明**

絞り込みエリアは 1 行で、2 つのタブで異なるのはタスク ID の入力欄だけです。以下の表は、絞り込みエリアでの表示順に並んでいます。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 絞り込み項目 | 定義 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| 期間 | タスクの送信日時で絞り込みます。開始日時と終了日時も範囲に含まれます。 | プリセットは「今日」「7 日間」（今日を含む）、「今週」（日曜から土曜）、「30 日間」（今日を含む）、「今月」です。手動で指定する場合は秒単位で入力し、「確定」をクリックします。 | 当日の 00:00:00 から現在時刻の 1 時間後まで |
| タスク ID で絞り込む | 「タスクログ」タブのタスクをタスク ID で検索します。 | 任意です。ID の完全一致で検索します。「タスク ID」列の値をクリックするとコピーできます。 | 空欄 |
| MjProxy タスク ID で絞り込む | 「画像生成ログ」タブのタスクをタスク ID で検索します。 | 任意です。ID の完全一致で検索します。 | 空欄 |
| チャネル ID（管理者にのみ表示） | タスクを処理したチャネルで絞り込みます。 | 「すべて」ビューにのみ表示されます。チャネル ID を数値で入力します。 | 空欄 |
</div>

## タスクの詳細と成果物を確認する

- タスクログ - タスクの詳細

![タスクログのタスク詳細ページ](/assets/guide/feature-guide/general-task-logs-task-details.png)

**詳細を確認する手順**

1. 「タスクログ」タブで、対象タスクの行の「詳細」列にある「詳細を表示」をクリックします。
2. 「タスクの詳細」ウィンドウでタスク情報を確認します。失敗したタスクの詳しい理由は「失敗理由」で確認できます。

**成果物を確認する手順**

1. ステータスが「成功」のタスクの行で、「成果物」列の「成果物」をクリックします。一部の音楽・動画タスクでは、「クリックして音楽をプレビュー」または「クリックして動画をプレビュー」をクリックします。
2. ウィンドウで画像をプレビューするか、動画や音声を再生します。
3. 「ダウンロード」をクリックし、新しいタブでファイルを開いて保存します。

<Callout type="warn" title="注意">

- 成果物はアクセスするたびに上流サービスから取得します。上流サービス側でファイルの有効期限が切れたり削除されたりすると、プレビューやダウンロードができなくなるため、早めにダウンロードして保存してください。
- プレビューに失敗すると「メディアのプレビューに失敗しました。もう一度お試しください。」と表示されます。「再試行」をクリックすると再読み込みできます。
</Callout>

## 画像生成ログを確認する

- タスクログ - 画像生成ログ

![タスクログの画像生成ログページ](/assets/guide/feature-guide/general-task-logs-drawing-logs.png)

**操作手順**

1. ページタイトルの下にある「画像生成ログ」タブをクリックします。
2. 必要に応じて期間を設定するか、「MjProxy タスク ID で絞り込む」にタスク ID を入力し、「検索」をクリックします。
3. タスクのステータス、進捗、生成された画像を確認します。

**項目の説明**

「画像生成ログ」タブには以下の列があります。「表示」で選択できる列は[ページのボタンと絞り込み](#ページのボタンと絞り込み)を参照してください。

| 項目 | 定義 | 入力要件と制限 | 備考 |
| --- | --- | --- | --- |
| 送信日時 | タスクの送信日時とステータスです。 | システムが自動で記録します。変更できません。 | 上段に送信日時、下段にステータスが色付きの文字で表示されます。各ステータスの意味は[画像生成タスクのステータス](#画像生成タスクのステータス)を参照してください。 |

| プロンプト | タスク送信時のプロンプトです。 | — | 1 行に収まるように省略表示されます。クリックすると「プロンプトの詳細」ウィンドウが開きます。 |
| 失敗理由 | タスクが失敗した理由です。 | 失敗したタスクにのみ内容が表示されます。その他のタスクには「-」が表示されます。 | 赤字で 1 行に収まるように省略表示されます。クリックすると「失敗理由の詳細」ウィンドウが開きます。 |

## プロンプト、画像、失敗理由を確認する

- タスクログ - プロンプトの詳細

![タスクログのプロンプト詳細ページ](/assets/guide/feature-guide/general-task-logs-drawing-logs-prompt-details.png)

**プロンプトを確認する手順**

1. 「画像生成ログ」タブで、対象タスクの行の「プロンプト」列にあるテキストをクリックします。
2. 「プロンプトの詳細」ウィンドウで「プロンプト」を確認します。英訳がある場合は、下に「プロンプト (英語)」が表示されます。
3. 内容欄の右上にあるコピーボタンをクリックして、プロンプトをコピーします。

**画像を確認する手順**

1. 対象タスクの行の「画像」列にある「表示」をクリックします。
2. 「画像プレビュー」ウィンドウで画像と画像の URL を確認します。

**失敗理由を確認する手順**

1. 対象タスクの行の「失敗理由」列にある赤字のテキストをクリックします。
2. 「失敗理由の詳細」ウィンドウで「エラーメッセージ」を確認します。コピーボタンをクリックするとコピーできます。

<Callout type="info" title="ヒント">
画像は上流サービスに保存されます。上流サービス側で画像が削除されたり有効期限が切れたりすると、「画像プレビュー」ウィンドウに「画像を読み込めません」と表示されます。
</Callout>

## 失敗したタスクの返金を確認する

**操作手順**

1. 「タスクログ」タブで、失敗したタスクの行にある「詳細を表示」をクリックし、「失敗理由」を確認してタスク ID をコピーします。画像生成タスクの場合は、「画像生成ログ」タブの「タスク ID」列でコピーします。
2. <a href="/ja/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">利用ログ</a>を開き、種類のドロップダウンから「返金」を選択します。タスクが失敗した時刻を含む期間を指定して「検索」をクリックします。
3. 返金記録の「詳細」列にある「非同期タスクの返金」をクリックし、「返金の詳細」でタスク ID と理由を照合します。

**返金ルール**

タスクの送信時に、まず価格に応じてクォータが差し引かれます。タスクが失敗またはタイムアウトすると、差し引かれた全額が元の請求元（ウォレット残高またはサブスクリプションのクォータ）に戻ります。使用した API キーのクォータも戻り、利用ログに「返金」の記録が 1 件追加されます。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 状況 | 「失敗理由」の表示 | 返金 |
| --- | --- | --- |
| 上流サービスがタスクの失敗を返した | 上流サービスが返した理由。英語の場合があります。 | 全額返金 |
| 上流サービスでタスクが見つからない | 「上流サービスでこのタスクが見つかりません」 | 全額返金 |
| 複数回連続でタスクのステータスを取得できなかった | 「上流サービスのタスクステータスの照会に失敗しました」 | 全額返金 |
| 送信から 3 日（デフォルト）を過ぎても完了しなかった | 「タスクがタイムアウトしました」 | 全額返金 |
| 2026 年 2 月 22 日より前に送信されたタスクがタイムアウトした | 「タスクがタイムアウトしました（旧システムから引き継がれたタスクのため返金されません。管理者にお問い合わせください）」 | 返金されません。管理者にお問い合わせください。 |
| タスクで使用したチャネルが利用できなくなった | 「チャネル情報の取得に失敗しました。管理者にお問い合わせください」 | 利用ログで返金記録を確認してください。記録がない場合は、タスク ID を管理者に送ってください。 |
| 画像生成タスクが失敗した | 上流サービスが返した理由 | 全額返金。返金理由は「構図の作成に失敗」です。 |
| 画像生成タスクが送信から 1 時間を過ぎても完了しなかった | 「上流サービスのタスクがタイムアウトしました（1 時間超過）」 | 全額返金。返金理由は「構図の作成に失敗」です。 |
</div>

<Callout type="info" title="ヒント">

- 返金の有無は、利用ログの「返金」記録で確認してください。タスクのステータスが「失敗」でも、返金済みかどうかは判断できません。
- 成功したタスクは実際の使用量に基づいて精算されます。実際の使用量が送信時に差し引かれたクォータを下回る場合は、差額が返金され、「返金」として記録されます。上回る場合は差額が追加で差し引かれ、「消費」の記録が 1 件追加されます。
</Callout>

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| ステータス | 意味 | 備考 |

| 未開始 | タスクは送信済みで、システムは上流サービスの処理状況をまだ取得していません。 | 進捗は通常「0%」です。しばらくしてから「検索」をクリックし、最新のステータスを確認してください。 |

| 処理中 | 上流サービスが結果を生成しています。 | — |

| 失敗 | タスクが失敗したか、タイムアウトしました。 | 進捗は「100%」と表示されます。失敗理由は「タスクの詳細」で確認できます。返金については[失敗したタスクの返金を確認する](#失敗したタスクの返金を確認する)を参照してください。 |

## よくある質問

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="タスクが「キュー待ち」または「処理中」のままになる">
**考えられる原因**

- 動画、音楽、画像の生成には数十秒から数分かかります。上流サービスが混雑している場合は、さらに時間がかかります。
- バックグラウンドでタスクの状態を定期的に照会して更新するため、反映に時間がかかります。
- ページは自動で更新されません。

**対処方法**

1. 「検索」をクリックして最新の状態を確認します。
2. そのままお待ちください。送信から 3 日（デフォルト）を過ぎても完了しないタスクは「失敗」となり、クォータが返還されます。画像生成タスクの場合は 1 時間です。
3. 長時間状態が変わらない場合は、タスク ID を管理者に送ってください。
</Accordion>

<Accordion title="タスクの状態が「失敗」になっている">
「失敗理由」には、上流サービスから返されたメッセージ（英語の場合があります）または以下のシステムメッセージが表示されます。

| 表示メッセージ | 考えられる原因 | 対処方法 |
| --- | --- | --- |
| 「タスクがタイムアウトしました」（英語: Task timed out） | 送信から 3 日（デフォルト）を過ぎてもタスクが完了していません。 | タスクを再送信し、使用ログで返金を確認します。 |
| 「上流サービスでタスクが見つかりません」（英語: Upstream task not found） | 上流サービスにこのタスクの記録が残っていません。 | タスクを再送信し、使用ログで返金を確認します。 |
| 「上流サービスのタスク状態を照会できませんでした」（英語: Failed to query the upstream task status） | タスクの状態を繰り返し照会しましたが、取得できませんでした。 | しばらくしてからタスクを再送信し、使用ログで返金を確認します。 |
| 「チャネル情報を取得できませんでした。管理者にお問い合わせください」（英語: Failed to get the channel information. Please contact the administrator） | タスクで使用したチャネルが利用できなくなっています。 | 使用ログで該当タスクの返金記録を探し、見つからない場合はタスク ID を管理者に送ってください。 |
| 「上流サービスのタスクがタイムアウトしました（1 時間超過）」（英語: Upstream task timed out (over 1 hour)） | 画像生成タスクの送信から 1 時間を過ぎても完了していません。 | タスクを再送信し、使用ログで返金を確認します。 |
| 「タスクがタイムアウトしました（旧システムから引き継がれたタスクは返金対象外です。管理者にお問い合わせください）」（英語: Task timed out (a task left by the old system is not refunded; contact the administrator)） | 2026 年 2 月 22 日より前に送信されたタスクがタイムアウトしました。 | 管理者にお問い合わせください。 |
| 上流サービスから返されたその他の理由（プロンプトにセンシティブな内容が含まれる、歌詞に著作権で保護された内容が含まれるなど） | 上流サービスがリクエストを拒否したか、生成に失敗しました。 | 表示された理由に応じてプロンプトなどを修正し、再送信します。 |
</Accordion>

<Accordion title="失敗したタスクにも料金がかかりますか">
タスクの送信時にクォータが先に差し引かれます。タスクが失敗またはタイムアウトすると、差し引かれた分が元の引き落とし元（ウォレット残高またはサブスクリプションのクォータ）に全額戻ります。使用した API キーのクォータも返還され、使用ログに「返金」の記録が残ります。

**対処方法**

1. [失敗したタスクの返金を確認する](#失敗したタスクの返金を確認する)の手順に沿って、使用ログで「返金」の記録を確認します。
2. 返金記録が見つからない場合は、タスク ID を管理者に送ってください。
</Accordion>

<Accordion title="「アーティファクト」をプレビューまたはダウンロードできない">
**表示メッセージ**

「メディアのプレビューに失敗しました。もう一度お試しください。」（英語: Media preview failed. Please try again.）、「プレビューできません」（英語: Preview unavailable）、または「アーティファクトの読み込みに失敗しました」（英語: Failed to load artifacts）

**考えられる原因**

- 上流サービスに保存されたファイルの有効期限が切れたか、ファイルが削除されました。
- ネットワーク接続が切断されたか、上流サービスが一時的に利用できなくなっています。

**対処方法**

1. 「再試行」をクリックします。
2. ファイルを開けたら、すぐに「ダウンロード」をクリックして保存してください。
3. それでも失敗する場合は、タスク ID を管理者に送ってください。
</Accordion>

<Accordion title="「アーティファクト」列に「結果は保存されていません」と表示される">
**表示メッセージ**

「結果は API レスポンスで返され、アーティファクトとしては保存されていません」（英語: The result was returned in the API response and was not saved as an artifact）

「結果は保存されていません」にマウスポインターを合わせると、このメッセージが表示されます。

**考えられる原因**

タスクの結果は、送信時の API レスポンスで直接返されており、システムには保存されていません。

**対処方法**

1. API を呼び出すプログラムで、レスポンスに含まれる結果を保存してください。
</Accordion>

<Accordion title="特定のタスクが見つからない">
**考えられる原因**

- 期間がデフォルトの「今日」のままになっています。タスクは送信日時で絞り込まれます。
- タスク ID の入力が途中までです。検索ではタスク ID の完全一致が必要です。
- 表示しているタブが異なります。動画や音楽などのタスクは「タスクログ」タブ、Midjourney の画像生成タスクは「描画ログ」タブに表示されます。
- 管理者が「自分のみ」を選択した状態で、他のユーザーのタスクを探しています。

**対処方法**

1. タスクの送信日時が含まれるように期間を設定し、「検索」をクリックします。
2. 完全なタスク ID を貼り付けて、もう一度検索します。
3. もう一方のタブに切り替えて探します。
</Accordion>

<Accordion title="「描画ログ」または「タスクログ」タブが表示されない">
**考えられる原因**

- 左サイドバーの設定で「描画ログ」または「タスクログ」が無効になっています。両方が有効な場合にタブが表示されます。
- 管理者がいずれかの機能を無効にしています。

**対処方法**

1. 「プロフィール」ページの「左サイドバーの個人設定」で「コンソール領域」「描画ログ」「タスクログ」を有効にし、保存します。
2. 有効にしても表示されない場合は、管理者にお問い合わせください。
</Accordion>

<Accordion title="タスク ID の下の操作が「不明」と表示される">
ページで識別できるタスクの種類は「音楽生成」「歌詞生成」など一部に限られます。その他の種類は「不明」と表示されますが、タスクの実行や課金には影響しません。
</Accordion>

<Accordion title="成功したタスクの使用ログに「返金」または追加の「消費」記録がある">
一部のタスクは、正常に完了した後で実際の使用量に基づいて精算されます。実際の使用量が送信時に差し引かれたクォータを下回ると、差額が返還され、「返金」として記録されます。上回った場合は差額が追加で差し引かれ、「消費」の記録が 1 件追加されます。この場合の「返金」は、正常に完了したタスクの精算によるものです。

**対処方法**

1. 使用ログで該当する「返金」記録の詳細を開き、「返金詳細」でタスク ID と理由を確認します。
2. タスク送信時の「消費」記録にはタスク ID が表示されないため、送信日時とモデルで照合してください。
</Accordion>

<Accordion title="タスクの記録はどのくらい保存されますか">
タスクと画像生成の記録は自動削除されません。生成された画像、動画、音声は上流サービスに保存されます。上流サービスでファイルが削除されたり、有効期限が切れたりすると、プレビューやダウンロードができなくなるため、早めにダウンロードして保存してください。
</Accordion>

</Accordions>
