- 左側のサイドバーに「概要」ページがない場合は、<br/>「プロフィール」ページの「左サイドバーの個人設定」で「コンソール領域」と「ダッシュボード」を有効にし、保存します。「ダッシュボード」のスイッチは「概要」と「ダッシュボード」の両方のメニュー項目を制御します。

</Callout>

## セットアップガイドに沿って利用を開始する

**操作手順**

1. 「1. API キーを作成」をクリックし、「API キー」ページでキーを作成します。
2. 「2. クォータを追加」をクリックし、「ウォレット」ページでチャージするか、クォータを引き換えます。
3. 「3. リクエストを送信」をクリックし、「プレイグラウンド」でメッセージを 1 件送信します。「最初の API リクエスト」のコマンドをコピーして、ターミナルで実行することもできます。
4. 「概要」ページに戻り、ブラウザーでページを再読み込みして、各ステップに緑色のチェックマークが表示されることを確認します。
5. セットアップガイドが不要になったら、右上の「セットアップガイドを非表示」をクリックします。

<Callout type="info" title="ヒント">

- ステップの完了状況は、ログイン時に取得したアカウント情報をもとに判定されます。操作が完了したら、ブラウザーでページを再読み込みしてください。
- 展開または折りたたみの選択は現在のブラウザーに保存されます。以降は完了状況に応じて表示が自動で切り替わることはありません。
- ガイドが折りたたまれているとき、未完了のステップがあれば「セットアップの進捗：…/3」と 1 行で表示されます。「セットアップガイドを表示」をクリックすると再展開できます。すべて完了している場合は、ページタイトル右側の「セットアップガイド」をクリックして再展開します。

</Callout>

**ステップの説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| ステップ | 説明 | 完了条件 | クリックで開くページ |
| --- | --- | --- | --- |
| 1. API キーを作成 | 「アプリケーションやサービス用のキーを作成する」 | アカウントに API キーが 1 つ以上あります。無効化されたキーや有効期限切れのキーも含まれます。 | 「API キー」ページ |
| 2. クォータを追加 | 「本番トラフィックを処理する前に十分な残高を確保する」 | ウォレット残高が 0 を超えているか、アカウントが過去にクォータを消費したことがあります。登録時にクォータが付与されたアカウントでは、最初からこのステップは完了済みです。 | 「ウォレット」ページ |
| 3. リクエストを送信 | 「Playground またはお使いのクライアントでルートを検証する」 | アカウントで 1 回以上の呼び出しが成功しています。失敗した呼び出しは集計されません。 | 「プレイグラウンド」ページ。管理者がプレイグラウンドを無効にしている場合は「概要」ページに戻ります。 |

</div>

## サンプルコマンドをコピーして最初のリクエストを送信する

**操作手順**

1. アカウントにまだ API キーがない場合は、「最初の API リクエスト」の右上にある「API キーを作成」をクリックします。キーを作成したら「概要」ページに戻ります。
2. 「最初の API リクエスト」の右上にある「コピー」をクリックします。
3. ターミナルにコマンドを貼り付けて実行します。

<Callout type="warn" title="API キーの取り扱いに注意">
コピーしたコマンドには完全な API キーが含まれます。グループチャットに送信したり、スクリーンショットや公開コードリポジトリに含めたりしないでください。
</Callout>

<Callout type="info" title="ヒント">

- コマンドは macOS と Linux のターミナル、および Windows の Git Bash で実行できます。
- 「コピー」は完全なキーを取得するため、「API キー」ページで完全なキーを表示する場合と同じ頻度制限が適用されます。監査ログには「API トークン『…』のキーを表示」と記録されます。
- 別のキーやモデルを使用する場合は、「API キー」ページでキーと API アドレスをコピーしてください。呼び出し方法は<a href="/ja/docs/guide/feature-guide/user/token#复制密钥并调用模型" target="_blank" rel="noopener noreferrer">API キー</a>を参照してください。

</Callout>

**コマンドの説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 構成要素 | 値 | 備考 |
| --- | --- | --- |
| リクエスト先 | 「API 情報」の先頭のアドレスに `/v1/chat/completions` を付加した URL です。管理者が API 情報を設定していない場合や無効にしている場合は、ブラウザーで現在開いているサイトのアドレスに `/v1/chat/completions` を付加します。 | 「ルーティング有効」欄の「オンライン」は API 情報のアドレスを使用していることを示し、「現在のドメイン」は現在のサイトのアドレスを使用していることを示します。「オンライン」と表示されていても、アドレスへのアクセス可否は確認されていません。 |
| API キー | 「API キー」一覧にある有効なキーのうち、最も上にあるキーです。有効なキーがない場合は、一覧の先頭のキーを使用します。 | カードのサブタイトルにキー名が表示されます。表示上のコマンドにはキーの先頭と末尾の数文字だけが表示され、「コピー」をクリックすると完全なキーがコピーされます。「認証設定済み」欄の「保護済み」はキーがあることを示し、「API キーが必要」はキーが未作成であることを示します。このカードでは別のキーを選択できません。 |
| モデル | アカウントで利用可能なモデルのうち、先頭のモデルです。 | 「モデル選択済み」欄に表示されます。利用可能なモデルを取得できない場合、欄には「読み込み中」と表示され、コマンドでは gpt-4o-mini が使われます。 |
| リクエスト内容 | ChatCompletions 形式の英語の会話メッセージ 1 件です。 | その他のパラメーターは<a href="/ja/docs/api/ai-model/chat/openai/createchatcompletion" target="_blank" rel="noopener noreferrer">ChatCompletions 形式</a>を参照してください。 |

## クォータと使用量を確認する

**操作手順**

1. 「使用量の概要」で、現在のアカウントの直近 1 日の消費量、累計消費量、累計呼び出し回数を確認します。
2. 右側の「残りクォータ」で、ウォレット残高、残高ステータス、「利用可能期間」を確認します。
3. 残高が不足している場合は、「ウォレット」をクリックしてチャージするか、クォータを引き換えます。

<Callout type="info" title="ヒント">

- 「残りクォータ」「利用履歴」「リクエスト数」は、ログイン時に取得したアカウント情報をもとに表示されます。別のページでチャージや呼び出しを行ってもすぐには更新されません。ブラウザーでページを再読み込みすると最新の値が表示されます。
- 「残りクォータ」にはウォレット残高のみが表示されます。サブスクリプションの残りクォータは「ウォレット」ページの「マイサブスクリプション」で確認できます。詳しくは<a href="/ja/docs/guide/feature-guide/user/wallet#サブスクリプションプラン" target="_blank" rel="noopener noreferrer">ウォレット</a>を参照してください。
- 「直近 24 時間の消費量」はダッシュボードと同じ集計データを使用します。新しい呼び出しは通常、数分後に反映されます。デフォルトでは 5 分ごとに集計されます。詳しくは<a href="/ja/docs/guide/feature-guide/user/dashboard" target="_blank" rel="noopener noreferrer">ダッシュボード</a>を参照してください。

</Callout>

**集計項目の説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 集計項目 | 定義 | 集計範囲 | 備考 |
| --- | --- | --- | --- |
| 直近 24 時間の消費量 | 現在のアカウントが直近 1 日に消費したクォータです。 | 毎正時を区切りとして 1 時間単位で集計します。現在の時間帯とそれ以前の 22 時間分が含まれるため、集計範囲は 24 時間よりやや短くなります。ウォレット残高とサブスクリプションのクォータから差し引かれた消費量が含まれます。管理者がダッシュボードの集計を無効にすると、新しい消費量は加算されません。 | 下部に「直近 24 時間の消費量」と表示されます。通貨表示の場合は「(USD)」などの単位が付きます。カード下部の折れ線は、この期間の消費量の推移を示します。「残りクォータ」の「直近 24 時間の消費量」も同じ値です。 |
| 利用履歴 | 現在のアカウントが消費したクォータの累計です。 | アカウント作成時からの集計で、ウォレット残高とサブスクリプションのクォータから差し引かれた消費量が含まれます。 | 下部に「総消費量 (…)」と表示されます。クォータをトークン単位で表示する場合は「クォータの総消費量」と表示されます。カード下部の折れ線は直近 1 日の消費量の推移を示します。 |
| リクエスト数 | 現在のアカウントで成功した呼び出しの累計回数です。 | アカウント作成時からの集計で、失敗した呼び出しは含まれません。 | 下部に「総リクエスト数」と表示されます。カード下部の折れ線は直近 1 日の呼び出し回数の推移を示します。 |
| 残りクォータ | 現在のアカウントのウォレット残高です。 | サブスクリプションのクォータは含まれません。 | 右上に残高ステータスが表示されます。[残高ステータス](#残高ステータス)を参照してください。 |
| 利用可能期間 | 直近 1 日の消費ペースから推定した、残高で利用できる日数です。「残りクォータ」を「直近 24 時間の消費量」で割って算出します。 | 「残りクォータ」と「直近 24 時間の消費量」の集計範囲に従います。 | 「~… 日」（小数点以下切り捨て）、「999+ 日」、または「残り 1 日未満」と表示されます。ウォレット残高が 0 以下の場合は「残高がありません」、直近 1 日に消費がない場合は「利用履歴がありません」と表示されます。 |

## お知らせ、API 情報、よくある質問、稼働時間を確認する

**お知らせを確認する手順**

1. 「お知らせ」に表示されている項目をクリックします。
2. 「お知らせの詳細」ウィンドウで「内容」を確認します。補足情報がある場合は、下部に「補足情報」が表示されます。

**API アドレスのレイテンシを測定する手順**

1. 「API 情報」でアドレスの右側にある稲妻アイコンをクリックします。マウスポインターを重ねると「レイテンシを測定」と表示されます。
2. アイコンの左側に表示される所要時間を確認します。たとえば「120 ミリ秒」と表示されます。色の意味は [API アドレスのレイテンシ](#api-アドレスのレイテンシ)を参照してください。

**稼働時間を確認する手順**

1. 「稼働時間」で、グループごとに各監視項目の丸印の色と直近 24 時間の稼働率を確認します。
2. 最新のステータスを取得するには、パネル右上の更新アイコンをクリックします。

<Callout type="info" title="ヒント">

- 4 つのパネルの内容は、管理者がコンソールのコンテンツ設定で指定します。変更が反映されるまで数分かかる場合や、ブラウザーでページの再読み込みが必要な場合があります。詳しくは<a href="/ja/docs/guide/feature-guide/system-settings/settings-content" target="_blank" rel="noopener noreferrer">コンソールのコンテンツ設定</a>を参照してください。
- 「レイテンシを測定」では、ブラウザーからそのアドレスまでの往復時間を測定します。モデルの応答速度は測定対象外です。「外部速度テスト」をクリックすると、サードパーティの速度測定サイトが新しいタブで開きます。

</Callout>

### 残高ステータス

「残りクォータ」の右上には、以下の 3 つのステータスのいずれかが表示されます。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| ステータス | 意味 | 備考 |
| --- | --- | --- |
| 正常 | ウォレット残高が 0 を超えており、直近 1 日の消費量から 3 日以上利用できると推定されるか、直近 1 日に消費がありません。 | 緑色の丸印が表示されます。 |
| 残高が少ない | ウォレット残高は 0 を超えていますが、直近 1 日の消費量から推定される利用可能期間は 3 日未満です。 | 黄色の丸印が表示され、「利用可能期間」も黄色で表示されます。判定のしきい値は 3 日で固定されており、「プロフィール」の「残高不足通知」の設定には左右されません。ウォレットでチャージしてください。 |

## よくある質問

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="「セットアップガイド」が表示されたままになる、または折りたたむと見つからない">

**考えられる原因**

- 3 つのステップがすべて完了していない場合、セットアップガイドは自動的に展開されます。
- セットアップガイドを手動で展開したことがある場合、ブラウザーにその選択が保存されるため、すべてのステップが完了しても自動的には折りたたまれません。
- すべてのステップが完了すると、セットアップガイドは自動的に折りたたまれ、ページタイトルの右側に「セットアップガイド」ボタンだけが表示されます。

**対処方法**

1. ガイドが不要な場合は、セットアップガイドの右上にある「セットアップガイドを非表示」をクリックします。
2. もう一度確認するには、ページタイトルの右側にある「セットアップガイド」か、折りたたみ時に表示される行の「セットアップガイドを表示」をクリックします。

</Accordion>

<Accordion title="チャージや API 呼び出しの後に数値が変わらない、またはステップにチェックマークが表示されない">

**考えられる原因**

- 「残りの利用枠」「利用履歴」「リクエスト数」と各ステップの完了状態は、ログイン時に取得したアカウント情報に基づいて表示されます。別のページで操作しても、すぐには更新されません。
- 「3. リクエストを送信」では、成功した呼び出しだけがカウントされます。呼び出しが失敗した場合、チェックマークは表示されません。
- 新しい呼び出しが「直近 24 時間の消費量」に反映されるまでには、数分かかります。

**対処方法**

1. ブラウザーでページを再読み込みします。
2. <a href="/ja/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">利用ログ</a>で、該当する呼び出しの「消費」記録、または該当するチャージの「チャージ」記録があるか確認します。
3. それでも一致しない場合は、管理者にお問い合わせください。

</Accordion>

<Accordion title="「直近 24 時間の消費量」が 0、または利用ログと一致しない">

**考えられる原因**

- 新しい呼び出しが反映されるまで、通常は数分かかります。デフォルトでは 5 分ごとに集計されます。
- 毎正時で区切って 1 時間単位で集計するため、集計対象の期間は 24 時間よりわずかに短くなります。そのため、利用ログの各記録を個別に集計した結果とは異なります。
- 管理者がデータダッシュボードの集計を有効にしていない場合や無効にした場合、「直近 24 時間の消費量」は増加せず、「利用可能時間」には「利用記録はまだありません」と表示されます。「利用履歴」と「リクエスト数」には影響しません。

**対処方法**

1. 数分待ってから、ブラウザーでページを再読み込みします。
2. <a href="/ja/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">利用ログ</a>で同じ期間を選択し、「消費」記録を基準に照合します。
3. 長時間 0 のままの場合は、管理者に連絡し、サイトでデータダッシュボードの集計が有効になっているか確認してください。

</Accordion>

<Accordion title="「残高がなくなりました」と表示されるが、API は正常に呼び出せる">

**補足**

「残りの利用枠」と残高の状態は、ウォレット残高のみを基に表示されます。「利用履歴」と「直近 24 時間の消費量」には、サブスクリプションの利用枠で支払った分も含まれます。ウォレット残高が 0 以下になると「残高がなくなりました」と表示されます。有効なサブスクリプションがある場合は、請求の優先設定に従って、API 呼び出しの消費分がサブスクリプションの利用枠から差し引かれます。

**対処方法**

1. <a href="/ja/docs/guide/feature-guide/user/wallet#サブスクリプションプラン" target="_blank" rel="noopener noreferrer">ウォレット</a>ページの「マイサブスクリプション」で、サブスクリプションの残りの利用枠を確認します。
2. ウォレット残高を使って API を呼び出すには、チャージするか、利用枠の引き換えを行ってください。

</Accordion>

<Accordion title="サンプルコマンドを実行するとエラーが発生する">

**補足**

このコマンドは、「API キー」一覧で有効なキーのうち先頭にあるものと、アカウントで利用可能なモデルのうち先頭にあるものを使用します。呼び出しが失敗する原因は、他のクライアントを使用する場合と同じです。「選択中のモデル」に「読み込み中」と表示されている場合、利用可能なモデルの情報は取得できておらず、コマンド内の gpt-4o-mini が利用できるとは限りません。実際に表示されたメッセージを基に原因を確認してください。

| 表示メッセージ | 考えられる原因 | 対処方法 |
| --- | --- | --- |
| 「無効なトークン」（英語表記は Invalid token） | キーが無効になっているか、有効期限が切れているか、利用枠を使い切っています。 | 「API キー」ページで該当するキーを確認してください。詳しくは <a href="/ja/docs/guide/feature-guide/user/token#api-密钥状态" target="_blank" rel="noopener noreferrer">API キーのステータス</a>を参照してください。 |
| 「このトークンにはモデル … へのアクセス権がありません」（英語表記は This token has no access to model …） | キーに「モデル制限」が設定されており、コマンドで指定したモデルは許可されていません。 | コマンド内のモデルをそのキーで利用できるモデルに変更するか、キーの「モデル制限」を編集してください。 |
| 「ユーザーの利用枠が不足しています」（英語表記は Insufficient user quota） | アカウントの残高が不足しています。 | <a href="/ja/docs/guide/feature-guide/user/wallet" target="_blank" rel="noopener noreferrer">ウォレット</a>でチャージするか、利用枠の引き換えを行ってください。 |
| 接続に失敗するかタイムアウトし、メッセージは表示されない | 現在の端末からコマンド内のリクエスト先にアクセスできません。 | 「API キー」ページの右上にある「API アドレス」から利用可能なアドレスをコピーし、コマンド内のアドレスを置き換えてください。 |

</Accordion>

<Accordion title="「コピー」をクリックすると失敗したと表示される">

**表示メッセージ**

「クリップボードへのコピーに失敗しました」（英語表記は Failed to copy to clipboard）、またはサーバーが返したエラーの理由が表示されます。

**考えられる原因**

- ブラウザーが、ページからクリップボードへの書き込みをブロックしています。
- 短時間にキー全体を表示またはコピーした回数が多すぎます。
- ネットワーク接続が切断されたか、ログインセッションの有効期限が切れています。

**対処方法**

1. ブラウザーでクリップボードへのアクセスを許可してから、再試行します。
2. しばらく待ってから再試行します。十数分かかることもあります。
3. それでも失敗する場合は、「API キー」ページでキーをコピーし、<a href="/ja/docs/guide/feature-guide/user/token#复制密钥并调用模型" target="_blank" rel="noopener noreferrer">API キー</a>に記載されている呼び出し方法に従って、コマンドにキーを設定します。

</Accordion>

<Accordion title="お知らせ、API 情報、よくある質問、または稼働時間が表示されない">

**考えられる原因**

- 管理者が該当するパネルを無効にしています。
- 管理者がコンテンツを設定していないため、パネルには「現在お知らせはありません」「API ルートが設定されていません」「FAQ 項目はまだありません」「稼働時間の監視が設定されていません」のいずれかが表示されます。
- 管理者がコンテンツを変更したばかりで、ページに反映されるまで数分かかります。
- サイトが監視ステータスを取得できない場合も、「稼働時間」に「稼働時間の監視が設定されていません」と表示されるか、グループ内に監視項目が表示されません。

**対処方法**

1. ブラウザーでページを再読み込みします。
2. それでも表示されない場合は、管理者にお問い合わせください。

</Accordion>

<Accordion title="「3. リクエストを送信」をクリックすると「概要」ページに戻る">

**考えられる原因**

管理者が「プレイグラウンド」を無効にしています。

**対処方法**

1. 「最初の API リクエスト」のコマンドをコピーしてターミナルで実行するか、別のクライアントから API を呼び出します。
2. プレイグラウンドを利用する必要がある場合は、管理者にお問い合わせください。

</Accordion>

<Accordion title="監査ログに「API トークン「…」のキーを表示」という記録がある">

**補足**

「最初の API リクエスト」で「コピー」をクリックすると、API キー全体が読み取られ、監査ログに「API トークン「…」のキーを表示」と記録されます。これは正常な記録です。

**対処方法**

1. 記録された日時、IP アドレス、クライアントを確認し、ご自身の操作かどうかを確かめます。
2. ご自身の操作でない場合は、<a href="/ja/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">監査ログ</a>のよくある質問に記載されている手順に従って対処してください。

</Accordion>

</Accordions>
