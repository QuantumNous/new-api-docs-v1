- New API は、リクエストの詳細、描画記録、および動画や音楽などの非同期タスクを個別に保存します。
- ログイン後、左側のナビゲーションから「使用ログ」または「タスクログ」にアクセスできます。
- このページでは、3つのデータパーティション、タスクステータス、およびインターフェース照会方法について統一的に説明します。

3つのパーティションは以下のパスに対応します：

- `/usage-logs/common`：一般的なAPI使用ログと課金詳細；
- `/usage-logs/drawing`：Midjourney描画タスク；
- `/usage-logs/task`：Suno、動画などの一般的な非同期タスク。

<Callout type="info">
  一般ユーザーは自分の記録のみ表示できます。AdminとRootはページ右上の「すべて」と「自分のみ」を切り替えることができます。「自分のみ」に切り替えると、ページは一般ユーザーのフィールドと権限に基づいてデータを返します。
</Callout>

## 使用ログ

- 左側のサイドバーで「使用ログ」をクリックするか、`/usage-logs/common` にアクセスしてAPIリクエストと課金詳細を表示します。

### 記録のフィルタリング

使用ログ記録の照会で利用可能なフィルター項目は以下の通りです：

| フィルター項目 | 説明 |
| --- | --- |
| 期間 | 記録作成時間でフィルタリングします。開始時間と終了時間は照会範囲に含まれます。 |
| モデル名 | モデル名でフィルタリングします。 |
| グループ | リクエストで使用されたグループでフィルタリングします。 |
| ログタイプ | すべてのタイプ、チャージ、消費、管理、システム、エラー、返金、ログイン。 |
| トークン名 | APIキー名でフィルタリングします。 |
| リクエストID | New API リクエストIDで単一のリクエストを特定します。 |
| アップストリームリクエストID | アップストリームサービスが返す、または記録するリクエストIDでリクエストを特定します。 |
| ユーザー名（Admin/Rootのみ） | 管理者ビューでユーザー名でフィルタリングします。 |
| チャネルID（Admin/Rootのみ） | 管理者ビューでチャネルIDでフィルタリングします。 |

### ページ統計

フィルターバーの統計値は、現在の権限とフィルター条件に関連しています：

- **Usage**：消費記録のクォータを合計します。時間、モデル、グループ、キー、チャネル、ユーザーの条件に基づいてフィルタリングできます。
- **RPM**：過去60秒間の消費リクエスト数。
- **TPM**：過去60秒間の入力トークンと出力トークンの合計数。

### リストと詳細

- 一般ユーザーは、時間とタイプ、トークン、モデル、ストリーム、トークン、費用、所要時間、詳細列を表示できます。
- Admin/Rootビューでは、チャネルとユーザー列も表示できます。

![使用ログページ](/assets/guide/feature-guide/usage-logs.png)

<Callout type="info">
  1. **トークン**：入力トークン/出力トークンを表示します。キャッシュを使用している場合は、キャッシュの読み取りと書き込みの数も表示されることがあります。
  2. **費用**：この記録のクォータ消費または返金結果を表示します。具体的な形式は、インスタンスのクォータ表示方法によって異なります。
  3. **所要時間**：計時データのある消費またはエラー記録に対して応答所要時間を表示します。ストリーミングリクエストでは、初回応答時間（FRT）とスループット情報が追加で表示されることがあります。
  4. **詳細**：記録をクリックすると詳細ダイアログが開きます。ログタイプと記録に実際に保存されているフィールドに応じて、リクエストID、モデルマッピング、エラーまたは返金理由、トークン詳細、課金詳細、キャッシュ/オーディオ/画像使用量、ストリームステータスなどが含まれる場合があります。すべての記録がすべてのブロックを表示するわけではありません。
  5. 管理者は詳細で、チャネルリトライチェーン、リクエスト変換、課金パス、チャージ監査、または管理操作監査などの情報も確認できる場合があります。
</Callout>

<Callout type="warn">
  - **なぜ特定の記録が見えないのですか？** <br/>
  消費ログの書き込みは、プラットフォームの「システム設定」→「運用」→「ログメンテナンス」→「クォータ使用量の記録」スイッチによって制御されます。Rootがこの設定をオフにすると、新しい消費記録は生成されない可能性があります。エラーログは、エラーログスイッチと記録可能なエラータイプによっても制限され、すべての失敗応答がError記録を生成するわけではありません。ユーザープロファイルの「IPアドレスを記録」設定は、消費ログとエラーリクエストログのIPアドレス保存のみを制御します。ログイン、管理監査、チャージなどの他のログは、それぞれの監査プロセスに従ってIPを記録する場合があります。
</Callout>

## タスクログ

- 「タスクログ」には「描画ログ」と「タスクログ」が含まれます。
1. 「描画ログ」：Midjourney描画タスクログを記録します。
2. 「タスクログ」：テキストから動画、画像から動画、音声生成などの非同期タスクログを記録します。

## 描画ログ

- 左側のサイドバーで「タスクログ」→「描画ログ」をクリックするか、`/usage-logs/drawing` にアクセスしてMidjourney描画タスク記録を表示します。
- 一般ユーザーは自分のタスクのみ表示できます。Admin/Rootは「すべて」ビューで管理範囲内のタスクを表示でき、追加でチャネルと提出結果を確認できます。

描画ログは以下の条件でフィルタリングをサポートします：
1. 期間；
2. MidjourneyタスクID；
3. チャネルID（Admin/Rootのみ）。

![描画ログページ](/assets/guide/feature-guide/drawing-logs.png)

<Callout type="info">
  1. リストには、提出時間とステータス、チャネルID（Admin/Rootのみ）、操作タイプ、タスクID、所要時間、提出結果、進捗、画像、プロンプト、失敗理由が含まれます。画像をクリックするとプレビューが開きます。プロンプトをクリックすると完全な内容が表示されます。失敗理由をクリックすると完全なエラー情報が表示されます。
  2. 描画ステータスには、未開始、キュー中、実行中、成功、失敗、ウィンドウ待機が含まれます。
  3. 描画ステータスはバックエンドがアップストリームタスクをポーリングして更新します。ポーリングには間隔があるため、タスクステータスに遅延が生じる可能性があります。バックエンドが対応するアップストリームタスクデータを取得すると、提出から約1時間以上経過しても完了していないMidjourneyタスクは失敗としてマークされます。
</Callout>

## タスクログ（非同期タスクログ）

- 左側のサイドバーで「タスクログ」→「タスクログ」をクリックするか、`/usage-logs/task` にアクセスして非同期タスクログを表示します。一般ユーザーは自分のタスクのみ表示できます。Admin/RootビューではチャネルIDとユーザーも表示されます。
- 動画、音楽などの非同期APIは、リクエスト提出時に最終結果をすぐに返しません。提出が成功すると、New API は公開タスクIDを返し、タスク記録を保存します。その後、バックエンドがアップストリームサービスをポーリングしてステータス、進捗、結果を更新します。

### タスクのフィルタリング

タスクログは以下の条件でフィルタリングをサポートします：
1. 期間；
2. タスクID；
3. チャネルID (Admin/Rootのみ)。

### リストと結果

タスクリストには、提出時間と完了時間、チャネル、ユーザー、タスクID、プラットフォームと操作、所要時間、ステータス、進捗、詳細が表示されます：

- Sunoタスクが成功し、音声アドレスが返された場合、詳細列に音声プレビューが提供されます。
- 一部の動画タスクは成功後にプレビューエントリを表示します。また、同じアカウントのログインセッションまたはAPIキーを使用して `/v1/videos/{task_id}/content` をリクエストすることで、完了したタスクの動画コンテンツを取得できます。このAPIはタスクの帰属を検証し、タスクが未完了または現在のユーザーに属していない場合はコンテンツを返しません。
- その他の失敗記録は、詳細列に失敗理由が表示され、クリックすると完全な情報が表示されます。

## タスクステータスとバックエンド処理

非同期タスクログは以下のステータス値を使用します。プラットフォームアダプターによっては、アップストリームステータスの大文字小文字やプラットフォームの違いを保持することがあるため、APIの戻り値は実際のタスク記録を基準とすべきです：

| ステータス | 意味 |
| --- | --- |
| `未開始` | タスク記録は作成されましたが、まだ処理が開始されていません。 |
| `キュー中` | アップストリームに提出され、後続の処理を待機しています。 |
| `キューイング中` | 処理キューに入りました。 |
| `実行中` | 処理中です。 |
| `成功` | 完了しました。結果を表示または取得できます。 |
| `失敗` | 処理が失敗しました。失敗理由はタスク記録に書き込まれます（アップストリームが提供する場合）。 |
| `不明` | 内部で定義された不明なステータスのフォールバック値。 |

![タスクログページ](/assets/guide/feature-guide/task-logs.png)

<Callout type="info">
  タスクステータスはバックエンドによってポーリング更新されます。提出されたばかりのタスクステータスには遅延が生じる可能性があります。デフォルトの非同期タスクポーリングは約15秒ごとにチェックされます。ポーリングは `UPDATE_TASK` が有効で、未完了のタスクが存在する場合にのみ実行されます。非同期タスクのタイムアウトしきい値は `TASK_TIMEOUT_MINUTES` によって制御され、デフォルトは1440分です。`0` に設定するとタイムアウト処理が無効になります。
</Callout>

### 失敗、タイムアウト、返金

タスクが最終的な失敗ステータスになった後、タスクに提出段階で事前差し引かれたクォータがある場合、システムは通常、返金を試み、返金が成功した場合は「返金」ログを書き込みます。返金が成功すると、タスク記録の返金待ちクォータがクリアされ、ユーザーとチャネルの累積使用量が減算されます。リクエスト回数はこれにより元に戻されません。

<Callout type="warn">
  以下の状況では、ページステータスと残高が一時的に一致しない可能性があります：
  1. タスクに事前差し引かれたクォータがない（`quota = 0`）；
  2. 資金源からの返金が失敗した場合、システムは再試行または手動照合のためにタスククォータを保持します；
  - 返金を調査する際は、ウォレット残高またはサブスクリプションの残りクォータ（および使用中のAPIキーのクォータ）と、一般的な使用ログの「返金」記録の両方を確認してください。「失敗」ステータスのみに基づいて返金が完了したかどうかを判断しないでください。
</Callout>

## APIリファレンス

### ログ照会API

APIを使用する場合（コンソールではなく）、以下の読み取り専用APIを呼び出すことができます。APIは認証と権限の制限を受け、一般ユーザーの結果は現在のユーザーアカウントに強制的に限定されます：

| データ | 管理者API | ユーザーAPI | 時間パラメータ単位 |
| --- | --- | --- | --- |
| 一般ログ | `GET /api/log/` | `GET /api/log/self` | 秒（`created_at`） |
| ログ統計 | `GET /api/log/stat` | `GET /api/log/self/stat` | 秒 |
| Midjourney描画 | `GET /api/mj/` | `GET /api/mj/self` | ミリ秒（`submit_time`） |
| 非同期タスク | `GET /api/task/` | `GET /api/task/self` | 秒（`submit_time`） |

ログとタスクリストAPIはページングパラメータ `p` と `page_size` を使用します。ページ番号は `1` から始まり、通常の正の整数を使用する場合、`100` を超える `page_size` は `100` に切り捨てられます。ユーザーログの合計数統計は、インスタンスの内部照会上限の影響も受けます。タスクの戻りデータには、キー、アップストリームタスク識別子、または課金コンテキストを含む可能性のあるプライベートフィールドは含まれません。

また、`GET /api/log/token` はAPIキーを使用して、そのキーの最新のログを読み取ることができます。このAPIは読み取り専用トークン認証を採用しています。キーの存在、キーが明示的に無効になっていないこと、および所属ユーザーが利用可能であることを検証しますが、キーの期限切れやクォータの枯渇によって照会を拒否することはありません。最大で最新の `1000` 件の記録を返します。

タスクリストAPIの一般的な照会パラメータは以下の通りです：

| 範囲 | メソッドとパス | 一般的な照会パラメータ |
| --- | --- | --- |
| 現在のユーザー | `GET /api/task/self` | `p`、`page_size`、`task_id`、`start_timestamp`、`end_timestamp`；`platform`、`action`、`status` も受け入れます。 |
| Admin/Root | `GET /api/task/` | ユーザーAPIパラメータに `channel_id` を追加し、`platform`、`action`、`status` でフィルタリングできます。 |

<Callout type="info">
  タスクAPIの `start_timestamp`、`end_timestamp` はUnix秒タイムスタンプを使用します。Midjourney描画APIの時間パラメータはミリ秒を使用します。
</Callout>

### 非同期生成とタスクAPI

以下の非同期生成およびアップストリームタスク照会APIは、インスタンスが設定されたチャネルとアダプターによって提供され、提出および照会APIは通常APIキー認証を使用します。動画コンテンツプロキシはAPIキーまたはログインセッションの両方をサポートし、タスク帰属検証を遵守します。Midjourney画像プロキシはAPIキー不要の例外です。以下の `/api/task` リストAPIはログイン後のユーザーまたは管理者権限を使用します。具体的な認証方法はAPIの要件に従います。

| API | パス | 説明 |
| --- | --- | --- |
| OpenAI動画生成 | `POST /v1/videos` | OpenAI互換の動画生成非同期タスクを作成し、成功するとタスク識別子を返します。 |
| OpenAI動画タスク照会 | `GET /v1/videos/{task_id}` | 動画生成タスクのステータス、進捗、結果情報を照会します。 |
| 動画コンテンツ取得 | `GET /v1/videos/{task_id}/content` | 完了した動画コンテンツをストリーミングで返します。システムはタスク結果に基づいてアップストリームからコンテンツを取得するか、保存されたデータURLをデコードします。 |
| 動画リミックス | `POST /v1/videos/{video_id}/remix` | 既存の動画に基づいて新しいリミックス非同期タスクを提出します。 |
| 旧版動画生成 | `POST /v1/video/generations` | 旧版動画生成パスと互換性があり、非同期動画タスクを作成します。 |
| 旧版動画タスク照会 | `GET /v1/video/generations/{task_id}` | 旧版動画生成タスクのステータスと結果を照会します。 |
| Klingテキストから動画生成 | `POST /kling/v1/videos/text2video` | Kling形式を使用してテキストから動画生成タスクを提出します。システムはまずリクエスト形式変換を実行します。 |
| Kling画像から動画生成 | `POST /kling/v1/videos/image2video` | Kling形式を使用して画像から動画生成タスクを提出します。 |
| Klingタスク照会 | `GET /kling/v1/videos/text2video/{task_id}`<br />`GET /kling/v1/videos/image2video/{task_id}` | Klingテキストから動画生成または画像から動画生成タスクの結果を照会します。 |
| Jimeng公式API | `POST /jimeng/` | Jimeng公式API形式と互換性があり、`Action`、`Version`などのパラメータでタスク提出と照会操作を区別します。 |
| Sunoタスク提出 | `POST /suno/submit/{action}` | Suno音楽生成タスクを提出します。具体的なタスクタイプは `action` パラメータによって決定されます。 |
| Sunoタスク照会 | `POST /suno/fetch`<br />`GET /suno/fetch/{id}` | Sunoタスクリストまたは指定されたタスクのステータスと結果を照会します。 |
| Midjourneyタスク提出 | `POST /mj/submit/{action}`<br />`POST /{mode}/mj/submit/{action}` | `imagine`、`describe`、`blend`、`change`、`simple-change`、`edits`、`video`、`action`、`modal`、`shorten` などのタスク操作をサポートします。 |
| Midjourneyタスク照会 | `GET /mj/task/{id}/fetch`<br />`GET /mj/task/{id}/image-seed`<br />`POST /mj/task/list-by-condition` | タスクステータス、画像シード、または条件によるタスクリストを照会します。`{mode}` プレフィックス付きのパスもサポートします。 |
| Midjourney画像プロキシ | `GET /mj/image/{id}`<br />`GET /{mode}/mj/image/{id}` | MidjourneyタスクIDに基づいて生成された画像を取得またはプロキシします。 |
| Midjourney拡張操作 | `POST /mj/insight-face/swap`<br />`POST /mj/submit/upload-discord-images` | 顔交換やDiscord画像のアップロードなどの拡張機能を提供します。 |

## データダッシュボードとの関係

- ログは個々の詳細であり、データダッシュボードは時間、モデル、ユーザー、またはチャネルごとに集計された統計です。
- 両者のフィルタリング範囲、更新タイミング、統計基準は異なる場合があります。
- 新しいリクエストはまずログに表示され、グラフデータは集計または更新後に反映される場合があります。

<Callout type="info">
  呼び出しをトラブルシューティングする際は、まず一般的なログで時間、モデル、リクエストID、またはアップストリームリクエストIDでリクエストを特定することをお勧めします。非同期リクエストの場合は、提出APIが返す `task_id` を記録し、その後タスクの最終ステータスと失敗詳細を照会します。タスクが長時間変化しない場合は、チャネルの可用性、タスクポーリングスイッチ、タイムアウト設定、および対応する「返金」ログを確認してください。
</Callout>
