- サイドバーの「一般」→「使用ログ」から開きます。
- モデル呼び出しごとの使用量と請求額、およびチャージや返金などによるクォータの変動履歴を確認できます。
- モデルを呼び出すと、料金に応じてアカウントのクォータ（ウォレット残高またはサブスクリプションのクォータ）が差し引かれます。課金の内訳はこのページで確認できます。

<Callout type="info" title="ヒント">

- ページタイトルは「汎用ログ」と表示されます。
- 一般ユーザーは自分のアカウントの記録のみ閲覧できます。管理者はページ右上の「すべて」「自分のみ」（管理者のみに表示）を切り替えられます。「自分のみ」を選ぶと、一般ユーザーと同じ内容が表示されます。
- 料金と使用量の表示単位はサイトによって異なります。
- ログインやアカウントのセキュリティに関する操作の記録は<a href="/ja/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">監査ログ</a>、動画、音楽、画像生成などの非同期タスクの状態は<a href="/ja/docs/guide/feature-guide/user/task-log" target="_blank" rel="noopener noreferrer">タスクログ</a>を参照してください。
- 左サイドバーに「使用ログ」がない場合<br/>「プロフィール」ページの「左サイドバーの個人設定」で「コンソール領域」と「使用ログ」を有効にして保存します。
</Callout>

## ログを絞り込んで統計を確認する

**操作手順**

1. 「期間」をクリックし、「今日」「7 日間」などのクイック選択肢を選びます。期間を手動で指定するには、「開始時刻」と「終了時刻」を入力して「確定」をクリックします。
2. 必要に応じて「モデル名」「グループ」を入力し、種類のドロップダウンからログの種類を選びます。
3. トークン名やリクエスト ID などで検索する場合は、「展開」をクリックして 2 行目の絞り込み項目を入力します。
4. 「検索」をクリックするか、いずれかの入力欄で Enter キーを押します。
5. 絞り込みエリアの左下で「使用量」「RPM」「TPM」を確認します。
6. 絞り込み条件をクリアするには、「リセット」をクリックします。

<Callout type="info" title="ヒント">

- デフォルトでは、今日の 00:00:00 から現在時刻の 1 時間後までの記録のみ表示されます。それより前の記録を確認するには、先に期間を調整してください。
- 絞り込み条件を変更したら、「検索」をクリックして適用します。ページは自動更新されないため、新しい記録を表示するには再度「検索」をクリックします。
- スマートフォンでは、期間以外の絞り込み項目は「絞り込み」にまとめられています。期間を選ぶと、一覧がすぐに更新されます。
</Callout>

**絞り込み項目の説明**

絞り込みエリアは 2 行に分かれています。2 行目はデフォルトで折りたたまれており、「展開」をクリックすると表示されます。次の表は、絞り込みエリアでの表示順に並んでいます。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 絞り込み項目 | 位置 | 定義 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- | --- |
| 期間 | 1 行目 | 記録が生成された時刻で絞り込みます。開始時刻と終了時刻はいずれも範囲に含まれます。 | クイック選択肢は「今日」「7 日間」（今日を含む）、「今週」（日曜から土曜）、「30 日間」（今日を含む）、「今月」です。クリックすると期間が入力されます。手動で指定する場合は秒単位で入力し、「確定」をクリックします。一般ユーザーが 1 回の検索で指定できる期間には上限（デフォルトは 365 日）があり、超えると「期間は … 日を超えることはできません」と表示されます。 | 今日の 00:00:00 から現在時刻の 1 時間後まで |
| モデル名 | 1 行目 | 呼び出したモデルで絞り込みます。 | 任意入力です。デフォルトではモデル名の完全一致で検索します。部分一致で検索するには、`%gpt%` のようにキーワードの前後に % を付けます。% は最大 2 個までで、連続して使用できません。% 以外の文字を 2 文字以上入力してください。 | 空欄 |
| グループ | 1 行目 | 呼び出しで使用したグループで絞り込みます。 | 任意入力です。ドロップダウンから選ぶか、直接入力できます。グループ名の完全一致で検索します。 | 空欄 |
| 種類 | 1 行目 | ログの種類で絞り込みます。 | 「すべての種類」「チャージ」「消費」「管理」「システム」「エラー」「返金」「ログイン」のうち 1 つを選びます。「管理」と「ログイン」には「非推奨」の表示があり、過去のログの検索にのみ使用できます。各種類の意味は[ログの種類](#ログの種類)を参照してください。 | 「すべての種類」 |
| トークン名 | 2 行目 | 呼び出しに使用した API キーの名前で絞り込みます。 | 任意入力です。完全一致で検索します。部分一致には対応していません。 | 空欄 |
| ユーザー名（管理者のみに表示） | 2 行目 | リクエストを送信したユーザーで絞り込みます。 | 「すべて」ビューでのみ表示されます。デフォルトではユーザー名の完全一致で検索します。部分一致のルールは「モデル名」と同じです。 | 空欄 |
| チャネル ID（管理者のみに表示） | 2 行目 | リクエストを処理したチャネルで絞り込みます。 | 「すべて」ビューでのみ表示されます。チャネル ID の数値を入力します。 | 空欄 |
| リクエスト ID | 2 行目 | New API がリクエストごとに生成した ID で検索します。 | 任意入力です。ID の完全一致で検索します。「ログの詳細」からコピーできます。 | 空欄 |
| 上流リクエスト ID | 2 行目 | 上流サービスが返したリクエスト ID で検索します。 | 任意入力です。ID の完全一致で検索します。 | 空欄 |
</div>

統計値は絞り込みエリアの左下に表示され、「検索」をクリックすると更新されます。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 統計項目 | 定義 | 集計範囲 |
| --- | --- | --- |
| 使用量 | 「消費」の記録にある料金の合計。 | 選択した期間内で、「モデル名」「グループ」「トークン名」（管理者の場合は「ユーザー名」「チャネル ID」も含む）の条件に一致する「消費」の記録を集計します。「種類」「リクエスト ID」「上流リクエスト ID」の条件は適用されず、「返金」も差し引かれません。 |

## ログの詳細を確認する

**操作手順**

1. 記録の行にある「詳細」列の概要テキストをクリックして、「ログの詳細」ウィンドウを開きます。
2. 各セクションで、その記録のリクエスト情報、Token 使用量、課金の内訳を確認します。
3. ログの内容をコピーするには、「内容」の右上にあるコピーボタンをクリックします。

<Callout type="info" title="ヒント">

- ウィンドウには、その記録に実際に保存された情報のみ表示されます。表示されるセクションは、ログの種類やリクエストによって異なります。
- 課金内容を照合するには、「Token の内訳」と「課金の詳細」を確認してください。
</Callout>

### リクエストポリシーの判定

「ログの詳細」の「リクエストポリシーの判定」セクション（管理者のみに表示）には、リクエストのチャネル選択、リトライ、停止の判定過程がステップごとに表示されます。ページ右上で「すべて」を選択した場合にのみ表示されます。

- 成功したリクエストでは、判定履歴が「消費」の記録とともに書き込まれ、少なくとも「チャネルを選択」と「リクエスト完了」の 2 つのステップが含まれます。管理者が「クォータ使用量を記録」を無効にすると、以降は書き込まれません。
- 失敗した試行ごとに「エラー」の記録が 1 件書き込まれ、その試行までの判定履歴が含まれます。サイトでエラーログの記録が有効になっていない場合、これらの記録は書き込まれず、失敗した試行の判定履歴は表示されません。

**ステップの表示形式**

1. 1 行目には判定内容が表示されます。チャネルに関する判定では末尾に「#チャネル ID」、失敗したステップでは末尾に HTTP ステータスコードが付きます。リトライを停止したステップは琥珀色で表示されます。
2. 2 行目には「試行 N」、リクエスト開始からの累計所要時間（ミリ秒）、グループ、一致したルール名、HTTP ステータスコードが表示されます。該当する情報がない項目は表示されません。
3. 3 行目には「根拠：」に続いて判定の根拠が表示されます。失敗に伴いチャネルの稼働状態に関する処理が行われた場合は、その内容が根拠に続いて表示されます。

**判定内容の説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 判定内容 | 意味 |
| --- | --- |
| チャネルを選択 | 今回の試行で選択されたチャネルです。 |
| セッションルールに一致 | リクエストがセッション維持ルールに一致しました。ルール名は 2 行目に表示されます。 |
| 上流リクエストが失敗 | 今回の試行は上流サービス側、またはネットワーク接続時に失敗しました。 |
| リクエストがローカルで拒否された | 上流サービスへの送信前に、ローカルチェックでリクエストが拒否されました。 |
| チャネルエラー | チャネル自体にエラーが発生したと判定されました。 |
| ステータスコードがリトライルールに一致 | 失敗時のステータスコードがリトライルールの対象であるため、リトライを続けます。 |
| ステータスコードがリトライルールに不一致 | 失敗時のステータスコードがリトライルールの対象外であるため、リトライを停止します。 |
| 認識できないステータスコード | 上流サービスから返されたステータスコードを認識できません。 |
| 最大試行回数に到達 | 試行回数が上限に達したため、リトライを停止します。 |
| システムによるリトライ禁止 | システムのルールでリトライが禁止されている条件に該当したため、リトライを停止します。 |
| チャネル固定の制約 | リクエストが特定のチャネルに固定されているため、そのチャネルを使い続けます。 |
| セッション維持設定によりチャネルの切り替えを停止 | セッション維持のため、元のチャネルを使い続けます。 |
| タスクは受理済みで再送信不可 | 非同期タスクは上流サービスに受理されているため、リトライを停止します。 |
| タスクが失敗 | 非同期タスクの送信時に失敗しました。 |
| ストリーミング出力が正常に完了しなかった | ストリーミング出力が正常に終了しませんでした。 |
| リクエスト完了 | リクエストが正常に終了しました。 |
</div>

**判定の根拠と稼働状態に関する処理**

- 判定の根拠が「グローバルデフォルト」「グローバル設定とチャネル設定」「チャネル」「セッションルール」の場合は、サイトまたはチャネルのリトライ設定やセッション設定に基づく判定です。「システム制約」「チャネル固定の制約」はシステムルールに基づく判定です。「チャネル選択」「上流レスポンス」「上流接続」「ローカルチェック」は、その試行時の状況に基づく判定です。
- 稼働状態に関する処理が「変更なし」の場合、チャネルの状態に変更はありません。「チャネルの無効化を要求済み」「現在のキーの無効化を要求済み」の場合、その試行の失敗によって無効化が要求されました。

## ログをエクスポートする

**操作手順**

1. 必要に応じてページの絞り込み条件を設定し、「検索」をクリックします。
2. 絞り込みエリアの右下にある「エクスポート」をクリックして、「ログのエクスポート」ウィンドウを開きます。
3. ウィンドウでエクスポートする期間を設定します。
4. ウィンドウ内の「エクスポート」をクリックし、ブラウザーでファイルのダウンロードが完了するまで待ちます。

<Callout type="info" title="ヒント">

- 管理者が一般ユーザー向けのエクスポートを無効にすると、一般ユーザーのページに「エクスポート」は表示されません。管理者は常にエクスポートできます。
- 同じアカウントで同時に実行できるエクスポートは 1 件のみです。処理中にウィンドウを閉じると、エクスポートは中止されます。
- 「非表示」はエクスポートに影響しません。ファイルには元の名前が出力されます。
</Callout>

**設定項目の説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 設定項目 | 定義 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| 期間 | エクスポートする記録の期間。 | 必須です。開始時刻と終了時刻の両方を設定します。終了時刻が開始時刻より前の場合は「終了時刻は開始時刻より後にしてください」と表示されます。期間が上限（デフォルトは 365 日）を超えると「期間は … 日を超えることはできません」と表示され、「エクスポート」をクリックできなくなります。ページで設定したモデル名、グループ、種類、トークン名、リクエスト ID などの絞り込み条件も適用されます。 | ページで現在適用されている期間 |
</div>

**エクスポートファイルの説明**

- ファイルは CSV 形式です。ファイル名は「usage-logs-開始日-終了日.csv」で、たとえば `usage-logs-20261101-20261108.csv` となります。表計算ソフトで直接開けます。
- 「時刻」「種類」「トークン」「グループ」「モデル」「ストリーム」「入力 Token」「出力 Token」「キャッシュ読み取り」「キャッシュ書き込み」「料金」「所要時間」「IP」「リクエスト ID」「詳細」の列が含まれます。「すべて」ビューでエクスポートすると、「ユーザー」「チャネル」の列（管理者のみに表示）が追加され、すべてのユーザーの記録が含まれます。
- 記録は時刻の新しい順に並び、件数に上限はありません。

## よくある質問

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="特定の呼び出しの記録が見つからない">
**考えられる原因**

- 期間がデフォルトの「今日」のままか、絞り込み条件が厳しすぎます。トークン名、グループ、リクエスト ID、上流リクエスト ID は、いずれも完全一致で照合されます。
- 呼び出しが失敗しました。サイトでエラーログの記録が有効になっていない場合、失敗したリクエストは記録されません。キーの検証失敗、利用可能なチャネルの不足、リクエスト数の上限到達、クォータ不足などにより呼び出し前に拒否されたリクエストは、設定にかかわらず記録されません。
- 管理者が「クォータ使用量を記録」を無効にしたため、成功した呼び出しの「消費」ログが作成されなくなりました。
- 管理者が「自分のみ」を選択しており、探している記録が別のユーザーのものです。
- ページは自動更新されません。

**対処方法**

1. 不要な絞り込み条件を解除し、呼び出しが行われた時間帯に期間を設定します。
2. リクエスト ID がわかっている場合は、「展開」をクリックし、「リクエスト ID」に完全な ID を入力します。
3. 「検索」をクリックして一覧を更新します。
4. それでも見つからない場合は、管理者にサイトのログ記録設定を確認してもらってください。
</Accordion>

<Accordion title="失敗したリクエストは課金されるか">
**説明**

エラーを返したリクエストには課金されません。サイトでエラーログの記録が無効になっている場合、失敗したリクエストは記録されません。有効にすると、失敗したリクエストは「エラー」として記録され、「料金」は 0 と表示されます。エラー情報は「ログ詳細」の「内容」で確認できます。非同期タスクが失敗またはタイムアウトした場合は、差し引かれたクォータが返還され、「返金」ログが 1 件作成されます。

**対処方法**

1. 「消費」「返金」のログとアカウント残高の変動を照合し、請求内容を確認します。
2. 失敗の原因を調べる必要があり、一覧に「エラー」ログがない場合は、管理者にお問い合わせください。
</Accordion>

<Accordion title="料金が想定と異なる">
**説明**

「課金詳細」の入力単価と出力単価は、いずれも 100 万 Token あたりの価格です。表示単位はサイトによって異なります。

**考えられる原因**

- 利用したグループに倍率が設定されているか、アカウントに個別の倍率が設定されています。倍率は「トークン」列のグループ名の横に表示されます。
- キャッシュの読み書き、音声、画像、ウェブ検索などの機能を利用した場合は、それぞれの単価で課金されます。ツール呼び出しの追加料金を含むログには、「料金」の横にレンチアイコンが表示されます。
- モデルには段階別料金が設定されており、適用された料金段階によって単価が異なります。
- サブスクリプションのクォータで支払った場合、「料金」にはサブスクリプションから実際に差し引かれたクォータが表示されます。

**対処方法**

1. 該当するログの「ログ詳細」を開き、「課金詳細」で課金方式、単価、倍率、合計料金を確認します。
2. 「Token 明細」で種類ごとの Token 数を確認します。
3. 不明な点が残る場合は、「リクエスト ID」を管理者にお伝えください。
</Accordion>

<Accordion title="「使用量」が一覧の合計料金やダッシュボードと一致しない">
**説明**

- 「使用量」は選択した期間内の「消費」ログのみを集計します。「返金」は差し引かれず、「種類」「リクエスト ID」「上流リクエスト ID」による絞り込みも反映されません。
- 「RPM」と「TPM」は常に直近 60 秒を集計します。
- ダッシュボードは一定の間隔（デフォルトでは 5 分ごと）で集計されます。新しい呼び出しは先に使用ログに表示されます。

**対処方法**

1. 種類のドロップダウンで「消費」を選択して「検索」をクリックし、「使用量」と照合します。
2. 種類で「返金」を選択し、返還されたクォータを個別に確認します。
3. ダッシュボードのデータは、しばらく待ってからページを更新して確認してください。
</Accordion>

<Accordion title="検索時に「期間は … 日を超えることはできません」と表示される">
**表示メッセージ**

「期間は … 日を超えることはできません」（英語 The time range cannot exceed … days）

**考えられる原因**

一般ユーザーが一度に検索できる期間には上限があります。デフォルトは 365 日で、管理者が設定できます。エクスポート時は管理者にもこの上限が適用されます。

**対処方法**

1. 期間を短くしてから再検索します。
2. より長い期間のログが必要な場合は、期間を分割して検索またはエクスポートします。
</Accordion>

<Accordion title="「エクスポート」ボタンが表示されない、またはエクスポート時にエラーが表示される">
**説明**

表示されたメッセージをもとに原因を確認してください。

| 表示メッセージ | 考えられる原因 | 対処方法 |
| --- | --- | --- |
| ページに「エクスポート」が表示されない、または「ログのエクスポートは無効です」と表示される（英語 Log export is disabled） | 管理者がユーザーによるエクスポートを無効にしています。 | 管理者にお問い合わせください。 |
| 「別のログのエクスポートが実行中です。完了してから再試行してください。」（英語 Another log export is running. Try again after it finishes.） | このアカウントですでにエクスポートが実行されています。 | 実行中のエクスポートが完了してから再試行してください。 |
| 「終了時刻は開始時刻より後である必要があります」（英語 End time must be after start time） | 終了時刻が開始時刻より前に設定されています。 | 期間を設定し直してください。 |
| 「期間は … 日を超えることはできません」（英語 The time range cannot exceed … days） | エクスポート対象の期間が上限を超えています。デフォルトの上限は 365 日です。 | 期間を分割してエクスポートしてください。 |
| 「ログのエクスポートに失敗しました」（英語 Failed to export logs） | ネットワーク接続が切断されたか、サーバー側でエラーが発生しました。 | 再試行してください。それでも失敗する場合は、管理者にお問い合わせください。 |
</Accordion>

<Accordion title="詳細に「IP アドレス」が表示されない">
**考えられる原因**

アカウントで「IP アドレスを記録」が有効になっていません。この設定はデフォルトで無効です。有効にすると、それ以降に作成された「消費」「エラー」のログにのみ適用されます。

**対処方法**

1. <a href="/ja/docs/guide/feature-guide/user/security#ip-アドレスの記録を設定する" target="_blank" rel="noopener noreferrer">セキュリティとアクセス</a>ページを開き、「プライバシー」で「IP アドレスを記録」を有効にして「設定を保存」をクリックします。
2. 以降のログには IP アドレスが表示されます。有効にする前のログに IP アドレスを追加することはできません。
</Accordion>

<Accordion title="モデル名の横に「応答モデル：…」と表示される">
**表示メッセージ**

「上流サービスが返したモデル名は、リクエストモデルと上流リクエストモデルのどちらとも一致しません。モデルのエイリアスや日付付きバージョンによっても差異が生じるため、この警告だけではモデルが置き換えられたとは判断できません。」（英語 The upstream returned a model name different from both the requested and upstream models. Aliases or dated versions may also cause this; this warning alone does not prove model substitution.）

**考えられる原因**

上流サービスが返したモデル名が、リクエストしたモデル名と異なります。たとえば、モデルのエイリアスや日付付きのバージョン名が返される場合があります。

**対処方法**

1. この表示をクリックし、「リクエストモデル」「上流リクエストモデル」「応答モデル」を確認します。
2. モデルが置き換えられた可能性がある場合は、「リクエスト ID」を管理者に伝え、確認を依頼してください。
</Accordion>

<Accordion title="% を使ったあいまい検索で形式エラーが表示される">
**説明**

「モデル名」と「ユーザー名」では、% を使ったあいまい検索ができます。形式が正しくない場合は、以下のメッセージが表示されます。

| 表示メッセージ | 考えられる原因 | 対処方法 |
| --- | --- | --- |
| 「検索パターンに連続したワイルドカード % を含めることはできません」（英語 The search pattern cannot contain consecutive % wildcards） | % が連続して入力されています。 | 余分な % を削除してください。 |
| 「検索パターンに含められるワイルドカード % は最大 2 個です」（英語 The search pattern can contain at most 2 % wildcards） | % が 3 個以上使われています。 | % を 2 個以下にしてください。 |
| 「あいまい検索のキーワードは 2 文字以上で入力してください」（英語 Fuzzy search keywords must be at least 2 characters long） | % を除く文字が 2 文字未満です。 | キーワードに文字を追加してください。 |
</Accordion>

<Accordion title="種類に「管理」または「ログイン」を選択しても新しい記録が見つからない">
**説明**

新しいログインや管理操作は監査ログに記録されます。「管理」と「ログイン」は過去のログの検索にのみ使用でき、絞り込み条件では「非推奨」と表示されます。

**対処方法**

1. <a href="/ja/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">監査ログ</a>を開き、ログインやアカウント操作の記録を確認します。
</Accordion>

<Accordion title="「チャネル」「ユーザー」列や「リクエストポリシーの判定」が表示されない">
**説明**

管理者向けの「チャネル」「ユーザー」列、「ユーザー名」「チャネル ID」の絞り込み条件、詳細ウィンドウの「リクエストポリシーの判定」などは、管理者が「すべて」を選択した場合にのみ表示されます。失敗した試行の判定ログを表示するには、サイトでエラーログの記録も有効にする必要があります。

**対処方法**

1. 管理者はページの右上で「すべて」を選択します。
2. 一般ユーザーはこれらの項目を閲覧できません。調査が必要な場合は、「リクエスト ID」を管理者にお伝えください。
</Accordion>

<Accordion title="使用ログはどのくらい保存されるか">
**説明**

使用ログはデフォルトでは自動削除されません。管理者は指定した日時より前の使用ログを削除できます。削除したログは復元できません。

**対処方法**

1. 長期保存が必要な場合は、定期的に[ログをエクスポート](#ログをエクスポートする)してください。
</Accordion>

</Accordions>
