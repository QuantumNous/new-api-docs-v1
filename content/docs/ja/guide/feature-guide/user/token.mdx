- サイドバーの「一般」→「API キー」から開きます。
- API キーを作成、管理できます。
- モデルを呼び出すと、料金に応じてアカウントのクォータ（ウォレット残高またはサブスクリプションのクォータ）が差し引かれます。

<Callout type="info" title="ヒント">

- API キーは、プログラムやクライアントがモデルを呼び出す際に使う認証情報です。`sk-` で始まり、一部のメッセージでは「トークン」とも呼ばれます。
- クォータの単位はサイトによって異なります。
- 左側のサイドバーに「API キー」ページが表示されない場合は、「プロフィール」ページの「左サイドバーの個人設定」で「コンソール領域」と「トークン管理」を有効にして保存します。

</Callout>

## API キーの作成

- API キー — API キーの作成

![API キー — API キーの作成ページ](/assets/guide/feature-guide/general-api-key-create.png)

**操作手順**

1. ページ右上の「API キーを作成」をクリックします。
2. アプリや利用環境を区別できるように、キーの名前を入力します。
3. 必要に応じてクォータ、有効期限、モデル制限、IP 制限、グループなどを設定します。
4. 「変更を保存」をクリックします。

**設定項目の説明**

ウィンドウは「基本情報」「クォータ設定」「詳細設定」の 3 つのセクションに分かれています。「詳細設定」はデフォルトで折りたたまれており、見出しをクリックすると展開できます。下表はウィンドウの表示順に並んでいます。

<div id="创建配置项说明" className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 設定項目 | セクション | 定義 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- | --- |
| 名前 | 基本情報 | キーの用途や利用環境を区別するための名前です。 | 必須。このキーを使うアプリや利用環境が分かる名前を推奨します。最大で英字 50 文字、または漢字約 16 文字です。上限を超えると「トークン名が長すぎます」と表示されます。 | 空欄 |
| グループ | 基本情報 | 呼び出し時に使うグループです。利用可能な接続先と課金倍率を決定します。 | 任意。プルダウンには、アカウントに利用権限のあるグループのみが表示されます。各グループには説明と倍率が付いています。auto を選ぶと、システムが利用可能なグループを自動で選択します。 | 未選択（「グループを選択」と表示）。アカウントが所属するグループを使います。サイトによっては auto がデフォルトで選択されます。 |
| 自動グループ選択の順序 | 基本情報 | auto グループを使う場合に、このキーが試行するグループとその順序です。 | 「グループ」で auto を選択すると表示されます。デフォルトの設定を使うか、「Auto グループを追加」をクリックしてドラッグで順序を調整できます。カスタマイズする場合は、1 つ以上のグループを選択してください。同じグループを複数回選択することはできません。追加できるグループ数の上限はウィンドウの案内に従ってください（デフォルトは 5 個）。 | 「グローバルの Auto グループ順序を継承」 |
| グループをまたいで再試行 | 基本情報 | 現在のグループで呼び出しに失敗したときに、設定順で次のグループに切り替えて再試行するかどうかを指定します。 | 「グループ」で auto を選択すると表示されます。必要に応じて切り替えられ、auto グループにのみ適用されます。説明末尾の「リクエストポリシー」リンク（Root のみ表示）から、サイトの該当するシステム設定を開けます。 | auto を選択すると自動で有効になります。 |
| 有効期限 | 基本情報 | キーが失効する日時です。 | 任意。日時を直接選択するか、「無期限」「1 か月」「1 日」「1 時間」をクリックします。「1 か月」「1 日」「1 時間」は設定時点から計算されます。過去の日時も選択できますが、その場合は保存直後からキーで呼び出せなくなります。 | 空欄（無期限） |
| 数量 | 基本情報 | 一度に作成するキーの数です。 | 作成時のみ表示されます。最小値は 1 です。複数のキーを作成する場合、最初のキーには入力した名前を使い、残りのキーには名前の末尾にランダムな 7 文字を追加します。追加後の名前にも同じ文字数制限が適用されます。途中で作成に失敗すると処理が停止し、作成済みのキーは保持されます。アカウントごとのキーの総数には上限（デフォルトは 1000 個）があり、超過すると「トークン数の上限（…）に達しました」と表示されます。 | 1 |
| クォータ (…) | クォータ設定 | このキーで使用できるクォータの上限です。括弧内には「クォータ ($)」のように、サイトのクォータ単位が表示されます。 | 「無制限クォータ」を無効にすると表示されます。0 以上の数値を入力してください。最大値を超えると「クォータの値が有効範囲を超えています。最大値は … です」と表示されます。クォータを使い切ると、このキーで呼び出せなくなります。 | 10 |
| 無制限クォータ | クォータ設定 | このキー自体の使用量の上限を解除するかどうかを指定します。 | 必要に応じて切り替えます。無効にすると、上に「クォータ」の入力欄が表示されます。この設定で解除されるのはキー自体の上限です。呼び出し時にはアカウントのクォータから差し引かれ、アカウントのクォータが不足していると呼び出しは失敗します。 | 有効 |
| モデル制限 | 詳細設定 | このキーで呼び出せるモデルの範囲です。 | 任意。複数選択できます。候補にはアカウントで利用可能なモデルのみが表示されます。モデルを選択しない場合は、利用可能なすべてのモデルを呼び出せます。 | 未選択（制限なし） |
| IP 許可リスト（CIDR 表記に対応） | 詳細設定 | このキーの使用を許可する IP アドレスまたはネットワーク範囲です。 | 任意。1 行につき 1 つの IP アドレスまたは CIDR 範囲（例：192.168.1.0/24）を入力します。カンマ区切りには対応していません。空欄の場合は制限がありません。形式が正しくない行は無視され、すべての行が無効な場合はどのアドレスからもキーを使用できません。IP アドレスは偽装される可能性があるため、IP 許可リストのみをセキュリティ対策として使うことは推奨しません。 | 空欄（制限なし） |
| ユーザークォータの照会を許可 | 詳細設定 | このキーで<a href="/ja/docs/api/management/token-management/usage-token-get" target="_blank" rel="noopener noreferrer">トークンの使用状況を取得</a>する API を呼び出したときに、アカウントの残りクォータと使用済みクォータも返すかどうかを指定します。 | 必要に応じて切り替えます。この設定はモデルの呼び出しに影響しません。 | 有効 |
</div>

## キーをコピーしてモデルを呼び出す

**操作手順**

1. 対象の行の「API キー」列で、キーの右側にあるコピーボタンをクリックします。
2. キーをクライアントの入力欄に貼り付けます。
3. ページ右上の「API アドレス」をクリックします。
4. 各アドレスの説明を参照して必要な API アドレスを選び、その右側にあるコピーボタンをクリックします。
5. API アドレスをクライアントの入力欄に貼り付けます。

**呼び出し方法**

1. クライアントで設定する場合、API アドレスには通常 `/v1` が含まれていません。多くの OpenAI 互換クライアントでは、Base URL に API アドレスの末尾に `/v1` を付けた値を指定します。詳しくはクライアントの説明を参照してください。
2. リクエストを送信する場合は、API アドレスにエンドポイントのパスを付けます。たとえば、チャットエンドポイントを呼び出すには、以下のように API アドレスに `/v1/chat/completions` を付けます。

```bash
curl https://your-host/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-xxxxxxxx" \
  -d '{"model":"模型名称","messages":[{"role":"user","content":"你好"}]}'
```

- `https://your-host` をコピーした API アドレスに、`sk-xxxxxxxx` を API キーに、`模型名称` を利用可能なモデル名に置き換えます。<br/>このコマンドは macOS と Linux のターミナル、および Windows の Git Bash で使えます。
- API アドレスに `/v1/models` を付けてリクエストを送ると、そのキーで利用可能なモデルの情報を取得できます。<br/>詳細は<a href="/ja/docs/api/ai-model/models/list/listmodels" target="_blank" rel="noopener noreferrer">モデル一覧の取得（OpenAI ネイティブ形式）</a>を参照してください。その他のエンドポイントやパラメーターについては、<a href="/ja/docs/api/ai-model/chat/openai/createchatcompletion" target="_blank" rel="noopener noreferrer">ChatCompletions 形式</a>などの API ドキュメントを参照してください。

<Callout type="warn" title="API キーの取り扱いに注意">

- API キーを入手した人は誰でも、そのキーを使ってアカウントのクォータを消費できます。
- キーをグループチャットに送信したり、スクリーンショットや公開コードリポジトリに含めたりしないでください。
- キーの漏えいが疑われる場合は、直ちにそのキーを削除し、新しいキーを作成してください。

</Callout>

## CC Switch またはチャットアプリへのインポート

- API キー — CC Switch に入力

![API キー — CC Switch に入力する画面](/assets/guide/feature-guide/general-api-key-import-cc-switch.png)

<a href="/ja/docs/apps/cc-switch" target="_blank" rel="noopener noreferrer">CC Switch</a> は、Claude Code、Codex、Gemini CLI の設定を管理するデスクトップツールです。使用するには、あらかじめパソコンにインストールしておく必要があります。

**CC Switch へのインポート手順**

1. 対象の行の末尾にある ⋯ メニューを開き、最上位の「CC Switch」を選択して「CC Switch に入力」ウィンドウを開きます。
2. 「アプリ」で Claude、Codex、Gemini のいずれかを選択します。
3. 必要に応じて設定情報を入力します。
4. 「CC Switch を開く」をクリックします。
5. ブラウザーに CC Switch を開くかどうかの確認が表示されます。許可すると、API アドレス、選択したキー、モデルの設定情報が CC Switch に取り込まれます。

**その他のチャットアプリへのインポート手順**

1. 対象のキーの右側にある「⋯」をクリックしてメニューを開きます。
2. 「チャット」からインポート先のチャットアプリを選択し、設定を取り込んで使用します。

<Callout type="info" title="ヒント">

- Web アプリは新しいタブで開きます。デスクトップアプリやブラウザー拡張機能はあらかじめインストールしてください。ブラウザーから起動するか、キーを直接受け取ります。
- サイドバーの「チャット」では、有効なキーのうち最も新しく作成されたものが自動で使われます。

</Callout>

## キーの編集、無効化、削除

- API キー — API キーの更新

![API キー — API キーの更新ページ](/assets/guide/feature-guide/general-api-key-update.png)

**編集手順**

1. 対象の行にある編集アイコンをクリックします。
2. 「API キーを更新」ウィンドウで、必要に応じて設定を変更します。
3. 「変更を保存」をクリックします。

**無効化または有効化の手順**

1. 対象の行にある電源アイコンをクリックします。有効なキーには「無効化」、その他のステータスのキーには「有効化」と表示されます。
2. 操作はすぐに反映されます。確認ウィンドウは表示されません。

<Callout type="info" title="ヒント">
「期限切れ」または「クォータ消尽」のキーは直接有効にできません。対処方法は [API キーのステータス](#api-密钥状态)を参照してください。
</Callout>

**削除手順**

1. 対象の行の末尾にある ⋯ をクリックし、「削除」を選択します。
2. キーの名前を確認し、「削除」をクリックします。複数のキーを一度に削除するには、[一括操作](#批量操作)を参照してください。

<Callout type="warn" title="注意">
削除したキーは復元できません。そのキーを使っているプログラムやクライアントは、削除直後から呼び出せなくなります。一時的に使用を停止する場合は「無効化」を使ってください。
</Callout>

**設定項目の説明**

「API キーを更新」ウィンドウの設定項目は作成ウィンドウと同じで、開いたときにはそのキーの現在の設定が表示されます。各項目の定義、入力要件、制限、デフォルト値については、[API キー作成時の設定項目の説明](#创建配置项说明)を参照してください。下表には、作成時と異なる項目のみを記載しています。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 設定項目 | 「API キーを作成」ウィンドウ | 「API キーを更新」ウィンドウ |
| --- | --- | --- |
| 数量 | 表示されます。デフォルトは 1 で、複数のキーを一度に作成できます。 | 表示されません。一度に変更できるキーは 1 つです。 |
| グループ | デフォルトは未選択です。サイトによっては auto がデフォルトで選択されます。 | キーの現在のグループが表示されます。現在のグループが利用できなくなっている場合は、ウィンドウを開いたときに利用可能なグループに自動で置き換わり、保存後に反映されます。 |
| 有効期限、クォータ (…) | 保存すると入力した値が適用されます。 | 値を変更しても、「期限切れ」または「クォータ消尽」のキーは自動で「有効」に戻りません。保存後に一覧で「有効化」を実行してください。 |
</div>

<Callout type="info" title="ヒント">

- キー自体の変更や有効・無効の切り替えは編集ウィンドウでは行えません。キーを交換するには、新しいキーを作成してから古いキーを削除してください。有効化または無効化するには、行内の電源アイコンを使ってください。

</Callout>

## ステータスの説明

<a id="api-密钥状态" />

### API キーのステータス

一覧の「ステータス」列と「ステータス」フィルターには、次の 4 種類のステータスがあります。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| ステータス | 意味 | 備考 |
| --- | --- | --- |
| 有効 | キーを使ってモデルを呼び出せます。 | — |
| 無効 | キーが手動で無効化されています。 | 一覧で「有効化」を実行します。 |
| 期限切れ | キーの「有効期限」を過ぎています。 | 直接有効にしようとすると、「トークンの有効期限が切れているため、有効化できません…」と表示されます。まずキーを編集し、「有効期限」を将来の日時または「無期限」に変更します。保存してから「有効化」を実行してください。 |
| クォータ消尽 | キー自体のクォータを使い切っています。アカウント残高が残っていても、この状態になります。 | 直接有効にしようとすると、「トークンのクォータを使い切ったため、有効化できません…」と表示されます。まずキーを編集して「クォータ」を増やすか、「無制限クォータ」を有効にします。保存してから「有効化」を実行してください。 |
</div>

## よくある質問

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="呼び出し時に「無効なトークン」と表示される">
**表示メッセージ**　「無効なトークン」（英語では Invalid token）

**考えられる原因**　リクエストにキーが含まれていないか、キーが間違っている、削除されている、無効になっている、有効期限が切れている、またはクォータを使い切っています。いずれの場合も同じメッセージが表示されます。

**対処方法**

1. 一覧からキーをコピーし直し、リクエストヘッダーが `Authorization: Bearer sk-…` になっていることと、キーの前後に余分な空白や改行がないことを確認します。
2. キーの「ステータス」が「有効」になっていることを確認し、「有効期限」列で期限切れになっていないか、「クォータ」列でクォータを使い切っていないかを確認します。対処方法は [API キーのステータス](#api-密钥状态)を参照してください。
3. 使用しているのが API キーであることを確認します。「セキュリティとアクセス」で作成した「アクセストークン」はアカウント管理専用です。モデルの呼び出しには API キーを使用してください（<a href="/ja/docs/guide/feature-guide/user/security#アクセストークンの作成と管理" target="_blank" rel="noopener noreferrer">セキュリティとアクセス</a>を参照）。
4. それでも解決しない場合は、キーを新規作成して再試行するか、管理者にお問い合わせください。
</Accordion>

<Accordion title="呼び出し時に「このトークンにはモデル … へのアクセス権限がありません」と表示される">
**表示メッセージ**　「このトークンにはモデル … へのアクセス権限がありません」（英語では This token has no access to model …）

**考えられる原因**　キーに「モデル制限」が設定されており、リクエストしたモデルが許可されていません。

**対処方法**

1. キーを編集し、「詳細設定」を展開します。
2. 「モデル制限」に対象モデルを追加します。利用可能なすべてのモデルの呼び出しを許可する場合は、「モデル制限」を空にします。
3. 「変更を保存」をクリックします。
</Accordion>

<Accordion title="呼び出し時に「お使いの IP アドレスがトークンの許可リストに含まれていません」と表示される">
**表示メッセージ**　「お使いの IP アドレスがトークンの許可リストに含まれていません」（英語では Your IP address is not on this token's allowlist）

**考えられる原因**

- キーに「IP 許可リスト」が設定されており、リクエスト元のマシンの IP アドレスがリストに含まれていません。プロキシ経由でリクエストを送信する場合、外部に公開される送信元 IP アドレスはローカルマシンの IP アドレスと異なることがあります。
- 許可リストに形式が正しくない行があります。形式が正しくない行は無視されます。すべての行が無効な場合は、どの IP アドレスからもキーを使用できません。

**対処方法**

1. キーを編集し、「詳細設定」の「IP 許可リスト」に、外部に公開される送信元 IP アドレスまたはネットワーク範囲を 1 行に 1 件ずつ追加します。
2. どの行に誤りがあるか特定できない場合は、許可リストをいったん空にしてから、1 行ずつ追加します。
3. 「変更を保存」をクリックします。
</Accordion>

<Accordion title="呼び出し時に「グループ … へのアクセス権限がありません」または「グループ … は廃止されました」と表示される">
**表示メッセージ**　「グループ … へのアクセス権限がありません」（英語では No permission to access group …）または「グループ … は廃止されました」（英語では Group … has been deprecated）

**考えられる原因**　管理者がグループ設定を変更したなどの理由で、キーに指定されたグループが利用できなくなっています。

**対処方法**

1. キーを編集します。編集画面を開いた時点で、「グループ」が利用可能なグループに自動で切り替わっている場合があります。
2. 「グループ」のドロップダウンリストで、利用可能なグループが選択されていることを確認します。
3. 「変更を保存」をクリックします。
</Accordion>

<Accordion title="呼び出し時にクォータ不足と表示される（「無制限クォータ」を有効にしたキーを含む）">
**説明**　「無制限クォータ」を有効にすると、キー自体の使用量上限が解除されます。呼び出しにかかる費用は引き続きアカウントのクォータから差し引かれます。表示されたメッセージから原因を確認してください。

| 表示メッセージ | 考えられる原因 | 対処方法 |
| --- | --- | --- |
| 「ユーザーのクォータが不足しています」（英語では Insufficient user quota）<br/>「クォータの事前引き落としに失敗しました」（英語では Not enough quota to pre-consume） | アカウント残高が不足しています。「クォータの事前引き落としに失敗しました」は、残高が今回のリクエストの見積もり額を下回っていることを示します。入力が長く、モデルの価格やグループ倍率が高いほど、見積もり額は大きくなります。 | <a href="/ja/docs/guide/feature-guide/user/wallet" target="_blank" rel="noopener noreferrer">ウォレット</a>でチャージまたはクォータの引き換えを行います。 |
| 「サブスクリプションのクォータが不足しているか、サブスクリプションが設定されていません」（英語では Subscription quota is insufficient or no subscription is configured） | 今回のリクエストはサブスクリプションによる課金の対象ですが、サブスクリプションのクォータが不足しているか、利用可能なサブスクリプションがありません。 | <a href="/ja/docs/guide/feature-guide/user/wallet#サブスクリプションプラン" target="_blank" rel="noopener noreferrer">ウォレット</a>でサブスクリプションを確認します。 |
| token quota is not enough（英語のみ） | キーの「無制限クォータ」が無効になっており、今回のリクエストに必要なクォータが残っていません。 | キーを編集し、「クォータ」を引き上げます。 |
</Accordion>
