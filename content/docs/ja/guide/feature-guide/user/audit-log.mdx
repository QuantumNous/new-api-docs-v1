- サイドバーの「一般」→「監査ログ」から開きます。
- アカウントのログイン、セキュリティ設定、API キー、アクセストークンなどの操作履歴を確認できます。
- 監査ログにはアカウントの操作のみが記録されます。モデル呼び出しの使用量や課金額は記録されません。

<Callout type="info" title="ヒント">

- 一般ユーザーは自分のアカウントの記録のみを閲覧できます。「他のアカウントの監査ログを閲覧」権限を持つ管理者は、ページ右上で「すべて」と「自分のみ」を切り替えられます。この切り替えは管理者にのみ表示されます。
- モデル呼び出しの使用量と課金額は<a href="/ja/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">利用ログ</a>で確認できます。利用ログの種類フィルターにある「管理」と「ログイン」は廃止されました。以降のログインや管理操作は監査ログに記録されます。
- イベントに表示される「API トークン」は、「API キー」ページのキーを指します。「アクセストークン」は<a href="/ja/docs/guide/feature-guide/user/security#アクセストークンの作成と管理" target="_blank" rel="noopener noreferrer">セキュリティとアクセス</a>ページで作成する、アカウント管理用の認証情報です。モデルの呼び出しには使用できません。
- 左サイドバーに「監査ログ」ページが表示されない場合<br/>「プロフィール」ページの「左サイドバーの個人設定」で「コンソールエリア」と「監査ログ」を有効にして保存します。
</Callout>

## 監査ログの絞り込み

**操作手順**

1. 「期間」をクリックしてプリセットを選択します。または、「開始日時」と「終了日時」を入力し、「確定」をクリックします。
2. 必要に応じて、結果のドロップダウン（デフォルトは「すべての結果」）とカテゴリのドロップダウン（デフォルトは「すべてのカテゴリ」）から項目を選択します。
3. トークン識別子やリクエスト ID で検索する場合は、「展開」をクリックし、2 行目のフィルターに入力します。
4. 自動更新された一覧を確認します。現在の条件で再検索する場合は、「検索」をクリックします。
5. 絞り込み条件をクリアする場合は、「リセット」をクリックします。

<Callout type="info" title="ヒント">

- 条件を変更すると一覧がすぐに更新されるため、「検索」をクリックする必要はありません。
- デフォルトでは、期間を限定せずにすべての記録が表示されます。ページを再読み込みすると絞り込み条件がクリアされます。
</Callout>

**フィルターの説明**

フィルターエリアは 2 行に分かれています。2 行目はデフォルトで折りたたまれており、「展開」をクリックすると表示されます。以下の表は、フィルターエリアでの表示順です。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| フィルター | 位置 | 定義 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- | --- |
| 期間 | 1 行目 | 操作日時で絞り込みます。開始日時と終了日時の両方を範囲に含みます。 | プリセットは「今日」「7 日間」（今日を含む）、「今週」（日曜から土曜）、「30 日間」（今日を含む）、「今月」です。手動で指定する場合は秒単位で入力し、「確定」をクリックします。開始日時と終了日時は片方だけでも指定でき、期間の長さに制限はありません。開始日時が終了日時より後の場合は、「終了日時は開始日時より後にしてください」と表示され、一覧は更新されません。 | 空欄（期間の指定なし） |
| 結果 | 1 行目 | 操作結果で絞り込みます。 | 「すべての結果」「成功」「失敗」から 1 つを選択します。 | 「すべての結果」 |
| カテゴリ | 1 行目 | 記録のカテゴリで絞り込みます。 | 「すべてのカテゴリ」「ログイン」「アカウントセキュリティ」「操作監査」「アクセストークン」から 1 つを選択します。各カテゴリのイベントは[イベントカテゴリ](#イベントカテゴリ)を参照してください。 | 「すべてのカテゴリ」 |
| トークン識別子 | 2 行目 | アクセストークンの識別子。特定のアクセストークンで送信されたリクエストを検索できます。 | 任意です。数字と小文字の a～f からなる 64 文字の識別子をすべて入力します。「アクセストークン」カテゴリの記録の詳細からコピーできます。このカテゴリの記録のみが検索対象です。入力が不完全な場合は、一覧に「監査記録の読み込みに失敗しました」と表示されます。 | 空欄 |
| リクエスト ID | 2 行目 | 個々の操作に対応するリクエストの識別子。 | 任意です。ID の完全一致で検索します。詳細の「リクエスト」セクションからコピーできます。 | 空欄 |
| ユーザー名（管理者にのみ表示） | 2 行目 | 記録が属するアカウントで絞り込みます。 | 「すべて」ビューでのみ表示されます。記録が生成された時点のユーザー名に完全一致するものを検索します。 | 空欄 |
</div>

## 監査ログの詳細の確認

- 監査ログ：ログ詳細

![監査ログのログ詳細画面](/assets/guide/feature-guide/general-audit-logs-log-details.png)

**操作手順**

1. 対象の行の「詳細」列で「詳細」をクリックし、「ログ詳細」ウィンドウを開きます。
2. イベント、結果、操作者、リクエスト情報を確認します。
3. クライアント、ルート、リクエスト ID などをコピーする場合は、値の右側にあるコピーボタンをクリックします。

**詳細ウィンドウの説明**

以下の表は、ウィンドウでの表示順です。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| セクション | フィールド | 定義 | 表示条件 |
| --- | --- | --- | --- |
| ウィンドウ上部 | イベント、結果、日時 | 操作の説明、「成功」または「失敗」、操作が行われた日時。 | すべての記録。 |
| トークン操作の詳細 | トークン名、トークン ID、変更フィールド、ステータスの変化など | API キーの作成、更新、削除、閲覧の記録の詳細。一括操作では、リクエスト件数と完了件数も表示されます。 | 「API トークン」に関連するイベント。 |

| 操作監査情報 | ロール | 操作実行時のアカウントのロール。user、admin、root のいずれかが表示されます。 | すべての記録。 |

| 操作監査情報 | 認証方式 | 「セッション」は Web ページにログインした状態で操作したことを、「アクセストークン」はアクセストークンで API を呼び出したことを示します。 | すべての記録。 |
| 操作監査情報 | その他のフィールド | 「ユーザー ID」「変更フィールド」「有効期限」「検証方法」「失敗理由」「必要な権限」など、イベントの補足情報。 | イベントに応じて表示されます。記録の追加情報を読み取れない場合は、「監査の追加情報を利用できません」と表示されます。 |
| リクエスト | リクエストメソッド、HTTP、IP、クライアント、ルート、リクエスト ID | 操作を開始したリクエストの情報。長い値の右側にはコピーボタンが表示されます。 | すべての記録。 |
| リクエスト | トークン識別子 | リクエストに使用したアクセストークンの識別子。コピーして「トークン識別子」フィルターに使用できます。 | 「アクセストークン」カテゴリの記録。 |
| 追加情報 | — | 上記以外の記録情報。管理者は「すべて」ビューで、より多くのリクエスト情報を確認できます（管理者にのみ表示）。 | その他の情報がある場合に表示されます。 |
</div>

## ステータスの説明

### 監査結果

「結果」列と結果フィルターには、次の 2 種類の結果が表示されます。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 結果 | 意味 | 備考 |
| --- | --- | --- |
| 成功 | 操作が完了しました。 | — |

<Accordion title="心当たりのないログイン記録がある">
**考えられる原因**

- 自分で別のデバイスやブラウザーからログインした。
- パスワードやサードパーティアカウントの認証情報が漏えいし、第三者がそのアカウントにログインした。

**対処方法**

1. 該当する記録の「ログ詳細」を開き、「IP」「クライアント」とログイン方法を確認します。
2. 自分の操作でないことを確認した場合は、すぐにパスワードを変更します。
3. <a href="/ja/docs/guide/feature-guide/user/security" target="_blank" rel="noopener noreferrer">セキュリティとアクセス</a>ページで、心当たりのないログインセッションとアクセストークンを取り消します。
4. 2 段階認証または Passkey を有効にします。
5. 問題が解消しない場合は、管理者に連絡してください。
</Accordion>

<Accordion title="操作の記録が見つからない">
**考えられる原因**

- 監査ログに記録されるのは、成功したログインのみです。
- モデルの呼び出し、チャージ、クォータの引き換え、デイリーチェックインは利用ログに記録されます。
- 言語やサイドバーなど、個人設定の変更は記録されません。
- 管理者がアカウントに対して行った操作は、その管理者の記録として保存されるため、一般ユーザーの一覧には表示されません。
- 監査ログが有効になる前のログインや管理操作の記録は、利用ログに「ログイン」「管理」の種類で残っています。
- 絞り込み条件が厳しすぎます。

**対処方法**

1. 「リセット」をクリックして絞り込み条件をクリアし、再度検索します。
2. <a href="/ja/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">利用ログ</a>で種類を「ログイン」または「管理」に設定し、過去の記録を検索します。
</Accordion>

<Accordion title="「すべて / 自分のみ」の切り替えや「ユーザー名」フィルターが表示されない">
**表示メッセージ**「監査ログの閲覧権限が変更されました。現在は自分の記録のみが表示されています。」（英語表記 Audit access changed. Showing only your records.）

**考えられる原因**

- 一般ユーザーは自分のアカウントの記録のみを閲覧できるため、この 2 つの項目は表示されません。
- 管理者に「他のアカウントの監査ログを閲覧」権限が付与されていないか、その権限が取り消されています。

**対処方法**

1. 管理者が他のアカウントの記録を閲覧する必要がある場合は、Root に「他のアカウントの監査ログを閲覧」権限の付与を依頼してください。
</Accordion>

<Accordion title="絞り込み時に「監査記録の読み込みに失敗しました」と表示される">
**表示メッセージ**「監査記録の読み込みに失敗しました」（英語表記 Failed to load audit records）

**考えられる原因**

- 「トークン識別子」の入力が不完全か、大文字が含まれています。
- ネットワーク接続が切断されたか、サーバーでエラーが発生しました。

**対処方法**

1. 「アクセストークン」カテゴリの記録の詳細から完全な「トークン識別子」をコピーし、入力し直します。
2. メッセージの横にある「再試行」をクリックします。
3. 問題が解消しない場合は、管理者に連絡してください。
</Accordion>

<Accordion title="「アクセストークン」カテゴリの記録が多い">
**説明**　アクセストークンでダッシュボード API を呼び出すと、拒否されたリクエストも含め、リクエストごとに 1 件記録されます。

**対処方法**

1. 記録の詳細の「リクエスト」セクションで「トークン識別子」を確認し、どのアクセストークンで送信されたリクエストかを特定します。
2. 「トークン識別子」で絞り込み、そのアクセストークンによるすべてのリクエストを確認します。
3. 心当たりのないリクエストを見つけた場合は、<a href="/ja/docs/guide/feature-guide/user/security#アクセストークンの作成と管理" target="_blank" rel="noopener noreferrer">セキュリティとアクセス</a>ページで該当のアクセストークンを取り消します。
</Accordion>

<Accordion title="監査記録はどのくらい保存されるか">
**説明**　監査記録は無期限に保存され、自動削除は行われません。管理者が過去のログを削除する際の対象は利用ログのみで、監査記録は削除されません。
</Accordion>

</Accordions>
