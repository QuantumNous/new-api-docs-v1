ログイン後、左側のナビゲーションバーにある「ウォレット」をクリックするか、直接 `/wallet` にアクセスしてウォレットページに入ります。ウォレットページでは、残高統計、オンラインチャージ、引き換えコード、注文履歴、サブスクリプションプラン、マイサブスクリプション、招待報酬などの機能が集中して提供されます。表示される領域、金額、支払い方法、プラン内容はプラットフォームの設定によって決定されます。

![ウォレットとサブスクリプションページ](/assets/guide/feature-guide/wallet-subscriptions.png)

## 残高と使用量の確認

ウォレット統計エリアには以下の情報が含まれます：

-   **現在の残高**：モデル呼び出しやその他の課金操作に使用できる内部クォータであり、現金残高ではありません。
-   **累計消費**：アカウントが過去に使用したクォータ。
-   **APIリクエスト数**：アカウントが発行したAPIリクエストの数。

<Callout type="warn">
  1. 残高と使用量の表示単位は、Rootが「システム設定」→「課金と支払い」で設定した通貨とクォータ表示ルールによって決定されます。
  2. ページ上の記号や数値に基づいて固定為替レートを自己判断しないでください。実際の課金は、モデル、グループ、チャネル、インスタンスの課金ルールにも影響されます。
</Callout>

## オンラインチャージ

プラットフォームがオンライン決済を有効にしている場合、ウォレットのチャージエリアには利用可能なチャージオプションが表示されます。チャージ金額、プリセット金額、最低チャージ金額、割引、為替レートはすべてプラットフォームの設定によって決定されます。

1.  「チャージ」エリアで、ページに表示されているプリセット金額を選択するか、カスタム金額を入力します。
2.  システムが計算したチャージクォータと支払い金額を確認します。
3.  現在のプラットフォームが提供する支払い方法を選択します。
4.  確認ウィンドウで、チャージクォータ、支払い金額、割引、支払い方法を再確認します。
5.  確認後、サードパーティ決済ページにリダイレクトされ、支払いを完了します。
6.  支払い完了後、ウォレットに戻り、注文ステータスと残高の更新を待ちます。

<Callout type="warn">
  1. プロジェクトコードはEPay、Stripe、Creem、Waffo、Waffo Pancakeなどの決済ゲートウェイをサポートしていますが、有効化され、完全に設定され、現在利用可能な支払い方法のみが表示されます。異なるゲートウェイには追加の金額または支払い制限がある場合がありますので、ページ表示に従ってください。利用可能な支払い方法がない場合は、プラットフォーム管理者にお問い合わせください。
  2. 支払い成功には、サードパーティ決済からのコールバックによる注文確認が必要です。支払い後、残高がすぐに更新されない場合があります。支払い成功にもかかわらず残高が更新されない場合は、注文番号を控えて管理者に連絡し、重複して支払いをしないでください。
  3. 支払い方法、最低チャージ金額、割引、為替レート、プリセット金額はNew APIの固定値ではありません。他のインスタンスやサンプルページから現在のインスタンスのルールを推測することはできません。
</Callout>

## 引き換えコード

引き換えコードが利用可能な場合、チャージエリアに引き換えコード入力ボックスが表示されます。管理者が引き換えコード取得アドレスを設定している場合、ページには対応する外部リンクも表示されます。

1.  チャージエリアで「引き換えコード」入力ボックスを見つけます。
2.  管理者から提供された引き換えコードを入力します。
3.  「引き換え」をクリックし、結果のプロンプトを待ち、残高を更新します。

<Callout type="info">
  1. 引き換えコードは、プラットフォームで設定された有効期限と使用ルールを満たし、有効な状態であり、まだ使用されていない必要があります。各引き換えコードは1回のみ正常に使用できます。
  2. 引き換えが失敗した場合、ページには「使用済み」「期限切れ」「存在しない」などの具体的な理由が表示されないことがあります。引き換えコードが完全であるかを確認し、管理者とステータスを確認してください。
  3. プラットフォームが関連する支払いコンプライアンス設定を完了していない場合、引き換えコードの入力と引き換え操作は無効になり、ページに該当するプロンプトが表示されます。
</Callout>

## サブスクリプションプラン

サブスクリプションプランはウォレットページのサブスクリプションエリアにあります。有効化され、現在プラットフォームの支払いコンプライアンスチェックを通過したプランのみがAPIから返され表示されます。利用可能なプランがない場合、サブスクリプションエリアは表示されません。

プランカードには以下の情報が含まれます：

| 項目 | 説明 |
| --- | --- |
| タイトルとサブタイトル | 管理者がプランに設定した名称と説明。 |
| 価格 | プラン購入に必要な金額。具体的な数値はインスタンス設定によって決定されます。 |
| 有効期限 | 年、月、日、時間、またはカスタム期間（秒）で設定可能。 |
| 総クォータ | プランに含まれるサブスクリプションクォータ。0に設定されている場合、総クォータは無制限です。 |
| クォータリセット | リセットなし、毎日、毎週、毎月、またはカスタム周期で設定可能。 |
| 購入上限 | 同一ユーザーが購入できる回数を制限します。0に設定されている場合、回数制限はありません。 |
| グループアップグレード | 購入成功後、管理者が設定したグループに切り替わる場合があります。 |
| グループダウングレード | サブスクリプション期限切れ後、管理者が設定したグループに切り替わる場合があります。設定されていない場合、購入時にグループアップグレードで切り替わり、期限切れ時もそのグループにいる場合にのみ、通常は購入前のグループに戻ります。 |

<Callout type="warn">
 「総クォータ無制限」は、そのサブスクリプション自体に総クォータ上限が設定されていないことを意味するだけであり、無制限に呼び出しができることを意味するものではありません。リクエストは引き続きモデル、ルーティング、グループ、および課金ルールによって制限されます。
</Callout>

## サブスクリプションプランの購入

1.  ウォレットページのサブスクリプションエリアを開きます。
2.  プランを選択し、有効期限、クォータ、リセット周期、購入制限を確認します。
3.  ページに表示されている購入方法を選択します。
4.  注文情報を確認後、残高からの引き落としまたはサードパーティ決済を完了します。
5.  サードパーティ決済を使用する場合、ウォレットに戻り、支払いコールバックを待ちます。ステータスが更新された後にサブスクリプションが有効になったことを確認します。

利用可能な購入方法は、グローバル決済ゲートウェイとプラン自体の設定によって異なり、以下が含まれる場合があります：

-   **ウォレット残高**：プランが残高支払いを許可しており、アカウント残高が十分な場合に利用可能です。引き落とされるクォータは「プラン価格 × `QuotaPerUnit`」で計算され、切り上げられます。具体的な単位はプラットフォームの設定によって決定されます。
-   **EPay**：プラットフォームでEPay決済が有効になっており、現在の決済設定が利用可能である必要があります。
-   **Stripe、Creem、またはWaffo Pancake**：グローバルゲートウェイが利用可能であることに加え、プランにも対応する決済製品が設定されている必要があります。

<Callout type="warn">
  通常のWaffo支払い方法がオンラインチャージに使用される場合でも、それがサブスクリプション購入をサポートしているとは限りません。ユーザーの購入上限に達した場合、プランが無効化された場合、支払い方法が利用できない場合、または残高が不足している場合、購入ボタンが無効になるか、操作が失敗する可能性があります。
</Callout>

## サブスクリプションステータスの確認

「マイサブスクリプション」エリアには、現在のサブスクリプションと履歴ステータスが表示されます。一般的なステータスは以下の通りです：

-   **Active**：サブスクリプションが有効で、ページには残り日数と終了時刻が表示されます。次回リセット時刻が設定されている場合は、その時刻も表示されます。クォータ制限のあるサブスクリプションの場合、総クォータ、使用済みクォータ、残りクォータ、使用進捗も表示されます。
-   **Expired**：サブスクリプションが期限切れで、そのサブスクリプションクォータは使用できません。
-   **Cancelled**：サブスクリプションがキャンセルされたか、早期に無効になりました。ユーザー側には自己キャンセル機能はなく、このステータスは通常、管理者操作によって発生します。
<Callout type="info">
  1. クォータリセット時刻に達すると、クォータ制限のあるサブスクリプションの使用済みクォータはゼロになり、新しいクォータサイクルが開始されます。次回のリセット時刻がサブスクリプション終了時刻を超えている場合、そのリセットは設定されません。
  2. サブスクリプション期限切れ後のグループはプラン設定によって決定されます。ダウングレードグループが設定されている場合、通常はそのグループに切り替わります。設定されていない場合、購入時にアップグレードグループで切り替わり、期限切れ時もそのアップグレードグループにいる場合にのみ、通常は購入前のグループに戻ります。アップグレードが発生しなかった場合、またはアカウントに他のアクティブなアップグレードサブスクリプションがある場合、現在のグループが維持される可能性があります。最終的なグループは他のサブスクリプションステータスと組み合わせて処理されます。
  3. 現在、自動更新サブスクリプションプラン機能はありません。サブスクリプション期限切れ後も引き続き使用したい場合は、プランを再度購入してください。
</Callout>

## 課金優先順位の選択

ウォレットページでは、リクエストのクォータ引き落とし順序を選択できます。優先順位を保存すると、バックエンドは以下のルールに従って処理します：

| 課金優先順位 | 引き落としルール |
| --- | --- |
| **サブスクリプション優先** | アクティブなサブスクリプションがある場合、まずサブスクリプションから引き落とされます。サブスクリプションクォータが不足している場合、すべてのアクティブなサブスクリプションがウォレットへのフォールバックを許可している場合にのみウォレットが使用されます。<br/>アクティブなサブスクリプションがない場合はウォレットが使用されます。 |
| **ウォレット優先** | まずウォレットから引き落とされます。ウォレット残高が不足している場合、サブスクリプションの使用が試みられます。 |
| **サブスクリプションのみ** | サブスクリプションのみを使用します。アクティブなサブスクリプションがない場合、またはサブスクリプションクォータが不足している場合、リクエストは失敗し、ウォレットには切り替わりません。 |
| **ウォレットのみ** | ウォレットのみを使用します。残高が不足している場合、リクエストは失敗し、サブスクリプションは使用されません。 |

<Callout type="info">
  プランの「ウォレットオーバーフローフォールバック」ルールは、「サブスクリプション優先」の結果に影響を与えます。アクティブなサブスクリプションのいずれかがフォールバックを禁止している場合、サブスクリプションクォータが不足してもウォレットに切り替えることはできません。アクティブなサブスクリプションがない場合、ページは「サブスクリプション優先」と「サブスクリプションのみ」オプションを無効にします。
</Callout>

## 招待報酬

ウォレットページの招待報酬エリアには、招待リンク、保留中の報酬、累計報酬履歴、招待人数が表示されます。招待コードは招待リンクの `aff` パラメータに埋め込まれており、リンク形式は以下の通りです：

```text
現在のサイトアドレス/sign-up?aff=<招待コード>
```

使用手順：

1.  招待報酬エリアで招待リンクをコピーします。
2.  リンクを新しいユーザーに送信し、そのユーザーがリンクを通じてアカウントを登録します。アカウントとパスワードによる登録およびOAuthステータスフローの一部である新規ユーザー登録はこのパラメータを読み取りますが、WeChat、Telegramなどの独立したログインフローには適用されません。
3.  プラットフォームで設定された招待条件が満たされると、ルールに従って報酬が発行されます。
4.  招待者の報酬は通常、まず保留中の報酬に入ります。報酬が移動可能な条件に達した後、「残高に転送」をクリックしてメイン残高に追加します。

<Callout type="warn">
  - 招待されたユーザーの報酬（プラットフォームが有効にしている場合）は直接そのアカウントクォータに追加されます。招待者の報酬は通常、まず保留中の報酬に入ります。
  - 招待報酬の金額、発行条件、最低転送量はプラットフォームの設定によって決定されます。
  - 残高への転送は部分転送をサポートしていますが、現在の保留中の報酬を超えることはできず、プラットフォームのクォータ単位要件を下回ることもできません。これは現金引き出し、返金、または引き出し申請ではありません。
  - 支払いコンプライアンスステータスが要件を満たしていない場合、報酬が発行されない可能性があり、「残高に転送」操作も利用できない場合があります。
  - 無効な招待コードは登録を妨げず、すでに登録済みのユーザーが招待コードを再度使用しても報酬を再度得ることはありません。
</Callout>

## 注文履歴

-   チャージカードの右上にある「注文履歴」をクリックすると、チャージと支払い注文の記録を確認できます。
-   ページは注文番号による検索とページネーションをサポートしており、注文番号、作成時間、支払い方法、チャージクォータまたは金額、支払い金額、注文ステータスが表示されます。

<Callout type="info">
  1. 一般ユーザーは、過去30日間の自分の記録のみを照会でき、検索条件は注文番号のみに一致します。
  2. このリストは主にチャージと支払い注文の確認に使用され、すべてのサブスクリプション注文を網羅していることを保証するものではありません。
</Callout>

## よくある制限

以下の状況では、ウォレットまたはサブスクリプション関連機能が利用できない場合があります：

1.  プラットフォームが決済ゲートウェイまたは決済製品を設定しておらず、利用可能な支払い方法またはサブスクリプションプランがない場合。
2.  支払いコンプライアンスステータスがまだ要件を満たしておらず、支払い方法またはサブスクリプションプランが利用できない場合、引き換えコード操作が無効と表示される場合。
3.  チャージ金額がプラットフォームまたはゲートウェイが要求する最低金額を下回る場合。
4.  残高不足、プランが無効化されている、または個人購入上限に達している場合。
5.  サードパーティ決済からのコールバックがまだ完了しておらず、注文が処理中の場合。

<Callout type="warn">
支払い成功にもかかわらず、注文または残高が長時間更新されない場合は、注文番号、支払い証明、発生時刻を控えてプラットフォーム管理者に確認を依頼し、重複して支払いをしないでください。
</Callout>
