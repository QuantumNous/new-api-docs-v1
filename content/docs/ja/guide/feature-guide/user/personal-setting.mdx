- サイドバーの「個人」→「プロフィール」から開きます。
- アカウント情報を確認し、通知方法や動作の設定、表示言語、左サイドバーに表示するページを変更できます。また、毎日のチェックインでクォータを受け取れます。
- パスワード、アカウント連携、2 段階認証、Passkey、ログインセッション、アクセストークンは、<a href="/ja/docs/guide/feature-guide/user/security" target="_blank" rel="noopener noreferrer">セキュリティとアクセス</a>ページで管理します。

<Callout type="info" title="ヒント">

- ページ上部に大きく表示されるのはアカウントの表示名です。未設定の場合はユーザー名が表示されます。
- クォータの単位はサイトによって異なります。
- 「毎日チェックイン」は、管理者がチェックイン機能を有効にした場合にのみ表示されます。
- 左サイドバーに「プロフィール」が表示されない場合は、ページ右上のアバターをクリックし、「プロフィール」を選択します。<br/>「左サイドバーの個人設定」で「個人センターセクション」と「個人設定」をオンにして保存します。これら 2 つのスイッチが表示されない場合は、管理者がページを非表示にしています。管理者にお問い合わせください。

</Callout>

## プロフィールの概要

- プロフィール - 概要

![プロフィールの概要ページ](/assets/guide/feature-guide/personal-profile.png)

ページ上部にアカウント情報と使用量が表示されます。その下の「設定」「言語設定」「毎日チェックイン」「左サイドバーの個人設定」では、以下の操作ができます。

- [通知と動作を設定する](#通知と動作を設定する)
- [表示言語を設定する](#表示言語を設定する)
- [毎日のチェックインでクォータを受け取る](#毎日のチェックインでクォータを受け取る)
- [左サイドバーに表示するページを設定する](#左サイドバーに表示するページを設定する)

<Callout type="info" title="ヒント">
通知が届かない、チェックインが表示されない、サイドバーからページが消えた場合は、[よくある質問](#よくある質問)をご覧ください。
</Callout>

## 通知と動作を設定する

- プロフィール - 通知方法

![プロフィールの通知方法の設定画面](/assets/guide/feature-guide/personal-profile-settings-notification-method.png)

**操作手順**

1. 「設定」の「通知方法」で「メール」「Webhook」「Bark」「Gotify」のいずれかを選択します。
2. 選択した通知方法の下に表示される項目を入力します。
3. 「受け取る通知」で「残高不足の通知」をオンまたはオフにし、必要に応じて「通知しきい値 (…)」を入力します。
4. 「詳細設定」で、必要に応じて「価格未設定のモデルを許可」をオンまたはオフにします。
5. 「設定を保存」をクリックします。

<Callout type="info" title="ヒント">

- 「通知方法」「受け取る通知」「詳細設定」は、下部の「設定を保存」でまとめて保存します。選択した通知方法の必須項目が空欄か、入力形式に誤りがある場合は、設定全体の保存に失敗します。同時に変更した他のスイッチの状態も保存されません。
- 選択した通知方法の入力内容のみが保存されます。通知方法を切り替えて保存すると、他の通知方法に入力した内容は消去されます。
- 管理者がサイトの残高不足通知を無効にすると、一般ユーザーの「設定」には「現在受け取れる通知はありません」と「詳細設定」のみが表示されます。
- 通知先にはサイトのサーバーからアクセスできる必要があります。内部ネットワークやローカルホストを指すアドレスは、サイトのセキュリティポリシーによってブロックされることがあります。送信に失敗してもページには表示されません。同じ種類の通知が短時間に何度も発生すると、一部の通知が送信されない場合があります。

</Callout>

<Callout type="warn" title="注意">
「価格未設定のモデルを許可」をオンにすると、管理者が価格を設定していないモデルを呼び出せるようになり、想定外に多くのクォータを消費する可能性があります。この項目はデフォルトでオフになっており、オンにすることは推奨されません。
</Callout>

**通知方法の説明**

スクリーンショットは、左上、右上、左下、右下の順に「メール」「Bark」「Gotify」「Webhook」を選択したときの入力項目を示しています。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 通知方法 | 入力項目 | 入力要件と制限 |
| --- | --- | --- |
| メール | 通知先メールアドレス | 任意です。プレースホルダーは「空欄の場合はアカウントのメールアドレスを使用」です。空欄の場合は、アカウントに登録されているメールアドレスに送信されます。メールアドレスが登録されていない場合は送信されません。形式に誤りがある場合は「無効なメールアドレス」と表示されます。 |
| Webhook | Webhook URL、Webhook シークレット | 「Webhook URL」は必須です。`https://example.com/webhook` のような有効な URL を入力します。空欄の場合は「Webhook URL を入力してください」、形式に誤りがある場合は「無効な Webhook URL」と表示されます。「Webhook シークレット」は任意です。入力すると各通知に署名が付与され、受信側で送信元を検証できます。通知の内容は JSON 形式です。 |
| Bark | Bark プッシュ URL | 必須です。http:// または https:// で始まる URL を入力します。テンプレート変数 `{{title}}` と `{{content}}` を使用でき、送信時に通知のタイトルと本文に置き換わります。空欄の場合は「Bark プッシュ URL を入力してください」、形式に誤りがある場合は「無効な Bark プッシュ URL」と表示されます。 |
| Gotify | Gotify サーバー URL、Gotify アプリトークン、メッセージの優先度 | 「Gotify サーバー URL」は必須です。http:// または https:// で始まる URL を入力します。空欄の場合は「Gotify サーバー URL を入力してください」と表示されます。「Gotify アプリトークン」は必須です。Gotify サーバーでアプリを作成してからトークンをコピーします。空欄の場合は「Gotify トークンを入力してください」と表示されます。「メッセージの優先度」は 0（最低）～10（最高）で、範囲外の値は 5 として保存されます。入力した数値が保存後の優先度として使われるため、必要に応じて設定してください。下部の「設定手順」には 3 つの手順と「Gotify ドキュメント」へのリンクが表示されます。 |
</div>

**設定項目の説明**

「設定」は「通知方法」「受け取る通知」「詳細設定」の 3 つに分かれています。通知方法ごとの入力項目は上の表をご覧ください。以下の表は、画面での表示順に並んでいます。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 設定項目 | セクション | 定義 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- | --- |
| 通知方法 | 通知方法 | 通知を受け取る方法。 | 「メール」「Webhook」「Bark」「Gotify」のいずれかを選択します。管理者がサイトの残高不足通知を無効にすると、一般ユーザーには表示されません。 | 「メール」 |
| 残高不足の通知 | 受け取る通知 | 残高がしきい値を下回ったときに通知するかどうか。 | 説明には「残高がしきい値を下回ったときに一度通知する」と表示されます。ウォレット残高とサブスクリプションの残りクォータは個別に判定されます。1 回の引き落としで残高がしきい値を上回る状態から下回る状態になったときに一度だけ通知されます。再び通知を受けるには、しきい値を上回るまでチャージする必要があります。管理者がサイトの残高不足通知を無効にしている場合は表示されません。 | オン |
| 通知しきい値 (…) | 受け取る通知 | 残高不足の通知を送信する基準となる残高。括弧内には「通知しきい値 (USD)」のようにサイトのクォータ単位が表示されます。 | 「残高不足の通知」がオンの場合に表示されます。負の値は指定できません。入力すると「通知しきい値に負の値は指定できません」と表示されます。空欄または 0 の場合はサイトのデフォルト値が使われます。入力欄の下には「空欄の場合はシステムのデフォルト値（…）を使用」と表示されます。 | 空欄。サイトのデフォルト値（初期値は $0.002）を使用します。 |
| チャネル通知（管理者のみ表示） | 受け取る通知 | チャネルが自動的に無効化または再有効化されたとき、あるいは全チャネルのテストが完了したときに通知するかどうか。 | 管理者がサイトの残高不足通知を無効にしていても表示されます。 | Root はオン、その他の管理者はオフ |
| 上流モデルの更新（管理者のみ表示） | 受け取る通知 | 定期的なモデルチェックで上流モデルの変更が検出されたとき、またはチェックに失敗したときに、結果をまとめて通知するかどうか。 | 管理者がサイトの残高不足通知を無効にしていても表示されます。 | オフ |
| 価格未設定のモデルを許可 | 詳細設定 | 管理者が価格を設定していないモデルの呼び出しを許可するかどうか。 | 説明には「価格が設定されていないモデルの使用を許可する」と表示されます。オフの状態で該当するモデルを呼び出すと、「モデル … の価格は管理者によってまだ設定されていません…」と表示されます。 | オフ |
</div>

## 表示言語を設定する

**操作手順**

1. 「言語設定」の「表示言語」ドロップダウンをクリックします。
2. 使用する言語を選択します。

<Callout type="info" title="ヒント">

- 選択すると設定がすぐに保存され、表示言語が切り替わります。保存ボタンをクリックする必要はありません。「言語設定を保存しました」と表示され、同じアカウントでログインしているすべてのデバイスに設定が同期されます。
- 簡体字中国語、English、Français、Русский、日本語、Tiếng Việt、繁體中文から選択できます。
- API が返すエラーメッセージは、簡体字中国語、繁体字中国語、英語の 3 言語に対応しています。その他の言語を選択した場合は英語で表示されます。

</Callout>

## 毎日のチェックインでクォータを受け取る

**操作手順**

1. 「毎日チェックイン」で「今すぐチェックイン」をクリックします。
2. サイトで人間かどうかの確認が有効になっている場合は、表示される「セキュリティ認証」ウィンドウで確認を完了します。
3. カレンダーでチェックイン済みの日付と獲得したクォータを確認します。

<Callout type="info" title="ヒント">

- 管理者がチェックイン機能を有効にした場合にのみ表示されます。詳しくは<a href="/ja/docs/guide/feature-guide/system-settings/settings-billing#チェックイン報酬" target="_blank" rel="noopener noreferrer">課金と支払いの設定</a>をご覧ください。
- チェックインは、サーバーの日付を基準に 1 日 1 回まで行えます。報酬は管理者が設定した範囲内でランダムに決まり、「現在の残高」に直接加算されます。使用ログには「システム」タイプの記録が 1 件追加されます。
- 当日のチェックインが済んでいる場合、ボタンは「チェックイン済み」と表示され、グレーアウトします。タイトルの横には「チェックイン済み」と「今日 +…」が表示されます。セクションはデフォルトで折りたたまれており、タイトルをクリックすると展開できます。

</Callout>

**項目の説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 項目 | 定義 | 入力要件と制限 | 備考 |
| --- | --- | --- | --- |
| 累計チェックイン | これまでのチェックイン回数の合計。 | システムが自動集計します。 | — |
| 月間獲得クォータ | カレンダーに表示されている月に獲得した報酬の合計。 | システムが自動集計します。 | 表示する月を切り替えると値も変わります。 |
| 累計獲得クォータ | これまでに獲得した報酬の合計。 | システムが自動集計します。 | — |
| カレンダー | 日ごとのチェックイン状況。 | 左右の矢印をクリックして月を切り替えます。 | 今日の日付は強調表示されます。チェックイン済みの日付の下には緑色の点が表示され、マウスカーソルを合わせると「チェックイン済み」と獲得したクォータが表示されます。 |
</div>

## 左サイドバーに表示するページを設定する

**操作手順**

1. 「左サイドバーの個人設定」で、セクションスイッチとモジュールスイッチをオンまたはオフにします。
2. 「変更を保存」をクリックします。

<Callout type="info" title="ヒント">

- サイドバーの表示は、管理者の設定と個人設定の 2 段階で決まります。個人設定にスイッチが表示されるのは、管理者が有効にしたセクションとページのみです。個人設定では、それらをさらに非表示にできます。詳しくは<a href="/ja/docs/guide/feature-guide/system-settings/settings-site#サイドバーモジュール" target="_blank" rel="noopener noreferrer">サイトとブランドの設定</a>をご覧ください。
- セクションスイッチをオフにすると、配下のモジュールスイッチがグレーアウトします。保存すると、そのセクションのページはすべて非表示になります。
- 「デフォルトに戻す」をクリックすると、すべてのスイッチがオンに戻ります。適用するには「変更を保存」をクリックします。
- 変更されるのはサイドバーのリンクの表示のみです。権限の付与や取り消しは行われません。ページ右上のアバターメニューにある「プロフィール」は常に表示されます。
- Root アカウントにはこのセクションが表示されません。サイドバーの表示は管理者のシステム設定で決まります。

</Callout>

**設定項目の説明**

以下の表は、画面での表示順に並んでいます。管理者が無効にしたセクションやページは、このセクションには表示されません。

| セクションスイッチ | モジュールスイッチ | 表示を制御する項目 | デフォルト値 |
| --- | --- | --- | --- |
| チャットセクション | プレイグラウンド | サイドバーの「チャット」グループにある「プレイグラウンド」 | オン |
| チャットセクション | チャット | サイドバーの「チャット」グループにある「チャット」 | オン |
| コンソールセクション | ダッシュボード | サイドバーの「一般」グループにある「概要」と「ダッシュボード」 | オン |
| コンソールセクション | トークン管理 | 「API キー」 | オン |
| コンソールセクション | 使用ログ | 「使用ログ」 | オン |

| 個人センターセクション | ウォレット管理 | サイドバーの「個人」グループとアバターメニューにある「ウォレット」 | オン |

## よくある質問

<Accordion title="残高不足の通知が届かない">

**考えられる原因**

- 管理者がサイトの残高不足通知を無効にしているか、アカウントの「残高不足の通知」がオフになっています。
- 残高がすでにしきい値を下回っています。通知は、残高がしきい値を下回った時点で一度だけ送信されます。再び通知を受けるには、しきい値を上回るまでチャージする必要があります。
- 「メール」を選択していますが、「通知先メールアドレス」が空欄で、アカウントにもメールアドレスが登録されていません。
- サイトのサーバーから通知先にアクセスできないか、サイトのセキュリティポリシーによってアクセスがブロックされています。
- 同じ種類の通知が短時間に何度も発生し、一部の通知が送信されなかったか、メールが迷惑メールに振り分けられています。

**対処方法**

1. 「残高不足の通知」がオンになっていることを確認し、「通知しきい値 (…)」を確認します。
2. 「メール」を選択した場合は、「通知先メールアドレス」を入力するか、<a href="/ja/docs/guide/feature-guide/user/security" target="_blank" rel="noopener noreferrer">セキュリティとアクセス</a>ページでメールアドレスを登録します。
3. Webhook、Bark、Gotify の通知先にインターネットからアクセスできることを確認するか、別の通知方法を選択して保存します。
4. それでも通知が届かない場合は、管理者にサイトの通知設定の確認を依頼してください。

</Accordion>

<Accordion title="「設定」に「現在受け取れる通知はありません」とだけ表示される">

**考えられる原因**

**対処方法**

<Accordion title="設定の保存時に「Webhook URL を入力してください」などのエラーが表示される">

**説明**  
表示されたメッセージに応じて、原因を確認してください。

| 表示メッセージ | 考えられる原因 | 対処方法 |
| --- | --- | --- |
| 「Webhook URL を入力してください」（英語 Webhook URL cannot be empty）<br/>「無効な Webhook URL」（英語 Invalid Webhook URL） | Webhook を選択したときに URL を入力していないか、URL の形式に誤りがあります。 | 完全な URL を入力します。 |
| 「Bark プッシュ URL を入力してください」（英語 Bark push URL cannot be empty）<br/>「無効な Bark プッシュ URL」（英語 Invalid Bark push URL） | Bark プッシュ URL が空欄か、形式に誤りがあります。 | http:// または https:// で始まる完全な URL を入力します。 |
| 「Gotify サーバー URL を入力してください」（英語 Gotify server URL cannot be empty）<br/>「無効な Gotify サーバー URL」（英語 Invalid Gotify server URL）<br/>「Gotify トークンを入力してください」（英語 Gotify token cannot be empty） | Gotify サーバー URL またはアプリトークンが未入力か、形式に誤りがあります。 | サーバー URL とアプリトークンを正しく入力します。 |
| 「URL は http:// または https:// で始める必要があります」（英語 URL must start with http:// or https://） | URL に http:// または https:// がありません。 | URL の先頭に https:// を追加します。 |
| 「無効なメールアドレス」（英語 Invalid email address） | 「通知先メールアドレス」の形式に誤りがあります。 | メールアドレスを修正するか、空欄にしてアカウントのメールアドレスを使用します。 |
| 「通知しきい値に負の値は指定できません」（英語 Reminder threshold cannot be negative） | しきい値が負の値です。 | 0 または正の値を入力するか、空欄にします。 |
| 「設定を更新できませんでした」（英語 Failed to update settings） | ネットワークが切断されたか、ログインセッションの有効期限が切れています。 | ページを再読み込みしてから再試行します。 |

<Accordion title="チェックイン時に「本日はチェックイン済みです」などのエラーが表示される">

**説明**  
表示されたメッセージに応じて、原因を確認してください。

| 表示メッセージ | 考えられる原因 | 対処方法 |
| --- | --- | --- |
| 「本日はチェックイン済みです」（英語 Already checked in today） | サーバーの日付を基準に、本日はすでにチェックインしています。 | 翌日にチェックインします。 |
| 「チェックイン機能が有効になっていません」（英語 Check-in feature is not enabled） | 管理者がチェックイン機能を無効にしています。 | ページを再読み込みします。チェックイン機能が必要な場合は、管理者にお問い合わせください。 |
| 「Turnstile トークンが空です」（英語 Turnstile token is empty） | サイトで人間かどうかを確認する機能が正しく設定されていません。 | 管理者にお問い合わせください。 |
| 「Turnstile の検証に失敗しました。ページを再読み込みして再試行してください！」（英語 Turnstile verification failed, please refresh and try again!） | 人間かどうかの確認を通過できませんでした。 | ページを再読み込みしてからチェックインをやり直します。 |
| 「チェックインに失敗しました。しばらくしてから再試行してください」（英語 Check-in failed, please try again later）<br/>「チェックインに失敗しました」（英語 Check-in failed） | ネットワークが切断されたか、サーバーでエラーが発生しました。 | しばらくしてから再試行します。 |

</Accordion>

<Accordion title="チェックインが成功しても残高がすぐに変わらない">

**説明**  
報酬はすでに残高に加算されています。画面の残高に反映されるまで、少し時間がかかる場合があります。

**対処方法**

1. ページを再読み込みし、「現在の残高」を確認します。
2. <a href="/ja/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">使用ログ</a>でタイプに「システム」を選択し、チェックインの記録を確認します。

</Accordion>

<Accordion title="サイドバーからページが消えた">

**考えられる原因**

- 「左サイドバーの個人設定」で、該当するモジュールまたはセクションをオフにして保存しています。
- 管理者がシステム設定でそのページを非表示にしています。
- 「画像生成ログ」と「タスクログ」の両方をオフにすると、サイドバーに「タスクログ」が表示されなくなります。片方だけをオフにすると、ページ内の該当するタブが非表示になります。

**対処方法**

1. 「左サイドバーの個人設定」で該当するセクションとモジュールをオンにし、「変更を保存」をクリックします。「デフォルトに戻す」をクリックしてから「変更を保存」をクリックすることもできます。
2. サイドバーに「プロフィール」がない場合は、ページ右上のアバターをクリックし、「プロフィール」を選択してこのページを開きます。
3. 該当するスイッチが表示されない場合や、スイッチがオンでもページが表示されない場合は、管理者がそのページを非表示にしています。管理者にお問い合わせください。

</Accordion>

<Accordion title="表示言語を切り替えても API のエラーメッセージが英語のままになっている">

**説明**  
API が返すエラーメッセージは、簡体字中国語、繁体字中国語、英語の 3 言語に対応しています。その他の表示言語を選択した場合は英語で表示されます。

**対処方法**

1. 中国語のエラーメッセージが必要な場合は、「表示言語」で「简体中文」または「繁體中文」を選択します。

</Accordion>

<Accordion title="モデルを呼び出すと「モデル … の価格は管理者によってまだ設定されていません…」と表示される">

**表示メッセージ**  
「モデル … の価格は管理者によってまだ設定されていないため、現在は利用できません。このモデルを有効にするには、サイト管理者にお問い合わせください」（英語 Model … has not been priced by the administrator yet. Please contact the site administrator to enable this model.）

**考えられる原因**  
管理者がそのモデルの価格を設定しておらず、アカウントの「価格未設定のモデルを許可」もオフになっています。

**対処方法**

1. 管理者に、そのモデルの価格設定を依頼します。
2. すぐに使用する必要がある場合は、「詳細設定」で「価格未設定のモデルを許可」をオンにし、「設定を保存」をクリックします。想定外に多くのクォータを消費する可能性があるため、ご注意ください。

</Accordion>

<Accordion title="表示名、ユーザー名、メールアドレス、グループを変更する方法">

**説明**  
表示名、ユーザー名、グループはこのページでは変更できません。メールアドレスの登録や変更は「セキュリティとアクセス」ページで行います。

**対処方法**

1. メールアドレスを登録または変更するには、<a href="/ja/docs/guide/feature-guide/user/security" target="_blank" rel="noopener noreferrer">セキュリティとアクセス</a>を開き、「アカウント連携」で操作します。
2. 表示名、ユーザー名、グループを変更する場合は、管理者にお問い合わせください。

</Accordion>

<Accordion title="ページに「左サイドバーの個人設定」が表示されない">

**説明**  
Root アカウントにはこのセクションが表示されません。サイドバーの表示は管理者のシステム設定で決まります。その他のアカウントにはこのセクションが表示されます。

</Accordion>
