- このページでは、すべての設定領域に共通する保存、反映、機密設定、変更時の検証に関するルールを説明します。個々の項目については、該当する設定領域のドキュメントを参照してください。

## アクセス方法と権限

Root のみが以下の 3 か所からシステム設定にアクセスできます。いずれも「サイトとブランド › システム情報」が開きます。

1. サイドバーの「管理者」グループの末尾にある「システム設定」。
2. 右上のアバターメニューにある「システム設定」。
3. トップバーの「検索」またはショートカットキー ⌘/Ctrl+K で開くコマンドパレット。サイドバーと同じページが一覧に表示されます。

価格設定が未処理のモデルがある場合は、サイドバーの「システム設定」、左側ナビゲーションの「課金と支払い」、およびその中の「モデル料金」セクションに、未処理のモデル数が表示されます。

項目ごとに保存する場合は、変更したフィールドのみが個別に送信され、フィールドごとに「設定を更新しました」と表示されます。いずれかのフィールドで保存に失敗すると、後続のフィールドは送信されず、保存済みのフィールドはロールバックされません。変更がない場合、「保存する変更はありません」というメッセージが表示されるかどうかはセクションによって異なります。

<Callout type="info" title="ヒント">

- 「設定を更新しました」「保存しました」などのメッセージは、サーバーが保存リクエストを受け付けたことを示します。OAuth、SMTP、決済ゲートウェイ、Webhook、Worker などの外部サービスへの接続は別途確認してください。

</Callout>

### 反映範囲と複数インスタンス間の同期

1. 設定はキーと値の形式でメインデータベースに保存されます。保存リクエストを処理したノードは、データベースへの書き込み直後にメモリ上の値を更新します。再起動は不要です。
2. 保存後、他のノードは約 3 秒以内にデータベースから設定を再読み込みします。保存ごとに同期タスクが 1 件登録され、各ノードは約 3 秒ごとに確認し、新しい変更を検出すると設定を再読み込みします。リクエストポリシー、モデル料金、パスキーのドメインなど、専用の保存方法で書き込まれた設定も対象です。各設定領域のページでは、この仕組みを「システム設定の同期により約 3 秒以内に反映（遅くとも 1 同期周期以内、デフォルトは 60 秒）」と表記しています。
   - 各ノードは予備の仕組みとして、`SYNC_FREQUENCY` 秒ごと（デフォルトは 60 秒）にすべての設定を再読み込みします。同期タスクの書き込みに失敗した場合や、クラスター内に未アップグレードで同期タスクを確認しない旧バージョンのノードがある場合は、次の周期で変更が読み込まれます。
   - `SYNC_FREQUENCY` は秒単位の環境変数です。画面に対応する設定項目はありません。起動時にのみ読み込まれるため、変更後は再起動が必要です。
   - この同期は Redis の有効・無効にかかわらず動作します。すべてのノードが同じメインデータベースに接続している必要があります。
   - 読み込みが完了するまで、ノードによって参照する値が異なる場合があります。各ノードの読み込み状況は、<a href="/ja/docs/guide/feature-guide/admin/system-info#ノード同期" target="_blank" rel="noopener noreferrer">システム情報</a>のインスタンス一覧にある「同期」列で確認できます。読み込みに失敗したノードの「同期」列には「更新に失敗しました」と表示され、そのノードは次回の確認時に再試行します。
3. Master インスタンスと Worker インスタンス（`NODE_TYPE`）は、設定の保存と同期で同じように動作します。どのノードからでも保存できます。

「認証 › カスタム OAuth」で追加、編集、削除を行った場合も同期タスクが登録され、他のノードは約 3 秒以内に自動で変更を読み込みます。再起動は不要です。定期的な再読み込みによる予備の仕組みがないため、クラスター内の未アップグレードの旧バージョンのノードでは、再起動後に変更が読み込まれます。

以下の変更を反映するには再起動が必要です。

1. 「リクエストポリシー › セッションとリトライ」の「キャッシュするセッションの最大数」を変更した場合は、再起動が必要です（Redis を使用している場合は対象外です）。詳細は<a href="/ja/docs/guide/feature-guide/system-settings/settings-request-policies#保存と反映" target="_blank" rel="noopener noreferrer">リクエストポリシーの設定</a>を参照してください。
2. デプロイ時に指定する環境変数は起動時にのみ読み込まれます。変更後は再起動が必要で、画面にも表示されません。`SYNC_FREQUENCY`、`NODE_TYPE`、および `GLOBAL_API_RATE_LIMIT` などのグローバルなレート制限用の変数が該当します。
   - `CHANNEL_TEST_FREQUENCY` や `CHANNEL_TEST_ENABLED` など、一部の環境変数は画面で設定した値を上書きします。詳細は<a href="/ja/docs/guide/feature-guide/system-settings/settings-request-policies#チャネルのヘルス" target="_blank" rel="noopener noreferrer">チャネルの稼働状態</a>を参照してください。

### フロントエンドの表示とキャッシュ

1. ログイン方法、システム名、ロゴ、フッター、上部ナビゲーション、サイドバーモジュール、クォータの表示形式、コンソールパネルなどの画面表示には、サイトの状態情報が使われます。サーバーはリクエストごとに、処理を担当するノードのメモリ上の設定に基づいて応答します。ブラウザーは取得した情報をキャッシュし、5 分間は再取得を行いません。ページを再読み込みすると再取得します。通知センターに表示されるシステムのお知らせには、同じ動作をする別のキャッシュがあります。
2. 保存操作を行ったブラウザーでは、上部ナビゲーション、サイドバーモジュール、クォータと通貨の表示、サーバーアドレス、パスキー、カスタム OAuth など、一部の表示関連設定のみが自動で更新されます。その他の設定や、他のユーザーがすでに開いているページでは、ページを再読み込みすると新しい値が表示されます。
3. サーバーはブラウザーキャッシュに依存せず、保存後の設定に従ってリクエストを処理します。すでに開いているページには以前のメニュー項目やフォームが表示される場合がありますが、再読み込みすると現在の設定に一致します。

## 機密設定と監査記録

**機密設定**

- 設定キー名が `Token`、`Secret`、`Key`、`secret`、`api_key`、`private_key` のいずれかで終わる設定は、設定取得 API の応答から項目ごと除外されます。主に各種キー、トークン、認証情報のフィールドが対象です。そのため、画面ではマスクされた値が表示されることもなく、該当フィールドは常に空欄です。
- 通常、空欄のままにすると保存済みの値が維持され、新しい値を入力した場合のみ送信されます。一部のフィールドには「既存のキーを維持するには空欄のままにしてください」「既存の認証情報を維持するには空欄のままにしてください」「キーをローテーションする場合を除き、空欄のままにしてください」と表示されます。「運用管理 › Worker プロキシ」で「Worker URL」を空欄にして保存すると、「Worker アクセスキー」も消去されます。カスタム OAuth のクライアントシークレットも画面には表示されず、編集時に空欄のままにすると既存の値が維持されます。
- 設定値はデータベースに平文で保存されます。データベースとバックアップは同等に保護してください。

**監査記録**

- 項目ごとの保存に成功すると、フィールドごとに「システム設定の変更」と設定キー名を含む監査ログが 1 件記録されます。設定値は記録されません。
- 専用の保存方法を使う設定では、記録する内容が異なります。リクエストポリシーではリクエストのメソッドとパスのみ、モデル料金では変更したモデル名、パスキーのドメイン設定（「システム情報」の「サーバーアドレス」を含む）では削除したドメインと影響を受ける認証情報の件数、カスタム OAuth では追加、編集、削除の操作種別のみを記録します。
- 保存に失敗したリクエストも記録されますが、設定キー名は含まれません。
- <a href="/ja/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">監査ログ</a>は、サイドバーの「一般 › 監査ログ」にあります。Root の操作記録を閲覧できるのは Root のみです。
- 監査ログには変更前の値が保存されないため、設定の復元には使えません。キーの管理と変更の記録は、外部の仕組みで別途行ってください。

<Callout type="warn" title="キーの取り扱いに注意">

クライアントシークレット、SMTP トークン、決済キーなどの機密値をスクリーンショット、チケット、通常のログに記録しないでください。設定取得 API では平文の値を返さない仕様ですが、ブラウザー、プロキシ、データベースのバックアップ、運用環境でも認証情報を保護してください。

</Callout>

## 変更前の記録と検証

システム設定には、設定スナップショット、過去のバージョンとの比較、ワンクリックでのロールバック機能がありません。本番環境で変更する前に元の値を記録し、元の設定を項目ごとに復元できるようにしてください。少なくとも以下を記録することを推奨します。

- 変更する設定領域、セクション、フィールド
- 変更前の機密性のない値と、キー管理システム上の機密認証情報のバージョン
- 影響が見込まれるページ、API、ロール、外部サービス
- テスト手順、合格基準、復元を行う条件
- 複数インスタンス環境で同期を待つ時間と、再起動が必要な項目

保存後は、以下の手順で検証してください。

1. メッセージを確認します。項目ごとの保存では、変更したフィールドごとに「設定を更新しました」と表示されます。失敗のメッセージが表示された場合、失敗したフィールドとそれ以降のフィールドは保存されていません。
2. ページを再読み込みし、機密性のないフィールドの値を照合します。機密フィールドは常に空欄なので、再読み込みでは確認できません。複数インスタンス構成では、重要な変更は他のノードが読み込んだ後にページを再読み込みして確認します。
3. 実際に影響を受ける機能で動作を確認します。対象にはログイン、メール送信、決済サンドボックス、コールバック、モデルへのリクエストなどが含まれます。
4. 複数インスタンス構成では、<a href="/ja/docs/guide/feature-guide/admin/system-info#ノード同期" target="_blank" rel="noopener noreferrer">システム情報</a>のインスタンス一覧にある「同期」列で、各ノードが変更を読み込んだことを確認してから、他のノードで動作を検証します。
5. 認証、決済、課金、リクエストポリシー、SSRF、外部へのコールバックに関わる変更は、テスト用インスタンスまたはメンテナンス時間帯で先に検証してください。

## 注意事項

- **項目ごとの保存ではロールバックされません**。複数のフィールドを一度に保存する場合、先に処理されたフィールドはすでに書き込まれています。いずれかのフィールドで保存に失敗すると、後続のフィールドは送信されません。[保存方法](#保存方法)を参照してください。
- **複数ノード間の同期には遅延があり、一部の項目には再起動が必要です**。他のノードには、システム設定の同期により約 3 秒以内に反映されます（遅くとも 1 同期周期以内、デフォルトは 60 秒）。「キャッシュするセッションの最大数」や環境変数を変更した場合は再起動が必要です。[反映範囲と複数インスタンス間の同期](#反映範囲と複数インスタンス間の同期)を参照してください。
- **表示関連の設定はページの再読み込みが必要です**。ブラウザーはサイトの状態情報をキャッシュします。保存後、他のユーザーが開いているページでも、再読み込みすると新しい値が表示されます。[フロントエンドの表示とキャッシュ](#フロントエンドの表示とキャッシュ)を参照してください。
- **環境変数が画面の設定値を上書きする場合があります**。`CHANNEL_TEST_FREQUENCY` や `CHANNEL_TEST_ENABLED` などで上書きされている場合、画面で値を変更しても反映されないことがあります。
- **キーのフィールドに保存済みの値は表示されません**。空欄のまま保存すると既存の値が維持されます。「Worker URL」を空欄にして保存した場合は、「Worker アクセスキー」も消去されます。[機密設定と監査記録](#機密設定と監査記録)を参照してください。
- **設定のバージョン履歴はありません**。監査ログには変更前の値が保存されないため、設定の復元には使えません。変更前に元の値を記録してください。[変更前の記録と検証](#変更前の記録と検証)を参照してください。

<Accordion title="サイドバーに「システム設定」が見つからない">

**説明**

このメニュー項目が表示されるのは Root アカウントのみです。

**考えられる原因**

Root にも表示されない場合は、「サイトとブランド › サイドバーモジュール」の「管理者エリア」または「システム設定」のスイッチがオフになっています。

**対処方法**

1. アバターメニューから「システム設定」を開きます。

</Accordion>

<Accordion title="Admin が「設定へ移動」をクリックすると「アクセスが拒否されました」と表示される">

**表示メッセージ**

「アクセスが拒否されました」（英語では「Access Forbidden」）

**考えられる原因**

システム設定にアクセスできるのは Root のみです。

**対処方法**

1. Root に設定の変更を依頼してください。

</Accordion>

<Accordion title="一度の保存で「設定を更新しました」が複数回表示される">

**表示メッセージ**

「設定を更新しました」（英語では「Setting updated successfully」）

**説明**

項目ごとの保存では、変更したフィールドごとに 1 回ずつ表示されます。

</Accordion>

<Accordion title="保存後に一部のフィールドだけが反映される">

**考えられる原因**

いずれかのフィールドで保存に失敗すると、後続のフィールドは送信されません。

**対処方法**

1. エラーメッセージに従って修正し、再度保存します。
2. ページを再読み込みし、各フィールドを確認します。

</Accordion>

<Accordion title="保存をクリックしても何も表示されない">

**考えられる原因**

そのセクションでは変更が検出されていません。一部のセクションでは、変更がない場合にメッセージが表示されません。

**対処方法**

1. フィールドの値を変更したことを確認します。

</Accordion>

<Accordion title="複数のノードで一時的に動作が異なる">

**考えられる原因**

- いずれかのノードで読み込みに失敗し、システム情報のインスタンス一覧にある「同期」列に「更新に失敗しました」と表示されています。
- クラスター内に未アップグレードの旧バージョンのノードがあり、`SYNC_FREQUENCY` で指定した周期でのみ設定を読み込んでいます。カスタム OAuth の変更は再起動後に読み込まれます。
- すべてのノードが同じメインデータベースに接続していません。

**対処方法**

1. <a href="/ja/docs/guide/feature-guide/admin/system-info#同期状態" target="_blank" rel="noopener noreferrer">システム情報</a>のインスタンス一覧で「同期」列にカーソルを合わせ、失敗した項目とエラーを確認します。該当ノードのサーバーログも確認してください。
2. 1 同期周期（デフォルトは 60 秒）待ちます。サーバーログには、周期ごとに `syncing options from database` が 1 行出力されます（`DEFAULT_LANGUAGE=zh-CN` の場合は「正在从数据库同步配置项」）。
3. 旧バージョンのノードでカスタム OAuth の変更がまだ読み込まれていない場合は、そのノードを再起動します。

</Accordion>

<Accordion title="キーのフィールドが空欄になっている">

**説明**

機密設定の値が表示されないのは仕様です。空欄のままにすると、元の値が維持されます。

**対処方法**

1. キーを変更する場合は、新しい値を入力します。

</Accordion>

<Accordion title="保存後も外部サービスとの連携に失敗する">

**説明**

保存時に接続テストは行われません。

**考えられる原因**

公開アドレス、コールバック、DNS、証明書、ネットワーク、または認証情報の権限に問題がある可能性があります。

**対処方法**

1. サードパーティサービスのログを確認します。

</Accordion>

<Accordion title="以前の設定に戻す必要がある">

**説明**

システム設定には、過去のバージョンを復元する機能がありません。

**対処方法**

1. 変更前に記録した元の値を項目ごとに入力し直して保存します。

</Accordion>

</Accordions>
