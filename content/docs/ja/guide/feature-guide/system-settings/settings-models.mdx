<Callout type="info" title="ヒント">

</Callout>

## モデル設定の概要

「モデル」には 5 つのセクションがあり、左側のナビゲーションで切り替えられます。デフォルトでは「グローバルモデル設定」が開きます。

**各セクションの説明**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| セクション | 用途 | セクション内のタブ |
| --- | --- | --- |
| [グローバルモデル設定](#グローバルモデル設定) | リクエストのパススルー、思考サフィックスの処理除外、ChatCompletions の変換、ストリーミングのハートビート。 | — |
| [Gemini](#gemini) | Gemini/Vertex の変換時のデフォルト値と思考モードへの対応。 | — |
| [Claude](#claude) | Claude のリクエストヘッダーの上書き、デフォルトの出力上限、思考モードへの対応。 | — |
| [Grok](#grok) | 利用ポリシー違反に対する追加課金。 | — |
| [モデルデプロイ](#モデルデプロイ) | io.net のマネージドデプロイの有効化と認証情報の設定。 | — |

</div>

<Callout type="info" title="ヒント">

- 保存後にフィールドの値が変わらない場合、保存が拒否された場合、またはデプロイページで無効と表示される場合は、[よくある質問](#よくある質問)を参照してください。

</Callout>

## 設定セクション

左側のナビゲーションに表示される順に 5 つのセクションを説明します。各セクションの保存ボタンと設定が反映されるタイミングについては、[保存と反映](#保存と反映)を参照してください。

### グローバルモデル設定

- モデル-グローバルモデル設定

![グローバルモデル設定セクション](/assets/guide/feature-guide/system-settings-model-global-model-configuration.png)

セクション内のフィールドは区切り線で、リクエストのパススルーと思考サフィックス、「ChatCompletions → Responses 互換」（「プレビュー」ラベル付き）、接続維持用ハートビートの 3 つに分かれています。

**操作手順**

1. 必要に応じて「リクエストのパススルーを有効にする」をオンにします。
2. 「思考サフィックスを自動処理しないモデル」に、処理対象から除外するモデルを入力します。
3. 「ポリシー JSON」に変換ポリシーを入力します。「サンプルを入力（指定チャネル）」または「サンプルを入力（全チャネル）」をクリックして入力することもできます。
4. 必要に応じて「接続維持用ハートビート」をオンにし、「Ping 間隔（秒）」を入力します。
5. ページ上部の「変更を保存」をクリックします。

<Callout type="warn" title="注意">

- 「ChatCompletions → Responses 互換」は実験的な機能です。画面の「警告」には「この機能は実験的な機能です。設定形式や動作が変更される可能性があります。」と表示されます。
- グローバルのリクエストパススルー、または対象チャネルのリクエストボディのパススルーが有効な場合、この変換処理は実行されません。
- リクエストのパススルーが有効な場合、「形式変換前」と「送信前」の段階に設定されたインスタンスは実行されません。<a href="/ja/docs/guide/feature-guide/admin/request-processing" target="_blank" rel="noopener noreferrer">リクエスト処理</a>を参照してください。

</Callout>

**ポリシー JSON のフィールド**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| フィールド | 用途 |
| --- | --- |
| `enabled` | ポリシー全体のスイッチです。オフの場合、ほかのフィールドは適用されません。 |
| `all_channels` | `true` の場合、すべてのチャネルがマッチングの対象になります。 |
| `channel_ids` | `all_channels` が `false` の場合に、チャネル ID で照合します。いずれかの ID に一致すれば条件を満たします。 |
| `channel_types` | `all_channels` が `false` の場合に、チャネルタイプの番号で照合します。いずれかの番号に一致すれば条件を満たします。 |
| `model_patterns` | 正規表現の配列です。リクエストで指定されたモデルが少なくとも 1 つのパターンに一致すると、変換が行われます。 |

</div>

**設定項目**

以下の表は、セクション内の表示順に並んでいます。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap [&_td_code]:wrap-anywhere">

| 設定項目 | 説明 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| リクエストのパススルーを有効にする | リクエストを後処理せずに上流プロバイダーへ直接転送します。クライアントの元のリクエストボディをそのまま送信し、リクエストボディの変換、フィールドの削除、システムプロンプトのマージ、パラメーターの上書きなどをスキップします。 | スイッチ。 | オフ |
| 思考サフィックスを自動処理しないモデル | ここに記載したモデルでは、-thinking / -nothinking サフィックスの自動追加や削除を行いません。一致したモデルは、@ 修飾子の解析と HTTP 400 を返す検証の対象からも除外されます。 | JSON の文字列配列。re: で始まる項目は、Go の正規表現でモデル名全体と照合します（例 `re:.*@sha256:.*`）。形式が正しくない場合は「無効な JSON 形式」と表示されます。空欄のまま保存すると空の配列になります。 | `moonshotai/kimi-k2-thinking`、`kimi-k2-thinking` |
| ポリシー JSON | 「ChatCompletions → Responses 互換」の変換ポリシーです。チャネルとモデルの正規表現の両方の条件を満たす必要があります。各フィールドについては「ポリシー JSON のフィールド」を参照してください。 | JSON オブジェクト。空欄の場合は {} として保存されます。 | `{"enabled":false,"all_channels":true}` |
| 接続維持用ハートビート | ping フレームを定期的に送信し、ストリーミング接続を維持します。 | スイッチ。 | オフ |
| Ping 間隔（秒） | ハートビートの送信間隔です。 | `1` 以上。上流のレート制限にかかりにくくするため、間隔は長めに設定することを推奨します。「接続維持用ハートビート」がオフの間は編集できません。 | `60` |

</div>

### Gemini

- モデル-Gemini

![Gemini セクション](/assets/guide/feature-guide/system-settings-model-gemini.png)

Gemini セクションでは、Gemini および一部の Vertex の変換処理に使用するインスタンス単位のデフォルト動作を設定します。

**操作手順**

1. 必要に応じて、安全性設定、バージョンの上書き、対応 Imagine モデルを入力します。
2. 必要に応じて思考サフィックスアダプターをオンにし、トークン予算の比率を入力します。
3. 必要に応じて、FunctionCall に関する 2 つのスイッチをオンまたはオフにします。
4. ページ上部の「変更を保存」をクリックします。

<Callout type="info" title="ヒント">

- 「対応 Imagine モデル」を設定すると、変換時の出力モダリティのみが変わります。モデル、料金、チャネルの対応機能は自動で追加されません。モデルマッピング適用後の上流側のモデル名を入力してください。
- 思考サフィックスアダプターがオフの場合、「トークン予算の比率」の下に「アダプターを無効にしても、Gemini は引き続き思考モードを自動検出します。料金と予算をより細かく制御する必要がある場合にのみ、このオプションを有効にしてください。」と表示されます。

</Callout>

**変換時のデフォルト値**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 設定項目 | 説明 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| 安全性設定 | カテゴリ別の安全性設定を JSON 形式で上書きします。フォールバック値には `default` を使用します。 | 値が文字列の JSON マップ。しきい値はサーバー側で検証されます。指定可能な値については、[よくある質問](#よくある質問)を参照してください。 | `{"default":"OFF"}` |
| バージョンの上書き | モデル識別子を Gemini API のバージョンにマッピングします。一致するモデルがない場合は `default` の項目が適用されます。 | 値が文字列の JSON マップ。 | `{"default":"v1beta","gemini-1.0-pro":"v1"}` |
| 対応 Imagine モデル | Imagine API に対応するモデルの識別子を JSON 配列で指定します。 | JSON の文字列配列。 | 組み込みモデル 7 件 |

</div>

**思考モードと FunctionCall の設定項目**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 設定項目 | 説明 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| 思考サフィックスアダプター | `-thinking`、`-thinking-{{budget}}`、`-nothinking` や `-high` などの推論強度を指定するサフィックスに対応し、適切な Gemini バリアントへルーティングします。オフの場合は、モデル名をそのまま上流へ送信します。 | スイッチ。 | オフ |
| トークン予算の比率 | トークン予算 = 最大トークン数 × 比率。上流の課金方式に合わせることを推奨します。 | 0.002 以上 1 以下の小数。 | `0.6` |
| FunctionCall の思考シグネチャ補完を有効にする | OpenAI 形式を使用する Gemini/Vertex チャネルに限り、thoughtSignature を補完します。 | スイッチ。 | オン |
| functionResponse.id フィールドを削除する | Vertex AI は functionResponse.id フィールドに対応していません。オンにすると、このフィールドを自動で削除します。 | スイッチ。 | オン |

</div>

### Claude

- モデル-Claude

![Claude セクション](/assets/guide/feature-guide/system-settings-model-claude.png)

**操作手順**

1. 必要に応じて「リクエストヘッダーの上書き」と「デフォルトの最大トークン数」を入力します。
2. 必要に応じて思考サフィックスアダプターをオンにし、トークン予算の比率を入力します。
3. ページ上部の「変更を保存」をクリックします。

**設定項目**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 設定項目 | 説明 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| リクエストヘッダーの上書き | モデルごとのヘッダーの上書きを JSON 形式で指定します。コンテキストウィンドウの拡張など、試験的な機能の有効化に使用できます。一致したモデルの送信リクエストに適用し、元のリクエストにある同名のヘッダーとマージして重複を取り除きます。 | モデル名 → リクエストヘッダー → 値の配列の形式の JSON オブジェクト。 | `{}` |
| デフォルトの最大トークン数 | `max_tokens` が指定されていないか、0 の場合に適用されます。 | 値が非負整数の JSON オブジェクト。`default` の指定がない場合は 8192 が適用されます。入力例は `{ "default": 8192, "claude-3-haiku-20240307": 4096, "claude-3-opus-20240229": 4096, "claude-3-7-sonnet-20250219-thinking": 8192 }` です。 | `{"default":8192}` |
| 思考サフィックスアダプター | `-thinking`、`-nothinking` や `-high` などの推論強度を指定するサフィックスが付いたリクエストを、Anthropic ネイティブの思考モード用リクエストに変換し、課金額を予測しやすくします。オフの場合は、モデル名をそのまま上流へ送信します。 | スイッチ。 | オン |
| トークン予算の比率 | トークン予算 = 最大トークン数 × 比率。思考モードのトークン予算の推定に使用します。 | 0.1 以上 1 以下の小数。 | `0.8` |

</div>

### Grok

- モデル-Grok

![Grok セクション](/assets/guide/feature-guide/system-settings-model-grok.png)

**操作手順**

1. 「違反時の追加課金を有効にする」をオンまたはオフにします。
2. オンにする場合は「違反時の追加課金額」を入力します。
3. ページ上部の「変更を保存」をクリックします。

<Callout type="warn" title="注意">

- 上流から返されたエラーに、対応する違反マーカー（コンテンツが利用ポリシーに違反していることを示すメッセージなど）が含まれる場合にのみ、追加課金が発生します。
- 通常の上流エラー、コンテンツ審査の失敗、その他の Grok リクエストに対して、この設定による追加課金は発生しません。違反時の追加課金が発生したエラーはリトライされません。
- 実際の課金額は「基本額 × システムのグループ倍率」で換算され、「違反料金を徴収しました」という消費ログが別途 1 件記録されます。調査時は、元のリクエストのエラーとこのログの両方を確認してください。
- この設定により、ユーザーの残高から直接差し引かれます。有効化や金額の変更前に、上流の最新の違反料金ルール、グループ倍率、ユーザー向けの料金案内を確認してください。

</Callout>

**設定項目**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 設定項目 | 説明 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| 違反時の追加課金を有効にする | オンにすると、違反したリクエストに対して追加課金が発生します。説明の後にある「公式の説明」リンクから、x.ai の違反料金に関する説明を開けます。 | スイッチ。 | オン |
| 違反時の追加課金額 | 課金の基本額です。実際の課金額 = 基本額 × システムのグループ倍率。 | `0` 以上、0.01 刻み。「違反時の追加課金を有効にする」がオフの間は編集できません。 | `0.05` |

</div>

### モデルデプロイ

- モデル-モデルデプロイ

![モデルデプロイセクション](/assets/guide/feature-guide/system-settings-model-model-deployment.png)

現在、モデルデプロイ連携は io.net に対応しており、セクションのタイトルは「io.net デプロイ」です。このセクションで連携を有効にし、認証情報を設定します。デプロイリソースの作成は別途行います。スクリーンショットは「io.net デプロイを有効にする」をオンにした状態です。

**操作手順**

1. 「io.net デプロイを有効にする」をオンにして、キー設定欄を表示します。
2. 「io.net API キーのページへ」をクリックし、<a href="https://ai.io.net/ai/api-keys" target="_blank" rel="noopener noreferrer">io.net API キーページ</a>を開きます。
3. キーを作成または選択する際は、Project を `io.cloud` に設定します。
4. キーをコピーし、「io.net API キー」入力欄に貼り付けます。保存済みのキーを引き続き使用する場合は、入力欄を空欄のままにできます。
5. 「接続をテスト」をクリックします。
6. ページ上部の「io.net 設定を保存」をクリックします。

<Callout type="warn" title="注意">

- このセクションの連携スイッチをオフにしても、既存の io.net デプロイは終了せず、外部サービスの料金も停止しません。
- オフにすると、New API での既存デプロイの表示、延長、終了の操作も拒否されます。
- デプロイの作成、延長、終了は、外部サービスのリソースと料金に影響します。実行前に io.net のアカウント、リソース構成、請求内容を確認してください。
- New API は、外部サービスのリソース容量、請求内容、デプロイの成功率を保証しません。

</Callout>

**接続テスト**

- 入力欄のキーを使って接続をテストします。空欄の場合は保存済みのキーを使用します。この操作では設定を保存しません。
- 成功すると「接続成功」「io.net サービスに正常に接続しました。」と表示されます。
- 失敗すると「接続失敗」とエラー情報が表示されます。キー、プロジェクト、ネットワーク接続を確認してください。
- 保存済みのキーは入力欄に再表示されません。設定済みの場合も入力欄は空欄です。

**設定項目**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 設定項目 | 説明 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| io.net デプロイを有効にする | コンソールで io.net のモデルデプロイサービスを有効にします。 | スイッチ。オンにすると、キーの入力欄、「接続をテスト」、「io.net API キーの取得方法」が表示されます。デプロイサービスを使用するには、オンにした状態と有効なキーの両方を保存する必要があります。 | オフ |
| io.net API キー | io.net デプロイ API の認証に使用します。 | 初回設定時は必須です。保存済みのキーは入力欄に再表示されません。 | 空欄 |

</div>

## 保存と反映

保存方法は <a href="/ja/docs/guide/feature-guide/system-settings/system-setting#保存方法" target="_blank" rel="noopener noreferrer">システム設定の概要</a>を、設定の反映と複数インスタンス間の同期ルールは <a href="/ja/docs/guide/feature-guide/system-settings/system-setting#反映範囲と複数インスタンス間の同期" target="_blank" rel="noopener noreferrer">適用範囲と複数インスタンス間の同期</a>を参照してください。特に記載がない限り、保存リクエストを処理したノードでは新しい値が直ちに適用され、ほかのノードにはシステム設定の同期によって約 3 秒以内（遅くとも 1 同期周期以内。デフォルトは 60 秒）に反映されます。同期周期は環境変数 `SYNC_FREQUENCY` で秒単位で設定できます。デフォルトは 60 秒です。変更後は New API の再起動が必要です。各設定項目で新しい値が読み込まれるタイミングは以下のとおりです。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 設定項目 | 保存方法 | 反映タイミング |
| --- | --- | --- |
| グローバルモデル設定 › リクエストのパススルーを有効にする、思考サフィックスを自動処理しないモデル、ポリシー JSON | ページ上部の「変更を保存」 | 次のリクエストから適用されます。 |
| Gemini、Claude › すべてのフィールド | ページ上部の「変更を保存」 | 次のリクエストから適用されます。 |
| グローバルモデル設定 › 接続維持用ハートビート、Ping 間隔（秒） | ページ上部の「変更を保存」 | ストリーミングレスポンスの開始時に読み込まれ、新しいストリーミングリクエストから適用されます。進行中のストリームには従来の設定が引き続き適用されます。 |
| Grok › 違反時の追加課金のスイッチと金額 | ページ上部の「変更を保存」 | 次に違反マーカーが検出され、課金が必要になった時点で、新しい設定に従って計算します。 |
| モデルデプロイ › io.net デプロイを有効にする、io.net API キー | 「io.net 設定を保存」 | 次にデプロイを表示、作成、延長、終了する際に、新しい値に基づいて操作の可否が決まります。オフにするとこれらの操作は拒否され、既存のデプロイは稼働を続けます。 |
| モデルデプロイ › 接続をテスト | 設定の保存なし | 入力欄のキーを使ってテストします。空欄の場合は保存済みのキーを使用します。 |

</div>

**補足**

- **項目ごとの保存**。「変更を保存」と「io.net 設定を保存」は、変更のあった項目だけを送信します。保存に成功するたびに、項目ごとに「設定を更新しました」と表示されます。変更がない場合は「保存する変更はありません」と表示されます。
- **検証**。ページ上で JSON フィールドの形式を検証します。サーバー側ではさらに、Gemini の「安全性設定」のしきい値が許可された値であることと、Claude の「デフォルトの最大トークン数」が非負であることを検証します。検証に失敗すると、該当フィールドとそれ以降のフィールドは保存されません。エラーメッセージについては、[よくある質問](#よくある質問)を参照してください。

## 注意事項

- **Grok の違反料金はユーザーの残高から直接差し引かれます**。[Grok](#grok)を参照してください。
- **io.net デプロイを無効にしても、既存のデプロイは終了しません**。外部サービスの料金も停止しません。[モデルデプロイ](#モデルデプロイ)を参照してください。
- **保存できても、上流が設定を受け付けるとは限りません**。上記の 2 項目以外について、上流が設定を受け付けるかどうかは、実際にリクエストを送信した時点で確認できます。
- **リクエストのパススルーは変換処理をスキップします**。グローバルまたはチャネル単位でリクエストボディのパススルーが有効な場合、ChatCompletions の変換やパラメーターの上書きなどは適用されません。[グローバルモデル設定](#グローバルモデル設定)を参照してください。

<Accordion title="保存後もフィールドの値が変わらない">

**考えられる原因**

- 別のセクションの保存ボタンをクリックした。
- 保存時にエラーが表示された。項目ごとの保存で失敗した項目は自動でリトライされません。

</Accordion>

<Accordion title="正規表現を指定しても一致しない">

「思考サフィックスを自動処理しないモデル」に指定する正規表現は、`re:` で始め、モデル名全体と照合する必要があります。無効な正規表現は、実行時にのみシステムエラーとして記録されます。

</Accordion>

<Accordion title="パススルーを有効にすると変換ポリシーが適用されない">

グローバルまたはチャネル単位のリクエストパススルーでは、変換処理がスキップされます。

</Accordion>

<Accordion title="max_tokens を指定していない Claude リクエストが上流で拒否される">

**考えられる原因**

「デフォルトの最大トークン数」の値が、上流の出力上限を超えています。

</Accordion>

<Accordion title="Grok で追加課金が発生する">

**考えられる原因**

元のリクエストのエラーに違反マーカーが含まれています。

**対処方法**

1. 利用ログで「違反料金を徴収しました」と記録されている項目を確認し、グループ倍率を照合します。

</Accordion>

<Accordion title="デプロイページにサービスが無効、または接続に失敗したと表示される">

**表示メッセージ**

「モデルデプロイサービスが無効です」（英語では Model deployment service is disabled）または「接続失敗」（英語では Connection failed）

**考えられる原因**

- 「モデルデプロイサービスが無効です」と表示される場合は、「io.net デプロイを有効にする」をオンにした状態が保存されていません。
- 「接続失敗」と表示される場合は、スイッチはオンですが、接続テストに失敗しています。有効な API キーが保存されていない場合などに発生します。

**対処方法**

1. 「io.net デプロイを有効にする」をオンにし、有効な API キーを保存します。両方の設定を保存する必要があります。

</Accordion>

<Accordion title="作成済みのデプロイがモデルリクエストに使用されない">

デプロイを作成しても、チャネルは自動で作成も関連付けもされません。

**対処方法**

1. エンドポイントを手動で設定します。

</Accordion>

<Accordion title="安全性設定やデフォルトの最大トークン数の保存が拒否される">

**表示メッセージ**

`invalid Gemini safety threshold "…" for "…"`、`negative Claude default max_tokens … for "…"`、`Claude default max tokens must be a JSON map of model to integer: …` など（英語のみ）

**考えられる原因**

- Gemini の「安全性設定」で、いずれかのカテゴリのしきい値が `OFF`、`BLOCK_NONE`、`BLOCK_ONLY_HIGH`、`BLOCK_MEDIUM_AND_ABOVE`、`BLOCK_LOW_AND_ABOVE`、`HARM_BLOCK_THRESHOLD_UNSPECIFIED` のいずれにも該当しません。しきい値が空欄のカテゴリは検証の対象外です。
- Claude の「デフォルトの最大トークン数」で、いずれかのモデルの値が負数です。
- Claude の「デフォルトの最大トークン数」が「モデル名 → 整数」のマッピングになっていません。

**対処方法**

1. メッセージに表示されたカテゴリまたはモデル名に対応する値を修正します。
2. 「変更を保存」を再度クリックします。

</Accordion>

</Accordions>
