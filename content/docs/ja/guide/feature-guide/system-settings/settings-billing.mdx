- **モデル料金**は、リクエストの使用量と料金ルールに基づいて計算されます。
- **ゲートウェイでの実際の受取額**は、各決済チャネルの注文によって決まります。

## 設定セクション

ここでは、左側のナビゲーションの順に 6 つのセクションを紹介します。各セクションの保存ボタンと設定が反映されるタイミングについては、[保存と反映](#保存と反映)を参照してください。

### クォータ設定

- 課金と決済－クォータ設定

![課金と決済－クォータ設定画面](/assets/guide/feature-guide/system-settings-billing-and-payments-quota-settings.png)

**操作手順**

1. 入力するクォータをクォータポイントに換算します。デフォルトの換算基準では、`500000` クォータポイントが `$1` に相当します。
2. 新規ユーザーのクォータ、ウォレットの事前控除を省略するしきい値、入力料金の事前控除倍率、無料モデルの事前消費を設定します。
3. 招待報酬を付与する場合は、先に[決済コンプライアンスの確認](#決済コンプライアンスの確認)でコンプライアンス条項を確認します。
4. 招待者報酬と被招待者報酬を設定します。
5. チャージ用リンクを入力します。
6. ページ上部の「変更を保存」をクリックします。

<Callout type="warn" title="注意">

- 決済コンプライアンスを確認していない場合は、フォームの上に「0 を超える招待報酬を設定するには、先に決済ゲートウェイの設定でコンプライアンス条項を確認する必要があります。」という赤い警告が表示されます。
- この状態で `0` を超える招待報酬を保存しようとすると拒否されます。表示されるメッセージの全文は、[よくある質問](#よくある質問)を参照してください。
</Callout>

**設定項目**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 設定項目 | 定義 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| 新規ユーザーのクォータ | 新規ユーザーに付与される初期クォータ。既存ユーザーへの遡及付与はありません。 | 0 以上の整数。単位はクォータポイントで、換算後の金額が説明文にリアルタイムで表示されます。 | `0` |
| ウォレットの事前控除を省略するしきい値（米ドル） | ユーザーのウォレット残高と、上限が設定された API トークンの残高がどちらもこの金額を超えると、事前控除を省略し、実際の使用量に基づいて精算します。`0` に設定すると常に事前控除を行います。サブスクリプションと非同期タスクでは常に事前控除を行います。 | `0` 以上の数値。小数も指定できます。`0` 未満の場合は「0 以上である必要があります」と表示されます。 | `10` |
| 入力料金の事前控除倍率 | 見積もり入力料金にこの倍率を掛けた額を事前控除します。出力 Token は見積もりの対象外です。最終的には実際の使用量に基づいて精算します。リクエスト単位の課金とタスク単位の課金には影響しません。 | `0` より大きい数値。小数も指定できます。条件を満たさない場合は「0 より大きい値を指定してください」と表示されます。 | `1` |
| 招待者報酬 | 招待を受けたユーザーが登録し、条件を満たした場合に、招待者に付与されるクォータ。報酬はまず招待者の招待クォータに計上され、招待者がウォレットで「残高に移す」をクリックすると残高に反映されます。 | 0 以上の整数。単位はクォータポイントです。`0` を超える場合は、先に決済コンプライアンスを確認する必要があります。 | `0` |
| 被招待者報酬 | 招待されたユーザーに付与されるクォータ。 | 0 以上の整数。単位はクォータポイントです。`0` を超える場合は、先に決済コンプライアンスを確認する必要があります。 | `0` |
| 無料モデルの事前消費 | 有効にすると、料金がゼロのモデルでも最終精算前にクォータを消費します。 | オン・オフを切り替えます。 | オン |
| チャージ用リンク | ユーザーがクォータを購入するための外部リンク。このサイトの決済コールバックには自動で連携されません。 | 任意。`https://example.com/topup` のように完全な URL を入力します。 | 空欄 |

</div>

### 通貨と表示

- 課金と決済－通貨と表示

![課金と決済－通貨と表示画面](/assets/guide/feature-guide/system-settings-billing-and-payments-currency-and-display.png)

**操作手順**

1. 「表示モード」で「USD」「人民元」「カスタム通貨」のいずれかを選択します。
2. 「カスタム通貨」を選択した場合は、「カスタム通貨記号」と「1 USD あたりの通貨単位数」を入力します。
3. 「米ドル為替レート」を入力し、必要に応じて「Token 統計情報を表示」をオンまたはオフにします。
4. ページ上部の「変更を保存」をクリックします。

<Callout type="info" title="ヒント">

- デフォルトの換算基準では、内部の `500000` クォータポイントが `$1` に相当します。
- ページ上部の「リセット」をクリックすると、フォームが保存済みの値に戻り、「フォームを保存済みの値にリセットしました」と表示されます。変更がない場合は使用できません。
</Callout>

**設定項目**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 設定項目 | 定義 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| 表示モード | ユーザーにクォータの値を表示する形式。 | 「USD」「人民元」「カスタム通貨」から選択できます。 | `USD` |
| 米ドル為替レート | 米ドルと決済ゲートウェイで使用する通貨との実際の為替レート。 | `0.0001` 以上の値を指定します。条件を満たさない場合は「為替レートは 0 より大きい値を指定してください」と表示されます。<br/>表示モードが「人民元」の場合、項目名は「人民元の対米ドル為替レート」と表示されます。 | `7.3` |
| カスタム通貨記号 | 料金を表示する際に金額の前に付ける記号。 | 「カスタム通貨」モードでのみ表示される必須項目です。最大 8 文字です。空欄の場合は「カスタム通貨記号は必須です」と表示されます。 | `¤` |
| 1 USD あたりの通貨単位数 | 米ドルからカスタム通貨への換算レート。`1 USD = X` カスタム通貨単位として指定します。 | 「カスタム通貨」モードでのみ表示される必須項目です。最小値は `0.0001` です。空欄の場合は「為替レートは必須です」と表示されます。 | `1` |
| Token 統計情報を表示 | OpenAI 互換のクォータ照会 API が、対象トークンとアカウント全体のどちらのクォータと使用量を返すかを指定します。 | オン・オフを切り替えます。画面には「ユーザーインターフェースにトークンの使用統計を表示する」と説明されています。 | オン |

</div>

### モデルの価格設定

ページ上部のタイトルの右側には「モデル価格」「価格未設定のモデル」「ツール価格」「上流価格の同期」の 4 つのタブがあり、デフォルトでは「モデル価格」が開きます。モデルの課金モード、使用量の種類ごとの単価、課金式、ツール呼び出しの単価を設定できます。また、価格が未設定のモデルに価格を設定したり、上流の価格を同期したりできます。

#### モデル価格

- 課金と支払い-モデルの価格設定-モデル価格

![課金と支払い-モデルの価格設定-モデル価格ページ](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-model-prices.png)

タブ内の左側にモデル一覧、右側に編集パネルが表示されます。モデルを選択していない場合は「モデルを選択して価格を編集」が表示されます。一覧には、価格が設定済みのモデルと、有効なチャネルで使用されている組み込み価格設定済みのモデルのみが表示されます。チャネルにモデルが自動で追加されることはありません。価格設定は、リクエストで使用するモデル識別子と実際に適用される課金経路に一致させてください。

- 課金と支払い-モデルの価格設定-モデル価格-モデル価格の編集

![課金と支払い-モデルの価格設定-モデル価格-モデル価格の編集ページ](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-model-prices-edit-model-pricing.png)

**追加・編集の手順**

1. ツールバー右側の「モデルを追加」またはモデル行の編集アイコンをクリックします。新規作成時は正確なモデル名を入力します。編集時にモデル名を直接変更することはできません。
2. 価格設定通貨と課金モードを選択し、価格または課金式を設定します。エディターの使い方については、<a href="/ja/docs/guide/feature-guide/admin/billing-expression" target="_blank" rel="noopener noreferrer">課金式</a>を参照してください。
3. 「Token 見積もりツール」に既知の使用量を入力し、料金を確認します。
4. リクエスト条件がある場合は、「リクエストシミュレーション」にリクエストボディ、リクエストヘッダー、時刻を入力します。
5. 「モデル価格を保存」をクリックします。
6. 「価格変更の確認」で各モデルの「現在の価格」と「保存後の価格」を確認し、「確認して保存」をクリックします。

#### 価格の対応が必要

プラグインが提供するタスクモデルを課金できない場合、モデル価格の一覧で対象モデルにマークが付きます。サイドバーの「システム設定」と、左側のナビゲーションの「課金と支払い」「モデルの価格設定」にも、対応が必要なモデルの件数が表示されます。タスクモデルの課金ルールについては、<a href="/ja/docs/guide/feature-guide/admin/billing-expression#タスクモデル" target="_blank" rel="noopener noreferrer">課金式</a>を参照してください。

**集計対象**

- 有効なチャネルが実際に提供しているモデル。
- プラグインが提供を終了したモデルのうち、価格が引き続き保存されているモデル。
- プラグインを無効にした場合、そのモデルの価格は保持され、対応が必要なモデルの件数には含まれません。

**対応手順**

1. 「モデル価格」タブ上部の「… 件のモデルで価格の対応が必要です」にある「価格を確認」をクリックするか、ツールバーの「価格ステータス」で「価格の対応が必要」を選択します。
2. モデルを選択し、編集パネル上部の「修正が必要な内容」で、プラグインごとの原因と対応方法を確認します。
3. 「原因と対応方法」の表に沿って対応した後、「モデル価格を保存」をクリックし、保存を確定します。

<Callout type="info" title="ヒント">

- 「価格を確認」をクリックすると、対応が必要なモデルのみが一覧に表示され、最初のモデルの編集パネルが開きます。「すべてのモデルを表示」をクリックすると元の一覧に戻ります。
- 対応を促す通知は「モデル価格」タブでのみ表示されます。
- モデル名の横に「価格の対応が必要」と表示され、その下に「プラグイン名：原因」がグレーの文字で表示されます。
- プラグインのアップロード、インストール、有効化、またはバージョンの切り替えによって課金できなくなったモデルがある場合は、プラグイン管理ページにも「以下のモデルで価格の対応が必要です：」と表示されます。

</Callout>

**原因と対応方法**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 原因 | 対応方法 |
| --- | --- |
| 価格が未設定 | 下部で該当するプラグインを選択し、対象モデルに価格を設定して保存します。 |
| 価格設定が、プラグインで提供されなくなった使用量項目を参照している | 下部で該当するプラグインを選択し、現在の課金フィールドに合わせて価格を再設定して保存します。 |
| プラグインがこのモデルの提供を終了した | 下部で該当するプラグインを選択し、保存済みの価格を削除して変更を保存します。 |

</div>

#### 価格未設定のモデル

- 課金と支払い-モデルの価格設定-価格未設定のモデル

![課金と支払い-モデルの価格設定-価格未設定のモデルページ](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-models-without-prices.png)

有効なチャネルで利用できるモデルと、現在の価格設定のスナップショットを照合し、価格がまだ設定されていないモデルを表示します。一覧の形式は「モデル価格」と同じです。このタブには「モデルを追加」がなく、モデルの削除もできません。

**操作手順**

1. モデル行の編集アイコンをクリックし、右側の編集パネルで価格を設定します。
2. 一括で設定する場合は、確認済みのコピー元モデルを右側で開き、コピー先のモデルにチェックを入れて、下部のフローティングバーにある「… の価格設定をコピー」をクリックします。
3. コピー先の各モデルについて、プロトコル、キャッシュ、メディアの課金方法の違いを確認します。
4. 編集パネル下部の「モデル価格を保存」をクリックし、「価格変更の確認」で「確認して保存」をクリックします。

<Callout type="info" title="ヒント">

- このタブは「モデル価格」と同じ下書きを使用します。このタブで変更した価格も、「モデル価格を保存」をクリックすると設定に反映されます。
- ページ上部の操作項目は「モデル価格」タブにあります。「倍率 API を公開」「価格をリセット」「JSON に切り替え」はそちらで操作します。
- 価格が未設定のモデルがない場合は「価格が未設定のモデルはありません」と表示されます。
- 有効なモデルの取得に失敗した場合は「有効なモデルを取得できませんでした」と表示されます。

</Callout>

#### ツール価格

- 課金と支払い-モデルの価格設定-ツール価格

![課金と支払い-モデルの価格設定-ツール価格ページ](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-tool-prices.png)

検索、ファイル検索、画像生成などのツール呼び出しの単価を一元管理します。設定した単価は、ツール呼び出しの追加料金の計算に使用されます。

**操作手順**

1. 設定の適用範囲を決めます。すべてのモデルに適用する場合は共通のツール識別子を使用し、特定のモデルシリーズに適用する場合は `ツール名:モデルプレフィックス*` を使用します。
2. 既存の行を編集するか、「追加」をクリックしてツール識別子と価格を入力します。価格は 1,000 回あたりの米ドル額で入力します。
3. 対象のモデル名に最長一致するプレフィックスのルールを確認し、1 回あたりの基本料金に換算します。
4. タブ下部の右側にある「ツール価格を保存」をクリックします。

<Callout type="info" title="ヒント">

- ツールごとの追加料金 = 価格（米ドル/1,000 回）× 課金対象の呼び出し回数 ÷ 1,000 × グループ倍率。
- ツールの追加料金の合計 = 各ツールの追加料金の合計。
- リクエスト単位で課金するモデルには、ツールの追加料金はかかりません。

</Callout>

**操作項目**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 操作 | 位置 | 説明 |
| --- | --- | --- |
| 追加 | 表の上のツールバー（ビジュアルモード） | ツール価格ルールを 1 件追加します。新しい行のツール識別子は空欄で、価格は `0` です。 |
| 削除アイコン | 行の末尾 | 編集中の設定から該当行を削除します。保存後に対応するカスタム設定が削除され、該当する組み込みルールがない場合は、組み込みのフォールバック価格が適用されます。 |
| デフォルトに戻す | 表の上のツールバー | 編集中の設定を組み込みのデフォルト価格一覧に置き換え、カスタム項目を含む現在の下書きを上書きします。保存は手動で行います。 |
| JSON に切り替え、ビジュアル表示に切り替え | ツールバーの右側 | 表と JSON オブジェクトを切り替えます。JSON のキーはツール識別子、値は非負の数値です。入力例は `{"web_search":10}` です。JSON にエラーがある場合は、修正してから切り替えることを推奨します。 |
| コピー | 表の上のツールバー（JSON モード） | JSON 編集欄の内容をコピーします。変更前の設定を控えておく際に使用できます。成功すると「クリップボードにコピーしました」と表示されます。 |
| ツール価格を保存 | タブ下部の右側 | 現在の価格設定をまとめて送信します。成功すると「設定を更新しました」と表示されます。<br/>価格が無効な場合は「有効な数値を入力してください」と表示されます。<br/>JSON にエラーがある場合は「JSON のエラーを修正してから保存してください」と表示されます。 |

</div>

**設定項目**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 設定項目 | 定義 | 入力要件と制限 | デフォルト値 |
| --- | --- | --- | --- |
| ツール識別子 | 価格を適用するツールと、必要に応じて適用対象のモデルを指定する識別子。 | 共通形式は `ツール名` です。モデル固有の形式は `ツール名:モデルプレフィックス*` です。入力例は `web_search_preview:gpt-4o*` です。 | 組み込みのデフォルト価格一覧 |
| 価格（$/1K 回） | ツール呼び出し 1,000 回あたりの米ドル単価。 | `0` 以上の数値を指定します。小数も使用できます。たとえば `10` は 1,000 回あたり 10 米ドルを表し、1 回あたりの基本料金は 0.01 米ドルです。 | 新規行は `0` |

#### 上流価格の同期

- 課金と支払い-モデルの価格設定-上流価格の同期

![課金と支払い-モデルの価格設定-上流価格の同期ページ](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-upstream-price-sync.png)

プリセットまたは上流チャネルからモデル価格を取得し、ローカルの設定と比較します。モデルごとに価格ソースを選択し、プレビューで確認してからローカルの課金設定を一括更新できます。

**同期手順**

1. 「価格ソースを選択」をクリックし、プリセットまたはチャネルを検索して、1 つ以上にチェックを入れます。
2. API アドレスと同期エンドポイントを確認します。プリセットを使用する場合は、デフォルト値をそのまま使用できます。
3. 「選択を確定」をクリックし、比較結果が表示されるまで待ちます。
4. モデル検索、タイプフィルター、ページ切り替えを使って対象モデルを探します。
5. 対象モデルの価格ソースにチェックを入れます。価格ソース列のヘッダーから一括で選択することもできます。
6. 下部に表示される選択件数を確認し、「同期を適用」をクリックします。
7. 「価格変更のプレビュー」で「価格ソース」「モデル」「現在の課金設定」「保存される価格」を確認します。
8. 「変更を確定」をクリックします。

<Callout type="info" title="補足">

- 支払額 = チャージ額 × 価格（現地通貨/米ドル）× ユーザーグループのチャージ倍率 × 該当する割引係数。
- たとえば、Epay で残高を `100` 米ドル分チャージするとします。価格（現地通貨/米ドル）が `7.3`、ユーザーが所属するグループのチャージ倍率が `1`、割引設定が `100 → 0.85` の場合、支払額は現地通貨で `620.50`、残高への加算額は `100` 米ドルです。
- 「支払い方法」と「チャージ金額の選択肢」では、「ビジュアルエディター」と「JSON 編集」を切り替えられます。

</Callout>

#### Waffo Pancake

- 請求と決済 › 決済ゲートウェイ › Waffo Pancake

![請求と決済 › 決済ゲートウェイ › Waffo Pancake 画面](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-waffo-pancake-mor.png)

Pancake の加盟店、ストア、チャージ用商品を紐付け、ユーザーのチャージ額に応じてチェックアウトセッションを作成します。

<Callout type="info" title="Waffo Pancake MoR">

- 法人を設立せずに世界各地からの支払いを受け付けられます。独立系開発者、一人会社（OPC）の経営者、スタートアップチーム向けのサービスです。
- Waffo Pancake が販売主体（Merchant of Record）となり、消費税、請求書発行、サブスクリプション管理、返金、チャージバックなど、国際決済に伴うコンプライアンス業務を引き受けます。

</Callout>

3. 既存のストアと、そのストアで有効化済みの商品を選択します。

- 有効化すると、Waffo Pancake が支払い方法としてウォレットに自動表示されます。表示名、アイコン、最低チャージ額をカスタマイズするには、「一般 › 支払い方法」で決済処理識別子が `waffo_pancake` の項目を追加します。

</Callout>

**操作手順**

1. 「Waffo を有効にする」をオンにし、必要に応じて「サンドボックスモード」をオンにします。
2. 選択した環境の API キー、RSA 秘密鍵、Waffo 公開鍵を入力し、加盟店 ID と金額に関する項目を設定します。
3. コールバック通知 URL と決済後の戻り先 URL を確認します。
4. 支払い方法を追加または編集し、ダイアログで「確認」をクリックします。
5. ページ上部の「すべての設定を保存」をクリックします。

<Callout type="info" title="補足">

- 支払い方法のダイアログで「確認」をクリックすると、画面上の一覧が更新されます。「すべての設定を保存」をクリックすると変更が保存されます。

</Callout>

### チェックイン報酬

- 課金と支払い - チェックイン報酬

![課金と支払い - チェックイン報酬ページ](/assets/guide/feature-guide/system-settings-billing-and-payments-check-in-rewards.png)

毎日のチェックイン機能の有効・無効と、ランダムに付与する報酬クォータの下限・上限を設定します。ユーザーはチェックインに成功すると、報酬クォータを受け取ります。

**操作手順**

1. 「チェックイン機能を有効にする」をオンにします。
2. チェックインの最小クォータと最大クォータを入力します。
3. ページ上部の「チェックイン設定を保存」をクリックします。

<Callout type="warn" title="注意">

- 最大値が最小値より大きい場合は、両端を含む範囲内でランダムに付与します。それ以外の場合は、常に最小値を付与します。
- 現在のフォームでは、最小値が最大値より大きくても、自動でエラーは表示されません。
- 日付の切り替わりはサービスプロセスのローカル日付で判定し、ユーザーごとのブラウザーのタイムゾーンは使用しません。複数インスタンスで運用する場合は、各ノードのタイムゾーンを統一してください。
- ユーザーと日付の組み合わせに対する一意性制約により、同じ日に報酬を重複して受け取ることを防ぎます。
- Turnstile をグローバルで有効にすると、チェックインリクエストも Turnstile の検証を通過する必要があります。
</Callout>

**補足**

- **項目ごとの書き込み**　「変更を保存」「グループ設定を保存」「すべての設定を保存」「チェックイン設定を保存」では、変更した項目のみを送信します。更新に成功した項目ごとに「設定を更新しました」と表示されます。変更がない場合、「グループ設定を保存」では通知が表示されず、その他の保存操作では「保存する変更はありません」と表示されます。
- **未保存の変更**　クォータ設定、または通貨と表示に未保存の変更がある状態でページを離れると、「未保存の変更」の確認ダイアログが表示されます。「ページを離れる」または「ページにとどまる」を選択できます。
- **モデル価格の確認と通知**　価格を変更した場合は、まず「価格変更の確認」で確定します。保存に成功すると「モデル価格を保存しました」、変更がない場合は「保存するモデル価格の変更はありません」と表示されます。
- **他のユーザーによる価格変更**　ページを開いた後に他のユーザーが同じモデルの価格を変更した場合、保存は拒否されます。「価格設定を再読み込み」をクリックし、変更し直してください。
- **易支付の署名方式の切り替え**　同じ保存操作の中で、先に秘密鍵と公開鍵を書き込み、その後に署名方式を書き込みます。署名方式が RSA で鍵を解析できない場合、保存は拒否され、「易支付の加盟店秘密鍵が設定されていないか、形式が正しくありません」または「易支付のプラットフォーム公開鍵が設定されていないか、形式が正しくありません」と表示されます。

## 注意事項

- **「価格をリセット」ですべてのカスタム価格が削除されます**。課金式も削除されます。詳細は[モデル価格](#モデル価格)を参照してください。
- **見積もりと実際の請求額は異なる場合があります**。「トークン見積もりツール」にはリクエストルールとグループ倍率が反映されません。実際の引き落とし額は利用ログで確認してください。
- **入金は支払い通知に基づいて反映されます**。支払いゲートウェイがサイトに送信する支払い通知を受けて、ウォレットに入金が反映されます。支払い完了後の戻り先ページは入金判定には使用されません。各ゲートウェイの有効化条件は[支払いゲートウェイ](#決済ゲートウェイ)を参照してください。

## よくある質問

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="保存に成功したのに価格が変わらないのはなぜですか？">

**考えられる原因**

- 編集中の下書きを最終的な保存と混同している。
- モデル名、現在のモード、プロバイダーによる上書き設定、またはリクエスト開始時の価格スナップショットが想定と異なる。
</Accordion>

<Accordion title="価格設定を無効にすると無料になりますか？">

**説明**

必ずしも無料になるわけではありません。上書き設定を削除すると、デフォルト値に戻る場合があります。ツール価格では、より具体的なプレフィックスに一致する場合もあります。ゼロを明示的に設定した状態、未設定の状態、設定を削除した状態はそれぞれ異なります。
</Accordion>

<Accordion title="公開価格 API にアクセスできないのはなぜですか？">

**説明**

この API の現在のパスは `/api/ratio_config` です。

**考えられる原因**

「倍率 API を公開」がオフになっています。
</Accordion>

<Accordion title="100 の金額に対する割引が 200 に適用されないのはなぜですか？">

**説明**

金額別の割引は、割引前の金額が設定額と完全に一致する場合に適用されます。設定額を最低しきい値とするルールではありません。
</Accordion>

<Accordion title="Stripe の見積もりと支払いページの金額が一致しないのはなぜですか？">

**考えられる原因**

- Stripe Price の通貨、単価、または数量が想定と異なる。
- サイト側の単価、チャージ倍率、割引、Stripe のプロモーションコードを区別していない。
</Accordion>

<Accordion title="Creem の商品クォータに 1 を入力しても 1 米ドルが入金されないのはなぜですか？">

**説明**

この項目には内部クォータのポイント数を入力します。デフォルトの換算レートでは、1 USD はシステム上の 500000 クォータポイントに相当します。
</Accordion>

<Accordion title="キーの入力欄が空の場合は未設定ですか？">

**説明**

空欄でも設定済みの場合があります。入力欄にキーを表示しない場合の共通ルールについては、<a href="/ja/docs/guide/feature-guide/system-settings/system-setting#機密設定と監査記録" target="_blank" rel="noopener noreferrer">機密性の高い設定と監査ログ</a>を参照してください。Waffo の公開鍵は、入力欄を空にして保存すると既存の値が削除されます。空欄にすると既存の値が保持される秘密鍵とは扱いが異なります。
</Accordion>

<Accordion title="ユーザーが特定のグループを選択できないのはなぜですか？">

**考えられる原因**

- 公開の利用可能グループ一覧、特別ルール、アカウントの所属グループ、倍率設定、またはトークンの制限により、そのグループを選択できない。
- Auto の使用時に `auto` が有効になっていない。
</Accordion>

<Accordion title="Pancake での作成に成功したのに設定が完了しないのはなぜですか？">

**説明**

外部リソースの作成、作成したリソースの選択、ローカルでの紐付けの保存は、それぞれ別の手順です。

**対処方法**

ショップと商品の選択内容を確認し、「すべての設定を保存」をクリックして紐付けを保存します。
</Accordion>

<Accordion title="チェックイン報酬が毎日最小値になるのはなぜですか？">

**考えられる原因**

- 最大値が最小値以下になっている。
- 入力値の単位がクォータポイントになっていない。
</Accordion>

<Accordion title="招待報酬を保存すると、機能が無効と表示される">

**表示メッセージ**

「支払い、引き換えコード、サブスクリプションプラン、招待報酬の機能は無効です。有効にするには、管理者が先にコンプライアンスに関する声明を確認する必要があります。」（英語 Payment, redemption, subscription, and invitation reward features are disabled. The administrator must confirm compliance terms before enabling them.）

**考えられる原因**

支払いコンプライアンスが未確認の状態で、「招待者報酬」または「被招待者報酬」に `0` より大きい値が設定されています。

**対処方法**

1. Root ユーザーが「支払いゲートウェイ」でコンプライアンス条項を確認します。詳細は[支払いコンプライアンスの確認](#支付合规确认)を参照してください。
2. 「クォータ設定」に戻り、再度保存します。
</Accordion>

<Accordion title="モデル価格を保存すると、価格が変更されたと表示される">

**表示メッセージ**

メッセージに `model pricing changed; reload before saving` が含まれます（英語のみ）。

**考えられる原因**

ページを開いた後に、他のユーザーが同じモデルの価格を変更したか、別のウィンドウで同じモデルの価格が変更された可能性があります。

**対処方法**

1. 「価格設定を再読み込み」をクリックします。
2. 価格を変更し直して保存します。
</Accordion>

</Accordions>
