- 从侧边栏「常规」→「使用日志」进入。
- 查看每次调用模型的用量和扣费，以及充值、退款等额度变动记录。
- 调用模型会按价格扣账户里的额度（钱包余额或订阅额度），扣费明细在这里查看。

<Callout type="info" title="提示">
- 页面标题显示为「通用日志」。
- 普通用户仅可查看本账户的记录。管理员可在页面右上角切换「全部」「仅自己」（仅管理员可见），选择「仅自己」时，页面内容与普通用户相同。
- 费用和用量的显示单位由站点决定。
- 登录和账户安全操作的记录见<a href="/zh/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">审计日志</a>；视频、音乐、绘图等异步任务的状态见<a href="/zh/docs/guide/feature-guide/user/task-log" target="_blank" rel="noopener noreferrer">任务日志</a>。
- 左侧边栏无「使用日志」页时：<br/>到「个人资料」页的「左侧边栏个人设置」区域中，开启「控制台区域」和「使用日志」并保存。
</Callout>

## 筛选日志并查看统计

**操作流程：**
1. 点击「时间范围」，选择「今天」「7 天」等快捷范围；或填写「起始时间」「结束时间」后点击「确认」。
2. 按需填写「模型名称」「分组」，在类型下拉框中选择日志类型。
3. 按令牌名称、请求 ID 等查找时，点击「展开」，填写第二行的筛选项。
4. 点击「搜索」，或在任一输入框中按回车键。
5. 在筛选区左下角查看「用量」「RPM」「TPM」。
6. 需要清除筛选条件时，点击「重置」。

<Callout type="info" title="提示">
- 默认仅显示今天 00:00:00 至当前时间后 1 小时内的记录，查看更早的记录请先调整时间范围。
- 修改筛选条件后需点击「搜索」才会生效。页面不会自动刷新，新产生的记录需再次点击「搜索」后显示。
- 在手机上，除时间范围外的筛选项收在「筛选」中；选好时间范围后列表立即刷新。
</Callout>

## 查看日志详情

**操作流程：**
1. 点击记录所在行「详情」列的摘要文字，打开「日志详情」窗口。
2. 按区域查看该记录的请求信息、Token 用量和计费明细。
3. 需要复制日志内容时，点击「内容」右上角的复制按钮。

<Callout type="info" title="提示">
- 窗口仅显示该记录实际保存的信息，不同类型、不同请求的记录显示的区域不同。
- 核对计费时，查看「Token 明细」和「计费详情」。
</Callout>

### 请求策略决策

「日志详情」中的「请求策略决策」区域（仅管理员可见）按步骤列出该请求选择渠道、重试或停止的过程，仅在页面右上角选择「全部」时显示，选择「仅自己」后不显示。

- 成功的请求：决策记录随「消耗」记录写入，至少包含「选择渠道」「请求已完成」两步。管理员关闭「记录配额使用量」后不再写入。
- 失败的尝试：每次失败的尝试各写一条「错误」记录，带有截至该次尝试的决策记录。站点未开启错误日志记录时不写入这类记录，此时看不到失败尝试的决策记录。

**步骤的显示方式：**
1. 第一行：决策内容；涉及渠道时后接「#渠道 ID」，失败的步骤后接 HTTP 状态码；停止重试的步骤以琥珀色显示。
2. 第二行：「尝试 N」、从请求开始累计的耗时（毫秒）、分组、命中的规则名和 HTTP 状态码，无相应信息的项不显示。
3. 第三行：「来源：」及该决定的依据；该次失败对渠道健康有处理时，在来源后显示。

**决策内容说明：**

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 决策内容 | 含义 |
| --- | --- |
| 选择渠道 | 本次尝试选中的渠道。 |
| 命中会话规则 | 请求命中了一条会话保持规则，规则名显示在第二行。 |
| 上游请求失败 | 本次尝试在上游或网络连接环节失败。 |
| 请求在本地被拒绝 | 请求在发往上游前被本地检查拒绝。 |
| 渠道错误 | 判定为渠道本身出错。 |
| 状态码命中重试规则 | 失败的状态码在重试规则范围内，继续重试。 |
| 状态码未命中重试规则 | 失败的状态码不在重试规则范围内，不再重试。 |
| 无法识别的状态码 | 上游返回的状态码无法识别。 |
| 整次尝试次数已耗尽 | 已达到最多尝试次数，不再重试。 |
| 系统禁止重试的情况 | 属于系统规定不重试的情况，不再重试。 |
| 固定渠道约束 | 请求被固定到某个渠道，不切换渠道。 |
| 会话保持设置阻止切换渠道 | 会话保持要求使用原渠道，不切换渠道。 |
| 任务已接受，不能重复提交 | 异步任务已被上游接受，不再重试。 |
| 任务失败 | 异步任务在提交时失败。 |
| 流式输出未成功完成 | 流式输出未正常结束。 |
| 请求已完成 | 请求成功结束。 |
</div>

**来源与健康处理：**
- 来源：「全局默认」「全局与渠道设置」「渠道」「会话规则」表示依据站点或渠道的重试、会话设置；「系统约束」「固定渠道约束」表示依据系统规则；「渠道选择」「上游响应」「上游连接」「本地检查」表示依据该次尝试的实际情况。
- 健康处理：「不变」表示渠道状态未改变；「已请求停用渠道」「已请求停用当前密钥」表示该次失败触发了停用请求。

## 导出日志

**操作流程：**
1. 按需设置页面上的筛选条件，点击「搜索」。
2. 点击筛选区右下角的「导出」，打开「导出日志」窗口。
3. 在窗口中设置要导出的时间范围。
4. 点击窗口中的「导出」，等待浏览器下载文件。

<Callout type="info" title="提示">
- 管理员关闭用户导出后，普通用户的页面上不显示「导出」；管理员始终可导出。
- 同一账户同一时间仅可进行一个导出，导出过程中关闭窗口会中止导出。
- 「隐藏」不影响导出，文件中的名称均为原文。
</Callout>

**配置项说明：**

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 时间范围 | 要导出的记录的时间范围。 | 必填，需同时设置起止时间。结束时间早于起始时间时提示「结束时间必须晚于开始时间」；跨度超过上限（默认 365 天）时提示「时间跨度不能超过 … 天」，此时「导出」不可点击。页面上的模型名称、分组、类型、令牌名称、请求 ID 等其他筛选条件同样生效。 | 页面当前生效的时间范围 |
</div>

**导出文件说明：**
- 文件为 CSV 格式，文件名为「usage-logs-起始日期-结束日期.csv」，如 `usage-logs-20261101-20261108.csv`，可用表格软件直接打开。
- 包含「时间」「类型」「令牌」「分组」「模型」「流」「输入 Token」「输出 Token」「缓存读取」「缓存写入」「费用」「耗时」「IP」「请求 ID」「详情」列。在「全部」视图下导出时，另含「用户」「渠道」列（仅管理员可见），并包含所有用户的记录。
- 记录按时间从新到旧排列，不限条数。

## 常见问题

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="找不到某次调用的记录">
**可能原因**：
- 时间范围仍为默认的今天，或筛选条件过严：令牌名称、分组、请求 ID、上游请求 ID 均按完整内容匹配。
- 调用失败。站点未开启错误日志记录时，不记录失败的请求。
- 管理员关闭了「记录配额使用量」，成功的调用不再产生「消耗」记录。
- 管理员选择了「仅自己」，而要找的是其他用户的记录。
- 页面不会自动刷新。

**处理方法**：
1. 清除多余的筛选条件，将时间范围调整为调用发生的时间段。
2. 已知请求 ID 时，点击「展开」，在「请求 ID」中填写完整 ID。
3. 点击「搜索」刷新列表。
4. 如仍无法找到，请联系管理员确认站点的日志记录设置。
</Accordion>

<Accordion title="调用失败的请求是否扣费">
**说明**：返回错误的请求不扣费。站点未开启错误日志记录时，不记录失败的请求；开启后，失败的请求显示为「错误」记录，「费用」为 0，错误信息见「日志详情」中的「内容」。异步任务失败或超时后，已扣除的额度会退回，并产生一条「退款」记录。

**处理方法**：
1. 以「消耗」「退款」记录和账户余额的变化核对扣费。
2. 需要排查失败原因而列表中无「错误」记录时，请联系管理员。
</Accordion>

<Accordion title="费用与预期不一致">
**说明**：「计费详情」中的输入、输出单价为每百万 Token 的价格，显示单位由站点决定。

**可能原因**：
- 使用的分组有倍率，或账户有专属倍率，倍率显示在「令牌」列的分组旁。
- 使用了缓存读写、音频、图片或网页搜索等工具，这些按各自的价格计费；含工具调用附加费的记录在「费用」旁显示扳手图标。
- 模型按档位计费，命中的档位价格不同。
- 由订阅额度支付时，「费用」显示订阅实际扣除的额度。

**处理方法**：
1. 打开该记录的「日志详情」，在「计费详情」中核对计费模式、单价、倍率和总费用。
2. 在「Token 明细」中核对各类 Token 数。
3. 如仍有疑问，请将「请求 ID」发给管理员。
</Accordion>

<Accordion title="「用量」与列表中的费用合计或数据看板不一致">
**说明**：
- 「用量」仅汇总所选时间范围内的「消耗」记录，不扣除「退款」，也不受「类型」「请求 ID」「上游请求 ID」影响。
- 「RPM」「TPM」始终统计最近 60 秒。
- 数据看板按时间段定期汇总（默认每 5 分钟），新的调用会先出现在使用日志中。

**处理方法**：
1. 在类型下拉框中选择「消耗」后点击「搜索」，再与「用量」对照。
2. 将类型选择为「退款」，单独查看退回的额度。
3. 数据看板的数据请稍后刷新再看。
</Accordion>

<Accordion title="查询时提示「时间跨度不能超过 … 天」">
**提示原文**：「时间跨度不能超过 … 天」（英文 The time range cannot exceed … days）

**可能原因**：普通用户一次可查询的时间跨度有上限，默认 365 天，由管理员设置；导出时管理员也受此限制。

**处理方法**：
1. 缩小时间范围后重新搜索。
2. 需要更长时间的记录时，分多次查询或导出。
</Accordion>

<Accordion title="看不到「导出」按钮，或导出时提示错误">
**说明**：请根据提示原文判断原因：

| 提示原文 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 页面上不显示「导出」，或提示「日志导出已关闭」（英文 Log export is disabled） | 管理员关闭了用户导出。 | 联系管理员。 |
| 「已有一个日志导出正在进行，请等它完成后再试。」（英文 Another log export is running. Try again after it finishes.） | 本账户已有一个导出正在进行。 | 等上一个导出完成后重试。 |
| 「结束时间必须晚于开始时间」（英文 End time must be after start time） | 结束时间早于起始时间。 | 重新设置时间范围。 |
| 「时间跨度不能超过 … 天」（英文 The time range cannot exceed … days） | 导出的时间跨度超过上限，默认 365 天。 | 缩小时间范围，分多次导出。 |
| 「导出日志失败」（英文 Failed to export logs） | 网络中断或服务端出错。 | 重试；如仍失败，请联系管理员。 |
</Accordion>

<Accordion title="详情中不显示「IP 地址」">
**可能原因**：账户未开启「记录 IP 地址」。该设置默认关闭，开启后仅对之后产生的「消耗」「错误」记录生效。

**处理方法**：
1. 打开「安全与访问」页，在「隐私」区域开启「记录 IP 地址」。
2. 之后产生的记录会显示 IP 地址，开启前的记录无法补充。
</Accordion>

<Accordion title="模型名称旁显示「响应模型：…」">
**提示原文**：「上游返回的模型名与请求模型、上游请求模型均不一致。模型别名或日期版本也可能导致差异，不能仅凭此警示认定模型被替换。」（英文 The upstream returned a model name different from both the requested and upstream models. Aliases or dated versions may also cause this; this warning alone does not prove model substitution.）

**可能原因**：上游返回的模型名与请求的模型名不同，例如模型别名或带日期的版本名。

**处理方法**：
1. 点击该提示，查看「请求模型」「上游请求模型」「响应模型」。
2. 如怀疑模型被替换，请将「请求 ID」发给管理员核实。
</Accordion>

<Accordion title="使用 % 模糊查找时提示格式错误">
**说明**：「模型名称」「用户名」支持用 % 模糊查找，格式不符时提示以下内容：

| 提示原文 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 「搜索模式中不允许包含连续的 % 通配符」（英文 The search pattern cannot contain consecutive % wildcards） | 连续输入了多个 %。 | 删除多余的 %。 |
| 「搜索模式中最多允许包含 2 个 % 通配符」（英文 The search pattern can contain at most 2 % wildcards） | 使用了 2 个以上的 %。 | 最多保留 2 个 %。 |
| 「使用模糊搜索时，关键词长度至少为 2 个字符」（英文 Fuzzy search keywords must be at least 2 characters long） | % 以外的字符少于 2 个。 | 补充关键词。 |
</Accordion>

<Accordion title="选择「管理」或「登录」类型查不到新记录">
**说明**：新的登录和管理操作记录在审计日志中，「管理」「登录」类型仅用于查询历史日志，筛选中带「已弃用」标记。

**处理方法**：
1. 打开<a href="/zh/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">审计日志</a>，查看登录和账户操作记录。
</Accordion>

<Accordion title="看不到「渠道」「用户」列或「请求策略决策」">
**说明**：「渠道」「用户」列、「用户名」「渠道 ID」筛选，以及详情窗口中的「请求策略决策」等管理员区域，仅在管理员选择「全部」时显示。失败尝试的决策记录还需要站点开启错误日志记录。

**处理方法**：
1. 管理员在页面右上角选择「全部」。
2. 普通用户无法查看这些内容，如需排查请将「请求 ID」发给管理员。
</Accordion>

<Accordion title="使用日志会保存多久">
**说明**：使用日志默认不会自动删除。管理员可删除某一时间之前的使用日志，删除后无法恢复。

**处理方法**：
1. 需要长期保存的记录，请定期[导出日志](#导出日志)。
</Accordion>

</Accordions>
