登录后点击左侧导航栏的「钱包」，或直接访问 `/wallet`，进入钱包页面。钱包页面集中提供余额统计、在线充值、兑换码、订单历史、订阅计划、我的订阅和邀请奖励等功能。具体显示的区域、金额、支付方式和套餐内容由平台配置决定。

![钱包与订阅页](/assets/guide/feature-guide/wallet-subscriptions.png)

## 查看余额与用量

钱包统计区域包括以下信息：

- **当前余额**：可用于模型调用或其他计费操作的内部额度，不是现金余额。
- **累计消耗**：账户历史上已使用的额度。
- **API 请求数**：账户发起的 API 请求数量。

<Callout type="warn">
  1. 余额和用量的显示单位由 Root 在「系统设置」→「计费与支付」中配置的货币和额度显示规则决定。
  2. 不要根据页面上的符号或数值自行推算固定汇率；实际扣费还会受到模型、分组、渠道和实例计费规则影响。
</Callout>

## 在线充值

如果平台启用了在线支付，钱包的充值区域会显示可用的充值选项。充值金额、预设金额、最低充值金额、折扣和汇率均由平台配置决定。

1. 在「充值」区域选择页面提供的预设金额，或输入自定义金额。
2. 查看系统计算的充值额度和应付金额。
3. 选择当前平台提供的支付方式。
4. 在确认窗口核对充值额度、应付金额、折扣和支付方式。
5. 确认后跳转到第三方支付页面完成付款。
6. 支付完成后返回钱包，等待订单状态和余额更新。

<Callout type="warn">
  1. 项目代码支持 EPay、Stripe、Creem、Waffo 和 Waffo Pancake 等支付网关，但只有已启用、配置完整且当前可用的支付方式才会显示。不同网关还可能有额外的金额或支付限制，请以页面提示为准。没有可用支付方式时，请联系平台管理员。
  2. 支付成功需要第三方支付回调完成订单确认，付款后余额不一定立即更新。遇到支付成功但余额未变化的情况，请先保留订单号并联系管理员，不要重复支付。
  3. 支付方式、最低充值金额、折扣、汇率和预设金额不是 New API 的固定值，不能根据其他实例或示例页面推断当前实例的规则。
</Callout>

## 兑换码

当兑换码可用时，充值区域会显示兑换码输入框；如果管理员配置了兑换码获取地址，页面还会显示相应的外部链接。

1. 在充值区域找到「兑换码」输入框。
2. 输入管理员提供的兑换码。
3. 点击「兑换」，等待结果提示并刷新余额。


<Callout type="info">
  1. 兑换码必须满足平台配置的有效期和使用规则，并且处于启用状态、尚未使用。每个兑换码只能成功使用一次。
  2. 兑换失败时，页面可能不会显示“已使用”“已过期”或“不存在”等具体原因，请检查兑换码是否完整，并向管理员确认其状态。
  3. 如果平台尚未完成相关支付合规配置，兑换码输入和兑换操作会被禁用，页面会显示相应提示。
</Callout>

## 订阅计划

订阅计划位于钱包页面的订阅区域。只有启用且当前平台通过支付合规检查的计划才会由接口返回并显示；没有可用计划时，订阅区域不显示。

套餐卡包含以下信息：

| 项目 | 说明 |
| --- | --- |
| 标题和副标题 | 管理员为套餐设置的名称和说明。 |
| 价格 | 购买套餐所需的金额，具体数值由实例配置决定。 |
| 有效期 | 可按年、月、日、小时或自定义时长配置。 |
| 总额度 | 套餐包含的订阅额度；配置为 0 时表示不限总额度。 |
| 额度重置 | 可配置为不重置、每日、每周、每月或自定义周期。 |
| 购买上限 | 限制同一用户可购买的次数；配置为 0 时表示不限制次数。 |
| 升级分组 | 购买成功后可能切换到管理员配置的分组。 |
| 降级分组 | 订阅到期后可能切换到管理员配置的分组；未设置时，只有购买时通过升级分组切换且到期时仍处于该分组，才通常恢复购买前分组。 |

<Callout type="warn">
 「不限总额度」只表示该订阅本身不设置总额度上限，并不代表可以无限制调用。请求仍会受到模型、路由、分组和计费规则限制。
</Callout>

## 购买订阅套餐

1. 打开钱包页面的订阅区域。
2. 选择套餐并查看有效期、额度、重置周期和购买限制。
3. 选择页面显示的购买方式。
4. 核对订单信息后完成余额扣款或第三方支付。
5. 使用第三方支付时，返回钱包并等待支付回调；状态更新后再确认订阅是否生效。

可用的购买方式取决于全局支付网关和套餐本身的配置，可能包括：

- **钱包余额**：套餐允许余额支付且账户余额足够时可用。扣除额度按“套餐价格 × `QuotaPerUnit`”计算并向上取整，具体单位由平台配置决定。
- **EPay**：需要平台启用 EPay 支付，并且当前支付配置可用。
- **Stripe、Creem 或 Waffo Pancake**：除全局网关可用外，套餐还必须配置对应的支付产品。

<Callout type="warn">
  普通 Waffo 支付方式用于在线充值时，不代表它支持订阅购买。达到用户购买上限、套餐被停用、支付方式不可用或余额不足时，购买按钮可能被禁用或操作失败。
</Callout>

## 查看订阅状态

「我的订阅」区域会显示当前订阅和历史状态，常见状态包括：

- **Active**：订阅正在生效，页面会显示剩余天数和结束时间；如果配置了下次重置时间，还会显示该时间；对于有限额度订阅，还会显示总额度、已用额度、剩余额度和使用进度。
- **Expired**：订阅已到期，不能再使用该订阅额度。
- **Cancelled**：订阅已被取消或提前失效。用户端没有自助取消入口，此状态通常由管理员操作产生。
<Callout type="info">
  1. 达到额度重置时间后，有限额度订阅的已用额度会清零，并开始新的额度周期。若下一次重置时间已经超过订阅结束时间，则不会再设置该次重置。
  2. 订阅到期后的分组由套餐配置决定：如果设置了降级分组，通常会切换到该分组；未设置时，只有购买时通过升级分组切换、且到期时仍处于该升级分组，才通常回到购买前分组。若没有发生升级，或账户中仍有其他活动升级订阅，则可能保持当前分组；最终分组会结合其他订阅状态处理。
  3. 当前无自动续费订阅套餐功能，订阅到期后如需继续使用，请重新购买套餐。
</Callout>

## 选择计费偏好

钱包页面可以选择请求的额度扣除顺序。保存偏好后，后端会按照以下规则处理：

| 计费偏好 | 扣除规则 |
| --- | --- |
| **优先订阅** | 有活动订阅时先扣订阅；订阅额度不足时，只有所有活动订阅都允许回退钱包，才会使用钱包。<br/>没有活动订阅时使用钱包。 |
| **优先钱包** | 先扣钱包；钱包余额不足时再尝试使用订阅。 |
| **仅用订阅** | 只使用订阅。没有活动订阅或订阅额度不足时，请求失败，不会切换到钱包。 |
| **仅用钱包** | 只使用钱包。余额不足时请求失败，不会使用订阅。 |

<Callout type="info">
  套餐的「钱包溢出回退」规则会影响“优先订阅”的结果：只要有一个活动订阅禁止回退，订阅额度不足时就不能转用钱包。没有活动订阅时，页面会禁用“优先订阅”和“仅用订阅”选项。
</Callout>

## 邀请奖励

钱包页面的邀请奖励区域会显示邀请链接、待转入奖励、历史累计奖励和邀请人数。邀请码嵌在邀请链接的 `aff` 参数中，链接格式为：

```text
当前站点地址/sign-up?aff=<邀请码>
```

使用流程：

1. 在邀请奖励区域复制邀请链接。
2. 将链接发送给新用户，由对方通过链接注册账号；账号密码注册及使用 OAuth 状态流程的部分新用户注册会读取该参数，微信、Telegram 等独立登录流程不适用。
3. 满足平台配置的邀请条件后，奖励会按照规则发放。
4. 邀请人的奖励通常先进入待转入奖励；待奖励达到可转移条件后，点击「转入余额」将其加入主余额。

<Callout type="warn">
  - 被邀请用户的奖励（如果平台启用）会直接加入其账户额度；邀请人的奖励通常先进入待转入奖励。
  - 邀请奖励的金额、发放条件和最低转移量由平台配置决定。
  - 转入余额支持部分转移，但不能超过当前待转奖励，且不能低于平台额度单位要求；这不是现金提现、退款或提现申请。
  - 如果支付合规状态未满足要求，奖励可能不会发放，「转入余额」操作也可能不可用。
  - 无效邀请码不会阻止注册，已注册用户也不会因为重复使用邀请码再次获得奖励。
</Callout>

## 订单历史

- 点击充值卡右上角的「订单历史」可以查看充值和支付订单记录。
- 页面支持按订单号搜索和分页，并显示订单号、创建时间、支付方式、充值额度或金额、支付金额和订单状态。

<Callout type="info">
  1. 普通用户只能查询自己最近 30 天的记录，搜索条件只匹配订单号。
  2. 该列表主要用于查看充值和支付订单，不保证涵盖所有订阅订单。
</Callout>

## 常见限制

以下情况可能导致钱包或订阅相关功能不可用：

1. 平台未配置支付网关或支付产品，导致没有可用的支付方式或订阅套餐。
2. 支付合规状态尚未满足要求，导致支付方式或订阅计划不可用，兑换码操作显示为禁用状态。
3. 充值金额低于平台或网关要求的最低金额。
4. 余额不足、套餐已停用或达到个人购买上限。
5. 第三方支付尚未完成回调，订单仍处于处理中。

<Callout type="warn">
遇到支付成功但订单或余额长时间未更新时，请保留订单号、支付凭证和发生时间，联系平台管理员核查，不要重复支付。
</Callout>
