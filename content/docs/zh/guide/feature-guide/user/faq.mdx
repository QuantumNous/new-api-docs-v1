## 调用失败

使用 API 密钥或游乐场调用模型时返回错误的问题。

<Accordion title="调用时提示「分组 … 下模型 … 无可用渠道」，或模型不存在">
**提示原文**：「分组 … 下模型 … 无可用渠道（distributor）」（英文 No available channel for model … under group … (distributor)），或「分组 … 下模型 … 的可用渠道不存在（retry）」（英文 No available channel for model … under group … (retry)）

**说明**：本站没有单独的「模型不存在」提示，模型名称填写错误时也返回此提示。

**可能原因**：
- 模型名称填写错误，如大小写或版本后缀与模型广场中的名称不一致。
- API 密钥所用的分组不可调用该模型。
- 提供该模型的渠道暂时全部不可用，或管理员停用了该模型。

**处理方法**：
1. 在<a href="/zh/docs/guide/feature-guide/user/pricing" target="_blank" rel="noopener noreferrer">模型广场与排行榜</a>中复制模型名称，替换请求中的模型名称。
2. 在模型详情「概览」的「按分组定价」中查看可调用该模型的分组，编辑 API 密钥的「分组」；使用游乐场时，在分组与模型选择器中切换分组。
3. 稍后重试；如仍无法解决，请联系管理员。
</Accordion>

<Accordion title="调用时提示「您已达到请求数限制」或「您已达到总请求数限制」">
**提示原文**：「您已达到请求数限制：…分钟内最多请求…次」（英文 You have reached the request limit: maximum … requests in … minutes），或「您已达到总请求数限制：…分钟内最多请求…次，包括失败次数，请检查您的请求是否正确」（英文 You have reached the total request limit: maximum … requests in … minutes, including failed attempts. Please check that your requests are correct）

**说明**：管理员开启了请求数限制，HTTP 状态码为 429。次数按账户统计，同一账户的所有 API 密钥共用，管理员可为部分分组单独设置；游乐场中的调用不计入。状态码为 429、但提示不是这两句时，为上游服务的限流，见本节「调用时提示上游服务的错误，或「数据库出错，请联系管理员」」。

**可能原因**：
- 提示中的时间内调用次数超过了站点设置的上限。
- 「总请求数限制」把失败的请求也计入，请求参数错误导致的反复失败会很快达到上限。

**处理方法**：
1. 等待提示中的时间过去后重试，并降低调用频率；在程序中，请在失败后等待一段时间再重试。
2. 提示为「总请求数限制」时，先根据其他失败请求的提示排查原因。
3. 需要更高的限制时，请联系管理员。
</Accordion>

<Accordion title="调用时提示「用户已被封禁」">
**提示原文**：「用户已被封禁」（英文 User has been banned）

**可能原因**：账户已被管理员禁用，账户下的所有 API 密钥均无法调用。

**处理方法**：
1. 请联系管理员确认账户状态。
2. 网页登录时的同类提示见<a href="/zh/docs/guide/feature-guide/user/auth#常见问题" target="_blank" rel="noopener noreferrer">注册与登录</a>。
</Accordion>

<Accordion title="调用时提示「普通用户不支持指定渠道」">
**提示原文**：「普通用户不支持指定渠道」（英文 Regular users cannot specify a channel）

**说明**：API 密钥 `sk-` 之后的部分含有「-」时，「-」之后的内容会被当作指定的渠道，仅管理员账户可以这样使用。

**可能原因**：
- 复制密钥时带入了多余的内容，或把两段内容粘在了一起。
- 按管理员的用法在密钥后添加了「-」和渠道编号。

**处理方法**：
1. 在 <a href="/zh/docs/guide/feature-guide/user/token" target="_blank" rel="noopener noreferrer">API 密钥</a>页点击密钥右侧的复制按钮，重新复制完整的密钥。
2. 确认请求头为 `Authorization: Bearer sk-…`，密钥后无其他内容。
</Accordion>

<Accordion title="调用时提示「无效的请求」「未指定模型名称」，或请求体过大（413）">
**说明**：请求的格式不符合要求时，请根据提示原文判断原因：

| 提示原文 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 「无效的请求，…」（英文 Invalid request: …） | 请求体不是有效的 JSON，或格式与所调用的接口不符。 | 按 <a href="/zh/docs/api" target="_blank" rel="noopener noreferrer">API 参考</a>核对请求格式。 |
| 「未指定模型名称，模型名称不能为空」（英文 Model name not specified, model name cannot be empty） | 请求中缺少 `model`。 | 在请求中填写模型名称。 |
| HTTP 状态码 413，提示中含 request body too large（仅英文） | 请求体超过站点的上限（默认 128 MB），如附带的图片或文件过大。 | 压缩或减少附件后重试；需要更大的上限时，请联系管理员。 |
</Accordion>

<Accordion title="调用时提示上游服务的错误，或「数据库出错，请联系管理员」">
**说明**：模型由管理员接入的上游服务处理。上游返回错误时，提示为上游的原文，多为英文，已隐去上游的地址；HTTP 状态码通常与上游相同，如 400、429、500、502。

**可能原因**：
- 上游服务暂时繁忙、限流或故障，常见状态码为 429 和 5xx。
- 请求参数不被该模型支持，上游返回 400 类错误。
- 提示为「数据库出错，请联系管理员」（英文 Database error, please contact the administrator）时，为本站服务出错。

**处理方法**：
1. 稍后重试，或改用其他模型、其他分组。
2. 提示与请求参数有关时，按 <a href="/zh/docs/api" target="_blank" rel="noopener noreferrer">API 参考</a>和模型提供方的说明修改参数。
3. 如仍无法解决，请将提示原文连同末尾的「(request id: …)」发给管理员。
</Accordion>

<Accordion title="报错消息末尾的「(request id: …)」是什么">
**说明**：本站为每次请求生成一个编号。调用失败时，编号附在提示的末尾，管理员可凭它查找该请求的处理记录。

**处理方法**：
1. 复制完整的提示原文，连同 request id 发给管理员。
2. 该请求有使用日志记录时，可在<a href="/zh/docs/guide/feature-guide/user/log#筛选日志并查看统计" target="_blank" rel="noopener noreferrer">使用日志</a>中点击「展开」，在「请求 ID」中填写该编号查找。
</Accordion>

<Accordion title="调用失败，但使用日志中没有这次请求">
**说明**：以下请求在调用模型之前即被拒绝，不扣费，也不产生使用日志记录：
- API 密钥校验未通过，如「无效的令牌」「您的 IP 不在令牌允许访问的列表中」「用户已被封禁」。
- 无权访问分组或模型、无可用渠道、达到请求数限制，或请求格式错误。
- 额度不足，如「用户额度不足」「预扣费额度失败」。

其他失败的请求仅在站点开启错误日志记录后显示为「错误」记录。

**处理方法**：
1. 根据提示原文，在本页或对应页面的常见问题中查找原因。
2. 需要管理员排查时，请提供提示末尾的「(request id: …)」。
3. 失败的请求与日志记录的关系见<a href="/zh/docs/guide/feature-guide/user/log#常见问题" target="_blank" rel="noopener noreferrer">使用日志</a>。
</Accordion>

</Accordions>

## 账号与登录

登录、注册、验证和登录状态的问题。

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="提示「会话已过期！」，或被退出登录">
**提示原文**：「会话已过期！」（英文 Session expired!），随后回到登录页。

**可能原因**：
- 自登录起已满 30 天。
- 在其他设备的「安全与访问」页撤销了该会话，或点击了「退出其他会话」。
- 在其他设备上修改了密码，启用或禁用了两步验证，重新生成了备用码，或注册、解绑了 Passkey。
- 通过忘记密码重置了密码，或管理员重置了账户的两步验证或 Passkey。

**处理方法**：
1. 重新登录。
2. 不是本人的操作时，登录后立即修改密码，并在<a href="/zh/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">审计日志</a>中核对登录记录。
3. 登录状态的保持时间和会话管理见<a href="/zh/docs/guide/feature-guide/user/security#管理登录会话" target="_blank" rel="noopener noreferrer">安全与访问</a>。
</Accordion>

## 界面与显示

页面打不开、找不到菜单和显示相关的问题。

<Accordion title="页面显示「403」「禁止访问」，或「404」「糟糕！页面未找到！」">
**提示原文**：「禁止访问」（英文 Access Forbidden），下方为「您没有必要的权限 查看此资源。」；或「糟糕！页面未找到！」（英文 Oops! Page Not Found!），下方为「您要查找的页面似乎 不存在或可能已被移除。」

**可能原因**：
- 打开了账户无权访问的页面，如收藏夹或他人发来的管理页面地址。
- 打开的地址不存在，如旧版本的地址或输入错误。

**处理方法**：
1. 点击「返回」或「返回主页」。
2. 从侧边栏或顶部导航打开需要的页面，入口位置见<a href="/zh/docs/guide/feature-guide/user/quick-start#认识控制台界面" target="_blank" rel="noopener noreferrer">快速上手</a>。
3. 需要访问管理页面时，请联系管理员。
</Accordion>

<Accordion title="页面显示「糟糕！出错了」或「请求过于频繁」">
**提示原文**：「糟糕！出错了」（英文 Oops! Something went wrong），下方为「请稍后再试。」；或「请求过于频繁」（英文 Too many requests），下方为「请稍候再试。」。操作按钮时也可能只提示一句含 429 的英文（仅英文）。

**可能原因**：
- 站点刚升级，浏览器仍在使用旧版本的页面文件。
- 网络中断。
- 同一网络出口（如学校、公司或代理）短时间内访问次数过多，站点按来访地址限制访问频率，默认 3 分钟内最多打开 120 次页面、调用 360 次接口。

**处理方法**：
1. 等待几分钟后刷新页面。
2. 仍然出错时，强制刷新页面（Windows 按 Ctrl+F5，Mac 按 ⌘+Shift+R），或清除该站点的浏览器缓存后重试。
3. 如仍无法解决，请联系管理员。
</Accordion>

<Accordion title="页面中的时间与所在地区的时间不一致">
**说明**：使用日志、审计日志等页面中的时间，按浏览器所在电脑的时区显示；每日签到按服务器的日期计算；概览和数据看板的统计按整点小时汇总。

**处理方法**：
1. 检查电脑的时区和时间设置。
2. 签到日期和统计时段与本地时间不同时，以服务器时间为准。
</Accordion>

</Accordions>
