## 筛选任务

**操作流程：**
1. 点击页面标题下方的「任务日志」或「绘图日志」标签。
2. 点击「时间范围」，选择快捷范围；或填写「起始时间」「结束时间」后点击「确认」。
3. 按需填写任务 ID：「任务日志」标签填写「按任务 ID 筛选」，「绘图日志」标签填写「按 MjProxy 任务 ID 筛选」。
4. 点击「搜索」，或在输入框中按回车键。
5. 需要清除筛选条件时，点击「重置」。

<Callout type="info" title="提示">
- 默认仅显示今天 00:00:00 至当前时间后 1 小时内提交的任务，查找更早的任务请先调整时间范围。
- 修改筛选条件后需点击「搜索」才会生效。页面不会自动刷新，查看任务的最新状态请点击「搜索」。
</Callout>

**筛选项说明：**

筛选区只有一行，两个标签仅任务 ID 输入框不同。下表按筛选区中的顺序排列。

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 筛选项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 时间范围 | 按任务的提交时间筛选，起止时间均包含在内。 | 快捷范围：「今天」「7 天」（含今天）、「本周」（周日至周六）、「30 天」（含今天）、「本月」；手动填写时精确到秒，填好后点击「确认」。 | 今天 00:00:00 至当前时间后 1 小时 |
| 按任务 ID 筛选 | 按任务 ID 查找「任务日志」标签中的任务。 | 选填，按完整 ID 匹配，可在「任务 ID」列点击复制。 | 空 |
| 按 MjProxy 任务 ID 筛选 | 按任务 ID 查找「绘图日志」标签中的任务。 | 选填，按完整 ID 匹配。 | 空 |
| 渠道 ID（仅管理员可见） | 按处理任务的渠道筛选。 | 仅在「全部」视图中显示，填写渠道 ID 数字。 | 空 |

## 查看任务详情和制品

- 任务日志-任务详情

![任务日志-任务详情页面](/assets/guide/feature-guide/general-task-logs-task-details.png)

**查看详情操作流程：**
1. 在「任务日志」标签中，点击任务所在行「详情」列的「查看详情」。
2. 在「任务详情」窗口中查看任务信息；失败的任务在「失败原因」中查看完整原因。

**查看制品操作流程：**
1. 在状态为「成功」的任务所在行，点击「制品」列的「制品」；部分音乐、视频任务点击「点击预览音乐」「点击预览视频」。
2. 在窗口中预览图片、播放视频或音频。
3. 点击「下载」，在新标签页中打开并保存文件。

<Callout type="warn" title="及时下载生成结果">
- 制品每次都从上游获取，上游的文件过期或被删除后，将无法预览和下载，请及时下载保存。
- 预览失败时显示「媒体预览失败，请重试。」，点击「重试」重新加载。
</Callout>

## 查看提示词、图片和失败原因

- 任务日志-提示词详情

![任务日志-提示词详情页面](/assets/guide/feature-guide/general-task-logs-drawing-logs-prompt-details.png)

**查看提示词操作流程：**
1. 在「绘图日志」标签中，点击任务所在行「提示」列的文字。
2. 在「提示词详情」窗口中查看「提示」；有英文翻译时，下方显示「提示词 (英文)」。

1. 点击任务所在行「失败原因」列的红色文字。

图片保存在上游，上游删除或过期后，「图片预览」窗口显示「无法加载图像」。
</Callout>

## 查看失败任务的退款

**操作流程：**
1. 在「任务日志」标签中，点击失败任务所在行的「查看详情」，确认「失败原因」并复制任务 ID；绘图任务在「绘图日志」标签的「任务 ID」列复制。
2. 打开<a href="/zh/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">使用日志</a>，在类型下拉框中选择「退款」，将时间范围设为任务失败的时间段后点击「搜索」。
3. 点击退款记录「详情」列的「异步任务退款」，在「退款详情」中核对任务 ID 和原因。

**退款规则：**

提交任务时先按价格扣除额度，任务失败或超时后全额退回原扣费来源（钱包余额或订阅额度），所用 API 密钥的额度一并退回，并在使用日志中产生一条「退款」记录：

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| 情形 | 「失败原因」显示 | 退款 |
| --- | --- | --- |
| 上游返回任务失败 | 上游返回的原因，可能为英文 | 全额退回 |
| 上游找不到该任务 | 「上游找不到这个任务」 | 全额退回 |
| 连续多次查询不到任务状态 | 「查询上游任务状态失败」 | 全额退回 |
| 提交后超过 3 天（默认）仍未完成 | 「任务超时」 | 全额退回 |
| 2026 年 2 月 22 日之前提交的任务超时 | 「任务超时（旧系统遗留任务，不进行退款，请联系管理员）」 | 不退款，请联系管理员 |
| 任务所用的渠道已不可用 | 「获取渠道信息失败，请联系管理员」 | 请在使用日志中确认是否有退款记录，无退款记录时将任务 ID 发给管理员 |
| 绘图任务失败 | 上游返回的原因 | 全额退回，退款原因为「构图失败」 |
| 绘图任务提交后超过 1 小时仍未完成 | 「上游任务超时（超过1小时）」 | 全额退回，退款原因为「构图失败」 |
</div>

<Callout type="info" title="提示">
- 请勿仅凭「失败」状态判断是否已退款，请以使用日志中的「退款」记录为准。
- 成功的任务按实际用量结算：实际用量低于提交时扣除的额度时，差额作为「退款」记录退回；高于时补扣一条「消耗」记录。
</Callout>

| 排队中 | 上游已接收任务，正在排队等待处理。 | 以黄色或橙色显示，含义相同。 |

## 常见问题

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="任务一直显示「排队中」或「进行中」">
**可能原因**：
- 视频、音乐和绘图生成需要几十秒到几分钟，上游繁忙时更久。
- 任务状态由后台定期查询后更新，存在延迟。
- 页面不会自动刷新。

**处理方法**：
1. 点击「搜索」查看最新状态。
2. 继续等待。提交后超过 3 天（默认）仍未完成的任务会标记为「失败」并退回额度；绘图任务为 1 小时。
3. 如长时间无变化，请将任务 ID 发给管理员。
</Accordion>

<Accordion title="任务状态为「失败」">
**说明**：「失败原因」可能是上游返回的原文（可能为英文），也可能是以下系统提示：

| 提示原文 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 「任务超时」（英文 Task timed out） | 提交后超过 3 天（默认）仍未完成。 | 重新提交任务；在使用日志中确认退款。 |
| 「上游找不到这个任务」（英文 Upstream task not found） | 上游已无该任务的记录。 | 重新提交任务；在使用日志中确认退款。 |
| 「查询上游任务状态失败」（英文 Failed to query the upstream task status） | 连续多次无法查询到任务状态。 | 稍后重新提交；在使用日志中确认退款。 |
| 「获取渠道信息失败，请联系管理员」（英文 Failed to get the channel information. Please contact the administrator） | 任务所用的渠道已不可用。 | 在使用日志中查找该任务的退款记录，无退款记录时将任务 ID 发给管理员。 |
| 「上游任务超时（超过1小时）」（英文 Upstream task timed out (over 1 hour)） | 绘图任务提交后超过 1 小时仍未完成。 | 重新提交任务；在使用日志中确认退款。 |
| 「任务超时（旧系统遗留任务，不进行退款，请联系管理员）」（英文 Task timed out (a task left by the old system is not refunded; contact the administrator)） | 2026 年 2 月 22 日之前提交的任务超时。 | 联系管理员。 |
| 上游返回的其他原因，如提示词含敏感内容、歌词含版权内容 | 上游拒绝或生成失败。 | 按原因修改提示词等内容后重新提交。 |
</Accordion>

<Accordion title="失败的任务是否扣费">
**说明**：提交任务时先扣除额度；任务失败或超时后，额度全额退回原扣费来源（钱包余额或订阅额度），所用 API 密钥的额度一并退回，并在使用日志中产生「退款」记录。

**处理方法**：
1. 按[查看失败任务的退款](#查看失败任务的退款)的步骤，在使用日志中核对「退款」记录。
2. 未找到退款记录时，请将任务 ID 发给管理员。
</Accordion>

<Accordion title="「制品」无法预览或下载">
**提示原文**：「媒体预览失败，请重试。」（英文 Media preview failed. Please try again.）、「无法预览」（英文 Preview unavailable）或「制品加载失败」（英文 Failed to load artifacts）

**可能原因**：
- 上游保存的文件已过期或被删除。
- 网络中断或上游暂时不可用。

**处理方法**：
1. 点击「重试」。
2. 能打开时，请及时点击「下载」保存文件。
3. 如仍失败，请将任务 ID 发给管理员。
</Accordion>

<Accordion title="「制品」列显示「结果未保留」">
**说明**：鼠标悬停在「结果未保留」上时显示以下提示。

**提示原文**：「结果已在接口响应中返回，未保存为制品」（英文 The result was returned in the API response and was not saved as an artifact）

**可能原因**：该任务的结果已在提交时的接口响应中直接返回，系统未保存。

**处理方法**：
1. 在调用接口的程序中保存接口返回的结果。
</Accordion>

<Accordion title="找不到某个任务">
**可能原因**：
- 时间范围仍为默认的今天；时间范围按任务的提交时间筛选。
- 任务 ID 未填写完整，任务 ID 按完整内容匹配。
- 查看的标签不对：视频、音乐等任务在「任务日志」标签，Midjourney 绘图任务在「绘图日志」标签。
- 管理员选择了「仅自己」，而要找的是其他用户的任务。

**处理方法**：
1. 将时间范围调整为提交任务的时间段，点击「搜索」。
2. 粘贴完整的任务 ID 后重新搜索。
3. 切换到另一个标签查找。
</Accordion>

<Accordion title="看不到「绘图日志」或「任务日志」标签">
**可能原因**：
- 左侧边栏设置中关闭了「绘图日志」或「任务日志」，两个都开启时才显示标签。
- 管理员关闭了其中一项功能。

**处理方法**：
1. 到「个人资料」页的「左侧边栏个人设置」区域中，开启「控制台区域」和「绘图日志」「任务日志」并保存。
2. 开启后仍不显示时，请联系管理员。
</Accordion>

<Accordion title="任务 ID 下方的操作显示「未知」">
**说明**：页面仅能识别部分任务类型，如「生成音乐」「生成歌词」，其他类型显示为「未知」，不影响任务的执行和扣费。
</Accordion>

<Accordion title="成功的任务在使用日志中有「退款」或额外的「消耗」记录">
**说明**：部分任务在成功后按实际用量结算。实际用量低于提交时扣除的额度时，差额作为「退款」记录退回；高于时补扣一条「消耗」记录。这类「退款」不表示任务失败。

**处理方法**：
1. 在使用日志中打开该「退款」记录的详情，在「退款详情」中查看任务 ID 和原因。
2. 提交任务时的「消耗」记录不显示任务 ID，请按提交时间和模型对应。
</Accordion>

<Accordion title="任务记录会保存多久">
**说明**：任务和绘图记录不会被自动删除。生成的图片、视频、音频保存在上游，上游删除或过期后无法再预览和下载，请及时下载保存。
</Accordion>

</Accordions>
