- 仅 Root 可访问，从侧边栏「管理员」→「系统信息」进入。

- 本页只用于查看和清理；系统任务由渠道管理、运维配置中的操作或系统自动创建。

<Callout type="info" title="提示">
- 实例指一个 New API 进程，按 `NODE_NAME` 区分。
- 定时后台任务只由 Master 实例执行；Worker 实例正常上报实例信息，但不领取系统任务。
- 系统任务是一轮后台维护、检测或轮询批次，不等同于用户提交的一条绘图、音乐或视频任务。例如，`异步任务轮询` 表示后台执行了一轮业务任务状态轮询，而不是某个用户异步任务本身。
</Callout>

| 最后上报 | 最近一次成功写入实例心跳的时间。 | 由系统自动记录。 | 页面显示相对时间，悬停可查看完整时间。 |

<Callout type="info" title="提示">
- CPU、内存和存储使用率旁的圆环使用固定颜色帮助快速浏览：低于 70% 为绿色，70% 至不足 90% 为黄色，90% 及以上为红色。

</Callout>

## 常用操作

本节介绍查看实例与同步状态、清理失联实例记录，以及筛选与清理历史任务。

### 查看实例与同步状态

- 系统信息-实例监控

![系统信息-实例监控页面](/assets/guide/feature-guide/system-information-instance-monitoring.png)

每个 New API 进程启动后都会立即尝试上报一次实例信息，之后固定每 30 秒上报一次。

**操作流程：**
1. 在「实例」面板查看各实例的状态、角色和资源占用。
2. 将鼠标悬停在「同步」列的状态上，查看该节点各同步项的状态和错误。
3. 实例名称旁显示黄色警示图标时，点击查看「配置 NODE_NAME」示例。

<Callout type="info" title="提示">
- 悬停列出的同步项随部署而变，见[节点同步](#节点同步)。
- 失联的实例和未上报同步信息的旧版本节点，「同步」列显示 `-`。
</Callout>

### 清理失联实例记录

- 系统信息-清理失联实例

![系统信息-清理失联实例页面](/assets/guide/feature-guide/system-information-delete-instance.png)

删除失联实例仅清理数据库中的实例状态记录，不会停止或重启实例，也不会影响实例正在处理的业务请求。若实例仍在运行并恢复上报，记录会自动重新创建。

**删除单个失联实例操作流程：**
1. 在实例列表中找到状态为「失联」的实例。
2. 确认该实例已经下线，或旧记录不再需要保留。
3. 点击行末的删除按钮。
4. 在确认框中点击「删除」。

**删除全部失联实例操作流程：**
1. 检查当前列表中的全部失联实例，确认它们不再需要保留。
2. 点击面板右上角的「删除所有失联」。
3. 在确认框中点击「删除」。

<Callout type="info" title="提示">
- 「删除所有失联」仅在列表中存在失联记录时显示。
- 确认框标题都是「删除失联实例」；删除全部时提示「删除 … 条失联实例记录？在线实例不会被删除。」
- 删除全部的成功提示显示实际删除的数量。
</Callout>

### 筛选与清理历史任务

**操作流程：**
1. 在「历史任务」标题下方用「所有类型」和「所有状态」下拉框筛选，状态可选「已成功」或「已失败」；点击「重置」清除筛选。
2. 点击右侧的「清理历史任务」。
3. 在确认框中点击「删除」。

<Callout type="warn" title="注意">
- 清理范围是所有分页中符合当前筛选条件的历史任务，不只是当前页。
- 进行中的任务和每种类型最新的一条记录始终保留，系统据此安排下一次定时任务。
- 清理无法撤销；成功提示显示实际清理的条数。
</Callout>

### 节点同步

保存设置、渠道等数据后，各节点通过同步任务载入修改；实例表的「同步」列和「…同步」任务都反映这一过程。

**同步项：**
- 设置、权限、插件、登录方式、模型各节点都会同步。
- 渠道：仅在启用内存缓存的节点和 Master 实例上同步。设置环境变量 `MEMORY_CACHE_ENABLED=true` 或启用 Redis 即启用内存缓存。
- 订阅套餐：仅在未启用 Redis 时同步。是否启用 Redis 由环境变量 `REDIS_CONN_STRING` 决定。
- 「同步」列的悬停列出本站各节点同步项的合集；节点不同步某一项（如未启用内存缓存的 Worker 实例的渠道）时，该项直接读取数据库或共享缓存，显示「已同步」。

**载入规则：**
- 各节点每 3 秒检查一次同步任务，发现新的修改即重新载入，并立即上报，「同步」列随之更新，不必等 30 秒的实例上报。
- 载入失败时，该节点显示「更新失败」并记录错误，下一轮重试；载入成功后错误自动清除。
- 同步任务写入失败或集群中有旧版本节点时，设置、权限和渠道缓存按同步周期（由环境变量 `SYNC_FREQUENCY` 调整，单位秒，默认 60 秒）重新载入作为兜底；其他同步项的兜底时间各不相同，见<a href="/zh/docs/guide/feature-guide/system-settings/system-setting#生效范围与多实例同步" target="_blank" rel="noopener noreferrer">生效范围与多实例同步</a>。

**「…同步」任务的完成：**
- Master 实例约每 15 秒检查一次：在线且同步该项的节点都已载入时，任务变为「已成功」，进度为 100%。
- 仍在等待时，「进度」为已载入节点的比例，「详情」显示载入失败的节点和错误。
- 失联超过 90 秒的节点不计入。
- 没有运行中的 Master 实例时，「…同步」任务一直是「等待中」；各节点仍每 3 秒载入，修改已生效。

### 任务执行与保留

系统任务只由 Master 实例执行；记录按下列规则保留。

**执行规则：**
- Master 实例约每 15 秒检查一次：领取等待中的任务，并为到期的定时任务创建新任务。
- 手动发起的任务立即唤醒处理该请求的 Master 实例；处理该请求的节点不是 Master 实例时，由 Master 实例约 15 秒内领取。
- 同类型已有进行中的任务时，不再新建。
- 执行实例每 20 秒续期一次 60 秒的任务锁；锁到期未续期时，任务标为「已失败」，详情为 `task lease expired`。
- 没有运行中的 Master 实例时，任务停在「等待中」。Worker 实例不领取系统任务。

**保留规则：**
- 手动清理历史任务时，进行中的任务和每种类型最新的一条记录始终保留。
- 系统每天自动删除早于「已结束任务保留天数」（默认 30 天）的已结束任务，每种类型最新的一条保留，见<a href="/zh/docs/guide/feature-guide/system-settings/settings-operations#日志维护" target="_blank" rel="noopener noreferrer">运维配置</a>。

## 保存与生效

本页没有保存按钮。删除和清理在确认框中点击「删除」后立即执行，无法撤销；系统任务由 Master 实例领取执行。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 操作 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 删除单个失联实例 | 点击行末删除按钮，在确认框中点击「删除」 | 立即从数据库删除该实例记录；只删除超过 90 秒未上报的记录，确认时已恢复上报的实例不会被删除。 |
| 删除所有失联实例 | 点击「删除所有失联」，在确认框中点击「删除」 | 立即删除当前超过 90 秒未上报的全部记录，成功提示显示实际删除的数量。 |
| 清理历史任务 | 点击「清理历史任务」，在确认框中点击「删除」 | 立即删除符合当前筛选的已成功、已失败任务，不限当前页；进行中的任务和每种类型最新的一条始终保留。 |
| 实例状态 | 无需操作 | 实例每 30 秒上报一次，超过 90 秒未上报显示「失联」；刷新后看到的状态最多落后一个上报周期。 |
| 手动发起的系统任务 | 在<a href="/zh/docs/guide/feature-guide/admin/channel" target="_blank" rel="noopener noreferrer">渠道管理</a>或<a href="/zh/docs/guide/feature-guide/system-settings/settings-operations#日志维护" target="_blank" rel="noopener noreferrer">运维配置</a>中发起 | 先显示「等待中」：处理该请求的节点是 Master 实例时立即开始，否则由 Master 实例约 15 秒内领取；同类型已有进行中的任务时不再新建。 |
| 定期系统任务 | 由系统自动调度 | Master 实例约每 15 秒检查一次是否到期，到期后创建新任务。 |
| 「…同步」任务 | 由系统在保存对应数据时自动创建 | 各节点约 3 秒内检查并载入；在线且同步该项的节点都载入后，Master 实例在下一轮检查时把任务标为「已成功」，见[节点同步](#节点同步)。 |
| 任务记录清理 | 由系统自动调度 | 每天一次；运维配置中修改「已结束任务保留天数」后，下一次清理按新值执行。 |

</div>

**补充说明：**
- **记录会重建**：删除失联实例只清理数据库中的实例记录，不会停止实例；实例仍在运行时，下一次上报会重新创建记录。

## 注意事项

- **「失联」不等于已下线**：只表示超过 90 秒没有上报，数据库短暂不可用或网络中断时也会出现；删除所有失联记录前，先确认这些节点已下线。
- **系统任务只由 Master 实例执行**：Worker 实例不领取系统任务；没有运行中的 Master 实例时，任务停在「等待中」，见[任务执行与保留](#任务执行与保留)。
- **节点名需唯一**：多个实例使用相同的 `NODE_NAME` 时写入同一条记录，状态互相覆盖。

## 常见问题

<Accordion title="实例显示「失联」">
**说明**：「失联」表示超过 90 秒没有上报心跳。

**可能原因**：
- 该实例的进程已停止。
- 该实例无法写入数据库，上报失败。

**处理方法**：
1. 检查该实例的进程和数据库连接，以及服务端日志。
2. 确认该实例已下线后，再删除该记录，见[清理失联实例记录](#清理失联实例记录)。
</Accordion>

<Accordion title="实例列表的数量少于实际部署的实例">
**可能原因**：多个实例使用了相同的 `NODE_NAME`，写入同一条记录。未设置 `NODE_NAME` 时使用主机名，名称旁显示黄色警示图标。

**处理方法**：
1. 为每个实例设置唯一的 `NODE_NAME`，然后重启这些实例。
</Accordion>

<Accordion title="删除失联实例时提示 instance is not stale or no longer exists">
**提示原文**：`instance is not stale or no longer exists`（仅英文）

**可能原因**：
- 打开确认框后，该实例已恢复上报。
- 该记录已被其他管理员删除。

**处理方法**：
1. 点击「刷新」，重新查看实例状态。
2. 实例仍在运行但不再需要时，先停止该实例。
</Accordion>

<Accordion title="系统任务一直是「等待中」">
**说明**：Master 实例约每 15 秒领取一次等待中的任务。

**可能原因**：
- 当前没有运行中的 Master 实例。`NODE_TYPE=slave` 的实例为 Worker，不领取系统任务。此时「…同步」任务也一直等待，但各节点仍会载入修改。
- 「…同步」任务在某个在线节点载入失败或尚未载入时保持「等待中」。

**处理方法**：
1. 确认至少有一个 Master 实例在运行，见[任务执行与保留](#任务执行与保留)。
2. 同步任务等待时，查看实例表「同步」列的悬停信息和任务「详情」中的错误，并检查该节点的服务端日志；该节点失联超过 90 秒后不再计入。
</Accordion>

<Accordion title="系统任务「已失败」，详情为 task lease expired">
**提示原文**：`task lease expired`（仅英文）

**可能原因**：执行该任务的实例在 60 秒的任务锁到期前没有续期，如进程退出或无法写入数据库。

**处理方法**：
1. 根据「执行实例」查看该实例的服务端日志。
2. 定时任务会在下次调度时再次执行；手动任务需重新发起。
</Accordion>

<Accordion title="清理历史任务后仍有记录，或提示已清理 0 条">
**提示原文**：「已清理 0 条历史系统任务」（英文 Deleted 0 historical system tasks）

**说明**：每种类型最新的一条记录和进行中的任务始终保留，系统据此安排下一次定时任务。只剩这些记录时，清理结果为 0 条。
</Accordion>

<Accordion title="「同步」列显示「更新失败」">
**说明**：该节点有同步项载入失败，修改在该节点尚未生效。

**可能原因**：该节点载入某一同步项时出错，例如读取数据库失败；具体原因以悬停中的错误原文为准。

**处理方法**：
1. 将鼠标悬停在「更新失败」上，查看出错的同步项和错误原文。
2. 检查该节点的服务端日志和数据库连接。
3. 该节点每 3 秒自动重试，载入成功后恢复为「已同步」。
</Accordion>

</Accordions>
