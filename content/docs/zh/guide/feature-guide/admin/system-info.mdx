- 系统信息仅 Root 可访问，从侧边栏「管理员」 → 「系统信息」或访问 `/system-info` 进入。
- 用于观察当前部署中的 New API 实例和跨实例系统任务，并清理失联实例记录与历史系统任务。

## 系统信息概览

- 系统信息-实例与系统任务

![系统信息-实例与系统任务页面](/assets/guide/feature-guide/system-information.png)

页面由「实例」和「系统任务」两个面板组成。

| 区域 | 主要用途 | 自动刷新规则 | 可执行操作 |
| --- | --- | --- | --- |
| 实例 | 展示当前部署实例的运行状态、资源使用情况及心跳上报信息，帮助管理员监控各实例的健康状况。| 固定每 30 秒刷新。 | 手动刷新；删除单条或全部失联记录。 |
| 系统任务 | 用于查看跨实例运行的系统维护任务及其执行状态，便于管理员了解任务进度和历史执行情况。 | 存在等待中或运行中的任务时每 8 秒刷新；空闲时暂停，需点击「刷新」查看新任务。 | 手动刷新；筛选和清理历史任务。 |

## 实例监控

- 系统信息-实例监控

![系统信息-实例监控页面](/assets/guide/feature-guide/system-information-instance-monitoring.png)

每个 New API 进程启动后都会立即尝试上报一次实例信息，之后固定每 30 秒上报一次。

### 实例字段说明

| 界面字段 | 数据来源 | 含义 | 注意事项 |
| --- | --- | --- | --- |
| 实例 | `NODE_NAME`；未设置时回退为操作系统主机名 | 实例上报和数据库记录使用的节点身份。第二行显示实际主机名，便于辅助识别。 | 多个实例使用相同节点名时会写入同一条记录，导致状态互相覆盖。未设置 `NODE_NAME` 时，名称旁显示黄色警示图标，点击可查看配置示例。 |
| 状态 | 最近一次上报时间 | 「在线」表示最近一次上报未超过 90 秒；「失联」表示超过 90 秒没有上报。 | 这是应用心跳状态，不代表所有上游、数据库或 Redis 均健康。 |
| 角色 | `NODE_TYPE` | `NODE_TYPE=slave` 时显示 `worker`；未设置或填写其他值时显示 `master`。 | 只有 Master 启动系统任务执行器；Worker 仍会正常上报实例信息。 |
| CPU | 性能监控器的最近一次 CPU 采样 | 该实例的 CPU 使用百分比。 | 不是严格实时数据；关闭性能监控后显示为 0%，不代表实例空闲。 |
| 内存 | 性能监控器的最近一次内存采样 | 该实例的内存使用百分比。 | 在容器中优先按容器的内存配额计算，取不到时按宿主机的内存使用率计算；两种口径都不是 New API 单进程独占的内存。 |
| 存储 | 磁盘缓存路径所在文件系统 | 显示使用率；悬停后还可查看已用、可用和总空间。 | 未配置磁盘缓存路径时，统计系统临时目录所在文件系统；不代表数据库容量或全部磁盘。 |
| 版本 | 该实例进程的编译或运行版本 | 该实例实际运行的 New API 版本。 | 多实例升级时可用于识别版本不一致。 |
| 运行环境 | Go 运行时的 `GOOS/GOARCH` | 例如 `linux/amd64`。 | 不表示 Linux 发行版、容器镜像标签或宿主机型号。 |
| 启动时间 | 该实例进程的启动时间 | 该实例本次运行的开始时间。 | 实例重启后会更新。 |
| 最后上报 | `last_seen_at` | 最近一次成功写入实例心跳的时间。 | 页面显示相对时间，悬停可查看完整时间。 |
| 操作 | 当前实例状态 | 只有失联实例提供删除按钮。 | 在线实例不能从此页面删除。 |

<Callout type="info" title="提示">
  - CPU、内存和存储使用率旁的圆环使用固定颜色帮助快速浏览：低于 70% 为绿色，70% 至不足 90% 为黄色，90% 及以上为红色。
  - 性能监控启用时，CPU 和内存约每 5 秒采样一次（优先按容器 cgroup 配额计算），实例每 30 秒上报最近一次采样值。关闭性能监控后，CPU 和内存显示为 0%，存储仍正常统计。开关与阈值见<a href="/zh/docs/guide/feature-guide/system-settings/settings-operations#性能" target="_blank" rel="noopener noreferrer">运维配置 › 性能</a>；判断异常时应同时查看最后上报时间和外部监控。
</Callout>

## 清理失联实例记录

- 系统信息-清理失联实例

![系统信息-清理失联实例页面](/assets/guide/feature-guide/system-information-delete-instance.png)

删除失联实例仅清理数据库中的实例状态记录，不会停止或重启实例，也不会影响实例正在处理的业务请求。若实例仍在运行并恢复上报，记录会自动重新创建。

### 删除单个失联实例

1. 在实例列表中找到状态为「失联」的实例。
2. 确认该实例已经下线，或旧记录不再需要保留。
3. 点击行末的删除按钮。
4. 在确认框中点击「删除」。
5. 删除成功后，页面重新请求实例列表。

### 删除全部失联实例

1. 检查当前列表中的全部失联实例，确认它们不再需要保留。
2. 点击面板右上角的「删除所有失联」。该按钮仅在列表中存在失联记录时显示。
3. 在确认框中点击「删除」。成功提示会显示实际删除的记录数。

## 系统任务

系统任务是一轮后台维护、检测或轮询批次，不等同于用户提交的一条绘图、音乐或视频任务。例如，`异步任务轮询` 表示后台执行了一轮业务任务状态轮询，而不是某个用户异步任务本身。

面板分为「进行中任务」和「历史任务」两部分：前者列出等待中或运行中的任务；后者列出已成功或已失败的任务，最新的在前，每页 20 条。

### 系统任务类型

| 页面名称 | 后端类型 | 来源与触发方式 | 创建条件与行为 |
| --- | --- | --- | --- |
| 日志清理 | `log_cleanup` | Root 在<a href="/zh/docs/guide/feature-guide/system-settings/settings-operations" target="_blank" rel="noopener noreferrer">运维配置</a>的「日志维护」中选择时间并手动发起。 | 按每批 100 条清理指定时间以前的数据库日志；使用 ClickHouse 日志库时由一次同步 mutation 完成。同类型已有活动任务时，入口会继续跟踪现有任务。 |
| 渠道批量测试 | `channel_test` | 在<a href="/zh/docs/guide/feature-guide/admin/channel" target="_blank" rel="noopener noreferrer">渠道管理</a>手动执行「测试所有渠道」，或在<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#渠道健康" target="_blank" rel="noopener noreferrer">请求策略配置</a>中开启「定期渠道测试」后按「测试间隔 (分钟)」周期触发。 | 自动任务需要开启「定期渠道测试」。手动触发遇到同类型活动任务时会被拒绝，不会再创建并行批次。 |
| 上游模型批量更新 | `model_update` | 在渠道管理中执行「检测所有上游更新」，或由后台周期任务触发。 | 只处理已启用且开启上游模型检测的渠道。自动任务的默认计划间隔为 30 分钟；手动触发遇到同类型活动任务时会被拒绝。 |
| 绘图任务轮询 | `midjourney_poll` | 系统自动调度；页面辅助标识显示为 `drawing_task_poll`。 | `UPDATE_TASK` 开启且至少存在一个未完成的 Midjourney 任务时，以 15 秒任务间隔参与调度；空闲时不创建记录。 |
| 异步任务轮询 | `async_task_poll` | 系统自动调度。 | `UPDATE_TASK` 开启且至少存在一个未完成的 Suno 或视频任务时，以 15 秒任务间隔参与调度；空闲时不创建记录。 |

### 任务字段说明

| 界面字段 | 数据来源 | 含义 | 页面边界 |
| --- | --- | --- | --- |
| 类型 | 系统任务 `type` | 显示中文名称，并在下方显示任务标识。 | 未识别的新任务类型会直接显示原始标识。 |
| 状态 | `status` | 等待中、运行中、已成功或已失败。 | 状态表示本批系统任务的生命周期，不直接代表每个处理项的业务结果。 |
| 进度 | `state.progress` | 有有效数字时显示 `0–100%`。 | 不提供数字进度的任务显示 `-`；页面不展示 `processed` 和 `total` 明细。 |
| 执行实例 | `locked_by` | 领取任务的 Master 执行器标识。 | 格式通常为节点名加随机后缀，不应当作纯粹的 `NODE_NAME` 使用。 |
| 更新时间 | `updated_at` | 最近一次领取、进度写入或结束状态的时间。 | 不是独立的开始时间或完成时间。 |
| 详情 | `error` | 失败任务的错误文本。 | 成功任务通常显示 `-`；这里不是完整结果摘要或独立任务日志。 |

<Callout type="info" title="提示">
  **已成功** 表示系统任务批次正常结束，不保证批次内每个渠道或业务任务都成功。渠道测试、模型检测和异步轮询会把局部失败写入结果摘要或服务端日志。
</Callout>

### 筛选与清理历史任务

1. 在「历史任务」标题下方用「所有类型」和「所有状态」下拉框筛选，状态可选「已成功」或「已失败」；点击「重置」清除筛选。
2. 点击右侧的「清理历史任务」。历史任务为空时该按钮不可用。
3. 在确认框中点击「删除」。成功提示会显示实际清理的条数。

清理范围是所有分页中符合当前筛选条件的历史任务，不只是当前页。进行中的任务和每种类型最新的一条记录始终保留，系统据此安排下一次定时任务。清理无法撤销。

## 保存与生效

本页没有保存按钮。删除和清理在确认框中点击「删除」后立即执行，无法撤销；系统任务由 Master 实例领取执行。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 操作 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 删除单个失联实例 | 点击行末删除按钮，在确认框中点击「删除」 | 立即从数据库删除该实例记录；只删除超过 90 秒未上报的记录，确认时已恢复上报的实例不会被删除。 |
| 删除所有失联实例 | 点击「删除所有失联」，在确认框中点击「删除」 | 立即删除当前超过 90 秒未上报的全部记录，成功提示显示实际删除的数量。 |
| 清理历史任务 | 点击「清理历史任务」，在确认框中点击「删除」 | 立即删除符合当前筛选的已成功、已失败任务，不限当前页；进行中的任务和每种类型最新的一条始终保留。 |
| 实例状态 | 无需操作 | 实例每 30 秒上报一次，超过 90 秒未上报显示「失联」；刷新后看到的状态最多落后一个上报周期。 |
| 手动发起的系统任务 | 在<a href="/zh/docs/guide/feature-guide/admin/channel" target="_blank" rel="noopener noreferrer">渠道管理</a>或<a href="/zh/docs/guide/feature-guide/system-settings/settings-operations#日志维护" target="_blank" rel="noopener noreferrer">运维配置</a>中发起 | 先显示「等待中」：处理该请求的节点是 Master 实例时立即开始，否则由 Master 实例约 15 秒内领取；同类型已有进行中的任务时不再新建。 |
| 定期系统任务 | 由系统自动调度 | Master 实例约每 15 秒检查一次是否到期，到期后创建新任务。 |

</div>

### 补充说明

- **记录会重建**：删除失联实例只清理数据库中的实例记录，不会停止实例；实例仍在运行时，下一次上报会重新创建记录。

## 注意事项

- **「失联」不等于已下线**：只表示超过 90 秒没有上报，数据库短暂不可用或网络中断时也会出现；删除所有失联记录前，先确认这些节点已下线。
- **系统任务只由 Master 实例执行**：Worker 实例不领取系统任务；没有运行中的 Master 实例时，任务停在「等待中」，见[实例字段说明](#实例字段说明)的「角色」。
- **节点名需唯一**：多个实例使用相同的 `NODE_NAME` 时写入同一条记录，状态互相覆盖。

<Accordion title="实例显示「失联」">
**说明**：「失联」表示超过 90 秒没有上报心跳。

**可能原因**：
- 该实例的进程已停止。
- 该实例无法写入数据库，上报失败。

**处理方法**：
1. 检查该实例的进程和数据库连接，以及服务端日志。
2. 确认该实例已下线后，再删除该记录，见[清理失联实例记录](#清理失联实例记录)。
</Accordion>

<Accordion title="实例列表的数量少于实际部署的实例">
**可能原因**：多个实例使用了相同的 `NODE_NAME`，写入同一条记录。未设置 `NODE_NAME` 时使用主机名，名称旁显示黄色警示图标。

**处理方法**：
1. 为每个实例设置唯一的 `NODE_NAME`，然后重启这些实例。
</Accordion>

<Accordion title="删除失联实例时提示 instance is not stale or no longer exists">
**提示原文**：`instance is not stale or no longer exists`（仅英文）

**可能原因**：
- 打开确认框后，该实例已恢复上报。
- 该记录已被其他管理员删除。

**处理方法**：
1. 点击「刷新」，重新查看实例状态。
2. 实例仍在运行但不再需要时，先停止该实例。
</Accordion>

<Accordion title="系统任务一直是「等待中」">
**说明**：Master 实例约每 15 秒领取一次等待中的任务。

**可能原因**：当前没有运行中的 Master 实例。`NODE_TYPE=slave` 的实例为 Worker，不领取系统任务。

**处理方法**：
1. 确认至少有一个 Master 实例在运行，见[实例字段说明](#实例字段说明)。
</Accordion>

<Accordion title="系统任务「已失败」，详情为 task lease expired">
**提示原文**：`task lease expired`（仅英文）

**可能原因**：执行该任务的实例在 60 秒的任务锁到期前没有续期，如进程退出或无法写入数据库。

**处理方法**：
1. 根据「执行实例」查看该实例的服务端日志。
2. 定时任务会在下次调度时再次执行；手动任务需重新发起。
</Accordion>

<Accordion title="清理历史任务后仍有记录，或提示已清理 0 条">
**提示原文**：「已清理 0 条历史系统任务」（英文 Deleted 0 historical system tasks）

**说明**：每种类型最新的一条记录和进行中的任务始终保留，系统据此安排下一次定时任务。只剩这些记录时，清理结果为 0 条。
</Accordion>

</Accordions>
