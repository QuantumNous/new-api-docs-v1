## 常用操作

本节介绍添加、编辑、排序、启停和删除实例，以及试运行和在渠道中添加实例。

### 添加与编辑实例

- 请求处理-添加请求处理

![请求处理-添加请求处理页面](/assets/guide/feature-guide/request-processing-add-instance.png)

**添加操作流程：**
1. 点击页面右上角「添加」。
2. 在「添加请求处理」对话框中点击一个插件卡片。
3. 需要时点击对话框顶部名称旁的铅笔图标修改实例名称。名称默认与插件名相同，最多 64 个字符，清空后恢复为插件名。
4. 在「设置」中填写插件的设置项，各内置插件的设置见[内置请求处理插件](#内置请求处理插件)。
5. 在「用在哪里」中，第一行选择适用范围，第二行选择适用的模型，选项见本节末的表。
6. 需要时在右侧「试一试」中选择「示例请求」或「粘贴请求」，点击「运行」。
7. 确认左下角「已启用」开关，点击「保存」。

<Callout type="info" title="提示">
- 对话框标题下方显示「选一个插件开始，设置之后随时可以改。」
- 插件卡片显示插件的说明和运行阶段，运行阶段如「读取请求前」「发送前」「检查回复」。
- 卡片还显示出错时的处理：「出错时跳过」或「出错时拒绝请求」。
- 已有实例的插件，卡片上显示「已添加 … 个」。
- 选错插件时，点击左下角「换个插件」重新选择。名称和设置恢复为新插件的默认值，「用在哪里」和「已启用」保留。
- 设置不符合要求时，该项下方显示原因，如「此项必填」。
- 服务端校验未通过时，「用在哪里」下方显示「请求处理实例 … 的设置无效：…」，对话框保持打开。
- 保存成功后对话框关闭，新实例添加到列表末尾。
- 点击「取消」不保存，再次打开时不保留未保存的改动。
</Callout>

### 调整顺序、启用或删除实例

以下操作在实例列表中直接进行，每次操作立即保存整张列表，成功时没有提示。

**列表内操作：**
- 调整顺序：点击「顺序」列序号右侧的上移、下移按钮。
- 启用或停用：点击「已启用」列的开关。保存失败时开关恢复原状。
- 修改设置：见[添加与编辑实例](#添加与编辑实例)。

**删除实例操作流程：**
1. 点击实例所在行末的删除图标。
2. 在「删除实例？」确认框中点击「删除」。

<Callout type="warn" title="注意">
- 确认框提示「… 将停止处理请求，包括添加了它的渠道。」，删除后无法恢复。
- 删除不会从渠道中移除对它的引用，渠道中显示「已删除」，见[在渠道中添加实例](#在渠道中添加实例)。
- 保存失败时弹出服务端的错误原文，列表不变。
- 常见的失败原因是有已启用的实例使用了已停用的插件，见[实例状态](#实例状态)。
</Callout>

### 试运行

- 请求处理-试运行

![请求处理-试运行页面](/assets/guide/feature-guide/request-processing-dry-run.png)

「试运行」用示例请求运行已保存的实例，不发往上游，也不计费。「内容审核」实例会实际调用审核接口。

**操作流程：**

4. 在「请求体」中填写示例请求，点击「运行」。
5. 查看「结果」。

<Callout type="info" title="提示">
- 只运行已保存且已启用的实例，不运行「检查回复」阶段。
- 遇到拒绝请求或使请求失败的出错时停止，后面的实例不再运行。
- 关闭对话框后再打开，所有输入恢复默认值。
</Callout>

### 在渠道中添加实例

「用在哪里」为「只在渠道添加」的实例，只在添加了它的渠道上运行。其他实例添加到渠道后，也会在该渠道的请求上运行。

**操作流程：**
1. 在<a href="/zh/docs/guide/feature-guide/admin/channel" target="_blank" rel="noopener noreferrer">渠道管理</a>中编辑渠道，打开「请求与响应」页签。
2. 在「覆盖规则」中找到「请求处理插件」，从「添加实例」下拉框中选择实例。
3. 需要时用上移、下移按钮或拖动调整顺序，点击 × 移除实例。
4. 点击「更新渠道」保存。

<Callout type="info" title="提示">
- 「请求处理插件」字段只对拥有「绑定任务插件」权限的账号显示。
- 修改「请求处理插件」属于渠道的敏感项。
- 实例已因「所有请求」或分组在该请求上运行过时，不会再次运行。
</Callout>

## 规则与机制

本节说明实例的运行阶段和顺序、请求被拦截时的处理和记录，以及六个内置请求处理插件的设置。

### 运行阶段与顺序

每个插件声明自己在哪些阶段运行，阶段显示在插件卡片和实例对话框顶部。

**运行阶段说明：**
- 「读取请求前」：收到请求后、选择渠道前，检查或修改客户端的请求；渠道添加的实例在选定渠道后运行。
- 「转换格式前」：选定渠道后、把请求转换为渠道的格式之前。
- 「发送前」：每次发往渠道之前，早于渠道的参数覆盖。
- 「最终检查」：渠道的参数覆盖之后，检查即将发往上游的请求，只能拒绝，不能修改。
- 「检查回复」：检查模型的回复，命中时中止回复。

**运行顺序：**
- 列表上方的说明为「实例从上到下运行：先运行对所有请求生效的实例，再运行请求所在分组的实例，最后运行渠道添加的实例。」
- 每组内按列表顺序运行，渠道添加的实例按渠道中的顺序运行。
- 顺序不同，结果可能不同，修改顺序后用[试运行](#试运行)检查。
- 对所有渠道生效的参数规则用[全局参数覆盖](#全局参数覆盖)实例设置。

### 内置请求处理插件

New API 内置以下六个请求处理插件（随版本更新，以实际列表为准）。也可以在<a href="/zh/docs/guide/feature-guide/admin/task-plugins" target="_blank" rel="noopener noreferrer">插件管理</a>中上传或从插件市场安装其他请求处理插件。

**插件说明：**

「出错时」为「拒绝请求」的插件运行出错时，请求被拒绝，见[拦截与日志](#拦截与日志)；为「跳过」的插件跳过该实例，请求照常发送。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 插件 | 运行阶段 | 出错时 | 用途 |
| --- | --- | --- | --- |
| 请求过滤（`request-filter`） | 读取请求前、最终检查、检查回复 | 拒绝请求 | 拒绝文本命中关键词或正则表达式的请求，见[请求过滤](#请求过滤)。 |
| 请求脱敏（`request-redact`） | 读取请求前、最终检查、检查回复 | 拒绝请求 | 发送前替换请求文本中的个人信息和密钥，见[请求脱敏](#请求脱敏)。 |
| 内容审核（`content-moderation`） | 读取请求前、检查回复 | 拒绝请求 | 使用 OpenAI 兼容的审核接口检查用户内容，拒绝被标记的请求，见[内容审核](#内容审核)。 |
| 全局参数覆盖（`param-override`） | 发送前 | 拒绝请求 | 对所有请求、指定分组或指定模型应用参数覆盖规则，见[全局参数覆盖](#全局参数覆盖)。 |
| 自动推理强度（`auto-reasoning`） | 转换格式前 | 跳过 | 根据请求的规模设置推理强度，见[自动推理强度](#自动推理强度)。 |
| 图片压缩（`image-compress`） | 发送前 | 跳过 | 发送到上游前压缩请求中的大图片，见[图片压缩](#图片压缩)。 |

</div>

各插件的设置见下面各小节，「默认值」为新建实例时的值。

### 请求过滤

- 请求处理-请求过滤配置

![请求处理-请求过滤配置页面](/assets/guide/feature-guide/request-processing-add-request-filtering.png)

拒绝文本命中关键词或正则表达式的请求。在「读取请求前」检查请求中的全部文本：各角色的消息、系统提示词、工具定义和调用参数、工具结果、提示词，以及附带的文本、PDF、DOCX 文件；在「最终检查」阶段再检查一次即将发往上游的请求，渠道参数覆盖加入的文本也在其中。命中时客户端收到 HTTP 400、错误码 `request_rejected`，消息为「拒绝提示」，末尾附 `(code: request_filtered)`。

**配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |

| 规则 › 关键词或表达式 | 要匹配的关键词或正则表达式 | 必填，1–1024 个字符；正则表达式以 `(?i)` 开头时不区分大小写；表达式无效时无法保存 | — |
| 规则 › 匹配方式 | 「关键词」或「正则表达式」 | — | 关键词 |
| 规则 › 区分大小写 | 是否区分大小写 | — | 关闭 |
| 规则 › 规则 ID | 命中时记录在使用日志中 | 选填，最多 64 个字符；留空时按顺序编号为 rule-1、rule-2… | 空 |
| 关键词列表 | 每行一个，请求中出现任意一个时拒绝 | 选填，适合大量关键词；只命中关键词列表时，日志中记为 keywords | 空 |

| 拒绝提示 | 返回给客户端的提示 | 选填，最多 256 个字符；留空时为「请求被策略拒绝」；输入框中的灰字是示例 | 空 |
| 检查回复 | 同时中止命中规则的模型回复 | 中止时客户端收到错误码 `response_rejected`；流式回复会暂缓发出末尾一小段文字，以免关键词被拆在两段之间而漏检 | 关闭 |

</div>

### 请求脱敏

- 请求处理-请求脱敏配置

![请求处理-请求脱敏配置页面](/assets/guide/feature-guide/request-processing-add-request-redaction.png)

在「读取请求前」把请求文本中的个人信息和密钥替换为替换文本，再继续处理请求。替换范围是消息、系统提示词和提示词，不含工具定义；先按「内置类型」替换，再按「自定义规则」替换。附带的文本文件一并替换；PDF、DOCX 等文件无法改写，其中含有此类信息时按「发送前检查」处理。

**配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 内置类型 | 要替换的信息类型：邮箱地址、电话号码、身份证号、银行卡号、API 密钥和令牌、IPv4 地址 | 点击标签选择，可多选；电话号码指中国大陆手机号和带 + 的国际号码；身份证号、银行卡号通过校验位才替换 | 除「IPv4 地址」外全选 |
| 自定义规则 | 在内置类型之后应用的正则表达式；点击「添加规则」逐条添加 | 选填，最多 50 条 | 无 |
| 自定义规则 › 正则表达式 | 匹配到的文本会被替换 | 必填，1–1024 个字符；表达式无效时无法保存 | — |
| 自定义规则 › 替换文本 | 该规则的替换文本 | 选填，最多 64 个字符；留空时使用「默认替换文本」 | 空 |
| 自定义规则 › 规则 ID | 命中时记录在使用日志中 | 选填，最多 64 个字符；留空时按顺序编号 | 空 |
| 默认替换文本 | 替换每处匹配的文本 | 最多 64 个字符 | `[REDACTED]` |
| 发送前检查 | 即将发送的请求仍含此类信息时的处理方式：「拒绝请求」或「关闭」 | 「拒绝请求」时，以下情况拒绝请求，消息为「请求被策略拒绝」，末尾附 `(code: sensitive_content)`：「最终检查」阶段发现请求仍含此类信息（如渠道参数覆盖加入的）；附带的文件无法改写；需要替换的位置超过 512 处、无法全部替换。「关闭」时这些情况都照常发送，无法全部替换时只替换前 512 处 | 拒绝请求 |
| 遮盖回复 | 同时遮盖模型回复中的这些类型和规则 | 回复中匹配的文字统一替换为 `***`，不使用替换文本；流式回复会暂缓发出末尾一小段文字 | 关闭 |

</div>

<Callout type="info" title="提示">
「IPv4 地址」默认不选：版本号、示例地址与 IPv4 地址形式相同，容易被误替换。
</Callout>

### 内容审核

- 请求处理-内容审核配置

![请求处理-内容审核配置页面](/assets/guide/feature-guide/request-processing-add-content-moderation.png)

在「读取请求前」把用户消息（以及其中的图片和附带文档的文字）发给 OpenAI 兼容的审核接口，被标记时拒绝请求：客户端收到 HTTP 400、错误码 `request_rejected`，消息为 `The request was flagged by content moderation (code: moderation.flagged)`（仅英文）。只检查用户消息和补全、嵌入、图片生成等请求的提示词，不检查系统提示词和工具。需要一个可访问的审核接口，例如 OpenAI 的审核接口。

**配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_td_code]:wrap-anywhere [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 审核接口地址 | 接受 OpenAI 审核请求的接口 | 必填，以 http:// 或 https:// 开头的完整地址，最多 2048 个字符 | `https://api.openai.com/v1/moderations` |
| API 密钥 | 调用审核接口的密钥，以 Bearer 令牌发送 | 选填，接口无需密钥时留空；最多 1024 个字符 | 空 |
| 审核模型 | 发给审核接口的模型名 | 留空时使用接口的默认模型；最多 128 个字符 | `omni-moderation-latest` |
| 检查的文本 | 发送给审核接口的用户消息：「最后一条用户消息」或「全部用户消息」 | 文本过长、无法全部送审时拒绝请求，消息为 `The request is too long for content moderation (code: moderation.too_long)`（仅英文） | 最后一条用户消息 |
| 检查图片 | 同时把用户消息中的图片发给审核接口 | 每个请求最多送审 3 张图片 | 开启 |
| 拦截的类别 | 只拒绝被标记为所选类别的请求，共 13 个类别，如「骚扰」「仇恨」「暴力」 | 点击标签选择，可多选；都不选时拒绝所有被标记的请求 | 都不选 |
| 审核回复 | 同时审核模型回复，被标记时中止回复 | 非流式回复整段送审；流式回复约每 1000 字送审一次，通过后才发给客户端。中止时客户端收到错误码 `response_rejected`，消息为 `The reply was flagged by content moderation (code: moderation.flagged)`（仅英文） | 关闭 |

</div>

<Callout type="warn" title="注意">
- 用户消息、图片和附带文档的文字会发送到「审核接口地址」，只填写可信任的服务。
- 每个请求都会调用审核接口，开启「审核回复」后回复也会，响应时间和审核接口的用量随之增加；在「试一试」「试运行」中运行时同样会调用。
- 审核接口无法访问、返回错误或单次调用超过 15 秒时，按运行出错处理：请求被拒绝，客户端收到 HTTP 500，见[拦截与日志](#拦截与日志)。
</Callout>

- 超过 20 MiB 或 4000 万像素的图片和 GIF 动图不处理。
- 每个请求最多压缩 32 张，其余原样发送。
</Callout>

## 保存与生效

本页没有统一的保存按钮：添加、编辑、删除、调整顺序和启停后，整张实例列表立即保存。实例保存为系统设置：处理该请求的节点立即生效，其他节点约 3 秒内随系统设置同步（最迟一个同步周期，默认 60 秒）。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 操作 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 添加、编辑实例 | 对话框中点击「保存」 | 下一次请求起按新设置运行。 |
| 调整顺序、启用、停用 | 点击上移、下移按钮或「已启用」开关，立即保存；成功时没有提示 | 下一次请求起按新顺序和状态运行。 |
| 删除实例 | 确认框「删除实例？」中点击「删除」；成功时没有提示 | 下一次请求起不再运行，添加了它的渠道也不再运行。 |
| 在渠道中添加实例 | 渠道抽屉中点击「更新渠道」 | 见<a href="/zh/docs/guide/feature-guide/admin/channel#保存与生效" target="_blank" rel="noopener noreferrer">渠道管理</a>。 |

</div>

**补充说明：**
- **试运行不保存**：「试运行」只用已保存的实例，对话框中的「试一试」只用当前未保存的设置，两者都不改变实例列表。
- **插件开关**：插件管理页的「启用插件」全局开关不影响请求处理；单个请求处理插件被停用后，使用它的实例不运行，设置保留，见[实例状态](#实例状态)。
- **保存失败**：列表操作保存失败时弹出服务端的错误原文，列表保持原状；对话框保存失败时，错误原文显示在「用在哪里」下方。

## 注意事项

- **删除会影响添加了它的渠道**：确认框提示「… 将停止处理请求，包括添加了它的渠道。」，删除后无法恢复。
- **拦截不重试**：实例拒绝的请求直接返回 HTTP 400，不换渠道重试，见[拦截与日志](#拦截与日志)。
- **顺序决定结果**：每组实例按列表顺序运行，顺序不同，结果可能不同；修改顺序后用「试运行」检查，见[运行阶段与顺序](#运行阶段与顺序)。
- **透传请求体时部分实例不运行**：渠道开启「透传请求体」或系统设置「全局模型配置」中开启「启用请求透传」时，请求原样发往上游，「转换格式前」「发送前」阶段的实例（自动推理强度、图片压缩、全局参数覆盖）不运行，渠道添加的实例在「读取请求前」也不运行；「最终检查」「检查回复」照常运行，「最终检查」检查原样请求。使用日志中，未运行的「发送前」实例和渠道添加实例的「读取请求前」标注「未检查」。
- **自动推理强度只用于支持推理的模型**：应在「用在哪里」第二行选择「指定模型」，只选支持推理的模型，见[自动推理强度](#自动推理强度)。
- **内容审核会发送用户文本**：用户消息、图片和附带文档的文字会发到设置中的审核接口地址，见[内容审核](#内容审核)。

<Accordion title="请求被拒绝，客户端收到 HTTP 400">
**提示原文**：「请求被策略拒绝 (code: …)」（英文 Request rejected by policy），或插件的提示加「(code: …)」；错误码 `request_rejected`。

**可能原因**：请求命中了某个请求处理实例的规则，例如「请求过滤」的关键词。

**处理方法**：
1. 在使用日志详情的「请求处理」区查看拦截的实例。
2. 在本页用「试运行」复现，按需修改实例设置、适用范围或停用实例。
</Accordion>

<Accordion title="客户端收到 HTTP 500，提示请求处理插件执行失败">
**提示原文**：「请求处理插件执行失败」（英文 A request plugin failed），错误码 `request_plugin_failed`。

**可能原因**：某个实例运行出错，例如「内容审核」的审核接口地址或密钥无效、无法访问，或超过 15 秒未响应。

**处理方法**：
1. 在本页用「试运行」复现，结果首行显示「… 运行失败：…」及原因。
2. 按原因修改该实例的设置，或暂时停用该实例。
</Accordion>

<Accordion title="实例没有生效">
**可能原因**：
- 实例未启用，或使用的插件已停用、未安装（列表中显示「插件已停用」），见[实例状态](#实例状态)。
- 请求的分组或模型不在实例的适用范围内。
- 实例为「只在渠道添加」，但处理请求的渠道没有添加它。
- 处理请求的渠道开启了透传请求体，「转换格式前」「发送前」阶段的实例不运行，见[注意事项](#注意事项)。

**处理方法**：
1. 用「试运行」填写相同的模型、分组和渠道 ID，查看哪些实例运行。
</Accordion>

<Accordion title="编辑渠道时看不到「请求处理插件」">
**可能原因**：当前账号没有「绑定任务插件」权限。

**处理方法**：
1. 由 Root 在<a href="/zh/docs/guide/feature-guide/admin/user#管理员权限" target="_blank" rel="noopener noreferrer">管理员权限</a>中授予。
</Accordion>

</Accordions>
