- 仅 Admin 和 Root 可访问，从侧边栏「管理员」→「兑换码」进入。
- 批量创建和分发额度兑换码，维护名称、额度、过期时间和启用状态，并清理已失效的兑换码。
- 创建兑换码前，需要 Root 先确认支付合规条款，见[权限与合规前置](#权限与合规前置)。

<Callout type="info" title="提示">
- 兑换码是一次性的额度凭证，用户在钱包页兑换后，额度计入其余额。
- 额度和过期时间在创建时填写；额度的显示单位由本站的计费设置决定。
- Admin 与 Root 在本页的操作权限相同；「管理员权限」中没有兑换码相关权限。
- 「系统设置」→「站点与品牌」→「侧边栏模块」→「管理员区域」只控制菜单入口是否显示，不撤销管理员权限。
- 需要禁止某位 Admin 使用兑换码功能时，只能调整其账户角色（如<a href="/zh/docs/guide/feature-guide/admin/user#角色状态" target="_blank" rel="noopener noreferrer">降级</a>为普通用户），或在部署侧做访问控制。
</Callout>

## 常用操作

本节按使用顺序介绍创建、复制和分发、编辑、启用或禁用兑换码，以及删除兑换码和清理无效兑换码。

### 创建兑换码

- 兑换码管理-创建兑换码

![兑换码管理-创建兑换码页面](/assets/guide/feature-guide/redemption-create.png)

- 兑换码管理-兑换码创建完成

![兑换码管理-兑换码创建完成页面](/assets/guide/feature-guide/redemption-save.png)

**前置条件：**
- Root 已确认当前版本的支付合规条款，见[权限与合规前置](#权限与合规前置)。

**操作流程：**
1. 点击页面右上角的「创建代码」。
2. 在「创建兑换码」抽屉中填写名称、额度、过期时间和数量。
3. 点击「保存更改」。
4. 在弹出的「兑换码创建完成」窗口中，需要保存发放清单时勾选「保存为文件」，并选择文件格式和包含的内容。
5. 点击「完成」。

<Callout type="warn" title="注意保管兑换码">
  完整兑换码等同于可转移的额度凭证。不要将其放入公开截图、群聊、工单、日志或代码仓库；批量创建后应记录发放对象和批次，未使用的明文副本也应限制访问。
</Callout>

**「兑换码创建完成」窗口说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 区域 | 显示条件 | 说明 |
| --- | --- | --- |
| 保存为文件 | — | 默认不勾选。 |
| 保存为 TXT、保存为 Markdown | 勾选「保存为文件」时 | 选择文件格式，默认「保存为 TXT」。<br/>TXT：每行一个兑换码，名称、兑换码、额度依次以 Tab 分隔，没有表头。<br/>Markdown：带表头的表格，列名为「名称」「代码」「额度」。 |
| 包含名称、包含额度 | 勾选「保存为文件」时 | 默认已勾选；取消后文件中不写入该项。 |
| 完成 | — | 勾选「保存为文件」时，下载以 `redemption-codes-` 开头的文件后关闭窗口；未勾选时只关闭窗口。 |

</div>

<Callout type="warn" title="注意">
- 窗口标题下方显示「成功创建了 … 个兑换码」。
- 点击右上角 × 或按 Esc 关闭窗口时，不下载文件。
- 该窗口只在创建成功后出现一次，之后列表不能再导出文件，见[复制和分发兑换码](#复制和分发兑换码)。
</Callout>

**配置项说明：**

抽屉不分区，下表按抽屉中的顺序排列。

<div id="兑换码配置项" className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 名称 | 兑换码的批次或用途标识。 | 1–20 个字符，超出时字段下方提示「名称必须介于 1 到 20 个字符之间」。<br/>创建时留空，保存时自动以额度的显示值（如 `$10`）作为名称。 | 空 |

### 复制和分发兑换码

**单个复制操作流程：**
1. 在目标行「兑换码」列点击复制图标（悬停提示「复制代码」）。

**批量复制操作流程：**
1. 勾选当前页需要复制的兑换码。
2. 点击页面底部批量操作栏中的复制图标（悬停提示「复制选定的代码」）。

**复制格式：**

批量复制的内容每行一个兑换码：

```text
名称<Tab>完整兑换码
```

<Callout type="info" title="提示">
- 点击脱敏的兑换码，可在弹出的「完整代码」中查看完整值。
- 本页没有兑换码导入功能，列表也不能导出文件。
- 文件只能在「兑换码创建完成」窗口中保存一次。
- 复制的内容和保存的文件应在受控环境中处理，避免把完整兑换码长期存放在普通表格或共享文档中。
</Callout>

### 编辑兑换码

- 兑换码管理-更新兑换码

![兑换码管理-更新兑换码页面](/assets/guide/feature-guide/redemption-update.png)

**操作流程：**
1. 点击目标行的编辑图标。
2. 在「更新兑换码」抽屉中修改名称、额度或过期时间。

<Callout type="info" title="提示">
- 只有「未使用」的兑换码可以编辑，其他状态的编辑图标为灰色。

### 启用或禁用兑换码

**操作流程：**
1. 点击目标行的 ⋯ 菜单。
2. 选择「禁用」或「启用」。

<Callout type="info" title="提示">
- 「未使用」的兑换码菜单中显示「禁用」，「已禁用」的显示「启用」。
- 「已使用」和「已过期」的兑换码菜单中只有「删除」。
- 点击后直接提交，没有确认框。
- 已过了过期时间的「已禁用」兑换码，启用后显示为「已过期」，仍无法兑换。
</Callout>

### 删除兑换码

**单条删除操作流程：**
1. 点击目标行的 ⋯ 菜单并选择「删除」。
2. 在「您确定吗？」确认框中点击「删除」。

**批量删除操作流程：**
1. 勾选当前页需要删除的兑换码。
2. 点击页面底部批量操作栏中的红色删除图标（悬停提示「删除选中的兑换码」）。
3. 在「删除 … 个兑换码？」确认框中点击「删除」。

<Callout type="warn" title="注意">
- 删除不区分状态，「未使用」的兑换码也会被删除。
- 删除后没有恢复入口。只是暂时停止发放时，请使用「禁用」。
</Callout>

### 删除无效兑换码

- 兑换码管理-删除无效兑换码

![兑换码管理-删除无效兑换码页面](/assets/guide/feature-guide/redemption-delete-invalid.png)

「删除无效」是全局清理操作，不受当前搜索、筛选和勾选的影响。

**清理范围：**
- 「已使用」的兑换码；
- 「已禁用」的兑换码；
- 未被禁用、但已超过过期时间的兑换码（按服务器时间判断）。

**操作流程：**
1. 点击页面右上角的「删除无效」。
2. 在「删除无效的兑换码？」确认框中点击「删除无效」。

<Callout type="warn" title="注意">
- 清理后没有恢复入口。
- 「已禁用」的兑换码也会被清理。仍需日后启用的兑换码，请勿在此前执行「删除无效」。
</Callout>

## 规则与机制

本节说明创建兑换码和用户兑换的前提，以及兑换时的校验与结果。

### 权限与合规前置

**合规规则：**
- Root 需在「系统设置」→「计费与支付」→「支付网关」中确认当前版本的支付合规条款，管理员才能创建兑换码，用户的钱包页也才会显示兑换入口。<a href="/zh/docs/guide/feature-guide/system-settings/settings-billing#支付合规确认" target="_blank" rel="noopener noreferrer">详见：支付合规确认</a>
- 合规状态需同时满足「已确认」和「条款版本为当前版本」。
- 确认操作只能通过 Root 的控制台会话完成，访问令牌不能代替该会话。
- 合规未确认或条款版本不匹配时，已有兑换码仍可查看、编辑、启用、禁用和删除，但创建兑换码和用户兑换会被拒绝。

### 兑换规则

用户在钱包页的「有兑换码吗？」区域输入兑换码兑换，操作见<a href="/zh/docs/guide/feature-guide/user/wallet#兑换码" target="_blank" rel="noopener noreferrer">钱包</a>。

**校验与结果：**
- 只有「未使用」的兑换码可以兑换，即未被禁用且未过期；是否过期按服务器时间判断。
- 同一个兑换码在重复或并发请求中最多成功一次。
- 兑换成功后，兑换码变为「已使用」，并记录兑换人和兑换时间。
- 额度计入该用户的余额，其使用日志中记录一条「充值」类型的记录，只含兑换码 ID。
- 兑换失败时，用户端统一提示「兑换失败，请稍后重试」，不区分原因，见[常见问题](#常见问题)。

## 状态项说明

### 兑换码状态

兑换码列表的「状态」列显示以下状态：

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 状态 | 含义 | 备注 |
| --- | --- | --- |
| 未使用 | 未被禁用，并且尚未过期，可以被用户兑换。 | 绿色。可编辑、禁用和删除。 |
| 已禁用 | 管理员已暂停使用；重新启用后，只要仍在有效期内即可兑换。 | 灰色，整行置灰。可启用和删除。是否过期不影响此状态的显示。 |
| 已使用 | 已成功绑定一位用户并增加其额度，不能再次兑换。 | 灰色，整行置灰。只能删除。 |
| 已过期 | 未被禁用，但设置的过期时间已经早于当前时间。 | 黄色，整行置灰。只能删除。<br/>列表按浏览器的当前时间显示此状态；「状态」筛选、「删除无效」和用户兑换按服务器时间判断，两者可能短暂不一致。 |

</div>

## 保存与生效

兑换码只保存在数据库中，没有缓存；下表操作在各节点从下一次兑换起生效。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 创建兑换码 | 「创建兑换码」抽屉中点击「保存更改」，随后弹出「兑换码创建完成」<br/>创建 1 个：提示「兑换码创建成功」<br/>创建多个：提示「成功创建了 … 个兑换码」 | 立即可兑换。 |
| 编辑 | 「更新兑换码」抽屉中点击「保存更改」，提示「兑换码更新成功」 | 立即生效，只影响之后的兑换，已兑换的不变。 |
| 启用、禁用 | ⋯ 菜单中点击后直接提交，没有确认框；提示「兑换码已启用」或「兑换码已禁用」 | 立即生效；已兑换到账的额度不受影响。 |
| 单条删除、批量删除、删除无效 | 在确认框中确认<br/>单条删除：提示「兑换码删除成功」<br/>批量删除：提示「成功删除 … 个兑换码」<br/>删除无效：提示「已成功删除 … 个无效兑换码」 | 立即生效，删除后无法兑换，也没有恢复入口；已兑换到账的额度不会收回。 |
| 过期 | 无需操作 | 到达过期时间后无法兑换，按服务器时间判断；列表中的「已过期」按浏览器的当前时间显示。 |

</div>

## 注意事项

- **完整兑换码等同于额度凭证**：分发和保存方式见[创建兑换码](#创建兑换码)中的提示。
- **删除没有恢复入口**：暂停发放请使用「禁用」；「删除无效」会清理本站全部已禁用的兑换码，见[删除无效兑换码](#删除无效兑换码)。
- **审计记录**：创建、编辑、启用或禁用、删除（包括单条删除、批量删除和删除无效）兑换码会产生审计记录，可在<a href="/zh/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">审计日志</a>页面查询，不会写入「使用日志」。
- **服务端错误日志含原始兑换码**：使用日志中的兑换记录只含兑换码 ID；用户兑换失败时，服务端错误日志会记录其提交的原始兑换码，部署方应限制日志访问，并按自身合规要求做好保护或脱敏。
- **用户兑换受关键接口限流**：同一 IP 的兑换请求与登录、注册、找回密码、充值下单等操作共用一个计数，默认 1200 秒内最多 20 次，超出后请求被拒绝。启用 Redis 时各节点共用计数，否则各节点分别计数。
- **限流由环境变量调整**：`CRITICAL_RATE_LIMIT` 为次数（默认 20），`CRITICAL_RATE_LIMIT_DURATION` 为窗口（单位秒，默认 1200），`CRITICAL_RATE_LIMIT_ENABLE` 默认为 `true`、设为 `false` 时不限流。三者只在启动时读取，修改后需重启；本页没有对应设置，见<a href="/zh/docs/guide/feature-guide/system-settings/settings-security#速率限制" target="_blank" rel="noopener noreferrer">安全与限制配置</a>。

<Accordion title="创建兑换码时提示支付、兑换码、订阅计划和邀请返利功能已禁用">
**提示原文**：「支付、兑换码、订阅计划和邀请返利功能已禁用。管理员需先确认合规声明后方可启用。」（英文 Payment, redemption, subscription, and invitation reward features are disabled. The administrator must confirm compliance terms before enabling them.）

**可能原因**：Root 尚未确认支付合规条款，或已确认的条款版本不是当前版本。

**处理方法**：
1. 请 Root 在「系统设置」→「计费与支付」→「支付网关」中确认合规条款，见<a href="/zh/docs/guide/feature-guide/system-settings/settings-billing#支付合规确认" target="_blank" rel="noopener noreferrer">支付合规确认</a>。
2. 重新创建兑换码。
</Accordion>

<Accordion title="创建或编辑兑换码时提示参数不合法">
**说明**：名称、额度和数量由抽屉先行校验，提示显示在对应字段下方；额度为 0 和过期时间早于当前时间由服务端校验，保存时弹出提示。

| 提示原文 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 「名称必须介于 1 到 20 个字符之间」 | 名称超过 20 个字符，或编辑时名称为空。 | 修改名称。 |
| 「配额必须是正数」 | 额度为负数。 | 填写大于 0 的额度。 |
| 「计数必须介于1和100之间」 | 「数量」超过 100 或为负数。 | 分批创建。 |
| 「兑换码额度必须大于 0」（英文 Redemption quota must be positive） | 额度为 0。 | 填写大于 0 的额度。 |
| 「过期时间不能早于当前时间」（英文 Expiration time cannot be earlier than current time） | 过期时间早于当前时间。 | 重新选择过期时间，或选择「永不」。 |
</Accordion>

<Accordion title="用户反映兑换时提示「兑换失败，请稍后重试」">
**提示原文**：「兑换失败，请稍后重试」（英文 Redemption failed, please try again later）

**说明**：用户端不区分失败原因。

**可能原因**：
- 兑换码不存在或已被删除。
- 兑换码已使用、已禁用或已过期。
- 数据库短暂出错。

**处理方法**：
1. 在列表中按名称或 ID 查找该兑换码，核对状态和过期时间。
2. 「已禁用」的兑换码先启用；「已使用」「已过期」的兑换码无法再次兑换，需另行创建。
3. 用户侧的处理见<a href="/zh/docs/guide/feature-guide/user/wallet#常见问题" target="_blank" rel="noopener noreferrer">钱包</a>。
</Accordion>

<Accordion title="创建兑换码时提示「创建兑换码失败，请稍后重试」">
**提示原文**：「创建兑换码失败，请稍后重试」（英文 Failed to create redemption code, please try again later）

**说明**：批量创建时逐个生成兑换码，中途出错即停止。出错前已生成的兑换码保留在列表中，但不会弹出「兑换码创建完成」窗口。

**可能原因**：写入数据库失败，如数据库短暂出错。

**处理方法**：
1. 在列表中按名称搜索本次创建的兑换码，核对已生成的数量。
2. 按需复制已生成的兑换码，或将其删除。
3. 重新创建所需数量的兑换码。
</Accordion>
