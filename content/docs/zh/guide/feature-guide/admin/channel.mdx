渠道是 New API 连接上游 AI 服务的配置单元。管理员可访问 `/channels`或从侧边栏进入「渠道」。<br/>
本页仅说明渠道页面的配置和维护。<br/>
模型目录、价格与用户分组还需要结合[模型管理](/zh/docs/guide/feature-guide/admin/model)、[计费与支付配置](/zh/docs/guide/feature-guide/system-settings/settings-billing)和[用户管理](/zh/docs/guide/feature-guide/admin/user)共同配置。

### 搜索、筛选与显示

| 控件 | 说明 |
| --- | --- |
| 名称、ID 或密钥 | 搜索名称、渠道 ID、密钥或 Base URL；列表接口不会返回完整密钥。 |
| 模型、分组、类型 | 按渠道公开模型、分组或渠道类型筛选。 |
| 状态 | 「禁用」同时包含手动禁用和自动禁用，不能在此筛选器中进一步区分两者。 |
| 标签模式 | 按标签聚合渠道。聚合行不是单个渠道，不能当作普通渠道编辑。 |
| 敏感数据显示 | 只切换列表中的遮罩显示，不授予查看完整密钥的权限。完整密钥使用独立的 Root 安全验证入口。 |
| 批量操作 | 先开启选择模式，再对已选择的渠道执行启停、标签或删除；不会自动选中所有筛选结果。 |
| 使用 ID 排序、列设置、分页 | 调整列表排序、列显示和每页数量。分页选择只影响当前加载的行。 |

### 权限与安全边界

所有渠道接口先要求 Admin 或 Root，再按操作检查渠道权限。普通 Admin 的具体权限由 Root 在管理员权限矩阵中配置。

| 权限 | 主要操作 |
| --- | --- |
| `ChannelRead` | 查看列表、详情、模型列表、默认 Base URL、运行策略、余额/用量结果和 vLLM/SGLang 状态。 |
| `ChannelOperate` | 测试渠道、查询余额、启用或手动禁用、修复能力索引、检测上游模型更新、启停多 Key。 |
| `ChannelWrite` | 编辑模型、分组、映射、标签、备注、优先级、权重；应用上游模型更新。 |
| `ChannelSensitiveWrite` | 创建、删除、复制渠道；修改凭证、类型、Base URL、代理、请求头覆盖、参数覆盖和其他敏感配置；临时配置获取模型。 |
| `TaskPluginBind` | 创建或修改任务插件绑定，以及绑定到 New API 网关的插件扩展。 |
| Root 与安全验证 | 查看完整渠道密钥。该接口额外要求 Root、安全验证、限流和禁止缓存；不要把 `ChannelSecretView` 描述成当前密钥接口的独立路由权限。 |

<Callout type="warn">
  列表、截图、日志和工单中不要暴露 API Key、服务账号 JSON、代理密码、请求头凭证或 Codex OAuth JSON。编辑抽屉不会回填旧密钥；留空表示保留旧值，填写新值才替换。复制渠道会复制凭证，删除渠道或 Key 后没有恢复入口。
</Callout>

## 创建与编辑渠道

当前编辑器先选择提供商或插件，再进入四个配置页签：**连接与模型、路由与映射、请求与响应、其他设置**。保存时前端校验表单，后端再次检查渠道类型、凭证、插件绑定和高级配置。

### 选择服务商或插件

![选择内置渠道](/assets/guide/feature-guide/channel-management-select-provider-or-plugin-built-in.png)

![选择插件渠道](/assets/guide/feature-guide/channel-management-select-provider-or-plugin-plugin.png)

![选择网关渠道](/assets/guide/feature-guide/channel-management-select-provider-or-plugin-gateway.png)

![选择自定义渠道](/assets/guide/feature-guide/channel-management-select-provider-or-plugin-custom.png)

| 分类 | 身份与用途 | 创建时的关键差异 |
| --- | --- | --- |
| 内置渠道 | 由数值 `channel.type` 选择固定适配器，例如 OpenAI、Anthropic、Vertex、AWS、Gemini、Codex、vLLM 和 SGLang。 | 凭证格式、地址、`other` 字段和可用操作由类型决定；不能把所有内置类型都按普通 API Key 处理。 |
| 插件渠道 | 选择已安装且允许绑定的 Task Plugin；保存为 `type=61` 和 `setting.task_plugin_key`。 | 插件可能预填模型和 Base URL；插件是任务转发渠道，不是普通 API 适配器；需要 `TaskPluginBind`。 |
| 网关渠道 | New API 为 `type=60`，Sub2API 为 `type=59`。 | 填写网关 Base URL 和凭证，从网关获取模型；New API 仍可绑定支持 `new_api` 上游的插件扩展，但不会变成插件渠道。 |
| 自定义渠道 | Legacy Custom 为 `type=8`，Advanced Custom 为 `type=58`。 | Legacy Custom 是旧版完整 URL 接入并标记弃用；新配置优先使用 Advanced Custom，按入口路径配置上游、鉴权和转换器。 |

创建时插件分类只有在当前用户拥有绑定权限且插件加载成功时显示。搜索框也可以按内置类型编号查找自定义类型；这不是对任意类型都提供了适配器支持。

#### 四种创建方式的选择建议

- **标准供应商或协议**：选择内置渠道，使用该类型专属凭证和默认地址提示。
- **已安装任务插件**：选择 Plugins，确认插件的模型、上游类型和默认地址，再配置插件所需凭证。
- **New API/Sub2API 上游网关**：选择 Gateways；不要用 Legacy Custom 代替网关适配器。
- **多入口、多协议或多供应商**：选择 Advanced Custom；必须先设计入口路径、上游路径、鉴权和转换器。

### 连接与模型

![连接与模型](/assets/guide/feature-guide/create-channel-connection-and-models.png)

| 字段 | 必填或默认 | 说明 |
| --- | --- | --- |
| 名称 | 必填 | 管理员识别名称。插件新建时空名称可能使用插件名称预填。 |
| 类型/提供商 | 必填 | 决定适配器、凭证格式、默认地址、可用页签和专属校验。 |
| Base URL | 取决于类型 | 这是上游 Base URL，不是 `/v1/chat/completions` 等完整请求路径。New API、vLLM、SGLang 必须填写；Legacy Custom 的地址是旧版完整接入地址；Advanced Custom 使用相对上游路径时必须填写。 |
| API Key/凭证 | 新建必填 | 具体格式由类型决定。编辑时不回填旧值；留空保留原凭证。 |
| 模型 | 至少一项 | 逗号分隔的用户侧模型名；模型列表参与能力索引和路由。插件可能预填模型。 |
| 分组 | 默认 `default`，至少一项 | 只有用户或 API Key 具备相应分组，且其他模型条件满足时，渠道才可能被选中。 |
| 模型获取 | 仅支持的类型显示 | 从当前保存渠道或当前未保存的连接读取上游模型；获取结果只有在点击保存模型或保存渠道后才写入。 |
| 模型映射 | 可选 JSON 对象 | 将客户端模型名映射到上游模型名；值必须是字符串。映射目标通常不应同时放在公开模型列表中。 |

**连接与模型流程**

1. 选择类型后先阅读该类型的地址和凭证提示。
2. 填写名称、Base URL、凭证、模型和分组。
3. 对支持的类型点击获取模型，勾选实际可用模型并保存选择。
4. 如需映射，确认源模型在模型列表中；映射目标应由上游真实支持。
5. 保存渠道后，再进行测试，不要把表单中成功读取模型理解为渠道已完成可用性验证。

### 类型专属凭证

| 类型 | 凭证与专属字段 | 限制或注意事项 |
| --- | --- | --- |
| Vertex AI | `vertex_key_type` 可选服务账号 JSON 或 API Key；区域/项目配置保存在 `other`。 | JSON 模式可批量使用服务账号；API Key 模式只支持单密钥。`other` 需要有效 JSON，并包含 `default` 区域。 |
| AWS | `aws_key_type` 为 AK/SK 或 API Key；凭证提示包含区域。 | 按界面提示填写 `AccessKey|SecretAccessKey|Region` 或 `APIKey|Region`；不要把分隔符格式当作所有 AWS 错误都能在前端拦截。 |
| Azure | API Key、Base URL、默认 API 版本；可选 Responses API 版本。 | `other` 为必填的默认版本；模型名称通常对应 Azure deployment。 |
| Codex | OAuth JSON，至少包含 `access_token` 和 `account_id`。 | 只支持单密钥创建；编辑可刷新凭证；测试未指定端点时使用 Responses。 |
| vLLM/SGLang | 自托管 Base URL，API Key 或 `EMPTY`。 | 使用固定协议预设，HTTP/2 与模型检测按页面条件配置；不要把它们当作可任意编辑的 Advanced Custom 路由。 |
| Ollama | 默认使用本地/自托管地址，也可切换 OpenAI 兼容聊天端点。 | 模型拉取、删除和版本查询是 Ollama 专属操作，可能对上游模型产生副作用。 |

### 单密钥、批量创建与多 Key

| 模式 | 结果 | 适用注意 |
| --- | --- | --- |
| 单密钥 | 一个凭证创建一个渠道。 | 适合首次验证地址、模型和凭证。Codex 和 Vertex API Key 只允许此模式。 |
| 批量创建 | 每行一个凭证，创建多个独立渠道。 | 可按凭证前缀追加名称；每个新渠道独立参与路由。 |
| 多 Key 合并 | 多个凭证保存到一个渠道。 | 选择随机或轮询；轮询依赖缓存组件，后续在多 Key 管理中按 Key 维护状态。 |

### 路由与映射

![路由与映射](/assets/guide/feature-guide/create-channel-routing-and-mapping.png)

| 字段 | 默认或格式 | 说明 |
| --- | --- | --- |
| 模型映射 | 空或 JSON 对象 | 客户端名称 → 上游名称；支持批量生成规则。保存前检查源模型是否在 Models 列表中。 |
| 优先级 | 默认 `0` | 同模型、同分组候选中优先级较高的渠道先参与选择。不是全局重试次数。 |
| 权重 | 默认 `0` | 同优先级渠道的选择权重；不是严格固定比例，重试或渠道状态会改变实际结果。 |
| 测试模型 | 可选 | 快速测试未指定模型时使用；应填写该渠道实际支持的模型。 |
| 自动禁用 | 默认开启 | 可靠性失败时可能自动禁用；手动禁用和自动禁用是不同状态。 |

映射存在三类常见风险：JSON 无效、源模型不在公开列表、上游目标名称被公开给用户。保存时界面会提示缺失源模型，也会提示公开了映射目标；应先确认用户侧模型列表，再决定是否添加或移除名称。

### 请求与响应

![请求与响应](/assets/guide/feature-guide/create-channel-request-and-response.png)

#### 覆盖规则

| 字段 | 格式/默认 | 说明 |
| --- | --- | --- |
| 状态码映射 | 可选 JSON；状态码为 HTTP 整数 | 将上游响应映射为 New API 处理状态；新增可能改变重试行为，保存时可能需要确认。 |
| 参数覆盖 | 可选 JSON 或可视化规则 | 在发送前改写已转换的请求 JSON；支持字段设置、删除、移动、复制、字符串处理、条件和自定义错误。 |
| 请求头覆盖 | 可选 JSON 对象 | 设置、删除或复制上游请求头；支持 `{api_key}` 和完整值形式的 `{client_header:NAME}`。 |
| 请求体透传 | 默认关闭，按类型显示 | 尽量发送客户端原始请求体，会跳过部分转换、字段过滤和参数覆盖；开启前必须确认上游协议兼容。 |
| Responses WebSocket | 仅支持的类型显示 | 为对应 Responses WebSocket 路径启用连接；不能用参数覆盖的 `stream` 字段替代传输模式。 |
| 系统提示词 | 可选 | 添加或替换渠道级系统提示词；会改变发送给上游的语义。 |
| 强制格式化、思维到内容 | 按类型显示，默认关闭 | 处理特定请求/响应格式或将 reasoning 内容转换为 `<think>`；不是通用协议切换。 |

![参数覆盖可视化编辑器](/assets/guide/feature-guide/create-channel-request-and-response-parameter-overrides-visual-editor.png)

**透传与覆盖的执行边界**

- 全局或渠道级请求体透传会跳过正常转换链路；不要同时假设模型映射、参数覆盖和协议转换仍会按普通路径执行。
- 请求头透传使用 `*` 或 `re:`/`regex:` 规则复制客户端请求头，但会排除 Authorization、`x-api-key`、`x-goog-api-key`、WebSocket 握手和其他安全头。
- 请求头覆盖在透传之后应用，显式覆盖优先；`{client_header:NAME}` 必须是完整值，客户端未携带该头时不会加入。
- 请通过客户端请求选择流式模式。参数覆盖改写 JSON 中的 `stream` 不保证同步调整网关、适配器和上游的流式处理状态。

![请求体透传说明](/assets/guide/feature-guide/create-channel-pass-through-request-body-description.png)

![请求头透传说明](/assets/guide/feature-guide/create-channel-pass-through-request-headers-description.png)

### 其他设置

![其他设置](/assets/guide/feature-guide/create-channel-other-settings.png)

| 设置 | 默认或范围 | 说明 |
| --- | --- | --- |
| 代理地址 | 空；HTTP、HTTPS、SOCKS5、SOCKS5H | 代理地址必须包含有效主机；不要把代理密码写入备注或截图。 |
| HTTP 协议 | `auto` | 可协商 HTTP/2；选择 `http1` 时连接分片必须为 `1`。 |
| HTTP/2 连接分片 | `1–8`，默认 `1` | 将 HTTP/2 请求分布到多个连接；仅在 HTTP/2 模式有意义。 |
| 跳过任务轮询延迟 | 默认关闭 | 减少异步任务轮询间隔，但可能提高上游请求频率。 |
| 标签、备注 | 空；备注最多 255 字符 | 用于筛选和内部管理；不要写入密钥、用户隐私或临时凭证。 |
| 上游模型检查 | 默认关闭 | 仅支持模型获取的类型；启用自动同步前必须先启用检查。 |
| 忽略上游模型 | 逗号分隔的精确名称或 `regex:` 规则 | 排除不希望自动加入的模型；不要把它当作渠道模型的永久替代清单。 |

## 渠道类型专属配置

### 网关渠道：New API 与 Sub2API

![New API 网关渠道](/assets/guide/feature-guide/create-channel-newapi-gateway-channel.png)

New API 和 Sub2API 都通过网关 Base URL 拼接请求路径，普通配置不会自动补 `/v1`，因此 Base URL 不应以 `/v1` 结尾。两者可提供 OpenAI、Responses、Claude、Gemini 等网关能力；具体支持范围以网关实际部署为准。

New API 还可以绑定支持 `new_api` 上游的任务插件扩展。扩展仍保持 `type=60`，不能把它和独立插件渠道混淆。绑定、解绑和复制带扩展的渠道需要 `TaskPluginBind`。

### 独立插件渠道

![插件渠道](/assets/guide/feature-guide/create-channel-plugin-channel.png)

1. 在 Plugins 中选择已注册插件。
2. 核对插件名称、标识、预填模型和默认 Base URL。
3. 填写插件所需凭证、分组和其他字段。
4. 保存后按插件支持的任务流程验证；不要使用普通 API 渠道的测试结论替代插件验证。

插件默认地址为空时必须填写地址；插件模型是插件声明的初始值，不代表上游凭证已经可用。插件具体支持模型、路由和请求类型可能随安装版本变化。

### 高级自定义渠道

![高级自定义渠道](/assets/guide/feature-guide/create-channel-advanced-custom-channel.png)

选择 Advanced Custom 后，必须至少保留一条有效路由。打开路由编辑器：

![高级自定义路由](/assets/guide/feature-guide/create-channel-advanced-custom-channel-advanced-custom-routing.png)

| 路由字段 | 说明 |
| --- | --- |
| 入口路径 | 必须以 `/` 开头，不得包含查询字符串；例如 `/v1/chat/completions`。 |
| 上游路径 | 可以是完整 `http(s)` URL，也可以是相对路径；相对路径依赖渠道 Base URL。可在路径中使用 `{model}`，管理路由不得使用。 |
| 模型规则 | 空列表为该入口的兜底规则；普通名称精确匹配，`re:` 开头表示正则。具体规则应排在兜底规则前。 |
| 转换器 | 必须与入口协议匹配；原生转发使用 `none`。转换器路由不能启用请求体透传。 |
| 鉴权 | Default Bearer、No Auth、Header 或 Query；Header/Query 需要名称和值，值可使用 `{api_key}`。 |
| 模型列表路由 | 最多一条 `/v1/models`，必须使用原生转发；启用上游模型检查时必须存在。 |
| 余额路由 | 最多一条 `/v1/dashboard/billing/credit_grants`，不支持模型规则、转换器、透传或 `{model}`。 |

保存前检查入口与上游协议匹配、鉴权不会泄露、相对路径有 Base URL。路由配置错误会阻止保存或导致对应入口无法转发。


## 渠道操作

![渠道操作](/assets/guide/feature-guide/channel-management-channel-actions.png)

### 测试连接

快速测试使用渠道的 `test_model`；未配置时依次使用渠道模型和默认测试模型。详细测试允许选择端点、流式模式和模型。

![测试渠道连接](/assets/guide/feature-guide/channel-management-test-channel-connection.png)

1. 选择端点类型；自动检测会按渠道类型选择默认端点，Codex 未指定时使用 Responses。
2. 按需启用流式测试；Embedding、图片、Rerank 和 Responses Compact 不支持流式。
3. 选择单个或多个模型并执行测试。
4. 查看成功/失败、响应时间和错误详情。
5. 删除失败模型前确认失败不是临时网络、限流、代理、端点或价格配置问题。

批量测试前端每批最多运行 5 个模型；停止操作只停止后续批次，不保证取消已发出的请求。全部渠道测试是后台维护任务，不受当前列表筛选范围限制，已有同类任务时可能返回冲突。

### 查询余额与运行状态

![查询余额](/assets/guide/feature-guide/channel-management-check-balance.png)

普通渠道的余额查询按渠道类型调用不同上游接口，并非所有类型支持余额。全部余额更新遍历启用且非多 Key 渠道，可能产生大量上游请求；不会因为当前列表筛选而只处理可见行。vLLM/SGLang 的余额位置实际打开推理服务状态，不是普通余额查询；Codex 则显示用量和额度重置信息。

### 获取模型与上游模型更新

![获取模型](/assets/guide/feature-guide/channel-management-fetch-models.png)

1. 发起上游模型列表请求。
2. 在「新模型」「现有模型」「已移除模型」之间切换。
3. 按提供商分组，勾选单个或整组模型。
4. 点击「保存模型」后才写回渠道；取消或请求失败不会替换已保存列表。

已有渠道获取模型和创建/编辑表单使用临时凭证获取模型的权限不同：前者是 `ChannelOperate`，后者是 `ChannelSensitiveWrite`。

### 复制渠道

![复制渠道](/assets/guide/feature-guide/channel-management-duplicate-channel.png)

1. 选择复制渠道，填写名称后缀。
2. 确认是否重置余额和已用额度；页面默认后缀为 `_copy`，直接调用 API 的默认后缀可能不同。
3. 确认复制。新渠道会复制原渠道的大部分配置和凭证，并获得新的 ID 与创建时间。
4. 重新检查凭证、模型、分组、映射、路由和状态。

复制带任务插件绑定的渠道还需要绑定权限。复制完成后测试时间和响应时间会重置；不要将复制动作当作凭证轮换。

### 启用、禁用与删除

- 手动状态操作只接受启用或手动禁用；自动禁用由可靠性逻辑产生。
- 删除单个、批量删除和删除全部已禁用需要 `ChannelSensitiveWrite`。
- 「删除全部已禁用」按全库的手动/自动禁用状态删除，**不受当前搜索、类型、分组、标签或分页筛选限制**。
- 删除渠道会同步删除相关能力记录，无法从 New API 恢复；执行前导出或记录配置。

### 修复渠道一致性

![修复渠道一致性](/assets/guide/feature-guide/channel-management-fix-channel-consistency.png)

「修复渠道一致性」会根据全部渠道配置重建模型能力、分组、优先级和权重索引。过程中路由可能短暂不完整；建议低峰期执行，完成后刷新列表并测试代表性模型。它不会修复上游凭证、代理或模型价格问题。

### 标签与批量操作

![标签和批量操作](/assets/guide/feature-guide/channel-management-table-view.png)

批量选择操作作用于当前已选择的渠道 ID。按标签启停或编辑是独立的标签范围操作，不等于当前分页中已选行。批量测试、全部余额更新和上游更新可能产生大量请求或后台任务，应先确认维护窗口。

## 多 Key 渠道

### 创建与轮询模式

创建时选择「多 Key 合并」会把多个凭证保存到一个渠道；批量创建则会生成多个独立渠道。

| 模式 | 行为 |
| --- | --- |
| 单 Key | 一个凭证对应一个渠道。 |
| 批量创建 | 每行一个凭证，可按凭证前缀追加名称。 |
| 多 Key 合并-随机 | 从当前启用的 Key 中随机选择。 |
| 多 Key 合并-轮询 | 按顺序从当前启用的 Key 中选择并推进位置；依赖缓存组件。 |

### 状态管理与删除风险

![多 Key 管理](/assets/guide/feature-guide/channel-management-channel-actions.png)

多 Key 状态包括启用、手动禁用和自动禁用。状态列表按 Key 分页显示预览、原因和时间；统计卡可能仍显示全部 Key 的统计，不只是当前筛选页。

- 启用或禁用单个 Key 只改变该 Key 状态。
- 删除单个 Key 后，后续 Key 索引会重新排列；不能删除最后一个 Key。
- 「删除已禁用 Key」实际只清理自动禁用的 Key，手动禁用 Key 不会被该批量清理删除。
- 所有 Key 都不可用时，渠道可能不再参与路由或被自动处理；重新启用 Key 后仍需检查渠道状态。

## 条件功能

以下功能按渠道类型、权限或配置动态显示：

- Ollama 模型拉取、删除和版本查询；这些操作可能直接改变上游模型资源。
- Codex 凭证刷新、用量与额度重置。
- vLLM/SGLang 推理服务状态。
- 任务插件绑定、New API 扩展插件。
- Advanced Custom 路由、协议透传和专属模型检测。
- 支持上游模型获取的类型及其模型更新检查。

## 保存后的验证流程

1. 检查连接与模型页签状态为可保存，确认名称、凭证、模型和分组。
2. 保存后刷新页面，确认密钥空框仍表示保留而不是被清空。
3. 使用详细测试选择一个代表性端点和模型，核对成功、失败和响应时间。
4. 使用实际用户分组和 API Key 发起端到端请求，检查最终渠道和上游模型。
5. 若配置映射、参数覆盖、透传、代理或高级路由，再分别验证一个启用和一个未启用场景。
6. 上游模型更新先检测、审核新增/移除列表，再选择性应用；不要未经审核自动扩大公开模型列表。

## 故障排查

| 现象 | 检查顺序 |
| --- | --- |
| 渠道无法保存 | 检查类型专属凭证、Base URL、名称、模型、分组、JSON、代理、HTTP/2 分片及 Advanced Custom 路由。 |
| 测试认证失败 | 检查 Base URL 是否误包含完整接口路径、凭证格式、组织/项目/区域、代理和端点类型。 |
| 模型不可见 | 检查渠道模型、模型映射、渠道分组、用户分组、API Key 限制、模型元信息和上游目标名称。 |
| 请求被路由到意外渠道 | 检查优先级、权重、渠道状态、标签范围、请求路径、亲和规则和系统重试。 |
| 参数覆盖没有生效 | 检查是否开启请求体透传、操作顺序、条件路径、JSON 类型和实际 relay 路径。 |
| 渠道频繁自动禁用 | 查看失败状态码、错误文本、测试模型、代理和上游限流；区分自动禁用与手动禁用。 |
| 获取模型失败 | 检查该类型是否支持模型获取、凭证、模型列表路由、Base URL 和网络；失败不会自动替换原列表。 |
| 余额没有更新 | 确认渠道类型支持普通余额接口；Codex、vLLM/SGLang 使用其他运行信息入口。 |
| 多 Key 渠道不可用 | 检查每个 Key 状态、自动禁用原因和剩余可用 Key；不要只看渠道总状态。 |
| 修复后仍无法路由 | 等待能力索引重建，刷新后检查模型、分组、优先级和权重，再排查凭证与上游。 |

## 参数覆盖系统

参数覆盖在请求转换后、发送上游前执行。它不是完整协议转换器，也不会自动同步客户端流式状态。可视化编辑器和 JSON 模式写入同一份 `param_override`。

### 生效顺序与边界

- 只有请求进入相应 relay 处理路径时才会执行覆盖；请求体透传会绕过普通转换和部分覆盖链路。
- `operations` 按数组顺序执行，前一个操作的结果会成为后一个操作的输入。
- 同时存在旧式顶层字段和 `operations` 时，旧式字段先应用，再应用 `operations`。
- 条件默认使用 `OR`；`logic: "AND"` 才要求全部条件满足。
- 条件读取当前请求 JSON 和运行上下文；前序操作修改模型后，后续条件可能读取修改后的值。`original_model`、`upstream_model` 等上下文值不是自动写入请求 JSON 的字段。
- `return_error` 会提前返回自定义错误；其状态码和错误字段仍受后端解析范围约束，不应仅依据输入框可接受的范围宣称所有值都可用。

### 可视化编辑器与 JSON

![参数覆盖可视化编辑器](/assets/guide/feature-guide/create-channel-request-and-response-parameter-overrides-visual-editor.png)

可视化模式适合逐条编辑；JSON 模式适合复制完整规则。保存前确认规则数量、操作类型、路径、值、条件逻辑和保留原值开关。复杂规则先在测试渠道验证，再应用到生产渠道。

### 操作速查

| 操作 | 常用字段 | 说明 |
| --- | --- | --- |
| `set`、`delete` | `path`、`value` | 设置或删除 JSON 字段。 |
| `append`、`prepend` | `path`、`value`、`keep_origin` | 在字符串或数组前后追加内容；保留原值时避免覆盖已有内容。 |
| `move`、`copy` | `from`、`to` | 移动会删除源字段，复制保留源字段。 |
| `trim_prefix`、`trim_suffix` | `path`、`value` | 删除匹配的前缀或后缀。 |
| `ensure_prefix`、`ensure_suffix` | `path`、`value` | 不存在时补充前缀或后缀。 |
| `trim_space`、`to_lower`、`to_upper` | `path` | 清理或转换字符串。 |
| `replace`、`regex_replace` | `path`、`from`、`to` | 普通替换或正则替换；先用代表性请求验证。 |
| `prune_objects` | `path`、条件 | 按条件清理对象项。 |
| `set_header`、`delete_header` | Header 名和值 | 修改覆盖头；不能保证删除适配器后续重新生成的原生头。 |
| `copy_header`、`move_header` | `from`、`to` | 在运行时请求头覆盖表中复制或移动。 |
| `pass_headers` | Header 列表/规则 | 将指定客户端头写入运行时头覆盖；安全头仍受排除规则保护。 |
| `sync_fields` | JSON/Header 来源与目标 | 在请求字段与请求头之间同步值。 |
| `return_error` | 错误对象 | 直接结束请求并返回自定义错误，适合明确拒绝条件。 |

### 条件、路径与安全字段

| 条件项 | 说明 |
| --- | --- |
| `full`、`prefix`、`suffix`、`contains` | 字符串或可比较值的匹配方式。 |
| `gt`、`gte`、`lt`、`lte` | 双方必须是 JSON 数字，不能把任意字符串当作数字比较。 |
| `invert` | 反选匹配结果；缺失字段是否通过由 `pass_missing_key` 先决定。 |
| `pass_missing_key` | 路径缺失时允许条件通过；默认不通过。 |
| `logic` | `AND` 要求全部条件通过；省略时为 `OR`。 |
| JSON 路径 | 支持 `messages.0.content`、`messages.-1.content` 等路径。 |
| 运行上下文 | 可按原始模型、上游模型、用户/分组等上下文条件匹配；不要把这些名称当作请求体固定字段。 |

<Callout type="warn">
  参数覆盖可以改变请求语义、请求头和错误处理。不要用它切换 `stream`，不要把客户端密钥透传到不可信上游，也不要在没有真实请求验证的情况下直接启用正则替换、Header 同步或自定义错误。
</Callout>
