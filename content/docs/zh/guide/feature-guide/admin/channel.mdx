- 仅 Admin 和 Root 可访问，从侧边栏「管理员」→「渠道」进入。
- 配置连接上游 AI 服务的渠道，维护凭证、模型、分组、路由策略和请求改写规则。
- 渠道决定请求能发往哪里；模型资料、价格与用户分组在其他页面配置。

<Callout type="info" title="提示">
- 渠道分内置、插件、网关和自定义四类，创建时在选择窗口中挑选，见[创建与编辑渠道](#创建与编辑渠道)。
- Admin 能做哪些渠道操作，由 Root 在管理员权限中授予，见[权限与安全边界](#权限与安全边界)。
- 模型目录、价格与用户分组还需要结合<a href="/zh/docs/guide/feature-guide/admin/model" target="_blank" rel="noopener noreferrer">模型管理</a>、<a href="/zh/docs/guide/feature-guide/system-settings/settings-billing" target="_blank" rel="noopener noreferrer">计费与支付配置</a>和<a href="/zh/docs/guide/feature-guide/admin/user" target="_blank" rel="noopener noreferrer">用户管理</a>共同配置。
- 对所有渠道生效的请求改写在<a href="/zh/docs/guide/feature-guide/admin/request-processing" target="_blank" rel="noopener noreferrer">请求处理</a>页设置。
</Callout>

## 常用操作

本节按使用顺序介绍创建与编辑渠道、插件、网关和高级自定义三类特殊渠道，以及测试、余额、模型更新、复制、启停删除、标签、优先级、多 Key 和一致性修复等维护操作。

### 创建与编辑渠道

**操作流程：**
1. 点击页面右上角「创建渠道」；编辑时点击行内编辑图标，或在卡片 ⋯ 菜单中点击「编辑」。
2. 在选择窗口中选择提供商或插件。
3. 按需打开抽屉顶部的快捷选项。
4. 依次填写「连接与模型」「路由与映射」「请求与响应」「其他设置」四个标签页。
5. 点击「创建渠道」或「更新渠道」。

<Callout type="info" title="提示">
- 抽屉标题下方的「更换提供商」可重新选择类型或插件。
- 每个标签页旁显示状态点：「未完成」「错误」「就绪」或「已配置」。
- 账号没有「编辑敏感渠道设置」权限时，抽屉顶部显示「你的账号只能查看敏感渠道设置。你仍可编辑模型、分组、优先级和权重等非敏感运维字段。」
- 保存时页面先校验表单，服务端再检查渠道类型、凭证、插件绑定和高级配置。
</Callout>

选择窗口按「全部」「内置」「插件」「网关」「自定义」分类：

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 分类 | 身份与用途 | 创建时的关键差异 |
| --- | --- | --- |
| 内置渠道 | 由类型选择固定适配器，例如 OpenAI、Anthropic、Vertex、AWS、Gemini、Codex、vLLM 和 SGLang；卡片上显示类型编号（如「#1」）。 | 凭证格式、地址、额外字段和可用操作由类型决定；不能把所有内置类型都按普通 API Key 处理，见[类型专属配置](#类型专属配置)。 |
| 插件渠道 | 选择已安装且允许绑定的插件；卡片显示插件标识和「… 个模型」。 | 插件可能预填模型和 Base URL；只有任务部分的插件是任务转发渠道，包含渠道部分的插件（提供商插件）可以像高级自定义渠道一样转发普通 API 请求；只有请求处理部分的插件不在列表中；需要「绑定任务插件」权限，见[独立插件渠道](#独立插件渠道)。 |
| 网关渠道 | New API（#60）与 Sub2API（#59）。 | 填写网关 Base URL 和凭证，从网关获取模型；New API 仍可绑定支持 New API 上游的插件扩展，但不会变成插件渠道，见[网关渠道：New API 与 Sub2API](#网关渠道new-api-与-sub2api)。 |
| 自定义渠道 | 自定义（#8，显示「已弃用」）与高级自定义（#58，显示「灵活接入」）。 | 自定义是旧版完整 URL 接入；新配置优先使用高级自定义，按入口路径配置上游、鉴权和转换器，见[高级自定义渠道](#高级自定义渠道)。 |

</div>

<Callout type="info" title="提示">
- 「插件」分类只在账号拥有「绑定任务插件」权限时显示；插件列表加载失败时显示「加载插件失败」和重试入口，没有可绑定插件时显示「暂无可绑定的插件」。
- 搜索框可按名称、插件或类型编号查找；输入未列出的数字时显示「使用渠道类型 …」卡片。这不代表任意编号都有适配器支持。
- 已安装插件替代某些旧内置类型时（如 Sora、可灵、即梦），创建时只显示插件卡片，搜索旧类型名或编号也会找到插件。
</Callout>

**四种创建方式的选择建议：**
- **标准供应商或协议**：选择内置渠道，使用该类型专属凭证和默认地址提示。
- **已安装插件**：选择「插件」，确认插件的模型、上游类型和默认地址，再配置插件所需凭证。
- **New API/Sub2API 上游网关**：选择「网关」；不要用自定义（#8）代替网关适配器。
- **多入口、多协议或多供应商**：选择高级自定义；必须先设计入口路径、上游路径、鉴权和转换器。

抽屉标题行右侧的开关与各标签页中的同名设置是同一项，按类型显示：

| 开关 | 显示条件 | 说明 |
| --- | --- | --- |
| 透传请求体 | 非插件渠道 | 开启前弹出确认框。与「请求与响应」中的「透传请求体」是同一项，见[透传与覆盖的执行边界](#透传与覆盖的执行边界)。 |
| 透传请求头 | 非插件渠道 | 开启前弹出确认框。写入「请求头覆盖」中的透传规则；请求头覆盖不是有效 JSON 时不可用，提示「请先修正请求头覆盖的 JSON」。 |
| 异常自动禁用 | 始终显示 | 默认开启，即「路由与映射」中的「自动封禁」。下方显示本渠道是否参与自动停用及来源。 |
| 检测模型更新 | 支持获取模型的类型 | 即「其他设置」中的「上游模型更新检查」。 |
| Responses WebSocket | 支持的类型；插件渠道按插件声明 | 即「请求与响应」中的同名设置，需上游支持 WebSocket。 |

**「连接与模型」配置项说明：**

下表按标签页中的顺序排列。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 名称 | 管理员识别名称。 | 必填。 | 空；选择插件时为插件名 |
| 已启用 | 渠道是否参与路由。 | — | 开启 |
| API 地址 | 上游 Base URL，不是 `/v1/chat/completions` 等完整请求路径。 | Azure、自定义（#8）、New API、插件渠道、vLLM、SGLang 等类型必须填写；自定义（#8）填写旧版完整接入地址；高级自定义使用相对上游路径时必须填写。 | 按类型或插件预填 |
| 添加模式 | 一个凭证对应一个渠道，或一次添加多个凭证。 | 三选一，见下方「**添加模式：**」。 | 单密钥 |
| API 密钥 | 上游凭证。 | 新建必填，格式由类型决定，插件渠道下方显示「密钥格式：…」。编辑时不回填旧值，留空保留原凭证。 | 空 |
| 模型 | 渠道提供的用户侧模型名。 | 至少一项；可「获取模型」或用「快捷操作」填入。模型列表参与能力索引和路由。 | 空；插件可能预填 |
| 分组 | 可以使用该渠道的用户分组。 | 至少一项。只有用户或 API 密钥具备相应分组、且其他模型条件满足时，渠道才可能被选中。 | `default` |

</div>

<Callout type="info" title="提示">
- 选择类型后请先阅读该类型的地址和凭证提示。类型专属字段（如「OpenAI 组织」、Vertex AI 的部署区域、AWS 接口）显示在「API 地址」附近，见[类型专属配置](#类型专属配置)。
- 「获取模型」从当前保存的渠道或未保存的连接读取上游模型，点击保存模型或保存渠道后才写入。
- Root 编辑渠道时可在「当前密钥」中点击「显示密钥」，需通过安全验证。
</Callout>

**添加模式：**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 模式 | 结果 | 适用注意 |
| --- | --- | --- |
| 单密钥 | 一个凭证创建一个渠道。 | 适合首次验证地址、模型和凭证。Codex 和 Vertex AI 的 API Key 模式只允许此模式。 |
| 批量添加（每行一个密钥） | 每行一个凭证，创建多个独立渠道。 | 每个新渠道独立参与路由；可「移除重复项」。登录型插件不提供此模式。 |
| 多密钥模式（多个密钥，一个渠道） | 多个凭证保存到一个渠道。 | 「多密钥策略」选「随机」或「轮询」；轮询提示「轮询模式需要 Redis 和内存缓存，否则性能将显著下降」。编辑时可在「密钥更新模式」中选「追加」或「替换」。 |

</div>

**「路由与映射」配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 所属区域 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- | --- |
| 模型映射 | 模型映射 | 客户端模型名 → 上游模型名。 | 可选 JSON 对象，值必须是字符串；支持批量生成规则。源模型需在「模型」列表中；映射目标应由上游真实支持，通常不应同时放在公开模型列表中。 | 空 |

| 测试模型 | 路由策略 | 快速测试未指定模型时使用的模型。 | 应填写该渠道实际支持的模型。 | 空 |

</div>

<Callout type="info" title="提示">
- 映射存在三类常见风险：JSON 无效、源模型不在公开列表、上游目标名称被公开给用户。
- 保存时映射的源模型不在模型列表中，会弹出「模型未加入列表，可能无法调用」，可选「返回修改」「直接提交」或「添加后提交」。
- 映射目标也在模型列表中时，界面以黄色提示并提供「移除映射目标」。
- 请先确认用户侧模型列表，再决定是否添加或移除名称。
</Callout>

### 独立插件渠道

- 渠道管理-插件渠道

![渠道管理-插件渠道页面](/assets/guide/feature-guide/create-channel-plugin-channel.png)

包含渠道部分的插件渠道可以测试、获取模型、检测上游模型更新，并在插件提供余额时查询余额。插件模型是插件声明的初始值，不代表上游凭证已经可用。插件具体支持的模型、路由和请求类型可能随安装版本变化。

在 `/v1/images/generations`、`/v1/images/edits`、`/v1/responses`、`/v1/videos` 等共享入口上，同一模型的普通渠道与插件渠道按分组、优先级和权重一起参与选择。选中普通渠道时，请求按普通渠道转发，不经过插件。

**前置条件：**
- 账号拥有「绑定任务插件」权限，选择窗口中才显示「插件」分类。
- 目标插件已安装并启用，见<a href="/zh/docs/guide/feature-guide/admin/task-plugins#创建插件渠道" target="_blank" rel="noopener noreferrer">插件管理</a>。

1. 在「插件」分类中选择已注册插件。

3. 插件声明了设置项时，填写「插件设置」区块。
4. 点击「创建渠道」；需要登录上游账号的插件，按钮为「保存并登录」。
5. 保存后自动打开登录窗口，按提示完成登录。

<Callout type="info" title="提示">
- 选择插件后，名称为空时填入插件名，插件声明的模型和默认地址也会预填。

### 测试连接

- 渠道管理-测试渠道连接

![渠道管理-测试渠道连接页面](/assets/guide/feature-guide/channel-management-test-channel-connection.png)

快速测试点击行内「测试连接」图标，直接发送一次请求，使用渠道的测试模型；未配置时依次使用渠道模型和默认测试模型。详细测试在测试窗口中选择端点、流式模式和模型。

### 查询余额与运行状态

- 渠道管理-查询余额

页头 ⋯ 菜单中的「更新所有余额」在后台遍历启用的渠道（跳过内置类型的多 Key 渠道），可能产生大量上游请求，不会因为当前列表筛选而只处理可见行。

- 提交后提示「余额正在后台更新，列表会自动刷新。」，进度可在<a href="/zh/docs/guide/feature-guide/admin/system-info" target="_blank" rel="noopener noreferrer">系统信息</a>的「系统任务」中查看（类型「余额批量更新」）。
- 查询到余额小于等于 0 时，开启了「异常自动禁用」的渠道会被自动禁用（只看渠道开关，不受全局「失败时禁用」影响），原因为「余额不足」；多 Key 插件渠道只禁用余额不足的 Key。
- 设置环境变量 `CHANNEL_UPDATE_FREQUENCY`（单位分钟，默认不设置；值须为整数，否则启动失败）后，系统按该周期自动执行「更新所有余额」；未设置时仅可手动执行。页面上没有对应设置。

### 权限与安全边界

所有渠道操作先要求 Admin 或 Root，再按操作检查渠道权限。普通 Admin 的具体权限由 Root 在<a href="/zh/docs/guide/feature-guide/admin/user#管理员权限" target="_blank" rel="noopener noreferrer">管理员权限</a>中配置。

| 读取渠道 | 查看列表、详情、模型列表、默认 Base URL、运行策略、余额/用量结果和 vLLM/SGLang 状态。 |
| 运维渠道 | 测试渠道、查询余额、启用或手动禁用、修复渠道一致性、获取已有渠道的模型、检测上游模型更新、启停多 Key。 |

### 透传与覆盖的执行边界

- 渠道管理-确认开启透传请求体

![渠道管理-确认开启透传请求体页面](/assets/guide/feature-guide/create-channel-pass-through-request-body-description.png)

- 渠道管理-确认开启透传请求头

![渠道管理-确认开启透传请求头页面](/assets/guide/feature-guide/create-channel-pass-through-request-headers-description.png)

开启透传前会弹出确认框，列出透传后不可用的功能；点击「确认开启透传」后生效。

**执行规则：**
- 全局或渠道级请求体透传会跳过正常转换链路；不要同时假设模型映射、参数覆盖和协议转换仍会按普通路径执行。
- 渠道开启「透传请求体」时，侧边栏「请求处理」页中「转换格式前」「发送前」阶段的实例不运行，本渠道添加的实例在「读取请求前」也不运行，「最终检查」「检查回复」照常运行，见<a href="/zh/docs/guide/feature-guide/admin/request-processing#注意事项" target="_blank" rel="noopener noreferrer">请求处理</a>。
- 请求头透传使用 `*` 或 `re:`/`regex:` 规则复制客户端请求头，但会排除 Authorization、`x-api-key`、`x-goog-api-key`、WebSocket 握手和其他安全头。
- 请求头覆盖在透传之后应用，显式覆盖优先；`{client_header:NAME}` 必须是完整值，客户端未携带该头时不会加入。
- 请通过客户端请求选择流式模式。参数覆盖改写 JSON 中的 `stream` 不保证同步调整网关、适配器和上游的流式处理状态。

**字段透传控制：**
- 「请求与响应」中的「字段透传控制」开关默认全部关闭，按类型显示：「允许透传 service_tier」适用于该区域显示的全部类型。
- OpenAI 类渠道另有「禁止透传 store」「允许透传 safety_identifier」「允许 include 用量混淆透传」「允许推理地理位置透传」。
- Claude 类渠道另有「允许 speed 透传」；Anthropic 渠道还有「允许 inference_geo 透传」「允许 Claude beta 查询透传」。

### 参数覆盖系统

- 渠道管理-参数覆盖

![渠道管理-参数覆盖页面](/assets/guide/feature-guide/create-channel-request-and-response-parameter-overrides-visual-editor.png)

参数覆盖在请求转换后、发送上游前执行。它不是完整协议转换器，也不会自动同步客户端流式状态。可视化编辑器和 JSON 模式写入同一份参数覆盖规则。

**生效顺序与边界：**
- 只有请求进入相应 relay 处理路径时才会执行覆盖；请求体透传会绕过普通转换和部分覆盖链路。
- 侧边栏「请求处理」页的<a href="/zh/docs/guide/feature-guide/admin/request-processing#全局参数覆盖" target="_blank" rel="noopener noreferrer">全局参数覆盖</a>实例先于本渠道的参数覆盖执行，同一参数以渠道的设置为准；它的「返回自定义错误」一律返回 HTTP 400。
- 规则列表（`operations`）按数组顺序执行，前一个操作的结果会成为后一个操作的输入。
- 同时存在旧式顶层字段和规则列表（`operations`）时，旧式字段先应用，再应用规则列表。
- 命中会话规则时，规则中的参数覆盖模板会与渠道参数覆盖合并，见<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#会话与重试" target="_blank" rel="noopener noreferrer">会话与重试</a>。
- 条件默认为「满足任一条件（OR）」；选「必须全部满足（AND）」（`logic: "AND"`）才要求全部条件满足。
- 条件读取当前请求 JSON 和运行上下文；前序操作修改模型后，后续条件可能读取修改后的值。`original_model`、`upstream_model` 等上下文值不是自动写入请求 JSON 的字段。
- 返回自定义错误（`return_error`）会提前返回自定义错误；其状态码和错误字段仍受后端解析范围约束，不应仅依据输入框可接受的范围宣称所有值都可用。
- 条件比较出错时，本次请求以 `channel:param_override_invalid` 失败，按渠道类错误处理，而不是视为条件不匹配。出错情形如「完全匹配」（`full`）两侧类型不同、数值比较的一侧不是数字、「正则」（`regex`）表达式无效。

**可视化编辑器与 JSON：**

在「请求与响应」中点击「可视化编辑」打开「参数覆盖」窗口，「模式」可选「可视化」或「JSON 文本」。可视化模式适合逐条编辑，JSON 模式适合复制完整规则。

**操作速查（字段与内容）：**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作类型 | 常用字段 | 说明 |
| --- | --- | --- |
| 设置字段（`set`）、删除字段（`delete`） | `path`、`value`；设置字段可选保留原值（`keep_origin`） | 设置或删除 JSON 字段。 |
| 追加到末尾（`append`）、追加到开头（`prepend`） | `path`、`value`、保留原值（`keep_origin`） | 在字符串或数组前后追加内容；保留原值时避免覆盖已有内容。 |
| 移动字段（`move`）、复制字段（`copy`） | `from`、`to` | 移动会删除源字段，复制保留源字段。 |
| 裁剪前缀（`trim_prefix`）、裁剪后缀（`trim_suffix`） | `path`、`value` | 删除匹配的前缀或后缀。 |
| 确保前缀（`ensure_prefix`）、确保后缀（`ensure_suffix`） | `path`、`value` | 不存在时补充前缀或后缀。 |
| 去掉空白（`trim_space`）、转小写（`to_lower`）、转大写（`to_upper`） | `path` | 清理或转换字符串。 |
| 字符串替换（`replace`）、正则替换（`regex_replace`） | `path`、`from`、`to` | 普通替换或正则替换。 |
| 清理对象项（`prune_objects`） | `path`、条件 | 按条件清理对象项。 |

</div>

**操作速查（请求头与流程）：**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作类型 | 常用字段 | 说明 |
| --- | --- | --- |
| 设置请求头（`set_header`）、删除请求头（`delete_header`） | Header 名和值；设置请求头可选保留原值（`keep_origin`） | 修改覆盖头；不能保证删除适配器后续重新生成的原生头。 |
| 复制请求头（`copy_header`）、移动请求头（`move_header`） | `from`、`to`、保留原值（`keep_origin`） | 在运行时请求头覆盖表中复制或移动。 |
| 请求头透传（`pass_headers`） | Header 名称列表、保留原值（`keep_origin`） | 按原名把列出的客户端请求头复制到运行时头覆盖。这里不做安全头排除（与请求头覆盖中的 `*`、`re:` 透传不同），列出的 `Authorization`、`x-api-key` 也会照样复制；只列出确实需要的头。 |
| 字段同步（`sync_fields`） | JSON/Header 来源与目标 | 在请求字段与请求头之间同步值。 |
| 返回自定义错误（`return_error`） | 错误对象 | 直接结束请求并返回自定义错误，适合明确拒绝条件。 |

</div>

**条件、路径与安全字段：**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 条件项 | 说明 |
| --- | --- |
| 完全匹配（`full`）、前缀（`prefix`）、后缀（`suffix`）、包含（`contains`） | 字符串或可比较值的匹配方式。 |
| 正则（`regex`） | 按正则表达式匹配字段的字符串形式；条件值必须是字符串。 |
| 大于（`gt`）、大于等于（`gte`）、小于（`lt`）、小于等于（`lte`） | 双方必须是 JSON 数字，不能把任意字符串当作数字比较。 |
| 反向匹配（`invert`） | 反选匹配结果；缺失字段是否通过由「字段缺失时通过」（`pass_missing_key`）先决定。 |
| 字段缺失时通过（`pass_missing_key`） | 路径缺失时允许条件通过；默认不通过。 |
| 满足任一条件（OR）、必须全部满足（AND）（`logic`） | 「必须全部满足（AND）」要求全部条件通过；省略时为「满足任一条件（OR）」。 |
| JSON 路径 | 支持 `messages.0.content`、`messages.-1.content` 等路径。 |
| 运行上下文 | 可按原始模型、上游模型、用户/分组等上下文条件匹配；不要把这些名称当作请求体固定字段。 |

</div>

<Callout type="warn" title="注意">
参数覆盖可以改变请求语义、请求头和错误处理。不要用它切换 `stream`，不要把客户端密钥透传到不可信上游，正则替换、Header 同步和自定义错误也应谨慎启用。
</Callout>

## 保存与生效

渠道保存在数据库中。未启用内存缓存时，各节点每次请求直接读取数据库，下表操作在各节点从下一次请求起生效。启用内存缓存（含启用 Redis 的部署）时，处理该请求的节点立即刷新，其他节点约 3 秒内重新载入渠道（最迟一个同步周期，默认 60 秒）；请求失败后的自动禁用和测试后的自动恢复例外，见下方「自动变更与后台任务」。同步周期由环境变量 `SYNC_FREQUENCY` 调整，单位为秒，默认 60 秒。本页提到的环境变量都只在启动时读取，修改后需重启 New API。

**补充说明：**
- **抽屉保存**：四个页签共用一个表单，成功提示「渠道创建成功」或「渠道更新成功」；保存失败时抽屉保持打开，并显示失败原因。
- **不自动测试**：保存只写入配置，不连接上游，也不自动测试；需要时在[测试连接](#测试连接)中手动测试。
- **正在进行的连接**：禁用或删除渠道（含自动禁用）时，该渠道上正在进行的 Realtime 和 Responses WebSocket 连接会被关闭；启用 Redis 时，其他节点上的这类连接一并关闭。
- **同步完成前**：启用内存缓存时，各节点的路由可能暂时不一致。
- **后台任务进度**：「测试所有渠道」「检测所有上游更新」「更新所有余额」的进度可在<a href="/zh/docs/guide/feature-guide/admin/system-info" target="_blank" rel="noopener noreferrer">系统信息</a>的「系统任务」中查看。

## 注意事项

- **批量操作作用于全部渠道**：「测试所有渠道」「更新所有余额」「检测所有上游更新」「应用所有上游更新」「删除所有已禁用」「修复渠道一致性」都不受当前列表筛选限制，建议在低峰期执行。
- **测试和余额更新可能改变渠道状态**：「测试所有渠道」可能自动禁用或恢复渠道，「更新所有余额」可能自动禁用余额不足的渠道，见[保存与生效](#保存与生效)的「自动变更与后台任务」。
- **自动同步会直接改动模型列表**：开启「自动同步上游模型」后，定时检测发现的新模型会直接加入渠道模型列表（只新增、不移除，已忽略的模型除外）。
- **「应用所有上游更新」不逐项审核**：一次应用所有已检测渠道的待新增和待移除模型；需要逐项审核时，在「预览上游模型变更」中勾选后点击「确认应用所选变更」。
- **敏感操作需要「编辑敏感渠道设置」权限**：没有该权限的 Admin 不能创建、复制或删除渠道，也不能保存凭证、类型、Base URL、代理、请求头覆盖、参数覆盖等敏感项的修改，见[权限与安全边界](#权限与安全边界)。
- **删除不可恢复，复制会带走凭证**：删除渠道后无法从 New API 恢复；复制渠道会复制原渠道的凭证，不能当作凭证轮换，见[启用、禁用与删除](#启用禁用与删除)和[复制渠道](#复制渠道)。

<Accordion title="创建或更新渠道时无法保存">
**说明**：保存前先在页面中校验，再由服务端校验，常见提示如下。

| 提示原文 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 「请先修复高亮字段后再保存」（英文 Please fix the highlighted fields before saving） | 名称、模型、分组未填写，新建时未填写凭证；或 JSON 字段、代理地址、HTTP/2 连接分片、高级自定义路由不符合要求。 | 按高亮字段逐项修正。 |
| 「无权进行此操作，权限不足」（英文 Unauthorized, insufficient privileges） | 修改了凭证、类型、Base URL、代理、请求头覆盖或参数覆盖等敏感项，账户没有「编辑敏感渠道设置」权限。 | 请 Root 授予权限或代为修改。 |
| 「部署地区不能为空」「部署地区必须包含 default 字段」 | Vertex AI 的「部署区域」为空，或 JSON 中缺少 `default`。 | 填写区域；使用 JSON 时加入 `default`。 |
| 「渠道额外设置格式错误：…」 | 渠道额外设置不是合法的 JSON。 | 修正后重新保存。 |
| `Codex key must be a valid JSON object`、`New API channel base URL cannot be empty` 等（仅英文） | 类型专属凭证或 Base URL 不符合要求，如 Codex 凭证不是含 `access_token`、`account_id` 的 JSON，New API、vLLM、SGLang 渠道未填写 Base URL。 | 按提示修正对应字段。 |
</Accordion>

<Accordion title="测试渠道时认证失败">
**说明**：测试失败时提示「… 测试失败」（英文 … test failed），并附上游返回的错误详情。

**可能原因**：
- Base URL 误包含完整接口路径。
- 凭证格式不正确，或组织、项目、区域填写有误。
- 代理或端点类型与上游不符。

**处理方法**：
1. 按错误详情修正对应字段。
2. 用详细测试换一个端点类型或模型重新测试，见[测试连接](#测试连接)。
</Accordion>

<Accordion title="用户看不到某个模型">
**说明**：调用方获取的模型列表只包含其分组中已启用渠道提供、且已配置价格的模型。模型广场是否展示另由模型管理中的「广场展示」决定，见<a href="/zh/docs/guide/feature-guide/admin/model#广场展示状态" target="_blank" rel="noopener noreferrer">模型管理</a>。

**可能原因**：
- 渠道模型列表未包含该名称；使用模型映射时，映射的源名称也需加入模型列表。
- 渠道分组与用户分组或 API 密钥的分组不匹配。
- API 密钥限制了可用模型。
- 提供该模型的渠道已禁用。
- 模型未配置价格。站点开启「自用模式」或用户开启「接受未定价模型」时不受此限制。

**处理方法**：
1. 核对渠道的模型、分组和状态，以及 API 密钥的模型限制。
2. 未配置价格时，请 Root 在<a href="/zh/docs/guide/feature-guide/system-settings/settings-billing#模型定价" target="_blank" rel="noopener noreferrer">计费与支付配置</a>中配置价格。
</Accordion>

<Accordion title="请求被路由到意外的渠道">
**可能原因**：
- 优先级、权重、渠道状态或标签范围与预期不符。
- 请求路径不同，或命中了会话规则，或触发了<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#会话与重试" target="_blank" rel="noopener noreferrer">重试设置</a>。
- 在共享入口上，普通渠道与插件渠道一起参与选择。

**处理方法**：
1. 在使用日志详情的<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#请求决策记录" target="_blank" rel="noopener noreferrer">请求策略决策</a>中查看实际选择过程。
</Accordion>

<Accordion title="参数覆盖没有生效">
**可能原因**：
- 开启了请求体透传，绕过了参数覆盖。
- 操作顺序、条件路径或 JSON 类型与预期不符。
- 请求没有进入执行参数覆盖的 relay 处理路径。

**处理方法**：
1. 对照[参数覆盖系统](#参数覆盖系统)的「生效顺序与边界」逐项检查。
</Accordion>

<Accordion title="渠道频繁被自动禁用">
**可能原因**：
- 上游返回的状态码或错误文本命中了<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#渠道健康" target="_blank" rel="noopener noreferrer">渠道健康</a>中的自动禁用规则，如测试模型、代理或上游限流导致的失败。
- 执行「更新所有余额」时余额小于等于 0，渠道被自动禁用，原因为「余额不足」。

**处理方法**：
1. 查看渠道的禁用原因，区分自动禁用与手动禁用。
2. 对照渠道健康中的规则调整渠道或测试设置。
</Accordion>

<Accordion title="获取模型失败">
**提示原文**：「获取模型失败」（英文 Failed to fetch models）或「此渠道类型不支持获取模型」（英文 This channel type does not support fetching models）；服务端或上游返回了原因时，显示该原文。

**说明**：获取失败不会替换已保存的模型列表。

**可能原因**：
- 该渠道类型不支持获取模型。
- 凭证、Base URL 或网络有误。
- 高级自定义渠道缺少模型列表路由。

**处理方法**：
1. 修正后重新获取。
</Accordion>

<Accordion title="余额没有更新">
**提示原文**：「多密钥渠道不支持余额查询」（英文 Multi-key channels do not support balance queries）；插件不提供余额的插件渠道为「该渠道的插件不提供余额。」（英文 The plugin of this channel does not report a balance）。

**可能原因**：
- 该渠道类型不支持普通余额接口，或是内置类型的多 Key 渠道、插件不提供余额的插件渠道。
- 「更新所有余额」仍在后台运行，完成前列表中的余额可能仍是旧值。
- Codex、vLLM/SGLang 使用其他运行信息入口，见[查询余额与运行状态](#查询余额与运行状态)。
</Accordion>

<Accordion title="多 Key 渠道不可用">
**可能原因**：渠道中的 Key 已被禁用或自动禁用，没有剩余可用的 Key。渠道总状态不能反映每个 Key 的状态。

**处理方法**：
1. 查看每个 Key 的状态和自动禁用原因，见[管理多 Key 渠道](#管理多-key-渠道)和[渠道状态](#渠道状态)。
</Accordion>

<Accordion title="执行「修复渠道一致性」后仍无法路由">
**说明**：修复在点击后同步完成。启用内存缓存的多实例部署中，其他节点约 3 秒内重新载入渠道（最迟一个同步周期，默认 60 秒）后使用新的索引。已有修复在运行时提示「已经有一个修复任务在运行中，请稍后再试」（英文 A repair task is already running. Please try again later）。

**可能原因**：渠道的模型、分组、优先级或权重与预期不符，或凭证、上游有问题。修复只重建索引，不修复这些配置。

**处理方法**：
1. 刷新列表，检查模型、分组、优先级和权重。
2. 排查凭证与上游。
</Accordion>

<Accordion title="保存渠道后，部分请求仍按旧配置路由">
**说明**：启用内存缓存（含启用 Redis 的部署）时，其他节点约 3 秒内重新载入渠道（最迟一个同步周期，默认 60 秒），载入完成前不同节点的路由可能不一致。请求失败后的自动禁用和测试后的自动恢复，其他节点按同步周期（默认 60 秒）重新载入。未启用内存缓存时，路由直接读取数据库。

**处理方法**：
1. 多实例部署时，Root 查看渠道列表右上角的节点状态；显示「… 个节点更新失败」时点击查看失败的节点，并检查该节点日志。
2. 等待几秒后重试；自动禁用或自动恢复的渠道最迟等待一个同步周期（默认 60 秒）。
</Accordion>

<Accordion title="执行「测试所有渠道」时提示已有任务正在运行">
**提示原文**：「已有通道测试任务正在运行或等待中，不能启动本次手动任务」（英文 A channel test task is already running or queued. Cannot start this manual task）；执行「检测所有上游更新」时为「已有模型更新任务正在运行或等待中，不能启动本次手动任务」（英文 A model update task is already running or queued. Cannot start this manual task）。

**可能原因**：同类型的系统任务（含定时触发的任务）正在运行或等待执行。

**处理方法**：
1. 在<a href="/zh/docs/guide/feature-guide/admin/system-info" target="_blank" rel="noopener noreferrer">系统信息</a>的「系统任务」中查看进度。
2. 任务结束后重新执行。
</Accordion>
