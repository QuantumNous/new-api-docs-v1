### 权限与安全边界

所有渠道接口先要求 Admin 或 Root，再按操作检查渠道权限。普通 Admin 的具体权限由 Root 在管理员权限矩阵中配置。

| 权限 | 主要操作 |
| --- | --- |
| `ChannelRead` | 查看列表、详情、模型列表、默认 Base URL、运行策略、余额/用量结果和 vLLM/SGLang 状态。 |
| `ChannelOperate` | 测试渠道、查询余额、启用或手动禁用、修复能力索引、检测上游模型更新、启停多 Key。 |
| `ChannelWrite` | 编辑模型、分组、映射、标签、备注、优先级（含拖拽调整）、权重；应用上游模型更新。 |
| `ChannelSensitiveWrite` | 创建、删除、复制渠道；修改凭证、类型、Base URL、代理、请求头覆盖、参数覆盖和其他敏感配置；临时配置获取模型；删除多 Key 渠道中的 Key。 |
| `TaskPluginBind` | 创建或修改任务插件绑定，以及绑定到 New API 网关的插件扩展。 |
| Root 与安全验证 | 查看完整渠道密钥。该接口额外要求 Root、安全验证、限流和禁止缓存；不要把 `ChannelSecretView` 描述成当前密钥接口的独立路由权限。 |

<Callout type="warn" title="注意保管密钥">
  列表、截图、日志和工单中不要暴露 API Key、服务账号 JSON、代理密码、请求头凭证或 Codex OAuth JSON。编辑抽屉不会回填旧密钥；留空表示保留旧值，填写新值才替换。复制渠道会复制凭证，删除渠道或 Key 后没有恢复入口。
</Callout>

## 创建与编辑渠道

当前编辑器先选择提供商或插件，再进入四个配置页签：**连接与模型、路由与映射、请求与响应、其他设置**。保存时前端校验表单，后端再次检查渠道类型、凭证、插件绑定和高级配置。

![渠道管理-选择自定义渠道页面](/assets/guide/feature-guide/channel-management-select-provider-or-plugin-custom.png)

| 分类 | 身份与用途 | 创建时的关键差异 |
| --- | --- | --- |
| 内置渠道 | 由数值 `channel.type` 选择固定适配器，例如 OpenAI、Anthropic、Vertex、AWS、Gemini、Codex、vLLM 和 SGLang。 | 凭证格式、地址、`other` 字段和可用操作由类型决定；不能把所有内置类型都按普通 API Key 处理。 |
| 插件渠道 | 选择已安装且允许绑定的 Task Plugin；保存为 `type=61` 和 `setting.task_plugin_key`。 | 插件可能预填模型和 Base URL；插件是任务转发渠道，不是普通 API 适配器；需要 `TaskPluginBind`。 |
| 网关渠道 | New API 为 `type=60`，Sub2API 为 `type=59`。 | 填写网关 Base URL 和凭证，从网关获取模型；New API 仍可绑定支持 `new_api` 上游的插件扩展，但不会变成插件渠道。 |
| 自定义渠道 | Legacy Custom 为 `type=8`，Advanced Custom 为 `type=58`。 | Legacy Custom 是旧版完整 URL 接入并标记弃用；新配置优先使用 Advanced Custom，按入口路径配置上游、鉴权和转换器。 |

创建时「插件」分类只在当前用户拥有 `TaskPluginBind` 权限时显示；插件列表加载失败时显示「加载插件失败」和重试入口，没有可绑定插件时显示「暂无可绑定的插件」。搜索框也可以按内置类型编号查找自定义类型；这不是对任意类型都提供了适配器支持。

#### 四种创建方式的选择建议

- **标准供应商或协议**：选择内置渠道，使用该类型专属凭证和默认地址提示。
- **已安装任务插件**：选择「插件」，确认插件的模型、上游类型和默认地址，再配置插件所需凭证。
- **New API/Sub2API 上游网关**：选择「网关」；不要用 Legacy Custom 代替网关适配器。
- **多入口、多协议或多供应商**：选择 Advanced Custom；必须先设计入口路径、上游路径、鉴权和转换器。

### 连接与模型

- 渠道管理-连接与模型

![渠道管理-连接与模型页面](/assets/guide/feature-guide/create-channel-connection-and-models.png)

| 字段 | 必填或默认 | 说明 |
| --- | --- | --- |
| 名称 | 必填 | 管理员识别名称。插件新建时空名称可能使用插件名称预填。 |
| 类型/提供商 | 必填 | 决定适配器、凭证格式、默认地址、可用页签和专属校验。 |
| Base URL | 取决于类型 | 这是上游 Base URL，不是 `/v1/chat/completions` 等完整请求路径。Azure、New API、任务插件、vLLM、SGLang 等类型必须填写；Legacy Custom 的地址是旧版完整接入地址；Advanced Custom 使用相对上游路径时必须填写。 |
| API Key/凭证 | 新建必填 | 具体格式由类型决定。编辑时不回填旧值；留空保留原凭证。 |
| 模型 | 至少一项 | 逗号分隔的用户侧模型名；模型列表参与能力索引和路由。插件可能预填模型。 |
| 分组 | 默认 `default`，至少一项 | 只有用户或 API Key 具备相应分组，且其他模型条件满足时，渠道才可能被选中。 |
| 模型获取 | 仅支持的类型显示 | 从当前保存渠道或当前未保存的连接读取上游模型；获取结果只有在点击保存模型或保存渠道后才写入。 |
| 模型映射 | 可选 JSON 对象 | 将客户端模型名映射到上游模型名；值必须是字符串。映射目标通常不应同时放在公开模型列表中。 |

**连接与模型流程**

1. 选择类型后先阅读该类型的地址和凭证提示。
2. 填写名称、Base URL、凭证、模型和分组。
3. 对支持的类型点击获取模型，勾选实际可用模型并保存选择。
4. 如需映射，确认源模型在模型列表中；映射目标应由上游真实支持。

### 类型专属凭证

| 类型 | 凭证与专属字段 | 限制或注意事项 |
| --- | --- | --- |
| Vertex AI | 「Vertex AI 密钥格式」可选 JSON（服务账号）或 API Key；「部署区域」保存在 `other`；API Key 模式另有可选的「Vertex AI 项目 ID」。 | JSON 模式可批量使用服务账号，项目取自服务账号；API Key 模式只支持单密钥，不填项目 ID 时由 Google 决定区域，填写后请求发往部署区域。`other` 需要有效 JSON，并包含 `default` 区域。 |
| AWS | 「AWS 接口」可选「InvokeModel（旧接口）」（默认）或「Mantle（Messages API）」；`aws_key_type` 为 AK/SK 或 API Key；凭证提示包含区域。 | 按界面提示填写 `AccessKey\|SecretAccessKey\|Region` 或 `APIKey\|Region`；不要把分隔符格式当作所有 AWS 错误都能在前端拦截。Mantle 只用于支持的 Claude 模型，Amazon Nova 和旧模型继续使用 InvokeModel；使用 Mantle 时 Base URL 可留空（按区域使用默认地址），自定义地址必须是 HTTPS。 |
| Azure | API Key、Base URL、默认 API 版本；可选 Responses API 版本。 | `other` 为必填的默认版本；模型名称通常对应 Azure deployment。 |
| Codex | OAuth JSON，至少包含 `access_token` 和 `account_id`。 | 只支持单密钥创建；编辑可刷新凭证；测试未指定端点时使用 Responses。 |
| vLLM/SGLang | 自托管 Base URL，API Key 或 `EMPTY`。 | 使用固定协议预设，HTTP/2 与模型检测按页面条件配置；不要把它们当作可任意编辑的 Advanced Custom 路由。 |
| Ollama | 默认使用本地/自托管地址，也可切换 OpenAI 兼容聊天端点。 | 模型拉取、删除和版本查询是 Ollama 专属操作，可能对上游模型产生副作用。 |

### 单密钥、批量创建与多 Key

| 模式 | 结果 | 适用注意 |
| --- | --- | --- |
| 单密钥 | 一个凭证创建一个渠道。 | 适合首次验证地址、模型和凭证。Codex 和 Vertex API Key 只允许此模式。 |
| 批量创建 | 每行一个凭证，创建多个独立渠道。 | 可按凭证前缀追加名称；每个新渠道独立参与路由。 |
| 多 Key 合并 | 多个凭证保存到一个渠道。 | 选择随机或轮询；轮询依赖缓存组件，后续在多 Key 管理中按 Key 维护状态。 |

### 路由与映射

- 渠道管理-路由与映射

![渠道管理-路由与映射页面](/assets/guide/feature-guide/create-channel-routing-and-mapping.png)

| 字段 | 默认或格式 | 说明 |
| --- | --- | --- |
| 模型映射 | 空或 JSON 对象 | 客户端名称 → 上游名称；支持批量生成规则。保存前检查源模型是否在 Models 列表中。 |
| 优先级 | 默认 `0` | 同模型、同分组候选中优先级较高的渠道先参与选择。不是全局重试次数。 |
| 权重 | 默认 `0` | 同优先级渠道的选择权重；不是严格固定比例，重试或渠道状态会改变实际结果。 |
| 测试模型 | 可选 | 快速测试未指定模型时使用；应填写该渠道实际支持的模型。 |
| 自动封禁 | 默认开启 | 即顶部快捷选项「异常自动禁用」。还需在<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#渠道健康" target="_blank" rel="noopener noreferrer">请求策略 → 渠道健康</a>中开启全局「失败时禁用」才会生效（全部余额更新发现余额不足时除外，见[查询余额与运行状态](#查询余额与运行状态)）；手动禁用和自动禁用是不同状态。 |

映射存在三类常见风险：JSON 无效、源模型不在公开列表、上游目标名称被公开给用户。保存时界面会提示缺失源模型，也会提示公开了映射目标；应先确认用户侧模型列表，再决定是否添加或移除名称。

- 渠道管理-请求与响应

![渠道管理-请求与响应页面](/assets/guide/feature-guide/create-channel-request-and-response.png)

#### 覆盖规则

| 字段 | 格式/默认 | 说明 |
| --- | --- | --- |
| 状态码映射 | 可选 JSON；状态码为 HTTP 整数 | 将上游响应映射为 New API 处理状态；新增可能改变重试行为，保存时可能需要确认。 |
| 参数覆盖 | 可选 JSON 或可视化规则 | 在发送前改写已转换的请求 JSON；支持字段设置、删除、移动、复制、字符串处理、条件和自定义错误。 |
| 请求头覆盖 | 可选 JSON 对象 | 设置、删除或复制上游请求头；支持 `{api_key}` 和完整值形式的 `{client_header:NAME}`。 |
| 请求体透传 | 默认关闭，按类型显示 | 尽量发送客户端原始请求体，会跳过部分转换、字段过滤和参数覆盖；开启前必须确认上游协议兼容。高级自定义渠道开启后作用于所有路由，见[高级自定义渠道](#高级自定义渠道)。 |
| Responses WebSocket | 仅支持的类型显示 | 为对应 Responses WebSocket 路径启用连接；不能用参数覆盖的 `stream` 字段替代传输模式。 |
| 系统提示词 | 可选 | 添加或替换渠道级系统提示词；会改变发送给上游的语义。 |
| 强制格式化、思维到内容 | 按类型显示，默认关闭 | 处理特定请求/响应格式或将 reasoning 内容转换为 `<think>`；不是通用协议切换。 |

**透传与覆盖的执行边界**

- 渠道管理-确认开启透传请求体

![渠道管理-确认开启透传请求体页面](/assets/guide/feature-guide/create-channel-pass-through-request-body-description.png)

- 渠道管理-确认开启透传请求头

![渠道管理-确认开启透传请求头页面](/assets/guide/feature-guide/create-channel-pass-through-request-headers-description.png)

- 全局或渠道级请求体透传会跳过正常转换链路；不要同时假设模型映射、参数覆盖和协议转换仍会按普通路径执行。
- 请求头透传使用 `*` 或 `re:`/`regex:` 规则复制客户端请求头，但会排除 Authorization、`x-api-key`、`x-goog-api-key`、WebSocket 握手和其他安全头。
- 请求头覆盖在透传之后应用，显式覆盖优先；`{client_header:NAME}` 必须是完整值，客户端未携带该头时不会加入。
- 请通过客户端请求选择流式模式。参数覆盖改写 JSON 中的 `stream` 不保证同步调整网关、适配器和上游的流式处理状态。

### 其他设置

- 渠道管理-其他设置

| 设置 | 默认或范围 | 说明 |
| --- | --- | --- |
| 代理地址 | 空；HTTP、HTTPS、SOCKS5、SOCKS5H | 代理地址必须包含有效主机；不要把代理密码写入备注或截图。 |

| 标签、备注 | 空；备注最多 255 字符 | 用于筛选和内部管理；不要写入密钥、用户隐私或临时凭证。 |

| 已忽略上游模型 | 逗号分隔的精确名称或 `regex:` 规则 | 排除不希望自动加入的模型；不要把它当作渠道模型的永久替代清单。 |

## 渠道类型专属配置

### 网关渠道：New API 与 Sub2API

- 渠道管理-New API 网关渠道

![渠道管理-New API 网关渠道页面](/assets/guide/feature-guide/create-channel-newapi-gateway-channel.png)

New API 和 Sub2API 都通过网关 Base URL 拼接请求路径，普通配置不会自动补 `/v1`，因此 Base URL 不应以 `/v1` 结尾。两者可提供 OpenAI、Responses、Claude、Gemini 等网关能力；具体支持范围以网关实际部署为准。

New API 还可以绑定支持 `new_api` 上游的任务插件扩展。扩展仍保持 `type=60`，不能把它和独立插件渠道混淆。绑定、解绑和复制带扩展的渠道需要 `TaskPluginBind`。

### 独立插件渠道

- 渠道管理-插件渠道

![渠道管理-插件渠道页面](/assets/guide/feature-guide/create-channel-plugin-channel.png)

1. 在「插件」分类中选择已注册插件。
2. 填写插件所需凭证、分组和其他字段。

### 状态管理与删除风险

- 渠道管理-多密钥管理

![渠道管理-多密钥管理页面](/assets/guide/feature-guide/channel-management-key-management.png)

在渠道操作菜单中点击「管理密钥」打开「多密钥管理」。列表按 Key 分页显示索引、状态、禁用原因和禁用时间，可按状态筛选；顶部「已启用」「手动禁用」「自动禁用」统计卡始终统计全部 Key，不随筛选变化。

## 参数覆盖系统

参数覆盖在请求转换后、发送上游前执行。它不是完整协议转换器，也不会自动同步客户端流式状态。可视化编辑器和 JSON 模式写入同一份 `param_override`。

### 生效顺序与边界

- 只有请求进入相应 relay 处理路径时才会执行覆盖；请求体透传会绕过普通转换和部分覆盖链路。
- `operations` 按数组顺序执行，前一个操作的结果会成为后一个操作的输入。
- 同时存在旧式顶层字段和 `operations` 时，旧式字段先应用，再应用 `operations`。
- 命中会话规则时，规则中的参数覆盖模板会与渠道参数覆盖合并，见<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#会话与重试" target="_blank" rel="noopener noreferrer">会话与重试</a>。
- 条件默认使用 `OR`；`logic: "AND"` 才要求全部条件满足。
- 条件读取当前请求 JSON 和运行上下文；前序操作修改模型后，后续条件可能读取修改后的值。`original_model`、`upstream_model` 等上下文值不是自动写入请求 JSON 的字段。
- `return_error` 会提前返回自定义错误；其状态码和错误字段仍受后端解析范围约束，不应仅依据输入框可接受的范围宣称所有值都可用。
- 条件比较出错时（如 `full` 两侧类型不同、数值比较的一侧不是数字、`regex` 表达式无效），本次请求以 `channel:param_override_invalid` 失败，按渠道类错误处理，而不是视为条件不匹配。

### 可视化编辑器与 JSON

- 渠道管理-参数覆盖

![渠道管理-参数覆盖页面](/assets/guide/feature-guide/create-channel-request-and-response-parameter-overrides-visual-editor.png)

可视化模式适合逐条编辑；JSON 模式适合复制完整规则。

### 操作速查

| 操作 | 常用字段 | 说明 |
| --- | --- | --- |
| `set`、`delete` | `path`、`value` | 设置或删除 JSON 字段。 |
| `append`、`prepend` | `path`、`value`、`keep_origin` | 在字符串或数组前后追加内容；保留原值时避免覆盖已有内容。 |
| `move`、`copy` | `from`、`to` | 移动会删除源字段，复制保留源字段。 |
| `trim_prefix`、`trim_suffix` | `path`、`value` | 删除匹配的前缀或后缀。 |
| `ensure_prefix`、`ensure_suffix` | `path`、`value` | 不存在时补充前缀或后缀。 |
| `trim_space`、`to_lower`、`to_upper` | `path` | 清理或转换字符串。 |
| `replace`、`regex_replace` | `path`、`from`、`to` | 普通替换或正则替换。 |
| `prune_objects` | `path`、条件 | 按条件清理对象项。 |
| `set_header`、`delete_header` | Header 名和值 | 修改覆盖头；不能保证删除适配器后续重新生成的原生头。 |
| `copy_header`、`move_header` | `from`、`to` | 在运行时请求头覆盖表中复制或移动。 |
| `pass_headers` | Header 名称列表 | 按原名把列出的客户端请求头复制到运行时头覆盖。这里不做安全头排除（与请求头覆盖中的 `*`、`re:` 透传不同），列出的 `Authorization`、`x-api-key` 也会照样复制；只列出确实需要的头。 |
| `sync_fields` | JSON/Header 来源与目标 | 在请求字段与请求头之间同步值。 |
| `return_error` | 错误对象 | 直接结束请求并返回自定义错误，适合明确拒绝条件。 |

### 条件、路径与安全字段

| 条件项 | 说明 |
| --- | --- |
| `full`、`prefix`、`suffix`、`contains` | 字符串或可比较值的匹配方式。 |
| `regex` | 按正则表达式匹配字段的字符串形式；条件值必须是字符串。 |
| `gt`、`gte`、`lt`、`lte` | 双方必须是 JSON 数字，不能把任意字符串当作数字比较。 |
| `invert` | 反选匹配结果；缺失字段是否通过由 `pass_missing_key` 先决定。 |
| `pass_missing_key` | 路径缺失时允许条件通过；默认不通过。 |
| `logic` | `AND` 要求全部条件通过；省略时为 `OR`。 |
| JSON 路径 | 支持 `messages.0.content`、`messages.-1.content` 等路径。 |
| 运行上下文 | 可按原始模型、上游模型、用户/分组等上下文条件匹配；不要把这些名称当作请求体固定字段。 |

<Callout type="warn" title="注意">
  参数覆盖可以改变请求语义、请求头和错误处理。不要用它切换 `stream`，不要把客户端密钥透传到不可信上游，正则替换、Header 同步和自定义错误也应谨慎启用。
</Callout>

| 自动同步上游模型 | 开启「自动同步上游模型」后，由 Master 实例定时检测，默认每 30 分钟一次 | 新模型加入渠道模型列表后，下一次请求起参与路由；启用内存缓存时，Master 实例以外的节点在下一次同步后才使用。 |
| 测试所有渠道、检测所有上游更新 | 点击后提交为后台任务 | 由 Master 实例领取：处理该请求的节点是 Master 实例时立即开始，否则约 15 秒内开始；已有同类任务时提交会被拒绝。手动检测只记录待新增和待移除的模型，应用后才改动模型列表。 |
| 更新所有余额 | 点击后同步执行 | 逐个渠道查询，全部完成后才返回；余额不足的渠道会被自动禁用。 |
| 测试连接、查询余额（单个渠道） | 在测试对话框中测试，或点击余额 | 只更新测试时间、响应时间或余额，不改变渠道状态，不影响路由。 |

</div>

### 补充说明

- **抽屉保存**：四个页签共用一个表单，成功提示「渠道创建成功」或「渠道更新成功」；保存失败时抽屉保持打开，并显示失败原因。
- **不自动测试**：保存只写入配置，不连接上游，也不自动测试；需要时在[测试连接](#测试连接)中手动测试。
- **正在进行的连接**：禁用或删除渠道（含自动禁用）时，该渠道上正在进行的 Realtime 和 Responses WebSocket 连接会被关闭；启用 Redis 时，其他节点上的这类连接一并关闭。
- **同步完成前**：启用内存缓存时，各节点的路由可能暂时不一致。

## 注意事项

- **批量操作作用于全部渠道**：「测试所有渠道」「更新所有余额」「检测所有上游更新」「应用所有上游更新」「删除所有已禁用」「修复渠道一致性」都不受当前列表筛选限制，建议在低峰期执行。
- **测试和余额更新可能改变渠道状态**：「测试所有渠道」可能自动禁用或恢复渠道，「更新所有余额」可能自动禁用余额不足的渠道，见[自动变更与后台任务](#自动变更与后台任务)。
- **自动同步会直接改动模型列表**：开启「自动同步上游模型」后，定时检测发现的新模型会直接加入渠道模型列表（只新增、不移除，已忽略的模型除外）。
- **「应用所有上游更新」不逐项审核**：一次应用所有已检测渠道的待新增和待移除模型；需要逐项审核时，在「预览上游模型变更」中勾选后点击「确认应用所选变更」。
- **敏感操作需要 `ChannelSensitiveWrite`**：没有该权限的 Admin 不能创建、复制或删除渠道，也不能保存凭证、类型、Base URL、代理、请求头覆盖、参数覆盖等敏感项的修改，见[权限与安全边界](#权限与安全边界)。
- **删除不可恢复，复制会带走凭证**：删除渠道后无法从 New API 恢复；复制渠道会复制原渠道的凭证，不能当作凭证轮换，见[启用、禁用与删除](#启用禁用与删除)和[复制渠道](#复制渠道)。

<Accordion title="创建或更新渠道时无法保存">
**说明**：保存前先在页面中校验，再由服务端校验，常见提示如下。

| 提示原文 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 「请先修复高亮字段后再保存」（英文 Please fix the highlighted fields before saving） | 名称、模型、分组未填写，新建时未填写凭证；或 JSON 字段、代理地址、HTTP/2 连接分片、高级自定义路由不符合要求。 | 按高亮字段逐项修正。 |

| 「部署地区不能为空」「部署地区必须包含 default 字段」 | Vertex AI 的「部署区域」为空，或 JSON 中缺少 `default`。 | 填写区域；使用 JSON 时加入 `default`。 |

</Accordion>

<Accordion title="测试渠道时认证失败">
**说明**：测试失败时提示「… 测试失败」（英文 … test failed），并附上游返回的错误详情。

**可能原因**：
- Base URL 误包含完整接口路径。
- 凭证格式不正确，或组织、项目、区域填写有误。
- 代理或端点类型与上游不符。

**处理方法**：
1. 按错误详情修正对应字段。
2. 用详细测试换一个端点类型或模型重新测试，见[测试连接](#测试连接)。
</Accordion>

<Accordion title="用户看不到某个模型">
**说明**：调用方获取的模型列表只包含其分组中已启用渠道提供、且已配置价格的模型。模型广场是否展示另由模型管理中的「广场展示」决定，见<a href="/zh/docs/guide/feature-guide/admin/model#广场展示状态" target="_blank" rel="noopener noreferrer">模型管理</a>。

**可能原因**：
- 渠道模型列表未包含该名称；使用模型映射时，映射的源名称也需加入模型列表。
- 渠道分组与用户分组或 API 密钥的分组不匹配。
- API 密钥限制了可用模型。
- 提供该模型的渠道已禁用。
- 模型未配置价格。站点开启「自用模式」或用户开启「接受未定价模型」时不受此限制。

**处理方法**：
1. 核对渠道的模型、分组和状态，以及 API 密钥的模型限制。
2. 未配置价格时，请 Root 在<a href="/zh/docs/guide/feature-guide/system-settings/settings-billing#模型定价" target="_blank" rel="noopener noreferrer">计费与支付配置</a>中配置价格。
</Accordion>

<Accordion title="请求被路由到意外的渠道">
**可能原因**：
- 优先级、权重、渠道状态或标签范围与预期不符。
- 请求路径不同，或命中了会话规则，或触发了<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#会话与重试" target="_blank" rel="noopener noreferrer">重试设置</a>。
- 在共享入口上，普通渠道与插件渠道一起参与选择。

**处理方法**：
1. 在使用日志详情的<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#请求决策记录" target="_blank" rel="noopener noreferrer">请求策略决策</a>中查看实际选择过程。
</Accordion>

<Accordion title="参数覆盖没有生效">
**可能原因**：
- 开启了请求体透传，绕过了参数覆盖。
- 操作顺序、条件路径或 JSON 类型与预期不符。
- 请求没有进入执行参数覆盖的 relay 处理路径。

**处理方法**：
1. 对照[生效顺序与边界](#生效顺序与边界)逐项检查。
</Accordion>

<Accordion title="渠道频繁被自动禁用">
**可能原因**：
- 上游返回的状态码或错误文本命中了<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#渠道健康" target="_blank" rel="noopener noreferrer">渠道健康</a>中的自动禁用规则，如测试模型、代理或上游限流导致的失败。
- 执行「更新所有余额」时余额小于等于 0，渠道被自动禁用，原因为「余额不足」。

**处理方法**：
1. 查看渠道的禁用原因，区分自动禁用与手动禁用。
2. 对照渠道健康中的规则调整渠道或测试设置。
</Accordion>

<Accordion title="获取模型失败">
**提示原文**：「获取模型失败」（英文 Failed to fetch models）或「此渠道类型不支持获取模型」（英文 This channel type does not support fetching models）；服务端或上游返回了原因时，显示该原文。

**说明**：获取失败不会替换已保存的模型列表。

**可能原因**：
- 该渠道类型不支持获取模型。
- 凭证、Base URL 或网络有误。
- 高级自定义渠道缺少模型列表路由。

**处理方法**：
1. 修正后重新获取。
</Accordion>

<Accordion title="余额没有更新">
**提示原文**：「多密钥渠道不支持余额查询」（英文 Multi-key channels do not support balance queries）；任务插件渠道为 `Task Plugin channels do not support balance queries`（仅英文）。

**可能原因**：
- 该渠道类型不支持普通余额接口，或是多 Key 渠道、任务插件渠道。
- Codex、vLLM/SGLang 使用其他运行信息入口，见[查询余额与运行状态](#查询余额与运行状态)。
</Accordion>

<Accordion title="多 Key 渠道不可用">
**可能原因**：渠道中的 Key 已被禁用或自动禁用，没有剩余可用的 Key。渠道总状态不能反映每个 Key 的状态。

**处理方法**：
1. 查看每个 Key 的状态和自动禁用原因，见[状态管理与删除风险](#状态管理与删除风险)。
</Accordion>

<Accordion title="执行「修复渠道一致性」后仍无法路由">
**说明**：修复在点击后同步完成。启用内存缓存的多实例部署中，其他节点在同步周期（默认 60 秒）后才使用新的索引。已有修复在运行时提示「已经有一个修复任务在运行中，请稍后再试」（英文 A repair task is already running. Please try again later）。

**可能原因**：渠道的模型、分组、优先级或权重与预期不符，或凭证、上游有问题。修复只重建索引，不修复这些配置。

**处理方法**：
1. 刷新列表，检查模型、分组、优先级和权重。
2. 排查凭证与上游。
</Accordion>

<Accordion title="保存渠道后，部分请求仍按旧配置路由">
**说明**：启用内存缓存（含启用 Redis 的部署）时，各节点按同步周期（默认 60 秒）从数据库重新载入渠道，同步完成前不同节点的路由可能不一致。未启用内存缓存时，路由直接读取数据库。

**处理方法**：
1. 等待一个同步周期后重试。
</Accordion>

<Accordion title="执行「测试所有渠道」时提示已有任务正在运行">
**提示原文**：「已有通道测试任务正在运行或等待中，不能启动本次手动任务」（英文 A channel test task is already running or queued. Cannot start this manual task）；执行「检测所有上游更新」时为「已有模型更新任务正在运行或等待中，不能启动本次手动任务」（英文 A model update task is already running or queued. Cannot start this manual task）。

**可能原因**：同类型的系统任务（含定时触发的任务）正在运行或等待执行。

**处理方法**：
1. 在<a href="/zh/docs/guide/feature-guide/admin/system-info" target="_blank" rel="noopener noreferrer">系统信息</a>的「系统任务」中查看进度。
2. 任务结束后重新执行。
</Accordion>
