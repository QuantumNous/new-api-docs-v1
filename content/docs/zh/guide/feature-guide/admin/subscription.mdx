- 订阅套餐把价格、有效期、可用额度、额度重置周期、用户分组和支付方式组合成一项可购买的权益。
- 订阅管理仅 Admin 和 Root 可访问，从侧边栏「管理员」 → 「订阅」或访问 `/subscriptions` 进入，可以创建、编辑、启用、禁用套餐，以及批量重置某个套餐下的有效订阅额度。

<Callout type="info" title="提示">
  Root 在「系统设置」 → 「计费与支付」 → 「支付网关」中<a href="/zh/docs/guide/feature-guide/system-settings/settings-billing#支付合规确认" target="_blank" rel="noopener noreferrer">确认支付合规条款</a>之前，订阅管理页面只能查看套餐列表：页面顶部显示「管理员在支付网关设置中确认合规条款之前，订阅套餐的创建和修改会被锁定。」，「新建套餐」以及行内的编辑、重置订阅额度、启用/禁用按钮均不可用。
</Callout>

## 使用前准备

创建套餐前，建议先完成以下检查：

1. Root 需要在「系统设置」 → 「计费与支付」 → 「支付网关」中确认支付合规条款。
2. 明确套餐面向的用户、售价、有效期、总额度和额度重置方式。
3. 如需改变用户分组，先在<a href="/zh/docs/guide/feature-guide/system-settings/settings-billing#定价分组" target="_blank" rel="noopener noreferrer">分组定价</a>中创建并核对升级分组和降级分组。
4. 如需第三方支付，先完成对应网关的全局凭证、回调地址和 Webhook 配置。
5. 决定是否允许钱包余额兑换，以及订阅额度耗尽后是否允许继续使用钱包余额。

<Callout type="warn" title="注意">
  套餐保存成功不等于所有支付方式已经可用。第三方支付同时依赖套餐产品 ID、全局网关配置、回调可达性和支付平台中的产品状态。
</Callout>

## 创建订阅套餐

- 订阅管理-创建套餐

![订阅管理-创建套餐页面](/assets/guide/feature-guide/subscription-management-create-subscription.png)

1. 在订阅管理页面点击「新建套餐」。
2. 在「基本信息」中填写套餐标题、价格、额度、分组、限购和排序等字段。
3. 设置套餐是否立即启用、是否允许余额兑换，以及额度用尽后是否允许使用钱包余额。
4. 在「有效期设置」中选择有效期单位和值。
5. 在「额度重置」中选择重置周期；选择自定义周期时填写秒数。
6. 如需 Stripe、Creem 或 Waffo Pancake 支付，填写或选择对应的产品标识。
7. 点击「保存更改」。保存成功后，套餐状态由「启用状态」开关决定；新建表单默认启用。

### 基本信息参数

| 界面字段 | API 字段 | 类型、默认值与范围 | 生效方式与注意事项 |
| --- | --- | --- | --- |
| 套餐标题 | `title` | 必填文本；新建时为空。 | 显示在管理列表和用户侧套餐卡片中。只填写空白字符会被拒绝。 |
| 套餐副标题 | `subtitle` | 可选文本；新建时为空。 | 用于补充适用场景或权益摘要，不参与计费。 |
| 套餐价格 | `price_amount` | 数值；默认 `0`；后端允许 `0–9999`。 | 表示用户购买一次套餐需要支付的金额。套餐记录的 `currency` 固定保存为 `USD`，具体支付币种和结算行为仍受网关配置影响。 |
| 额度 | `total_amount` | 非负数；默认 `0`；`0` 表示不限总额度。 | 界面显示单位跟随实例的计费显示设置，保存时会换算为内部 quota。该额度会在创建用户订阅时写入权益快照。 |
| 升级分组 | `upgrade_group` | 可选；默认「不升级」；选项来自当前分组配置。 | 创建订阅时把用户切换到目标分组，并保存购买前分组。目标分组不存在时无法保存。 |
| 降级分组 | `downgrade_group` | 可选；默认「降级到购买前分组」；选项来自当前分组配置。 | 订阅到期、作废或删除时优先切换到指定分组；留空时按条件尝试恢复购买前分组。 |
| 限购 | `max_purchase_per_user` | 非负整数；默认 `0`；`0` 表示不限。 | 统计该用户在此套餐下仍存在的全部订阅记录，包括已过期、已作废和管理员添加的记录。删除记录后才会释放对应次数。 |
| 排序 | `sort_order` | 整数；默认 `0`。 | 数值越大，套餐在管理列表和用户侧越靠前；列表中显示为「优先级」。 |
| 启用状态 | `enabled` | 开关；默认开启。 | 控制套餐是否进入公开展示和普通购买流程，不会终止已经创建的订阅。 |
| 允许余额兑换 | `allow_balance_pay` | 开关；默认开启。 | 开启后，余额足够的用户可以用钱包余额购买；关闭后，购买弹窗中的「使用余额支付」不可用，并提示「该套餐不允许使用余额兑换」。 |
| 额度用尽后允许使用钱包余额 | `allow_wallet_overflow` | 开关；默认开启。 | 创建订阅时写入权益快照。是否实际回退钱包还取决于用户选择的计费偏好。 |

<Callout type="info" title="提示">
  界面中的「额度」不是所有部署都固定显示为美元。其标签和步进值会跟随实例的货币或 Token 显示设置，最终保存为 New API 内部 quota；配置时应使用本站显示的单位。
</Callout>

### 有效期参数

| 界面字段 | API 字段 | 可选值与默认值 | 计算方式 |
| --- | --- | --- | --- |
| 有效期单位 | `duration_unit` | 年、个月、天、小时、自定义(秒)；默认「个月」。 | 决定如何从订阅创建时间计算结束时间。 |
| 有效期数值 | `duration_value` | 正整数；默认 `1`；单位选择「自定义(秒)」时不显示，改为填写「自定义秒数」。 | 年和月按日历增加；日按 24 小时、小时按固定小时数增加。 |
| 自定义秒数 | `custom_seconds` | 单位选择「自定义(秒)」时必须大于 `0`。 | 直接把指定秒数加到订阅创建时间。非正值会导致订阅无法创建。 |

<Callout type="info" title="提示">
  有效期在每份用户订阅创建时计算并保存。之后修改套餐的有效期，不会延长或缩短已经存在的订阅。
</Callout>

### 额度重置参数

| 界面字段 | API 字段 | 可选值与默认值 | 生效方式 |
| --- | --- | --- | --- |
| 重置周期 | `quota_reset_period` | 不重置、每天、每周、每月、自定义(秒)；默认「不重置」。 | 决定订阅的下一次额度重置时间。每天推进到次日，每周推进到下一个周一，每月推进到下月第一天。 |
| 自定义秒数 | `quota_reset_custom_seconds` | 重置周期为「自定义(秒)」时才可填写，必须大于 `0`。 | 从当前计算基准向后增加指定秒数。下一次重置晚于订阅结束时间时，不再安排重置。 |

<Callout type="info" title="提示">
  重置额度只会把已用额度清零，不会改变套餐总额度，也不会延长订阅有效期。
</Callout>

### 第三方支付参数

| 界面字段 | API 字段 | 套餐侧用途 | 权限与依赖 |
| --- | --- | --- | --- |
| Stripe Price ID | `stripe_price_id` | 将套餐关联到 Stripe Price，并用 Stripe Checkout 的 `subscription` 模式创建首次购买会话。 | 还需配置全局 Stripe API Secret、Webhook Secret 和充值用 Stripe Price ID；套餐 Price ID 与系统充值 Price ID 是两个独立配置。套餐 Price 必须适用于订阅模式。 |
| Creem Product ID | `creem_product_id` | 将套餐关联到 Creem 产品。 | 还需配置全局 Creem API Key、Webhook Secret 和产品列表；套餐 Product ID 与系统充值产品配置是两个层级。 |
| Waffo Pancake Product ID | `waffo_pancake_product_id` | 从已保存店铺的一次性产品中选择套餐产品。 | 产品列表和「+ 新建」接口要求 Root，并依赖 Merchant ID、Private Key、Store ID 和回调配置。当前网关启用判定还要求系统已配置钱包充值用 Pancake Product ID；它与套餐 Product ID 不能混用。 |

<Callout type="info" title="提示">
  EPay 没有套餐级产品 ID。启用全局 EPay、配置至少一种支付方式且套餐价格不低于 `0.01` 后，用户可以按套餐价格创建 EPay 订单。钱包余额购买同样不需要第三方产品 ID。
</Callout>

<Callout type="warn" title="注意">
  - Stripe 和 Creem 下单时分别以套餐的外部 Price ID 或 Product ID 为准，实际扣款金额与币种由第三方产品决定；New API 列表展示和订单记录使用本地「套餐价格」。发布前必须确保外部产品与本地价格完全一致。修改一端不会自动同步另一端。
  - Stripe 套餐使用 `subscription` 模式创建周期性订阅。Stripe 会按所选 Price 的周期自动续费，直到订阅被取消。Stripe 后续的续费扣款不会在 New API 中创建或延长订阅，本地订阅仍按套餐有效期到期；上线前请在 Stripe 后台确认取消方式，并告知用户续费规则。
</Callout>

#### 创建 Waffo Pancake 产品

「Waffo Pancake Product ID」右侧的「+ 新建」会使用当前表单中的套餐标题和价格，在已保存的 Pancake 店铺中创建并发布一个一次性产品，然后把返回的产品 ID 填入表单。

执行前需要满足：

- 当前账户是 Root；
- 已在计费与支付设置中完成 Waffo Pancake 凭证和店铺配置；
- 套餐标题不为空；
- 套餐价格大于 `0`。

<Callout type="warn" title="注意">
  该操作会先在第三方平台创建产品，之后仍需保存套餐表单。若第三方产品创建成功但套餐保存失败，Pancake 中的产品不会由 New API 自动删除，应到第三方平台核对并按需清理。
</Callout>

## 编辑订阅套餐

- 订阅管理-编辑套餐

![订阅管理-编辑套餐页面](/assets/guide/feature-guide/subscription-management-edit-subscription.png)

1. 在目标套餐右侧点击编辑图标。
2. 修改需要调整的字段并点击「保存更改」。

编辑套餐主要影响后续购买和新建订阅，不是批量迁移既有订阅的工具。各类字段对已有订阅的影响如下：

| 套餐字段 | 对已有订阅的影响 |
| --- | --- |
| 价格、允许余额兑换、启用状态、排序、支付产品 ID | 影响后续展示或购买，不改变已购买订阅的权益。 |
| 有效期、总额度、升级分组、降级分组、额度用尽后允许使用钱包余额 | 购买订阅时写入快照；修改套餐不会重写已有订阅中的对应值。 |
| 额度重置周期、自定义重置秒数 | 自动重置或管理员选择推进下次重置时间时，会读取套餐当前规则，因此可能影响已有的有效订阅。 |
| 限购 | 后续购买或管理员添加订阅时重新统计现存记录并应用当前上限。 |

<Callout type="warn" title="注意">
  待支付订单保存的是套餐 ID 和下单金额。支付回调完成订单时会重新读取套餐并创建权益；用户支付期间若修改套餐的有效期、额度、分组或「额度用尽后允许使用钱包余额」配置，最终创建的权益可能与下单时看到的内容不同。高风险调整应先暂停公开购买并处理待支付订单。
</Callout>

## 启用和禁用套餐

- 订阅管理-启用套餐

![订阅管理-启用套餐页面](/assets/guide/feature-guide/subscription-management-enable-subscription-plan.png)

- 订阅管理-禁用套餐

![订阅管理-禁用套餐页面](/assets/guide/feature-guide/subscription-management-disable-subscription-plan.png)

在套餐行末点击状态图标（已启用的套餐显示「禁用」图标，已禁用的套餐显示「启用」图标），再在「确认启用」或「确认禁用」对话框中点击「启用」或「禁用」。两项操作的效果如下：

- **启用**：套餐重新进入用户侧公开展示和普通购买流程。
- **禁用**：套餐不再向用户显示，也不能发起新的普通购买。

禁用套餐不会：

- 取消或暂停已经购买的用户订阅；
- 清零订阅额度或改变结束时间；
- 使历史订单失效；
- 阻止已经创建的待支付订单在成功回调后完成；
- 阻止管理员在用户管理中为指定用户添加该套餐。

<Callout type="warn" title="注意">
  当前订阅管理页面没有删除套餐功能。禁用是发布状态控制，不是撤销权益；如需立即终止某个用户的订阅，应在「用户管理」 → 「管理订阅」中执行作废操作，并先确认分组回退和其他有效订阅的影响。
</Callout>

## 重置订阅额度

- 订阅管理-重置订阅额度

![订阅管理-重置订阅额度页面](/assets/guide/feature-guide/subscription-management-reset-subscription-quota.png)

套餐列表中的重置操作会处理该套餐下所有状态为生效的订阅：

1. 点击目标套餐右侧的重置图标。
2. 决定是否开启「推进下次重置时间」。该开关默认开启。
3. 点击「重置额度」。成功提示会显示实际重置的有效订阅数量。

| 选项 | 实际行为 |
| --- | --- |
| 开启「推进下次重置时间」 | 清零已用额度，并按套餐当前重置规则重新计算下一次重置时间。 |
| 关闭「推进下次重置时间」 | 只清零已用额度，保留订阅原有的下一次重置时间。 |

<Callout type="warn" title="注意">
  这是对套餐下所有用户的批量操作。执行前应确认目标套餐、重置周期和影响人数；尤其不要把它当作给单个用户补额度的快捷方式。单个用户的重置应从「用户管理」 → 「管理订阅」执行。
</Callout>

## 用户订阅与权益状态

订阅管理页面维护的是「套餐定义」。某个用户已经获得的订阅，需要在「用户管理」中打开该用户的「管理订阅」进行维护。管理员可以在那里添加订阅、按套餐重置额度、使订阅作废或删除订阅记录。

| 用户订阅状态 | 含义 |
| --- | --- |
| `active`（生效） | 订阅处于有效期内，可以按计费偏好参与额度结算。 |
| `expired`（已过期） | 到达结束时间后，被后台维护流程标记为已过期。 |
| `cancelled`（已作废） | 管理员提前执行作废，结束时间同时改为当前时间。 |

<Callout type="info" title="提示">
  「作废」会保留订阅历史记录；「删除」会硬删除该条订阅记录且没有恢复入口。删除订阅并不表示相关支付订单、充值流水、使用日志或任务记录也会被一并删除。完整操作说明参阅<a href="/zh/docs/guide/feature-guide/admin/user#用户订阅管理" target="_blank" rel="noopener noreferrer">用户管理</a>。
</Callout>

## 分组升级与回退

如果套餐配置了升级分组，订阅创建时系统会立即尝试把用户切换到该分组，并在订阅中记录购买前分组。订阅到期、被管理员作废或删除时，回退逻辑如下：

1. 用户还有其他生效中、且设置了升级分组的订阅时，保持当前分组不变。
2. 否则，订阅设置了降级分组时，直接切换到该分组；即使用户分组已被手动修改，也会被改为降级分组。
3. 没有设置降级分组时，只有用户当前仍处于该订阅的升级分组，才恢复购买前分组。购买时用户已在升级分组中的，订阅没有记录购买前分组，因此不回退。

<Callout type="warn" title="注意">
  执行作废或删除前，应先检查用户的当前分组和其他有效订阅。
</Callout>

## 支付方式与续费边界

| 支付方式 | 套餐要求 | 创建订阅的方式 |
| --- | --- | --- |
| 钱包余额 | 开启「允许余额兑换」，用户余额充足。 | 按 `ceil(套餐价格 × QuotaPerUnit)` 扣除内部额度，并立即创建一份订阅。 |
| EPay | 全局 EPay 已启用且有可用支付方式；套餐价格至少为 `0.01`。 | 支付回调成功后创建一份订阅，不需要套餐产品 ID。 |
| Stripe | 套餐填写 Stripe Price ID，全局 Stripe 与 Webhook 配置完整。 | 首次 Checkout 支付确认后创建一份本地订阅。 |
| Creem | 套餐填写 Creem Product ID，全局 Creem 和回调配置完整。 | 支付回调成功后创建一份订阅。 |
| Waffo Pancake | 套餐选择独立的 Waffo Pancake Product ID，全局凭证、店铺和回调配置完整。 | 购买一次性产品并在回调成功后创建一份订阅。 |

<Callout type="info" title="提示">
  - 用户可以在钱包页面选择「优先订阅」「优先钱包」「仅用订阅」或「仅用钱包」。
  - 套餐的「额度用尽后允许使用钱包余额」只在用户选择「优先订阅」时起作用：订阅额度不足时，只有用户所有生效中的订阅都开启了该选项，才会继续使用钱包余额。该选项不会覆盖用户自己的计费偏好。
  - 用户侧购买、订阅状态和计费偏好说明参阅<a href="/zh/docs/guide/feature-guide/user/wallet" target="_blank" rel="noopener noreferrer">钱包</a>。
</Callout>

## 自动维护机制

订阅到期和周期额度重置由后台维护任务处理：

- 只在 Master 实例运行；
- 服务启动后先执行一次，之后约每分钟检查一次；
- 每批最多处理 300 条记录；
- 到期处理会更新订阅状态，并按条件执行用户分组回退；
- 周期重置只处理状态仍为生效的订阅。

## 保存与生效

本页的操作提交后立即写入数据库；套餐与用户订阅的读取方式不同，按下列两组查看。

### 套餐

用户侧的套餐列表直接读取数据库，保存后各节点立即可见。下单、支付回调、余额购买、管理员添加订阅、重置额度和订阅额度的周期重置读取套餐缓存：启用 Redis 时保存后立即生效；未启用 Redis 的多实例部署中，其他节点最长约 5 分钟（默认）后才读到新值。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 新建套餐 | 「新建套餐」抽屉中点击「保存更改」，提示「创建成功」 | 立即写入，用户侧套餐列表刷新后即可看到。 |
| 编辑价格、允许余额兑换、排序、支付产品 ID | 编辑抽屉中点击「保存更改」，提示「更新成功」 | 只影响之后的展示和购买，已购订阅不变。 |
| 编辑有效期、总额度、升级分组、降级分组、额度用尽后允许使用钱包余额 | 编辑抽屉中点击「保存更改」 | 购买订阅时写入快照，修改套餐不改变已有订阅。 |
| 编辑额度重置周期、自定义重置秒数 | 编辑抽屉中点击「保存更改」 | 已有的有效订阅在下一次自动重置，或管理员重置时开启「推进下次重置时间」时，才按新规则计算。 |
| 编辑限购 | 编辑抽屉中点击「保存更改」 | 之后每次购买或管理员添加订阅时，按新上限重新统计。 |
| 启用、禁用套餐 | 点击状态图标，在「确认启用」「确认禁用」对话框中确认，提示「已启用」或「已禁用」 | 用户侧套餐列表随即显示或隐藏；已购订阅、待支付订单的支付回调和管理员添加订阅不受影响。 |
| 重置订阅额度 | 点击重置图标，在确认框中点击「重置额度」，提示「已重置 … 个有效订阅」 | 立即执行，只处理该套餐下状态为生效且未到结束时间的订阅。 |

</div>

### 订阅与到期

用户订阅直接写入数据库，各节点立即生效。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 用户订阅的添加、重置、作废、删除 | 在「用户管理」→「管理订阅」中逐项提交 | 立即生效；用户分组随之切换，不撤销用户会话，见<a href="/zh/docs/guide/feature-guide/admin/user#用户订阅管理" target="_blank" rel="noopener noreferrer">用户管理</a>。 |
| 订阅到期、周期重置 | 无需操作 | 到达结束时间后立即不再提供订阅额度；状态改为「已过期」和分组回退，由 Master 实例的后台任务约每分钟处理一次，见[自动维护机制](#自动维护机制)。 |

</div>

## 注意事项

- **重置订阅额度是全员批量操作**：影响该套餐下所有有效订阅；单个用户的重置请在「用户管理」→「管理订阅」中执行，见[重置订阅额度](#重置订阅额度)。
- **作废、删除订阅会触发分组回退**：执行前检查用户当前分组和其他有效订阅，见[分组升级与回退](#分组升级与回退)。
- **编辑套餐会影响待支付订单**：支付回调完成订单时重新读取套餐，支付期间修改有效期、额度或分组，最终权益可能与下单时不同，见[编辑订阅套餐](#编辑订阅套餐)。
- **禁用套餐不撤销权益**：页面没有删除套餐功能，见[启用和禁用套餐](#启用和禁用套餐)。
- **保存成功不代表支付可用**：第三方支付还依赖产品 ID、全局网关配置和回调，见[使用前准备](#使用前准备)和[支付方式与续费边界](#支付方式与续费边界)。

<Accordion title="订阅已到期，状态仍为「生效」或分组没有回退">
**说明**：到期处理由 Master 实例上的后台维护任务约每分钟执行一次。已到结束时间但尚未被标记的订阅，不再用于扣除订阅额度。

**可能原因**：
- 没有运行中的 Master 实例。
- 后台维护任务执行失败，应用日志中有对应错误。
- 订阅刚到期，任务尚未执行。

**处理方法**：
1. 检查 Master 实例和后台任务的运行情况。
2. 查看应用日志。
3. 需要立即终止时，在「用户管理」→「管理订阅」中作废该订阅。
</Accordion>

<Accordion title="添加订阅或用户购买时提示「已达到该套餐购买上限」">
**提示原文**：「已达到该套餐购买上限」（英文 Purchase limit for this plan has been reached）

**可能原因**：该用户在此套餐下现存的订阅记录数已达到「限购」，已过期、已作废和管理员添加的记录都计入。

**处理方法**：
1. 调高套餐的「限购」。
2. 或删除该用户的旧订阅记录；删除不可恢复。
</Accordion>

<Accordion title="保存套餐时提示参数不合法">
**说明**：服务端校验失败时的提示如下。

| 提示原文 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 「套餐标题不能为空」（英文 Subscription plan title cannot be empty） | 未填写套餐标题。 | 填写标题。 |
| 「价格不能超过9999」（英文 Price cannot exceed 9999） | 价格超过 9999。 | 调低价格。 |
| 「升级分组不存在」「降级分组不存在」（英文 Upgrade group does not exist、Downgrade group does not exist） | 所选分组未在分组定价中创建。 | 先在<a href="/zh/docs/guide/feature-guide/system-settings/settings-billing#定价分组" target="_blank" rel="noopener noreferrer">分组定价</a>中创建分组。 |
| 「自定义重置周期需大于0秒」（英文 Custom reset cycle must be greater than 0 seconds） | 选择自定义周期时，秒数不大于 0。 | 填写大于 0 的秒数。 |
</Accordion>

<Accordion title="用户侧看不到刚创建的套餐">
**可能原因**：
- 套餐的「启用状态」未开启。
- Root 尚未确认支付合规条款，此时用户侧套餐列表为空。

**处理方法**：
1. 开启「启用状态」。
2. 请 Root 在「系统设置」→「计费与支付」→「支付网关」中确认合规条款。
</Accordion>
