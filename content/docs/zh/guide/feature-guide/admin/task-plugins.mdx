- 任务插件管理仅 Root 可访问，Root 从侧边栏「管理员」 → 「任务插件」或访问 `/task-plugins` 进入管理页。
- 任务插件把图像、视频、音频等异步任务平台接入 New API 的统一任务接口。
- 插件以 JavaScript 插件形式在 `pkg/jsplugin` 沙箱中运行，并通过「任务插件」类型渠道与平台路由集成。


## 任务插件管理概览

页面顶部提供「启用任务插件」全局开关，下方为「已安装」「插件市场」两个标签页。已安装标签用于查看、上传和管理插件；市场标签从配置的索引源浏览和安装插件。

![任务插件页面](/assets/guide/feature-guide/task-plugins-overview.png)

### 全局启用开关

- 「启用任务插件」开关对应系统选项 `TaskPluginEnabled`。
- 该开关只提供两个层级：**全局主开关**和**每个插件各自的启用开关**。关闭主开关时，整个任务插件系统（包括出厂与自定义插件）立即停止服务。

<Callout type="info">
  出厂插件不可删除、也不可单独禁用。自定义版可以覆盖出厂插件；删除或禁用。
</Callout>

<Callout type="warn">
  全局开关关闭不会取消在途任务，出厂插件和自定义插件都会立即停止服务；进行中的任务交由超时清理流程处理（见「任务超时与清理」）。
</Callout>

### 已安装与市场

- 「已安装」：列出当前注册的任务插件，支持表格/卡片视图、搜索、分页与排序。
- 「插件市场」：从已配置的市场来源浏览可安装插件，安装流程与手动上传完全一致。

## 任务插件简介与内置插件

任务插件描述了一个异步任务平台如何提交任务、查询结果、提取用量与产出结果。插件声明自己支持的模型、可绑定的渠道类型、计费参数与能力端点。插件与渠道两层分离：**上传插件只注册插件能力，不会自动创建渠道**；需另行创建「任务插件」渠道并绑定插件 Key（见「创建任务插件渠道」）。

插件分为三层来源：

- **出厂插件**：随 New API 内置，源码以 `//go:embed` 方式嵌入（`plugins/tasks/<key>/plugin.js`），启动时自动注册。出厂插件不可独立删除。
- **自定义插件**：通过上传或市场安装的覆盖层，与同名出厂插件按 Key 关联，可以覆盖出厂插件的某个版本。
- **第三方插件**：与出厂插件不同名的插件。

## 创建任务插件渠道

插件本身不参与路由；要让某个平台可调用，需要创建「任务插件」类型的渠道并绑定插件 Key。

### 前置条件

1. 目标插件已注册：已在任务插件页上传，或从市场安装，且运行时状态为「已注册」。
2. Root 默认拥有创建渠道权限；Admin 需由 Root 在管理员权限矩阵中授予。
3. 准备好上游服务地址与凭证（Base URL、API Key 等，按插件接入的平台要求）。

### 操作流程

1. 进入「渠道管理」 → 「创建渠道」。
2. 类型选择**任务插件**。
3. 填写「任务插件」字段：下拉选择已注册插件（列表来自 `/api/task_plugin_options`）。选择插件后，表单会自动把该插件声明的模型填入「模型」列表。
4. 填写「Base URL」（必填）——插件执行时作为上游服务地址注入插件环境。
5. 填写「API 密钥」——渠道 `key` 会作为插件环境的 `apiKey` 传入。
6. 核对模型、分组，按需设置优先级/权重、测试模型、标签、状态等。
7. 保存渠道。保存后可使用实际模型发起一次异步任务验证。

- 创建任务插件渠道

![创建任务插件渠道页面](/assets/guide/feature-guide/task-plugins-create-plugin-channel.png)

### 字段说明

| 字段 | 规则与说明 |
| --- | --- |
| 类型 | 选择 Task Plugin（61）；无 `task_plugin.bind` 权限时该类型不可选。 |
| 任务插件 | 必填；≤30 字符；必须是当前已注册的插件。选择后会按插件声明的模型自动填充模型列表。 |
| Base URL | 必填（`base URL is required for task plugin channels`），为插件执行时的上游服务地址。 |
| API 密钥 | 渠道 `key`；新增时后端要求非空；作为插件环境的 `apiKey` 注入。 |
| 模型 | 必填；建议直接用插件声明的模型，也可按需增删。 |
| 分组 | 必填；决定哪些用户可使用该渠道。 |
| 优先级/权重 | 参与渠道选择的排序参数。 |
| 测试模型 | 用于渠道探测的模型名。 |

<Callout type="warn">
  - 「任务插件」渠道不支持**「测试连接」**（探测类型会被跳过）。请直接用真实模型发起任务验证，或通过任务日志确认提交与查询是否成功。
  - 删除或禁用插件前，先处理绑定它的渠道（切换到其他插件，或执行级联禁用），否则后续请求仍会路由到已失效的插件。
</Callout>

### 运行时状态

| 状态 | 含义 | 常见条件 |
| --- | --- | --- |
| 已注册 | 插件已编译并进入路由。 | 编译成功、插件已启用且全局主开关已开启。 |
| 编译失败 | 插件源码无法编译或元信息校验失败，悬停可查看详细错误。 | 源码错误、元信息缺失、必需钩子缺失。 |
| 已禁用 | 插件被全局主开关关闭，或其 Key 被禁用集合收录、或自定义层被单独关闭。 | 插件开关关闭、主开关关闭、或对应 Key 处于禁用集合。 |
| 已禁用；已回落出厂版 | 自定义层被禁用但同名出厂插件仍在服务（且其 Key 未被禁用集合收录）。 | 存在出厂插件且该 Key 未被禁用。 |

### 行操作

- **详情**：打开插件详情面板，查看元信息、计费参数、源码、版本历史、源码差异与沙箱干跑。
- **上传新版本**：为该 Key 上传一个新的版本。
- **删除活动自定义版本**：仅自定义版本可删除；出厂插件不可删除。删除前会校验是否仍被使用，并处理出厂回退或平台不可用提示。

## 上传插件

点击「上传插件」打开上传对话框。上传即注册一个新的插件版本；同名 Key 的多个版本保存在数据库中，同一 Key 同一时刻只有一个版本处于激活态。

- 任务插件-上传插件

![任务插件-上传插件页面](/assets/guide/feature-guide/task-plugins-upload-plugin.png)

- 任务插件-上传新版本

![任务插件-上传新版本页面](/assets/guide/feature-guide/task-plugins-upload-new-version.png)

1. 核对风险提示：上传插件是管理员级别的信任决策。插件可以访问渠道凭证并塑造上游请求，激活前应审查源码。
2. 选择源码来源，支持三种方式：
   - 拖放或选择 `.js` 插件文件；
   - 直接粘贴 JavaScript 源码到编辑器；
   - 输入插件源码 URL 并点击「获取」，由浏览器拉取源码填入编辑器（GitHub / gist 页面地址会自动改写为 raw URL）。
3. 填写「备注」（可选），用于描述该版本。
4. 点击「上传」。服务端会先解析元信息、校验 `ValidateV1Meta`，再执行路由冲突预检；通过后保存记录并同步注册表。
5. 上传成功后，页面会展示解析出的插件元信息，方便确认名称、Key、版本和来源。

上传参数与限制：

| 项 | 说明 |
| --- | --- |
| 源码大小 | 单次上传不超过 **1 MiB**。超限报错，可下载源码后粘贴处理。 |
| `enabled` | 是否上传后立即启用，默认启用。 |
| `remark` | 本版本备注，仅描述用途。 |
| `sourceSha256` | 可选。提供时必须等于源码的 SHA-256（忽略大小写），用于固定来源完整性与促进服务端校验。 |
| 同名同版本源码 | 若同一 `Key + Version` 已存在但源码哈希不同，会拒绝并提示「该 Key 和版本已存在且源码不同」。版本内容不可变。 |
| 冲突预检 | 启用且非强制时，会先构建有效注册表检查模型/渠道类型/路由冲突；存在冲突则拒绝保存。使用「强制」可跳过预检（插件可能发布后被抑制）。 |

<Callout type="info">
  编译与校验：`apiVersion` 必须为 `1`；`name`、`author.name` 必填；`key` 只能为小写字母、数字、`-`、`_` 且不超过 30；`version` 需为语义化版本；`models` 非空且大小写不敏感唯一；`channelTypes` 为正整数、不为 `61` 且不重复；`allowedHosts` 为无 scheme/端口/路径的主机名；`fetchMode` 只能为 `per_task` 或 `batch`。原始不规范字段（如 `channelType`、`submitPaths`、`actions` 等旧别名）会被兼容解析。
</Callout>

## 插件元信息

| 字段 | 类型/规则 | 说明 |
| --- | --- | --- |
| `apiVersion` | 整数，当前必须 `1` | 插件 API 版本。 |
| `key` | 字符串 ≤30，`^[a-z0-9][a-z0-9\\-_]*$` | 插件唯一标识，用于渠道绑定与市场识别。 |
| `name` | 字符串，必填 | 插件显示名称。 |
| `icon` | 可选 | 图标。 |
| `description` | 本地化文本 | 多语言描述。 |
| `version` | 字符串，语义化 | 插件版本号。 |
| `author` | `{ name, url }`，`name` 必填 | 作者信息。 |
| `channelTypes` | 正整数数组 | 可绑定的渠道类型编号；必须 ≠ `61`。 |
| `models` | 字符串数组，非空且唯一 | 插件支持的模型标识。 |
| `fetchMode` | `per_task` / `batch` | 拉取模式：逐任务需 `buildQueryRequest`，批量需 `buildBatchQueryRequest + parseBatchResult`。 |
| `routes` | 数组 | 插件声明的原生路由，参与路由生成。 |
| `protocols` | 数组 | 宿主协议声明（如流式、同步、后台）。 |
| `allowedHosts` | 主机名数组 | 插件允许访问的宿主集合。 |
| `auth` | 对象 | 认证方式（如 OAuth2 JWT），用于插件接入。 |
| `usageSchema` | 对象 | 计费参数声明，驱动阶梯计费。 |

`routes` 与 `protocols` 决定插件如何接入请求；`usageSchema` 决定任务结果如何计费（见「插件详情」 → 「计费参数」）。只有与插件声明的模型、渠道类型相匹配的请求才会路由到该插件。

## 插件市场

「插件市场」标签页从已配置的市场来源（每个来源提供一个 `index.json`，列出可安装插件）浏览并安装插件。市场索引与插件源码都由浏览器拉取，网关不发起任何外部请求，因此不存在服务端 SSRF 面。

- 任务插件-插件市场

![任务插件-插件市场页面](/assets/guide/feature-guide/task-plugins-plugin-marketplace.png)

### 浏览与安装

1. 若配置了多个来源，先切换目标来源；点击「刷新」重新拉取当前来源索引。
2. 浏览插件列表，点击某个版本打开安装确认对话框。
3. 核对「声明的能力」：允许访问的主机、可绑定渠道类型、认证方式、完整性哈希（来源索引提供时为审查用），并审查源码与差异（升级场景会有安装版→市场版 diff）。
4. 若索引未提供 `sha256`，会提示「无完整性哈希」：本次下载的源码无法固定到源预期版本。
5. 若浏览器拉取源码后计算出的哈希与索引不一致，会提示「完整性检查失败」并阻止安装。
6. 点击「安装并启用」（升级时为「升级并启用」）。安装走与手动上传完全相同的审查与准入流程：服务端会重新计算收到的源码哈希。索引与哈希均由浏览器提供，服务端不校验市场索引；篡改的浏览器可同时替换源码与哈希，因此完整性检查不能防止此类篡改。

<Callout type="warn">
  安装绝不会强制越过冲突。若模型、渠道类型或路由与现有插件冲突，安装会失败并提示；应先到「已安装」页处理冲突（例如删除/禁用冲突插件），再重新安装。
</Callout>

## 插件详情

从列表的「详情」操作打开插件详情面板，包含插件元信息卡、计费参数卡，以及「源码」「版本历史」「源码差异」「沙箱」四个标签。

- 任务插件-插件详情

![任务插件-插件详情页面](/assets/guide/feature-guide/task-plugins-plugin-details.png)

### 元信息

展示插件名称、Key、描述、作者、版本、渠道类型、模型与路由等元信息。若插件存在同名出厂插件，会同时显示「内置 vX / 市场 vY」关系与覆盖层级。

### 计费参数

插件可在 `usageSchema` 中声明计费参数。详情面板以「计费参数」表格展示，列包括名称、类型（数字/布尔/枚举）、单位（秒/次数/token/credit）、枚举值与描述。计费参数配合「模型与路由」 / 「计费与支付配置」中的阶梯计费表达式使用；未声明时显示「未声明计费参数」。

<Callout type="warn">
  计费参数表的字段来源于插件元信息。若渠道所在请求未命中该插件的模型或渠道类型，任务结果不会按该插件的 `usageSchema` 计费；需要同时满足路由匹配与计费表达式配置。
</Callout>

### 源码

显示当前激活版本的 JavaScript 源码，便于人工审查。审查时重点确认插件访问的主机、读取的凭证以及塑造的上游请求。

### 版本历史与激活

列出该 Key 的所有版本，可按版本查看来源差异，或选择任意历史版本执行「激活」，使该版本成为当前生效版本。激活前服务端会先编译该版本源码。

### 沙箱（干跑）

沙箱用于在不真正发起上游请求的情况下验证插件的钩子行为：

1. 选择钩子（如 `buildSubmitRequest`、`parseSubmitResponse`、`extractUsage`、`buildQueryRequest`、`parseTaskResult`、`buildBatchQueryRequest`、`parseBatchResult`、`buildContentRequest`、`renderers.openai_video` 等）。
2. 以 JSON 数组填写参数（必须是数组）。
3. 点击「运行干跑」，查看 JSON 结果；若钩子或参数错误，会在结果中显示错误信息。

<Callout type="info">
  干跑使用一个临时的插件副本执行，不会影响当前生效的注册表。可用于排查钩子逻辑、字段取值参数与计费提取是否正确。
</Callout>

## 启用、禁用与删除

### 启用与禁用单个插件

插件行的「启用」开关用于启停单个插件。禁用时若插件仍被使用，后端会返回「插件仍在使用中」确认，并附上仍在用的启用渠道数与在途任务数：

- 点击「级联禁用渠道」：将绑定该插件的启用渠道手动禁用（禁用原因「任务插件已禁用」），然后禁用插件。
- 点击「强制操作」：忽略使用中的渠道路由与在途任务，直接禁用插件。

<Callout type="warn">
  禁用「被覆盖的插件」时，如果它存在同名出厂插件，系统会**同时抑制出厂层**：把这个 Key 写入持久化的 `TaskPluginDisabledFactoryKeys`，使出厂插件也停止路由、语义上表现为「已禁用」，而不是「已回落出厂版」。只有没有被禁用集合收录时，自定义层被关才会显示「已回落出厂版」。
</Callout>

<Callout type="warn">
  禁用不会取消在途任务。仍在使用中的渠道如果不级联禁用，会导致后续请求仍指向已禁用插件，可能持续失败；建议先切换渠道或执行级联禁用。
</Callout>

### 删除活动自定义版本

仅自定义版本可删除（出厂插件不可删除）。删除前：

- 若存在同名出厂插件：提示「删除该自定义版不会停用平台，同名出厂插件将自动恢复」。
- 若没有出厂回退：提示「该插件没有出厂回退，删除或禁用会使平台不可用」。
- 若该版本处于激活态且仍被使用：返回使用中确认；可「强制操作」删除。

删除后，系统会从该 Key 剩余的版本中激活最新版本；若无剩余版本则移除该 Key，出厂插件继续服务（除非其 Key 已被禁用集合收录）。

### 全局开关

关闭页面顶部「启用任务插件」会立即停用整个任务插件系统（含出厂与自定义，`prepareGeneration` 会清空两层）。此时所有为插件路由的请求不再进入插件；在途任务由超时清理流程处理（见下）。

## 任务超时与清理

- 在途任务指 `platform` 为插件 Key 且状态不是成功/失败的任务。
- 禁用插件不会取消任务；超时任务由全局轮询清理扫描，达到 `TaskTimeoutMinutes`（默认 1440 分钟）后标记失败，非旧版任务会退还额度。该清理仅在 `UPDATE_TASK` 开启时运行；关闭后，超时任务不会被标记失败，也不会退还额度。
- 连续轮询失败上限由 `TASK_POLL_MAX_FAILURES`（默认 20）控制。

<Callout type="info">
  超时清理是全局轮询，不是按插件隔离的。某个插件禁用后，其遗留任务仍会按同一套超时与重试策略被清理，不会立即失败。
</Callout>

## 推荐配置流程

1. 确认当前账户为 Root，并确认管理员具备所需渠道权限（创建任务插件渠道需要 `task_plugin.bind`）。
2. 打开「任务插件」页，确认全局「启用任务插件」开关已开启。
3. 上传插件源码，或从市场安装所需平台插件；上传/安装后核对解析出的 Key、版本、渠道类型与模型。
4. 在「已安装」列表检查插件运行时状态是否为「已注册」；若为编译失败或未注册，按详情与错误信息处理。
5. 前往「渠道管理」创建「Task Plugin」类型渠道，绑定插件 Key、填写 Base URL、API 密钥与分组；确认模型自动填充是否符合预期。
6. 使用实际模型发起一次异步任务请求，通过任务日志确认提交、查询与结果解析正常，并检查计费参数是否生效。
7. 需要切换插件版本时先在「版本历史」中激活目标版本，再进行渠道测试。
8. 变更或禁用插件前，先确认绑定的渠道与在途任务，必要时执行级联禁用，避免请求路由到不可用插件。

## 故障排查

| 现象 | 建议检查 |
| --- | --- |
| 渠道类型里没有「Task Plugin」 | 确认当前账户具备 `task_plugin.bind` 权限；权限缺失时该类型不可选。 |
| 任务插件渠道无法保存 | 检查插件是否已注册、`task_plugin_key` 是否 ≤30 字符、Base URL 与 API 密钥是否填写；按后端错误信息逐项处理。 |
| 请求所选渠道与插件不匹配 | 检查渠道 `setting.task_plugin_key` 与请求固定 Key 是否一致；其他渠道类型的编号是否在插件的 `channelTypes` 内。 |
| 插件上传失败 | 检查源码是否超过 1 MiB、`apiVersion/key/version/name/models` 是否满足校验，以及是否与现有插件存在模型/渠道类型/路由冲突；使用「强制」可先发布后处理冲突。 |
| 插件显示编译失败 | 在详情中查看源码与错误，确认 `buildSubmitRequest/parseSubmitResponse/parseTaskResult` 等必需导出存在；`batch` 模式还需批量导出。 |
| 插件未注册 | 检查插件启用状态、全局主开关是否开启；若 Key 被禁用集合收录则需重新启用。 |
| 禁用后仍显示使用中 | 在确认对话框中执行「级联禁用渠道」或「强制操作」；并确认绑定渠道已切换或禁用。 |
| 禁用后插件仍路由同模型 | 检查该 Key 是否被 `TaskPluginDisabledFactoryKeys` 收录；若仍希望出厂插件服务，需重新启用（启用会从集合移除该 Key）。 |
| 任务不进入插件 | 检查渠道类型是否为任务插件、渠道是否绑定正确 Key、分组是否匹配、模型是否在插件 `models` 中。 |
| 计费不生效 | 检查插件是否声明 `usageSchema`、请求是否命中该插件、以及「计费与支付配置」中是否配置了匹配的阶梯计费表达式。 |
| 市场安装失败 | 检查索引是否可访问、`indexVersion` 是否 ≤1、`kind` 是否为 `task`、是否缺少 `sha256`（无哈希提示）以及是否存在路由冲突。 |
| 市场来源无法拉取 | 确认 `index_url` 为绝对 http(s) 地址且浏览器可访问；主机禁止跨域或不可达时下载后粘贴源码。 |
| 任务插件渠道「测试连接」无效 | 「任务插件」渠道不支持测试探测；直接用真实模型发起任务验证。 |
