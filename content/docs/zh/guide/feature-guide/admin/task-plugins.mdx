- 仅 Root 可访问，从侧边栏「管理员」→「插件」进入。
- 上传或从插件市场安装插件，管理插件的启用状态和版本。
- 上传插件或从插件市场安装，不会自动创建渠道或请求处理实例。

<Callout type="info" title="提示">
- 插件是 JavaScript 脚本，在 New API 内置的沙盒中运行。
- 插件可以包含三部分：任务部分把图像、视频、音频等异步任务平台接入统一任务接口；渠道部分像高级自定义渠道一样转发普通 API 请求；请求处理部分在请求发往上游前检查或修改请求。一个插件可以同时包含多个部分。
- 任务部分和渠道部分需绑定到「任务插件」类型的渠道，见[创建插件渠道](#创建插件渠道)。插件也可以作为扩展绑定到 New API 渠道。
- 请求处理部分需在侧边栏<a href="/zh/docs/guide/feature-guide/admin/request-processing" target="_blank" rel="noopener noreferrer">请求处理</a>页中添加实例，实例也可以添加到指定渠道。
- 页面右上角的「启用插件」是全局开关，关闭后插件任务和插件渠道停止服务，请求处理照常运行，见[启用或禁用插件](#启用或禁用插件)。
</Callout>

## 常用操作

本节按任务介绍插件管理页的常用操作，包括上传、安装、创建渠道、查看详情、启用或禁用、删除和管理市场源。

### 上传插件

- 插件管理-上传插件

![插件管理-上传插件页面](/assets/guide/feature-guide/plugins-upload-plugin.png)

- 插件管理-上传新版本

![插件管理-上传新版本页面](/assets/guide/feature-guide/plugins-upload-new-version.png)

**上传插件操作流程：**
1. 在「已安装」标签中点击页面右上角「上传插件」。
2. 选择源码：拖放或点击「选择文件」选择 `.js` 文件；或在「从 URL 导入」中填写地址后点击「拉取」；或直接在「插件源码」中粘贴源码。
3. 核对「插件源码」下方预览的适用渠道、上游认证方式、默认 API 地址、额外访问域名和支持的模型。
4. 按需选择「插件图标」，填写「备注」。
5. 点击「上传」。

**上传新版本操作流程：**
1. 点击插件所在行末的 ⋯（卡片视图在卡片右上角），选择「上传新版本」。
2. 按上传插件的第 2～4 步填写，确认源码中的 `key` 与该插件的 Key 相同。
3. 点击「上传」。

<Callout type="warn" title="注意">
- 窗口顶部的「第三方插件风险」提示：「插件可以读取渠道密钥，并修改发往上游的内容。激活前请检查它的代码和改动。」上传前请审查源码。
- 服务端先编译源码、校验元信息，再检查与现有插件的模型、渠道类型和路由是否冲突，通过后才保存。未通过时窗口显示「网关拒绝了该插件」和具体原因，冲突时写明冲突的插件。规则见[插件元信息](#插件元信息)和[版本、启停与冲突规则](#版本启停与冲突规则)。
</Callout>

![插件管理-安装插件-更新日志页面](/assets/guide/feature-guide/plugins-plugin-marketplace-install-changelog.png)

**操作流程：**
1. 点击「插件市场」标签。
2. 选择「官方插件」或「社区插件」，再选择类型「任务」「渠道」或「请求处理」。
3. 在插件卡片上点击「安装」。已知插件码时，在右侧的「插件码」中填写 8 位数字，点击「查找」，再在查找结果的卡片上点击「安装」。
4. 在版本选择框中选择要安装的版本。
5. 在「插件详情」「版本差异」「完整源码」「更新日志」标签中核对插件。
6. 点击「安装并启用」。

<Callout type="warn" title="注意">
- 安装与上传经过相同的编译、元信息校验和冲突检查，任何方式都不能跳过。
- 安装失败时，窗口显示「插件安装失败」、具体原因和「请先在“已安装”页解决冲突，再重新安装。」。原因为冲突时，请先在「已安装」中删除或禁用冲突插件，再重新安装。
- 所安装插件所属的来源必须仍在来源列表中，否则提示「这个插件所属的市场源不在源列表里」。
- 「完整性校验失败」时无法安装；「无完整性哈希」时可以安装，但无法确认源码与该源发布的一致。
- 索引和哈希都由浏览器下载，服务端只重新计算收到的源码哈希，不校验市场索引。被篡改的浏览器可以同时替换源码和哈希，完整性检查不能防止这种篡改。
</Callout>

### 插件元信息

**编译与校验：**
- `apiVersion` 必须为 `1`。
- `name`、`author.name` 必填。
- `key` 只能为小写字母、数字、`-`、`_` 且不超过 30，且不能与网关已有的路径段同名（如 `api`），否则提示 `plugin meta key … is a reserved path segment`（仅英文）。
- `version` 需为语义化版本。
- `models` 非空且大小写不敏感唯一。
- `channelTypes` 为正整数、不重复，且不能为 `60`（New API）或 `61`（任务插件）。
- `allowedHosts` 为主机名（可带端口），不含 scheme、路径或凭据。
- `fetchMode` 只能为 `per_task` 或 `batch`。
- 旧字段（如 `channelType`、`submitPaths`、`actions`）已不再支持，出现时拒绝上传，需改用 `channelTypes`、`routes`。

**字段说明：**

插件在源码的 `meta` 中声明以下字段，各部分完整的声明规则见<a href="/zh/docs/plugins" target="_blank" rel="noopener noreferrer">插件文档</a>。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_td_code]:wrap-anywhere [&_th]:whitespace-nowrap">

| 字段 | 类型/规则 | 说明 |
| --- | --- | --- |
| `apiVersion` | 整数，当前必须 `1` | 插件 API 版本。 |
| `key` | 字符串 ≤30，`^[a-z0-9][a-z0-9_-]*$` | 插件唯一标识，用于渠道绑定与市场识别。 |
| `name` | 字符串或本地化文本，必填 | 插件显示名称；本地化文本须含 `en`，界面按语言显示。 |
| `icon` | 可选 | 图标。 |
| `description` | 本地化文本 | 多语言描述。 |
| `version` | 字符串，语义化 | 插件版本号。 |
| `author` | `{ name, url }`，`name` 必填 | 作者信息。 |
| `channelTypes` | 正整数数组 | 可绑定的渠道类型编号；不能为 `60`、`61`。 |
| `models` | 字符串数组，非空且唯一 | 插件支持的模型标识。 |
| `fetchMode` | `per_task` / `batch` | 拉取模式：逐任务需 `buildQueryRequest`，批量需 `buildBatchQueryRequest + parseBatchResult`。 |
| `routes` | 数组 | 插件声明的原生路由，参与路由生成。 |
| `protocols` | 数组 | 宿主协议声明，如 `openai_responses`、`openai_video`、`openai_image`；`openai_responses` 用 `supports` 选择流式、同步、后台模式。 |
| `allowedHosts` | 主机名数组 | 插件可请求的上游主机名（可带端口）。 |
| `auth` | 对象 | 认证方式（如 OAuth2 JWT），用于插件接入。 |
| `usageSchema` | 对象 | 计费参数声明，供任务模型的计费表达式读取。 |
| `baseUrl` | 字符串，可选 | 默认上游地址；创建任务插件渠道时自动填入「API 地址」。 |
| `relay` | 数组，可选 | 渠道部分的转发路由；非空时插件可像高级自定义渠道一样转发普通 API 请求。 |
| `channelConfig` | 对象，可选 | 渠道级设置的声明；绑定该插件的渠道表单显示「插件设置」。 |
| `configSchema` | 对象，可选 | 请求处理实例的设置声明，见<a href="/zh/docs/guide/feature-guide/admin/request-processing#添加与编辑实例" target="_blank" rel="noopener noreferrer">请求处理</a>。 |

</div>

<Callout type="info" title="提示">
- `routes` 与 `protocols` 决定插件如何接入请求；`usageSchema` 决定任务结果如何计费，见插件详情的「计费参数」标签。
- 只有与插件声明的模型、渠道类型相匹配的请求才会路由到该插件。
</Callout>

### 版本、启停与冲突规则

同一 Key 可以保存多个版本，同一时刻只有一个版本生效；启停分为全局开关和单个插件开关两层。

**版本规则：**
- 该 Key 的第一个版本上传或安装后自动激活；已有激活版本时，新版本只保存、不激活。
- 同一 Key 和版本已存在但源码不同时，上传被拒绝并提示 `plugin key and version already exist with different source`（仅英文）。版本内容不可变，修改源码需提升 `version`。
- 源码不超过 8 MiB；插件图标另计，不超过 512 KiB。

**启停与删除规则：**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 内置插件及其自定义版本 | 第三方插件 |
| --- | --- | --- |
| 禁用 | 该 Key 的内置插件一起停止服务，运行状态「已禁用」，不回落到内置版本。 | 该平台不可用，运行状态「已禁用；平台不可用」。 |
| 重新启用 | 自定义版本与内置插件一起恢复服务。 | 恢复服务。 |
| 删除当前自定义版本 | 还有其他已上传版本时，激活其中最近上传的一个，该版本沿用自己的启用状态；没有时恢复内置插件（该 Key 已被禁用时除外）。 | 还有其他版本时同左；没有时该平台不可用。 |
| 关闭全局开关 | 插件任务和插件渠道全部停止，请求处理照常运行。 | 同左。 |

</div>

**冲突检查：**
- 上传、安装、启用、激活版本、删除当前版本（会激活另一个版本或回落内置版本）时，都检查与现有插件的模型、渠道类型和路由是否冲突；存在冲突即拒绝，任何方式都不能跳过。

<Callout type="info" title="提示">
- 通过接口上传的版本可以带 `enabled`（默认启用）、`remark`（备注）和 `sourceSha256` 参数；`sourceSha256` 提供时须等于源码的 SHA-256（忽略大小写），否则拒绝上传。界面上传和市场安装固定为启用，市场安装自动提供 `sourceSha256`。
- 自定义版本未启用而同名内置插件仍在服务时，运行状态为「已禁用，使用内置版本」；在界面上禁用不会进入这一状态。
</Callout>

### 任务超时与清理

禁用插件或关闭全局开关后，在途任务不会被取消，由全局轮询按超时清理。

**清理规则：**
- 在途任务指 `platform` 为插件 Key 且状态不是成功/失败的任务。
- 超时任务由全局轮询清理扫描：达到 `TASK_TIMEOUT_MINUTES`（默认 4320 分钟，即 72 小时，从任务提交时间算起；设为 0 表示不按时长超时）后标记失败，非旧版任务会退还额度。
- 该清理仅在 `UPDATE_TASK` 开启时运行；关闭后，超时任务不会被标记失败，也不会退还额度。
- 连续轮询失败上限由 `TASK_POLL_MAX_FAILURES`（默认 20）控制。

<Callout type="info" title="提示">
超时清理是全局轮询，不是按插件隔离的。某个插件禁用后，其遗留任务仍会按同一套超时与重试策略被清理，不会立即失败。
</Callout>

## 保存与生效

本页各操作提交后由服务端立即执行，没有统一的保存按钮。处理该请求的节点立即生效；其他节点的同步方式因对象而异，按下列两组查看。多实例部署时，页面右上角显示各节点是否已载入，见[节点同步状态](#节点同步状态)。

**插件版本：**

处理该请求的节点立即更新插件注册表，其他节点约 3 秒内加载，最迟 30 秒。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 上传、市场「安装并启用」 | 服务端先编译、校验元信息并预检冲突，通过后才保存 | 该 Key 的第一个版本保存后立即激活；已有激活版本时提示「插件已保存，待激活」，当前版本不变，点击「立即激活」或在版本历史中激活后才生效。 |
| 激活、回滚版本 | 在「版本历史」中操作，成功提示「插件版本已激活」 | 激活前先编译，编译失败时不切换版本。 |
| 启用、禁用自定义插件 | 开关加确认框；插件仍在使用时按「插件仍在使用中」处理 | 禁用后该 Key 不再参与路由，重新启用后恢复；进行中的任务不会被取消。 |
| 删除当前自定义版本 | 确认框；成功提示「插件版本已删除」 | 该 Key 还有其他版本时激活其中最近上传的一个，否则回落内置插件；没有内置插件时该平台不可用；回落前检查冲突，存在冲突时拒绝删除。 |
| 上传、安装、激活、启用、删除当前版本后的价格检查 | 随操作返回 | 有任务模型无法计费时提示「以下模型的价格需要处理：」，到计费与支付配置处理，见[上传插件](#上传插件)。 |

</div>

**全局开关、内置插件与市场来源：**

这些对象保存为系统设置：处理该请求的节点立即生效，其他节点约 3 秒内随系统设置同步（最迟一个同步周期，默认 60 秒）。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 全局「启用插件」 | 切换开关；关闭前先确认「关闭插件任务和渠道？」；成功提示「插件设置已更新」 | 关闭后新的插件任务和插件渠道请求被拒绝，请求处理照常运行；进行中的任务不会被取消。 |
| 启用、禁用内置插件 | 开关加确认框 | 禁用后该 Key 的内置插件停止服务，不会回落；重新启用后恢复。 |
| 市场来源 | 「市场源」对话框中整张列表一次保存，成功提示「市场源已更新」 | 只改变「插件市场」中可浏览的来源，不影响已安装的插件。 |

</div>

**补充说明：**
- **同名内置与自定义插件一起启停**：两者各按所在组的方式同步，其他节点约 3 秒内全部生效，默认配置下最迟约 60 秒。
- **编译失败**：某个节点加载新版本时编译失败，该节点继续使用已加载的旧版本，运行状态显示「编译失败」。
- **插件沙盒「运行干跑」**：不保存，使用临时副本执行，不影响当前注册表。
- **插件渠道**：保存与生效见<a href="/zh/docs/guide/feature-guide/admin/channel#保存与生效" target="_blank" rel="noopener noreferrer">渠道管理</a>。

## 注意事项

**安装与来源：**
- **上传和安装是管理员级信任决策**：插件可以读取渠道凭证并构造上游请求，社区和第三方来源的插件由他人发布，安装前请审查源码，见[上传插件](#上传插件)和[官方插件与社区插件](#官方插件与社区插件)。
- **社区来源会发送安装统计**：从 Community 来源安装时，服务端向 newapi.ai 发送插件标识、版本号和本网关的随机编号，见[官方插件与社区插件](#官方插件与社区插件)。

**启停与删除：**
- **禁用会连带同名内置插件**：禁用内置插件，或禁用有同名内置插件的自定义版本，该 Key 的内置插件一起停止服务，不会回落，见[版本、启停与冲突规则](#版本启停与冲突规则)。
- **在途任务不会被取消**：关闭全局开关或禁用插件后，进行中的任务交由超时清理，清理只在 `UPDATE_TASK` 开启时运行，见[任务超时与清理](#任务超时与清理)。
- **删除或禁用前先处理绑定的渠道**：否则这些渠道上的请求会因插件不可用而失败，见[启用或禁用插件](#启用或禁用插件)。
- **删除后由其他版本接替**：删除当前自定义版本时，若该 Key 还有其他版本，会激活最近上传的一个，见[删除当前自定义版本](#删除当前自定义版本)。

**版本与冲突：**
- **修改源码需提升版本**：同一 Key 和版本的源码不同会被拒绝，见[版本、启停与冲突规则](#版本启停与冲突规则)。
- **冲突检查不能跳过**：上传、安装、启用、激活和删除当前版本都会检查冲突，任何方式都不能跳过，见[版本、启停与冲突规则](#版本启停与冲突规则)。

<Accordion title="创建渠道时看不到「插件」分类">
**提示原文**：复制或提交任务插件渠道时可能提示 `task plugin channels require the task_plugin.bind permission`（仅英文）。

**可能原因**：当前账户没有 `task_plugin.bind` 权限。没有该权限时，选择对话框不显示「插件」分类。

**处理方法**：
1. 请 Root 在<a href="/zh/docs/guide/feature-guide/admin/user#管理员权限" target="_blank" rel="noopener noreferrer">用户管理</a>的「管理员权限」中授予「绑定任务插件」。
</Accordion>

<Accordion title="任务插件渠道无法保存">
**提示原文**：如 `task plugin "…" is not registered`、`task plugin key must not exceed 30 characters`、`base URL is required for task plugin channels`、`channel cannot be empty`（仅英文），或「此渠道类型需要填写 Base URL」（英文 Base URL is required for this channel type）。

**可能原因**：
- 绑定的插件未注册。
- `task_plugin_key` 超过 30 个字符。
- 未填写「API 地址」或「API 密钥」。

**处理方法**：
1. 按提示逐项修正。
2. 确认该插件的运行状态为「已注册」。
</Accordion>

<Accordion title="请求没有进入预期的插件">
**提示原文**：`selected channel does not match the pinned task plugin`；插件系统或该插件已关闭时，客户端收到 HTTP 400 和 `the task plugin system is disabled on this gateway` 或 `task plugin "…" is disabled on this gateway`（仅英文）。

**可能原因**：
- 渠道 `setting.task_plugin_key` 与请求固定的 Key 不一致。
- 其他渠道类型的编号不在插件的 `channelTypes` 内。
- 渠道类型不是任务插件、渠道绑定的 Key 有误、分组不匹配，或模型不在插件的 `models` 中。
- 全局「启用插件」或该插件已关闭。

**处理方法**：
1. 按上述原因逐项核对渠道与插件。
2. 插件已关闭时重新启用。
</Accordion>

<Accordion title="插件上传失败">
**提示原文**：如「插件源码超过 8 MiB 上限。」（英文 Plugin source exceeds the 8 MiB limit.）、`plugin source sha256 mismatch`、`plugin key and version already exist with different source`（仅英文）。

**可能原因**：
- 源码超过 8 MiB。
- `apiVersion`、`key`、`version`、`name`、`models` 不满足校验。
- 与现有插件存在模型、渠道类型或路由冲突。
- 同一 Key 和版本已存在，但源码不同。

**处理方法**：
1. 存在冲突时，先在「已安装」中删除或禁用冲突插件，再重新上传。
2. 修改源码后提升 `version` 再上传。
</Accordion>

<Accordion title="插件显示编译失败">
**提示原文**：悬停运行状态可看到错误，如 `plugin … is missing required export "buildSubmitRequest"`（仅英文）。

**可能原因**：源码错误、元信息缺失，或缺少 `buildSubmitRequest`、`parseSubmitResponse`、`parseTaskResult` 等必需导出；`batch` 模式还需批量导出。

**处理方法**：
1. 在详情中查看源码与错误并修正。
</Accordion>

<Accordion title="插件显示未注册">
**说明**：该版本已启用，但处理该请求的节点的注册表尚未加载。其他节点约 3 秒内加载新版本；各节点另每 30 秒从数据库同步一次。

**处理方法**：
1. 稍后刷新列表。
2. 持续未注册时，查看服务端日志中的任务插件同步错误。
</Accordion>

<Accordion title="禁用插件时提示「插件仍在使用中」">
**说明**：插件仍被启用的渠道或在途任务使用。

**处理方法**：
1. 在确认框中点击「级联禁用渠道」；仍有在途任务时点击「强制操作」，见[启用或禁用插件](#启用或禁用插件)。
2. 需要保留这些渠道时，先把它们切换到其他插件。
</Accordion>

<Accordion title="禁用自定义版本后，同名内置插件也不再服务">
**说明**：禁用有同名内置插件的自定义版本时，内置插件一起停用。

**处理方法**：
1. 直接重新启用，恢复当前的自定义版本。
2. 需要改由内置插件服务时，用「删除当前自定义版本」删除该 Key 的全部自定义版本，待「来源」显示「内置」后，打开该行的「已启用」开关。
</Accordion>

<Accordion title="任务计费不生效">
**可能原因**：
- 插件未声明 `usageSchema`。
- 请求未命中该插件。
- 未在<a href="/zh/docs/guide/feature-guide/admin/billing-expression#任务模型" target="_blank" rel="noopener noreferrer">计费表达式</a>中为该任务模型配置任务表达式。
</Accordion>

<Accordion title="市场安装失败">
**提示原文**：如「完整性校验失败」（英文 Integrity check failed）、`unsupported indexVersion …`（仅英文），或「请先在“已安装”页解决冲突，再重新安装。」（英文 Resolve the conflict on the Installed tab, then install again.）

**可能原因**：
- 索引无法访问。
- `indexVersion` 大于 1，或 `kind` 不是 `task`。
- 源码哈希与索引不一致。
- 存在路由冲突。
- 从社区或第三方来源安装的插件标识与内置插件相同，或不以作者 GitHub 用户名加下划线开头。
- 插件所属的来源已不在来源列表中。

**处理方法**：
1. 按提示处理后重新安装；存在冲突时，先在「已安装」中处理冲突插件。
2. 标识不合规时联系插件作者。
</Accordion>

<Accordion title="市场来源无法拉取">
**提示原文**：「无法加载该源」（英文 Could not load this source），或「无法下载插件代码，请稍后重试。」（英文 Could not download the plugin code. Try again later.）

**可能原因**：
- 「源地址」不是绝对 http(s) 地址。
- 浏览器无法访问该主机，或主机禁止跨域请求。

**处理方法**：
1. 改正「源地址」。
2. 主机禁止跨域或无法访问时，下载源码后在「上传插件」中粘贴。
</Accordion>

<Accordion title="任务插件渠道「测试连接」无效">
**提示原文**：`Task Plugin channel test is not supported`（仅英文）

**说明**：只有任务部分的插件渠道不支持测试探测；包含渠道部分的插件渠道可以测试。

**处理方法**：
1. 直接用真实模型发起任务，在任务日志中查看结果。
</Accordion>

<Accordion title="社区插件安装时提示标识不符合要求">
**提示原文**：「社区插件不能使用内置插件 … 的标识」或「社区插件的标识必须以作者的 GitHub 用户名加下划线开头，例如 alice_foo」。

**说明**：从社区来源或其他第三方来源安装的插件，标识不能与内置插件相同，且必须带作者前缀。

**处理方法**：
1. 联系插件作者按规则修改标识并发布新版本。
2. 插件作者发布时的标识规则见[官方插件与社区插件](#官方插件与社区插件)中的「发布社区插件」。
</Accordion>

</Accordions>
