- 任务插件管理仅 Root 可访问，Root 从侧边栏「管理员」 → 「任务插件」或访问 `/task-plugins` 进入管理页。
- 任务插件把图像、视频、音频等异步任务平台接入 New API 的统一任务接口。
- 插件是 JavaScript 脚本，在 New API 内置的沙盒中运行，通过「任务插件」类型渠道（或绑定了插件扩展的 New API 渠道）接入渠道路由。


## 任务插件管理概览

页面顶部提供「启用任务插件」全局开关，下方为「已安装」「插件市场」两个标签页。已安装标签用于查看、上传和管理插件；市场标签从配置的索引源浏览和安装插件。

### 全局启用开关

- 「启用任务插件」开关对应系统选项 `TaskPluginEnabled`。
- 启停只有两个层级：**全局主开关**和**每个插件各自的启用开关**。关闭主开关时，整个任务插件系统（包括出厂与自定义插件）立即停止服务。

<Callout type="info">
  出厂插件不可删除，但可以单独禁用。上传同 Key 的自定义版本可以覆盖出厂插件：自定义版本全部删除后恢复出厂插件（该 Key 已被禁用时除外）；禁用自定义版本时，出厂插件会一起停用。没有同名出厂插件的第三方插件被禁用或全部版本被删除后，对应平台不可用。
</Callout>

<Callout type="warn">
  全局开关关闭不会取消在途任务，出厂插件和自定义插件都会立即停止服务；进行中的任务交由超时清理流程处理（见[任务超时与清理](#任务超时与清理)）。
</Callout>

### 已安装与市场

- 「已安装」：列出当前注册的任务插件，支持表格/卡片视图、搜索、分页与排序。
- 「插件市场」：从已配置的市场来源浏览可安装插件，安装流程与手动上传完全一致。

## 任务插件简介与内置插件

任务插件描述了一个异步任务平台如何提交任务、查询结果、提取用量与产出结果。插件声明自己支持的模型、可绑定的渠道类型、计费参数与能力端点。插件与渠道两层分离：**上传插件只注册插件能力，不会自动创建渠道**；需另行创建「任务插件」渠道并绑定插件 Key（见「创建任务插件渠道」）。

插件分为三层来源：

- **出厂插件**：随 New API 内置，源码以 `//go:embed` 方式嵌入（`plugins/tasks/<key>/plugin.js`），启动时自动注册。出厂插件不可独立删除。
- **自定义插件**：通过上传或市场安装的覆盖层，与同名出厂插件按 Key 关联，可以覆盖出厂插件的某个版本。
- **第三方插件**：与出厂插件不同名的插件。

## 创建任务插件渠道

插件本身不参与路由；要让某个平台可调用，需要创建「任务插件」类型的渠道并绑定插件 Key。也可以把插件作为扩展绑定到 New API 渠道，见<a href="/zh/docs/guide/feature-guide/admin/channel#网关渠道new-api-与-sub2api" target="_blank" rel="noopener noreferrer">网关渠道</a>。

### 前置条件

1. 目标插件已启用，且「运行状态」为「已注册」：出厂插件无需上传，其他插件需先上传或从市场安装。被禁用的插件不会出现在可选列表中。
2. Root 默认拥有创建渠道权限；Admin 需由 Root 在管理员权限矩阵中授予渠道操作权限和 `task_plugin.bind`（绑定任务插件）权限，否则创建渠道时看不到「插件」分类。
3. 准备好上游服务地址与凭证（API 地址、API Key 等，按插件接入的平台要求）。

### 操作流程

- 任务插件-创建任务插件渠道

![任务插件-创建任务插件渠道页面](/assets/guide/feature-guide/task-plugins-create-plugin-channel.png)

1. 进入「渠道管理」 → 「创建渠道」。
2. 在弹出的选择对话框中切到「插件」分类，点击目标插件卡片（卡片显示插件名称、描述、Key 和模型数）。
3. 进入渠道表单后，渠道类型自动设为「任务插件」；名称为空时填入插件名，「模型」中填入该插件声明的全部模型。
4. 填写「API 地址」（必填），即插件请求的上游地址。插件声明了默认地址时会自动填入，下方显示「插件默认值」；未声明时下方提示「该插件未声明默认地址，必须手动填写」。
5. 填写「API 密钥」——渠道 `key` 会作为插件环境的 `apiKey` 传入。
6. 核对模型、分组，按需设置优先级/权重、标签、状态等（通用字段见<a href="/zh/docs/guide/feature-guide/admin/channel#独立插件渠道" target="_blank" rel="noopener noreferrer">渠道管理</a>）。
7. 保存渠道。

### 字段说明

| 字段 | 规则与说明 |
| --- | --- |
| 插件 | 在「插件」分类中选择，必填。保存后渠道类型为「任务插件」（61），并记录插件 Key（≤30 字符，必须是当前已注册的插件）。选择后按插件声明的模型自动填充模型列表。没有 `task_plugin.bind` 权限时看不到「插件」分类。 |
| API 地址 | 必填，插件执行时的上游服务地址。插件声明了默认地址时自动填入；未声明时必须手动填写。 |
| API 密钥 | 渠道 `key`；新增时后端要求非空；作为插件环境的 `apiKey` 注入。 |
| 模型 | 必填；建议直接用插件声明的模型，也可按需增删。 |
| 分组 | 必填；决定哪些用户可使用该渠道。 |
| 优先级/权重 | 参与渠道选择的排序参数。 |

<Callout type="warn">
  - 「任务插件」渠道不支持**「测试连接」**（测试会直接提示该类型不支持测试）。请直接用真实模型发起任务验证，或通过任务日志确认提交与查询是否成功。
  - 删除或禁用插件前，先处理绑定它的渠道（切换到其他插件，或在禁用时执行级联禁用）；否则这些渠道上的请求会因插件不可用而失败。
</Callout>

### 运行状态

| 状态 | 含义 | 常见条件 |
| --- | --- | --- |
| 已注册 | 插件已编译并进入路由。 | 编译成功且插件已启用。 |
| 编译失败 | 插件源码无法编译、元信息校验失败，或因冲突未进入路由；悬停可查看详细错误。 | 源码错误、元信息缺失、必需钩子缺失，或与其他插件的模型、渠道类型、路由冲突而被排除出路由。 |
| 已禁用 | 出厂插件被单独禁用，或有同名出厂插件的自定义插件被禁用（出厂插件一起停用）。 | 在「已启用」中关闭了该插件。 |
| 已禁用；已回落出厂版 | 自定义版本未启用，同名出厂插件仍在服务。 | 通过接口上传了未启用的自定义版本。在界面上禁用时出厂插件会一起停用，不会进入此状态。 |
| 已禁用；平台不可用 | 插件被禁用且没有出厂回落版本。 | 第三方插件被禁用。 |
| 未注册 | 活动自定义记录存在但插件未进入当前注册表。 | 记录处于启用态但注册表未包含该 Key。 |

### 行操作

- **详情**：打开插件详情面板，包含概览、计费参数、插件源码、版本历史、源码差异和插件沙盒。
- **上传新版本**：为该 Key 上传一个新的版本。
- **删除当前自定义版本**：只对自定义插件可用，出厂插件该项为灰色。删除前会确认后果，并检查插件是否仍被使用，见[删除当前自定义版本](#删除当前自定义版本)。

## 上传插件

点击「上传插件」打开上传对话框。上传即注册一个新的插件版本；同名 Key 的多个版本保存在数据库中，同一 Key 同一时刻只有一个版本处于激活态。该 Key 的首个版本上传后自动激活；已有激活版本时，新上传的版本只保存、不激活。

- 任务插件-上传插件

![任务插件-上传插件页面](/assets/guide/feature-guide/task-plugins-upload-plugin.png)

- 任务插件-上传新版本

![任务插件-上传新版本页面](/assets/guide/feature-guide/task-plugins-upload-new-version.png)

1. 核对「第三方插件风险」提示：上传插件是管理员级别的信任决策。插件可以访问渠道凭证并构造上游请求，激活前应审查源码。
2. 选择源码来源，支持三种方式：
   - 拖放或选择 `.js` 插件文件；
   - 直接粘贴 JavaScript 源码到编辑器；
   - 在「从 URL 导入」中输入插件源码 URL 并点击「拉取」，由浏览器拉取源码填入编辑器（GitHub / gist 页面地址会自动改写为 raw URL）。

   源码填入后，下方会预览插件声明的适用渠道、上游认证方式、默认 API 地址、额外访问域名和支持的模型，可在上传前核对。
3. 按需选择「插件图标」（与 plugin.js 同目录的 `icon.svg` 或 `icon.png`，最大 512 KiB），并填写「备注」（可选），用于描述该版本。
4. 点击「上传」。服务端会先编译源码并校验元信息，再执行路由冲突预检；通过后保存版本并同步注册表。被拒绝时，对话框显示「网关拒绝了该插件」及具体原因（冲突时会写明冲突的插件）。
5. 上传成功后，对话框显示「插件上传成功」及插件名称、Key 和版本。首个版本会直接激活；该 Key 已有激活版本时显示「插件已保存，待激活」，可点击「立即激活」替换当前版本，或点击「稍后」，之后在插件详情的「版本历史」中激活。

上传参数与限制：

| 项 | 说明 |
| --- | --- |
| 源码大小 | 单个插件源码不超过 **8 MiB**，超限会被拒绝；插件图标另计，不超过 512 KiB。 |
| `enabled` | 上传接口参数，默认启用；界面上传和市场安装固定为启用。 |
| `remark` | 本版本备注，仅描述用途。 |
| `sourceSha256` | 可选，市场安装时自动提供。提供时必须等于源码的 SHA-256（忽略大小写），否则拒绝上传。 |
| 同名同版本源码 | 若同一 `Key + Version` 已存在但源码哈希不同，会拒绝并提示 `plugin key and version already exist with different source`。版本内容不可变，修改源码需提升 `version`。 |
| 冲突预检 | 启用状态上传时，会先检查与现有插件的模型、渠道类型和路由冲突，存在冲突则拒绝保存。界面上传和市场安装都不提供跳过预检的选项；只有接口参数 `force=true` 可以跳过；此时若冲突的版本被激活（该 Key 的首个版本上传后即激活），它不会进入路由，运行状态显示「编译失败」。 |

<Callout type="info">
  编译与校验：`apiVersion` 必须为 `1`；`name`、`author.name` 必填；`key` 只能为小写字母、数字、`-`、`_` 且不超过 30；`version` 需为语义化版本；`models` 非空且大小写不敏感唯一；`channelTypes` 为正整数、不重复，且不能为 `60`（New API）或 `61`（任务插件）；`allowedHosts` 为主机名（可带端口），不含 scheme、路径或凭据；`fetchMode` 只能为 `per_task` 或 `batch`。旧字段（如 `channelType`、`submitPaths`、`actions`）已不再支持，出现时拒绝上传，需改用 `channelTypes`、`routes`。
</Callout>

## 插件元信息

| 字段 | 类型/规则 | 说明 |
| --- | --- | --- |
| `apiVersion` | 整数，当前必须 `1` | 插件 API 版本。 |
| `key` | 字符串 ≤30，`^[a-z0-9][a-z0-9_-]*$` | 插件唯一标识，用于渠道绑定与市场识别。 |
| `name` | 字符串，必填 | 插件显示名称。 |
| `icon` | 可选 | 图标。 |
| `description` | 本地化文本 | 多语言描述。 |
| `version` | 字符串，语义化 | 插件版本号。 |
| `author` | `{ name, url }`，`name` 必填 | 作者信息。 |
| `channelTypes` | 正整数数组 | 可绑定的渠道类型编号；不能为 `60`、`61`。 |
| `models` | 字符串数组，非空且唯一 | 插件支持的模型标识。 |
| `fetchMode` | `per_task` / `batch` | 拉取模式：逐任务需 `buildQueryRequest`，批量需 `buildBatchQueryRequest + parseBatchResult`。 |
| `routes` | 数组 | 插件声明的原生路由，参与路由生成。 |
| `protocols` | 数组 | 宿主协议声明，如 `openai_responses`、`openai_video`、`openai_image`；`openai_responses` 用 `supports` 选择流式、同步、后台模式。 |
| `allowedHosts` | 主机名数组 | 插件可请求的上游主机名（可带端口）。 |
| `auth` | 对象 | 认证方式（如 OAuth2 JWT），用于插件接入。 |
| `usageSchema` | 对象 | 计费参数声明，供任务模型的计费表达式读取。 |
| `baseUrl` | 字符串，可选 | 默认上游地址；创建任务插件渠道时自动填入「API 地址」。 |

`routes` 与 `protocols` 决定插件如何接入请求；`usageSchema` 决定任务结果如何计费（见「插件详情」 → 「计费参数」）。只有与插件声明的模型、渠道类型相匹配的请求才会路由到该插件。

## 启用、禁用与删除

### 启用与禁用单个插件

插件行（或卡片）的「已启用」开关用于启停单个插件，切换前会弹出「启用插件？」或「禁用插件？」确认框；出厂插件也可以单独禁用。禁用时若插件仍被启用渠道或在途任务使用，会弹出「插件仍在使用中」，列出这些渠道和在途任务数：

- 点击「级联禁用渠道」（有启用渠道时显示）：把使用该插件的启用渠道改为手动禁用（禁用原因记录为 `task plugin disabled`），然后禁用插件；New API 渠道不会被禁用，只解除对该插件的绑定。仍有在途任务时此按钮无法完成禁用，需点击「强制操作」。
- 点击「强制操作」：同样按上述方式级联处理渠道，并且不等待在途任务，直接禁用插件。

<Callout type="warn">
  禁用出厂插件，或禁用有同名出厂插件的自定义插件时，系统都会把该 Key 写入系统选项 `TaskPluginDisabledFactoryKeys`，出厂插件也一起停止路由，运行状态显示「已禁用」，不会回落到出厂版。重新启用时该 Key 从选项中移除，两者一起恢复。
</Callout>

<Callout type="warn">
  禁用不会取消在途任务，在途任务由超时清理处理（见[任务超时与清理](#任务超时与清理)）。插件仍被启用渠道使用时，必须级联处理这些渠道才能禁用；如需保留这些渠道，先把它们切换到其他插件。
</Callout>

### 删除当前自定义版本

- 任务插件-删除插件版本

![任务插件-删除插件版本页面](/assets/guide/feature-guide/task-plugins-delete-current-custom-version.png)

仅自定义版本可删除（出厂插件不可删除）。删除前会弹出「删除插件版本？」确认框：

- 若存在同名出厂插件：提示「删除此自定义版本不会停用平台，同名出厂插件将自动恢复。」
- 若没有出厂回落版本：提示「此插件没有出厂回落版本，删除或禁用后该平台将不可用。」
- 若没有同名出厂插件，且插件仍被启用渠道或在途任务使用：会弹出「插件仍在使用中」，可点击「强制操作」继续删除。

删除后，若该 Key 还有其他已上传的版本，系统会激活其中最近上传的一个（被激活的版本沿用它自己的启用状态）；没有剩余版本时，有同名出厂插件则恢复出厂插件（该 Key 已被禁用时除外），否则该平台不可用。

### 全局开关

关闭页面顶部「启用任务插件」会立即停用整个任务插件系统（出厂插件和自定义插件都停止服务），新的插件请求会被拒绝；在途任务由超时清理处理，见[任务超时与清理](#任务超时与清理)。

## 任务超时与清理

- 在途任务指 `platform` 为插件 Key 且状态不是成功/失败的任务。
- 禁用插件不会取消任务；超时任务由全局轮询清理扫描，达到 `TASK_TIMEOUT_MINUTES`（默认 4320 分钟，即 72 小时，从任务提交时间算起；设为 0 表示不按时长超时）后标记失败，非旧版任务会退还额度。该清理仅在 `UPDATE_TASK` 开启时运行；关闭后，超时任务不会被标记失败，也不会退还额度。
- 连续轮询失败上限由 `TASK_POLL_MAX_FAILURES`（默认 20）控制。

<Callout type="info">
  超时清理是全局轮询，不是按插件隔离的。某个插件禁用后，其遗留任务仍会按同一套超时与重试策略被清理，不会立即失败。
</Callout>

## 推荐配置流程

1. 确认当前账户为 Root，并确认管理员具备所需渠道权限（创建任务插件渠道需要 `task_plugin.bind`）。
2. 打开「任务插件」页，确认全局「启用任务插件」开关已开启。
3. 上传插件源码，或从市场安装所需平台插件；上传/安装后核对解析出的 Key、版本、渠道类型与模型。
4. 在「已安装」列表检查插件运行状态是否为「已注册」；若为编译失败或未注册，按详情与错误信息处理。
5. 前往「渠道管理」创建任务插件渠道（在「插件」分类中选择插件），填写 API 地址、API 密钥与分组；确认模型自动填充是否符合预期。
6. 需要切换插件版本时，在插件详情的「版本历史」中激活目标版本。
7. 变更或禁用插件前，先确认绑定的渠道与在途任务，必要时执行级联禁用，避免请求路由到不可用插件。

## 保存与生效

本页各操作提交后由服务端立即执行，没有统一的保存按钮。处理该请求的节点立即生效；其他节点的同步方式因对象而异，按下列两组查看。

### 插件版本

处理该请求的节点立即更新插件注册表，其他节点最迟 30 秒后加载。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 上传、市场「安装并启用」 | 服务端先编译、校验元信息并预检冲突，通过后才保存 | 该 Key 的第一个版本保存后立即激活；已有激活版本时提示「插件已保存，待激活」，当前版本不变，点击「立即激活」或在版本历史中激活后才生效。 |
| 激活、回滚版本 | 在「版本历史」中操作，成功提示「插件版本已激活」 | 激活前先编译，编译失败时不切换版本。 |
| 启用、禁用自定义插件 | 开关加确认框；插件仍在使用时按「插件仍在使用中」处理 | 禁用后该 Key 不再参与路由，重新启用后恢复；进行中的任务不会被取消。 |
| 删除当前自定义版本 | 确认框；成功提示「插件版本已删除」 | 该 Key 还有其他版本时激活其中最近上传的一个，否则回落出厂插件；没有出厂插件时该平台不可用。 |

</div>

### 全局开关、出厂插件与市场来源

这些对象保存为系统设置：处理该请求的节点立即生效，其他节点随系统设置同步（默认 60 秒）。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 操作 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 全局「启用任务插件」 | 切换开关；关闭前先确认「禁用任务插件？」；成功提示「任务插件设置已更新」 | 关闭后新的任务插件请求被拒绝；进行中的任务不会被取消。 |
| 启用、禁用出厂插件 | 开关加确认框 | 禁用后该 Key 的出厂插件停止服务，不会回落；重新启用后恢复。 |
| 市场来源 | 「市场源」对话框中整张列表一次保存，成功提示「市场源已更新」 | 只改变「插件市场」中可浏览的来源，不影响已安装的插件。 |

</div>

### 补充说明

- **同名出厂与自定义插件一起启停**：两者各按所在组的方式同步，默认配置下其他节点最迟约 60 秒后全部生效。
- **编译失败**：某个节点加载新版本时编译失败，该节点继续使用已加载的旧版本，运行状态显示「编译失败」。
- **插件沙盒「运行干跑」**：不保存，使用临时副本执行，不影响当前注册表。
- **任务插件渠道**：保存与生效见<a href="/zh/docs/guide/feature-guide/admin/channel#保存与生效" target="_blank" rel="noopener noreferrer">渠道管理</a>。

## 注意事项

- **上传和安装是管理员级信任决策**：插件可以读取渠道凭证并构造上游请求，市场索引任何人都可以发布，安装前请审查源码，见[上传插件](#上传插件)和[浏览与安装](#浏览与安装)。
- **禁用会连带同名出厂插件**：禁用出厂插件，或禁用有同名出厂插件的自定义版本，该 Key 的出厂插件一起停止服务，不会回落，见[启用与禁用单个插件](#启用与禁用单个插件)。
- **在途任务不会被取消**：关闭全局开关或禁用插件后，进行中的任务交由超时清理，清理只在 `UPDATE_TASK` 开启时运行，见[任务超时与清理](#任务超时与清理)。
- **删除或禁用前先处理绑定的渠道**：否则这些渠道上的请求会因插件不可用而失败；删除当前自定义版本时，若该 Key 还有其他版本，会激活最近上传的一个，见[删除当前自定义版本](#删除当前自定义版本)。
- **修改源码需提升版本**：同一 Key 和版本的源码不同会被拒绝，见[上传插件](#上传插件)。
- **冲突预检不能跳过**：启用状态上传会先预检冲突，界面上传和市场安装都不能跳过预检，见[上传插件](#上传插件)。

<Accordion title="创建渠道时看不到「插件」分类">
**提示原文**：复制或提交任务插件渠道时可能提示 `task plugin channels require the task_plugin.bind permission`（仅英文）。

**可能原因**：当前账户没有 `task_plugin.bind` 权限。没有该权限时，选择对话框不显示「插件」分类。

**处理方法**：
1. 请 Root 在<a href="/zh/docs/guide/feature-guide/admin/user#管理员权限" target="_blank" rel="noopener noreferrer">用户管理</a>的「管理员权限」中授予「绑定任务插件」。
</Accordion>

<Accordion title="任务插件渠道无法保存">
**提示原文**：如 `task plugin "…" is not registered`、`task plugin key must not exceed 30 characters`、`base URL is required for task plugin channels`、`channel cannot be empty`（仅英文），或「此渠道类型需要填写 Base URL」（英文 Base URL is required for this channel type）。

**可能原因**：
- 绑定的插件未注册。
- `task_plugin_key` 超过 30 个字符。
- 未填写「API 地址」或「API 密钥」。

**处理方法**：
1. 按提示逐项修正。
2. 确认该插件的运行状态为「已注册」。
</Accordion>

<Accordion title="请求没有进入预期的插件">
**提示原文**：`selected channel does not match the pinned task plugin`；插件系统或该插件已关闭时，客户端收到 HTTP 400 和 `the task plugin system is disabled on this gateway` 或 `task plugin "…" is disabled on this gateway`（仅英文）。

**可能原因**：
- 渠道 `setting.task_plugin_key` 与请求固定的 Key 不一致。
- 其他渠道类型的编号不在插件的 `channelTypes` 内。
- 渠道类型不是任务插件、渠道绑定的 Key 有误、分组不匹配，或模型不在插件的 `models` 中。
- 全局「启用任务插件」或该插件已关闭。

**处理方法**：
1. 按上述原因逐项核对渠道与插件。
2. 插件已关闭时重新启用。
</Accordion>

<Accordion title="插件上传失败">
**提示原文**：如「插件源码超过 8 MiB 上限。」（英文 Plugin source exceeds the 8 MiB limit.）、`plugin source sha256 mismatch`、`plugin key and version already exist with different source`（仅英文）。

**可能原因**：
- 源码超过 8 MiB。
- `apiVersion`、`key`、`version`、`name`、`models` 不满足校验。
- 与现有插件存在模型、渠道类型或路由冲突。
- 同一 Key 和版本已存在，但源码不同。

**处理方法**：
1. 存在冲突时，先在「已安装」中删除或禁用冲突插件，再重新上传。
2. 修改源码后提升 `version` 再上传。
</Accordion>

<Accordion title="插件显示编译失败">
**提示原文**：悬停运行状态可看到错误，如 `plugin … is missing required export "buildSubmitRequest"`（仅英文）。

**可能原因**：源码错误、元信息缺失，或缺少 `buildSubmitRequest`、`parseSubmitResponse`、`parseTaskResult` 等必需导出；`batch` 模式还需批量导出。

**处理方法**：
1. 在详情中查看源码与错误并修正。
</Accordion>

<Accordion title="插件显示未注册">
**说明**：该版本已启用，但当前节点的注册表尚未加载。各节点每 30 秒从数据库同步一次。

**处理方法**：
1. 稍后刷新列表。
2. 持续未注册时，查看服务端日志中的任务插件同步错误。
</Accordion>

<Accordion title="禁用插件时提示「插件仍在使用中」">
**说明**：插件仍被启用的渠道或在途任务使用。

**处理方法**：
1. 在确认框中点击「级联禁用渠道」；仍有在途任务时点击「强制操作」，见[启用与禁用单个插件](#启用与禁用单个插件)。
2. 需要保留这些渠道时，先把它们切换到其他插件。
</Accordion>

<Accordion title="禁用自定义版本后，同名出厂插件也不再服务">
**说明**：禁用会把该 Key 写入 `TaskPluginDisabledFactoryKeys`，出厂插件一起停用。

**处理方法**：
1. 直接重新启用，恢复当前的自定义版本。
2. 需要改由出厂插件服务时，用「删除当前自定义版本」删除该 Key 的全部自定义版本，待「来源」显示「出厂」后，打开该行的「已启用」开关。
</Accordion>

<Accordion title="任务计费不生效">
**可能原因**：
- 插件未声明 `usageSchema`。
- 请求未命中该插件。
- 未在<a href="/zh/docs/guide/feature-guide/admin/billing-expression#任务模型" target="_blank" rel="noopener noreferrer">计费表达式</a>中为该任务模型配置任务表达式。
</Accordion>

<Accordion title="市场安装失败">
**提示原文**：如「完整性校验失败」（英文 Integrity check failed）、`unsupported indexVersion …`（仅英文），或「市场安装绝不会强制跳过冲突。请先在任务插件页面处理冲突，然后重新安装。」（英文 Marketplace installs never force past a conflict. Resolve it on the task plugins page, then install again.）

**可能原因**：
- 索引无法访问。
- `indexVersion` 大于 1，或 `kind` 不是 `task`。
- 源码哈希与索引不一致。
- 存在路由冲突。

**处理方法**：
1. 按提示处理后重新安装；存在冲突时，先在「已安装」中处理冲突插件。
</Accordion>

<Accordion title="市场来源无法拉取">
**提示原文**：「无法加载该源」（英文 Could not load this source），或「无法在浏览器中拉取插件源码。该主机可能禁止跨域请求或无法访问。」（英文 Could not fetch the plugin source from this browser. The host may block cross-origin requests or be unreachable.）

**可能原因**：
- `index_url` 不是绝对 http(s) 地址。
- 浏览器无法访问该主机，或主机禁止跨域请求。

**处理方法**：
1. 改正 `index_url`。
2. 主机禁止跨域或无法访问时，下载源码后在「上传插件」中粘贴。
</Accordion>

<Accordion title="任务插件渠道「测试连接」无效">
**提示原文**：`Task Plugin channel test is not supported`（仅英文）

**说明**：「任务插件」渠道不支持测试探测。

**处理方法**：
1. 直接用真实模型发起任务，在任务日志中查看结果。
</Accordion>

</Accordions>
