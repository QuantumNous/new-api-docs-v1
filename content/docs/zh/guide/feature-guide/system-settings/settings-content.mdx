## 配置分区

本节按左侧导航的顺序介绍七个分区，各分区的保存按钮和生效时机见[保存与生效](#保存与生效)。

### 数据仪表板

- 控制台内容-数据仪表板

![控制台内容-数据仪表板页面](/assets/guide/feature-guide/system-settings-console-content-data-dashboard.png)

本分区只配置后台用量数据的统计，不配置数据看板上各面板的显示。

**操作流程：**
1. 打开或关闭「启用数据仪表板」。
2. 填写「刷新间隔 (分钟)」，选择「默认时间粒度」。
3. 点击页头「保存更改」。

<Callout type="info" title="提示">
- 公告、API 地址、常见问答、Uptime Kuma 面板由各自分区的「已启用」开关控制。
- 设置引导、用量概览、性能健康等面板没有单独开关，性能健康仅管理员可见。
- 整个数据看板入口由<a href="/zh/docs/guide/feature-guide/system-settings/settings-site#侧边栏模块" target="_blank" rel="noopener noreferrer">站点与品牌配置</a>中侧边栏模块的「数据看板」开关控制。
</Callout>

**配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 启用数据仪表板 | 控制后台用量数据的定时汇总与写入。 | 开关。 | 开启 |
| 刷新间隔 (分钟) | 后台用量数据的汇总间隔。 | 1～1440 的整数；界面说明为「保持此值大于 1 分钟以避免数据库负载过重」。关闭「启用数据仪表板」时不可编辑。 | `5` |
| 默认时间粒度 | 界面说明为「仅 UI 粒度 — 数据仍按小时汇总」。用户进入数据看板时使用的粒度，由各自在<a href="/zh/docs/guide/feature-guide/user/dashboard#设置图表的默认显示" target="_blank" rel="noopener noreferrer">数据看板</a>「偏好设置」中的「默认时间粒度」决定。 | 可选「小时」「天」「本周」。关闭「启用数据仪表板」时不可编辑。 | 小时 |

</div>

### 公告

- 控制台内容-公告

![控制台内容-公告页面](/assets/guide/feature-guide/system-settings-console-content-announcement.png)

| 类型 | 公告类型。 |
| 额外 | 额外备注。 |
| 操作 | 编辑图标打开「编辑公告」；⋯ →「删除」从列表移除。 |

</div>

**「添加公告」配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

### API 地址

### 聊天预设

- 控制台内容-聊天预设（可视化）

![控制台内容-聊天预设可视化页面](/assets/guide/feature-guide/system-settings-console-content-chat-presets-visual.png)

- 控制台内容-聊天预设（JSON）

![控制台内容-聊天预设 JSON 页面](/assets/guide/feature-guide/system-settings-console-content-chat-presets-json.png)

本分区配置聊天应用一键导入的链接模板，分「可视化」「JSON」两个标签，两者编辑同一份预设，页头「保存聊天设置」一起保存。

**操作流程：**
1. 在「可视化」标签点击「添加聊天预设」，或切换到「JSON」标签直接编辑。
2. 填写聊天客户端名称和 URL。
3. 点击页头「保存聊天设置」。

<Callout type="warn" title="注意">
- `{key}` 会出现在打开的 URL 中，只配置可信客户端的导入地址；第三方或未知域名的预设可接收用户的 API 密钥。
- URL 不做格式校验；占位符填错或不受支持时不会报错，只在用户导入时暴露。
</Callout>

**可视化：**

列表列为「聊天客户端名称」「URL」「操作」，可用「搜索聊天预设...」筛选；编辑图标打开「编辑聊天预设」，⋯ →「删除」直接从列表移除，不弹确认。编辑后的预设移到列表末尾。

**JSON：**

「聊天配置 JSON」编辑器按数组编辑，界面说明为「聊天客户端预设数组。每个项目都是一个对象，包含一个键值对：客户端名称及其 URL。」格式不正确时，编辑器下方显示「应为 JSON 数组。」「每个条目必须是包含单个键值对的对象。」「每个条目必须恰好包含一个键值对。」或「无效的 JSON 字符串。」。

**占位符说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 占位符 | 替换为 |
| --- | --- |
| `{key}` | 用户的 API 密钥。 |
| `{address}` | 「站点与品牌 › 系统信息」中的服务器地址。 |
| `{cherryConfig}`、`{aionuiConfig}`、`{deepchatConfig}`、`{aqbotConfig}` | 对应客户端的导入配置，含 API 密钥和服务器地址。 |

</div>

<Callout type="info" title="提示">
- 默认内置 10 个客户端：Cherry Studio、AionUI、流畅阅读、CC Switch、DeepChat、AQBot、Lobe Chat 官方示例、AI as Workspace、AMA 问天、OpenCat。
- 「流畅阅读」预设不在侧边栏「聊天」中显示，只在 API 密钥行的「聊天」菜单中把密钥发送给浏览器扩展。
</Callout>

2. 点击页头「保存绘图设置」。

<Callout type="info" title="提示">
绘图分区只有开关。上游 Base URL、端点、密钥、账号过滤值等请到<a href="/zh/docs/guide/feature-guide/admin/channel" target="_blank" rel="noopener noreferrer">渠道管理</a>的 Midjourney 渠道配置。

**配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |

| 在后续操作前要求任务成功 | 用户必须等待成功的绘图完成，才能进行放大或变体。 | 开关。 | 开启 |

</div>

## 保存与生效

保存方式见<a href="/zh/docs/guide/feature-guide/system-settings/system-setting#保存方式" target="_blank" rel="noopener noreferrer">系统设置概览</a>，生效与多实例同步规则见<a href="/zh/docs/guide/feature-guide/system-settings/system-setting#生效范围与多实例同步" target="_blank" rel="noopener noreferrer">生效范围与多实例同步</a>，浏览器何时显示新值见<a href="/zh/docs/guide/feature-guide/system-settings/system-setting#前端显示与缓存" target="_blank" rel="noopener noreferrer">前端显示与缓存</a>。未特别说明时，保存后处理该请求的节点立即使用新值，其他节点约 3 秒内随系统设置同步（最迟一个同步周期，默认 60 秒）。同步周期由环境变量 `SYNC_FREQUENCY` 调整，单位为秒，默认 60 秒，修改后需重启 New API。各配置项读取新值的时机如下：

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 数据仪表板 › 启用数据仪表板 | 页头「保存更改」 | 之后记录的用量才计入看板，关闭后不再计入；已有数据保留，关闭期间的用量不会补记。 |
| 数据仪表板 › 刷新间隔 (分钟) | 页头「保存更改」 | 当前这一轮等待结束后，才按新间隔执行。 |
| 数据仪表板 › 默认时间粒度 | 页头「保存更改」 | — |
| 四个列表分区 › 「已启用」开关 | 切换后立即保存，先后提示「设置更新成功」「设置已保存」 | 公告、API 地址、常见问答、Uptime Kuma 在控制台中对应的面板（公告还包括通知中心）刷新页面后显示或隐藏。 |
| 四个列表分区 › 列表 | 新增、编辑、删除只修改页面数据，点击卡片内的「保存设置」后整体写入 | 控制台中对应的面板（公告还包括通知中心）刷新页面后显示新内容。 |
| 聊天预设 | 「保存聊天设置」 | 侧边栏「聊天」和 API 密钥列表中的「聊天」菜单刷新页面后更新。 |
| 绘图 › 启用绘制功能 | 「保存绘图设置」 | — |
| 绘图 › 其余 5 个开关 | 「保存绘图设置」 | 下一次相关的绘图请求起生效。 |

</div>

**补充说明：**
- **列表的保存**：四个列表分区的新增、编辑、删除只修改页面数据，提示「…已添加。点击 "保存设置" 以应用。」等；点击「保存设置」后整体写入，成功提示如「公告保存成功」。
- **删除确认**：删除列表条目前弹出「您确定吗？」，确认后仍需点击「保存设置」。
- **无改动不提示**：「保存更改」「保存聊天设置」「保存绘图设置」只提交有改动的项，没有改动时不提交，也不提示。
- **用量计入**：各节点各自汇总用量，并按刷新间隔写入数据库。
- **运行状态**：Uptime Kuma 各状态组的运行状态不经过保存，每次打开面板或点击刷新时由服务端实时获取。

## 注意事项

- **任一条不合规时整个列表被拒**：点击「保存设置」时服务端逐条检查，任一条不合规时整个列表都不保存。
- **两套公告**：本页「公告」与站点与品牌的「系统公告」是两套配置，不互相替代。
- **面板开关不在数据仪表板**：面板显示由各列表分区的「已启用」与侧边栏模块「数据看板」控制，见[数据仪表板](#数据仪表板)。
- **聊天预设不校验 URL**：占位符填错时只在用户导入时暴露，见[聊天预设](#聊天预设)。
- **绘图只有开关**：Midjourney 上游配置在渠道层，见[绘图](#绘图)。

<Accordion title="面板不显示">
**可能原因**：
- 对应分区的启用开关未开启。
- 侧边栏模块「数据看板」未开启。整个数据看板入口受该模块控制。

**处理方法**：
1. 在对应分区打开「已启用」开关。
2. 在站点与品牌的侧边栏模块中打开「数据看板」。
3. 刷新页面或重新进入数据看板。
</Accordion>

<Accordion title="保存被拒绝">
**可能原因**：列表中任一条不合规（URL 无效、颜色不在可选范围、条目超出上限或必填项缺失），整个列表都不保存。

**处理方法**：
1. 查看提示，修正后重试。
</Accordion>

<Accordion title="公告显示未读">
**说明**：公告按 id 记录已读（无 id 时按内容哈希）。新增公告显示为未读，编辑已有公告不会重新变为未读。打开通知中心的「时间线」标签即标记已读。
</Accordion>

<Accordion title="FAQ 顺序不对">
**说明**：界面没有排序控件，按列表顺序展示。
</Accordion>

<Accordion title="Uptime Kuma 不显示">
**可能原因**：
- 分区未启用。
- New API 服务器无法访问该 Uptime Kuma 地址。
- 分组数超过 20。
</Accordion>

<Accordion title="聊天导入不生效">
**说明**：填入错误或占位符不支持时，仅在客户端导入时才会发现。

**可能原因**：
- 应用名与客户端模板不一致。
- URL 不支持对应占位符。
</Accordion>

<Accordion title="绘图行为未生效">
**说明**：上游地址/密钥在 Midjourney 渠道层。

**可能原因**：
- 对应开关未开启，或开启后未保存。
- Midjourney 渠道配置不正确。
</Accordion>

<Accordion title="保存后状态未更新">
**说明**：保存后，执行保存的浏览器中已打开的看板面板和侧边栏「聊天」不会自动更新。

**处理方法**：
1. 刷新页面或重新进入对应入口。
</Accordion>
