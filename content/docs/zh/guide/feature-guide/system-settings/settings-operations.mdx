运维配置位于 `/system-settings/operations`，仅 Root 可访问。

## 运维配置简介

该工作区包含「系统行为」「模型性能指标」「邮件与通知」「Worker 代理」「日志维护」「性能」和「系统维护」七个分区。用于配置系统模式、模型性能指标、邮件发送与余额提醒、Worker、日志维护、性能保护和版本检查。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 分区 | 入口 | 主要用途 |
| --- | --- | --- |
| [系统行为](#系统行为) | `/system-settings/operations/behavior` | 侧边栏默认偏好、演示站与自用模式。 |
| [模型性能指标](#模型性能指标) | `/system-settings/operations/alerts` | 模型性能指标的记录、刷库与保留。 |
| [邮件与通知](#邮件与通知) | `/system-settings/operations/email` | 邮件发送方式（SMTP / Resend）与余额不足提醒。 |
| [Worker 代理](#worker-代理) | `/system-settings/operations/worker` | 指定下载与通知链路的外部代理。 |
| [日志维护](#日志维护) | `/system-settings/operations/logs` | 消费日志开关、用户日志导出与查询范围、数据库日志与服务器文件清理。 |
| [性能](#性能) | `/system-settings/operations/performance` | 请求体缓存、资源保护和进程统计。 |
| [系统维护](#系统维护) | `/system-settings/operations/update-checker` | 版本信息与更新检查。 |

</div>

<Callout type="warn" title="注意">
  日志删除、缓存清理和强制 GC 都是即时运维操作，不属于可撤销的表单草稿。执行前先确认目标、影响范围和恢复方案，并避免在高峰期反复操作。
</Callout>

## 配置分区

运维域下有七个独立分区：

### 系统行为

- 运维-系统行为配置

![系统行为配置](/assets/guide/feature-guide/system-settings-operations-system-behavior.png)

系统行为分区包含三个开关：

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 配置键 | 默认值 | 实际作用与边界 |
| --- | --- | --- | --- |
| 默认折叠侧边栏 | `DefaultCollapseSidebar` | `false` | 界面说明为「默认情况下为新用户折叠侧边栏」。 |
| 演示站点模式 | `DemoSiteEnabled` | `false` | 界面说明为「启用功能受限的演示模式」。 |
| 自用模式 | `SelfUseModeEnabled` | `false` | 未设置价格的模型按默认倍率 `37.5` 计费并出现在模型列表中，不再因未定价被拒绝；登录页隐藏「注册」链接，但不关闭注册接口。 |

</div>

### 模型性能指标

- 运维-模型性能指标配置

![模型性能指标配置](/assets/guide/feature-guide/system-settings-operations-model-performance-metrics.png)

模型性能指标从 Relay 请求完成和计费链路收集模型、分组、请求耗时、首 Token 时间、成功率、输出 Token 和生成耗时，用于模型广场等性能展示。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 配置键 | 默认值 | 行为与边界 |
| --- | --- | --- | --- |
| 启用模型性能指标 | `perf_metrics_setting.enabled` | `true` | 控制是否继续记录 Relay 性能样本。关闭后不会新增样本，刷库循环也会跳过写库和过期清理；已有数据库记录与关闭前的内存聚合桶不会立即清空。 |
| 刷库间隔（分钟） | `perf_metrics_setting.flush_interval` | `5` | 最小值为 `1`，控制把已完成的内存聚合桶写入数据库以及执行过期数据清理的循环周期，不是前端图表刷新频率。 |
| 聚合时间桶 | `perf_metrics_setting.bucket_time` | `hour` | 可选 1 分钟、5 分钟和 1 小时；修改后只影响后续样本的分桶。 |
| 保留天数 | `perf_metrics_setting.retention_days` | `0` | `0` 表示永久保留；正数会在刷库循环中清理更早的性能指标。 |

</div>

操作流程：
1. 按数据量选择是否记录模型性能指标、刷库间隔、聚合时间桶与保留天数，然后保存。
2. 检查性能指标时注意：处理本次查询的节点会直接合并其内存中尚未刷库的数据，但多实例部署时，其他节点的样本要等其刷库后才可见，模型广场还会缓存约 1 分钟；不能用保存后的即时空图判断失败。

<Callout type="info" title="提示">
选择较细的桶或较短的刷库间隔会增加内存、数据库和后台写入负载，应结合模型数量、分组数量和请求量评估。
</Callout>

### 邮件与通知

- 运维-邮件与通知配置

![邮件与通知配置（SMTP 方式）](/assets/guide/feature-guide/system-settings-operations-email-and-notifications.png)

系统邮件用于注册验证码、密码重置、用户通知和其他系统邮件，可通过 SMTP 或 Resend API 发送；本分区还包含余额不足提醒。

- 邮件发送方式

「邮件发送方式」（`EmailProvider`，默认 `smtp`）可选 SMTP 或 Resend API。只用所选方式发送邮件，另一种方式的配置会保留；所选方式发送失败时不会改用另一种。页面只显示所选方式的字段，保存时最后才写入发送方式，同一次保存中其他配置写入失败时不会切换。

- SMTP

选择 SMTP 时，主要配置键如下：

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 页面字段 | 配置键 | 默认值或格式 | 说明 |
| --- | --- | --- | --- |
| SMTP 主机 | `SMTPServer` | 空 | SMTP 提供商的主机名或 IP。 |
| 端口 | `SMTPPort` | `587` | 常用端口包括 25、465 和 587。 |
| 跳过 SMTP TLS 证书验证 | `SMTPInsecureSkipVerify` | `false` | 允许自签名或主机名不匹配的 SMTP 证书。 |
| 用户名 | `SMTPAccount` | 空 | 用于与 SMTP 服务器进行身份验证的账户。 |
| 密码 / 访问令牌 | `SMTPToken` | 不回显 | 留空以保留现有凭证。 |
| SMTP 加密方式 | `SMTPSSLEnabled`、`SMTPStartTLSEnabled` | 均关闭 | 选择一种 SMTP 传输加密方式；可选'无加密'、'SSL/TLS'、'STARTTLS'。 |
| 强制 AUTH LOGIN | `SMTPForceAuthLogin` | `false` | 强制使用 AUTH LOGIN 方法进行 SMTP 认证。 |
| 发件地址 | `SMTPFrom` | 空；只能是邮箱地址或留空 | 只填纯邮箱地址，例如 `noreply@example.com`；留空时使用「用户名」。收件人看到的发件人名称固定为系统名称，不能在此设置。 |

</div>

- 传输加密模式

| 模式 | 行为与建议 |
| --- | --- |
| 无加密 | 通常建立明文 SMTP 连接；端口 `465` 且未启用 STARTTLS 时仍按下述兼容规则使用隐式 TLS。明文连接只适合受控内网或明确要求该模式的服务。 |
| SSL/TLS | 建立隐式 TLS 连接。即使没有显式选择，端口为 `465` 且未启用 STARTTLS 时，当前后端也会使用隐式 TLS。 |
| STARTTLS | 先建立普通 SMTP 连接，再要求服务器支持并升级到 STARTTLS；服务器未声明 STARTTLS 时发信失败。 |

- Resend API

选择 Resend API 时显示以下字段：

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 配置键 | 默认值或格式 | 说明 |
| --- | --- | --- | --- |
| 发件邮箱地址 | `ResendFrom`（地址部分） | 空；必须是有效邮箱 | 域名须已在 Resend 完成验证。 |
| 发件人名称 | `ResendFrom`（名称部分） | 空 | 收件人看到的发件人名称，留空时使用「系统名称」；不能包含换行。保存时与地址合并为 `"名称" <地址>` 存入 `ResendFrom`。 |
| Resend API 密钥 | `ResendApiKey` | 不回显 | 留空以保留现有密钥；从未配置过密钥时必须填写，否则提示「请先配置 Resend API 密钥，再启用 Resend」。 |

</div>

Resend 为当前发送方式时，后端会拒绝把密钥或发件地址改成无效值。

<Callout type="info" title="提示">
SMTP 连接和 Resend 请求（`https://api.resend.com/emails`）都由后端直接发出，不经过 Worker 代理或 URL SSRF 校验；Resend 拒绝发送时，具体原因只写入服务端日志。生产环境应确认 DNS、端口、证书、认证、SPF、DKIM、DMARC 和发件人策略。
</Callout>

- 配置流程

1. 选择发送方式。SMTP 需从邮件服务商获取主机、端口、认证账号和授权码或密码，不要把 Web 邮箱登录地址填入主机字段；Resend 需准备已在 Resend 完成验证的发件域名和 API 密钥。
2. 使用 SMTP 时，按服务商要求选择 SSL/TLS 或 STARTTLS，填写纯邮箱发件地址。除已评估的内部场景外，不启用跳过证书验证。
3. 填写新 Token 并保存；不轮换凭证时保留输入框为空。

- 余额不足提醒

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 余额不足提醒 | `QuotaRemindEnabled` | `true` | 界面说明为「用户余额低于阈值时，通过其选择的通知方式提醒」，实际只在一次扣费跨过阈值时提醒（见下文）。关闭后全站不发送余额提醒。 |
| 默认提醒阈值 (USD) | `QuotaRemindThreshold` | `1000`（内部 quota） | 仅在开关开启时显示。括号内随「显示模式」变为 USD、CNY、自定义符号或 Tokens；按显示金额输入，保存时换算为内部 quota 单位。例如默认值 `1000` quota 在 USD 显示下为 `0.002`。 |

</div>

Relay 结算链路会分别检查钱包和订阅额度：钱包按 `UserQuota - (quota + preConsumedQuota)` 比较，订阅按订阅总额减已使用量比较。只有本次扣费使余额从阈值及以上降到阈值以下时才提醒一次；余额已低于阈值时不再重复提醒，充值回到阈值及以上后才可能再次提醒。

操作流程：
1. 根据<a href="/zh/docs/guide/feature-guide/system-settings/settings-billing#货币与展示" target="_blank" rel="noopener noreferrer">计费与支付配置</a>中的「显示模式」设置默认提醒阈值。

<Callout type="info" title="提示">
- 异步发送余额不足通知。用户在<a href="/zh/docs/guide/feature-guide/user/personal-setting#设置通知和行为偏好" target="_blank" rel="noopener noreferrer">个人资料</a>中关闭「余额不足提醒」时不发送；用户设置的非零提醒阈值优先于此全局值。
- 通知方式由用户设置决定，可以是邮件、Webhook、Bark 或 Gotify；未选择时默认使用邮件。通知失败会写入系统错误日志。
</Callout>

### Worker 代理

- 运维-Worker 代理配置

![Worker 代理配置](/assets/guide/feature-guide/system-settings-operations-worker-proxy.png)

Worker 代理用于源码中明确接入的服务端外部请求链路，例如远程文件或图片下载、用户 Webhook，以及 Bark 和 Gotify 通知。它不是渠道 Relay、支付、OAuth 或所有出站流量的通用代理。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 配置键 | 默认值或校验 | 行为 |
| --- | --- | --- | --- |
| Worker URL | `WorkerUrl` | 空；非空时必须以 `http://` 或 `https://` 开头 | 保存时移除末尾 `/`；非空时请求将被转发到此 Worker。 |
| Worker 访问密钥 | `WorkerValidKey` | 不回显 | 随 Worker 请求发送，用于与 Worker 进行身份验证。留空以保留现有密钥。 |
| 允许 HTTP 图像请求 | `WorkerAllowHttpImageRequestEnabled` | `false` | 界面说明为「当代理通过 HTTP 获取图像的 worker 时启用」。 |

</div>

- 配置与停用

1. 准备受控的 Worker 服务，确认其接受 New API 的请求格式并校验访问密钥，再填写 URL 与密钥。
2. 按目标资源的协议决定是否允许 HTTP，点击「保存 Worker 设置」。
3. 停用时清空 Worker URL 并保存，已保存的访问密钥会一并清除；若同时在密钥框输入了新值，则保存为该新值。仅清空密钥输入框但保留 URL，不会清除旧密钥。

<Callout type="info" title="提示">
- Worker 负载可能携带目标 URL、请求头、通知内容和认证信息。
- `WorkerValidKey` 作为请求 JSON 的 `key` 字段发送，是否校验由 Worker 实现决定；New API 不使用它验证 Worker 响应，也不能用它替代目标 URL 的访问控制。
- 普通下载、Webhook 和通知链路仍会在进入 Worker 前使用相应的 SSRF 校验，但 Worker URL 本身是 Root 配置的外部信任边界。
</Callout>

<Callout type="warn" title="注意">
  只使用由你控制并能审计日志的 Worker。启用 Worker 后，敏感通知或远程资源请求可能经过该服务；确认其 TLS、密钥验证、日志脱敏、超时、目标过滤和数据保留策略。
</Callout>

### 日志维护

- 运维-日志维护配置

![日志维护配置](/assets/guide/feature-guide/system-settings-operations-log-maintenance.png)

日志维护分为记录配额使用量、日志查询与导出、清理历史日志和服务器日志管理。两种清理影响不同的数据源。

- 记录配额使用量

1. 「记录配额使用量」对应 `LogConsumeEnabled`，默认开启。
2. 它控制是否创建逐请求的消费日志，包括普通 Relay 和异步任务结算产生的消费记录。
3. 关闭后会减少数据库写入，但使用日志、消费统计、数据看板统计和依赖这些记录的分析将缺少新数据。
4. 调整开关后点击「保存日志设置」。

<Callout type="info" title="提示">
该开关只控制消费日志：不会停止错误、充值、系统或退款日志，不影响审计日志，也不会关闭服务器文本日志、Midjourney 任务表或异步任务表。
</Callout>

- 日志查询与导出

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 配置键 | 默认值或校验 | 行为与边界 |
| --- | --- | --- | --- |
| 允许用户导出日志 | `log_setting.user_export_enabled` | `true` | 用户可以在使用日志页面下载自己的日志。管理员始终可以导出。关闭后普通用户的导出请求会被拒绝。 |
| 日志最长时间范围（天） | `log_setting.max_range_days` | `365`；整数，最小 `1` | 用户在日志和数据看板中一次最多能查看的时间范围，也是每次导出的最长时间范围。未指定开始时间时按该范围回溯，超出时报错。每次导出都受此限制，管理员查询日志不受限。 |

</div>

两项与「记录配额使用量」共用「保存日志设置」按钮。

- 清理历史日志

清理作用于执行节点连接的 `LOG_DB`，移除所选时间戳之前创建的所有日志条目。

1. 先归档必要数据，在日期与时间控件中选择截止时间，或使用「24 小时前」「7 天前」「30 天前」快捷项。
2. 点击「清理日志」，在确认框中确认删除；系统会创建 log_cleanup 系统任务。
3. 观察进度与已处理数量。任务处于待执行或运行中时，页面不会再发起同类任务；关闭页面不等于取消后台清理。
4. 成功时显示删除数量或“没有匹配日志”的提示；失败时查看任务错误。

| 任务状态 | 含义与处理 |
| --- | --- |
| `pending` | 等待运行器领取；长期等待时检查 Master 实例和系统任务运行器。 |
| `running` | 正在清理并更新进度，不要重复发起。 |
| `succeeded` | 本次任务完成。 |
| `failed` | 查看错误并检查日志库与运行器；已完成的删除不会自动恢复。 |

<Callout type="info" title="提示">
- 此操作不会清理 `quota_data` 聚合数据、性能指标、审计日志、绘图与异步任务记录，也不会删除服务器上的日志文件。
- 多个节点共享日志库时，删除会影响共同的日志历史，不能把它当作只清理某一个节点的日志。
</Callout>

- 服务器日志管理

服务器日志管理只在配置了日志目录时可用，并且只扫描该目录下名称匹配 `oneapi-*.log` 的文件。<br/>
可查看服务器日志目录、日志文件数、日志总大小和时间范围；服务器日志提供两种清理方式：

1. 按数量：按文件名（含时间戳）从新到旧保留最近 N 个文件，删除其余日志文件。
2. 按天数：保留最近 N 天，删除修改时间早于 N 天前的日志文件。

<Callout type="warn" title="注意">
  数据库日志和服务器日志文件的删除不可恢复。清理前确认审计、争议处理、支付、合规和故障排查所需的留存周期，并完成必要的数据库或日志归档。
</Callout>

### 性能

- 运维-性能配置

![性能配置](/assets/guide/feature-guide/system-settings-operations-performance.png)

性能分区同时管理请求体磁盘缓存、请求体内存缓存和系统性能监控。

- 请求体磁盘缓存

启用后，达到阈值且未超过当前缓存容量边界的大请求体或文件数据会临时存到磁盘，以减少内存占用；不满足条件时继续使用内存。

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap [&_td_code]:wrap-anywhere">

| 页面字段 | 配置键 | 默认值或校验 | 行为与边界 |
| --- | --- | --- | --- |
| 启用磁盘缓存 | `performance_setting.disk_cache_enabled` | `false` | 启用磁盘缓存后，大请求体将临时存储到磁盘而非内存，可显著降低内存占用。建议在 SSD 环境下使用。 |
| 磁盘缓存阈值 (MB) | `performance_setting.disk_cache_threshold_mb` | `10 MB`；最小 `1 MB` | 请求体超过此大小时使用磁盘缓存 |
| 磁盘缓存最大总量 (MB) | `performance_setting.disk_cache_max_size_mb` | `1024 MB`；最小 `100 MB` | 按当前进程统计判断“现有用量 + 新请求大小”是否超过该值；它不是操作系统磁盘配额。 |
| 缓存目录 | `performance_setting.disk_cache_path` | 空 | 留空使用系统临时目录下的 `new-api-body-cache`；非容器环境可编辑，容器环境不显示此字段，应通过挂载和容器存储策略管理。 |

</div>

- 系统性能监控

系统性能监控默认开启。后台约每 5 秒采集 CPU、内存和缓存目录所在磁盘的使用率；CPU 和内存优先按容器 cgroup 配额计算，取不到时使用宿主机数值。当某个阈值大于 `0`，且连续 3 次采样（约 15 秒）的整数使用率都严格高于阈值时，新 Relay 请求会被拒绝并返回 HTTP `503`；任一次采样回落即恢复。关闭监控或调高阈值后立即放行，采样超过 30 秒未更新时也不拒绝。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 配置键 | 默认值或校验 |
| --- | --- | --- |
| 启用性能监控 | `performance_setting.monitor_enabled` | `true` |
| CPU 阈值 (%) | `performance_setting.monitor_cpu_threshold` | `90`；前端最小值 `0`，没有前端最大值限制 |
| 内存阈值 (%) | `performance_setting.monitor_memory_threshold` | `90`；`0–100` |
| 磁盘阈值 (%) | `performance_setting.monitor_disk_threshold` | `95`；`0–100` |

</div>

<Callout type="info" title="提示">
- 资源保护使用周期性快照，不是排队或自动扩容系统。启用后通常每 5 秒更新一次；
- 资源保护中间件挂载在 Playground、`/v1`（含视频生成）、Gemini（`/v1beta`）、Midjourney 和任务插件等 Relay 路径，不影响登录、普通管理 API 或全部后台任务。
</Callout>

- 性能统计与操作

页面显示处理该请求的节点上的磁盘／内存缓存用量和命中次数、活动缓存数量、缓存目录文件、磁盘空间、Go 内存以及 Goroutine 数量，并提供以下操作：

| 操作 | 实际影响 |
| --- | --- |
| 刷新统计 | 重新获取处理该请求的节点的统计信息。 |
| 清理不活跃缓存 | 删除缓存目录中修改时间超过 10 分钟的普通文件。实现只按文件修改时间判断，没有额外核对文件是否仍被请求引用；高峰期或存在长时间请求时应谨慎执行。 |
| 重置统计 | 只清零磁盘和内存缓存命中次数，不清空活动缓存、当前用量或目录文件。 |
| 执行 GC | 在处理该请求的节点上立即调用垃圾回收，可能造成短暂延迟抖动。 |

<Callout type="info" title="提示">
这些统计和操作只作用于处理该请求的节点，不会自动遍历其他节点。
</Callout>

- 配置与操作顺序

1. 根据实例的磁盘空间和请求体大小设置缓存阈值与最大总量；不要把最大缓存值当作已经预留的磁盘空间。
2. 设置资源保护阈值并保存；按每个维度的单位和范围填写，不把 CPU 校验范围套用到内存或磁盘。
3. 先使用「刷新统计」观察用量，再按需要单独执行「清理不活跃缓存」「重置统计」或「执行 GC」。
4. 多实例部署要分别检查目标节点。缓存清理不可恢复，重置命中次数也不能代替释放缓存或清理日志。

## 注意事项

- **即时运维操作不可撤销**：日志清理、服务器日志清理、缓存清理、重置统计和执行 GC 都没有可撤销的草稿，见[日志维护](#日志维护)和[性能](#性能)。
- **日志清理影响共享的日志库**：清理作用于执行节点连接的日志库，多个节点共享日志库时影响各节点的日志历史，见[日志维护](#日志维护)。
- **资源保护会拒绝新的 Relay 请求**：阈值被连续采样超过时，新的 Relay 请求返回 HTTP `503`，登录和普通管理接口不受影响；阈值过低会拒绝正常请求，见[性能](#性能)。
- **保存成功不代表连接成功**：保存邮件配置时不测试连接，见[邮件与通知](#邮件与通知)。
- **SMTP 和 Resend 不经 Worker**：两者都由后端直接发出，不经过 Worker 代理或 URL SSRF 校验，见[邮件与通知](#邮件与通知)。
- **余额不足提醒失败不影响扣费**：提醒在结算后异步发送，发送失败只写入系统错误日志，见[邮件与通知](#邮件与通知)。

## 常见问题

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="修改默认侧边栏后当前前端没有变化">
**说明**：该值已发布到公开状态，但当前新版前端仅读取 `sidebar_state` Cookie，尚未消费该设置。清除 Cookie 仅会回到前端自身的默认展开状态。该配置主要供兼容客户端使用。
</Accordion>

<Accordion title="开启演示站点模式后危险操作仍可执行">
**说明**：当前版本的演示站点模式不限制任何功能（见[系统行为](#系统行为)）。

**处理方法**：
1. 使用角色权限、网络边界、只读数据副本和外部访问控制保护演示实例。
</Accordion>

<Accordion title="开启自用模式后仍能注册或看到多个用户">
**说明**：该开关不会关闭多用户与注册接口。

**处理方法**：
1. 如需限制注册，在<a href="/zh/docs/guide/feature-guide/system-settings/settings-auth" target="_blank" rel="noopener noreferrer">身份验证配置</a>中关闭对应能力。
</Accordion>

<Accordion title="额度已低于阈值但没有通知">
**说明**：提醒仅在一次扣费跨过阈值时发送，余额原本已低于阈值时不会再提醒。

**可能原因**：
- 站点「余额不足提醒」开关未开启。
- 用户关闭了个人提醒。
- 个人阈值或通知方式与预期不符。
- 所选邮件发送方式（SMTP 或 Resend）、Webhook、Bark、Gotify、Worker（含「允许 HTTP 图像请求」）或 SSRF 存在问题。

**处理方法**：
1. 查看服务端错误日志。
</Accordion>

<Accordion title="模型性能指标没有立即出现">
**说明**：查询时仅合并数据库中已刷库的数据和处理本次查询的节点的内存聚合桶。多实例部署时，其他节点的样本需等其刷库后才可见。模型广场的数据还会在页面缓存约 1 分钟。

**可能原因**：
- 总开关未开启。
- 模型名、分组（仅统计分组倍率中存在的分组和 `auto`）、桶时间或保留设置与预期不符。
</Accordion>

<Accordion title="保存后仍无法发信">
**说明**：页面不测试连接。

**可能原因**：
- 「邮件发送方式」选的不是已配置的方式。系统不会改用另一种。
- SMTP：主机、端口、安全模式、证书、账号、Token、发件地址（仅可填纯邮箱）或服务商限制存在问题。端口 `465` 还会触发隐式 TLS 行为。
- Resend：发件域名未验证，或 API 密钥无效。具体拒绝原因见服务端日志。
</Accordion>

<Accordion title="Worker 已配置但渠道请求仍直连上游">
**说明**：Worker 仅用于明确接入的下载和通知链路，不是模型渠道的通用网络代理。
</Accordion>

<Accordion title="清理数据库日志后看板历史数据仍存在">
**说明**：日志任务仅删除 `logs` 表，不会删除 `quota_data` 聚合、性能指标或任务记录。
</Accordion>

<Accordion title="日志清理一直等待或只完成了一部分">
**说明**：任务失败不会回滚已删除的数据。

**可能原因**：Master 实例的运行器或日志库连接存在问题。

**处理方法**：
1. 查看任务错误。
2. 重新提交前，再次确认截止时间。
</Accordion>

<Accordion title="清理服务器日志后仍保留一个旧文件">
**说明**：当前活动日志始终跳过。按数量清理还会保留指定的最新文件数。
</Accordion>

<Accordion title="磁盘缓存达到上限后请求失败了吗">
**说明**：系统通常改用内存。部分流式读取链路在磁盘创建失败且 Reader 已消费时可能直接报错。上限也不是磁盘配额保证。
</Accordion>

<Accordion title="资源使用率达到阈值但请求没有被拒绝">
**说明**：比较条件是严格高于阈值，使用采样的整数值，且需连续 3 次采样（约 15 秒）都超过阈值。采样超过 30 秒未更新时不拒绝。阈值为 `0` 时该维度不检查。在容器中，CPU 和内存按 cgroup 配额计算，可能与宿主机监控数值不同。
</Accordion>

<Accordion title="检查更新提示的版本不符合预期">
**说明**：页面按版本号比较，预发布版（如 `rc`）也参与比较，无法解析的标签会被忽略。当前版本为开发构建（`v0.0.0`）时无法比较。

**处理方法**：
1. 打开 Release，人工核对版本、分支和升级路径。
</Accordion>

</Accordions>
