### 模型性能指标

- 运维-模型性能指标配置

![模型性能指标配置](/assets/guide/feature-guide/system-settings-operations-model-performance-metrics.png)

分区说明为「收集 Relay 延迟和成功率指标，用于模型广场展示。」。指标从 Relay 请求完成和计费链路收集模型、分组、请求耗时、首 Token 时间、成功率、输出 Token 和生成耗时。

**操作流程：**
1. 按数据量设置是否记录模型性能指标、刷库间隔、聚合时间桶与保留天数。
2. 点击页头「保存更改」。

<Callout type="info" title="提示">
- 处理本次查询的节点会直接合并其内存中尚未刷库的数据；多实例部署时，其他节点的样本要等其刷库后才可见，模型广场还会缓存约 1 分钟。不能用保存后的即时空图判断失败。
- 选择较细的桶或较短的刷库间隔会增加内存、数据库和后台写入负载，应结合模型数量、分组数量和请求量评估。
</Callout>

**配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 启用模型性能指标 | 控制是否继续记录 Relay 性能样本。关闭后不会新增样本，刷库循环也会跳过写库和过期清理；已有数据库记录与关闭前的内存聚合桶不会立即清空。 | 开关；关闭时其余三项置灰。 | 开启 |
| 刷库间隔（分钟） | 控制把已完成的内存聚合桶写入数据库以及执行过期数据清理的循环周期，不是前端图表刷新频率。 | 最小值为 `1`。 | `5` |
| 聚合时间桶 | 修改后只影响后续样本的分桶。 | 可选「1 分钟」「5 分钟」「1 小时」。 | 1 小时 |
| 保留天数 | 正数会在刷库循环中清理更早的性能指标。 | `0` 表示永久保留数据。 | `0` |

</div>

### 邮件与通知

- 运维-邮件与通知配置

![邮件与通知配置（SMTP 方式）](/assets/guide/feature-guide/system-settings-operations-email-and-notifications.png)

系统邮件用于注册验证码、密码重置、用户通知和其他系统邮件，可通过 SMTP 或 Resend API 发送；本分区还包含余额不足提醒。

**操作流程：**
1. 选择「邮件发送方式」。SMTP 需从邮件服务商获取主机、端口、认证账号和授权码或密码，不要把 Web 邮箱登录地址填入主机字段；Resend 需准备已在 Resend 完成验证的发件域名和 API 密钥。
2. 使用 SMTP 时，按服务商要求选择 SSL/TLS 或 STARTTLS，填写纯邮箱发件地址。除已评估的内部场景外，不启用跳过证书验证。
3. 填写新的密码、令牌或 API 密钥；不轮换凭证时保留输入框为空。
4. 根据<a href="/zh/docs/guide/feature-guide/system-settings/settings-billing#货币与展示" target="_blank" rel="noopener noreferrer">计费与支付配置</a>中的「显示模式」设置「默认提醒阈值」。
5. 点击页头「保存更改」。

<Callout type="info" title="提示">
- 异步发送余额不足通知。用户在<a href="/zh/docs/guide/feature-guide/user/personal-setting#设置通知和行为偏好" target="_blank" rel="noopener noreferrer">个人资料</a>中关闭「余额不足提醒」时不发送；用户设置的非零提醒阈值优先于此全局值。
- 通知方式由用户设置决定，可以是邮件、Webhook、Bark 或 Gotify；未选择时默认使用邮件。通知失败会写入系统错误日志。
- 每位用户的同一种通知默认 10 分钟内最多发送 2 条，超出时不发送。条数由环境变量 `NOTIFY_LIMIT_COUNT`（默认 `2`）调整，时间窗口由 `NOTIFICATION_LIMIT_DURATION_MINUTE`（单位分钟，默认 `10`）调整，本页没有对应设置；两者只在启动时读取，修改后需重启 New API。
</Callout>

**邮件发送方式：**

「邮件发送方式」可选 SMTP 或 Resend API，默认 SMTP；界面说明为「只用所选方式发送邮件，另一种方式的配置会保留。」。所选方式发送失败时不会改用另一种。页面只显示所选方式的字段，保存时最后才写入发送方式，同一次保存中其他配置写入失败时不会切换。

**加密方式说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 模式 | 行为与建议 |
| --- | --- |
| 无加密 | 通常建立明文 SMTP 连接；端口 `465` 且未启用 STARTTLS 时仍按下述兼容规则使用隐式 TLS。明文连接只适合受控内网或明确要求该模式的服务。 |
| SSL/TLS | 建立隐式 TLS 连接。即使没有显式选择，端口为 `465` 且未启用 STARTTLS 时，当前后端也会使用隐式 TLS。 |
| STARTTLS | 先建立普通 SMTP 连接，再要求服务器支持并升级到 STARTTLS；服务器未声明 STARTTLS 时发信失败。 |

</div>

**SMTP 配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| SMTP 主机 | SMTP 提供商的主机名或 IP。 | 不要填入 Web 邮箱登录地址。 | 空 |
| 端口 | 常用端口包括 25、465 和 587。 | 1–65535 的整数，否则提示「端口必须为正整数」。 | `587` |
| SMTP 加密方式 | 选择一种 SMTP 传输加密方式。 | 可选「无加密」「SSL/TLS」「STARTTLS」，各方式见上方「加密方式说明」。初始值可由环境变量设定，见表后「SMTP 环境变量」。 | 无加密 |
| 跳过 SMTP TLS 证书验证 | 允许自签名或主机名不匹配的 SMTP 证书。 | 开关。初始值可由环境变量设定，见表后「SMTP 环境变量」。 | 关闭 |
| 强制 AUTH LOGIN | 强制使用 AUTH LOGIN 方法进行 SMTP 认证。 | 开关。 | 关闭 |
| 用户名 | 用于与 SMTP 服务器进行身份验证的账户。 | 按服务商要求填写。 | 空 |
| 发件地址 | 只填纯邮箱地址，例如 `noreply@example.com`；留空时使用「用户名」。收件人看到的发件人名称固定为系统名称，不能在此设置。 | 只能是邮箱地址或留空，否则提示「请输入有效的邮箱地址或留空」。 | 空 |
| 密码 / 访问令牌 | SMTP 认证使用的密码或访问令牌。 | 不回显；留空以保留现有凭证。 | 空 |

</div>

**SMTP 环境变量：**
- `SMTP_STARTTLS_ENABLE`（布尔，默认 `false`；旧名 `SMTP_STARTTLS_ENABLED` 仍可用）决定「SMTP 加密方式」初始是否为 STARTTLS。
- `SMTP_INSECURE_SKIP_VERIFY`（布尔，默认 `false`；旧名 `SMTP_TLS_INSECURE_SKIP_VERIFY` 仍可用）决定「跳过 SMTP TLS 证书验证」的初始值。
- 在页面保存过对应项后，以页面保存的值为准。

**Resend API 配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 发件邮箱地址 | 域名须已在 Resend 完成验证。 | 必须是有效邮箱，否则提示「请输入有效的发件邮箱地址」；Resend 为当前发送方式时，服务端拒绝保存无效地址。 | 空 |
| 发件人名称 | 收件人看到的发件人名称，留空使用站点名称。 | 不能包含换行符或空字符，否则提示「发件人名称不能包含换行符或空字符」；保存时与发件邮箱地址合并保存。 | 空 |
| Resend API 密钥 | 后端调用 Resend 发送邮件时使用的 API 密钥。 | 不回显，留空以保留现有密钥；从未配置过密钥时必须填写，否则提示「请先配置 Resend API 密钥，再启用 Resend」；Resend 为当前发送方式时，服务端拒绝保存无效密钥。 | 空 |

</div>

<Callout type="info" title="提示">
- SMTP 连接和 Resend 请求都由后端直接发出，不经过 Worker 代理或 URL SSRF 校验。
- Resend 拒绝发送时，具体原因只写入服务端日志。
- 生产环境应确认 DNS、端口、证书、认证、SPF、DKIM、DMARC 和发件人策略。
</Callout>

**提醒规则：**
- Relay 结算时分别检查钱包和订阅额度：钱包按本次扣费前后的余额比较，订阅按订阅总额减已使用量比较。
- 只有本次扣费使余额从阈值及以上降到阈值以下时才提醒一次。
- 余额已低于阈值时不再重复提醒，充值回到阈值及以上后才可能再次提醒。

**余额不足提醒配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 余额不足提醒 | 界面说明为「用户余额低于阈值时，通过其选择的通知方式提醒」，实际只在一次扣费跨过阈值时提醒（见上方「提醒规则」）。关闭后全站不发送余额提醒。 | 开关。 | 开启 |
| 默认提醒阈值 (USD) | 余额提醒的全局默认阈值。 | 仅在开关开启时显示；不小于 0，否则提示「必须大于或等于 0」。括号内随「显示模式」变为 USD、CNY、自定义符号或 Tokens；按显示金额输入，保存时换算为配额点数。 | `1000` 配额点数（USD 显示下为 `0.002`） |

</div>

### Worker 代理

- 运维-Worker 代理配置

![Worker 代理配置](/assets/guide/feature-guide/system-settings-operations-worker-proxy.png)

Worker 代理用于源码中明确接入的服务端外部请求链路，例如远程文件或图片下载、用户 Webhook，以及 Bark 和 Gotify 通知。它不是渠道 Relay、支付、OAuth 或所有出站流量的通用代理。

**操作流程：**
1. 准备受控的 Worker 服务，确认其接受 New API 的请求格式并校验访问密钥，再填写 URL 与密钥。
2. 按目标资源的协议决定是否允许 HTTP，点击页头「保存 Worker 设置」。
3. 停用时清空 Worker URL 并保存，已保存的访问密钥会一并清除；若同时在密钥框输入了新值，则保存为该新值。仅清空密钥输入框但保留 URL，不会清除旧密钥。

<Callout type="warn" title="注意">
- Worker 负载可能携带目标 URL、请求头、通知内容和认证信息。
- 「Worker 访问密钥」随请求 JSON 发送，是否校验由 Worker 实现决定；New API 不使用它验证 Worker 响应，也不能用它替代目标 URL 的访问控制。
- 普通下载、Webhook 和通知链路仍会在进入 Worker 前使用相应的 SSRF 校验，但 Worker URL 本身是 Root 配置的外部信任边界。
- 只使用由你控制并能审计日志的 Worker。启用 Worker 后，敏感通知或远程资源请求可能经过该服务；确认其 TLS、密钥验证、日志脱敏、超时、目标过滤和数据保留策略。
</Callout>

**配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| Worker URL | 保存时移除末尾 `/`；非空时请求将被转发到此 Worker。 | 非空时必须以 `http://` 或 `https://` 开头，否则提示「请提供以 http:// 或 https:// 开头的有效 URL」。 | 空 |
| Worker 访问密钥 | 随 Worker 请求发送，用于与 Worker 进行身份验证。 | 不回显；留空以保留现有密钥。 | 空 |
| 允许 HTTP 图像请求 | 界面说明为「当代理通过 HTTP 获取图像的 worker 时启用」。 | 开关。 | 关闭 |

</div>

### 日志维护

- 运维-日志维护配置

![日志维护配置](/assets/guide/feature-guide/system-settings-operations-log-maintenance.png)

日志维护分为「日志记录」「日志查询与导出」「系统任务记录」「清理历史日志」「服务器日志管理」五组。前三组共用页头「保存日志设置」；两种清理立即执行，影响不同的数据源。

**日志设置操作流程：**
1. 设置「记录配额使用量」「允许用户导出日志」「日志最长时间范围（天）」和「已结束任务保留天数」。
2. 点击页头「保存日志设置」。

<Callout type="info" title="提示">
- 「记录配额使用量」只控制消费日志：不会停止错误、充值、系统或退款日志，不影响审计日志，也不会关闭服务器文本日志、Midjourney 任务表或异步任务表。
- 错误日志本身只在环境变量 `ERROR_LOG_ENABLED` 为 `true` 时写入（默认 `false`，本页没有对应设置）。
</Callout>

**日志设置配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 所属区域 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- | --- |
| 记录配额使用量 | 日志记录 | 是否创建逐请求的消费日志，包括普通 Relay 和异步任务结算产生的消费记录。界面说明为「跟踪每个请求的消耗，以支持使用情况分析。保持开启会增加数据库写入。」 | 开关；关闭后使用日志、消费统计、数据看板统计和依赖这些记录的分析将缺少新数据。 | 开启 |
| 允许用户导出日志 | 日志查询与导出 | 用户可以在使用日志页面下载自己的日志。管理员始终可以导出。 | 开关；关闭后普通用户的导出请求会被拒绝。 | 开启 |
| 日志最长时间范围（天） | 日志查询与导出 | 用户在日志和数据看板中一次最多能查看的时间范围，也是每次导出的最长时间范围。未指定开始时间时按该范围回溯，超出时报错。每次导出都受此限制，管理员查询日志不受限。 | 整数，最小 `1`。 | `365` |
| 已结束任务保留天数 | 系统任务记录 | 界面说明为「超过这个天数的已结束系统任务每天自动删除。」。每种类型最新的一条保留，由 Master 实例执行，规则见<a href="/zh/docs/guide/feature-guide/admin/system-info#任务执行与保留" target="_blank" rel="noopener noreferrer">系统信息</a>。 | 整数，最小 `1`。 | `30` |

</div>

**清理历史日志：**

界面说明为「移除所选时间戳之前创建的所有日志条目。」。清理作用于执行节点连接的日志库：设置环境变量 `LOG_SQL_DSN` 时为独立日志库，否则为主数据库。

**清理日志操作流程：**
1. 先归档必要数据。
2. 在日期与时间控件中选择截止时间（默认 30 天前），或使用「24 小时前」「7 天前」「30 天前」快捷项。
3. 点击「清理日志」。
4. 在确认框「确认日志清理」中点击「删除日志」，提示「日志清理任务已启动。」，系统创建「日志清理」系统任务。

<Callout type="info" title="提示">
- 未选择时间时提示「清除日志前请选择一个时间戳。」。
- 任务等待或运行中时，按钮显示「正在清理...」且不可用；关闭页面不等于取消后台清理，重新打开本页会接回进行中的任务。
- 此操作不会清理 `quota_data` 聚合数据、性能指标、审计日志、绘图与异步任务记录，也不会删除服务器上的日志文件。
- 多个节点共享日志库时，删除会影响共同的日志历史，不能把它当作只清理某一个节点的日志。
- 任务状态见<a href="/zh/docs/guide/feature-guide/admin/system-info#系统任务状态" target="_blank" rel="noopener noreferrer">系统信息</a>。
</Callout>

**清理结果说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 情形 | 界面显示 | 后续操作 |
| --- | --- | --- |
| 进行中 | 「日志清理进度」卡片，显示百分比和「已处理 … / … 条日志。」 | 等待完成，不要重复发起。 |
| 完成 | 「已删除 … 条日志。」或「没有日志条目匹配所选时间。」 | — |
| 失败 | 「清理日志失败」或任务的错误原文 | 查看错误并检查日志库与 Master 实例；已完成的删除不会自动恢复。 |

</div>

**服务器日志管理：**

界面说明为「管理服务器运行日志文件。日志文件会随运行时间不断累积，建议定期清理以释放磁盘空间。」，下方显示「日志目录」「日志文件数」「日志总大小」「时间范围」。日志目录由启动参数 `--log-dir` 指定（默认 `./logs`），未配置时显示「服务器日志功能未启用（未配置日志目录）」。只扫描该目录下名称匹配 `oneapi-*.log` 的文件。

**清理日志文件操作流程：**
1. 在「清理方式」中选择「保留最近 N 个文件」或「保留最近N天」，并填写「保留文件数」或「保留天数」。
2. 点击「清理日志文件」。
3. 在确认框「确认清理日志文件？」中点击「确认清理」，成功提示「已清理 … 个日志文件，释放 …」。

<Callout type="warn" title="注意">
- 数据库日志和服务器日志文件的删除不可恢复。
- 清理前确认审计、争议处理、支付、合规和故障排查所需的留存周期，并完成必要的数据库或日志归档。
</Callout>

**清理规则：**
1. 按数量：按文件名（含时间戳）从新到旧保留最近 N 个文件，删除其余日志文件。
2. 按天数：保留最近 N 天，删除修改时间早于 N 天前的日志文件。
3. 当前活动日志始终跳过；数值小于 1 时提示「请输入有效的数值」。

### 性能

- 运维-性能配置

![性能配置](/assets/guide/feature-guide/system-settings-operations-performance.png)

分区标题为「性能设置」，分为「磁盘缓存设置」「系统性能监控」两组设置和「性能监控」工具栏；两组设置共用页头「保存更改」。

**操作流程：**
1. 根据实例的磁盘空间和请求体大小设置缓存阈值与最大总量；不要把最大缓存值当作已经预留的磁盘空间。
2. 设置资源保护阈值，点击页头「保存更改」；按每个维度的单位和范围填写，不把 CPU 校验范围套用到内存或磁盘。
3. 先使用「刷新统计」观察用量，再按需要单独执行「清理不活跃缓存」「重置统计」或「执行 GC」。
4. 多实例部署要分别检查目标节点。缓存清理不可恢复，重置命中次数也不能代替释放缓存或清理日志。

<Callout type="info" title="提示">
- 资源保护使用周期性快照，不是排队或自动扩容系统。启用后通常每 5 秒更新一次。
- 资源保护作用于 Playground、OpenAI 兼容接口（含视频生成）、Gemini、Midjourney 和任务插件等 Relay 请求，不影响登录、普通管理接口或全部后台任务。
</Callout>

**性能监控操作说明：**

页面显示处理该请求的节点上的磁盘／内存缓存用量和命中次数、活动缓存数量、缓存目录文件、磁盘空间、Go 内存以及 Goroutine 数量，并提供以下操作：

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 操作 | 位置 | 说明 |
| --- | --- | --- |
| 刷新统计 | 「性能监控」标题右侧 | 重新获取处理该请求的节点的统计信息。 |
| 清理不活跃缓存 | 「性能监控」标题右侧 | 先弹出确认框「确认清理不活跃的磁盘缓存？」，说明「这将删除超过 10 分钟未使用的临时缓存文件」，点击「确认」后删除缓存目录中修改时间超过 10 分钟的普通文件，提示「磁盘缓存已清理」。实现只按文件修改时间判断，没有额外核对文件是否仍被请求引用；高峰期或存在长时间请求时应谨慎执行。 |
| 重置统计 | 「性能监控」标题右侧 | 点击后立即执行，没有确认框，提示「统计已重置」。只清零磁盘和内存缓存命中次数，不清空活动缓存、当前用量或目录文件。 |

这些统计和操作只作用于处理该请求的节点，不会自动遍历其他节点。
</Callout>

**磁盘缓存设置：**

启用后，达到阈值且未超过当前缓存容量边界的大请求体或文件数据会临时存到磁盘，以减少内存占用；不满足条件时继续使用内存。

**磁盘缓存设置配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |

**系统性能监控：**

系统性能监控默认开启。后台约每 5 秒采集 CPU、内存和缓存目录所在磁盘的使用率；CPU 和内存优先按容器 cgroup 配额计算，取不到时使用宿主机数值。当某个阈值大于 `0`，且连续 3 次采样（约 15 秒）的整数使用率都严格高于阈值时，新 Relay 请求会被拒绝并返回 HTTP `503`；任一次采样回落即恢复。关闭监控或调高阈值后立即放行，采样超过 30 秒未更新时也不拒绝。

| --- | --- | --- | --- |

| 磁盘阈值 (%) | 缓存目录所在磁盘的使用率阈值。 | `0–100`；`0` 表示不检查该维度。 | `95` |

</div>

## 注意事项

- **即时运维操作不可撤销**：日志清理、服务器日志清理、缓存清理、重置统计和执行 GC 都没有可撤销的草稿，其中重置统计和执行 GC 没有确认框，见[日志维护](#日志维护)和[性能](#性能)。
- **日志清理影响共享的日志库**：清理作用于执行节点连接的日志库，多个节点共享日志库时影响各节点的日志历史，见[日志维护](#日志维护)。
- **资源保护会拒绝新的 Relay 请求**：阈值被连续采样超过时，新的 Relay 请求返回 HTTP `503`，登录和普通管理接口不受影响；阈值过低会拒绝正常请求，见[性能](#性能)。
- **保存成功不代表连接成功**：保存邮件配置时不测试连接，见[邮件与通知](#邮件与通知)。
- **SMTP 和 Resend 不经 Worker**：两者都由后端直接发出，不经过 Worker 代理或 URL SSRF 校验，见[邮件与通知](#邮件与通知)。
- **余额不足提醒失败不影响扣费**：提醒在结算后异步发送，发送失败只写入系统错误日志，见[邮件与通知](#邮件与通知)。

- 站点「余额不足提醒」开关未开启。
- 用户关闭了个人提醒。
- 个人阈值或通知方式与预期不符。
- 所选邮件发送方式（SMTP 或 Resend）、Webhook、Bark、Gotify、Worker（含「允许 HTTP 图像请求」）或 SSRF 存在问题。

**处理方法**：
1. 查看服务端错误日志。
</Accordion>

<Accordion title="模型性能指标没有立即出现">
**说明**：查询时仅合并数据库中已刷库的数据和处理本次查询的节点的内存聚合桶。多实例部署时，其他节点的样本需等其刷库后才可见。模型广场的数据还会在页面缓存约 1 分钟。

**可能原因**：
- 总开关未开启。
- 模型名、分组（仅统计分组倍率中存在的分组和 `auto`）、桶时间或保留设置与预期不符。
</Accordion>

<Accordion title="保存后仍无法发信">
**说明**：页面不测试连接。

**可能原因**：
- 「邮件发送方式」选的不是已配置的方式。系统不会改用另一种。
- SMTP：主机、端口、安全模式、证书、账号、Token、发件地址（仅可填纯邮箱）或服务商限制存在问题。端口 `465` 还会触发隐式 TLS 行为。
- Resend：发件域名未验证，或 API 密钥无效。具体拒绝原因见服务端日志。
</Accordion>

<Accordion title="Worker 已配置但渠道请求仍直连上游">
**说明**：Worker 仅用于明确接入的下载和通知链路，不是模型渠道的通用网络代理。
</Accordion>

<Accordion title="清理数据库日志后看板历史数据仍存在">
**说明**：日志任务仅删除 `logs` 表，不会删除 `quota_data` 聚合、性能指标或任务记录。
</Accordion>

<Accordion title="日志清理一直等待或只完成了一部分">
**说明**：任务失败不会回滚已删除的数据。

**可能原因**：Master 实例的运行器或日志库连接存在问题。

**处理方法**：
1. 查看任务错误。
2. 重新提交前，再次确认截止时间。
</Accordion>

<Accordion title="清理服务器日志后仍保留一个旧文件">
**说明**：当前活动日志始终跳过。按数量清理还会保留指定的最新文件数。
</Accordion>

<Accordion title="磁盘缓存达到上限后请求失败了吗">
**说明**：系统通常改用内存。部分流式读取链路在磁盘创建失败且 Reader 已消费时可能直接报错。上限也不是磁盘配额保证。
</Accordion>

<Accordion title="资源使用率达到阈值但请求没有被拒绝">
**说明**：比较条件是严格高于阈值，使用采样的整数值，且需连续 3 次采样（约 15 秒）都超过阈值。采样超过 30 秒未更新时不拒绝。阈值为 `0` 时该维度不检查。在容器中，CPU 和内存按 cgroup 配额计算，可能与宿主机监控数值不同。
</Accordion>

<Accordion title="检查更新提示的版本不符合预期">
**说明**：页面按版本号比较，预发布版（如 `rc`）也参与比较，无法解析的标签会被忽略。当前版本为开发构建时无法比较。

**处理方法**：
1. 打开 Release，人工核对版本、分支和升级路径。
</Accordion>

</Accordions>
