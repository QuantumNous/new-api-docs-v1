- 「系统设置」的地址为 `/system-settings`，仅 Root 可访问。
- 本页说明系统设置的各设置域通用的保存、生效、敏感配置和变更验证规则；具体字段说明见对应设置域的文档。

## 入口与权限

仅Root 可以从以下三处进入系统设置，都会打开「站点与品牌 › 系统信息」：

1. 侧边栏「管理员」分组末尾的「系统设置」。
2. 右上角头像菜单中的「系统设置」。
3. 顶栏「搜索」或快捷键 ⌘/Ctrl+K 打开的命令面板，其中列出的页面与侧边栏相同。

逐项保存：只提交有改动的字段，每个字段单独提交，各提示一次「设置更新成功」；某个字段失败时，其后的字段不再提交，已提交的字段不会回滚。没有改动时，部分分区提示「没有需要保存的更改」，部分分区不提示。

<Callout type="info" title="提示">
- 「设置更新成功」「保存成功」等提示只表示服务端已接受这次保存，不代表 OAuth、SMTP、支付网关、Webhook、Worker 等外部服务已经连通。
</Callout>

### 生效范围与多实例同步

1. 设置以键值形式保存在主数据库中。处理保存请求的节点写入数据库后立即更新内存中的值，不需要重启。
2. 其他节点每隔 `SYNC_FREQUENCY` 秒（默认 60 秒）从数据库重新载入全部设置，也包括请求策略、模型价格、通行密钥域名等使用专用保存方式写入的设置。各设置域页面把这一过程简称为「随系统设置同步（默认 60 秒）」。
   - 这项同步与是否启用 Redis 无关，前提是所有节点连接同一个主数据库。
   - 同步完成前，各节点读到的值可能不一致。
3. Master 实例和 Worker 实例（`NODE_TYPE`）在保存和同步设置时没有区别，可以在任一节点保存。

以下修改不随同步生效，需要重启：

1. 「身份验证 › 自定义 OAuth」的新增、编辑、删除只在处理该请求的节点生效；其他节点需要重启后才会加载。详见<a href="/zh/docs/guide/feature-guide/system-settings/settings-auth" target="_blank" rel="noopener noreferrer">身份验证配置</a>。
2. 「请求策略 › 会话与重试」中的「最多缓存会话数」修改后需要重启（使用 Redis 时不涉及），详见<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#保存与生效" target="_blank" rel="noopener noreferrer">请求策略配置</a>。
3. 部署环境变量只在启动时读取，修改后需要重启，界面中也不显示，例如 `SYNC_FREQUENCY`、`NODE_TYPE` 和 `GLOBAL_API_RATE_LIMIT` 等全局限流变量。
   - 少数环境变量会覆盖界面中的值，例如 `CHANNEL_TEST_FREQUENCY`、`CHANNEL_TEST_ENABLED`，详见<a href="/zh/docs/guide/feature-guide/system-settings/settings-request-policies#渠道健康" target="_blank" rel="noopener noreferrer">渠道健康</a>。

### 前端显示与缓存

1. 登录方式、系统名称、徽标、页脚、顶部导航、侧边栏模块、额度显示方式和控制台面板等界面内容来自站点状态。服务端每次按处理该请求的节点内存中的设置返回；浏览器读取后会缓存，5 分钟内不重新读取，刷新页面后重新读取。通知中心的系统公告另有一份同样的缓存。
2. 保存后，执行保存的浏览器只自动更新部分显示类设置，如顶部导航、侧边栏模块、额度与货币显示、服务器地址、通行密钥和自定义 OAuth；其余设置，以及其他用户已打开的页面，刷新页面后才显示新值。
3. 服务端按保存后的设置处理请求，不依赖浏览器缓存；已打开的页面可能仍显示旧的入口或表单，刷新后恢复一致。

## 敏感配置与审计记录

**敏感配置**

- 配置键名以 `Token`、`Secret`、`Key`、`secret` 或 `api_key` 结尾的设置（主要是各类密钥、令牌和凭证字段）不会通过设置读取接口返回：整项省略，而不是打码显示，因此界面中这些字段始终为空。
- 这类字段通常留空表示保留已保存的值，只有输入新值才会提交；部分字段下方提示「留空以保留现有密钥」「留空以保留现有凭证」或「除非正在轮换密钥，否则留空」。例外：「运维 › Worker 代理」中的「Worker URL」为空时保存，「Worker 访问密钥」会被一并清空。自定义 OAuth 的客户端密钥同样不回显，编辑时留空即保留。
- 设置值在数据库中以明文保存，应同等保护数据库和备份。

**审计记录**

- 逐项保存成功时，每个字段记录一条审计日志，显示为「修改系统设置」加配置键名，只记录配置键名，不记录值。
- 使用专用保存方式的设置记录方式不同：请求策略只记录请求方法和路径；模型定价记录改动的模型名；通行密钥域名（含「系统信息」中的「服务器地址」）记录被移除的域名和受影响的凭证数量；自定义 OAuth 只记录新增、编辑或删除的操作类型。
- 保存失败的请求也会留下记录，但不包含配置键名。
- <a href="/zh/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">审计日志</a>位于侧边栏「常规 › 审计日志」。Root 的操作记录只有 Root 能看到。
- 审计日志不保存旧值，不能用来恢复配置，也不能代替外部的密钥管理和变更记录。

<Callout type="warn" title="注意保管密钥">
不要在截图、工单或普通日志中记录客户端密钥、SMTP Token、支付密钥等敏感值。读取接口不回显明文，不代表浏览器、代理、数据库备份或运维环境可以不保护凭证。
</Callout>

## 变更前记录与验证

系统设置没有配置快照、历史版本对比或一键回滚。生产环境修改前应自行记录原值，并准备按原配置逐项恢复。建议至少记录：

- 修改的设置域、分区和字段；
- 修改前的非敏感值，以及敏感凭证在密钥管理系统中的版本；
- 预期影响的页面、接口、角色和外部服务；
- 测试步骤、通过标准和恢复条件；
- 多实例环境需要等待的同步时间，以及需要重启的项。

保存后按以下步骤验证：

1. 确认提示。逐项保存时，每个修改的字段都应有一条「设置更新成功」；出现失败提示时，失败的字段及其后的字段都没有保存。
2. 刷新页面，核对非敏感字段；敏感字段始终为空，无法通过刷新核对。重要修改在一个同步周期后再刷新复核。
3. 到真正受影响的入口验证，例如登录、发信、支付沙箱、回调和模型请求。
4. 多实例部署时，等待一个同步周期后在其他节点验证；修改自定义 OAuth 后，需要先重启其他节点再验证。
5. 涉及身份验证、支付、计费、请求策略、SSRF 或对外回调的修改，先在测试实例或维护窗口验证。

## 注意事项

- **逐项保存不回滚**：一次保存多个字段时，前面的字段已写入；某个字段失败后，其后的字段不再提交，见[保存方式](#保存方式)。
- **多节点有同步延迟，个别项需要重启**：其他节点随系统设置同步（默认 60 秒）；自定义 OAuth、「最多缓存会话数」和环境变量修改后需要重启，见[生效范围与多实例同步](#生效范围与多实例同步)。
- **显示类设置需刷新页面**：浏览器会缓存站点状态，保存后其他用户最迟刷新页面后显示新值，见[前端显示与缓存](#前端显示与缓存)。
- **环境变量可能覆盖界面值**：如 `CHANNEL_TEST_FREQUENCY`、`CHANNEL_TEST_ENABLED`，此时修改界面中的值不一定生效。
- **密钥字段不回显**：留空表示保留已保存的值；「Worker URL」为空时保存会一并清空「Worker 访问密钥」，见[敏感配置与审计记录](#敏感配置与审计记录)。
- **没有历史版本**：审计日志不保存旧值，不能用来恢复配置；修改前请自行记录原值，见[变更前记录与验证](#变更前记录与验证)。

**说明**：非 Root 账号看不到该入口。

**可能原因**：Root 也看不到时，「站点与品牌 › 侧边栏模块」中的「管理员区域」或「系统设置」开关未开启。

**可能原因**：系统设置仅 Root 可访问。

**处理方法**：
1. 请联系 Root 修改。
</Accordion>

<Accordion title="一次保存弹出多条「设置更新成功」">
**提示原文**：「设置更新成功」（英文 Setting updated successfully）

**说明**：逐项保存时，每个修改的字段各提示一次。
</Accordion>

<Accordion title="保存后只有部分字段生效">
**可能原因**：某个字段失败后，后续字段不会提交。

**处理方法**：
1. 根据失败提示修正后再次保存。
2. 刷新页面，核对各字段。
</Accordion>

<Accordion title="点击保存没有任何提示">
**可能原因**：该分区未检测到修改。部分分区在无改动时不做提示。

**处理方法**：
1. 确认已修改字段。
</Accordion>

<Accordion title="多个节点表现暂时不一致">
**可能原因**：
- 各节点未连接同一个主数据库。
- `SYNC_FREQUENCY` 的设置与预期不符。

**处理方法**：
1. 等待一个同步周期（默认 60 秒）。服务端日志每个周期输出一行 `syncing options from database`（设置 `DEFAULT_LANGUAGE=zh-CN` 时为「正在从数据库同步配置项」）。
2. 修改自定义 OAuth 后，重启其他节点。
</Accordion>

<Accordion title="密钥字段为空">
**说明**：敏感配置不回显是设计行为；留空即保留原值。

**处理方法**：
1. 更换时输入新值。
</Accordion>

<Accordion title="外部集成保存后仍然失败">
**说明**：保存时不测试连通性。

**可能原因**：公网地址、回调、DNS、证书、网络或凭证权限存在问题。

**处理方法**：
1. 检查第三方服务日志。
</Accordion>

<Accordion title="需要恢复旧配置">
**说明**：系统设置无历史版本恢复功能。

**处理方法**：
1. 按修改前自行记录的原值逐项填回并保存。
</Accordion>
