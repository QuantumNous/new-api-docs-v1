计费与支付配置位于 `/system-settings/billing`，仅 Root 可访问。

## 计费与支付配置简介

该工作区包含「额度设置」、「货币与展示」、「模型定价」、「分组定价」、「支付网关」、「签到奖励」六个分区。用于配置模型和工具定价、分组倍率、邀请奖励与额度预扣、货币汇率及显示、充值规则与支付网关，以及签到奖励。

| 分区 | 入口 | 主要用途 |
| --- | --- | --- |
| [额度设置](#额度设置) | `/system-settings/billing/quota` | 新用户配额、预扣、邀请奖励及充值链接。 |
| [货币与展示](#货币与展示) | `/system-settings/billing/currency` | 金额显示模式、汇率与 Token 统计。 |
| [模型定价](#模型定价) | `/system-settings/billing/model-pricing` | 模型价格、表达式、工具价格及上游同步。 |
| [分组定价](#分组定价) | `/system-settings/billing/group-pricing` | 调用与充值倍率、用户可用分组及 Auto 顺序。 |
| [支付网关](#支付网关) | `/system-settings/billing/payment` | 合规确认、充值规则及各网关凭证和回调。 |
| [签到奖励](#签到奖励) | `/system-settings/billing/checkin` | 每日签到开关和奖励范围。 |

配置时先区分四种量：
1. **内部额度 配额点数** 是余额和扣费的计量单位；
2. **显示金额**是 配额点数 格式化后的结果；
3. **模型费用**由请求用量和价格规则计算；
4. **网关实收**由各支付渠道的订单决定。

<Callout type="warn">
  计费与支付配置会影响扣费、余额和支付入账。修改前后的通用记录与验证步骤见<a href="/zh/docs/guide/feature-guide/system-settings/system-setting#变更前记录与验证" target="_blank" rel="noopener noreferrer">变更前记录与验证</a>，密钥类字段的处理见<a href="/zh/docs/guide/feature-guide/system-settings/system-setting#敏感配置与审计记录" target="_blank" rel="noopener noreferrer">敏感配置与审计记录</a>。本域另需用测试用户核对价格，并在支付服务商允许的测试环境中验证。
</Callout>

## 配置分区

### 额度设置

配置新用户初始配额、邀请双方奖励、钱包免预扣门槛、输入预扣倍率和免费模型预扣开关，以及充值链接。

- 计费与支付-额度设置

![额度设置](/assets/guide/feature-guide/system-settings-billing-and-payments-quota-settings.png)

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 新用户配额 | 默认 `0`；填写非负整数 配额点数 | 授予新用户的初始配额，不追补已有用户。 |
| 钱包免预扣门槛（美元） | 默认 `10`；填写不小于 `0` 的数，可为小数 | 用户钱包余额和有限额 API 令牌的余额都超过该金额时，跳过预扣，按实际用量结算；设为 `0` 则始终预扣。订阅和异步任务始终预扣。 |
| 输入预扣倍率 | 默认 `1`；须大于 `0`，可为小数 | 按预计输入费用乘以该倍率预扣，不预估输出 Token；最终按实际用量结算。按次计费和任务计费不受影响。 |
| 邀请者奖励 | 默认 `0`；填写非负整数 配额点数 | 符合条件的邀请注册后，授予邀请人的配额。奖励先计入邀请人的邀请额度，邀请人在钱包中点击「转移到余额」后才进入余额。 |
| 受邀者奖励 | 默认 `0`；填写非负整数 配额点数 | 授予被邀请人的配额。 |
| 免费模型预消耗 | 默认开启 | 启用后，零成本模型也会在最终结算前预先消耗配额。 |
| 充值链接 | 默认空 | 供用户购买配额的外部链接，不会自动接入该网站的支付回调。 |

</div>

**操作流程**

1. 核对额度单位。
2. 设置新用户配额、钱包免预扣门槛、输入预扣倍率和奖励；配置正数邀请奖励前，先到支付网关确认合规声明。
3. 填写充值链接并保存，刷新检查非敏感字段。
4. 用新建测试用户验证初始额度；用邀请注册验证双方奖励，用请求日志核对预扣与最终费用。

<Callout type="info">
配置邀请奖励不为0时，需要先在「系统设置」→「计费与支付」→「支付网关」设置中确认合规条款。
</Callout>

### 货币与展示

配置额度的显示模式、货币符号与换算汇率，以及是否展示 Token 用量统计。

- 计费与支付-货币与展示

![货币与展示](/assets/guide/feature-guide/system-settings-billing-and-payments-currency-and-display.png)

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 显示模式 | 默认 `USD` ；可选`USD`、`元`、`自定义货币`| 选择如何向用户展示配额值。 |
| 美元汇率 | 后端默认 `7.3`；表单最小 `0.0001` | 美元与您的支付网关货币之间的实际汇率。显示模式为「元」时，该字段名称显示为「人民币兑美元汇率」。 |
| 自定义货币符号 | 默认 `¤`；仅自定义货币 时必填，最多 8 字符 | 显示价格时使用的前缀；仅「自定义货币」模式显示。 |
| 每 USD 单位数 | 默认 `1`；仅自定义货币 时必填，最小 `0.0001` | 从美元到您的自定义货币的转换率，表示 `1 USD = X` 个自定义货币单位。 |
| 显示 Token 统计信息 | 默认开启 | 在用户界面中显示令牌使用统计信息。 |

</div>

**操作流程**

1. 选择货币显示模式 USD、元 或 自定义货币；使用 自定义货币 时需填写自定义货币符号以及每 USD 单位数。
2. 填写相关配置信息，核对 Token 统计信息开关，保存。
3. 在钱包、价格页和日志中对照同一笔额度，确认货币符号、小数和换算值。

<Callout type="info">
内部 `500000 配额点数` 在默认基准下为 `$1`。
</Callout>

### 模型定价

模型定价配置页分为「模型价格」「未设置价格模型」「工具价格」「上游价格同步」四个标签。配置模型计费模式、各类用量价格与计费表达式、工具调用价格，并支持补全未定价模型和同步上游价格。

「模型价格」标签右上角另有三个控件，作用于全部模型价格：

- 「暴露倍率接口」：默认关闭。开启后，任何人都可以通过 `/api/ratio_config` 读取本站的模型价格配置（含计费表达式），供其他站点在「上游价格同步」中选用；关闭时该接口返回 403。**已知问题（当前版本）**：开关旁「?」提示中写作 `/api/ratio`，实际路径以 `/api/ratio_config` 为准。
- 「重置价格」：确认后把所有模型的价格恢复为系统默认值，已保存的自定义价格（包括计费表达式）会被清除。
- 「切换到 JSON」：以 JSON 查看和编辑旧版价格字段，如「模型固定定价」「模型倍率」「补全倍率」。

<Callout type="warn">
配置或编辑模型价格时，计费模式推荐使用计费表达式；「按 Token」、「按次」为已弃用的计费模式，但仍可在对应界面将旧数据编辑转换为计费表达式。
</Callout>

列表用于搜索、检查和维护模型价格，不会自动给渠道增加模型。价格配置应与请求使用的模型标识和实际计费路径一致。

**添加或修改流程**

- 计费与支付-模型定价-模型价格-添加模型定价

![添加模型定价](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-model-prices-add-model-pricing.png)

- 计费与支付-模型定价-模型价格-编辑模型定价

![编辑模型定价](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-model-prices-edit-model-pricing.png)

1. 搜索模型并编辑，或点击「添加模型」。新建时填写准确模型名，编辑时模型名不可直接更改。
2. 选择定价货币和模式，设置价格或表达式（编辑器用法见<a href="/zh/docs/guide/feature-guide/admin/billing-expression" target="_blank" rel="noopener noreferrer">计费表达式</a>）。「预设模板」只是起点，先核对当前供应商价格和缓存规则。
3. 在「Token 估算器」中输入已知用量检查费用；含请求条件时，再用「请求模拟」填写请求体、请求头和时间。
4. 点击保存模型价格，并确认列表及刷新后的价格符合预期。
5. 用测试请求在日志中核对真实用量、分组倍率和最终费用。

- 基础字段

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 模型名称 | 新建必填 | API 请求中使用的确切模型标识符。 |
| 定价货币 | 默认「美元（USD）」；显示模式为「元」或「自定义货币」时可选「站点货币（…）」 | 系统底层统一使用美元计价。选择站点货币是为了方便输入和换算，金额会按站点汇率转换为美元。切换货币不会改变实际价格；原始计费表达式始终使用美元。 |
| 计费模式 | 「计费表达式」「按 Token（已弃用）」「按次（已弃用）」 | 推荐使用计费表达式；「按 Token」、「按次」为已弃用的计费模式，但仍可在对应界面将旧数据编辑转换为计费表达式。选择已弃用模式时，可点击「转换为计费表达式」生成表达式草稿，保存后生效。 |

</div>

编辑器模式、预设模板、阶梯与计费分支、Token 与媒体价格、请求规则、Token 估算器与请求模拟，以及计费表达式的变量、函数和语法，见<a href="/zh/docs/guide/feature-guide/admin/billing-expression" target="_blank" rel="noopener noreferrer">计费表达式</a>。

![未设置价格模型](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-models-without-prices.png)

1. 筛选未定价模型并进入价格编辑。

4. 刷新列表，发起测试请求确认。

#### 工具价格

统一配置搜索、文件检索、图像生成等工具的调用单价，用于计算工具调用附加费用。

- 计费与支付-模型定价-工具价格

![工具价格](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-tool-prices.png)

- 字段或操作说明

| 字段或操作      | 定义                                         | 填写要求或使用说明                                           |
| --------------- | -------------------------------------------- | ------------------------------------------------------------ |
| 工具标识        | 指定价格对应的工具，以及可选的模型匹配范围。 | 通用格式为 `工具名`；模型专属格式为 `工具名:模型前缀*`，例如 `web_search_preview:gpt-4o*`。 |
| 价格（$/1K 次） | 每 1,000 次工具调用的美元单价。              | 填写大于或等于 `0` 的数字，支持小数。例如 `10` 表示每千次 10 美元，单次基础费用为 0.01 美元。 |
| 添加            | 新增一条工具价格规则。                       | 新行的工具标识为空、价格为 `0`。 |
| 删除图标        | 从当前编辑内容中移除该行。                   | 保存后移除对应自定义配置；内置规则缺失时会使用内置兜底价格。 |
| 恢复默认        | 将当前编辑内容替换为内置默认价格列表。       | 会覆盖当前草稿，包括自定义条目。 |
| 切换到 JSON     | 以 JSON 对象形式查看或批量编辑价格。         | 对象键为工具标识，值为非负数字，例如 `{"web_search":10}`。 |
| 切换到可视化    | 返回表格编辑模式。                           | 建议先修复 JSON 错误，再切换模式。                           |
| 复制            | 复制 JSON 编辑区的内容。                     | 在 JSON 模式显示，可用于留存修改前的配置。                   |
| 保存工具价格    | 提交当前完整价格配置。                       | 无效价格或 JSON 错误会阻止保存；提交后应确认成功提示，并重新打开页面核对。 |

- 操作流程

1. 进入配置页面；使用超级管理员账号打开“模型定价”，选择“工具价格”。
2. 选择配置范围；全部模型使用通用工具标识；特定模型系列使用 `工具名:模型前缀*`。
3. 添加或修改规则；修改已有行，或点击“添加”填写工具标识和价格；按美元/千次填写。
4. 检查匹配与金额；按目标模型名称确认最长前缀规则，并换算单次基础费用。
5. 保存配置；点击“保存工具价格”，确认保存成功。
6. 复查配置与计费；重新打开页面核对保存结果，再用受控请求触发目标工具，检查消费记录；核对工具调用次数、单价、分组倍率和最终费用。

<Callout type="info">
单项工具附加费用 = 价格（美元/千次） × 计费调用次数 ÷ 1000 × 分组倍率
总工具附加费用 = 各项工具附加费用之和
</Callout>

#### 上游价格同步

从预设或上游渠道拉取模型价格，与本地配置对比后，按模型选择价格来源，并通过预览确认批量更新本地计费配置。

- 计费与支付-模型定价-上游价格同步

![上游价格同步](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-upstream-price-sync.png)

- 字段说明

| 字段 | 定义 | 默认或限制 |
| --- | --- | --- |
| 模型 | 本行价格对应的模型名称。 | 名称可能包含版本后缀，应以完整名称为准。 |
| 当前价格 | 本地用于本次比较的模型计费配置。 | 取自本次加载的本地配置。 |
| 价格来源列 | 展示该来源提供的模型价格，例如“官方定价预设”。 | 由本次拉取结果生成。 |

- 控件操作说明

| 控件操作 | 操作说明 | 限制 |
| --- | --- | --- |
| 选择价格来源 | 点击打开价格来源选择窗口，可选择多个来源及同步端点。 | 只可选择已有的价格来源。 |
| 搜索模型名称 | 输入模型名称或部分关键词。 | 不区分大小写进行包含匹配。 |
| 类型下拉框 | 选择「所有类型」「表达式计费」「按 Token」或「按次」。 | 按来源提供的计费方式筛选。 |
| 批量设置已选价格 | 对已勾选的价格统一选择「保持来源价格」「除以汇率」或「乘以汇率」；单个价格旁的 ⇆ 按钮可单独调整，底部的 × / ÷ 按钮作用于全部已选模型。 | 需要有效的站点货币汇率（显示模式为「元」或「自定义货币」），否则提示「请先设置有效的站点货币汇率。」 |
| 显示价格相同的模型 | 勾选后，与本地价格相同的模型也会列出。 | 默认不勾选，只列出有差异的模型。 |

- 计费与支付-模型定价-上游价格同步-选择价格来源

![选择价格来源](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-upstream-price-sync-select-price-source.png)

- 字段说明

| 字段 | 定义 | 默认或限制 |
| --- | --- | --- |
| 名称 | 预设名称或本地渠道名称。 | - |
| API 地址 | 价格来源的基础地址。 | 使用相对同步路径时与该地址拼接；使用完整 URL 时直接请求该 URL。 |
| 状态 | 渠道状态。 | 已启用、已禁用、自动禁用 |
| 同步端点 | 指定读取价格的接口类型或地址。 | `pricing`、`ratio_config`、`OpenRouter`、`custom`。 |

- 控件操作说明

| 控件操作 | 操作说明 | 限制 |
| --- | --- | --- |
| 按名称或 URL 搜索 | 输入关键词筛选匹配的预设或渠道。 | 匹配来源显示名称和 API 地址，不区分大小写。 |
| 行勾选框 | 勾选参与本次价格比较的来源，支持多选。 | 选择比较来源。 |
| 同步端点下拉框 | 根据来源接口选择 `pricing`、`ratio_config`、`OpenRouter` 或 `custom`。 | 来源必须支持所选接口。|
| 自定义端点输入框 | 选择 `custom` 后填写相对路径或完整 URL。相对路径与 API 地址拼接，完整 URL 直接使用。 | 仅在 `custom` 模式显示；完整地址需使用 HTTP/HTTPS。 |
| 确认选择 | 使用选中的来源拉取价格并与本地比较。 | 至少选择一个来源，否则提示「请选择至少一个渠道」。 |

- 计费与支付-模型定价-上游价格同步-预览价格变更

![预览价格变更](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-upstream-price-sync-apply-sync.png)

- 字段说明

| 字段 | 定义 |
| --- | --- |

9. 检查同步结果；确认成功提示，在“模型价格”中复查配置，必要时重新拉取比较。

### 支付网关

统一配置在线充值的支付渠道、充值金额选项、优惠规则和支付通知，使用户能够通过已接入的支付平台付款并获得账户额度。支持接入EPay、Stripe、Creem、Waffo Pancake、Waffo等支付网关。

#### 支付合规确认

由超级管理员确认运营合规声明，解除支付、兑换码、订阅套餐及邀请奖励相关功能的合规限制。确认内容涉及上游授权、服务使用与商业化范围、适用的运营义务及责任，完整条款以确认弹窗为准。

- **操作流程**

1. 使用超级管理员账号进入「计费与支付」 → 「支付网关」。
2. 点击「确认合规」，阅读条款并按提示填写各段确认文字。
3. 点击「确认并启用」，等待提交成功。

- Stripe：已填写「API 秘钥」「Webhook 密钥」「价格 ID」。
- Creem：已填写「API 密钥」并至少添加一个产品；处理支付通知还需要「Webhook 密钥」。
- Waffo Pancake：已填写「商户 ID」「API 私钥」，并保存了店铺和产品绑定。
- Waffo：已开启「启用 Waffo」，并填写当前环境（生产或沙盒）的 API 密钥、RSA 私钥和 Waffo 公钥。
</Callout>

#### 常规设置

常规设置为对所有支付网关的共享配置，包括以下四个配置区域：
1. **通用设置**；设置每美元余额（Epay）的收费金额，用户可以充值的最小美元金额。
2. **付款方式**；配置钱包中的支付按钮，并指定每个按钮使用的支付流程。
3. **充值金额选项**；提供用户可以直接选择的常用充值金额。
4. **金额折扣**；为指定充值金额配置折扣率。

- 计费与支付-支付网关-添加折扣等级

![添加折扣等级](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-general-amount-discounts-add-discount-tier.png)

- **字段说明**

| 字段 | 用途说明 | 填写要求 | 默认值 / 示例 |
| --- | --- | --- | --- |
| 价格（本地货币/美元） | 每美元余额（Epay）的收费金额。 | ≥ `0`；按服务商收款币种和定价填写。 | 默认：`7.3`。 |

| 图标 | 为按钮显示对应的图标。 | 输入 react-icons 组件名。无法解析的名称不会显示图标。 | 示例：`SiAlipay`、`SiWechat`。 |

<Callout type="info">
- 金额计算说明：<br/>
`应付金额 = 充值金额数量 × 价格（本地货币/美元） × 用户分组充值倍率 × 匹配的折扣率`<br/>

</Callout>

3. 将期望到账余额换算为配额点数，填写“额度”。
4. 核对本地售价、币种与 Creem 产品一致，统一保存后到钱包选择产品测试。

#### Waffo Pancake

绑定 Pancake 商户、店铺和充值产品，按用户充值金额创建结账会话。

- 计费与支付-支付网关-Waffo Pancake

![Waffo Pancake MoR](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-waffo-pancake-mor.png)

| 字段 | 用途说明 | 填写要求 |
| --- | --- | --- |
| 商户 ID | 标识当前 Pancake 商户。 | 接入时填写平台提供的商户 ID，格式示例：`MER_...`。 |
| API 私钥 | 授权访问 Pancake 商户接口。 | 首次接入时填写目标环境对应的私钥；已有私钥留空保留。 |
| 绑定 Pancake 店铺 | 指定 New API 使用的店铺。 | 有效凭据加载目录后选择；切换店铺会清除当前产品选择。 |
| 绑定 Pancake 产品 | 指定钱包充值使用的产品。 | 选择店铺下已激活的产品；同一产品可按本次充值金额结账，无需每种金额各建一个产品。 |
| 支付返回地址 | 创建新产品时设置支付成功后的跳转地址。 | 建议在新建前填写，如 `https://api.example.com/wallet`；留空创建时会要求确认。 |

- **操作流程**

1. 在 Pancake 配置对应环境的Webhook通知地址：测试使用 `<ServerAddress>/api/waffo-pancake/webhook/test`，生产使用 `<ServerAddress>/api/waffo-pancake/webhook/prod`。
2. 填写商户 ID 和私钥，等待校验及目录加载。
3. 选择已有店铺和激活产品；如需新建，先填写返回地址，再点击新建按钮。
4. 启用后钱包会自动显示 Waffo Pancake 支付方式；如需自定义显示名称、图标或最低充值，可在「常规 › 付款方式」中添加处理标识为 `waffo_pancake` 的条目。
5. 核对产品绑定，统一保存后发起测试充值

<Callout type="info">
**Waffo Pancake MoR**<br/>
- 无需注册公司即可开始全球收款。面向独立开发者、OPC 个体经营者和初创团队构建。
- Waffo Pancake 作为你的登记商户（Merchant of Record），承担全球收款相关的合规负担，包括消费税、开票、订阅管理、退款和拒付。
- 个人开发者可以快速上线，专注产品而不是合规事务。几分钟即可完成入驻，从一个提示词到完整集成。
</Callout>

#### Waffo

接入 Waffo 聚合支付，管理环境凭据、收款参数和用户可选支付方式。

- 计费与支付-支付网关-Waffo

![Waffo 网关](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-waffo.png)

| 字段 | 用途说明 | 填写要求 | 默认值 / 示例 |
| --- | --- | --- | --- |

| 沙盒模式 | 选择使用哪一组环境凭据。 | 开启使用沙盒，关闭使用生产；凭据需成套匹配。 | 默认：关闭。 |
| API 密钥（生产 / 沙盒） | 授权调用对应环境的接口。 | 首次使用该环境时填写；已有值留空保留。 | 默认：空。 |

| 最低充值数量 | 设置允许发起充值的最小数量。 | 页面最小值为 `1`；按整数设置。 | 默认：`1`。 |

| 支付返回地址 | 指定支付后浏览器跳转页面。 | 选填完整页面 URL；留空回退至服务器地址加 `/wallet?show_history=true`。 | 默认：空；示例：`https://api.example.com/wallet`。 |

**Waffo 聚合网关**

#### 金额与入账核对

| 网关 | 配置时重点核对 |
| --- | --- |
| EPay | 本地单价、充值倍率、优惠与服务商实收；到账基于订单充值额度。 |
| Stripe | 本地报价不等于 Stripe Price 实收；分组倍率参与站内入账，优惠码和本地优惠不是同一机制。 |
| Creem | 产品实际价格与站内展示一致；配额点数 直接作为内部额度入账。 |
| Waffo | 环境、实际货币、单价、倍率和通知地址；不要用显示汇率推断网关金额。 |
| Pancake | 钱包 checkout 使用本次 USD 价格：单价默认为 `1` USD（界面无对应输入项），充值倍率和金额折扣同样参与计算；提供方税费及最终应付需在 checkout 核对。 |

### 签到奖励

配置每日签到功能开关及随机奖励额度上下限，用户签到成功后获得相应额度。

- 计费与支付-签到奖励

![签到奖励](/assets/guide/feature-guide/system-settings-billing-and-payments-check-in-rewards.png)

**参数和控件说明**
| 字段 | 定义 |
| ---  | --- |
| 启用签到功能 | 控制站点是否允许用户通过每日签到领取随机额度奖励。 |
| 签到最小额度 | 单次签到奖励的下限，使用系统内部额度单位。 |
| 签到最大额度 | 单次签到奖励的上限，使用系统内部额度单位。 |

- **操作流程**
1. 开启签到功能，填写相应参数。
2. 点击保存签到设置，刷新确认。
3. 用测试用户签到，核对奖励和系统日志。

**注意事项**

- 关闭「启用签到功能」时不显示两个额度输入框，开启后才能填写。
- 最大值大于最小值时，在包含两端的区间内随机发放；否则固定发放最小值。当前表单不会因最小值大于最大值自动报错，保存前自行核对。
- 每日按服务进程的本地日期判断，不按每位用户的浏览器时区判断；多实例应保持时区一致。
- 用户和日期的唯一约束防止同一天重复领取；开启全局 Turnstile 时，签到请求也需通过对应校验。

## 保存后的验证清单

- [ ] 按<a href="/zh/docs/guide/feature-guide/system-settings/system-setting#变更前记录与验证" target="_blank" rel="noopener noreferrer">变更前记录与验证</a>完成通用的提示确认与刷新核对；模型价格遇到版本冲突时，点击「重新加载定价」后再修改。
- [ ] 用已知 Token、缓存、媒体和工具用量验证估算及真实日志；不要把估算器当真实账单。
- [ ] 用不同账户组和令牌组验证实际渠道、分组倍率及 Auto 顺序。
- [ ] 比较同一额度在钱包和日志中的显示，确认未混淆显示汇率与支付单价。
- [ ] 每个网关分别测试下单、实际收费、签名通知、订单状态与到账额度；确认返回页不是唯一成功依据。
- [ ] 测试新用户、邀请注册、邀请额度转移及重复签到，确认奖励进入正确余额。

<Accordion title="保存成功但价格没变？">
**可能原因**：
- 未区分编辑草稿与最终保存。
- 模型名、当前模式、提供方覆盖或请求开始时的价格快照与预期不符。
</Accordion>

<Accordion title="关闭某项价格是否就是免费？">
**说明**：不一定。移除覆盖可能恢复默认；工具价格还可能匹配更具体的前缀。显式零值、未配置和删除是不同状态。
</Accordion>

<Accordion title="公开价格接口为什么访问失败？">
**说明**：该接口当前路径为 `/api/ratio_config`。

**可能原因**：「暴露倍率接口」开关未开启。
</Accordion>

<Accordion title="100 的优惠为什么没有用于 200？">
**说明**：金额优惠按原始金额精确匹配，不是最低阈值规则。
</Accordion>

<Accordion title="Stripe 报价与付款页不一致？">
**可能原因**：
- Stripe Price 的货币、单价或数量与预期不符。
- 未区分本地单价、充值倍率、优惠与 Stripe 优惠码。
</Accordion>

<Accordion title="Creem 产品额度填 1 为什么不是到账 1 美元？">
**说明**：该字段是内部配额点数；默认基准下，系统 1 USD 对应 500000 quota。
</Accordion>

<Accordion title="密钥框为空是否未配置？">
**说明**：不一定。密钥不回显的通用规则见<a href="/zh/docs/guide/feature-guide/system-settings/system-setting#敏感配置与审计记录" target="_blank" rel="noopener noreferrer">敏感配置与审计记录</a>。注意 Waffo 公钥清空并保存会移除原值，不可当成留空保留的私钥。
</Accordion>

<Accordion title="用户不能选择某个组？">
**可能原因**：
- 公共可用列表、特殊规则、账户自身组、倍率配置或令牌限制不允许选择该组。
- 使用 Auto 时未开放 `auto`。
</Accordion>

<Accordion title="Pancake 创建成功为何没有完成配置？">
**说明**：外部资源创建、当前选择和本地绑定保存是三个阶段。

**处理方法**：
1. 核对并保存绑定。
</Accordion>

<Accordion title="签到每天都是最小值？">
**可能原因**：
- 最大值不大于最小值。
- 输入使用的不是配额点数。
</Accordion>

</Accordions>
