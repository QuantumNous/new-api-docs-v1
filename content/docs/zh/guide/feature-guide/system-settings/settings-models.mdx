## 配置分区

本节按左侧导航的顺序介绍五个分区，各分区的保存按钮和生效时机见[保存与生效](#保存与生效)。

### 全局模型配置

- 模型-全局模型配置

![全局模型配置分区](/assets/guide/feature-guide/system-settings-model-global-model-configuration.png)

分区内的字段以分隔线分为三组：请求透传与思考后缀、「ChatCompletions → 响应兼容」（带「预览」标记）、保持连接心跳。

**操作流程：**
1. 按需打开「启用请求透传」。
2. 在「不自动处理思考后缀的模型」中填写需要豁免的模型。
3. 在「策略 JSON」中填写转换策略，可点击「填充示例（指定渠道）」或「填充示例（全部渠道）」。
4. 按需打开「保持连接心跳」，填写「Ping 间隔（秒）」。
5. 点击页头「保存更改」。

<Callout type="warn" title="注意">
- 「ChatCompletions → 响应兼容」为实验性功能，界面「警告」为「此功能为实验性功能。配置格式和行为可能会发生变化。」
- 全局请求透传或目标渠道的请求体透传开启时，不会进入该转换链路。
- 开启请求透传时，<a href="/zh/docs/guide/feature-guide/admin/request-processing" target="_blank" rel="noopener noreferrer">请求处理</a>中「转换格式前」「发送前」阶段的实例不运行。
</Callout>

**策略 JSON 字段说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 字段 | 作用 |
| --- | --- |
| `enabled` | 总开关；关闭时其他字段不生效。 |
| `all_channels` | 为 `true` 时允许所有渠道参与匹配。 |
| `channel_ids` | `all_channels` 为 `false` 时按渠道 ID 匹配，命中任一即通过。 |
| `channel_types` | `all_channels` 为 `false` 时按渠道类型编号匹配，命中任一即通过。 |
| `model_patterns` | 正则表达式数组；请求模型至少命中一项才转换。 |

</div>

**配置项说明：**

下表按分区中的顺序排列。

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap [&_td_code]:wrap-anywhere">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 启用请求透传 | 将请求直接转发给上游提供商，不进行任何后处理。系统会把客户端原始请求体直接发送给上游，跳过请求体转换、字段移除、系统提示词合并和参数覆盖等步骤。 | 开关。 | 关闭 |
| 不自动处理思考后缀的模型 | 此处列出的模型不会自动添加或移除 -thinking / -nothinking 后缀。命中的模型同时豁免 @ 修饰符解析与 400 校验。 | JSON 字符串数组；以 re: 开头的条目会按 Go 正则匹配完整模型名，例如 re:.*@sha256:.*。格式不正确时提示「无效的 JSON 格式」；留空保存为空数组。 | `moonshotai/kimi-k2-thinking`、`kimi-k2-thinking` |
| 策略 JSON | 「ChatCompletions → 响应兼容」区域的转换策略，渠道匹配与模型正则需要同时满足。字段见「策略 JSON 字段说明」。 | JSON 对象；空值将保存为 {}。 | `{"enabled":false,"all_channels":true}` |
| 保持连接心跳 | 定期发送 ping 帧以保持流连接处于活动状态。 | 开关。 | 关闭 |
| Ping 间隔（秒） | 心跳的发送间隔。 | 不小于 `1`；建议保持此值较高，以避免上游限流。关闭「保持连接心跳」时不可编辑。 | `60` |

</div>

### Gemini

- 模型-Gemini

![Gemini 分区](/assets/guide/feature-guide/system-settings-model-gemini.png)

Gemini 分区控制 Gemini 和部分 Vertex 转换链路使用的实例级默认行为。

**操作流程：**
1. 按需填写安全设置、版本覆盖和支持的 Imagine 模型。
2. 按需打开思考后缀适配器，填写预算令牌比例。
3. 按需打开或关闭两个 FunctionCall 相关开关。
4. 点击页头「保存更改」。

<Callout type="info" title="提示">
- 「支持的 Imagine 模型」只改变转换时的输出模态，不会自动添加模型、价格或渠道能力；应填写模型映射后的上游名称。
- 思考后缀适配器关闭时，「预算令牌比例」下方显示「即使禁用适配器，Gemini 也会继续自动检测思维模式。仅当您需要对定价和预算进行更精细的控制时才启用此选项。」
</Callout>

**转换默认值配置项：**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 安全设置 | 以 JSON 格式提供按类别划分的安全覆盖。使用 `default` 作为回退值。 | JSON 字符串映射；阈值由服务端检查，取值见[常见问题](#常见问题)。 | `{"default":"OFF"}` |
| 版本覆盖 | 将模型标识符映射到 Gemini API 版本。当未找到特定匹配项时，将应用 `default` 条目。 | JSON 字符串映射。 | `{"default":"v1beta","gemini-1.0-pro":"v1"}` |
| 支持的 Imagine 模型 | 接受支持 Imagine API 的模型标识符的 JSON 数组。 | JSON 字符串数组。 | 7 项内置模型 |

</div>

**思考适配与 FunctionCall 配置项：**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 思考后缀适配器 | 支持 `-thinking`、`-thinking-{{budget}}`、`-nothinking` 以及 `-high` 等推理强度后缀，同时路由到正确的 Gemini 变体。关闭后模型名原样发送给上游。 | 开关。 | 关闭 |
| 预算令牌比例 | 预算令牌 = 最大令牌数 × 比例。建议与上游计费保持一致。 | 接受 0.002 到 1 之间的十进制数。 | `0.6` |
| 启用 FunctionCall 思维签名填充 | 仅为使用 OpenAI 格式的 Gemini/Vertex 渠道填充 thoughtSignature。 | 开关。 | 开启 |
| 移除 functionResponse.id 字段 | Vertex AI 不支持 functionResponse.id 字段，开启后将自动移除该字段。 | 开关。 | 开启 |

</div>

### Claude

- 模型-Claude

![Claude 分区](/assets/guide/feature-guide/system-settings-model-claude.png)

**操作流程：**
1. 按需填写请求头覆盖和默认最大 Token 数。
2. 按需打开思考后缀适配器，填写预算令牌比例。
3. 点击页头「保存更改」。

**配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 请求头覆盖 | 以 JSON 格式提供按模型划分的标头覆盖。可用于启用测试功能，例如扩展上下文窗口。作用于命中模型的出站请求头，与请求中原有的同名请求头合并去重。 | JSON 对象：模型名 → 请求头 → 值数组。 | `{}` |
| 默认最大 Token 数 | 作用于缺失或为 0 的 `max_tokens`。 | JSON 对象；值为非负整数，缺少 `default` 时按 8192；不可为负数。示例 `{ "default": 8192, "claude-3-haiku-20240307": 4096, "claude-3-opus-20240229": 4096, "claude-3-7-sonnet-20250219-thinking": 8192 }` | `{"default":8192}` |
| 思考后缀适配器 | 将带 `-thinking`、`-nothinking` 以及 `-high` 等推理强度后缀的请求适配为 Anthropic 原生思考请求，并保持计费可预测。关闭后模型名原样发送给上游。 | 开关。 | 开启 |
| 预算令牌比例 | 预算令牌 = 最大令牌数 × 比例。作用于思考预算估算。 | 接受 0.1 到 1 之间的十进制数。 | `0.8` |

</div>

### Grok

- 模型-Grok

![Grok 分区](/assets/guide/feature-guide/system-settings-model-grok.png)

**操作流程：**
1. 打开或关闭「启用违规扣费」。
2. 开启时填写「违规扣费金额」。
3. 点击页头「保存更改」。

<Callout type="warn" title="注意">
- 只有在上游错误中出现受支持的违规标记（例如内容违反使用规范的提示）时才触发。
- 普通上游错误、内容审核失败或其他 Grok 请求不会因此额外扣费；触发违规扣费的错误不会重试。
- 实际扣费按「基础金额 × 系统分组倍率」换算，并单独写入一条内容为「已收取违规费用」的消费日志；排查时应同时查看原请求错误和该日志。
- 该设置直接扣减用户余额；启用或调整金额前，请核对上游最新违规收费规则、分组倍率和面向用户的价格说明。
</Callout>

**配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 启用违规扣费 | 开启后，违规请求将额外扣费。说明后的「官方说明」链接打开 x.ai 的违规费说明。 | 开关。 | 开启 |
| 违规扣费金额 | 基础金额，实际扣费 = 基础金额 × 系统分组倍率。 | 不小于 `0`，步长 0.01；关闭「启用违规扣费」时不可编辑。 | `0.05` |

</div>

### 模型部署

- 模型-模型部署

![模型部署分区](/assets/guide/feature-guide/system-settings-model-model-deployment.png)

当前模型部署集成支持 io.net，分区标题为「io.net 部署」。本分区用于启用接入和配置凭证，不是创建部署资源的表单；截图为开启「启用 io.net 部署」后的状态。

**操作流程：**
1. 开启「启用 io.net 部署」，展开密钥配置区域。
2. 点击「前往 io.net API 密钥」，打开 <a href="https://ai.io.net/ai/api-keys" target="_blank" rel="noopener noreferrer">io.net API 密钥页面</a>。
3. 创建或选择密钥时，将 Project 设置为 `io.cloud`。
4. 复制密钥，粘贴到「io.net API 密钥」输入框；已有密钥且无需更换时，可保持空框不变。
5. 点击「测试连接」。
6. 点击页头「保存 io.net 设置」。

<Callout type="warn" title="注意">
- 关闭本分区的接入开关不会终止已有 io.net 部署，也不代表第三方费用停止。
- 关闭后，New API 中查看、延长和终止已有部署的操作也会被拒绝。
- 创建、延长和终止部署会改变第三方资源和费用，执行前应核对 io.net 账户、资源配置及账单。
- New API 不保证第三方容量、账单或部署成功率。
</Callout>

**测试连接说明：**
- 使用输入框中的密钥测试，输入为空时使用已保存的密钥；只测试连接，不保存设置。
- 成功时显示「连接成功」「已正常连接 io.net 服务。」。
- 失败时显示「连接失败」和错误信息，请检查密钥、项目和网络连接。
- 密钥保存后不回显，输入框为空不表示尚未配置。

**配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 启用 io.net 部署 | 在控制台启用 io.net 模型部署服务。 | 开关；开启后才显示密钥输入框、「测试连接」和「如何获取 io.net API 密钥」说明。使用部署服务需保存开启状态并保存有效密钥。 | 关闭 |
| io.net API 密钥 | 用于 io.net 部署 API 鉴权。 | 首次配置时必填；保存后不回显。 | 空 |

</div>

## 保存与生效

保存方式见<a href="/zh/docs/guide/feature-guide/system-settings/system-setting#保存方式" target="_blank" rel="noopener noreferrer">系统设置概览</a>，生效与多实例同步规则见<a href="/zh/docs/guide/feature-guide/system-settings/system-setting#生效范围与多实例同步" target="_blank" rel="noopener noreferrer">生效范围与多实例同步</a>。未特别说明时，保存后处理该请求的节点立即使用新值，其他节点约 3 秒内随系统设置同步（最迟一个同步周期，默认 60 秒）。同步周期由环境变量 `SYNC_FREQUENCY` 调整，单位为秒，默认 60 秒，修改后需重启 New API。各配置项读取新值的时机如下：

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| 配置项 | 保存方式 | 生效时机 |
| --- | --- | --- |
| 全局模型配置 › 启用请求透传、不自动处理思考后缀的模型、策略 JSON | 页头「保存更改」 | 下一次请求起。 |
| Gemini、Claude › 全部字段 | 页头「保存更改」 | 下一次请求起。 |
| 全局模型配置 › 保持连接心跳、Ping 间隔（秒） | 页头「保存更改」 | 每个流式响应开始时读取，新的流式请求起生效；已在进行的流沿用原设置。 |
| Grok › 违规扣费的开关和金额 | 页头「保存更改」 | 下一次出现违规标记、需要扣费时按新设置计算。 |
| 模型部署 › 启用 io.net 部署、io.net API 密钥 | 「保存 io.net 设置」 | 下一次查看、创建、延长或终止部署时按新值判断；关闭后这些操作被拒绝，已有部署不会终止。 |
| 模型部署 › 测试连接 | 不保存设置 | 用输入框中的密钥测试，输入为空时使用已保存的密钥。 |

</div>

**补充说明：**
- **逐项写入**：「保存更改」「保存 io.net 设置」只提交有改动的项，每项成功提示一次「设置更新成功」；没有改动时提示「没有需要保存的更改」。
- **校验**：页面检查 JSON 字段的格式。服务端另外校验两项：Gemini「安全设置」的阈值必须是允许的取值，Claude「默认最大 Token 数」不能为负数；校验不通过时该字段及其后的字段都不保存，提示见[常见问题](#常见问题)。

## 注意事项

- **Grok 违规扣费直接扣减用户余额**：见[Grok](#grok)。
- **关闭 io.net 部署不会终止已有部署**：也不会停止第三方费用，见[模型部署](#模型部署)。
- **保存成功不代表上游接受**：除上述两项取值外，其他配置是否被上游接受，要到实际请求时才能确定。
- **请求透传会绕过转换**：全局或渠道级请求体透传开启时，ChatCompletions 转换、参数覆盖等不生效，见[全局模型配置](#全局模型配置)。

<Accordion title="保存后字段没有变化">
**可能原因**：
- 点击的不是该分区的保存按钮。
- 保存时出现了失败提示。逐键保存时，失败项不会自动重试。

<Accordion title="正则写了却没有匹配">

**说明**：全局或渠道级请求透传会跳过转换链路。

<Accordion title="Claude 请求缺少 max_tokens 被上游拒绝">
**可能原因**：「默认最大 Token 数」中的数值超过上游输出上限。
</Accordion>

<Accordion title="Grok 出现额外扣费">
**可能原因**：原请求的错误包含违规标记。

**处理方法**：
1. 在使用日志中查看内容为「已收取违规费用」的记录，并核对分组倍率。
</Accordion>

<Accordion title="部署页提示未启用或连接失败">
**提示原文**：「模型部署服务未启用」（英文 Model deployment service is disabled）或「连接失败」（英文 Connection failed）

**可能原因**：
- 显示「模型部署服务未启用」：「启用 io.net 部署」尚未开启并保存。
- 显示「连接失败」：开关已开启，但连接测试失败，例如未保存有效 API Key。

**处理方法**：
1. 开启「启用 io.net 部署」并保存有效 API Key，两个条件缺一不可。
</Accordion>

<Accordion title="部署已创建但模型请求没有使用它">
**说明**：部署不会自动创建或绑定渠道。

**处理方法**：
1. 手动配置端点。
</Accordion>

<Accordion title="保存安全设置或默认最大 Token 数时被拒绝">
**提示原文**：如 `invalid Gemini safety threshold "…" for "…"` 、`negative Claude default max_tokens … for "…"` 或 `Claude default max tokens must be a JSON map of model to integer: …`（仅英文）

**可能原因**：
- Gemini「安全设置」中某个类别的阈值不是 `OFF`、`BLOCK_NONE`、`BLOCK_ONLY_HIGH`、`BLOCK_MEDIUM_AND_ABOVE`、`BLOCK_LOW_AND_ABOVE`、`HARM_BLOCK_THRESHOLD_UNSPECIFIED` 之一。阈值为空的类别不检查。
- Claude「默认最大 Token 数」中某个模型的值为负数。
- Claude「默认最大 Token 数」不是「模型名 → 整数」的映射。

**处理方法**：
1. 按提示中的类别或模型名修正对应的值。
2. 重新点击「保存更改」。
</Accordion>

</Accordions>
