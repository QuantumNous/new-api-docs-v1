## 配置分区

本节按左侧导航的顺序介绍五个分区，各分区的保存按钮和生效时机见[保存与生效](#保存与生效)。

### 基本身份验证

- 身份验证-基本身份验证

![身份验证-基本身份验证页面](/assets/guide/feature-guide/system-settings-authentication-basic-authentication.png)

**操作流程：**
1. 按需开启或关闭「密码登录」「注册已启用」「密码注册」「电子邮件验证」。
2. 需要限制邮箱域名时，先在「电子邮件域白名单」中每行填写一个域名并保存，再开启「电子邮件域限制」。
3. 点击页头「保存更改」。

<Callout type="warn" title="注意">
- 开启邮箱验证前，先确认发信配置（SMTP 或 Resend）能从服务端正常发信。
- 保存认证选项不会测试发信配置；邮件无法送达时，用户可能无法完成注册验证或找回密码。
</Callout>

**配置项说明：**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap [&_td_code]:wrap-anywhere">

| 配置项 | 定义 | 填写要求和限制 | 默认值 |
| --- | --- | --- | --- |
| 密码登录 | 允许用户使用用户名和密码登录。 | 开关。 | 开启 |
| 注册已启用 | 允许新用户注册。 | 开关；关闭后通过 OAuth 或微信首次登录也不再创建新账户。 | 开启 |
| 密码注册 | 允许使用密码注册。 | 开关；受「注册已启用」共同约束。 | 开启 |
| 电子邮件验证 | 要求通过密码注册的新账户验证邮箱。 | 开关；开启前应先在<a href="/zh/docs/guide/feature-guide/system-settings/settings-operations#邮件与通知" target="_blank" rel="noopener noreferrer">运维配置</a>的「邮件与通知」中完成发信设置。 | 关闭 |
| 电子邮件域限制 | 只接受「电子邮件域白名单」中的邮箱域名。 | 开关；白名单未保存时不可开启，提示见[常见问题](#常见问题)。 | 关闭 |
| 电子邮件别名限制 | 阻止电子邮件别名（例如，user+alias@domain.com）。 | 开关；开启后拒绝 @ 前含 `+` 或 `.` 的邮箱，如 `first.last@example.com`。 | 关闭 |
| 电子邮件域白名单 | 允许的邮箱域名，仅在启用域名限制时使用。 | 每行一个精确域名，不填完整邮箱或通配符。 | `gmail.com`、`163.com`、`126.com`、`qq.com`、`outlook.com`、`hotmail.com`、`icloud.com`、`yahoo.com`、`foxmail.com` |

</div>

<Callout type="info" title="提示">
- 用户名最长 20 个字符，邮箱最长 50 个字符，密码长度为 8–128 个字符。
- 新注册用户创建为普通用户；管理员角色应在<a href="/zh/docs/guide/feature-guide/admin/user" target="_blank" rel="noopener noreferrer">用户管理</a>中由有权限的管理员创建或调整。
- 发送密码注册验证码和已登录用户绑定邮箱时，都会检查域名白名单和邮箱别名规则。
</Callout>

### OAuth 集成

在内置第三方登录提供商处登记本站后，把凭证填入对应标签并开启。

分区以「GitHub」「Discord」「OIDC」「Telegram」「LinuxDO」「微信」六个标签展示，页头有「重置」和「保存更改」，「保存更改」一次保存各标签中的修改。除微信外，每个标签顶部有「设置引导」，说明「启用登录前，请先在提供商应用中设置这些值。」并列出可复制的回调地址。有未保存的修改时，标题旁显示「未保存的更改」。

**操作流程：**
1. 在提供商后台创建应用，登记应用名称、主页和该提供商要求的回调地址。
2. 在对应标签中填写凭证和端点，点击页头「保存更改」。
3. 开启该提供商的开关，再次点击页头「保存更改」。

<Callout type="info" title="提示">
- 「设置引导」中的回调地址由「服务器地址」推导，格式为 `/oauth/{provider}`；OIDC 标为「重定向 URL」，其余标为「授权回调 URL」。GitHub、Discord、OIDC 还显示「主页 URL」。
- 未设置服务器地址时，这些地址以占位文字「网站地址」开头，不能直接使用，应先在<a href="/zh/docs/guide/feature-guide/system-settings/settings-site#系统信息" target="_blank" rel="noopener noreferrer">站点与品牌配置</a>中填写。
- Discord 与 OIDC 的令牌交换会发送由服务器地址生成的对应回调；GitHub 当前令牌交换不发送 `redirect_uri`。
- LinuxDO 根据收到请求的协议和主机拼接 `/api/oauth/linuxdo`，与界面显示的地址可能不同。
- 回调地址、浏览器公开地址和服务端看到的协议必须一致；应复制页面为本站生成的地址，并以提供商要求和反向代理实际转发路径为准。
- 管理员可在<a href="/zh/docs/guide/feature-guide/admin/user" target="_blank" rel="noopener noreferrer">用户管理</a>中管理用户的绑定信息。
</Callout>

### 通行密钥认证

- 身份验证-通行密钥认证

![身份验证-通行密钥认证页面](/assets/guide/feature-guide/system-settings-authentication-passkey-authentication.png)

Passkey 使用 WebAuthn。启用后，用户可以注册 Passkey 并用它登录。「主域名」和「兼容的通行密钥域名」位于「通行密钥域名」分组，分组中的「为什么需要设置？」打开「如何设置通行密钥域名」。

**操作流程：**
1. 按需开启「启用 Passkey」，设置显示名称、用户验证和设备类型偏好。
2. 在「通行密钥域名」分组中填写「主域名」，旧域名保留在「兼容的通行密钥域名」中；带端口的完整地址填到「允许使用通行密钥的网站」。
3. 点击页头「保存更改」。
4. 弹出确认框时，核对「当前域名」和「新域名」，移除兼容域名时还要核对受影响的通行密钥，再点击「更改域名」或「移除域名」。

<Callout type="warn" title="注意">
- 「如何设置通行密钥域名」显示当前站点和系统目前使用的域名。弹窗中的按钮在尚未设置域名时为「填入当前网站」，已有域名时为「保留现有域名」。
- 该按钮只在通过 HTTPS 或 `http://localhost` 访问、且不是 IP 地址时可用，否则显示「请通过 HTTPS 域名配置 Passkey；本地开发可使用 localhost。」
- 主域名与当前网站不匹配或未设置时，分组提示变为黄色警告。「允许使用通行密钥的网站」中没有当前网站时，提示「列表中还没有当前网站。如果用户在这里登录，请添加 …。」
- 被移除域名上的通行密钥将无法使用，确认前应确保受影响用户可以用其他方式登录。
- 关闭「启用 Passkey」后，已注册通行密钥但未启用 2FA 的用户将无法登录：主认证通过后仍要求通行密钥验证，此时提示「此验证方式当前不可用。」。
- 如需恢复，可重新开启「启用 Passkey」，或在<a href="/zh/docs/guide/feature-guide/admin/user" target="_blank" rel="noopener noreferrer">用户管理</a>中为这些用户执行「重置 Passkey」；该操作会删除用户的 Passkey 凭证并撤销其现有登录会话。
</Callout>

**结果说明：**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| --- | --- | --- |
| 生效域名改变或清空主域名 | 确认框「更改通行密钥域名？」，说明「新通行密钥将使用新的主域名。原域名会被保留，已有通行密钥仍可验证。」；清空时「新域名」显示「从系统网站地址自动获取」。 | 点击「更改域名」后写入。 |
| 移除兼容域名 | 确认框「移除兼容的通行密钥域名？」，列出被移除的域名、「使用被删除域名的通行密钥：…」和「域名归属未知、可能受影响的通行密钥：…」。 | 确认受影响用户可以用其他方式登录后，点击「移除域名」。 |

</div>

### 机器人保护

## 登录验证与安全

本节说明与身份验证相关的安全检查边界，其中大多数能力不在本页表单中配置，但影响登录与账户安全。

- **统一登录验证**：当用户已启用 2FA 或 Passkey 时，主认证通过后会进入统一的验证质询流程（有效期约 5 分钟），验证通过后才签发会话。这是提升登录安全性的统一机制。直接使用 Passkey 登录时不再追加质询。
- **验证证明一次性消费**：这些验证证明绑定到「会话 + 动作」（基于 HMAC 的上下文哈希），且只被消费一次。回调、验证或绑定流程失败后通常需要重新发起，不要重复复用同一个证明。
- **2FA 的边界**：2FA 是用户级安全功能，不是本页的全局开关。用户在<a href="/zh/docs/guide/feature-guide/user/security#启用两步验证" target="_blank" rel="noopener noreferrer">安全与访问</a>页启用和管理 2FA；管理员重置某个用户的 2FA、备用码和登录会话时，应使用<a href="/zh/docs/guide/feature-guide/admin/user" target="_blank" rel="noopener noreferrer">用户管理</a>中的「重置 2FA」。
- **绑定/解绑/删除账户**：涉及账户绑定变更或删除的操作，也要求再次验证（已启用 2FA 或 Passkey 时使用它们，否则使用密码或第三方登录），避免会话被意外劫持。

<Callout type="warn" title="注意">
开启 2FA 或 Passkey 后，主认证之后还需要完成验证质询（约 5 分钟）才会签发会话。请为 Root 和用户保留至少一种经过验证的替代登录方式；如果验证证明或 OAuth state 已过期/被消费，需要重新发起登录或绑定，而不是反复刷新同一个地址。
</Callout>

## 密码传输加密

密码传输加密由环境变量 `PASSWORD_LOGIN_ENCRYPTION_ENABLED` 控制（布尔，默认 `false`），本页没有对应设置。该变量只在启动时读取，修改后需重启 New API。

开启后，密码登录和敏感操作中的密码验证会由前端使用 RSA-OAEP 加密后提交；注册不在加密范围内，仍提交原始密码。

**工作机制：**
- 服务端启动时从数据库读取 RSA 私钥，不存在时自动生成（2048 位）并写入数据库；连接同一数据库的节点共用该密钥。
- 前端从服务端获取是否启用和公钥，使用 RSA-OAEP v1/v2 信封加密密码后随请求提交。
- 服务端使用私钥解密校验密码。

<Callout type="warn" title="注意">
- 该开关是实例级环境变量，多实例部署时各节点必须一致。
- 各节点开关不一致时，部分登录请求会被拒绝（提示「无效的参数」）。
- 私钥无法读取或写入时服务无法启动；解密失败时提示「用户名或密码错误，或用户已被封禁」。
- 同时注意与反向代理的 HTTPS/HTTP 传输配合，关闭则为明文密码传输。
</Callout>

## 注意事项

**登录与回调：**
- **回调一致性**：浏览器公开地址、「服务器地址」、提供商登记回调与反向代理转发的 Host/Proto 必须一致。
- **验证证明与 state 一次性**：失败后不要反复刷新同一地址，应重新发起登录或绑定。
- **统一登录验证**：2FA/Passkey 用户需在主认证后完成验证质询（约 5 分钟）。

**凭证与域名：**
- **Passkey 与域名强绑定**：改域名/协议后需重新核对主域名、兼容的通行密钥域名、允许使用通行密钥的网站和「服务器地址」；旧域名应保留在兼容域名中。
- **Turnstile**：需站点密钥和密钥同时正确、Cloudflare 可达、token 有效，且只有一个全局开关。保护的流程见[机器人保护](#机器人保护)。
- **Telegram 迁移**：若此前用旧 Login Widget，需在 BotFather 的 Login Widget 中登记 `/oauth/telegram` 回调地址并取得 Client ID 和 Client Secret；现有绑定可继续使用。`telegram` 标识符（slug）保持内置保留。
- **密码加密的密钥共用**：密钥在启动时自动生成并存入数据库，各节点需连接同一数据库。

**说明**：当前域名/别名规则重点用于注册验证码流程，密码重置有独立的流程，不应假定两者完全相同。
</Accordion>

<Accordion title="OAuth 回调报错或状态失效">
**可能原因**：
- 「服务器地址」、反向代理的 Host/Proto 或提供商后台回调登记存在问题。
- 一次性流程令牌已过期。
</Accordion>

<Accordion title="OIDC 保存时报发现文档错误">
**可能原因**：
- Well-Known URL 不以 `http://` 或 `https://` 开头。
- 保存页面的浏览器无法访问该地址。

**处理方法**：
1. 清空 Well-Known URL 后手动填写端点。
2. 检查网络策略。
</Accordion>

<Accordion title="自定义 OAuth 的 Auto Detect 仍交换失败">
**说明**：「认证方式」为 Auto Detect 时按请求体参数发送凭证，不会改用 Basic Auth 重试。

**处理方法**：
1. 根据提供商要求，明确选择 Params (in body) 或 Header (Basic Auth)。
</Accordion>

<Accordion title="自定义 OAuth 无法删除">
**提示原文**：「该 OAuth 提供商还有用户绑定，无法删除。请先解除所有用户绑定。」（英文 This OAuth provider still has linked users and cannot be deleted. Unbind all users first.）

**说明**：禁用不会自动解绑。

**处理方法**：
1. 先在用户的「安全与访问」页或用户管理中解除该提供商的全部历史绑定。
</Accordion>

<Accordion title="关闭 OAuth 后用户仍显示绑定">
**说明**：关闭仅阻止新的登录或绑定，不会清理历史身份。

**处理方法**：
1. 到用户管理解除绑定。
</Accordion>

<Accordion title="Passkey 在新域名上不可用">
**可能原因**：主域名、兼容的通行密钥域名、允许使用通行密钥的网站、HTTPS 或「服务器地址」的设置与新域名不符。

**处理方法**：
1. 管理员可在用户管理重置后，让用户重新注册。
</Accordion>

<Accordion title="Turnstile 保存成功但所有请求仍失败">
**说明**：保存选项不会代替运行时验证。

**可能原因**：站点密钥、密钥、Cloudflare 站点域名、服务端出网或令牌有效期存在问题。
</Accordion>

<Accordion title="登录后无会话或验证失败">
**可能原因**：
- 用户已启用 2FA/Passkey，但统一验证质询未通过。
- 验证证明与 OAuth state 已被一次性消费或已过期。
</Accordion>

<Accordion title="开启密码传输加密后登录失败">
**可能原因**：
- 各节点的 `PASSWORD_LOGIN_ENCRYPTION_ENABLED` 不一致。
- 各节点未连接同一数据库。
</Accordion>

<Accordion title="Telegram 登录失败">
**可能原因**：
- 未在 BotFather 的 Login Widget 中登记 `/oauth/telegram` 回调地址。
- 未填写对应的 Client ID 和 Client Secret。
</Accordion>

<Accordion title="开启登录方式时提示「无法启用…」">
**说明**：对应的配置尚未保存时，开启开关会被拒绝，常见提示如下。

| 提示原文 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 「无法启用 GitHub OAuth，请先填入 GitHub OAuth 的 Client ID 和 Client Secret！」（英文 Cannot enable GitHub OAuth. Enter the GitHub OAuth Client ID and Client Secret first.）；Discord OAuth、OIDC、LinuxDO OAuth 同理 | 该提供商的凭证尚未保存。 | 先关闭开关，保存凭证，再开启并保存。 |
| 「无法启用邮箱域名限制，请先填入限制的邮箱域名！」（英文 Cannot enable the email domain restriction. Enter the allowed email domains first.） | 「电子邮件域白名单」尚未保存。 | 先保存白名单，再开启「电子邮件域限制」。 |
| 「无法启用微信登录，请先填入微信登录相关配置信息！」（英文 Cannot enable WeChat login. Enter the WeChat login settings first.） | 微信的服务器地址尚未保存。 | 先保存微信配置，再开启。 |
| 「无法启用 Turnstile 校验，请先填入 Turnstile 校验相关配置信息！」（英文 Cannot enable Turnstile verification. Enter the Turnstile settings first.） | 站点密钥既未保存，也未在本次保存中填写。 | 填写站点密钥和密钥后，与开关一起保存。 |
| 「Telegram OAuth 尚未配置或启用，请联系管理员。」（英文 Telegram OAuth is not configured or enabled. Please contact your administrator.） | Telegram 的 Client ID 或 Client Secret 既未保存，也未在本次保存中填写。 | 填写 Client ID 和 Client Secret 后，与开关一起保存。 |
</Accordion>

</Accordions>
