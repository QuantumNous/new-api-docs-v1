## 身份验证配置简介

身份验证域下有五个独立分区：

| 分区 | 路径 | 职责 |
| --- | --- | --- |
| [基本身份认证](#基本身份认证) | `/system-settings/auth`（默认进入） | 密码登录、注册、邮箱验证与域名限制。 |
| [OAuth 集成](#oauth-集成) | `/system-settings/auth/oauth` | 内置第三方身份提供方。 |
| [通行密钥认证](#通行密钥认证) | `/system-settings/auth/passkey` | WebAuthn / Passkey。 |
| [机器人防护](#机器人防护) | `/system-settings/auth/bot-protection` | Cloudflare Turnstile。 |
| [自定义 OAuth](#自定义-oauth) | `/system-settings/auth/custom-oauth` | 自定义身份提供方。 |

## 配置分区

### 基本身份认证

- 开关与字段

| 字段 | 作用与边界 |
| --- | --- |
| 密码登录 | 控制是否允许使用用户名和密码登录。 |
| 注册已启用 | 控制是否允许新用户注册。 |
| 密码注册 | 控制是否允许使用密码注册。它受「注册已启用」共同约束。 |
| 邮箱验证 | 要求通过密码注册的新账户必须验证邮件；配置此项前应先完成[运维设置](./settings-operations)中的 SMTP。 |
| 邮箱域名限制 | 启用后只接受白名单中的邮箱域名。 |
| 邮箱别名限制 | 启用后阻止电子邮件别名，例如 `user+test@example.com`。 |
| 邮箱域名白名单 | 每行一个域名 (仅在启用域名限制时使用) |

<Callout type="info">
- 用户名最长 20 个字符，邮箱最长 50 个字符，密码长度为 8–20 个字符。
- 新注册用户创建为普通用户；管理员角色应在[用户管理](/zh/docs/guide/feature-guide/admin/user)中由有权限的管理员创建或调整。
</Callout>

![身份验证-基本身份认证页面](/assets/guide/feature-guide/system-settings-authentication-basic-authentication.png)

<Callout type="info">
当前代码在发送邮箱验证码时检查域名白名单和邮箱别名规则；该接口既用于密码注册验证码，也可用于已登录用户的邮箱绑定验证码。

</Callout>

### OAuth 集成

OAuth 分区以标签页展示内置提供商。先在提供商后台创建应用，再把凭证和回调信息填入本页，最后开启对应开关。

| 提供商 | 配置字段或特殊行为 |
| --- | --- |
| GitHub | 开关、Client ID、Client Secret。|
| Discord | 开关、Client ID、Client Secret。 |
| OIDC | 开关、显示名称、Client ID/Secret、Well-Known URL，以及授权、令牌和用户信息端点。显示名称为空时使用 `OIDC`。填写 `http://` 或 `https://` 开头的 Well-Known URL 并保存时，浏览器会直接获取发现文档并自动填充端点；也可以手动填写端点。 |
| LinuxDO | 开关、Client ID、Client Secret、最低信任等级。只有达到配置阈值的 LinuxDO 账户才允许继续登录。 |
| Telegram | 开关、Client ID、Client Secret。使用 `oauth.telegram.org` 的统一 **OIDC/PKCE** OAuth；`telegram` 标识符（slug）为内置保留。 |
| 微信 | 开关、微信登录服务地址、服务 Token、二维码图片 URL。登录时后端调用配置服务的 `/api/wechat/user?code=...` 获取用户信息，属于依赖外部服务的专用流程。 |

<Callout type="info">
- 标准 OAuth 页面会显示当前 `ServerAddress` 推导出的主页和 `/oauth/{provider}` 回调地址。
- Discord 与 OIDC 的令牌交换会发送由 `ServerAddress` 生成的对应回调；

</Callout>

- OAuth 登录与绑定流程

1. 在提供商后台登记应用名称、主页和该提供商要求的回调地址。
2. 在本页填写凭证和端点，保存后再开启提供商。
3. 用未登录窗口测试登录；用已登录的个人设置测试账户绑定。
4. 检查回调后的错误提示、用户绑定记录和服务端日志。

<Callout type="info">
  管理员可使用[用户管理](/zh/docs/guide/feature-guide/admin/user)管理用户绑定信息。
</Callout>

<Callout type="warn">
  回调地址、浏览器公开地址和服务端看到的协议必须一致。
</Callout>

### 通行密钥认证

Passkey 使用 WebAuthn。启用后，用户可以注册 Passkey 并用它登录。

| 字段 | 说明 |
| --- | --- |
| 启用 Passkey | 开启 Passkey 注册和登录。 |
| 依赖方显示名称 | 在 Passkey 提示期间向用户显示的可读名称。 |
| 依赖方 ID | 用于 Passkey 注册的有效域。必须与当前域匹配或为其父域。 |
| 用户验证 | 控制在通行密钥流程中是否需要用户验证（生物识别/PIN）。 |
| 设备类型偏好 | 不限、内置设备（如指纹/面容、Windows Hello）或外部设备（如 USB 安全密钥）。 |
| 允许不安全来源| 允许在非 HTTPS 源上注册通行密钥（仅建议用于开发，生产环境应关闭。） |
| 允许 Origin | 允许用于 Passkey 注册和身份验证的来源列表（每行一个）。 |

### 机器人防护

「机器人防护」分区对应 Cloudflare Turnstile，包含：

| 字段 | 说明 |
| --- | --- |
| 启用 Turnstile | 全局开关 `TurnstileCheckEnabled`。启用后，相关匿名或敏感操作必须提交有效的 Cloudflare Turnstile 挑战令牌。 |
| 站点密钥 | 前端渲染挑战所需的站点密钥。 |
| 密钥 | 服务端向 Cloudflare 验证令牌所需的密钥。 |

<Callout type="info">
  - 当前中间件会在以下流程检查 Turnstile：注册、密码登录、请求注册邮箱验证码、请求密码重置邮件，以及用户签到。
  - Turnstile 密钥 是服务端凭证，启用或修改后应立即验证登录、注册、验证码和密码重置等受保护流程。
</Callout>

### 自定义 OAuth

自定义 OAuth 是身份验证工作区的正式分区，地址为 `/system-settings/auth/custom-oauth`。<br/>
只有 Root 可以在管理页创建、编辑、启用、禁用、发现或删除提供商；<br/>
普通管理员只能在具备相应用户管理权限时查看或解除用户绑定。

- 身份验证-自定义 OAuth

![身份验证-自定义 OAuth 页面](/assets/guide/feature-guide/system-settings-authentication-custom-oauth.png)

- 创建、编辑与启停

1. 点击「添加 OAuth 提供商」，选择预设或从空白表单开始。
2. 填写名称、标识符（slug）、客户端凭证、三个端点和所需高级字段；保存前确认回调地址已登记。
3. 保存后，在列表中单独切换「启用」状态。只有启用并完成端点配置的提供商才会注入登录页。
4. 编辑已有提供商时，Client Secret 输入框为空表示保留原值。修改端点、字段映射或访问策略后，应重新测试登录和绑定。
5. 修改标识符（slug）前先更新第三方后台的回调登记；保存后旧地址不再对应当前提供商。

- 身份验证-添加自定义 OAuth

![身份验证-添加自定义 OAuth 页面](/assets/guide/feature-guide/system-settings-authentication-custom-oauth-add-provider.png)

<Callout type="info">
- 创建前准备
1. 先在第三方提供商后台创建 OAuth 应用，并准备 Client ID、Client Secret、授权端点、令牌端点和用户信息端点。
2. 管理页提供以下创建预设：GitHub Enterprise、GitLab、Gitea、Nextcloud、Keycloak、Authentik 和 ORY Hydra。
3. 预设只是辅助填写名称、标识符（slug）、端点、作用域和常见字段映射，不保证提供商可以直接连通。
4. 使用预设时应根据实际版本和部署路径逐项核对。
</Callout>

- 字段说明

| 字段 | 作用与边界 |
| --- | --- |
| 名称、图标、启用状态 | 决定管理页和登录入口的显示；只有启用的提供商会出现在登录页。 |
| 标识符（slug） | 用于URL和API路由；会转为小写，只允许小写字母、数字和连字符。 |
| Client ID / Client Secret | 创建时均为必填项。接口不会回显 Secret；编辑时留空表示保留原值，填写新值才会替换。 |
| 认证方式 | 客户端凭据如何发送至令牌端点 |
| 授权、令牌、用户信息端点 | 分别用于跳转授权、交换 Token 和读取用户资料。 |
| 作用域 | 使用空格分隔，例如 `openid profile email`。 |
| Well-Known URL| 供管理页手动执行 OIDC 发现 URL，点击"自动发现"以自动获取端点。 |
| 用户字段映射 | 从用户信息响应中读取用户 ID、用户名、显示名和邮箱；支持 `ocs.data.id` 这类 gjson 嵌套路径。 |
| 访问策略、拒绝消息 | 根据用户信息限制允许登录的账号，并定制不满足条件时的提示。 |

- 高级配置-访问策略

根据提供商返回的用户信息字段执行策略判断。条件和嵌套分组支持 and/or 逻辑。<br/>
支持的操作符：eq、ne、gt、gte、lt、lte、in、not_in、contains、not_contains、exists、not_exists。留空则允许所有用户。

- 高级配置-访问被拒绝消息

访问被拒绝时的提示消息。<br/>
可用变量：`{{provider}}`、`{{field}}`、`{{op}}`、`{{required}}`、`{{current}}`，以及 `{{current.roles}}` 等路径变量。

- 登录、绑定与生命周期

1. 保存并启用后，用未登录窗口测试登录，再用已登录测试用户验证账户绑定。
2. OAuth state 当前有效期约 10 分钟；绑定 state 还会关联发起用户和会话，不能跨会话复用。
3. 同一用户对同一自定义提供商只能保留一个绑定，同一提供商账号也不能绑定到多个本地用户。
4. 禁用提供商只会阻止后续登录和绑定，不会删除历史绑定。
5. 删除提供商前必须先由用户在个人设置中解绑，或由有权限的管理员在[用户管理](/zh/docs/guide/feature-guide/admin/user)中解除全部绑定；仍有任意绑定时，删除请求会被拒绝。

## 登录验证与安全

本节说明与身份验证相关的安全检查边界，其中大多数能力不在本页表单中配置，但影响登录与账户安全。

- **统一登录验证**：当用户已启用 2FA、Passkey 或其他已登记因子时，主认证通过后会进入统一的验证质询流程（有效期约 5 分钟），验证通过后才签发会话。这是提升登录安全性的统一机制。
- **验证证明一次性消费**：这些验证证明绑定到「会话 + 动作」（基于 HMAC 的上下文哈希），且只被消费一次。回调、验证或绑定流程失败后通常需要重新发起，不要重复复用同一个证明。
- **2FA 的边界**：2FA 是用户级安全功能，不是本页的全局开关。用户在个人设置中启用和管理 2FA；管理员重置某个用户的 2FA、备用码和登录会话时，应使用[用户管理](/zh/docs/guide/feature-guide/admin/user)中的「重置 2FA」。
- **绑定/解绑/删除账户**：涉及账户绑定变更或删除的操作，也要求提供已登记因子的验证证明，避免会话被意外劫持。

<Callout type="warn">
  开启 2FA 或 Passkey 后，主认证之后还需要完成验证质询（约 5 分钟）才会签发会话。请为 Root 和用户保留至少一种经过验证的替代登录方式；如果验证证明或 OAuth state 已过期/被消费，需要重新发起登录或绑定，而不是反复刷新同一个地址。
</Callout>

## 密码传输加密

密码传输加密由**环境变量** `PASSWORD_LOGIN_ENCRYPTION_ENABLED` 控制（默认 `false`），不在页面表单中配置。<br/>
开启后，登录/注册时前端使用 RSA-OAEP 对密码进行加密传输，避免密码在传输层明文暴露。

工作机制：

- 服务端生成并保存 RSA 密钥对（加密密钥存储在数据库中，通过 `common` 初始化加载）。
- `/api/status` 返回 `password_login_encryption_enabled` 供前端判断是否启用。
- 前端通过 `GET /api/user/login/encryption-key` 获取公钥；密码使用 RSA-OAEP v1/v2 信封加密后随请求提交。
- 服务端使用私钥解密校验密码。

<Callout type="warn">
  - 该开关是实例级环境变量，多节点部署时各节点必须一致。
  - 开启后若私钥缺失或各节点不一致，登录/注册会因解密失败而报错；同时注意与反向代理的 HTTPS/HTTP 传输配合，关闭则为明文密码传输。
</Callout>

## 保存与凭证安全

保存方式见[系统设置概览](./system-setting#保存方式)，密钥字段不回显、留空保留的规则见概览中的[敏感配置与审计记录](./system-setting#敏感配置与审计记录)。

保存后按以下顺序验证：

1. 按[变更前记录与验证](./system-setting#变更前记录与验证)完成通用的提示确认与刷新核对。
2. 使用测试账户验证密码登录、注册、邮箱验证码和密码重置。
3. 对每个启用的 OAuth 提供商分别测试登录和绑定，并检查历史绑定是否符合预期。
4. 对自定义 OAuth 额外核对回调地址、字段映射、访问策略和禁用／解绑／删除流程。
5. 在支持 WebAuthn 的 HTTPS 浏览器中测试 Passkey 注册和登录。
6. 若启用了 Turnstile，重复测试所有受保护流程，而不只测试登录。
7. 若开启密码传输加密，确认各节点一致并能正常解密登录。

## 注意事项

- **回调一致性**：浏览器公开地址、`ServerAddress`、提供商登记回调与反向代理转发的 Host/Proto 必须一致。
- **验证证明与 state 一次性**：失败后不要反复刷新同一地址，应重新发起登录或绑定。
- **统一登录验证**：2FA/Passkey 用户需在主认证后完成验证质询（约 5 分钟）。
- **Turnstile**：需 Site+Secret 同时正确、Cloudflare 可达、token 有效，且只有一个全局开关。
- **Passkey 与域名强绑定**：改域名/协议后需重新核对 依赖方 ID、Allowed Origins、ServerAddress。
- **Telegram 迁移**：若此前用旧 Login Widget，需按 `oauth.telegram.org` 的 OIDC/PKCE 应用重新登记；`telegram`  标识符（slug）保持内置保留。
- **密码加密**：环境变量控制，多节点需一致；开启前确认密钥已正确生成/存储。

## 常见问题

- **注册开关已开但注册失败**：检查密码注册开关、邮箱验证、SMTP、白名单、别名规则和 Turnstile；再查看后端返回的具体错误。
- **邮箱白名单不生效**：确认域名限制已启用、列表非空，并且每行是精确域名而非完整邮箱或通配符。
- **密码重置仍接受被域名限制的邮箱**：当前域名/别名规则重点用于注册验证码流程，密码重置有独立的流程，不应假定两者完全相同。
- **OAuth 回调报错或状态失效**：检查 `ServerAddress`、反向代理的 Host/Proto、提供商后台回调登记和一次性流程令牌是否已过期。
- **OIDC 保存时报发现文档错误**：Well-Known URL 必须以 `http://` 或 `https://` 开头，且保存页面的浏览器必须能访问该地址；否则手动填写端点并检查网络策略。
- **自定义 OAuth 的 Auto Detect 仍交换失败**：当前 `0` 按请求体参数方式发送凭证，不会动态重试 Basic Auth；根据提供商要求明确选择 Params 或 Header。
- **自定义 OAuth 无法删除**：先在用户个人设置或用户管理中解除该提供商的全部历史绑定；禁用不会自动解绑。
- **关闭 OAuth 后用户仍显示绑定**：关闭只阻止新的登录或绑定，不会清理历史身份；需要到用户管理解除绑定。
- **Passkey 在新域名上不可用**：重新核对 依赖方 ID、Allowed Origins、HTTPS 和 `ServerAddress`；管理员可在用户管理重置后让用户重新注册。
- **Turnstile 保存成功但所有请求仍失败**：同时检查 Site Key、Secret Key、Cloudflare 站点域名、服务端出网和令牌有效期；保存选项不会代替运行时验证。
- **登录后无会话或验证失败**：若用户已启用 2FA/Passkey，确认统一验证质询能够通过；检查验证证明与 OAuth state 是否一次性被消费或已过期。
- **密码登录报解密/加密错误**：检查 `PASSWORD_LOGIN_ENCRYPTION_ENABLED` 与多节点一致性、私钥是否已生成并正确加载。
- **Telegram 登录失败**：确认已在 `oauth.telegram.org` 登记 OIDC/PKCE 应用并填写正确的 client_id/client_secret；旧 widget 配置与新 OAuth 应用的对应关系需核对。
