- Only Root can access these settings. In the sidebar, go to **Admin** → **System Settings**, then select a section under **Site and Branding** in the left navigation.
- Configure the site name and address, public page content, legal documents, system announcements, top navigation, and sidebar modules.
- Visitors can view the system name, announcement, About page, home page content, User Agreement, and Privacy Policy without signing in.

<Callout type="info" title="Tip">

- **System Announcement** on this page is a single global notice. Manage the console’s structured announcement list under **Announcements** in <a href="/en/docs/guide/feature-guide/system-settings/settings-content" target="_blank" rel="noopener noreferrer">Console Content Settings</a>.
- Top navigation and sidebar module settings control which menu items appear. Disabling **Model Marketplace** or **Leaderboard** also blocks requests for the corresponding data on the server. See [Important Notes](#important-notes).

</Callout>

## Settings Sections

This section covers the four sections in the order they appear in the left navigation. For each section’s save button and when changes take effect, see [Saving Changes and When They Take Effect](#saving-changes-and-when-they-take-effect).

### System Information

- Site and Branding – System Information

![Site and Branding – System Information page](/assets/guide/feature-guide/system-settings-site-brand-system-information.png)

**Steps**

1. Enter the system name, server address, and public address for asynchronous tasks.
2. Add a logo URL, documentation link, footer, About page content, and home page content as needed.
3. To require user consent, enter the User Agreement and Privacy Policy.
4. Click **Save Changes** in the page header.

<Callout type="warn" title="Caution">

- Visitors can see this content without signing in. Keep API keys, client secrets, internal network addresses, internal administrator information, and other nonpublic information out of these fields.
- End users must be able to reach the **Public Address for Asynchronous Tasks** from their browsers over the public internet. Validation only checks the URL format.
- An incorrect address can make task output URLs unreachable, and inconsistent secrets across nodes can cause validation to fail. See [Important Notes](#important-notes).

</Callout>

**Legal document rules**

- When the User Agreement or Privacy Policy field is populated, the corresponding link appears on the sign-in and registration pages and in the footer.
- On authentication pages, users must select the checkbox to agree to the configured documents.
- Clearing a field removes its link and disables the corresponding consent requirement.

<Callout type="info" title="Tip">
Use this feature to publish the current document content or an external link. Handle document versioning, signature records, and historical retention separately. If you need auditable agreement versions and a way to request consent again, set up those processes outside New API.
</Callout>

### System Announcement

- Site and Branding – System Announcement

![Site and Branding – System Announcement page](/assets/guide/feature-guide/system-settings-site-brand-system-announcement.png)

The system announcement appears in the **Notifications** tab of the notification center whenever the content field is populated. There is no separate toggle.

**Steps**

1. Enter the announcement in **Announcement Content**.
2. Click **Save Notification** in the page header.
3. To take down the announcement, clear **Announcement Content** and save.

<Callout type="info" title="Tip">
  **System Announcement** and **Console Content › Announcements** serve separate purposes. Use **System Announcement** for a single global notice and **Console Content › Announcements** for a structured list whose entries can be enabled or disabled.
</Callout>

### Top Navigation

- Site and Branding – Top Navigation

![Site and Branding – Top Navigation page](/assets/guide/feature-guide/system-settings-site-brand-top-navigation.png)

**Steps**

1. Turn each item’s visibility toggle on or off.
2. To require visitors to sign in before accessing **Model Marketplace** or **Leaderboard**, turn on **Require Sign-in to View Models** or **Require Sign-in to View the Leaderboard**, respectively.
3. Click **Save Navigation** in the page header.

<Callout type="info" title="Tip">

- You can change a subordinate toggle only when its parent item is enabled.
- The **Docs** item opens the **Documentation Link** configured in **System Information**.
- **Reset to Defaults** in the page header restores the form so that all items are visible and none require sign-in. Click **Save Navigation** to apply the defaults.

</Callout>

| Home | Landing page with a system overview. | Toggle. | On |
| Console | User dashboard and quota controls. | Toggle. | On |
| Docs | Documentation or an external knowledge base. | Toggle. | On |

### Sidebar Modules

- Site and Branding – Sidebar Modules

![Site and Branding – Sidebar Modules page](/assets/guide/feature-guide/system-settings-site-brand-sidebar-module.png)

Control which built-in sidebar items appear by toggling areas and individual modules.

**Steps**

1. Turn each area toggle on or off.
2. Within each enabled area, turn individual modules on or off.
3. Click **Save Sidebar Modules** in the page header.

<Callout type="info" title="Tip">

- Turning off an entire area disables all module toggles in that area. When you turn the area back on, each module’s own toggle determines whether it appears.
- **Reset to Defaults** in the page header enables all options in the form. Click **Save Sidebar Modules** to apply the defaults.
- These settings determine which modules are available to display. Users with permission to customize their sidebar can further hide available modules in **Chat**, **Console**, and **Personal Center**. **Admin** modules follow the site-wide settings.
- Personal sidebar settings do not apply to Root.

</Callout>

**Modules**

| Console | Dashboard, Tokens, and usage analytics. | Dashboard, Token Management, Usage Logs, Audit Logs, Drawing Logs, Task Logs |
| Personal Center | Wallet management and personal preferences. | Wallet, Profile, Security and Access |

## Saving Changes and When They Take Effect

For save behavior, see <a href="/en/docs/guide/feature-guide/system-settings/system-setting#save-methods" target="_blank" rel="noopener noreferrer">System Settings Overview</a>. For activation and synchronization rules, see <a href="/en/docs/guide/feature-guide/system-settings/system-setting#scope-and-multi-instance-synchronization" target="_blank" rel="noopener noreferrer">Scope and Multi-Instance Synchronization</a>. For when browsers display new values, see <a href="/en/docs/guide/feature-guide/system-settings/system-setting#frontend-display-and-caching" target="_blank" rel="noopener noreferrer">Frontend Display and Caching</a>.

Unless otherwise noted, the node that handles the save request uses the new values immediately. Other nodes pick up the changes through system settings synchronization in about 3 seconds, or within one synchronization interval at most. The `SYNC_FREQUENCY` environment variable sets the interval in seconds and defaults to 60. Restart New API after changing it. The tables below show when each setting reads the new value.

**Branding, addresses, and page content**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| Setting | How to save | When changes take effect |
| --- | --- | --- |
| System Name, Logo URL, Footer, Documentation Link | Click **Save Changes** in the page header to submit only modified fields. **Reset** restores the form. | New values appear after a page refresh, including in the browser used to save the changes. |
| Server Address | Click **Save Changes** in the page header. The trailing `/` is removed before submission. | The next request that uses the address picks up the new value. The browser used to save the changes updates automatically. |
| Public Address for Asynchronous Tasks | Click **Save Changes** in the page header. The trailing `/` is removed before submission. The server validates the format if the field is populated. | Subsequent task queries return output URLs generated from the new address. Previously issued URLs keep their original address. |
| About | Click **Save Changes** in the page header. | The new content loads the next time the About page opens. |
| Home Page Content | Click **Save Changes** in the page header. | The next time the home page opens, it first shows the browser’s cached content, then automatically updates to the latest content. To restore the built-in home page, clear the field. |
| User Agreement, Privacy Policy | Click **Save Changes** in the page header. | Document content loads when opened and remains cached for about 10 minutes if the page is not refreshed. Links on the sign-in and registration pages and in the footer update after a page refresh. |

</div>

**Announcement, navigation, and sidebar**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Setting | How to save | When changes take effect |
| --- | --- | --- |
| System Announcement | **Save Notification** saves the entire announcement. | The browser caches the system announcement shown in the notification center. Refresh the page to load the new content. Any content change marks the announcement as unread again. |
| Top Navigation | **Save Navigation** saves the entire configuration. **Reset to Defaults** only resets the form. | The browser used to save the changes updates automatically. Other browsers update after a page refresh. The server enforces the visibility and sign-in settings for **Model Marketplace** and **Leaderboard** starting with the next request. |
| Sidebar Modules | **Save Sidebar Modules** saves the entire configuration. **Reset to Defaults** only resets the form. | The browser used to save the changes updates automatically. Other browsers update after a page refresh. These settings affect sidebar visibility only. |

</div>

**Additional details**

- **Saving individual fields.** **System Information** submits only modified fields. Each successful field update displays “Settings updated successfully.” If you made no changes, the interface displays “No changes to save.”
- **Saving entire configurations.** **System Announcement**, **Top Navigation**, and **Sidebar Modules** each save their entire configuration. If you made no changes, the interface skips submission and displays no message.
- **Unsaved changes.** If you leave **System Information** with unsaved changes, the **Unsaved Changes** dialog lets you choose **Leave** or **Stay**.

## Important Notes

- **The footer renders raw HTML.** Keep untrusted scripts, event handler attributes, and third-party injection code out of the footer.
- **HTML embedded in the About page, home page, or legal documents.** DOMPurify removes tags such as `<script>` and prevents scripts from running. Isolation and sandboxing also restrict styles and iframe behavior. Avoid relying on arbitrary scripts.
- **Embedding external URLs.** A remote site may fail to display because of `X-Frame-Options`, CSP, mixed content, or certificate issues. New API respects these browser and remote-site restrictions.
- **Menu visibility and access.** Hiding **Home**, **Console**, **Docs**, **About**, or a sidebar module still allows direct access by URL. Disabling **Model Marketplace** blocks requests for model pricing data except for Root. Disabling **Leaderboard** blocks requests for leaderboard data. Enabling **Require Sign-in to View Models** or **Require Sign-in to View the Leaderboard** blocks unauthenticated access to the corresponding data.
- **Public Address for Asynchronous Tasks.** This address is used only for task output URLs and must be reachable over the public internet. In a multi-instance deployment, set the same `CRYPTO_SECRET` on every node. If `CRYPTO_SECRET` is unset, New API uses `SESSION_SECRET`. If both are unset, New API generates a random secret at each startup, so previously issued output URLs fail validation after a restart.

<Accordion title="Public Address for Asynchronous Tasks reports an invalid address format">

**Validation message**  
“Enter an absolute HTTP(S) URL without credentials, query parameters, or fragments.”

**Possible causes**  
The address may lack an `http://` or `https://` prefix, or it may contain query parameters (`?`), a fragment (`#`), user information (`@`), control characters, backslashes, or leading or trailing whitespace.

**How to fix it**

1. Use an absolute URL. It can include a port and a path prefix, as in `https://media.example.com/prefix`.
2. If you do not need a separate address, leave the field blank to use the **Server Address**.

</Accordion>

<Accordion title="The page still shows the old system name, logo, or footer after saving">

**Cause**  
The browser used to save the changes does not automatically reload site information it has already loaded.

**How to fix it**

1. Refresh the page.
2. In a multi-instance deployment, wait a few seconds and refresh again. If the old value persists, allow up to one synchronization interval (60 seconds by default).

</Accordion>

<Accordion title="Sidebar items differ from what you expect for some accounts after saving Sidebar Modules">

**Cause**  
The site-wide settings determine which items can appear. Users can hide additional items in their profile.

**Possible causes**

- The account hid the module under **Personal Sidebar Settings** in its profile.
- The module’s entire area is disabled on this page.

**How to fix it**

1. Check the area and module toggles on this page.
2. Ask the user to check their sidebar settings in <a href="/en/docs/guide/feature-guide/user/personal-setting#choose-which-pages-appear-in-the-left-sidebar" target="_blank" rel="noopener noreferrer">Profile</a>.

</Accordion>
