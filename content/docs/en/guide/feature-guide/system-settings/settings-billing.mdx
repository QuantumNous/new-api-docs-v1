### Quota Settings

- Billing and Payments → Quota Settings

![Billing and Payments – Quota Settings page](/assets/guide/feature-guide/system-settings-billing-and-payments-quota-settings.png)

**Steps**

1. Convert the amount you want to enter to quota points. At the default conversion rate, `500000` quota points equal `$1`.
2. Set the new user quota, wallet pre-deduction exemption threshold, input pre-deduction ratio, and free model quota pre-consumption.
3. To offer referral rewards, first accept the compliance terms under [Payment Compliance Confirmation](#payment-compliance-confirmation).
4. Set the referrer and invitee rewards.
5. Enter the top-up link.
6. Click “Save Changes” at the top of the page.

<Callout type="warn" title="Warning">

- Until you confirm payment compliance, a red warning appears above the form. “Nonzero referral rewards require you to accept the compliance terms in Payment Gateway settings first.”
- Saving a referral reward greater than `0` is blocked until you confirm payment compliance. For the exact message, see [Frequently Asked Questions](#frequently-asked-questions).

</Callout>

**Configuration Fields**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| Field | Definition | Requirements and Limits | Default |
| --- | --- | --- | --- |
| New User Quota | Initial quota granted only to newly registered users. | Enter a nonnegative integer in quota points. The help text shows the converted amount as you type. | `0` |
| Wallet Pre-deduction Exemption Threshold (USD) | When both the user's wallet balance and the balance of an API Token with a quota limit exceed this amount, the system skips pre-deduction and charges for actual usage. Set the threshold to `0` to always apply pre-deduction. Subscriptions and asynchronous tasks always use pre-deduction. | Enter a number greater than or equal to `0`. Decimals are allowed. Negative values trigger “Must be greater than or equal to 0.” | `10` |
| Input Pre-deduction Ratio | The system multiplies the estimated input cost by this ratio to calculate the pre-deduction. The estimate excludes output Tokens. The final charge is based on actual usage. This setting applies only to usage-based billing and leaves per-request and task billing unchanged. | Enter a number greater than `0`. Decimals are allowed. Values outside this range trigger “Must be greater than 0.” | `1` |
| Referrer Reward | Quota granted to the referrer after a qualifying referral signup. The reward is first credited to the referrer's referral quota. It enters the wallet balance when the referrer clicks “Transfer to Balance” in their wallet. | Enter a nonnegative integer in quota points. Values greater than `0` require payment compliance confirmation. | `0` |
| Invitee Reward | Quota granted to the invitee. | Enter a nonnegative integer in quota points. Values greater than `0` require payment compliance confirmation. | `0` |
| Free Model Quota Pre-consumption | When enabled, zero-cost models also consume quota in advance of final settlement. | Toggle. | Enabled |
| Top-up Link | External link where users can purchase quota. Connecting it to this site's payment callbacks requires separate integration. | Optional. Enter a full URL such as `https://example.com/topup`. | Blank |

### Currency and Display

- Billing and Payments → Currency and Display

![Billing and Payments – Currency and Display page](/assets/guide/feature-guide/system-settings-billing-and-payments-currency-and-display.png)

**Steps**

1. Under “Display Mode”, select “USD”, “CNY”, or “Custom Currency”.
2. If you select “Custom Currency”, enter the “Custom Currency Symbol” and “Units per USD”.
3. Enter the “USD Exchange Rate” and turn “Show Token Statistics” on or off as needed.
4. Click “Save Changes” at the top of the page.

<Callout type="info" title="Tip">

- At the default conversion rate, `500000` internal quota points equal `$1`.
- “Reset” at the top of the page restores the saved values and displays “Form reset to saved values.” The button is available only when the form has unsaved changes.

</Callout>

### Model Pricing

The page header has four tabs on the right: “Model Prices,” “Models Without Prices,” “Tool Prices,” and “Upstream Price Sync.” “Model Prices” opens by default. You can configure billing modes, prices for different types of usage, billing expressions, and tool call prices. You can also set prices for unpriced models and sync upstream prices.

#### Model Prices

![Billing and Payments → Model Pricing → Model Prices page](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-model-prices.png)

The model list is on the left, and the editor is on the right. If no model is selected, the editor displays “Select a model to edit its pricing.” The list includes only models with configured prices and models with built-in prices that enabled Channels currently use. The list does not automatically add models to Channels. The price configuration should match the model identifier used in requests and the billing path actually used.

**Add or edit model pricing**

1. Click “Add Model” on the right side of the toolbar, or click the edit icon in a model row. When adding a model, enter its exact name. The model name cannot be changed directly when editing.
2. Select the pricing currency and billing mode, then set the price or expression. For instructions on using the editor, see <a href="/en/docs/guide/feature-guide/admin/billing-expression" target="_blank" rel="noopener noreferrer">Billing Expressions</a>.

4. If the pricing includes request conditions, enter the request body, headers, and time in “Request Simulation.”
5. Click “Save Model Prices.”
6. In “Confirm Price Changes,” review the “Current Price” and “Price After Saving” for each model, then click “Confirm Save.”

#### Pricing Pending Review

When a task model provided by a plugin cannot be billed, the model price list flags it. The sidebar entry “System Settings” and the left navigation entries “Billing and Payments” and “Model Pricing” also show the number of models pending review. For task model billing rules, see <a href="/en/docs/guide/feature-guide/admin/billing-expression#task-models" target="_blank" rel="noopener noreferrer">Billing Expressions</a>.

**Models included in the count**

- Models currently available through enabled Channels.
- Models that a plugin no longer provides but that still have saved prices.
- Models from disabled plugins retain their prices and are excluded from the count.

**Resolve pricing issues**

1. Click “Review Prices” in the “… models have prices that need review” notice at the top of the “Model Prices” tab, or select “Pricing Pending Review” from the toolbar’s “Price Status” filter.
2. Select a model. Under “Required Changes” at the top of the editor, review the reason and resolution for each plugin.
3. Follow the steps in the table below, then click “Save Model Prices” and confirm.

<Callout type="info" title="Note">

- “Review Prices” lists only models pending review and opens the editor for the first model. Click “Show All Models” to restore the full list.
- The review notice appears only on the “Model Prices” tab.
- “Pricing Pending Review” appears next to the model name, with “Plugin Name: Reason” in gray text below it.
- If uploading, installing, enabling, or changing the version of a plugin makes any models unbillable, the plugin management page also displays “Pricing for the following models needs review:”.
</Callout>

**Reasons and resolutions**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Reason | Resolution |
| --- | --- |
| No price has been set | Select the relevant plugin below, set a price for the model, and save. |
| The price uses a usage metric the plugin no longer provides | Select the relevant plugin below, reconfigure the price using the current billing fields, and save. |
| The plugin no longer provides this model | Select the relevant plugin below, remove the saved price, and save your changes. |

</div>

#### Models Without Prices

- Billing and Payments → Model Pricing → Models Without Prices

![Billing and Payments → Model Pricing → Models Without Prices page](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-models-without-prices.png)

This tab lists models on enabled Channels that have no configured prices. It uses the models available through those Channels and the current pricing snapshot to determine which models to show. It uses the same list layout as “Model Prices,” with the “Add Model” and delete actions unavailable.

**Set model prices**

1. Click the edit icon in a model row and set the price in the editor on the right.
2. To set prices in bulk, open a source model whose pricing you have verified in the editor on the right. Select the target models, then click “Copy … Pricing” in the floating bar at the bottom.
3. Check each target model for differences in protocol, caching, and media billing.
4. Click “Save Model Prices” at the bottom of the editor, then click “Confirm Save” in “Confirm Price Changes.”

<Callout type="info" title="Note">

- This tab shares a draft with “Model Prices.” Click “Save Model Prices” to persist changes made on either tab.
- The page header controls are available on the “Model Prices” tab. Use that tab to access “Expose Ratio API,” “Reset Prices,” and “Switch to JSON.”
- If all models have prices, the interface displays “No models without prices.”
- If the enabled models fail to load, the interface displays “Failed to fetch enabled models.”
</Callout>

#### Tool Prices

- Billing and Payments → Model Pricing → Tool Prices

![Billing and Payments → Model Pricing → Tool Prices page](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-tool-prices.png)

Configure call prices for tools such as search, file retrieval, and image generation in one place. These prices determine the surcharges for tool calls.

**Set tool prices**

1. Choose the scope. Use a generic tool identifier for all models, or use `tool_name:model_prefix*` for a specific model family.
2. Edit an existing row, or click “Add” and enter the tool identifier and price. Enter the price in USD per 1,000 calls.
3. Use the target model name to identify the longest matching prefix rule, then calculate the base cost per call.
4. Click “Save Tool Prices” at the bottom right of the tab.

<Callout type="info" title="Note">

- Surcharge for one tool = price (USD per 1,000 calls) × billable calls ÷ 1,000 × Group Ratio.
- Total tool surcharge = the sum of the surcharges for all tools.
- Models billed per request incur no additional tool charges.
</Callout>

#### Upstream Price Sync

- Billing and Payments → Model Pricing → Upstream Price Sync

![Billing and Payments → Model Pricing → Upstream Price Sync page](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-upstream-price-sync.png)

Fetch model prices from presets or upstream Channels and compare them with the local configuration. Select a price source for each model, then preview and confirm the changes to update the local billing configuration in bulk.

**Sync upstream prices**

1. Click “Select Price Sources,” then search for and select one or more presets or Channels.
2. Verify the API addresses and sync endpoints. You can keep the defaults when using a preset.
3. Click “Confirm Selection” and wait for the comparison results.
4. Use the model search, type filter, and pagination to find the target models.
5. Select the source for each target model, or use the source column header to select multiple models at once.
6. Review the selection count at the bottom, then click “Apply Sync.”
7. In “Preview Price Changes,” review “Price Source,” “Model,” “Current Billing,” and “Final Price to Save.”
8. Click “Confirm Changes.”

- Individual developers can launch quickly and focus on their products while Pancake handles compliance. Onboarding takes minutes, from a single prompt to a complete integration.

</Callout>

4. To create a new store and product, first enter the payment return URL, then click “+ Create ….”

<Callout type="info" title="Tip">

- If you create a product with the payment return URL blank, the browser asks “The payment return URL is empty. Create the product without a SuccessURL redirect?”

**Additional Notes**

- **Saving individual settings.** “Save Changes,” “Save Group Settings,” “Save All Settings,” and “Save Check-in Settings” submit only modified settings. Each successful update displays “Settings updated successfully.” With no changes, “Save Group Settings” shows no message, while the other save actions show “No changes to save.”
- **Unsaved changes.** If you leave the page with unsaved changes under Quota Settings or Currency and Display, the “Unsaved Changes” dialog lets you choose “Leave” or “Stay.”
- **Model pricing confirmation and messages.** If pricing has changed, confirm the changes in “Confirm Pricing Changes” first. A successful save displays “Model pricing saved.” If there are no changes, the message is “No model pricing changes to save.”
- **Pricing changed by someone else.** If someone else changes the same model’s pricing after you open the page, the system rejects your save. Click “Reload Pricing” and reapply your changes.
- **Changing the EPay signature method.** In a single save, the system writes the private and public keys before writing the signature method. If the signature method is RSA and a required key cannot be parsed, the system rejects the save and displays either “EPay merchant private key is missing or incorrectly formatted” or “EPay platform public key is missing or incorrectly formatted.”

## Important Considerations

- **“Reset Pricing” clears all custom prices**, including billing expressions. See [Model Pricing](#model-prices).
- **Estimates and actual charges can differ.** The Token Estimator excludes request rules and Group Ratios. Check the Usage Logs for actual charges.
- **Wallet credit depends on the payment notification.** The wallet is credited when the payment gateway sends a payment notification to the site. Returning to the site after completing payment does not trigger the credit. For gateway requirements, see [Payment Gateways](#payment-gateway).

<Accordion title="Why did the price stay the same after I saved?">

**Possible causes**

- The changes are still a draft awaiting final confirmation.
- The model name, active mode, provider override, or pricing snapshot taken at the start of the request differs from what you expected.

</Accordion>

<Accordion title="Does removing a price make it free?">

**Explanation**

Removing an override may restore the default price. Tool pricing may also match a more specific prefix. An explicit zero, an unset price, and a deleted price are distinct states.

</Accordion>

<Accordion title="Why can't I access the public pricing endpoint?">

**Explanation**

The current endpoint path is `/api/ratio_config`.

**Possible cause**

“Expose Ratio Endpoint” is turned off.

</Accordion>

<Accordion title="Why doesn't the discount for 100 apply to 200?">

**Explanation**

Discounts require an exact match on the original amount. A discount configured for 100 applies only to 100.

</Accordion>

<Accordion title="Why does the Stripe quote differ from the checkout page?">

**Possible causes**

- The Stripe Price currency, unit price, or quantity differs from what you expected.
- The local unit price, top-up Ratio, discounts, and Stripe promotion codes may have been conflated.

</Accordion>

<Accordion title="Why doesn't a Creem product Quota of 1 credit 1 USD?">

**Explanation**

This field uses internal Quota points. At the default conversion rate, 1 USD corresponds to 500,000 Quota units.

</Accordion>

<Accordion title="Does an empty key field mean the key is unset?">

**Explanation**

A key may already be configured even if the field is blank. For the general rules on how key fields are displayed, see <a href="/en/docs/guide/feature-guide/system-settings/system-setting#sensitive-settings-and-audit-logs" target="_blank" rel="noopener noreferrer">Sensitive Configuration and Audit Records</a>. Clearing the Waffo public key field and saving removes the existing key. A blank private key field retains its existing value.

</Accordion>

<Accordion title="Why can't a user select a particular Group?">

**Possible causes**

- The public list of available Groups, special rules, the account’s own Group, Ratio settings, or Token restrictions prevent the user from selecting the Group.
- The user is using Auto, but `auto` is unavailable.

</Accordion>

<Accordion title="Why is Pancake still unconfigured after successful creation?">

**Explanation**

Creating the external resource, selecting it, and saving the local binding are three separate steps.

**Resolution**

Verify the selected store and product, then click “Save All Settings” to save the binding.

</Accordion>

<Accordion title="Why is the check-in reward always the minimum?">

**Possible causes**

- The maximum is less than or equal to the minimum.
- The values were entered in a unit other than Quota points.

</Accordion>

<Accordion title="Why does saving invitation rewards show a feature-disabled message?">

**Message**

“Payment, redemption, subscription, and invitation reward features are disabled. The administrator must confirm compliance terms before enabling them.”

**Possible cause**

Payment compliance has yet to be confirmed, and either “Referrer Reward” or “Invitee Reward” is set to a value greater than `0`.

**Resolution**

1. Have a Root user confirm the compliance terms under “Payment Gateways.” See [Payment Compliance Confirmation](#payment-compliance-confirmation).
2. Return to “Quota Settings” and save again.

</Accordion>

<Accordion title="Why does saving model pricing show a message that the pricing has changed?">

**Message**

The message includes `model pricing changed; reload before saving` (English only).

**Possible cause**

After you opened the page, someone else changed pricing for the same model, or it was changed in another window.

**Resolution**

1. Click “Reload Pricing.”
2. Reapply your changes and save.

</Accordion>
