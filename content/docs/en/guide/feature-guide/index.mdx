New API is a unified system for managing and distributing access to AI model APIs. It lets you call different large models through a common interface and supports formats such as OpenAI and Claude. Individuals and organizations can use it to manage channels and distribute access internally. Features include a playground, an OpenAI-compatible API, model and channel routing, usage logs, billing, subscriptions, and system operations.

- This guide is organized by role and function into three sections: the User Guide, the Administrator Guide, and the System Settings Guide.

### Account Roles

The platform controls menu access and permitted actions based on the account role. There are three roles:

- **Standard User** <br/>
This is the default role after registration. Standard users can access the personal features enabled on the platform, such as the playground, chat, overview, dashboard, API keys, usage logs, audit logs, task logs, wallet, profile, and security and access settings.<br/>The super administrator (Root) controls which entries appear in the top navigation and sidebar and whether features such as daily check-in are available. [Site and Branding Configuration →](/en/docs/guide/feature-guide/system-settings/settings-site)

- **Administrator (Admin)** <br/>
In addition to standard user permissions, Admin accounts have default access to resources for managing channels, models, users, redemption codes, and subscriptions.<br/>For resources such as channels, permissions distinguish between reading, running operations, making standard or sensitive changes, and viewing keys. The super administrator (Root) can override the defaults for an Admin account under “Administrator Permissions” in User Management. [Administrator Permissions →](/en/docs/guide/feature-guide/admin/user#administrator-permissions)

- **Super Administrator (Root)** <br/>
Root has all permissions, including access to **System Information**, **Plugins**, **Request Processing**, and **System Settings**, and can modify model prices.<br/>System settings are divided into eight areas: Site and Branding, Authentication, Billing and Payments, Models, Request Policies, Security and Limits, Console Content, and Operations. [System Settings Overview →](/en/docs/guide/feature-guide/system-settings/system-setting)

## Administrator Guide

This guide covers nine pages that Admin and Root use for routine administration. Billing Expressions, System Information, Plugin Management, and Request Processing are available only to Root. Instance-wide options are covered separately in the System Settings Guide below.

### Billing Expressions (Root Only)

Use billing expressions in the pricing editor to define per-token prices, pricing tier conditions, per-request prices, and request rules for a model. Verify pricing with cost estimates and simulated requests, and learn how pre-charging, settlement, and validation on save work.

[View detailed documentation →](/en/docs/guide/feature-guide/admin/billing-expression)

### Channel Management

Configure AI providers, plugins, gateways, and custom channels. Manage credentials, models, groups, routing mappings, and priorities. Use multiple keys and parameter overrides, run tests, check balances, update upstream models, and perform bulk operations.

[View detailed documentation →](/en/docs/guide/feature-guide/admin/channel)

### Model Management

Manage model metadata, name matching, model marketplace listings, providers, and prefill groups. Sync model metadata from upstream providers. Root can also edit model pricing and sync prices. If the deployment service is configured, you can also manage io.net model deployments.

[View detailed documentation →](/en/docs/guide/feature-guide/admin/model)

### User Management

View and manage user accounts, account status, roles, groups, quotas, linked sign-in methods, subscriptions, passkeys, and two-factor authentication (2FA). Root can set “Administrator Permissions” for Admin accounts.

[View detailed documentation →](/en/docs/guide/feature-guide/admin/user)

### Redemption Code Management

Create, view, edit, enable, disable, and delete quota redemption codes. Copy or delete codes in bulk, or remove invalid codes. When creating codes, you can save them to a TXT or Markdown file.

[View detailed documentation →](/en/docs/guide/feature-guide/admin/redemption)

### Subscription Management

Create and maintain subscription plans. Configure validity periods, quota reset intervals, group upgrades and reversions, and payment methods. Enable or disable plans and reset subscription quotas in bulk.

[View detailed documentation →](/en/docs/guide/feature-guide/admin/subscription)

### System Information (Root Only)

View instance node status, resource metrics, synchronization status for each node, and background system tasks. Remove records for unreachable instances and clear historical system tasks.

[View detailed documentation →](/en/docs/guide/feature-guide/admin/system-info)

### Plugin Management (Root Only)

Manage three types of plugins: task, channel, and request processing plugins. Browse the official and community plugin marketplaces, upload local plugins, inspect plugin details and sandboxes, enable or disable plugins, and manage their channel bindings.

[View detailed documentation →](/en/docs/guide/feature-guide/admin/task-plugins)

### Request Processing (Root Only)

Inspect or modify requests before they are sent upstream. Add a request processing instance, set its scope, target models, and execution order, test it with a sample request, and add it to a channel.

[View detailed documentation →](/en/docs/guide/feature-guide/admin/request-processing)

Groups are a shared routing and billing dimension used by channels, users, API keys, and billing settings. They no longer have a separate entry in the main navigation. For model calls and charges, see [Usage Logs](/en/docs/guide/feature-guide/user/log). For image generation records and users’ asynchronous tasks, see [Task Logs](/en/docs/guide/feature-guide/user/task-log).
