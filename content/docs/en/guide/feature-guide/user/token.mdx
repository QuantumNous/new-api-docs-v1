## Create an API Key

- API Keys – Create API Key

![Create API Key page](/assets/guide/feature-guide/general-api-key-create.png)

**Steps**

1. Click “Create API Key” in the upper-right corner of the page.
2. Enter a key name that identifies the app or environment.
3. Configure the quota, expiration time, model restrictions, IP restrictions, group, and other settings as needed.
4. Click “Save Changes”.

**Configuration options**

The dialog has three sections: “Basic Information”, “Quota Settings”, and “Advanced Settings”. “Advanced Settings” is collapsed by default. Click its heading to expand it. The table lists the options in the order they appear in the dialog.

| --- | --- | --- | --- | --- |
| Name | Basic Information | The key name, used to identify its purpose or environment. | Required. Include the name of the app or environment that uses the key. The limit is 50 English characters or approximately 16 Chinese characters. If you exceed the limit, the dialog displays “Token name is too long”. | Blank |
| Group | Basic Information | The group used for model calls, which determines available routes and billing ratios. | Optional. The dropdown lists only groups your account has access to, along with each group’s description and ratio. ## Copy a Key and Call a Model

**Steps**

1. In the key’s row, click the copy button next to the key in the “API Key” column.
2. Paste the key into your client.
3. Click “API Address” in the upper-right corner of the page.
4. Use the descriptions to choose an API address, then click the copy button next to it.
5. Paste the API address into your client.

**Calling models**

1. In a client, the API address usually comes without `/v1`. Most OpenAI-compatible clients expect the API address followed by `/v1` in the Base URL field. Check your client’s documentation.
2. For a direct request, append the endpoint path to the API address. The example below uses `/v1/chat/completions` for the chat endpoint.

```bash
curl https://your-host/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-xxxxxxxx" \
  -d '{"model":"模型名称","messages":[{"role":"user","content":"你好"}]}'
```

- Replace `https://your-host` with the API address you copied, `sk-xxxxxxxx` with your API key, and `模型名称` with an available model name.<br/>This command works in macOS and Linux terminals and in Git Bash on Windows.
- To see which models the key can call, send a request to the API address with `/v1/models` appended. See <a href="/en/docs/api/ai-model/models/list/listmodels" target="_blank" rel="noopener noreferrer">List Models (Native OpenAI Format)</a>.<br/>For other endpoints and parameters, see the API documentation, including <a href="/en/docs/api/ai-model/chat/openai/createchatcompletion" target="_blank" rel="noopener noreferrer">ChatCompletions Format</a>.

<Callout type="warn" title="Keep Your API Key Secure">

  - Anyone who obtains your API key can use it to consume your account quota.
  - Do not share your key in group chats or include it in screenshots or public code repositories.
  - If you suspect a key has been exposed, delete it immediately and create a new one.
</Callout>

## Import into CC Switch or a Chat App

- API Keys – Import into CC Switch

![Import into CC Switch page](/assets/guide/feature-guide/general-api-key-import-cc-switch.png)

<a href="/en/docs/apps/cc-switch" target="_blank" rel="noopener noreferrer">CC Switch</a> is a desktop tool for managing Claude Code, Codex, and Gemini CLI configurations. Install it on your computer before using this feature.

**Import into CC Switch**

1. Open the ⋯ menu at the end of the key’s row and select “CC Switch” from the main menu to open the “Import into CC Switch” dialog.
2. Under “App”, select Claude, Codex, or Gemini.
3. Enter the configuration details as needed.
4. Click “Open CC Switch”.
5. Your browser prompts you to open CC Switch. After you confirm, CC Switch imports the API address, selected key, and model configuration.

**Import into another chat app**

1. Click ⋯ at the end of the selected key’s row to open the menu.
2. Under “Chat”, select the chat app you want to import the configuration into.

<Callout type="info" title="Tip">

- Web apps open in a new tab. Install desktop apps and browser extensions first so the browser can launch them or pass the key to them directly.
- “Chat” in the sidebar automatically uses the most recently created enabled key.
</Callout>

## Edit, Disable, or Delete a Key

- API Keys – Update API Key

![Update API Key page](/assets/guide/feature-guide/general-api-key-update.png)

**Edit a key**

1. Click the edit icon in the key’s row.
2. Change the settings in the “Update API Key” dialog as needed.
3. Click “Save Changes”.

**Disable or enable a key**

1. Click the power icon in the key’s row. The icon shows “Disable” for enabled keys and “Enable” for keys in all other states.
2. The change takes effect immediately without a confirmation dialog.

<Callout type="info" title="Tip">
You cannot directly enable keys marked “Expired” or “Exhausted”. See [API Key Status](#api-key-status) for instructions.
</Callout>

**Delete a key**

1. Click ⋯ at the end of the key’s row and select “Delete”.
2. Check the key name and click “Delete”. To delete multiple keys at once, see [Bulk Actions](#bulk-actions).

<Callout type="warn" title="Warning">
  Deletion is permanent. Programs and clients using the key will immediately lose the ability to call models with it. To suspend a key temporarily, select “Disable”.
</Callout>

**Configuration options**

The “Update API Key” dialog has the same options as the creation dialog and opens with the key’s current settings. For option definitions, requirements, limits, and defaults, see [Create API Key Configuration Options](#create-api-key-configuration-options). The table below lists the options that behave differently when you update a key.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Option | “Create API Key” dialog | “Update API Key” dialog |
| --- | --- | --- |
| Quantity | Shown with a default of 1. You can create multiple keys at once. | Hidden. You can edit one key at a time. |
| Group | No group is selected by default. Some sites select `auto` by default. | Shows the key’s current group. If that group is no longer available, the dialog automatically selects an available group when it opens. The change takes effect when you save. |
| Expiration Time, Quota (…) | The values you enter take effect when you save. | After changing these settings for an “Expired” or “Exhausted” key, select “Enable” in the list to reactivate it. |
</div>

<Callout type="info" title="Tip">

- To replace a key, create a new key and delete the old one. To enable or disable a key, use the power icon in its row.
</Callout>

## Frequently Asked Questions

<Accordion title="A request returns “Invalid token”">
**Error message** — “Invalid token”

**Possible causes** — The request may be missing an API key, or the key may be incorrect, deleted, disabled, expired, or out of Quota. All of these cases return the same error message.

**How to resolve**

1. Copy the key again from the list. Make sure the request header is `Authorization: Bearer sk-…` with no extra spaces or line breaks before or after the key.
2. In the “Status” column, verify that the key is “Enabled.” Check the “Expiration” and “Quota” columns to confirm that the key is still valid and has Quota remaining. For troubleshooting steps, see [API Key Status](#api-key-status).
3. Make sure you are using an API key. Access Tokens created under “Security & Access” are for account management only. Model requests require an API key. See <a href="/en/docs/guide/feature-guide/user/security#create-and-manage-access-tokens" target="_blank" rel="noopener noreferrer">Security & Access</a>.
4. If the issue persists, create a new key and try again, or contact your administrator.
</Accordion>

<Accordion title="A request returns “This token has no access to model …”">
**Error message** — “This token has no access to model …”

**Possible cause** — The key has “Model Restrictions” enabled, and the requested model is outside the allowed set.

**How to resolve**

1. Edit the key and expand “Advanced Settings.”
2. Add the model to “Model Restrictions,” or clear “Model Restrictions” to allow requests to all available models.
3. Click “Save Changes.”
</Accordion>

<Accordion title="A request returns “Your IP address is not on this token's allowlist”">
**Error message** — “Your IP address is not on this token's allowlist”

**Possible causes**

- The key has an “IP Allowlist,” and the request is coming from an address outside that list. If you send the request through a proxy, the egress IP address may differ from your machine’s IP address.
- The allowlist contains incorrectly formatted entries. The system ignores invalid entries. If every entry is invalid, requests using the key are blocked from all addresses.

**How to resolve**

1. Edit the key and open “Advanced Settings.” Under “IP Allowlist,” add the machine’s egress IP address or subnet, with one entry per line.
2. If you cannot identify the invalid entry, clear the allowlist and add the entries back one at a time.
3. Click “Save Changes.”
</Accordion>

<Accordion title="A request returns a Group access or deprecation error">
**Error message** — “No permission to access group …” or “Group … has been deprecated”

**Possible cause** — The Group assigned to the key is no longer available. For example, an administrator may have changed the Group settings.

**How to resolve**

1. Edit the key. When you open the edit dialog, the “Group” field may already show an available Group selected automatically.
2. Verify that the selected “Group” is available in the drop-down list.
3. Click “Save Changes.”
</Accordion>

<Accordion title="A request returns an insufficient Quota error, including for keys with “Unlimited Quota” enabled">
**Note** — “Unlimited Quota” removes the usage limit for the key itself. Requests still draw from your account Quota. Use the exact error message to identify the cause.

| Error message | Possible cause | How to resolve |
| --- | --- | --- |
| “Insufficient user quota”<br/>“Not enough quota to pre-consume” | Your account balance is too low. “Not enough quota to pre-consume” means the balance is below the estimated cost of the request. Longer inputs, higher model prices, and higher Group Ratios increase the estimate. | Top up your balance or redeem Quota in your <a href="/en/docs/guide/feature-guide/user/wallet" target="_blank" rel="noopener noreferrer">Wallet</a>. |
| “Subscription quota is insufficient or no subscription is configured” | The request is billed against a subscription, but the subscription has insufficient Quota or no subscription is available. | Check your subscription in your <a href="/en/docs/guide/feature-guide/user/wallet#subscription-plans" target="_blank" rel="noopener noreferrer">Wallet</a>. |
| token quota is not enough (English only) | The key has a usage limit, and its remaining Quota is too low to cover the request. | Edit the key and increase its “Quota.” |
</Accordion>

</Accordions>
