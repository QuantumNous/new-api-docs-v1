- In the sidebar, go to “General” → “Task Logs”.
- View the status, progress, results, and failure reasons for asynchronous tasks such as video, music, and image generation.
- The page has two tabs, “Drawing Logs” and “Task Logs”. The “Task Logs” tab opens by default when you enter from the sidebar.

<Callout type="info" title="Tip">

- Asynchronous tasks take time to produce results after submission. Examples include video and music generation and Midjourney image generation. When a submission succeeds, the system returns a task ID, then periodically checks and updates the task status in the background.
- Regular users can only view tasks from their own accounts. Administrators can switch between “All” and “Only Me” in the upper-right corner of the page. This toggle is visible only to administrators. “Only Me” shows the same content that regular users see.
- To view charges and refunds for tasks, see <a href="/en/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">Usage Logs</a>.
- If “Task Logs” is missing from the left sidebar or the “Drawing Logs” and “Task Logs” tabs are missing from the page, open “Profile” and go to “Personal Sidebar Settings”. Enable “Console Section”, “Drawing Logs”, and “Task Logs”, then save your changes.

</Callout>

## Filter Tasks

**Steps**

1. Click the “Task Logs” or “Drawing Logs” tab below the page title.
2. Click “Time Range” and select a preset, or enter a “Start Time” and an “End Time” and click “Confirm”.
3. If needed, enter the task ID in “Filter by Task ID” on the “Task Logs” tab or in “Filter by MjProxy Task ID” on the “Drawing Logs” tab.
4. Click “Search” or press Enter in the input field.
5. To clear the filters, click “Reset”.

<Callout type="info" title="Tip">

- By default, the page shows only tasks submitted in the range from 00:00:00 today to one hour after the current time. Adjust the time range to find earlier tasks.
- Click “Search” to apply changes to the filters. The page does not refresh automatically. Click “Search” to see the latest task status.

</Callout>

**Filter Descriptions**

| Time Range | Filters tasks by submission time, including both endpoints. | Presets include “Today”, “7 Days” (including today), “This Week” (Sunday through Saturday), “30 Days” (including today), and “This Month”. ## View Task Details and Artifacts

- Task Logs – Task Details

![Task Logs – Task Details dialog](/assets/guide/feature-guide/general-task-logs-task-details.png)

**View Task Details**

1. In the “Task Logs” tab, click “View Details” in the “Details” column for the task.
2. Review the task information in the “Task Details” dialog. For a failed task, see “Failure Reason” for the full reason.

**View Artifacts**

1. For a task with the “Succeeded” status, click “Artifact” in the “Artifact” column. For some music and video tasks, click “Click to Preview Music” or “Click to Preview Video”.
2. Preview the image or play the video or audio in the dialog.
3. Click “Download” to open the file in a new tab and save it.

<Callout type="warn" title="Caution">

- The system fetches the artifact from the upstream provider each time. Once the upstream file expires or is deleted, you can no longer preview or download it. Download and save the file before it expires.
- If the preview fails, the dialog displays “Media preview failed. Please try again.” Click “Retry” to reload it.

</Callout>

## View Refunds for Failed Tasks

**Steps**

1. In the “Task Logs” tab, click “View Details” for the failed task, confirm the “Failure Reason”, and copy the task ID. For a drawing task, copy the ID from the “Task ID” column in the “Drawing Logs” tab.
2. Open <a href="/en/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">Usage Logs</a>, select “Refund” from the type dropdown, set the time range to cover when the task failed, and click “Search”.
3. Click “Asynchronous Task Refund” in the refund record’s “Details” column. Verify the task ID and reason in “Refund Details”.

**Refund Rules**

When you submit a task, the system deducts quota based on the price. If the task fails or times out, the system issues a full refund to the original source (wallet balance or subscription quota), restores the quota on the API key used for the task, and adds a “Refund” record to Usage Logs.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Scenario | “Failure Reason” Display | Refund |
| --- | --- | --- |
| The upstream provider reports that the task failed | The reason returned by the upstream provider, which may be in English | Full refund |
| The upstream provider cannot find the task | “The upstream provider could not find this task” | Full refund |
| Repeated attempts to retrieve the task status fail | “Failed to query upstream task status” | Full refund |
| The task remains incomplete more than 3 days (by default) after submission | “Task timed out” | Full refund |
| A task submitted before February 22, 2026 times out | “Task timed out (legacy task from the previous system, no refund issued, please contact an administrator)” | No refund. Contact an administrator. |
| The channel used for the task is no longer available | “Failed to retrieve channel information. Please contact an administrator.” | Check Usage Logs for a refund record. If there is none, send the task ID to an administrator. |
| A drawing task fails | The reason returned by the upstream provider | Full refund with the reason “Image composition failed” |
| A drawing task remains incomplete more than 1 hour after submission | “Upstream task timed out (over 1 hour)” | Full refund with the reason “Image composition failed” |
</div>

<Callout type="info" title="Tip">

- Confirm refunds by checking for a “Refund” record in Usage Logs. The “Failed” status alone does not confirm that a refund was issued.
- The system bills successful tasks based on actual usage. If actual usage is lower than the quota deducted at submission, the system returns the difference and records it as a “Refund”. If actual usage is higher, the system deducts the difference and adds a “Consumption” record.

</Callout>

## Status Descriptions

### Task Status

The “Status” column in the “Task Logs” tab typically progresses from “Not Started” → “Queued” → “In Progress”, then ends in “Succeeded” or “Failed”.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Status | Meaning | Notes |
| --- | --- | --- |
| Not Started | The task was submitted, and the system has yet to retrieve its processing status from the upstream provider. | Progress is usually “0%”. Click “Search” again later to see the latest status. |
| Queued | The upstream provider has received the task and queued it for processing. | Appears in yellow or orange. Both colors have the same meaning. |
| In Progress | The upstream provider is generating the result. | — |
| Succeeded | The task is complete. | View and download the result in the “Artifact” column. |
| Failed | The task failed or timed out. | Progress displays “100%”. Check “Task Details” for the failure reason and see [View Refunds for Failed Tasks](#view-refunds-for-failed-tasks) for refund information. |
</div>

### Drawing Task Status

In the “Drawing Logs” tab, the status appears below the timestamp in the “Submission Time” column.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Status | Meaning | Notes |
| --- | --- | --- |
| Not Started | The task was submitted and is awaiting processing. | — |
| Queued | The task is queued for processing. | — |
| In Progress | The image is being generated. | — |
| Succeeded | The image has been generated. | Click “View” in the “Image” column. |
| Failed | The task failed or timed out. | Check the “Failure Reason” column for the reason. The system refunds the deducted quota. See [View Refunds for Failed Tasks](#view-refunds-for-failed-tasks). |
| Waiting | The task requires a follow-up action before it can continue. | — |

### Drawing Submission Results

The “Submission Result” column (visible only to administrators) in the “Drawing Logs” tab can show the following values.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Submission Result | Meaning | Notes |
| --- | --- | --- |

## Frequently Asked Questions

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="A task stays in “Queued” or “In Progress”">

**Possible causes**

- Video, music, and image generation can take anywhere from tens of seconds to several minutes, or longer when the upstream provider is busy.
- The backend checks task statuses periodically, so updates may be delayed.
- The page requires a manual refresh to show status changes.

**What to do**

1. Click “Search” to view the latest status.
2. Continue waiting. By default, if a task is still incomplete 3 days after submission, the system marks it as “Failed” and refunds the quota. For image generation tasks, the timeout is 1 hour.
3. If the status stays the same for a long time, send the task ID to an administrator.

</Accordion>

<Accordion title="The task status is “Failed”">

**Note**

The “Failure Reason” field may show the original message from the upstream provider, which may be in English, or one of the following system messages.

| Message | Possible cause | What to do |
| --- | --- | --- |
| “Task timed out” | The task was still incomplete 3 days after submission, the default timeout. | Resubmit the task and confirm the refund in Usage Logs. |
| “Upstream task not found” | The upstream provider no longer has a record of the task. | Resubmit the task and confirm the refund in Usage Logs. |
| “Failed to query the upstream task status” | Repeated attempts to retrieve the task status failed. | Resubmit the task later and confirm the refund in Usage Logs. |
| “Failed to get the channel information. Please contact the administrator” | The channel used for the task is no longer available. | Look for the task’s refund record in Usage Logs. If you can’t find it, send the task ID to an administrator. |
| “Upstream task timed out (over 1 hour)” | The image generation task was still incomplete 1 hour after submission. | Resubmit the task and confirm the refund in Usage Logs. |
| “Task timed out (a task left by the old system is not refunded; contact the administrator)” | A task submitted before February 22, 2026, timed out. | Contact an administrator. |
| Other reasons reported by the upstream provider, such as sensitive content in the prompt or copyrighted content in the lyrics | The upstream provider rejected the request or failed to generate a result. | Revise the prompt or other input based on the reported reason, then resubmit the task. |

</Accordion>

<Accordion title="Are failed tasks charged?">

**Note**

The system deducts quota when you submit a task. If the task fails or times out, the full amount is refunded to the original payment source, either your wallet balance or your subscription quota. The system also restores the quota deducted from the API key used for the task and creates a “Refund” entry in Usage Logs.

**What to do**

1. Follow the steps in [Check refunds for failed tasks](#view-refunds-for-failed-tasks) to verify the “Refund” entry in Usage Logs.
2. If you can’t find a refund entry, send the task ID to an administrator.

</Accordion>

<Accordion title="Artifacts can’t be previewed or downloaded">

**Messages**

“Media preview failed. Please try again.”, “Preview unavailable”, or “Failed to load artifacts”

**Possible causes**

- The file stored by the upstream provider has expired or been deleted.
- The network connection was interrupted or the upstream provider is temporarily unavailable.

**What to do**

1. Click “Retry”.
2. Once you can open the artifact, click “Download” to save the file promptly.
3. If it still fails, send the task ID to an administrator.

</Accordion>

<Accordion title="The “Artifacts” column shows “Result Not Retained”">

**Message**

“The result was returned in the API response and was not saved as an artifact”

**Note**

This message appears when you hover over “Result Not Retained”.

**Possible cause**

The API returned the result directly in the response to the submission request without storing it.

**What to do**

1. Save the result from the API response in the application that calls the API.

</Accordion>

<Accordion title="Can’t find a task">

**Possible causes**

- The date range is still set to today by default. The filter uses the task’s submission time.
- The task ID is incomplete. The search requires an exact match for the full ID.
- You’re viewing the wrong tab. Video, music, and similar tasks appear in “Task Logs”, while Midjourney image generation tasks appear in “Image Generation Logs”.
- The administrator selected “Only Me”, but the task belongs to another user.

**What to do**

1. Set the date range to include the task’s submission time, then click “Search”.
2. Paste the full task ID and search again.
3. Switch to the other tab and look for the task there.

</Accordion>

<Accordion title="The “Image Generation Logs” or “Task Logs” tab is missing">

**Possible causes**

- “Image Generation Logs” or “Task Logs” is turned off in the left sidebar settings. Both must be enabled for the tabs to appear.
- An administrator has disabled one of the features.

**What to do**

1. On the “Profile” page, go to “Personal Settings for the Left Sidebar”. Enable “Console Section”, “Image Generation Logs”, and “Task Logs”, then save your changes.
2. If the tabs still don’t appear, contact an administrator.

</Accordion>

<Accordion title="The action below the task ID shows “Unknown”">

**Note**

The page recognizes some task types, such as “Generate Music” and “Generate Lyrics”, and displays “Unknown” for the others. Tasks still run and are billed as usual.

</Accordion>

<Accordion title="A successful task has a “Refund” or an additional “Usage” entry in Usage Logs">

**Note**

Some tasks are billed based on actual usage after they succeed. If actual usage is lower than the quota deducted at submission, the system refunds the difference and creates a “Refund” entry. If actual usage is higher, the system deducts the difference and creates an additional “Usage” entry. These refunds are billing adjustments for successful tasks.

**What to do**

1. Open the “Refund” entry in Usage Logs and check “Refund Details” for the task ID and reason.
2. Match the initial “Usage” entry by submission time and model, since that entry omits the task ID.

</Accordion>

<Accordion title="How long are task records kept?">

**Note**

The system keeps task and image generation records without automatically deleting them. The upstream provider stores generated images, videos, and audio. Download and save the files promptly, while they’re still available to preview and download.

</Accordion>
