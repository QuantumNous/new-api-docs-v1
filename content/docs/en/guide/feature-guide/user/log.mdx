- In the sidebar, go to “General” → “Usage Logs”.
- View usage and charges for each model call, along with Quota changes from top-ups, refunds, and other transactions.
- Model calls deduct Quota from your account at the applicable price, using either your wallet balance or your subscription Quota. You can review the charges here.

<Callout type="info" title="Tip">

- The page title is “General Logs”.
- Regular users can only view records for their own account. Administrators can switch between “All” and “Only Me” in the upper-right corner of the page. Only administrators can see this control. In “Only Me”, administrators see the same page content as regular users.
- The site determines the units used to display costs and usage.
- For records of sign-ins and account security actions, see <a href="/en/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">Audit Logs</a>. For the status of asynchronous tasks such as video, music, and image generation, see <a href="/en/docs/guide/feature-guide/user/task-log" target="_blank" rel="noopener noreferrer">Task Logs</a>.
- If “Usage Logs” is missing from the left sidebar, open “Profile”, go to “Personal Left Sidebar Settings”, enable “Console Area” and “Usage Logs”, and save.
</Callout>

## Filter Logs and View Statistics

**Steps**

1. Click “Time Range” and select a preset such as “Today” or “7 Days”. To set a custom range, enter a “Start Time” and “End Time”, then click “Confirm”.
2. Enter a “Model Name” and “Group” as needed, and select a log type from the type dropdown.
3. To search by Token name, request ID, or other criteria, click “Expand” and fill in the filters in the second row.
4. Click “Search” or press Enter in any input field.
5. View “Usage”, “RPM”, and “TPM” in the lower-left corner of the filter area.
6. To clear the filters, click “Reset”.

<Callout type="info" title="Tip">

- By default, the list shows records from 00:00:00 today through one hour after the current time. Adjust the time range to view earlier records.
- Click “Search” to apply changes to the filters. To see new records, click “Search” again.
- On mobile, all filters except the time range are under “Filters”. The list refreshes as soon as you select a time range.
</Callout>

### Request Policy Decisions

The “Request Policy Decisions” section in “Log Details” is visible only to administrators. It lists the steps used to select a Channel, retry, or stop for the request. It appears only when “All” is selected in the upper-right corner of the page.

- **Successful requests**. The system saves the decision log with the “Consumption” record. It includes at least the “Select Channel” and “Request Completed” steps. Disabling “Record Quota Usage” stops the system from saving these decision logs.
- **Failed attempts**. Each failed attempt generates an “Error” record containing the decisions through that attempt. Decision logs for failed attempts are available only when the site enables error logging.

**How each step is displayed**

1. The first line shows the decision, followed by “#Channel ID” when a Channel is involved and the HTTP status code if the step failed. Steps that stop retries appear in amber.
2. The second line shows “Attempt N”, elapsed time in milliseconds since the request started, the Group, the matched rule name, and the HTTP status code. Only available values appear.
3. The third line shows “Source:” and the basis for the decision. If the failure triggered a Channel health action, the action appears after the source.

**Decision labels**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Decision | Meaning |
| --- | --- |
| Select Channel | The Channel selected for this attempt. |
| Session Rule Matched | The request matched a session persistence rule. The rule name appears on the second line. |
| Upstream Request Failed | The attempt failed upstream or during network connection. |
| Request Rejected Locally | A local check rejected the request before it was sent upstream. |
| Channel Error | The system attributed the error to the Channel. |
| Status Code Matched a Retry Rule | The failure status code matched a retry rule, so the system retries the request. |
| Status Code Did Not Match a Retry Rule | The failure status code did not match a retry rule, so retries stop. |
| Unrecognized Status Code | The system could not recognize the status code returned upstream. |
| Attempt Limit Reached | The request reached the maximum number of attempts, so retries stop. |
| Retry Prohibited by System | A system rule prohibits retrying in this situation. |
| Fixed Channel Constraint | The request is pinned to a specific Channel and stays on that Channel. |
| Session Persistence Prevents Channel Switching | Session persistence requires the original Channel to be used. |
| Task Accepted, Duplicate Submission Prohibited | The upstream service has already accepted the asynchronous task, so retries stop. |
| Task Failed | The asynchronous task failed during submission. |
| Streaming Output Did Not Complete Successfully | Streaming output ended abnormally. |
| Request Completed | The request completed successfully. |
</div>

**Sources and Channel health actions**

- **Source**. “Global Defaults”, “Global and Channel Settings”, “Channel”, and “Session Rule” indicate that the decision was based on site or Channel retry or session settings. “System Constraint” and “Fixed Channel Constraint” indicate that the decision was based on system rules. “Channel Selection”, “Upstream Response”, “Upstream Connection”, and “Local Check” indicate that the decision was based on what happened during the attempt.
- **Health action**. “Unchanged” means the Channel status stayed the same. “Channel Deactivation Requested” and “Current Key Deactivation Requested” mean the failure triggered a deactivation request.

## Export Logs

**Steps**

1. Set the filters on the page as needed and click “Search”.
2. Click “Export” in the lower-right corner of the filter area to open the “Export Logs” dialog.
3. Set the time range to export.
4. Click “Export” in the dialog and wait for your browser to download the file.

<Callout type="info" title="Tip">

- “Export” is available to regular users when administrators enable user exports. Administrators can always export logs.
- Each account can run only one export at a time. Closing the dialog while an export is in progress cancels it.
- Exported files contain the original names even when “Hide” is enabled.
</Callout>

**Export settings**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Setting | Definition | Requirements and Limits | Default |
| --- | --- | --- | --- |
| Time Range | The time range of the records to export. | Both a start time and an end time are required. If the end time is earlier than the start time, the dialog shows “End time must be after start time”. If the range exceeds the limit (365 days by default), the dialog shows “The time range cannot exceed … days” and disables “Export”. Other filters applied on the page, such as model name, Group, type, Token name, and request ID, also apply to the export. | The time range currently applied on the page |
</div>

**Export file**

- The export is a CSV file named `usage-logs-<start-date>-<end-date>.csv`, for example `usage-logs-20261101-20261108.csv`. You can open it directly in a spreadsheet application.
- The file includes the “Time”, “Type”, “Token”, “Group”, “Model”, “Stream”, “Input Tokens”, “Output Tokens”, “Cache Reads”, “Cache Writes”, “Cost”, “Latency”, “IP”, “Request ID”, and “Details” columns. Exports from the “All” view include records for all users and add the “User” and “Channel” columns (administrators only).
- The records are sorted from newest to oldest, with no limit on the number of records.

<Accordion title="I can't find the log entry for a specific request">
**Possible causes**

- The time range is still set to today by default, or the filters are too restrictive. Token name, Group, request ID, and upstream request ID all require exact matches.
- The request failed. The site logs failed requests only when error logging is enabled. The site never logs requests it rejects before the call, such as when key validation fails, no Channel is available, the request limit is reached, or the available Quota is insufficient.
- The administrator turned off “Log Quota Usage.” Successful requests no longer generate “Consumption” entries.
- The administrator selected “Only Me,” and the entry belongs to another user.
- The page does not refresh automatically.

**What to do**

1. Clear any unnecessary filters and set the time range to include when the request was made.
2. If you know the request ID, click “Expand” and enter the full ID in “Request ID.”
3. Click “Search” to refresh the list.
4. If you still can't find the entry, contact the administrator to confirm the site's logging settings.
</Accordion>

<Accordion title="Am I charged for failed requests?">
**Explanation**

Requests that return an error incur no charge. The site logs failed requests only when error logging is enabled. When enabled, failed requests appear as “Error” entries with a “Cost” of 0. The error message appears under “Content” in “Log Details.” If an asynchronous task fails or times out, the system returns any deducted Quota and creates a “Refund” entry.

**What to do**

1. Verify charges against the “Consumption” and “Refund” entries and any changes to your account balance.
2. If you need to investigate a failure and the list has no “Error” entry, contact the administrator.
</Accordion>

<Accordion title="The cost differs from what I expected">
**Explanation**

The input and output unit prices in “Billing Details” are prices per million Tokens. The site determines the display unit.

**Possible causes**

- The Group you used has a Ratio, or your account has a custom Ratio. The Ratio appears next to the Group in the “Token” column.
- Cache reads and writes, audio, images, and tools such as web search have their own pricing. A wrench icon appears next to “Cost” on entries that include a tool call surcharge.
- The model uses tiered pricing, and the applicable tier has a different price.
- If the request was paid for with subscription Quota, “Cost” shows the amount actually deducted from the subscription.

**What to do**

1. Open “Log Details” for the entry and check the billing mode, unit prices, Ratios, and total cost in “Billing Details.”
2. Check the count for each Token type in “Token Details.”
3. If you still have questions, send the “Request ID” to the administrator.
</Accordion>

<Accordion title="“Usage” differs from the total cost in the list or the dashboard figures">
**Explanation**

- “Usage” totals only the “Consumption” entries within the selected time range. It excludes “Refund” entries from the calculation and ignores the “Type,” “Request ID,” and “Upstream Request ID” filters.
- “RPM” and “TPM” always cover the most recent 60 seconds.
- The dashboard aggregates data at regular intervals, every 5 minutes by default. New requests appear in the usage logs first.

**What to do**

1. Select “Consumption” from the “Type” dropdown, click “Search,” and compare the results with “Usage.”
2. Set “Type” to “Refund” to view returned Quota separately.
3. Wait a few minutes, then refresh the dashboard.
</Accordion>

<Accordion title="A search returns “The time range cannot exceed … days”">
**Message**

“The time range cannot exceed … days”

**Possible cause**

The administrator sets the maximum time range a regular user can query at once. The default is 365 days. The same limit applies to administrators when exporting logs.

**What to do**

1. Shorten the time range and run the search again.
2. If you need logs for a longer period, split it into multiple searches or exports.
</Accordion>

<Accordion title="The “Export” button is missing or an export returns an error">
Use the message to identify the cause.

| Message | Possible cause | What to do |
| --- | --- | --- |
| “Export” does not appear on the page, or the page displays “Log export is disabled” | The administrator disabled log exports for users. | Contact the administrator. |
| “Another log export is running. Try again after it finishes.” | This account already has an export in progress. | Wait for the current export to finish, then try again. |
| “End time must be after start time” | The end time is earlier than the start time. | Set the time range again. |
| “The time range cannot exceed … days” | The export time range exceeds the limit, which defaults to 365 days. | Shorten the time range and split the export into multiple exports. |
| “Failed to export logs” | The network connection was interrupted or a server error occurred. | Try again. If the export still fails, contact the administrator. |
</Accordion>

<Accordion title="“IP Address” is missing from the log details">
**Possible cause**

“Log IP Address” is disabled for the account. The setting is off by default and applies only to “Consumption” and “Error” entries created after you enable it.

**What to do**

1. Open the <a href="/en/docs/guide/feature-guide/user/security#configure-ip-address-logging" target="_blank" rel="noopener noreferrer">Security & Access</a> page. In the “Privacy” section, turn on “Log IP Address” and click “Save Settings.”
2. New entries will show the IP address. The setting cannot add IP addresses to existing entries.
</Accordion>

<Accordion title="“Response Model: …” appears next to the model name">
**Message**

“The upstream returned a model name different from both the requested and upstream models. Aliases or dated versions may also cause this; this warning alone does not prove model substitution.”

**Possible cause**

The upstream provider returned a model name different from the requested model name, such as a model alias or a dated version name.

**What to do**

1. Click the notice to view “Requested Model,” “Upstream Requested Model,” and “Response Model.”
2. If you suspect model substitution, send the “Request ID” to the administrator for verification.
</Accordion>

<Accordion title="A fuzzy search with % returns a format error">
“Model Name” and “Username” support fuzzy searches with `%`. If the search pattern is invalid, one of the following messages appears.

| Message | Possible cause | What to do |
| --- | --- | --- |
| “The search pattern cannot contain consecutive % wildcards” | You entered consecutive `%` wildcards. | Remove the extra `%` wildcards. |
| “The search pattern can contain at most 2 % wildcards” | You used more than two `%` wildcards. | Use at most two `%` wildcards. |
| “Fuzzy search keywords must be at least 2 characters long” | The pattern has fewer than two characters other than `%`. | Add characters to the search term. |
</Accordion>

<Accordion title="Selecting “Management” or “Login” returns no new entries">
**Explanation**

New login and administrative events appear in the audit log. The “Management” and “Login” types are marked “Deprecated” in the filter and apply only to historical logs.

**What to do**

1. Open the <a href="/en/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">Audit Log</a> to view login and account activity.
</Accordion>

<Accordion title="I can't see the “Channel” or “User” columns or “Request Policy Decision”">
**Explanation**

Administrator-only controls and details appear only when an administrator selects “All.” These include the “Channel” and “User” columns, the “Username” and “Channel ID” filters, and “Request Policy Decision” in the details window. Decision records for failed attempts also require error logging to be enabled on the site.

**What to do**

1. If you're an administrator, select “All” in the upper-right corner of the page.
2. If you're a regular user and need to investigate a request, send the “Request ID” to the administrator. These details are available only to administrators.
</Accordion>

<Accordion title="How long are usage logs retained?">
**Explanation**

By default, usage logs are retained indefinitely. Administrators can delete usage logs older than a specified time. Deleted logs cannot be recovered.

**What to do**

1. If you need to keep records long term, [export logs](#export-logs) regularly.
</Accordion>
