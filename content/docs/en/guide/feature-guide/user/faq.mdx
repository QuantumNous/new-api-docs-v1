## Request Failures

These issues occur when you call a model with an API key or from the Playground and receive an error.

<Accordion title="A request returns “No available channel for model … under group …”, or the model does not exist">

**Original message** — “分组 … 下模型 … 无可用渠道（distributor）” (English: “No available channel for model … under group … (distributor)”) or “分组 … 下模型 … 的可用渠道不存在（retry）” (English: “No available channel for model … under group … (retry)”)

**Explanation** — The site also returns this message when the model name is incorrect, so a nonexistent model produces the same error.

**Possible causes**

- The model name is incorrect. For example, its capitalization or version suffix may differ from the name in the Model Hub.
- The API key’s group cannot access this model.
- All channels that serve the model are temporarily unavailable, or an administrator has disabled the model.

**How to resolve it**

1. Copy the model name from the <a href="/en/docs/guide/feature-guide/user/pricing" target="_blank" rel="noopener noreferrer">Model Hub and Leaderboard</a> and use it in the request.
2. In the model’s “Overview” tab, check “Pricing by Group” to see which groups can access the model, then edit the API key’s “Group” setting. In the Playground, switch groups using the group and model selector.
3. Try again later. If the issue persists, contact an administrator.

</Accordion>

<Accordion title="A request returns “You have reached the request limit” or “You have reached the total request limit”">

**Original message** — “您已达到请求数限制：…分钟内最多请求…次” (English: “You have reached the request limit: maximum … requests in … minutes”) or “您已达到总请求数限制：…分钟内最多请求…次，包括失败次数，请检查您的请求是否正确” (English: “You have reached the total request limit: maximum … requests in … minutes, including failed attempts. Please check that your requests are correct”)

**Explanation** — An administrator has enabled request limits, which return HTTP status code 429. All API keys on an account share the same request count. Administrators can set separate limits for specific groups. Playground requests are excluded from the count. If you receive a 429 with a different message, the upstream service is rate-limiting your requests. See “A request returns an upstream service error or ‘Database error, please contact the administrator’” in this section.

**Possible causes**

- The number of requests made within the time window shown in the message exceeded the site limit.
- The total request limit includes failed requests, so repeatedly sending requests with incorrect parameters can quickly exhaust it.

**How to resolve it**

1. Wait until the time window shown in the message has elapsed, then retry at a lower request rate. In your application, add a delay before retrying a failed request.
2. If you reach the total request limit, use the messages from the other failed requests to diagnose their cause first.
3. Contact an administrator if you need a higher limit.

</Accordion>

<Accordion title="A request returns “User has been banned”">

**Original message** — “用户已被封禁” (English: “User has been banned”)

**Possible cause** — An administrator has disabled the account, so none of its API keys can make requests.

**How to resolve it**

1. Contact an administrator to confirm the account status.
2. For the equivalent message when signing in on the website, see <a href="/en/docs/guide/feature-guide/user/auth#frequently-asked-questions" target="_blank" rel="noopener noreferrer">Registration and Sign-in</a>.

</Accordion>

<Accordion title="A request returns “Regular users cannot specify a channel”">

**Original message** — “普通用户不支持指定渠道” (English: “Regular users cannot specify a channel”)

**Explanation** — If the part of an API key after `sk-` contains a hyphen, the content after that hyphen is interpreted as a channel selection. Only administrator accounts can specify a channel this way.

**Possible causes**

- You copied extra text with the key or pasted two pieces of text together.
- You appended a hyphen and a channel number to the key using the administrator syntax.

**How to resolve it**

1. On the <a href="/en/docs/guide/feature-guide/user/token" target="_blank" rel="noopener noreferrer">API Keys</a> page, click the copy button to the right of the key to copy the complete key again.
2. Confirm that the request header is `Authorization: Bearer sk-…` and that nothing follows the key.

</Accordion>

<Accordion title="A request returns “Invalid request”, “Model name not specified”, or HTTP 413">

**Explanation** — Use the original message to identify the request formatting issue.

| Original message | Possible cause | How to resolve it |
| --- | --- | --- |
| “无效的请求，…” (English: “Invalid request: …”) | The request body contains invalid JSON or uses a format the endpoint does not accept. | Check the request format against the <a href="/en/docs/api" target="_blank" rel="noopener noreferrer">API Reference</a>. |
| “未指定模型名称，模型名称不能为空” (English: “Model name not specified, model name cannot be empty”) | The request is missing `model`. | Specify the model name in the request. |
| HTTP status code 413 with “request body too large” (English only) | The request body exceeds the site limit (128 MB by default). For example, an attached image or file may be too large. | Compress the attachments or send fewer of them, then retry. Contact an administrator if you need a higher limit. |

</Accordion>

<Accordion title="A request returns an upstream service error or “Database error, please contact the administrator”">

**Explanation** — The upstream services configured by the administrator process model requests. When an upstream service returns an error, the site displays the original message, which is usually in English, and redacts the upstream address. The HTTP status code usually matches the upstream response, such as 400, 429, 500, or 502.

**Possible causes**

- The upstream service is temporarily busy, rate-limiting requests, or experiencing an outage. Common status codes are 429 and 5xx.
- The model does not support one or more request parameters, and the upstream service returns a 400-series error.
- “数据库出错，请联系管理员” (English: “Database error, please contact the administrator”) indicates an error on this site.

**How to resolve it**

1. Try again later or use a different model or group.
2. If the message concerns request parameters, use the <a href="/en/docs/api" target="_blank" rel="noopener noreferrer">API Reference</a> and the model provider’s documentation to correct them.
3. If the issue persists, send the original message to an administrator, including the “(request id: …)” at the end.

</Accordion>

<Accordion title="What does “(request id: …)” at the end of an error message mean?">

**Explanation** — The site generates an ID for each request. When a request fails, the ID appears at the end of the message. Administrators can use it to look up how the request was processed.

**How to use it**

1. Copy the complete original message, including the request ID, and send it to an administrator.
2. If the request has a usage log entry, click “Expand” in <a href="/en/docs/guide/feature-guide/user/log#filter-logs-and-view-statistics" target="_blank" rel="noopener noreferrer">Usage Logs</a> and enter the ID in the “Request ID” field to find it.

</Accordion>

<Accordion title="A request failed and does not appear in Usage Logs">

**Explanation** — The site rejects the following requests before calling the model. These requests incur no charges and produce no usage log entries.

- Requests that fail API key validation, with messages such as “Invalid token”, “Your IP is not on the token’s allowlist”, or “User has been banned”.
- Requests that lack permission to access a group or model, have no available channel, exceed a request limit, or use an invalid request format.
- Requests with insufficient quota, with messages such as “Insufficient user quota” or “Failed to pre-deduct quota”.

Other failed requests appear as “Error” entries only if the site has enabled error logging.

**How to resolve it**

1. Look up the original message on this page or in the FAQ for the relevant page.
2. If an administrator needs to investigate, provide the “(request id: …)” at the end of the message.
3. For details on when failed requests generate log entries, see <a href="/en/docs/guide/feature-guide/user/log#frequently-asked-questions" target="_blank" rel="noopener noreferrer">Usage Logs</a>.

</Accordion>

<Accordion title="You see “Session expired!” or are logged out">
**Message**

“Session expired!” appears, and you are returned to the login page.

**Possible causes**

- It has been 30 days since you logged in.
- On another device, you revoked this session on the “Security and Access” page or clicked “Log out of other sessions.”
- On another device, you changed your password, enabled or disabled two-step verification, regenerated your backup codes, or registered or removed a Passkey.
- You reset your password using “Forgot Password,” or an administrator reset two-step verification or the Passkey for your account.

**What to do**

1. Log in again.
2. If you did not make the change, log in, change your password immediately, and review your login history in the <a href="/en/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">Audit Log</a>.
3. For details on how long you stay logged in and how to manage sessions, see <a href="/en/docs/guide/feature-guide/user/security#manage-login-sessions" target="_blank" rel="noopener noreferrer">Security and Access</a>.

## Interface and Display

Issues with opening pages, finding menus, and how information is displayed.

<Accordions type="multiple" className="[&_h3]:font-semibold [&_h3[data-state=open]]:bg-fd-muted [&_[role=region]>div]:border-t [&_[role=region]>div]:pt-3 [&_[role=region]>div]:pb-3 [&_[role=region]>div]:ps-9 [&_[role=region]>div]:text-sm [&_[role=region]>div]:leading-6 [&_[role=region]>div]:text-fd-muted-foreground [&_[role=region]_strong]:text-fd-foreground [&_[role=region]_p]:my-2 [&_[role=region]_ol]:my-1 [&_[role=region]_ul]:my-1 [&_[role=region]_li]:my-0.5 [&_[role=region]_table]:table-fixed [&_[role=region]_th:nth-child(1)]:w-[40%] [&_[role=region]_th:nth-child(2)]:w-[30%]">

<Accordion title="The page shows “403” or “Access Forbidden,” or “404” or “Oops! Page Not Found!”">
**Messages**

“Access Forbidden” appears above “You do not have the necessary permissions to view this resource.” Alternatively, “Oops! Page Not Found!” appears above “The page you are looking for either does not exist or may have been removed.”

**Possible causes**

- You opened a page your account does not have permission to access, such as Favorites or an admin page someone sent you.
- The address does not exist. It may be from an older version or contain a typo.

**What to do**

1. Click “Back” or “Back to Home.”
2. Open the page you need from the sidebar or top navigation. For help finding it, see <a href="/en/docs/guide/feature-guide/user/quick-start#get-to-know-the-console-layout" target="_blank" rel="noopener noreferrer">Quick Start</a>.
3. If you need access to an admin page, contact an administrator.
</Accordion>

<Accordion title="The page shows “Oops! Something went wrong” or “Too many requests”">
**Messages**

“Oops! Something went wrong” appears above “Please try again later.” Alternatively, “Too many requests” appears above “Please wait and try again.” Clicking a button may display only a single English message containing `429`.

**Possible causes**

- The site was recently upgraded, and your browser is still using page files from the previous version.
- Your network connection was interrupted.
- Too many requests came from the same public IP address in a short period, such as from a school, company, or proxy network. The site applies rate limits per source IP address. By default, it allows up to 120 page loads and 360 API calls in 3 minutes.

**What to do**

1. Wait a few minutes, then refresh the page.
2. If the error persists, force a refresh (Ctrl+F5 on Windows or ⌘+Shift+R on Mac), or clear your browser cache for the site and try again.
3. If the issue persists, contact an administrator.
</Accordion>

<Accordion title="The times shown on the page differ from your local time">
**How times are displayed**

Pages such as the Usage Log and Audit Log display times in the time zone of the computer running your browser. Daily check-ins use the server's date. The Overview and Data Dashboard aggregate statistics into hourly intervals that start on the hour.

**What to do**

1. Check your computer's time zone and clock settings.
2. If check-in dates or reporting intervals differ from your local time, use the server time as the reference.
</Accordion>

</Accordions>
