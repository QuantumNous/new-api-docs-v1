- In the sidebar, go to “General” → “Audit Logs.”
- Review account activity such as sign-ins, security changes, API key operations, and access token operations.
- Audit Logs cover account activity only. Model usage and charges appear in Usage Logs.

<Callout type="info" title="Tip">

- Regular users can view only their own account records. Administrators with the “View Other Accounts’ Audit Logs” permission can switch between “All” and “Only Me” in the upper-right corner of the page. This switch is visible only to administrators.
- The “Management” and “Login” type filters in Usage Logs are deprecated. New sign-in and administrative actions appear in Audit Logs. To review model usage and charges, see <a href="/en/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">Usage Logs</a>.
- “API Token” in an event refers to a key on the “API Keys” page. Access tokens are credentials for account management only and cannot be used to call models. Create them on the <a href="/en/docs/guide/feature-guide/user/security#create-and-manage-access-tokens" target="_blank" rel="noopener noreferrer">Security & Access</a> page.
- If “Audit Logs” is missing from the left sidebar, go to “Profile” and find “Left Sidebar Personal Settings.”<br/>Enable “Console” and “Audit Logs,” then save your changes.
</Callout>

## Filter Audit Logs

**Steps**

1. Click “Time Range” and select a preset, or enter a “Start Time” and an “End Time” and click “Confirm.”
2. Select options as needed from the result drop-down (defaults to “All Results”) and the category drop-down (defaults to “All Categories”).
3. To search by token identifier or request ID, click “Expand” and fill in the filters in the second row.
4. Review the automatically refreshed list. To run the search again with the current filters, click “Search.”
5. To clear the filters, click “Reset.”

<Callout type="info" title="Tip">

- The list refreshes as soon as you change a filter. Clicking “Search” is optional.
- By default, the list shows records from all time. Reloading the page clears the filters.
</Callout>

**Filter Descriptions**

The filter area has two rows. The second row is collapsed by default. Click “Expand” to display it. The table lists the filters in the order they appear on the page.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Filter | Location | Definition | Requirements and Constraints | Default |
| --- | --- | --- | --- | --- |
| Time Range | First row | Filters by the time of the action, including both endpoints. | Presets include “Today,” “7 Days” (including today), “This Week” (Sunday through Saturday), “30 Days” (including today), and “This Month.” Enter custom times to the second, then click “Confirm.” Either endpoint can be left blank, and the range can span any length of time. If the start time is later than the end time, the page displays “End time must be later than start time” and leaves the list as it is. | Blank (all time) |
| Result | First row | Filters by the outcome of the action. | Select one of “All Results,” “Success,” or “Failure.” | “All Results” |
| Category | First row | Filters by record category. | Select one of “All Categories,” “Login,” “Account Security,” “Action Audit,” or “Access Token.” See [Event Categories](#event-categories). | “All Categories” |
| Token Identifier | Second row | Identifies the access token used to make a request. | Optional. Enter the full 64-character identifier, which consists of digits and lowercase letters a–f. You can copy it from the details of a record in the “Access Token” category. This filter matches only records in that category. If you enter an incomplete identifier, the list displays “Failed to load audit records.” | Blank |
| Request ID | Second row | The identifier of the request associated with an action. | Optional. Enter the full ID for an exact match. You can copy it from the “Request” section of the record details. | Blank |
| Username (administrators only) | Second row | Filters by the account the record belongs to. | Appears only in the “All” view. Enter the full username as it was when the record was created. | Blank |
</div>

## View Audit Details

- Audit Logs – Log Details

![Audit Logs log details window](/assets/guide/feature-guide/general-audit-logs-log-details.png)

**Steps**

1. In the record’s row, click “Details” in the “Details” column to open the “Log Details” window.
2. Review the event, result, actor, and request information.
3. To copy values such as the client, route, or request ID, click the copy button to the right of the value.

**Details Window**

The table lists the sections in the order they appear in the window, from top to bottom.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Section | Fields | Definition | When Shown |
| --- | --- | --- | --- |
| Top of window | Event, Result, Time | The action description, its result (“Success” or “Failure”), and the time it occurred. | All records. |
| Token Operation Details | Token Name, Token ID, Modified Fields, Status Changes, and other fields | Details about API key creation, updates, deletion, and viewing. Bulk actions also show the requested and completed counts. | Events related to “API Token.” |
| Quota Adjustment Details | Target User, Adjustment Method, Requested Amount, Quota Before and After | Details about an administrator’s adjustment to a user’s quota. If the action fails, this section shows the reason. | User quota adjustment events performed by administrators (administrators only). |
| Action Audit Information | Actor | The account that performed the action, displayed as “username (ID: …).” | All records. |
| Action Audit Information | Role | The account’s role when it performed the action, displayed as user, admin, or root. | All records. |
| Action Audit Information | Target | The object affected by the action, such as a user, channel, or access token. Shows the name and ID if available. | Appears when the record has a target. For API key and quota adjustment events, the target appears in the corresponding details section above. |
| Action Audit Information | Authentication Method | “Session” indicates an action performed after signing in to the web interface. “Access Token” indicates an API request authenticated with an access token. | All records. |

| Request | Request Method, HTTP, IP, Client, Route, Request ID | Information about the request that initiated the action. Longer values have a copy button on the right. | All records. |
| Request | Token Identifier | The identifier of the access token used to make the request. Copy it to use in the “Token Identifier” filter. | Records in the “Access Token” category. |
| Additional Information | — | Other record information beyond the fields above. Administrators can see more request information in the “All” view. | Appears when additional information is available. |

## Status Descriptions

### Audit Results

The “Result” column and the result filter use the following two outcomes.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Result | Meaning | Notes |
| --- | --- | --- |
| Success | The action completed. | — |
| Failure | The action could not be completed, for example because verification failed, the request was rejected, or the parameters were invalid. | “HTTP” can still show 200 if the request reached the service and the action failed. For rejected access token requests, “Failure Reason” in the details shows “Access token has expired,” “Access token lacks the required permission,” “Access tokens cannot use this feature,” or “This feature requires signing in to the dashboard.” “Required Permission” shows the permission the action requires. |
</div>

## Frequently Asked Questions

<Accordion title="I see a sign-in I don’t recognize">

**Possible Causes**

- You signed in on another device or browser.
- Someone signed in to your account using a compromised password or third-party account.

**What to Do**

1. Open “Log Details” for the record and check the “IP,” “Client,” and sign-in method.
2. If you confirm you didn’t sign in, change your password immediately.
3. Revoke any unfamiliar sign-in sessions and access tokens on the <a href="/en/docs/guide/feature-guide/user/security" target="_blank" rel="noopener noreferrer">Security & Access</a> page.
4. Enable two-step verification or set up a Passkey.
5. If the issue persists, contact your administrator.
</Accordion>

<Accordion title="I can’t find a record of an action">

**Possible Causes**

- Audit Logs record only successful sign-ins.
- Model calls, top-ups, quota redemptions, and daily check-ins appear in Usage Logs.
- Changes to personal settings, such as language and sidebar preferences, are excluded from Audit Logs.
- Actions an administrator performs on an account are recorded under the administrator’s account and are hidden from regular users.
- Sign-ins and administrative actions that occurred before Audit Logs were enabled are still in Usage Logs under the “Login” and “Management” types.
- The filters are too restrictive.

**What to Do**

1. Click “Reset” to clear the filters, then look for the record again.
2. To find older records, select “Login” or “Management” as the type in <a href="/en/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">Usage Logs</a>.
</Accordion>

<Accordion title="I can’t see the “All / Only Me” switch or the “Username” filter">

**Message**

“Audit access changed. Showing only your records.”

**Possible Causes**

- Regular users can view only their own account records. Both controls are hidden for regular users.
- The administrator lacks the “View Other Accounts’ Audit Logs” permission because it was never granted or has been revoked.

**What to Do**

1. If you are an administrator and need to view other accounts’ records, contact Root to request the “View Other Accounts’ Audit Logs” permission.
</Accordion>

<Accordion title="Filtering shows “Failed to load audit records”">

**Message**

“Failed to load audit records”

**Possible Causes**

- The “Token Identifier” is incomplete or contains uppercase letters.
- The network connection was interrupted or the server encountered an error.

**What to Do**

1. Copy the full “Token Identifier” from the details of a record in the “Access Token” category and paste it into the filter.
2. Click “Retry” next to the message.
3. If the error persists, contact your administrator.
</Accordion>

<Accordion title="There are many records in the “Access Token” category">

**Explanation**

Each dashboard API request made with an access token generates a record, including rejected requests.

**What to Do**

1. In the “Request” section of the record details, check the “Token Identifier” to identify the access token used for the request.
2. Filter by “Token Identifier” to see all requests made with that access token.
3. If you see requests you don’t recognize, revoke the access token on the <a href="/en/docs/guide/feature-guide/user/security#create-and-manage-access-tokens" target="_blank" rel="noopener noreferrer">Security & Access</a> page.
</Accordion>

<Accordion title="How long are audit records retained?">

**Explanation**

The system retains audit records indefinitely. When administrators clear historical logs, the cleanup applies only to Usage Logs.
</Accordion>
