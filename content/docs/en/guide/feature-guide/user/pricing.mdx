- Prices vary with the Ratio of the Group used for the request. When you call a model, the cost is deducted from your account Quota (wallet balance or subscription Quota).

<Callout type="info" title="Tip">

- You can view these pages while signed out. If the administrator requires sign-in, clicking either link opens a **Sign-in Required** dialog. After 5 seconds, you are redirected to the sign-in page. Once you sign in, you return to the original page.
- Your Group determines which models you can use and which billing Ratio applies. While signed out, you see the Groups the site makes available to everyone. After signing in, you see the Groups and custom Ratios available to your account, so the models and prices may differ.
- The currency symbol follows the site's Quota display settings. If the site displays Quota in Tokens, prices are still shown in US dollars.
- If **Model Marketplace** or **Leaderboard** is missing from the top navigation, the administrator has disabled that entry. Contact the administrator. ## Find and Filter Models

**Steps**

1. Enter a keyword in the search box at the top of the page. The placeholder reads **Search model names, providers, endpoints, or tags...**.
2. In the **Filters** panel on the left, select a Group, provider, tag, pricing type, or endpoint type.
3. Choose a sort order from the dropdown in the toolbar.
4. To clear the filters, select **Reset** in the **Filters** panel.

<Callout type="info" title="Tip">

- Search is case-insensitive and matches model names, descriptions, tags, and providers. Use the **Endpoint Type** filter to find models by API type.
- You can apply multiple filters at once. **Filters Active** appears when any filter is applied. **Reset** leaves the text in the search box intact.
- Search, filters, sort order, and view apply only to the current page. Refreshing the page restores the defaults.
- In a narrow window, such as on a phone, tablet, or resized browser window, use the **Filters** button in the toolbar to open the panel.
- If no models match, the page shows **No models found**.
</Callout>

## Understand Model Pricing

Prices in the list already account for the Group Ratio. If no Group is selected, they use the lowest Ratio among the available Groups. **Base Price** on the **Overview** tab of the model details shows the price at a Ratio of 1. Your actual charge uses the Group associated with the API key when you make the request.

**Billing methods**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Billing method | Prices in card and table views | Prices on the model details Overview tab | How charges are calculated |
| --- | --- | --- | --- |
| Usage-Based Billing | Shows **Input** and **Output** prices per 1M or 1K Tokens. If a cache price is configured, it also appears. | **Base Price** lists input and output prices and any configured prices for **Cached Input**, **Cache Write**, **Image Input**, **Audio Input**, and **Audio Output**. | Input and output Tokens are billed separately based on their counts. Cache hits, images, and audio are billed at the corresponding rates. |
| Per-Request Billing | Shows the price for one request. | **Base Price** shows the **Per Request** price. | Each request incurs a fixed charge regardless of the Token count. |
| Dynamic Billing | Table view also shows the number of tiers, such as **2 Tiers**. Models with time-based pricing also show **Current Time Slot Price**. | **Dynamic Billing** states, “Prices adjust dynamically based on usage tiers and request conditions.” It shows the **Tiered Pricing Table** and, for some models, **Conditional Multipliers**. Cache pricing appears as **Cache Read**. | Prices vary by conditions such as input length or time of day. Each request is billed at the tier that applies. If pricing cannot be listed by tier, the page shows **Special Billing Expression** and **Raw Expression**. |
| Task Billing | Shows prices per unit of usage, such as per second, per image, or per request. | May show **Pricing Examples** with **Specification** and **Example Price** columns and the note “Reference prices for common specifications.” | Asynchronous tasks, such as video and image tasks, are billed based on actual task usage. |
</div>

<Callout type="info" title="Tip">

- The Model Marketplace shows unit prices only. To see the actual charge for each request, check the <a href="/en/docs/guide/feature-guide/user/log#view-log-details" target="_blank" rel="noopener noreferrer">Usage Logs</a>.
- If a usage-based model has no configured price, the Model Marketplace shows the system default. In US dollars at a Group Ratio of 1, the input price is $75 per 1M Tokens and the output price varies by model. Calling the model returns a message that pricing has yet to be configured. See the [FAQ](#frequently-asked-questions).
- If a task-billed model has no configured price, the page shows **Usage-Based Billing · Pricing Not Configured** or **Not Configured**. If only some service providers lack configured prices, it shows **Pricing Not Configured for Some Service Providers**.
</Callout>

## View Model Details

**Steps**

1. Select **Details** in the lower-right corner of a card or select the model's row in table view. **Model Details** opens on the right.
2. Select **Overview**, **Performance**, or **API** to switch tabs.
3. To copy the model name, select the copy button to the right of the name.
4. Select **×** in the upper-right corner to close the panel.

<Callout type="info" title="Tip">

- Selecting a model name on the leaderboard opens a full-page view with the same details. Select **Back** in the upper-left corner to return to the Model Marketplace.
- The full-page view shows **Model Not Found** if the model is unavailable, for example, if it has been removed from the Model Marketplace or your account lacks access.
</Callout>

## View the Leaderboard

- Model Marketplace and Leaderboard – Leaderboard

![Model Marketplace and Leaderboard – Leaderboard page](/assets/guide/feature-guide/top-navigation-leaderboard.png)

The leaderboard ranks models and providers by Token usage across all users on the site. It combines usage across accounts and omits user information.

**Steps**

1. Select **Leaderboard** in the top navigation.
2. Select **Today**, **This Week**, **This Month**, or **This Year** below the title.
3. Hover over the charts to see usage for each model or provider.
4. Select a model name to view its details. Select a provider name to open the Model Marketplace filtered to that provider's models.

<Callout type="info" title="Tip">

- The time ranges are rolling windows ending at the current time. **Today** covers the past 24 hours, **This Week** the past 7 days, **This Month** the past 30 days, and **This Year** the past 365 days.
- The default is **This Week**. The screenshot shows **Today** selected, so the chart groups data by hour.
- Usage is the sum of input and output Tokens. By default, new requests are counted after about 5–10 minutes.
- Data appears only after the administrator enables statistics for the data dashboard. See <a href="/en/docs/guide/feature-guide/system-settings/settings-content#data-dashboard" target="_blank" rel="noopener noreferrer">Console Content Configuration</a>.
- A model on the leaderboard may have been removed from the Model Marketplace or may be unavailable to your account. If so, selecting its name shows **Model Not Found**.
</Callout>

<Accordion title="Model Marketplace or Rankings is missing from the top navigation or redirects to the homepage">
**Possible cause**  
The administrator disabled the corresponding navigation entry. Once an entry is disabled, opening a bookmarked URL also redirects you to the homepage.

**What to do**

1. On narrow screens such as phones, open the top navigation menu on a public page such as the homepage. In the console, the top navigation is hidden when the window is less than 1024 px wide.
2. If you need access, ask the administrator to enable the entry.
</Accordion>

<Accordion title="Model Marketplace or Rankings asks you to sign in">
**Message shown**  
“Please sign in to view ….” Below it, you’ll see “You will be redirected to the sign-in page in … seconds.”

**Possible cause**  
The administrator requires users to sign in to view the page, and you’re currently signed out.

**What to do**

1. Click **Sign In Now**, or wait 5 seconds to be redirected automatically.
2. After signing in, you’ll automatically return to the page you were trying to view.
</Accordion>

<Accordion title="Prices in the Model Marketplace differ from the amounts charged">
**Possible causes**

- If you haven’t selected a Group, the list shows prices for the available Group with the lowest Ratio. Requests are billed according to the Group assigned to your API key.
- Your account may have custom Ratios for certain Groups. Sign in to see the prices that apply to your account.
- Models with dynamic billing are charged at the tier or time window that applies to each request. Cached content, images, and audio are billed at their respective rates.
- If you select **Top Up**, the displayed prices are calculated from the amount paid for the top-up, before applying Group top-up Ratios or top-up discounts.

**What to do**

1. Sign in and use **Group** in the **Filters** bar to select the Group assigned to your API key and view its prices.
2. In the model details, open **Overview** and check the Ratio under **Pricing by Group**.
3. Check the billing breakdown for the request in <a href="/en/docs/guide/feature-guide/user/log#view-log-details" target="_blank" rel="noopener noreferrer">Usage Logs</a>.
</Accordion>

<Accordion title="A model shows a price, but requests report that pricing hasn’t been configured">
**Message shown**  
“Model … has not been priced by the administrator yet. Please contact the site administrator to enable this model.”

**Explanation**  
Until the administrator sets a price for the model, the Model Marketplace displays the system default price. When prices are displayed in USD and the Group Ratio is 1, input costs $75 / 1M Tokens, and output pricing varies by model. To use these models at the default price, enable **Accept Unpriced Models** in your <a href="/en/docs/guide/feature-guide/user/personal-setting#configure-notification-and-behavior-preferences" target="_blank" rel="noopener noreferrer">Profile</a>.

**What to do**

1. Use another model.
2. If you need this model, ask the administrator to set its price.
</Accordion>

<Accordion title="A model appears in the Model Marketplace, but requests fail">
**Explanation**  
A model appears in the Model Marketplace when the site has an available Channel that provides it and at least one Group available to your account can use it. Access depends on the Group used for the request, and individual requests can still fail. Use the exact message to identify the cause.

| Message shown | Possible cause | What to do |
| --- | --- | --- |
| “This token has no access to model …” | **Model Restrictions** are enabled for the API key, and the model is outside the allowed set. | Edit the key’s **Model Restrictions**. See <a href="/en/docs/guide/feature-guide/user/token#frequently-asked-questions" target="_blank" rel="noopener noreferrer">API Keys</a>. |
| “No available channel for model … under group … (distributor)” | The Group assigned to the API key can’t use this model. | Check the available Groups under **Pricing by Group** in the model details, then change the Group assigned to the key. |
| “Insufficient user quota, remaining quota: …” | Your account balance is too low. | Open your <a href="/en/docs/guide/feature-guide/user/wallet" target="_blank" rel="noopener noreferrer">Wallet</a> to top up or redeem Quota. |
| Other upstream errors | The model’s upstream service is temporarily experiencing issues. | Check **Status** on the model card and **Performance** in the model details, then try again later or use another model. |
</Accordion>

<Accordion title="A model is missing, or the models and prices change after you sign in">
**Possible causes**

- The Model Marketplace lists only the models accessible through the Groups available to you. Before you sign in, it uses the Groups the site makes available to all users. After you sign in, it uses the Groups available to your account.
- The administrator disabled the model, or all Channels that provide it have been disabled.
- The administrator just changed the settings. The Model Marketplace updates in about 1 minute.

**What to do**

1. Sign in and refresh the page.
2. Clear your search terms and click **Reset** in the **Filters** bar.
3. If you still can’t find the model, ask the administrator whether it’s available to the Groups assigned to your account.
</Accordion>

<Accordion title="The model’s Groups list includes Groups your account can’t use">
**Explanation**  
The **Groups** field on cards, in tables, and in the **Model** section of the model details lists all Groups that can use the model. **Performance by Group** under **Performance** lists Groups that made requests in the past 24 hours. Both can include Groups your account can’t use. The **Group** filter and **Pricing by Group** list only the Groups available to your account.

**What to do**

1. Use **Pricing by Group** to check which Groups are available to you and what they charge.
2. If you need to use another Group, contact the administrator.
</Accordion>

<Accordion title="Performance data is missing or Status shows “—”">
**Message shown**  
“Performance data is not yet available for this model.”

**Possible causes**

- The model had no requests that qualified for performance statistics in the past 24 hours. Failures caused by the requests themselves, such as invalid parameters or insufficient balance, are excluded.
- The administrator disabled model performance metrics.
- The data failed to load.

**What to do**

1. Refresh the page later.
2. If the data remains unavailable, ask the administrator whether performance metrics are enabled.
</Accordion>

<Accordion title="Supported Parameters or Rate Limits in the API section differ from actual behavior">
**Explanation**  
These sections show reference examples generated from the model type. The parameters the model accepts and the limits the site enforces may differ from the examples.

**What to do**

1. Check the model provider’s documentation and the <a href="/en/docs/api" target="_blank" rel="noopener noreferrer">API Reference</a> for request parameters.
2. Ask the administrator which rate limits apply.
</Accordion>

<Accordion title="The request example uses http://localhost:3000">
**Possible cause**  
The example uses the server URL configured by the administrator and falls back to `http://localhost:3000` if no URL is configured.

**What to do**

1. Replace the URL with the one shown under **API URL** on the <a href="/en/docs/guide/feature-guide/user/token#copy-a-key-and-call-a-model" target="_blank" rel="noopener noreferrer">API Keys</a> page.
2. Ask the administrator to configure the server URL.
</Accordion>

<Accordion title="Rankings are empty, aren’t updating, or show “Unable to load rankings”">
**Message shown**  
“Unable to load rankings.” The specific reason appears below the message.

**Possible causes**

- The administrator hasn’t enabled usage statistics for the data dashboard, or the requests were made before statistics were enabled.
- No requests were made during the selected time range.
- By default, new requests take about 5–10 minutes to appear.
- The network or service is temporarily experiencing issues.

**What to do**

1. Select a longer time range, such as **This Month**.
2. Refresh the page later.
3. If there’s still no data, ask the administrator whether usage statistics are enabled for the data dashboard.
</Accordion>

<Accordion title="Clicking a model name in Rankings shows “Model not found”">
**Message shown**  
“Model not found.” The description reads “The model you’re looking for does not exist.”

**Possible cause**  
Rankings are based on historical usage. The model may no longer be listed in the Model Marketplace, or the Groups available to your account may no longer have access to it.

**What to do**

1. Click **Back to Models** and look for an available alternative in the Model Marketplace.
</Accordion>
