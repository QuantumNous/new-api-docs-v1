## Send Messages and View Responses

**Steps**

1. Select a group and model. Click the group and model selector at the lower right of the input box. Select a group under “Model Groups” on the left, then select a model on the right.
2. Set request parameters as needed. Click the parameters icon below the input box, then enable and adjust parameters in “Parameter Settings”. See [Adjust Request Parameters](#adjust-request-parameters).
3. Enter a question, instruction, or prompt in the input box.
4. Click “Send” or press Enter to send the request.
5. View the model’s response as it streams into the chat area. To interrupt generation, click “Stop”.

<Callout type="info" title="Tip">

- If your selected model is unavailable after you switch groups, the Playground automatically selects the first model in the new group.
- For reasoning models, the reasoning process appears above the response. It shows “Thinking...” while the model is reasoning and “Thought for … seconds” once it finishes. Click to expand or collapse it.
- Any content already generated stays in the conversation after you click “Stop”.
- “Attach” and “Search” below the input box are still under development. Clicking them only displays “Feature under development” or “Search is under development”. File attachments, image attachments, and web search are unavailable.
</Callout>

The group and model selector has two columns. The table lists them from left to right.

| Option | Definition | Requirements and Limits | Default |
| --- | --- | --- | --- |

The Playground remembers your last selection. |

## Adjust Request Parameters

**Steps**

1. Click the parameters icon below the input box to open “Parameter Settings”. Hovering over the icon shows “Parameters”.
2. Turn on the switch to the right of each parameter you want to send.
3. Drag the slider or enter a value.

<Callout type="info" title="Tip">

- Requests include only enabled parameters. The current browser saves parameter values and switch settings for your next visit.
- Parameter support varies by model. If a request returns an error, disable the relevant parameter and try again.
- The Playground always streams responses. Custom system prompts and non-streaming responses are unavailable.
</Callout>

**Configuration Options**

The “Parameter Settings” window shows all parameters in one list, with a switch to the right of each. The table follows the order in the window.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| Option | Definition | Requirements and Limits | Default |
| --- | --- | --- | --- |
| Temperature | Controls the randomness and creativity of the output. | Use the slider to select a value from 0.1 to 1 in increments of 0.1. | 0.7, enabled |
| Top P | Limits token selection based on cumulative probability mass. | Use the slider to select a value from 0.1 to 1 in increments of 0.1. | 1, enabled |
| Frequency Penalty | Reduces repetitive wording. | Use the slider to select a value from -2 to 2 in increments of 0.1. | 0, enabled |
| Presence Penalty | Encourages the model to discuss new topics. | Use the slider to select a value from -2 to 2 in increments of 0.1. | 0, enabled |
| Max Tokens | Limits the response length. | Enter an integer from 0 to 200000. Out-of-range values are automatically set to the nearest valid value. | 4096, disabled |
| Seed | Makes responses from compatible models more reproducible. | Enter an integer from 0 to 2147483647. If left blank, the field shows “Not set” and the request omits the seed even when enabled. | Not set, disabled |
</div>

## Manage Conversations

**Regenerate a Response**

1. Hover over the message you want to regenerate from.
2. Click the regenerate icon below the message. Hovering over the icon shows “Regenerate”.

**Edit a Message**

1. Click the edit icon below the message.
2. Edit the content in the text box.
3. When editing a user message, click “Save and Submit” to regenerate the response using the revised content. To save only the edit, click “Save”.

**Delete a Message**

1. Click the delete icon below the message.

**Clear Chat History**

1. Click the trash icon below the input box. Hovering over the icon shows “Clear Chat History”.
2. Click “Clear” in the “Clear Chat History?” dialog.

<Callout type="warn" title="Warning">
Clearing chat history permanently deletes the messages. Your group, model, and parameter settings are retained.
</Callout>

<Callout type="info" title="Tip">

- Each request sends the existing messages in the conversation as context and omits the model’s reasoning. Clear the chat history before starting a new topic.
- Regenerating, editing, deleting, and clearing chat history are unavailable while a response is being generated.
- On narrow screens, message actions are available in the ⋯ menu below each message.
</Callout>

## API Base URL and Authentication

This is the typical OpenAI-compatible base URL for the gateway.

```text
https://your-host/v1
```

Pass your API key as a Bearer Token.

```http
Authorization: Bearer sk-your-api-key
```

The following command sends a chat completion request.

```bash
curl https://your-host/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-your-api-key" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"你好"}]}'
```

## SDK Examples

### Python (OpenAI SDK)

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-xxxxxxxx",
    base_url="https://your-host/v1",
)

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "你好"}],
)
print(response.choices[0].message.content)
```

### Claude Native Format

```bash
curl https://your-platform.com/v1/messages \
  -H "x-api-key: sk-xxxxxxxx" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model": "claude-3-5-sonnet-20241022", "max_tokens": 1024, "messages": [{"role": "user", "content": "Hello"}]}'
```

### Gemini Native Format

```bash
curl "https://your-platform.com/v1beta/models/gemini-1.5-pro:generateContent?key=sk-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"contents": [{"parts": [{"text": "Hello"}]}]}'
```

## Supported API Endpoints

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">
| API | Path | Description |
| --- | --- | --- |
| Chat Completions | `POST /v1/chat/completions` | OpenAI Chat Completions-compatible endpoint. Requires `model` and `messages` and supports both streaming and non-streaming responses. |
| Text Completions | `POST /v1/completions` | Traditional text completion endpoint. Requires `prompt` and `model`. |
| Embeddings | `POST /v1/embeddings` | Converts text or an array of text strings into vectors. Requires `input`. The channel adapter converts the request to the upstream format. |
| Image Generation | `POST /v1/images/generations` | Generates images from a prompt. The model, image size, quality, and number of images depend on the request parameters and configured channels. |
| Image Editing | `POST /v1/images/edits` | Edits images using an input image and a prompt. Supports JSON and `multipart/form-data` requests. |
| Legacy Edits | `POST /v1/edits` | Reserved legacy path that is currently unavailable. Use `/v1/images/edits` for image editing. |
| Speech to Text | `POST /v1/audio/transcriptions` | Converts audio to text. Forwards the request to the appropriate speech recognition channel using the OpenAI Audio API format. |
| Audio Translation | `POST /v1/audio/translations` | Recognizes spoken content in the audio and returns the translated text. |
| Text to Speech | `POST /v1/audio/speech` | Converts input text to audio. |
| Reranking | `POST /v1/rerank` | Ranks candidate `documents` by relevance to the `query`. Both the query and the document list must be non-empty. |
| Moderation | `POST /v1/moderations` | Moderates text or other inputs. If the request omits a model, the endpoint uses the default moderation model candidates. |
| Responses API | `POST /v1/responses` | OpenAI Responses-format endpoint that supports inputs, tools, and response events. |
| Responses WebSocket | `GET /v1/responses` (WebSocket) | Connects to the Responses endpoint over WebSocket. Once connected, send a `response.create` event to create a response. The endpoint selects a channel after receiving the first `response.create` event. Pass the API key the same way as for the Realtime endpoint. |
| Responses Compaction | `POST /v1/responses/compact` | Compacts the context of a Responses request. |
| Codex Web Search | `POST /v1/alpha/search` | Endpoint for the standalone Codex web search format. Currently, only Sub2API, New API, Codex, and advanced custom channels that support this capability can handle these requests. |
| DeepSeek Search | `POST /v1/tools/search` | DeepSeek search endpoint that forwards the request body and returns the response as received. It always uses `deepseek-search` for channel selection and bills per request without counting tokens. Currently, only DeepSeek, New API, Sub2API, and advanced custom channels can handle these requests. |
| DeepSeek Web Fetch | `POST /v1/tools/fetch` | DeepSeek web fetch endpoint. It always uses `deepseek-fetch` for channel selection and bills per request. It uses the same forwarding behavior and channels as DeepSeek Search. |
| Claude Messages | `POST /v1/messages` | Anthropic Claude Messages-compatible endpoint. Requires `model` and message content. New API converts the request to the upstream protocol when necessary. `/v1/messages/count_tokens` is currently disabled. |
| Realtime | `GET /v1/realtime` (WebSocket) | OpenAI Realtime-style endpoint for bidirectional real-time communication. The model is typically passed as a query parameter. You can pass the API key as a Bearer Token or through the WebSocket subprotocol. |
| Gemini Native Model Operations | `POST /v1beta/models/{model}:{action}` | Gemini native-format endpoint for model actions such as `generateContent`, `streamGenerateContent`, and embedding operations. `:countTokens` is currently unsupported and returns 404. |
| Gemini-Compatible Model Operations | `POST /v1/models/{model}:{action}` | Accepts Gemini-style model operation requests under the `/v1` prefix. Gemini Relay parses and converts the requests. |
| List Models | `GET /v1/models` | Returns an OpenAI-format model list by default. Returns Claude format when both `x-api-key` and `anthropic-version` headers are present, or Gemini format when the request includes an `x-goog-api-key` header or a `key` query parameter. |
| Model Details | `GET /v1/models/{model}` | Retrieves information about a single model. If the model does not exist, the endpoint returns a `model_not_found` error object with HTTP status 200. |
| Gemini Model List | `GET /v1beta/models` | Returns a list of available models in Gemini format. Response fields include `models` and `nextPageToken`. |
| OpenAI-Format Model List | `GET /v1beta/openai/models` | Returns the model list in OpenAI format under the Gemini-compatible namespace. |
</div>

<Accordion title="The model list is empty or Send is disabled">
**Message**  
“Failed to load playground models” or “Failed to load playground groups.” You may see no message at all.

**Possible causes**

- The selected group has no available models.
- Your account has no available groups, so the group and model selector is disabled.
- The input box is empty, or the model list is still loading.

**What to do**

1. Use the left side of the group and model selector to switch to another group.
2. Refresh the page and try again.
3. If the issue persists, contact your administrator to enable a model or group for your account.
</Accordion>

<Accordion title="Error and Request error: … appear after you send a message">
**Explanation**  
A failed reply appears in a red “Error” box. It shows “Request error: ” followed by the message returned by the server, with “Retry,” “Edit,” and “Delete” below. If you leave a failed reply in the conversation, the Playground sends it to the model as context with your next message. Click “Retry” or “Delete” before sending a new message. Use the exact error message to identify the cause.

| Message | Possible cause | What to do |
| --- | --- | --- |
| “No permission to access this group” | The selected group is no longer available to your account. For example, an administrator may have changed the group settings. | Refresh the page and select a group again. |
| “No available channel for model … under group … (distributor)” | No channel in the selected group is currently available to handle requests for this model. | Switch to another group or model. If the issue persists, contact your administrator. |
| “Insufficient user quota, remaining quota: …”<br/>“Not enough quota to pre-consume for this request: … remaining, … required” | Your account balance is insufficient. | Go to <a href="/en/docs/guide/feature-guide/user/wallet" target="_blank" rel="noopener noreferrer">Wallet</a> to top up or redeem quota. |
| “Subscription quota is insufficient or no subscription is configured: …” | This request is billed against your subscription, but the subscription has insufficient quota or no subscription is available. | Go to <a href="/en/docs/guide/feature-guide/user/wallet#subscription-plans" target="_blank" rel="noopener noreferrer">Wallet</a> to check your subscription. |
| Other errors returned by the upstream service, usually in English | The upstream service is busy, rate-limiting requests, or experiencing an outage. | Click “Retry” later, or switch to another model or group. |
</Accordion>

<Accordion title="Model Pricing Not Configured appears">
**Message**  
“Model … has not been priced by the administrator yet. Please contact the site administrator to enable this model.”

**Explanation**  
The model list shows available models by group without checking whether pricing is configured. If you send a message using a model without pricing, an orange “Model Pricing Not Configured” card appears and no charge applies. Administrators see the message “Pricing has not been configured for model …. Go to System Settings → Operations Settings to enable Self-Use Mode, or configure pricing for this model under System Settings → Group and Model Pricing Settings.” The card also includes a “Go to Settings” button visible only to administrators. The button opens the model pricing page in System Settings in a new tab. Only Root users can access that page.

**What to do**

1. Select another model in the group and model selector.
2. If you need to use this model, ask your administrator to configure its pricing.
</Accordion>

<Accordion title="There is no reply after sending a message, or the reply is empty">
**Possible causes**

- The model returned no reply text. For example, if it returned only its reasoning, the Playground displays only “Thought for … seconds.”
- “Max Tokens” is enabled and set too low.
- The upstream service has not responded for an extended period, so the Playground keeps displaying “Responding...”.

**What to do**

1. If “Responding...” stays on screen, click “Stop.”
2. In “Parameter Settings,” turn off “Max Tokens” or increase its value.
3. Click the regenerate icon below the previous user message, or switch models and try again.
</Accordion>

<Accordion title="Conversation history is missing">
**Possible causes**

- Conversation history is stored only in the current browser. You may have switched browsers or devices, or opened an incognito window.
- You cleared the site's data in your browser.
- You switched accounts. Each account's conversation history is stored separately.
- The conversation area displays only the 24 most recent messages. Older messages are still stored in the current browser and sent to the model as context each time you send a message.
- Once the conversation exceeds 100 messages, only the 100 most recent messages are kept.
- When the site is upgraded from an older version, conversation history saved by that version is no longer retained.

**What to do**

1. Sign in to the original account in the original browser to view your history.
2. To keep content long term, use the copy icon below the message and save the content separately.
</Accordion>

<Accordion title="Playground calls are missing from Usage Logs, or the API key's used quota is unchanged">
**Explanation**  
The Playground uses your account quota directly and does not use API keys. Its calls do not count toward any API key's used quota. Successful calls appear as “Consumption” entries in Usage Logs. The “Token” column shows `playground-` followed by the selected group name, as in `playground-default`. Failed calls incur no charge and appear in the logs only if the site has enabled error logging.

**What to do**

1. In <a href="/en/docs/guide/feature-guide/user/log" target="_blank" rel="noopener noreferrer">Usage Logs</a>, enter the full name in the “Token Name” field, such as `playground-default`.
2. Set the time range to cover when the calls were made, then click “Search.”
</Accordion>

<Accordion title="Clicking Playground takes you back to the Overview page">
**Possible cause**  
An administrator disabled the Playground.

**What to do**

1. Use an API key to call the model. See [API URL and Authentication](#api-base-url-and-authentication).
2. If you need to use the Playground, contact your administrator.
</Accordion>

<Accordion title="Clicking Attach or Search displays Feature in development">
**Message**  
“Feature in development” or “Search feature in development”

**Explanation**  
The “Upload File,” “Upload Photo,” “Screenshot,” and “Take Photo” options under “Attach” are still in development, as is “Search.” The Playground currently supports text messages only. File attachments, images, and web search are unavailable.

**What to do**

1. Send text only.
2. To send files or images, make an API call from a client that supports them.
</Accordion>
