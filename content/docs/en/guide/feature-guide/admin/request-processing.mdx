## Common Operations

This section covers adding, editing, reordering, enabling, disabling, and deleting instances, as well as running tests and adding instances to Channels.

### Add and Edit Instances

- Request Processing – Add Request Processing

![Add Request Processing page](/assets/guide/feature-guide/request-processing-add-instance.png)

**To Add an Instance**

1. Click “Add” in the upper-right corner of the page.
2. Click a plugin card in the “Add Request Processing” dialog.
3. To rename the instance, click the pencil icon next to the name at the top of the dialog. The name defaults to the plugin name and can be up to 64 characters long. Clearing the name restores the plugin name.
4. Configure the plugin under “Settings”. For the settings of each built-in plugin, see [Built-in Request Processing Plugins](#built-in-request-processing-plugins).
5. Under “Where to Apply”, select the scope on the first row and the applicable models on the second. See the table at the end of this section for the available options.
6. To test the instance, select “Sample Request” or “Paste Request” under “Try It” on the right, then click “Run”.
7. Check the “Enabled” switch in the lower-left corner, then click “Save”.

<Callout type="info" title="Tip">

- The text below the dialog title reads “Choose a plugin to get started. You can change its settings at any time.”
- Each plugin card shows the plugin description and execution stages, such as “Before Reading the Request”, “Before Sending”, and “Check Response”.
- The card also shows how the plugin handles errors, either “Skip on Error” or “Reject Request on Error”.
- Cards for plugins that already have instances show “… added”.
- To select a different plugin, click “Change Plugin” in the lower-left corner. The name and settings reset to the new plugin’s defaults. The “Where to Apply” and “Enabled” selections are retained.
- If a setting is invalid, the reason appears below the field, such as “This field is required”.
- If server-side validation fails, “Invalid settings for request processing instance …: …” appears below “Where to Apply” and the dialog stays open.
- On a successful save, the dialog closes and the new instance appears at the end of the list.
- Click “Cancel” to discard unsaved changes. The dialog reopens with the last saved values.

</Callout>

### Reorder, Enable, or Delete Instances

Perform these actions directly in the instance list. Each action saves the entire list immediately. Successful saves produce no notification.

**List Actions**

- To reorder instances, click the move up or move down button to the right of the position number in the “Order” column.
- To enable or disable an instance, click the switch in the “Enabled” column. If the save fails, the switch returns to its previous state.
- To change settings, see [Add and Edit Instances](#add-and-edit-instances).

**To Delete an Instance**

1. Click the delete icon at the end of the instance’s row.
2. Click “Delete” in the “Delete Instance?” confirmation dialog.

<Callout type="warn" title="Caution">

- The confirmation dialog says “… will stop processing requests, including on Channels it was added to.” Deletion is permanent.
- Channels retain their references to the deleted instance and show it as “Deleted”. See [Add an Instance to a Channel](#add-an-instance-to-a-channel).
- If the save fails, the server’s original error message appears in a pop-up and the list stays as it was.
- A common cause is an enabled instance that uses a disabled plugin. See [Instance Status](#instance-status).

</Callout>

**To Perform a Dry Run**

### Add an Instance to a Channel

Instances with “Where to Apply” set to “Only When Added to a Channel” run only on the Channels they are added to. Other instances also run on requests for the Channels they are added to.

## Rules and Behavior

This section covers execution stages and order, how blocked requests are handled and logged, and settings for the six built-in request processing plugins.

### Execution Stages and Order

Each plugin declares which stages it runs in. These stages appear on the plugin card and at the top of the instance dialog.

**Execution Stages**

- “Before Reading the Request” inspects or modifies the client request after it arrives and before a Channel is selected. Instances added to a Channel run after that Channel is selected.
- “Before Format Conversion” runs after Channel selection and before the request is converted to the Channel’s format.
- “Before Sending” runs before each attempt to send the request to the Channel and before Channel parameter overrides are applied.
- “Final Check” inspects the outgoing request after Channel parameter overrides are applied. At this stage, instances can reject the request only.
- “Check Response” inspects the model response and stops it when a rule matches.

**Execution Order**

- The text above the list reads “Instances run from top to bottom. Instances that apply to all requests run first, followed by instances for the request’s Group, then instances added to the Channel.”
- Within each scope, instances run in list order. Instances added to a Channel run in the order set on that Channel.
- Changing the order can change the result. Use [Dry Run](#dry-run) to check the result after reordering instances.
- To set parameter rules that apply across all Channels, configure a [Global Parameter Override](#global-parameter-override) instance.

### Blocking and Logging

When an instance rejects a request or encounters an error, the client receives an error according to the plugin’s error handling behavior. The usage log records the outcome.

**Errors Returned to Clients**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Situation | What the Client Receives | Sent Upstream |
| --- | --- | --- |
| An instance rejects the request | HTTP 400 with error code `request_rejected`.<br/>The message comes from the plugin, such as the “Rejection Message” in Request Filtering. Content Moderation returns an English message. If no message is set, the default is “Request rejected by policy”. The message ends with “(code: …)”, such as `request_filtered` for Request Filtering, `sensitive_content` for Request Redaction, or `moderation.flagged` for Content Moderation. | No. The request is also ineligible for retry on another Channel. |
| An instance encounters an error and the plugin’s “On Error” setting is “Reject Request”, such as when the moderation endpoint is unreachable | HTTP 500 with error code `request_plugin_failed`.<br/>Message “A request plugin failed”. | No. The request is also ineligible for retry on another Channel. |
| An instance encounters an error and the plugin’s “On Error” setting is “Skip” | — | Yes. The instance is skipped and the request is sent as usual. |
| A response is stopped during “Check Response” | Error code `response_rejected`. A non-streaming response returns HTTP 400. A streaming response ends with an error after any content already sent.<br/>The message comes from the plugin and defaults to “Response stopped by policy”. The message ends with “(code: …)”. | Yes. The model response is stopped. |

</div>

### Built-in Request Processing Plugins

New API includes the following six request processing plugins. The list can change by version. You can also upload other request processing plugins or install them from the plugin marketplace in <a href="/en/docs/guide/feature-guide/admin/task-plugins" target="_blank" rel="noopener noreferrer">Plugin Management</a>.

**Plugin Reference**

When a plugin encounters an error and its “On Error” behavior is “Reject Request”, the request is rejected. See [Blocking and Logging](#blocking-and-logging). If the behavior is “Skip”, the instance is skipped and the request is sent as usual.

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| Plugin | Execution Stages | On Error | Purpose |
| --- | --- | --- | --- |

| Request Redaction (`request-redact`) | Before Reading the Request, Final Check, Check Response | Reject Request | Replaces personal information and secrets in request text before sending. See [Request Redaction](#request-redaction). |

| Global Parameter Override (`param-override`) | Before Sending | Reject Request | Applies parameter override rules to all requests, specific Groups, or specific models. See [Global Parameter Override](#global-parameter-override). |

</div>

### Request Filtering

- Request Processing – Request Filtering Configuration

![Request Filtering configuration page](/assets/guide/feature-guide/request-processing-add-request-filtering.png)

Rejects requests whose text matches a keyword or regular expression. At “Before Reading the Request”, the plugin checks all request text, including messages from every role, system prompts, tool definitions and call arguments, tool results, prompts, and attached text, PDF, and DOCX files. At “Final Check”, it checks the outgoing request again, including any text added by Channel parameter overrides. On a match, the client receives HTTP 400 with error code `request_rejected`. The response uses the “Rejection Message” followed by `(code: request_filtered)`.

**Configuration Reference**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Setting | Definition | Requirements and Limits | Default |
| --- | --- | --- | --- |
| Rules | Rejects the request if any rule matches. Click “Add Rule” to add rules individually. | Optional. Up to 500 rules. | None |
| Rules › Keyword or Expression | The keyword or regular expression to match. | Required. 1–1024 characters. Regular expressions starting with `(?i)` are case-insensitive. Correct invalid expressions before saving. | — |
| Rules › Match Type | “Keyword” or “Regular Expression”. | — | Keyword |
| Rules › Case Sensitive | Whether matching is case-sensitive. | — | Off |
| Rules › Rule ID | Recorded in the usage log when the rule matches. | Optional. Up to 64 characters. Leave blank to assign IDs in order, such as rule-1, rule-2, and so on. | Blank |
| Keyword List | One keyword per line. A request is rejected if it contains any of them. | Optional. Useful for large keyword lists. If only the keyword list matches, the log records `keywords`. | Blank |
| Case-Sensitive Keywords | Whether the keyword list is case-sensitive. | — | Off |
| Rejection Message | The message returned to the client. | Optional. Up to 256 characters. Leave blank to use “Request rejected by policy”. The gray text in the input field is an example. | Blank |
| Check Response | Also stops model responses that match the rules. | If the response is stopped, the client receives error code `response_rejected`. For streaming responses, the plugin briefly buffers a short trailing segment of text so it can detect keywords split across chunks. | Off |

</div>

### Request Redaction

- Request Processing – Request Redaction Configuration

![Request Redaction configuration page](/assets/guide/feature-guide/request-processing-add-request-redaction.png)

At “Before Reading the Request”, the plugin replaces personal information and secrets in request text, then continues processing the request. It applies “Built-in Types” first, followed by “Custom Rules”, to messages, system prompts, prompts, and attached text files. Tool definitions are excluded. Files such as PDFs and DOCX documents cannot be rewritten. If they contain sensitive information, the “Pre-Send Check” setting determines how to handle the request.

**Configuration Reference**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Setting | Definition | Requirements and Limits | Default |
| --- | --- | --- | --- |
| Built-in Types | Types of information to replace, including email addresses, phone numbers, national ID numbers, bank card numbers, API keys and Tokens, and IPv4 addresses. | Click one or more tags to select types. Phone numbers include mainland China mobile numbers and international numbers with a leading +. National ID and bank card numbers are replaced only if they pass check digit validation. | All selected except “IPv4 Addresses” |
| Custom Rules | Regular expressions applied after the built-in types. Click “Add Rule” to add rules individually. | Optional. Up to 50 rules. | None |
| Custom Rules › Regular Expression | The expression that matches text to replace. | Required. 1–1024 characters. Correct invalid expressions before saving. | — |
| Custom Rules › Replacement Text | The replacement text for this rule. | Optional. Up to 64 characters. Leave blank to use “Default Replacement Text”. | Blank |
| Custom Rules › Rule ID | Recorded in the usage log when the rule matches. | Optional. Up to 64 characters. Leave blank to assign IDs in order. | Blank |
| Default Replacement Text | The text used to replace each match. | Up to 64 characters. | `[REDACTED]` |
| Pre-Send Check | How to handle outgoing requests that still contain sensitive information. Select “Reject Request” or “Off”. | With “Reject Request”, the plugin rejects the request with “Request rejected by policy” followed by `(code: sensitive_content)` in any of these cases. The “Final Check” stage finds sensitive information still present, such as text added by Channel parameter overrides. An attachment cannot be rewritten. The request has more than 512 matches, so some cannot be replaced. With “Off”, the request is sent as usual in all these cases. | Mask Response | Also masks text in model responses that matches these types and rules. | All matches in responses are replaced with `***`, regardless of the configured replacement text. For streaming responses, the plugin briefly buffers a short trailing segment of text. | Off |

</div>

<Callout type="info" title="Tip">
“IPv4 Addresses” is off by default because version numbers and example addresses can look like IPv4 addresses and be replaced by mistake.
</Callout>

### Content Moderation

- Request Processing – Content Moderation Configuration

![Content Moderation configuration page](/assets/guide/feature-guide/request-processing-add-content-moderation.png)

At “Before Reading the Request”, the plugin sends user messages, including their images and text from attached documents, to an OpenAI-compatible moderation endpoint. If the content is flagged, the plugin rejects the request. The client receives HTTP 400 with error code `request_rejected` and the message `The request was flagged by content moderation (code: moderation.flagged)` (English only). The plugin checks user messages and prompts in requests such as completions, embeddings, and image generation. It excludes system prompts and tools. You need a reachable moderation endpoint, such as OpenAI’s moderation endpoint.

**Configuration Reference**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_td_code]:wrap-anywhere [&_th]:whitespace-nowrap">

| Setting | Definition | Requirements and Limits | Default |
| --- | --- | --- | --- |
| Moderation Endpoint URL | The endpoint that accepts OpenAI moderation requests. | Required. Enter a full URL starting with http:// or https://, up to 2048 characters. | `https://api.openai.com/v1/moderations` |
| API Key | The key used to call the moderation endpoint, sent as a Bearer Token. | Optional. Leave blank if the endpoint requires no key. Up to 1024 characters. | Blank |
| Moderation Model | The model name sent to the moderation endpoint. | Leave blank to use the endpoint’s default model. Up to 128 characters. | `omni-moderation-latest` |
| Text to Check | Which user messages to send to the moderation endpoint. Select “Last User Message” or “All User Messages”. | If the text is too long to submit in full, the plugin rejects the request with `The request is too long for content moderation (code: moderation.too_long)` (English only). | Last User Message |
| Check Images | Also sends images from user messages to the moderation endpoint. | Up to 3 images are submitted per request. | On |
| Categories to Block | Rejects requests flagged in any of the selected categories. There are 13 categories, including “Harassment”, “Hate”, and “Violence”. | Click one or more tags to select categories. If none are selected, all flagged requests are rejected. | None selected |
| Moderate Responses | Also moderates model responses and stops them if flagged. | Non-streaming responses are submitted in full. Streaming responses are submitted in chunks of approximately 1000 characters and sent to the client only after they pass moderation. If the response is stopped, the client receives error code `response_rejected` and the message `The reply was flagged by content moderation (code: moderation.flagged)` (English only). | Off |

</div>

<Callout type="warn" title="Caution">

- User messages, images, and text from attached documents are sent to the “Moderation Endpoint URL”. Use a service you trust.
- Each request calls the moderation endpoint. With “Moderate Responses” enabled, responses also call it, increasing response times and endpoint usage. “Try It” and “Dry Run” also call the endpoint.
- If the moderation endpoint is unreachable, returns an error, or takes longer than 15 seconds for a call, the plugin treats it as an execution error. The request is rejected and the client receives HTTP 500. See [Blocking and Logging](#blocking-and-logging).

</Callout>

### Image Compression

- Request Processing – Image Compression Configuration

![Image Compression configuration page](/assets/guide/feature-guide/request-processing-add-image-compression.png)

At “Before Sending”, the plugin compresses large images embedded in the request as base64. Images referenced by URL are skipped. If the instance encounters an error, it is skipped and the images are sent as is.

**Configuration Reference**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Setting | Definition | Requirements and Limits | Default |
| --- | --- | --- | --- |
| Compression Mode | “Lossless” or “Lossy”. | Lossless mode converts only PNG and GIF images to WebP, preserving every pixel and the original dimensions. The upstream service must support WebP. JPEG and WebP images are skipped. | Lossless |
| Minimum Image Size | Images at or above this size are compressed. | 0 or greater. Available units are B, KB, and MB, with 1 KB equal to 1000 bytes. | 512 KB |
| Longest Side | Images whose longest side exceeds this value are compressed and scaled down proportionally. | Appears when “Compression Mode” is “Lossy”. Range 16–16384 px. In lossy mode, an image is compressed if it reaches “Minimum Image Size” or its longest side exceeds this value. | 2048 |
| Output Format | “Auto”, “JPEG”, or “PNG”. “Auto” uses PNG for images with transparency and JPEG for the rest. | Appears when “Compression Mode” is “Lossy”. | Auto |
| JPEG Quality | Higher values preserve more detail and save less space. | Appears when “Compression Mode” is “Lossy” and “Output Format” is “Auto” or “JPEG”. Range 1–100. | 85 |

</div>

<Callout type="info" title="Tip">

- The plugin keeps the original image if the compressed version is the same size or larger.
- The plugin skips animated GIFs and images larger than 20 MiB or 40 million pixels.
- The plugin compresses up to 32 images per request. Any remaining images are sent as is.

</Callout>

## Saving and Applying Changes

Adding, editing, deleting, reordering, enabling, or disabling an instance immediately saves the entire list as system settings. Changes take effect immediately on the node handling the save request. Other nodes usually receive the changes within about 3 seconds through system setting synchronization, and at the latest within one sync interval, which defaults to 60 seconds.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Action | How It Is Saved | When It Takes Effect |
| --- | --- | --- |
| Add or edit an instance | Click “Save” in the dialog. | The new settings apply starting with the next request. |
| Reorder, enable, or disable an instance | Click a move up or move down button or the “Enabled” switch. The list saves immediately, with no notification on success. | The new order and status apply starting with the next request. |
| Delete an instance | Click “Delete” in the “Delete Instance?” confirmation dialog. A successful save produces no notification. | The instance stops running starting with the next request, including on Channels it was added to. |
| Add an instance to a Channel | Click “Update Channel” in the Channel drawer. | See <a href="/en/docs/guide/feature-guide/admin/channel#saving-and-applying-changes" target="_blank" rel="noopener noreferrer">Channel Management</a>. |

</div>

**Additional Details**

- **Dry runs are read-only.** “Dry Run” uses saved instances only. “Try It” in the dialog uses the current settings, including unsaved changes. Both leave the instance list untouched.
- **Plugin switches.** Request processing operates independently of the global “Enable Plugins” switch on the Plugin Management page. Disabling an individual request processing plugin stops its instances from running and retains their settings. See [Instance Status](#instance-status).
- **Save failures.** If a list action fails to save, the server’s original error appears in a pop-up and the list stays as it was. If a save fails in the dialog, the original error appears below “Where to Apply”.

## Important Notes

- **Deleting an instance affects Channels it was added to.** The confirmation dialog says “… will stop processing requests, including on Channels it was added to.” Deletion is permanent.
- **Blocked requests are ineligible for retry.** A request rejected by an instance returns HTTP 400 immediately, with no retry on another Channel. See [Blocking and Logging](#blocking-and-logging).
- **Order affects results.** Instances within each scope run in list order. Reordering them can change the result. Use “Dry Run” to check the result after reordering. See [Execution Stages and Order](#execution-stages-and-order).
- **Request body passthrough skips some instances.** When “Pass Through Request Body” is enabled on the Channel or “Enable Request Passthrough” is enabled under “Global Model Configuration” in System Settings, the request is sent upstream as is. The “Before Format Conversion” and “Before Sending” stages are skipped, including Automatic Reasoning Effort, Image Compression, and Global Parameter Override. Channel-added instances are also skipped at “Before Reading the Request”. “Final Check” and “Check Response” run as usual, with “Final Check” inspecting the unchanged request. The usage log marks skipped “Before Sending” instances and skipped “Before Reading the Request” steps of Channel-added instances as “Not Checked”.
- **Automatic Reasoning Effort requires models with reasoning support.** Select “Specific Models” on the second row of “Where to Apply” and choose only models that support reasoning. See [Automatic Reasoning Effort](#automatic-reasoning-effort).
- **Content Moderation sends user text to the configured endpoint.** User messages, images, and text from attached documents are sent to the moderation endpoint in the settings. See [Content Moderation](#content-moderation).

<Accordion title="The request is rejected and the client receives HTTP 400">

**Error Message**

“Request rejected by policy (code: …)” or the plugin’s message followed by “(code: …)”. The error code is `request_rejected`.

**Possible Cause**

The request matched a rule in a request processing instance, such as a Request Filtering keyword.

**Resolution**

1. In the usage log details, check the “Request Processing” section to identify the instance that blocked the request.
2. Reproduce the issue with “Dry Run” on this page. Adjust the instance’s settings or scope, or disable it as needed.

<Accordion title="The client receives HTTP 500 and the message A request plugin failed">

**Error Message**

“A request plugin failed” with error code `request_plugin_failed`.

**Possible Cause**

An instance encountered an error. For example, Content Moderation may have an invalid endpoint URL or API key, or the endpoint may be unreachable or take longer than 15 seconds to respond.

**Resolution**

1. Reproduce the issue with “Dry Run” on this page. The first line of the results shows “… failed: …” and the reason.
2. Update the instance settings based on the error, or temporarily disable the instance.

</Accordion>

<Accordion title="An instance does not take effect">

**Possible Causes**

- The instance is disabled, or its plugin is disabled or missing. In the latter case, the list shows “Plugin disabled”. See [Instance Status](#instance-status).

- The instance is set to “Only When Added to a Channel” and has yet to be added to the Channel that processed the request.
- The Channel that processed the request has request body passthrough enabled, so the “Before Format Conversion” and “Before Sending” stages are skipped. See [Important Notes](#important-notes).

**Resolution**

1. Run “Dry Run” with the same model, Group, and Channel ID to see which instances run.

</Accordion>

**Resolution**
