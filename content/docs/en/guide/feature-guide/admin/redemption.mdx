## Common Operations

The following procedures cover creating, copying and distributing, editing, enabling and disabling, and deleting redemption codes, in the order you typically use them.

### Create Redemption Codes

- Redemption Code Management – Create Redemption Codes

![Redemption Code Management – Create Redemption Codes page](/assets/guide/feature-guide/redemption-create.png)

- Redemption Code Management – Redemption Codes Created

![Redemption Code Management – Redemption Codes Created dialog](/assets/guide/feature-guide/redemption-save.png)

**Prerequisite**

- Root has confirmed the current version of the payment compliance terms. See [Permission and Compliance Prerequisites](#permission-and-compliance-prerequisites).

**Procedure**

1. Click “Create Code” in the upper-right corner of the page.
2. In the “Create Redemption Codes” drawer, enter the name, quota, expiration time, and quantity.
3. Click “Save Changes”.
4. In the “Redemption Codes Created” dialog, select “Save as File” if you need to keep a distribution list, then choose the file format and which fields to include.
5. Click “Done”.

<Callout type="warn" title="Keep redemption codes secure">
  A full redemption code is a transferable quota credential. Keep full codes out of public screenshots, group chats, support tickets, logs, and code repositories. After creating a batch, record the recipients and the batch, and restrict access to plaintext copies of unused codes.
</Callout>

### Copy and Distribute Redemption Codes

**Copy a single code**

1. Click the copy icon in the “Redemption Code” column of the target row. The tooltip reads “Copy Code”.

**Copy codes in bulk**

1. Select the redemption codes you want to copy on the current page.
2. Click the copy icon in the bulk action bar at the bottom of the page. The tooltip reads “Copy Selected Codes”.

**Copy format**

Bulk copying puts one redemption code on each line.

```text
名称<Tab>完整兑换码
```

<Callout type="info" title="Tip">

- Click a masked redemption code to see its full value in the “Full Code” pop-up.
- This page has no redemption code import or list export option.
- You can save a file only once, from the “Redemption Codes Created” dialog.
- Handle copied content and saved files in a controlled environment. Avoid storing full redemption codes long-term in regular spreadsheets or shared documents.

</Callout>

### Enable or Disable Redemption Codes

**Procedure**

1. Click the ⋯ menu in the target row.
2. Select “Disable” or “Enable”.

<Callout type="info" title="Tip">

- The menu shows “Disable” for “Unused” codes and “Enable” for “Disabled” codes.
- The menu shows only “Delete” for “Used” and “Expired” codes.
- The action is submitted immediately without a confirmation dialog.
- If a “Disabled” code has passed its expiration time, enabling it changes its status to “Expired”. The code remains unavailable for redemption.

</Callout>

### Delete Redemption Codes

**Delete a single code**

1. Click the ⋯ menu in the target row and select “Delete”.
2. Click “Delete” in the “Are you sure?” confirmation dialog.

**Delete codes in bulk**

1. Select the redemption codes you want to delete on the current page.
2. Click the red delete icon in the bulk action bar at the bottom of the page. The tooltip reads “Delete Selected Redemption Codes”.
3. Click “Delete” in the “Delete … redemption codes?” confirmation dialog.

<Callout type="warn" title="Important">

- You can delete codes in any status, including “Unused” codes.
- Deletion is permanent. Use “Disable” if you only need to pause distribution.

</Callout>

### Delete Invalid Redemption Codes

- Redemption Code Management – Delete Invalid Redemption Codes

![Redemption Code Management – Delete Invalid Redemption Codes page](/assets/guide/feature-guide/redemption-delete-invalid.png)

“Delete Invalid” runs a site-wide cleanup regardless of the current search, filters, or selection.

**Codes removed**

- “Used” redemption codes.
- “Disabled” redemption codes.
- Redemption codes that are still enabled but have passed their expiration time according to the server clock.

**Procedure**

1. Click “Delete Invalid” in the upper-right corner of the page.
2. Click “Delete Invalid” in the “Delete invalid redemption codes?” confirmation dialog.

<Callout type="warn" title="Important">

- Cleanup is permanent.
- Cleanup also removes “Disabled” codes. If you plan to re-enable any of those codes, hold off on using “Delete Invalid”.

</Callout>

## Rules and Behavior

Code creation and redemption depend on payment compliance. The system also checks each code at redemption time.

### Permission and Compliance Prerequisites

**Compliance rules**

- Root must confirm the current version of the payment compliance terms under “System Settings” → “Billing & Payments” → “Payment Gateway”. Once Root confirms the terms, admins can create redemption codes and users can see the redemption option on the Wallet page. See <a href="/en/docs/guide/feature-guide/system-settings/settings-billing#payment-compliance-confirmation" target="_blank" rel="noopener noreferrer">Payment Compliance Confirmation</a>.
- The compliance status must be “Confirmed”, and the confirmed version must match the current version of the terms.
- Only Root can confirm the terms, using a console session. An access token cannot substitute for that session.
- If compliance is unconfirmed or the terms version does not match, admins can still view, edit, enable, disable, and delete existing codes. The system rejects code creation and user redemption requests.

### Redemption Rules

Users enter their code in the “Have a redemption code?” section of the Wallet page. For instructions, see <a href="/en/docs/guide/feature-guide/user/wallet#redemption-codes" target="_blank" rel="noopener noreferrer">Wallet</a>.

**Validation and results**

- Only “Unused” codes can be redeemed. The code must be enabled and within its validity period according to the server clock.
- Each code can be redeemed at most once, even if requests are repeated or submitted concurrently.
- After a successful redemption, the code status changes to “Used”, and the system records who redeemed it and when.
- The system credits the quota to the user's balance and adds a “Top-up” entry to their usage log. The entry includes only the redemption code ID.
- All failed redemptions show the same message to the user, “Redemption failed. Please try again later.” See [Frequently Asked Questions](#frequently-asked-questions).

## Status Reference

### Redemption Code Status

The “Status” column in the redemption code list shows the following statuses.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Status | Meaning | Notes |
| --- | --- | --- |
| Unused | The code is enabled, has yet to expire, and is available for redemption. | Green. Can be edited, disabled, or deleted. |
| Disabled | An admin has suspended use of the code. Once re-enabled, it can be redeemed if it is still valid. | Gray, with the entire row grayed out. Can be enabled or deleted. This status appears even if the code has passed its expiration time. |

Redemption codes are stored only in the database and are never cached. The actions below take effect on each node starting with the next redemption request.

| Action | How to Save | When It Takes Effect |
| --- | --- | --- |
| Create redemption codes | Click “Save Changes” in the “Create Redemption Codes” drawer. The “Redemption Codes Created” dialog opens.<br/>When you create one code, “Redemption code created successfully” appears.<br/>When you create multiple codes, “Successfully created … redemption codes” appears. | The codes can be redeemed immediately. |
| Edit | Click “Save Changes” in the “Update Redemption Code” drawer. “Redemption code updated successfully” appears. | Takes effect immediately for future redemptions. Completed redemptions are unaffected. |

| Delete one, delete in bulk, or delete invalid codes | Confirm in the confirmation dialog.<br/>Deleting one code shows “Redemption code deleted successfully”.<br/>Bulk deletion shows “Successfully deleted … redemption codes”.<br/>Deleting invalid codes shows “Successfully deleted … invalid redemption codes”. | Takes effect immediately. ## Important Notes

- **Treat full redemption codes as quota credentials.** For guidance on distribution and storage, see [Create Redemption Codes](#create-redemption-codes).
- **Deletion is permanent.** Use “Disable” to pause distribution. “Delete Invalid” removes all disabled codes on the site. See [Delete Invalid Redemption Codes](#delete-invalid-redemption-codes).
- **Audit records.** Creating, editing, enabling, disabling, or deleting codes generates audit records. This includes single deletions, bulk deletions, and cleanup of invalid codes. These records are available on the <a href="/en/docs/guide/feature-guide/user/audit-log" target="_blank" rel="noopener noreferrer">Audit Logs</a> page and are excluded from “Usage Logs”.
- **Server-side error logs contain raw redemption codes.** The redemption entry in the usage log includes only the code ID. If redemption fails, the server error log records the raw code the user submitted. Deployment operators should restrict access to logs and protect or mask the codes according to their compliance requirements.
- **User redemption is subject to the critical endpoint rate limit.** Redemption requests from the same IP address share a counter with operations such as sign-in, registration, password reset, and top-up order creation. By default, the limit is 20 requests per 1,200 seconds. The system rejects requests above the limit. With Redis enabled, all nodes share the counter. Otherwise, each node counts separately.
- **Environment variables control rate limiting.** `CRITICAL_RATE_LIMIT` sets the request count (default 20), and `CRITICAL_RATE_LIMIT_DURATION` sets the window in seconds (default 1200). `CRITICAL_RATE_LIMIT_ENABLE` defaults to `true`. Set it to `false` to disable rate limiting. The service reads all three variables at startup, so changes require a restart. This page has no corresponding settings. See <a href="/en/docs/guide/feature-guide/system-settings/settings-security#rate-limiting" target="_blank" rel="noopener noreferrer">Security and Limits Configuration</a>.

<Accordion title="Users see “Redemption failed, please try again later” when redeeming a code">

**Message**

“Redemption failed, please try again later”

**Note**

Users see the same message regardless of the cause.

**Possible causes**

- The redemption code does not exist or was deleted.
- The redemption code has already been used, was disabled, or has expired.
- A temporary database error occurred.

**Resolution**

1. Find the redemption code in the list by name or ID and check its status and expiration time.
2. Enable the code if its status is **Disabled**. If its status is **Used** or **Expired**, create a new code.
3. For troubleshooting steps users can take, see <a href="/en/docs/guide/feature-guide/user/wallet#frequently-asked-questions" target="_blank" rel="noopener noreferrer">Wallet</a>.

</Accordion>

<Accordion title="“Failed to create redemption code, please try again later” appears when creating a redemption code">

**Message**

“Failed to create redemption code, please try again later”

**Note**

Batch creation generates redemption codes one at a time and stops when an error occurs. Codes generated before the error remain in the list. The **Redemption Code Creation Complete** dialog does not appear.

**Possible cause**

A database write failed, possibly due to a temporary database error.

**Resolution**

1. Search the list by name for the redemption codes from this batch and check how many were generated.
2. Copy or delete the generated codes as needed.
3. Create the number of redemption codes you still need.

</Accordion>
