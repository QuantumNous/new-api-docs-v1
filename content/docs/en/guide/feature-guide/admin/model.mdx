- Only Root can change model pricing. See [Differences Between Admin and Root](#differences-between-admin-and-root).

- Creating a deployment does not create or link a Channel.

</Callout>

## Common Tasks

This section covers adding and editing models, setting prices, deleting models, adding missing models, syncing metadata and prices, and managing prefilled groups, providers, and deployments.

### Add and Edit Models

- Model Management – Create Model

![Model Management – Create Model page](/assets/guide/feature-guide/model-management-add-model-model-information.png)

**Steps**

1. To create a model, click “Add Model” in the upper-right corner of the “Models” tab to open the “Create Model” drawer. To edit an entry, click the model name, “Edit”, or “Add Metadata”. The drawer title shows the model name.
2. Fill in the fields on the “Model Metadata” tab.
3. Click “Save Metadata”.

<Callout type="info" title="Tip">

- Below the drawer title, the page displays “Manage metadata, pricing, and Channel associations. Save each section separately.”
- The drawer has three tabs, “Model Metadata”, “Pricing”, and “Channels and Groups”. When creating a model, fill in “Model Metadata” first. The other two tabs become available after you save.
- When you open the drawer from “Add Metadata” or “Missing Models → Configure”, the model name is already filled in and all three tabs are available.
- If saving fails, the reason appears at the bottom of the drawer.
- Save or discard any pending pricing changes before changing the model name.
- If you close the drawer with unsaved metadata or pricing changes, the drawer asks “Discard unsaved changes?”

</Callout>

### Pricing

- Model Management – Edit Model – Pricing

![Model Management – Edit Model – Pricing page](/assets/guide/feature-guide/model-management-edit-model-pricing.png)

**Set prices**

1. Click “Pricing” in the model row or open the “Pricing” tab in the edit drawer.
2. If the name rule is anything other than exact match, use “Select Model” to choose a specific matching model first.
3. Set the price in the editor below. For fields and billing methods, see <a href="/en/docs/guide/feature-guide/admin/billing-expression" target="_blank" rel="noopener noreferrer">Billing Expressions</a>.
4. Click “Save Model Price”.

<Callout type="info" title="Tip">

- Only Root can edit pricing. Admin sees the message “Model pricing is managed by the super admin.”
- The top of the tab shows a summary of the billing settings currently in effect.
- This tab uses the same editor and updates the same configuration as <a href="/en/docs/guide/feature-guide/system-settings/settings-billing#model-prices" target="_blank" rel="noopener noreferrer">Billing and Payment Configuration → Model Prices</a>.
- If the model's price changes elsewhere after you open the drawer, the save fails. Click “Reload Pricing” before editing again.

</Callout>

**Restore default pricing**

1. Click “Restore Default Pricing”, then click “Restore Defaults” in the confirmation dialog.

<Callout type="warn" title="Caution">
“Restore Default Pricing” removes the model's custom price and restores its built-in default. Models without a default price become unpriced.
</Callout>

### Delete Models

**Steps**

1. Click “Delete” in the ⋯ menu at the end of a row, or select multiple models and click “Delete Selected Models”. You can delete 1–1,000 models at a time.
2. In the “Delete Model?” dialog, select either option as needed. Both are unchecked by default.
3. Click “Delete”.

<Callout type="info" title="Tip">

- “Missing Metadata” rows have no metadata records to delete.
- Leave both options unchecked to delete only the model metadata and retain the model names, capabilities, and prices in Channels.
- If an enabled Channel still references the name, it reappears in a “Missing Metadata” row and under “Missing Models”.
- You can create a new metadata record with the same name after deletion.

</Callout>

**Deletion options**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Option | Description |
| --- | --- |
| Also Remove from All Channels | Removes the name from every Channel's model list and updates Channel capabilities accordingly. If any selected model uses a rule other than exact match, this option is unavailable and displays “Available for Exact Matches Only”. |
| Also Remove Pricing | Deletes the custom price for the model name. Selecting this option displays “Built-in pricing may take effect again.” Only Root can select this option. |

</div>

<Callout type="warn" title="Caution">
“Also Remove from All Channels” directly changes each Channel's model list. Once removed, the model can no longer be called through those Channels. To restore access, add the model name back to the Channels.
</Callout>

### Add Missing Models

- Model Management – Missing Models

![Model Management – Missing Models page](/assets/guide/feature-guide/model-management-missing-models.png)

“Missing Models” lists model names used by enabled Channels that have no metadata record with the **exact same name**. Names covered by prefix, contains, or suffix rules still appear.

**Steps**

1. In the upper-right corner of the “Models” tab, click ⋯ → “Missing Models”.
2. Search by name for the model you want to add.
3. Click “Configure” in the row, then fill in and save the metadata in the drawer, which opens with the model name already filled in. To import metadata, click “Sync Missing Metadata” at the bottom to open the [Sync Metadata](#sync-metadata) wizard.

<Callout type="info" title="Tip">

- The list shows 20 entries per page.
- “Missing Models” counts only enabled Channels.
- “Missing Metadata” rows in the model list also include names from disabled Channels, so the counts may differ.

</Callout>

### Sync Metadata

Click “Sync Metadata” to open the “Sync Model Metadata” wizard. It imports model metadata from the official metadata catalog and creates providers as needed. The wizard has four steps and requires a preview and confirmation every time you run it.

<Callout type="info" title="Tip">

- Sync updates only model metadata. It leaves Channels, model access, pricing, model names, and “Allow Metadata Sync” settings unchanged.
- The default data source is `https://basellm.github.io/llm-metadata`. Deployment operators can override it using the `SYNC_UPSTREAM_BASE` environment variable. This setting is available only through the environment variable.
- The server must be able to reach the data source. Step 1 of the wizard shows the actual sources for model and provider metadata.
- You cannot close the wizard while synchronization is running.

</Callout>

**Select models**

- Model Management – Sync Model Metadata – Select Models

![Model Management – Sync Model Metadata – Select Models page](/assets/guide/feature-guide/model-management-sync-information-select-model.png)

**Steps to select models**

1. Choose a “Metadata Language” (Chinese, English, or Japanese) and click “Load Metadata Preview”. Changing the language clears the loaded preview and your selections.
2. Under “Sync Scope”, choose “Models Used on This Site” (the default, which includes models with metadata and missing models) or “Upstream Model List” (all models in the official catalog).
3. Search or select “Show Only Syncable Models” as needed. Select individual models or click “Select All Syncable Models” to select them across all pages. Then click “Preview Selected Changes”.

For the “Planned Action” shown for each model, see [Planned Sync Actions](#planned-sync-actions).

**Preview fields**

- Model Management – Sync Model Metadata – Preview Fields

![Model Management – Sync Model Metadata – Preview Fields page](/assets/guide/feature-guide/model-management-sync-information-preview-fields.png)

Each selected model shows “Apply”, “Field”, “Current Value”, and “Change To”.

- **New metadata.** The wizard imports all seven fields without requiring you to select them individually. For the effect of each field, see [Metadata Sync Overwrite Rules](#metadata-sync-overwrite-rules).
- **Metadata changes.** The wizard lists only fields that differ from the official catalog and leaves them unchecked by default. Checking a field replaces its value with the value under “Change To”. “Select All Changed Fields” and “Deselect All” apply to all selected models with metadata changes.
- “Review and Confirm” becomes available when the selection includes a new model or at least one checked field.

**Confirm changes**

- Model Management – Sync Model Metadata – Confirm Changes

![Model Management – Sync Model Metadata – Confirm Changes page](/assets/guide/feature-guide/model-management-sync-information-confirm-changes.png)

**Steps to confirm changes**

1. Review the models to be created or updated, the fields to be updated, and any new providers.
2. Click “Apply Changes to N Models”.

<Callout type="info" title="Tip">
If the official catalog or this site's model metadata changes after you preview, applying the changes fails and the wizard asks you to preview again. Click “Preview Again” to return to step 1 and make your selections again.
</Callout>

**Sync results**

- Model Management – Sync Model Metadata – Sync Results

![Model Management – Sync Model Metadata – Sync Results page](/assets/guide/feature-guide/model-management-sync-information-sync-results.png)

The results show “Metadata Sync Complete”, the counts of models created and updated, any new providers, and the changes applied to each model. For models omitted from the results, see “Planned Action” in step 1 for the reason.

<Callout type="info" title="Tip">
The official catalog is a source of metadata. To make a synced model available for API calls, configure a Channel for it in <a href="/en/docs/guide/feature-guide/admin/channel" target="_blank" rel="noopener noreferrer">Channel Management</a>.
</Callout>

### Create a Deployment

**Prerequisites**

- The model deployment service must be enabled. See [Deployment Status](#deployment-status).

**Steps**

1. Click “Create Deployment” in the upper-right corner.

## Rules and Behavior

This section covers the differences between Admin and Root permissions, name matching rules, endpoint configuration formats, and field overwrite rules for metadata sync.

### Differences Between Admin and Root

Both Admin and Root users can manage model metadata, vendors, prefill Groups, and model deployments. Only Root users can change model pricing.

**Permission Differences**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| UI Element | Root | Admin |
| --- | --- | --- |
| “Sync Prices” button | Visible | Hidden |
| “Pricing” column | Shows a summary of current pricing. Click to open the “Pricing” tab. | Shows “Super Admin”. |
| Row-level “Pricing” button | Visible | Hidden |
| “Pricing” tab in the edit drawer | Can edit and save pricing. | Shows only “Model pricing is managed by the super admin.” |
| “Also Remove Pricing” option when deleting | Can select the option. | The option is disabled. Below it, the message “Model pricing is managed by the super admin.” appears. |

</div>

### Name Matching Rules

A name matching rule determines which model names use a metadata entry.

**Rule Types**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Rule | How It Matches |
| --- | --- |
| Exact Match | Matches only an identical model name. |
| Prefix Match | Matches model names that start with the specified string. |
| Contains Match | Matches model names that contain the specified string. |
| Suffix Match | Matches model names that end with the specified string. |

</div>

**Matching Behavior**

- If a model name matches multiple entries, the system uses the first match in this order: exact, prefix, suffix, contains.
- Matching rules apply only to model metadata (description, icon, tags, vendor, endpoints, and Model Marketplace visibility). Pricing is always configured for each specific model name.
- With a rule other than an exact match, individual model names from Channels are excluded from the metadata entry and may still appear under “Missing Models”. The “Also Remove from All Channels” option is disabled when deleting that entry.

### Endpoint Configuration

Endpoint configuration defines the endpoint types and custom paths shown to users for a model.

**Enter a Configuration**

- Enter an “Endpoint Type” and a “Configuration” on each row.
- Switch to “JSON Mode” to enter JSON directly.
- “Load Template...” **replaces** all current content with the selected template (`openai`, `openai-response`, `anthropic`, `gemini`, `jina-rerank`, `image-generation`, or `embeddings`).

**Validation Rules**

- Leave the field blank to omit the configuration. If provided, it must be a JSON object or an array of endpoint type strings.
- Each object key must be a nonempty endpoint type. Its value must be either a path starting with `/` or an object with a `path` starting with `/` and an optional `method` (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, or `OPTIONS`).

<Callout type="info" title="Tip">
The Channel Base URL and upstream Channels are configured separately from custom endpoints. The “Supported Endpoints” shown in the “Channels and Groups” tab are derived from enabled Channels independently of the custom endpoints configured here.
</Callout>

### Metadata Sync Overwrite Rules

Metadata sync updates only the selected fields. The table below describes what happens for each field.

**Field Effects**

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Field | Effect |
| --- | --- |
| Description, Icon, Tags | Replaces the fields with the official values. |
| Vendor | If no vendor with the same name exists on this instance, creates one from the official vendor list. |
| Custom Endpoints | Updates the endpoint types and custom paths shown to users. |
| Match Type | Changes which model names inherit this metadata. Pricing is configured separately for each model name. |
| Model Marketplace Visibility | Changes how the model appears in the Model Marketplace. Channel status and existing API access permissions are unaffected. |

</div>

**Sync Scope**

- Sync skips models with “Allow Metadata Sync” disabled.
- For metadata changes, the wizard lists only fields that differ from the official values and updates only the fields you select.

## Saving and Applying Changes

Each action on this page is saved as soon as you submit it, without a separate page-wide save step. Changes take effect immediately on the node that handles the request. The timing on other nodes depends on what changed, as described below.

**Model Metadata and Vendors**

Model metadata, vendors, and prefill Groups are stored in the database. The management page list updates immediately after saving. When you edit or sync metadata, hide or show models, or change vendor data, the Model Marketplace updates immediately on the node that handles the request. Other nodes usually update within about 3 seconds and may take up to about 1 minute. Users who already have the Model Marketplace open see the new content when they refresh the page.

## Important Notes

- **“Also Remove from All Channels” edits Channels directly.** To restore a model after deletion, add its name back to the affected Channels. See [Delete Models](#delete-models).
- **Deployments are external resources.** Deletion is irreversible. Before terminating or modifying a deployment, switch any Channels that point to it to another available Channel. See [View and Manage Deployments](#view-and-manage-deployments).
- **Model names are unique identifiers.** Renaming a model leaves its name in Channels and its pricing tied to the original name. Pricing is always configured for each specific model name. See [Add and Edit Models](#add-and-edit-models).
- **Metadata sync overwrites selected fields.** To protect a model’s metadata from being overwritten, disable “Allow Metadata Sync” for that model. See [Sync Metadata](#sync-metadata).
- **API access is governed separately from Model Marketplace visibility.** Whether a user can call a model depends on Channel, Group, and API key restrictions. See [Model Marketplace Visibility Status](#model-marketplace-visibility-status).
