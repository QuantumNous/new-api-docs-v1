## Common Operations

This section covers adding and editing users, adjusting quotas, setting administrator permissions, enabling and disabling users, promoting and demoting users, managing bindings and subscriptions, resetting passkeys and 2FA, and deleting users.

### Add a User

- User Management – New User

![User Management – New User page](/assets/guide/feature-guide/user-management-add-user.png)

**Steps**

1. Click “Add User” in the upper-right corner.
2. Enter a username and password. A password is required when creating a user.
3. Enter a display name if needed. If you leave it blank, the system uses the username.
4. Select “Regular User” (the default) or “Admin”, then click “Save Changes”. To create an Admin account, complete [Security Verification](#security-verification) first.

<Callout type="info" title="Tip">

- Only Root can add Admin accounts.
- When adding or editing an Admin account, Root can set its permissions in the “Administrator Permissions” section at the bottom of the drawer. See [Administrator Permissions](#administrator-permissions).
</Callout>

**Configuration fields**

The “New User” drawer contains two sections, “Basic Information” and “Administrator Permissions”. The “Administrator Permissions” section appears only when Root selects the “Admin” role. The fields below appear in drawer order.

<div className="[&_table]:min-w-[36rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| Field | Definition | Requirements and Limits | Default |
| --- | --- | --- | --- |
| Username | The username used to sign in. | Required, unique, and up to 20 characters long. It cannot be changed after the user is created. | Blank |
| Role | The account role. | Choose “Regular User” or “Admin”. The helper text reads “Set the user role (cannot be Root)”. Admin can only create regular users. Root can create both regular users and Admin accounts. | Regular User |
| Display Name | The name shown in the list and the user interface. | Up to 20 characters. If left blank, the system uses the username. The sign-in username stays the same. | Blank |
| Password | The initial password. | Required. Must be 8–128 characters long. Password strength and suggestions appear below the field. You can save the password regardless of its strength rating. | Blank |

</div>

<Callout type="warn" title="Caution">
Keep initial passwords out of screenshots, support tickets, and shared documents.
</Callout>

### Adjust User Quota

**Steps**

1. Click the pencil icon in the user's row to open the edit drawer.
2. Click “Adjust Quota” next to “Remaining Quota”.
3. Under “Mode”, select “Add”, “Subtract”, or “Override”.
4. Enter the amount and click “Confirm”.

<Callout type="info" title="Tip">

- The top of the dialog previews the adjustment, for example “Current Quota: … + … = …”.
- “Add” and “Subtract” require an amount greater than 0. “Override” accepts 0 and negative values.
- Quota adjustments are submitted separately from “Save Changes” and require no security verification.
- After a successful adjustment, the user's usage log contains a “Top-up” entry.
</Callout>

### Roles and Status

- User Management – Actions Menu

![User Management – Actions Menu page](/assets/guide/feature-guide/user-management-operations.png)

**Steps**

1. Click ⋯ in the user's row and select “Enable”, “Disable”, “Promote”, or “Demote”.
2. Complete [Security Verification](#security-verification).

**Available actions**

| Action | Applies To | Behavior and Limits |
| --- | --- | --- |
| Enable | Disabled users | Changes the status to enabled. The operator must still have permission to manage the target role. |
| Disable | Enabled users | Changes the status to disabled. Root accounts cannot be disabled. Use this action to temporarily block sign-ins and API calls while retaining the account record. |
| Promote | Regular users | Only Root can promote a regular user to Admin. |
| Demote | Admin | Changes an Admin to a regular user. Root accounts cannot be demoted. Demotion clears the account's fine-grained permission overrides and revokes its existing sessions. |

<Callout type="info" title="Tip">
When a role or status change affects authentication, the system updates the authentication state, clears the relevant caches, and revokes the user's sessions.
</Callout>

### Manage User Bindings

- User Management – Account Binding Management

![User Management – Account Binding Management page](/assets/guide/feature-guide/user-management-user-binding.png)

The “Manage Bindings” dialog can display email, GitHub, Discord, OIDC, WeChat, Telegram, LinuxDO, and configured custom OAuth providers. Disabled providers may still appear if the user linked them before they were disabled.

**Steps**

1. Click ⋯ in the user's row to open the actions menu, then select “Manage Bindings”.
2. The dialog shows linked methods by default. Click “Show All” to also see unlinked and disabled providers. The button label then changes to “Linked Only”.
3. To unlink a provider, click the unlink icon in the upper-right corner of the linked provider's card, confirm in the “Confirm Unlinking” dialog, and complete [Security Verification](#security-verification).

<Callout type="warn" title="Caution">

- The dialog only supports unlinking existing bindings. It cannot set up a new email address, OAuth connection, passkey, or other sign-in method on the user's behalf.
- Before unlinking a provider, confirm that the user still has a password or another available recovery method. The user loses the ability to sign in with that identity once it is unlinked.
</Callout>

### Manage User Subscriptions

- User Management – User Subscription Management

![User Management – User Subscription Management page](/assets/guide/feature-guide/user-management-user-subscription.png)

**Steps**

1. Click ⋯ in the user's row and select “Manage Subscriptions” to open the “User Subscription Management” drawer.
2. View the user's subscription records in the list or perform one of the actions below.

**Subscription list fields**

| Field | Description |
| --- | --- |
| ID | The subscription record's unique identifier. |
| Plan | The plan name and subscription source. Subscriptions added by an administrator typically have `admin` as the source. |
| Status | Active, invalidated, or expired. |
| Validity Period | Start and end times, calculated using the plan's validity period at the time the subscription was created. |
| Total Quota | Displays used quota over total quota. A total quota of 0 displays as “Unlimited”. The unit follows the instance's billing settings. |
| Actions | The row menu offers “Reset Quota”, “Invalidate”, and “Delete”. To add a subscription, use “Add Subscription” at the top. |

**Add a subscription**

1. In the plan selector at the top, select a plan available to administrators.
2. Click “Add Subscription”.

<Callout type="info" title="Tip">

- Adding a subscription assigns it to the user without creating a payment order. The API requires the instance to have completed its payment compliance confirmation and revalidates the plan ID and the per-user purchase limit.
- The purchase limit counts all existing subscription records for the user on that plan, including active, expired, and invalidated subscriptions. Only deleting an existing record frees up a slot.
</Callout>

**Reset subscription quota**

1. Open the actions menu in an active subscription row for the target plan and select “Reset Quota”.
2. Leave “Advance Next Reset Time” on or turn it off as needed. It is on by default.
3. Click “Reset Quota” in the confirmation dialog.

<Callout type="info" title="Tip">

- The reset affects all active, unexpired subscriptions the user has on that plan.
- The reset sets used quota to zero for each matching subscription.
- With the switch on, the system recalculates the next reset time using the plan's current reset rules. With the switch off, it sets used quota to zero and keeps the existing reset time.
- The success message shows how many active subscriptions were reset.
</Callout>

**Invalidation and deletion compared**

“Reset Quota” and “Invalidate” are available only for active subscriptions. “Delete” is available for subscriptions in any status. Before deleting an active subscription, check whether “Invalidate” better fits your needs.

| Effect | Invalidate Subscription | Delete Subscription |
| --- | --- | --- |
| Record handling | Retains the record, changes its status to “Invalidated”, and sets the end time to the current time. | Permanently removes the entire subscription record. |
| Subscription record | Retains the subscription history, plan information, total quota, used quota, source, and group snapshot. | Removes the record and all stored entitlements, quota, status, timestamps, and the group snapshot. |
| New requests | The system no longer recognizes the subscription as active or uses its quota for new requests. | The system no longer recognizes the subscription as active. |
| User group | May revert the user's group. | May revert the user's group in the same way and then delete the snapshot. |
| Wallet balance | Leaves the wallet balance unchanged. | Leaves the wallet balance unchanged. |
| Payment amount | Leaves the payment order unchanged and issues no refund. | Leaves the payment order unchanged and issues no refund. |
| Unused quota | Unused quota is forfeited and used quota is retained. | Unused quota disappears with the subscription record. No quota is transferred to the wallet or another account. |
| Usage and task logs | Retains the logs. | Retains the logs. Subscription IDs in the logs may become historical references. |
| Purchase limit | The retained record still counts toward the plan's purchase limit. | The deleted record no longer counts toward the limit. |
| Recovery | To resume the subscription, create a new one. Invalidation cannot be undone. | The interface offers no recovery option, and the record usually cannot be recovered. |
| In-flight requests and tasks | Because the record still exists, later settlement or refunds can usually use the subscription ID. | Later lookups by subscription ID may fail, which can prevent settlement or refunds from completing. |

<Callout type="warn" title="Caution">

- Use “Invalidate” to stop a subscription while retaining its full history.
- Use “Delete” only after confirming that the record is incorrect, contains test data, or does not need to be retained.
- If a refund is required, follow the separate refund process. Invalidation and deletion do not issue refunds.
- Before deleting a subscription, confirm that there are no in-flight requests, asynchronous tasks, or pending refunds.
</Callout>

### Reset Passkey

- User Management – Reset Passkey

![User Management – Reset Passkey page](/assets/guide/feature-guide/user-management-reset-passkey.png)

<Callout type="warn" title="Caution">
Before resetting, confirm that the user still has a usable sign-in method, such as a password, a linked third-party account they can access, or a linked email address that can receive password reset emails. Without one, the user will be unable to sign in or register a new passkey after the reset.
</Callout>

**Steps**

1. Select “Reset Passkey” from the user's row menu.
2. Confirm the reset in the dialog and complete [Security Verification](#security-verification).

<Callout type="info" title="Tip">

- The system deletes the user's existing passkey credentials and revokes all their sign-in sessions. The success message reads “Passkey reset successfully”.
- The user must register a new passkey before they can use passwordless sign-in again.
</Callout>

### Reset 2FA

- User Management – Reset 2FA

![User Management – Reset 2FA page](/assets/guide/feature-guide/user-management-reset-2fa.png)

**Steps**

1. Select “Reset 2FA” from the user's row menu.
2. Confirm the reset in the dialog and complete [Security Verification](#security-verification).

<Callout type="info" title="Tip">

- The system deletes the user's existing 2FA factors and backup codes, updates the authentication version, and revokes all their sign-in sessions. The success message reads “Two-factor authentication has been reset”.
- The user must set up 2FA again on the “Security & Access” page.
</Callout>

### Delete a User

<Callout type="warn" title="Caution">

- Only operators whose role ranks strictly above the target user's role can perform this action. Root accounts cannot be deleted through this workflow.
- Before deleting a user, export or save any audit information your organization requires you to retain. This page has no recovery option.
- “Delete” permanently removes the user and cannot be undone. Use “Disable” to temporarily block sign-ins and API calls. Use “Delete” only after confirming which data will be removed, what retention requirements apply, and how any subsequent recovery would be handled.
- Users deleted here disappear from the list. Accounts users close themselves on the “Security & Access” page stay in the list with the “Closed” status and have no available actions.
</Callout>

**Steps**

1. Open the ⋯ menu in the user's row and select “Delete”.
2. Click “Delete” in the “Are you sure?” dialog. The dialog warns, “This action cannot be undone”.
3. Complete [Security Verification](#security-verification).

<Callout type="info" title="Tip">
Hard deletion removes the primary user record and the authentication data explicitly associated with it in the system.

- API tokens and other user authentication tokens
- Browser sessions and authentication flow records
- Passkey credentials
- 2FA configuration and backup codes
- Records reserving linked identities for built-in third-party providers
- Custom OAuth bindings
</Callout>

## Rules and Behavior

This section covers the role hierarchy and the actions that require security verification.

### Role Hierarchy

| Role | Management Scope |
| --- | --- |
| User | Regular user with no access to the User Management page. |
| Admin | Can manage regular users. Cannot manage account details or security settings for other Admin accounts or Root accounts. |
| Root | Can manage regular users and Admin accounts. For Root accounts, can edit account details and manage bindings and subscriptions. The interface provides no option to disable, demote, or delete Root accounts, or to reset their passkeys or 2FA. |

### Security Verification

Before the following actions are submitted, a verification dialog appears with a title such as “Verify to Delete User”. The current operator must verify their identity again before the action can proceed.

- Enable, disable, promote, or demote a user.
- Delete a user.
- Reset a passkey or 2FA.
- Unlink a sign-in method in “Manage Bindings”.
- Change a password or administrator permissions while editing a user.
- Create a user with the “Admin” role.

Verification uses the same methods as sensitive actions on personal accounts. Use 2FA or a passkey if 2FA is enabled or a passkey is registered. Otherwise, use the account password. Accounts without a password use a linked third-party sign-in method. See <a href="/en/docs/guide/feature-guide/system-settings/settings-auth#login-verification-and-security" target="_blank" rel="noopener noreferrer">Authentication Configuration</a>.

<Callout type="info" title="Tip">

- Creating a regular user, editing only the display name, group, or note, adjusting quota, and managing subscriptions require no security verification.
- Disabling password sign-in or passkeys also makes that method unavailable for verification. If the operator has no other available method, they must first enable 2FA on the <a href="/en/docs/guide/feature-guide/user/security#enable-two-step-verification" target="_blank" rel="noopener noreferrer">Security & Access</a> page before they can complete these actions.
</Callout>

## Saving Changes and When They Take Effect

Actions on this page write directly to the database. Each node reads the new values starting with its next request. See the table for the exception for administrator permissions. In the tables, “revoke sessions” means invalidating all of the user’s active browser sessions and requiring the user to sign in again. The user’s API keys remain unaffected by session revocation.

**Profile, Quota, and Subscriptions**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| Action | How to save | When it takes effect |
| --- | --- | --- |
| Add a user | Click “Save Changes” in the drawer. The message “User created successfully” appears. Complete security verification before creating an administrator. | The new user can sign in immediately and receives the “New User Quota.” If the new user quota is greater than 0, a “New user signup bonus …” entry is also logged. |
| Change the display name or notes | Click “Save Changes” in the edit drawer. The message “User updated successfully” appears. | Takes effect immediately without revoking sessions. |
| Change the Group | Click “Save Changes” in the edit drawer. The message “User updated successfully” appears. | Starting with the next request, routing and billing use the new Group, and sessions are revoked. |
| Adjust Quota | Confirm in the “Adjust Quota” dialog. Security verification is unnecessary. | The new balance applies starting with the next request. Quota already deducted in advance for in-flight requests is unaffected. Sessions stay active. A “Top-up” entry is added to the user’s usage log. |
| Add, reset, void, or delete a user subscription | Submit each action separately in the Manage Subscriptions panel. Security verification is unnecessary. | Takes effect immediately. Group changes triggered by subscriptions leave sessions active. See <a href="/en/docs/guide/feature-guide/admin/subscription#saving-changes-and-when-they-take-effect" target="_blank" rel="noopener noreferrer">Subscription Management</a>. |

</div>

**Status, Permissions, and Sign-in Credentials**

<div className="[&_table]:min-w-[36rem] [&_th]:whitespace-nowrap">

| Action | How to save | When it takes effect |
| --- | --- | --- |
| Enable, disable, promote, or demote a user | ⋯ menu → Security verification | Takes effect immediately. Sessions are revoked if the status or role changes. Once the account is disabled, requests using the user’s API keys are rejected starting with the next request. Demoting the user also clears the account’s administrator permission overrides. |
| Change administrator permissions | Click “Save Changes” in the edit drawer and complete security verification. | Takes effect immediately on the node handling the request. Other nodes reload the permissions within about 3 seconds, or within one sync interval at most (60 seconds by default). Sessions stay active. Set the sync interval in seconds with the `SYNC_FREQUENCY` environment variable and restart after changing it. This page has no corresponding setting. |
| Change the password | Enter the new password in the edit drawer, click “Save Changes,” and complete security verification. | Takes effect immediately and revokes sessions. |
| Unlink an identity | In “Manage Linked Accounts,” click the unlink icon, select “Confirm Unlink,” and complete security verification. The message “Unlinked …” appears. | Takes effect immediately. The user can no longer sign in with that identity. Existing sessions stay active. |
| Reset Passkey or 2FA | ⋯ menu → Confirm → Security verification. The message “Passkey reset successfully” or “Two-factor authentication has been reset” appears. | Immediately deletes the corresponding credentials and revokes sessions. |
| Delete a user | ⋯ menu → “Are you sure?” → Security verification. The message “User deleted successfully” appears. | Deletes the user immediately and permanently. See [Delete a User](#delete-a-user). |

</div>

## Important Notes

- **User deletion is permanent.** To temporarily block sign-in and API access, use “Disable.” See [Delete a User](#delete-a-user).
- **Role hierarchy limits apply.** Admin can manage only regular users. Only Root can promote users and create administrators. See [Role Hierarchy](#role-hierarchy).
- **Security verification may be unavailable.** Disabling password sign-in or the Passkey feature makes the corresponding method unavailable for verification. Administrators without another available method cannot perform actions that require verification. See [Security Verification](#security-verification).
- **Confirm the user can still sign in before unlinking an identity.** Before unlinking an identity or resetting a Passkey, make sure the user still has a password or another available sign-in method. See [Manage Linked Accounts](#manage-user-bindings) and [Reset Passkey](#reset-passkey).
- **Voiding or deleting a subscription does not issue a refund.** Both actions forfeit any unused quota. Handle refunds separately. See [User Subscription Management](#manage-user-subscriptions).

| --- | --- | --- |

<Accordion title="The verification dialog shows “No verification method is available for this action.”">
**Message**  
“No verification method is available for this action.”

**Possible cause**  
The administrator performing the action has no available verification method. Disabling password sign-in or the Passkey feature makes the corresponding method unavailable for verification. The dialog explains why each method is unavailable.

**Resolution**

1. Enable 2FA on the <a href="/en/docs/guide/feature-guide/user/security#enable-two-step-verification" target="_blank" rel="noopener noreferrer">Security and Access</a> page.
2. Try the action again.
</Accordion>

<Accordion title="A user is prompted to sign in again after their password or Group changes">
**Explanation**  
The system revokes the user’s existing browser sessions whenever their password or Group changes. Enabling, disabling, promoting, or demoting a user also revokes sessions if their status or role changes. Resetting a Passkey or 2FA also revokes sessions.

**Resolution**

1. Ask the user to sign in again. To avoid interrupting their work, change their password or Group when they are inactive.
</Accordion>

<Accordion title="Resetting a user’s subscription quota returns “This user has no active subscription to this plan”">
**Message**  
“This user has no active subscription to this plan”

**Possible cause**  
The user has no subscription to the selected plan that is active and has yet to reach its end time. The subscription may have expired, been voided, or never been added.

**Resolution**

1. Check the status in the subscription list.
2. Add a subscription first if needed.
</Accordion>
